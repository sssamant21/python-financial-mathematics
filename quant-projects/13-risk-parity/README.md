# Project 13 — Inverse-Volatility Allocation and Walk-Forward Risk Budgets

**Question:** Can a portfolio reduce exposure to historically volatile assets without using future observations? This lab compares a long-only, inverse-volatility allocation concept with equal-weight intuition. It is **not** full covariance-based equal-risk-contribution optimization: correlations can make realized risk contributions unequal.

## Mathematics and business context

For each asset, compute the sample standard deviation of the previous 52 weekly returns, `s_i`. Set raw weight `a_i = 1 / max(s_i, 1e-6)`, then normalize weights to sum to one, respecting a 70% maximum allocation via water filling. Volatility is backward-looking and may change abruptly. Inverse-volatility weighting can concentrate on assets with artificially low historical volatility.

At each origin, fit on **only the preceding 52 observations**, hold weights for 13 future weeks, then advance by 13 weeks. Apply a one-way turnover estimate `sum(abs(new_weights - previous_drifted_weights))` and a linear cost assumption in basis points. The first allocation is charged against cash (zero previous risky holdings). The reported gross return uses fixed-weight weekly portfolio returns; this represents a constant-mix approximation during the held-out block, whereas the turnover reference uses buy-and-hold drift. This convention is educational and **not** a fully self-financing trade ledger.

## Run

From this folder, with Python 3.11 and `numpy>=1.26,<3`, `pytest>=8,<10`:

```bash
python risk_parity.py --seed 13
python -m pytest -q test_risk_parity.py
```

All inputs are generated by a seeded synthetic normal-return process with a deliberate mid-sample volatility shift. No third-party market prices are stored or redistributed.

## Validation and limitations

Tests cover weight normalization/caps, volatility ordering, deterministic output, origin isolation from future mutations, non-overlapping windows, cost monotonicity, and invalid inputs. The 52-week lookback, 13-week hold, and 70% cap are predeclared teaching assumptions, not optimized strategies. Asset identities, delistings, timestamped data availability, borrow/financing, intra-window execution, covariance-driven risk contribution, and real historical regime performance are not validated. Results are not investment advice or production certification.

## Extension — Covariance-aware equal-risk-contribution (ERC)

Inverse-volatility weights ignore correlations. The new `erc.py` estimates a training-only sample covariance, shrinks it toward the diagonal using a **fixed** 15% assumption, and solves for positive weights with approximately equal **fractional portfolio variance contributions**:

\[RC_i = w_i(\Sigma w)_i/(w^\top\Sigma w), \qquad RC_i \approx 1/N.\]

The coordinate-descent solver minimizes `0.5*x.T@Sigma@x - sum(log(x))` for positive unnormalized holdings, then normalizes. It requires a strictly positive-definite covariance and raises an error rather than silently returning an unstable answer. **No weight cap is imposed in this ERC extension**; compare with the capped inverse-volatility baseline only with that difference clearly disclosed. Equal *forecast* risk contributions do not guarantee equal realized contributions.

A 52-week historical window determines weights; 13-week non-overlapping future blocks are used **only after the origin** to score held-out covariance and contribution drift. Synthetic returns and a seeded regime shift make the lab reproducible. No future covariance enters the allocation.

```bash
python erc.py --seed 13
python -m pytest -q test_erc.py
```

The shrinkage level, training window and evaluation horizon are predeclared teaching assumptions. Covariance estimation error, changing correlations, return-data publication timestamps, real-world turnover and costs, survivorship, financing, and independent statistical review remain unverified. This is not a tradable or certified portfolio model.
