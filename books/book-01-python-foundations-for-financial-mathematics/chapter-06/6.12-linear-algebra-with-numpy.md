## 6.12.1 Purpose

Applying a known matrix and solving for unknown quantities are different tasks. Section 6.11 calculated outcomes from supplied allocations. Here the unknown is the instrument-unit vector needed to match a synthetic payoff target.

The lab solves a small square linear system, reconstructs its right-hand side, and reports numerical diagnostics. It deliberately distinguishes successful arithmetic from economic feasibility or reliable inference.

## 6.12.2 Learning Objectives

1. Express a payoff-matching question as A x = b.
2. Identify equation and unknown axes and their units.
3. Use np.linalg.solve for the supported square problem.
4. Check reconstruction residuals and conditioning separately.
5. Reject singular or poorly conditioned cases under an explicit teaching policy.
6. Distinguish solving from least squares, optimization, pricing, and trade execution.

## 6.12.3 Define the Synthetic System

Rows represent two common hypothetical payoff states. Columns represent two instruments. Each entry is the payoff per instrument unit in one stated currency at one common horizon.

| State | Instrument A per unit | Instrument B per unit | Target payoff |
|---|---|---|---|
| STATE-1 | 1 | 1 | 100 |
| STATE-2 | 1 | 2 | 150 |

Let x_A and x_B be instrument units. The equations are x_A+x_B=100 and x_A+2*x_B=150. Subtracting them gives x_B=50, then x_A=50.

\[
A=\begin{bmatrix}1&1\\1&2\end{bmatrix},\qquad
x=\begin{bmatrix}x_A\\x_B\end{bmatrix},\qquad
b=\begin{bmatrix}100\\150\end{bmatrix},\qquad Ax=b.
\]

This is an exact-match definition for the supplied finite state table, not a claim that two actual instruments span all possible market outcomes. No instrument prices, probabilities, financing rules, or transaction constraints are supplied.

## 6.12.4 Axes, Shapes, and Units

| Object | Shape | Meaning |
|---|---|---|
| A | (N, N) | State equations by instrument unknowns |
| b | (N,) | Target payoff in each state |
| x | (N,) | Instrument units |
| A @ x | (N,) | Reconstructed state payoffs |
| A @ x - b | (N,) | State residuals |

The kernel supports exactly one-dimensional b. A column-shaped (N,1) target is rejected to avoid silently changing the output convention. A one-equation case still returns a length-one vector.

State and instrument labels remain caller-owned. The caller must align b with A's rows and interpret x using A's columns. Matching dimensions do not verify those identities or units. Preserve the labeled source table alongside the numerical arrays.

## 6.12.5 Solve Directly

Use np.linalg.solve(A,b) for this square full-rank system. It targets the equation directly; there is no need to form an explicit inverse and multiply it by b just to obtain x.

A singular system lacks a unique square-system solution. Depending on the right-hand side, it may have multiple solutions or no exact solution. The lab rejects such cases rather than selecting one silently. Linear-algebra exceptions remain visible if a numerical operation fails.

The solution may contain negative units. For the same A with target [100,50], the equations give [150,-50]. These are signed instrument units, not normalized portfolio weights. The solver imposes no long-only, budget, or trading constraints.

## 6.12.6 Residual: Did the Computed Units Reconstruct the Target?

Define r = A*x-b and report the normalized infinity-norm residual:

\[
\eta_\infty=
\frac{\lVert Ax-b\rVert_\infty}
{\lVert A\rVert_\infty\lVert x\rVert_\infty+\lVert b\rVert_\infty}.
\]

For the supported zero-target/zero-solution case, the denominator and residual are zero; the implementation returns zero rather than dividing by zero. If diagnostic arithmetic becomes nonfinite, the run fails.

The lab requires this normalized residual to be at most 1e-12. This is a teaching numerical gate, not a general financial acceptance threshold. Inspect absolute state residuals as well, since a small normalized error can still have a material currency magnitude in a differently scaled application.

A small residual means the computed x fits the supplied equations numerically. It does not prove the coefficients are accurate, the financial assumptions are complete, or x is insensitive to uncertain input data.

## 6.12.7 Conditioning: Is the Question Sensitive?

The kernel also computes the matrix condition number using the 2-norm convention, np.linalg.cond(A,p=2). It rejects nonfinite values or values above 1e8 before solving. That threshold is deliberately explicit and is not a universal rule for every model.

The sensitivity test uses two nearly identical equations. A tiny change in the target changes computed units by more than ten units while reconstruction residual remains tiny. This is direct evidence that residual quality alone cannot establish solution stability.

Conditioning depends on representation and scaling. Rows or columns expressed in very different units can distort a naive threshold interpretation. Choose and document meaningful scaling, keep track of the transformation back to original units, and reassess tolerances. Do not automatically rescale data merely to make a gate pass.

A condition number is a diagnostic, not a calibrated forecast of actual input error or a guarantee about an economically acceptable solution. Retain assumptions about coefficient uncertainty and unit constraints separately.

## 6.12.8 Choosing a Different Problem Deliberately

| Task | Starting operation | Further decisions |
|---|---|---|
| Square supported exact-match equation | solve | Uniqueness, conditioning, residuals |
| Rectangular or approximate fit | lstsq | Residual objective, rank policy, weights, interpretation |
| Constrained holdings or budgets | Constrained model | Feasibility and objective, beyond this lab |
| Apply known units to states | A @ x | Axis alignment and units |

np.linalg.lstsq solves a least-squares question. It is not an automatic fallback that preserves the original exact-match claim after solve fails. Introducing a pseudoinverse, dropping equations, or regularizing also changes the problem and requires an explicit reviewed policy.

No least-squares or constrained solver is executed here. Broader numerical methods are developed later in the book. This section establishes the habit of identifying the question before choosing a linear-algebra routine.

## 6.12.9 Boundary and Numerical Policy

A must be an exact float64 ndarray, square with dimension 1–50. The target is an exact float64 ndarray with matching length. Every entry must be finite and have absolute value at most 1e6. The dimension and magnitude bounds are teaching constraints, not evidence of general numerical accuracy.

Local signal handling surrounds the numerical operations, and output units, residuals, normalization scale, and normalized error are checked for finiteness. A backend operation may also raise LinAlgError. Failures are propagated; no zero solution or approximate fallback is fabricated.

float64 remains approximate. Backend/library differences can affect final digits, especially near policy thresholds. The small known examples are checked with explicit tolerances rather than a cross-platform bitwise-equality promise.

The function reads input arrays and returns independent computed arrays. It assumes source data is not concurrently modified during execution. It does not create a complete audit record or save instrument labels automatically.

## 6.12.11 File — linear_algebra_lab.py

```python
"""Solve a small synthetic state-payoff matching system with diagnostics."""
import numpy as np


def solve_payoffs(a: np.ndarray, target: np.ndarray) -> dict[str, object]:
    """Solve A x = target for 1–50 states and equally many instruments.

    Exact float64 arrays; finite entries bounded in magnitude by 1e6.
    Columns are instrument payoff per unit, rows are common states.
    Caller aligns labels, currency, units, and horizon. Signed units allowed.
    Reject cond_2 > 1e8; require normalized infinity-norm residual <= 1e-12.
    These are teaching gates, not a general financial acceptance standard.
    """
    for value in (a,target):
        if type(value) is not np.ndarray or value.dtype != np.dtype('float64'):
            raise TypeError('expected exact float64 ndarrays')
        if not np.isfinite(value).all() or (np.abs(value) > 1e6).any():
            raise ValueError('entries must be finite and within lab bounds')
    if a.ndim != 2 or a.shape[0] != a.shape[1] or not 1 <= a.shape[0] <= 50:
        raise ValueError('A must be square with dimension 1 to 50')
    if target.ndim != 1 or target.shape[0] != a.shape[0]:
        raise ValueError('target must be a matching one-dimensional vector')
    with np.errstate(over='raise',under='raise',invalid='raise',divide='raise'):
        condition = float(np.linalg.cond(a,p=2))
        if not np.isfinite(condition) or condition > 1e8:
            raise ValueError('singular or ill-conditioned system under lab policy')
        units = np.linalg.solve(a,target)
        residual = a @ units - target
        numerator = float(np.linalg.norm(residual,ord=np.inf))
        scale = float(np.linalg.norm(a,ord=np.inf)*np.linalg.norm(units,ord=np.inf)
                      + np.linalg.norm(target,ord=np.inf))
        error = numerator/scale if scale else numerator
    if not (np.isfinite(units).all() and np.isfinite(residual).all()
            and np.isfinite(scale) and np.isfinite(error)):
        raise ValueError('nonfinite solver diagnostics')
    if error > 1e-12:
        raise ValueError('normalized residual exceeds lab tolerance')
    return {'units':units,'residual':residual,'condition_2':condition,
            'normalized_residual_inf':error}


def main() -> None:
    a = np.array([[1.,1.],[1.,2.]])
    target = np.array([100.,150.])
    result = solve_payoffs(a,target)
    print('Axes: payoff state, instrument')
    print('Instrument units:',[f'{x:.6f}' for x in result['units']])
    print('Reconstructed payoff:',(a @ result['units']).tolist())
    print(f'Condition number (2-norm): {result["condition_2"]:.6f}')
    print(f'Normalized residual: {result["normalized_residual_inf"]:.3e}')


if __name__ == '__main__':
    main()
```

The condition-number gate runs before solve. For singular or near-singular inputs it can reject the system without relying solely on the solver's exception behavior. A library factorization or diagnostic can still fail, and that remains a failed invocation.

## 6.12.12 File — test_linear_algebra_lab.py

```python
import unittest
import numpy as np
from linear_algebra_lab import solve_payoffs

class LinearAlgebraTests(unittest.TestCase):
    def test_known_payoff_match(self):
        a,target = np.array([[1.,1.],[1.,2.]]),np.array([100.,150.])
        result = solve_payoffs(a,target)
        np.testing.assert_allclose(result['units'],[50.,50.],rtol=1e-12,atol=1e-12,equal_nan=False)
        np.testing.assert_allclose(a @ result['units'],target,rtol=1e-12,atol=1e-12,equal_nan=False)
        self.assertLessEqual(result['normalized_residual_inf'],1e-12)

    def test_signed_units_are_not_weights(self):
        result = solve_payoffs(np.array([[1.,1.],[1.,2.]]),np.array([100.,50.]))
        np.testing.assert_allclose(result['units'],[150.,-50.],rtol=0,atol=1e-12,equal_nan=False)

    def test_singular_and_ill_conditioned(self):
        for a in (np.array([[1.,1.],[2.,2.]]),np.diag([1.,1e-10])):
            with self.assertRaises(ValueError):
                solve_payoffs(a,np.array([1.,1.]))
        with self.assertRaises(np.linalg.LinAlgError):
            np.linalg.solve(np.array([[1.,1.],[2.,2.]]),np.array([1.,2.]))

    def test_small_residual_can_hide_sensitivity(self):
        a = np.array([[1.,1.],[1.,1.+1e-10]])
        b = np.array([2.,2.+1e-10])
        first = np.linalg.solve(a,b)
        changed = b.copy(); changed[1] += 1e-8
        second = np.linalg.solve(a,changed)
        self.assertGreater(float(np.max(np.abs(second-first))),10.)
        self.assertLess(float(np.max(np.abs(a @ second-changed))),1e-10)

    def test_shapes_and_types(self):
        for a,b in ((np.ones((2,3)),np.ones(2)),(np.eye(2),np.ones((2,1))),
                    (np.zeros((0,0)),np.zeros(0)),(np.eye(51),np.ones(51))):
            with self.assertRaises(ValueError):
                solve_payoffs(a,b)
        with self.assertRaises(TypeError):
            solve_payoffs(np.eye(2,dtype=np.float32),np.ones(2))

    def test_nonfinite_and_bounds(self):
        for value in (np.nan,np.inf,1e6+1):
            b = np.array([value,1.])
            with self.assertRaises(ValueError):
                solve_payoffs(np.eye(2),b)

    def test_zero_target_and_one_dimension(self):
        result = solve_payoffs(np.eye(2),np.zeros(2))
        np.testing.assert_array_equal(result['units'],[0.,0.])
        self.assertEqual(result['normalized_residual_inf'],0.)
        self.assertEqual(solve_payoffs(np.array([[2.]]),np.array([6.]))['units'].shape,(1,))

    def test_source_and_output_storage(self):
        a,b = np.array([[1.,1.],[1.,2.]]),np.array([100.,150.])
        before = a.copy(),b.copy()
        result = solve_payoffs(a,b)
        np.testing.assert_array_equal(a,before[0]); np.testing.assert_array_equal(b,before[1])
        for key in ('units','residual'):
            self.assertFalse(np.shares_memory(result[key],a))
            self.assertFalse(np.shares_memory(result[key],b))

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

The sensitivity test intentionally calls the raw solver to demonstrate a case the guarded API rejects. This is an isolated numerical experiment, not a recommendation to bypass the API in an application.

## 6.12.14 Economic Review Remains Separate

After a numerical solve, inspect whether instruments exist, units are tradeable, shorting is permitted, and state payoffs are credible. If a cost or funding constraint matters, it must be supplied and modeled. This system contains no purchase prices and cannot determine a cheapest replication or an arbitrage opportunity.

An exact match on listed hypothetical states does not establish matching outcomes outside them. Sensitivity, input provenance, horizon, currency, and transaction assumptions remain part of a model review even when all numerical tests pass.

## 6.12.15 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| Square-system shape rejected | A dimensions and target rank | Supply the documented equation or choose a different task explicitly |
| Singular/ill-conditioned rejection | Redundant equations and scaling | Review model identification and uncertainty |
| Tiny residual, unstable units | Conditioning and input perturbations | Evaluate sensitivity separately |
| Negative solved units | Unconstrained linear equation | Add a deliberate feasibility model if required |
| Correct numbers assigned to wrong instruments | Column labels | Preserve label mapping outside the kernel |
| Numeric result called optimal | Missing objective/constraints | State what was solved and what was not |
| Diagnostics overflow | Magnitude and scale arithmetic | Review representation and supported bounds |
| Approximate fallback hides failure | Exception handling | Preserve failure or explicitly redefine the model |

## 6.12.17 Key Takeaways

Linear algebra solves precisely stated numerical questions. Define axes, units, and financial meaning before selecting an operation.

Check residuals and conditioning separately, preserve visible failure, and keep economic feasibility distinct from a successful solve. Small known systems and perturbation experiments provide complementary evidence.
