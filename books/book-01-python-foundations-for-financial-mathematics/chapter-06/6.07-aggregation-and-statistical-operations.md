## 6.7.1 Purpose

A reduction compresses values along an axis. The calculation becomes financially meaningful only when the entries being combined have compatible units and the reduced axis represents the intended question.

This section summarizes a synthetic scenario-by-position P&L table. It distinguishes adding positions within one scenario from describing outcomes across alternative scenarios. It supplies no scenario probabilities, forecasting claim, or calibrated risk measure.

## 6.7.2 Learning Objectives

1. Choose a reduction axis from its meaning.
2. Predict reduced shapes, including keepdims behavior.
3. Compute sums, means, extrema, and standard deviations.
4. State the denominator convention for dispersion.
5. Reject missing inputs deliberately instead of changing the sample silently.
6. Interpret numerical summaries within their units and scenario scope.

## 6.7.3 Input and Unit Contract

The source table has four alternative scenarios and two positions. Each entry is an additive same-currency price-only P&L over the same stated horizon, under the fixed-position assumptions developed in Sections 6.5–6.6.

| Scenario | Position A | Position B | Combined P&L |
|---|---|---|---|
| 0 | -100 | 40 | -60 |
| 1 | 0 | 0 | 0 |
| 2 | 100 | -40 | 60 |
| 3 | 200 | -80 | 120 |

Axis 0 means scenario and axis 1 means position. The kernel assumes identity alignment, currency compatibility, horizon, and additivity were established before entry. It cannot verify those facts from numerical values alone.

Scenarios are alternatives, not consecutive cash flows. Summing their combined P&Ls does not describe a realized account path. The table is deliberately nonsquare to make mistaken axes easier to detect.

## 6.7.4 Choose the Axis by the Question

| Expression for the (4, 2) table | Shape | Question |
|---|---|---|
| np.sum(pnl, axis=1) | (4,) | Combined position P&L within each scenario |
| np.mean(pnl, axis=0) | (2,) | Each position's arithmetic mean across listed scenarios |
| np.sum(pnl, axis=0) | (2,) | Each position summed across alternative scenarios; not used as account P&L |
| np.sum(pnl) | Scalar | All entries flattened; numerical total only |
| np.sum(pnl, axis=1, keepdims=True) | (4, 1) | Scenario totals retaining a position singleton axis |

The named axis is the axis removed by an ordinary reduction. With keepdims=True it remains with length one, which can make a later broadcast explicit. Inspect shape and meaning together; a compatible broadcast does not establish a correct interpretation.

The API returns scenario totals and per-position scenario means. It does not return a flattened aggregate as a financial result. The test's flattened sum of 120 demonstrates the mechanics only.

## 6.7.5 Descriptive Statistics of the Supplied Totals

Let t_s be the sum of positions in scenario s, and S the scenario count. This experiment defines the arithmetic mean and dispersion as:

```math
\bar t=\frac{1}{S}\sum_s t_s,\qquad
\sigma_d=\sqrt{\frac{\sum_s(t_s-\bar t)^2}{S-d}}.
```

The parameter d is ddof and is restricted here to 0 or 1, with S>d. For the supplied totals [-60, 0, 60, 120], the mean is 30 and deviations are [-90, -30, 30, 90]. Squared deviations sum to 18,000.

| Convention | Denominator | Standard deviation |
|---|---|---|
| ddof=0 | 4 | sqrt(4500), approximately 67.082039 |
| ddof=1 | 3 | sqrt(6000), approximately 77.459667 |

The default describes the listed set using ddof=0. Selecting ddof=1 changes the denominator; it does not prove that these hand-picked scenarios are an independent random sample. Nor does it make the resulting standard deviation an unbiased estimator in general.

The minimum -60 and maximum 120 are only extrema of the supplied list. They are not bounds on all possible market outcomes. The mean is an unweighted descriptive average, not an expected P&L justified by probabilities.

## 6.7.6 Aggregate First When Describing Aggregate Outcomes

For scenario totals, compute each row's sum before taking dispersion across rows. Do not sum position standard deviations as a substitute.

The counterexample uses rows [-10, 10] and [10, -10]. Both combined outcomes are zero, so their combined standard deviation is zero. Each position separately varies across the two rows, and its individual standard deviation is positive. Adding those two dispersions therefore answers a different question.

This example preserves the joint row pattern. It is a direct counterexample, not an estimate of portfolio covariance or a claim about future diversification. Later portfolio and statistics chapters develop those subjects.

## 6.7.7 Missing Data and Empty Inputs

The API requires a complete finite table with two nonempty axes. NaN, infinity, and empty axes fail. Negative values are valid because these entries are P&Ls, not nonnegative prices.

NumPy offers NaN-aware summaries such as nanmean, which omit NaNs rather than implementing this strict policy. Omitting observations changes the effective data and possibly the count used in each summary. It is not an automatic financial-data cleaning decision.

If missing-data support is added, specify whether to reject an entire scenario, exclude individual entries, impute values, or mark the result incomplete. Preserve counts and state what happens for an all-missing slice. Do not replace an uncomputed P&L with zero merely to obtain a finite report.

The single-scenario case is allowed with ddof=0 and yields zero dispersion for its one listed total. ddof=1 is rejected for that case before an invalid denominator is evaluated. A single listed outcome is not evidence of zero real-world risk.

## 6.7.8 Representation and Numerical Failure

The kernel accepts exact float64 ndarrays and uses float64 explicitly for sums, means, and standard deviation. This makes its accumulator choice visible without claiming exact decimal arithmetic.

Finite inputs can still overflow during addition or when squared deviations are formed. The tests cover both paths. Local floating-point handling raises on signaled overflow, underflow, invalid operations, or division errors, and the final check rejects nonfinite summaries.

These checks do not detect every rounding or cancellation issue. Reduction order, magnitude, and representation can affect numerical agreement. The small fixtures use exact checks where appropriate and explicit tolerances for scalar agreement; no universal error bound is claimed.

The implementation does not mutate input data. Returned reduction arrays have independent storage. It assumes no concurrent writer changes the source during execution.

## 6.7.10 File — aggregation_lab.py

```python
"""Describe a finite synthetic scenario-by-position P&L table."""
import numpy as np


def summarize(pnl: np.ndarray, *, ddof: int = 0) -> dict[str, object]:
    """Sum positions within each scenario; describe the supplied scenario set.

    Axis 0: scenarios; axis 1: additive same-currency position P&Ls.
    ddof is exact int 0 or 1, with scenario count > ddof. No probabilities,
    annualization, confidence interval, or calibrated risk claim is supplied.
    Missing/nonfinite inputs fail; no silent exclusion or zero filling.
    """
    if type(pnl) is not np.ndarray or pnl.dtype != np.dtype('float64'):
        raise TypeError('pnl must be an exact float64 ndarray')
    if pnl.ndim != 2 or 0 in pnl.shape:
        raise ValueError('pnl must be a nonempty scenario-by-position table')
    if not np.isfinite(pnl).all():
        raise ValueError('all supplied P&Ls must be finite')
    if type(ddof) is not int or ddof not in (0,1) or pnl.shape[0] <= ddof:
        raise ValueError('ddof must be 0 or 1 and smaller than scenario count')
    with np.errstate(over='raise',under='raise',invalid='raise',divide='raise'):
        totals = np.sum(pnl,axis=1,dtype=np.float64)
        position_means = np.mean(pnl,axis=0,dtype=np.float64)
        minimum = float(np.min(totals))
        maximum = float(np.max(totals))
        mean = float(np.mean(totals,dtype=np.float64))
        std = float(np.std(totals,ddof=ddof,dtype=np.float64))
    if not (np.isfinite(totals).all() and np.isfinite(position_means).all()
            and all(np.isfinite(x) for x in (minimum,maximum,mean,std))):
        raise ValueError('nonfinite summary')
    return {'totals':totals,'position_means':position_means,'minimum':minimum,
            'maximum':maximum,'mean':mean,'std':std,'ddof':ddof,
            'scenario_count':pnl.shape[0],'position_count':pnl.shape[1]}


def fixture() -> np.ndarray:
    return np.array([[-100.,40.],[0.,0.],[100.,-40.],[200.,-80.]],dtype=np.float64)


def main() -> None:
    pnl = fixture()
    result = summarize(pnl)
    print('Axes: scenario, position')
    print('Input shape:',pnl.shape)
    print('Scenario totals:',result['totals'].tolist())
    print('Position means:',result['position_means'].tolist())
    print(f'Min/max total: {result["minimum"]:.2f}, {result["maximum"]:.2f}')
    print(f'Mean total: {result["mean"]:.2f}')
    print(f'Std total (ddof=0): {result["std"]:.6f}')
    print('Totals with keepdims:',np.sum(pnl,axis=1,keepdims=True).shape)


if __name__ == '__main__':
    main()
```

The returned record names each output and includes counts and ddof. Python floats hold the scalar summaries; numerical arrays hold the scenario totals and position means. This is an in-memory teaching record, not a persistent audit bundle.

## 6.7.11 File — test_aggregation_lab.py

```python
import math
import unittest
import numpy as np
from aggregation_lab import fixture,summarize

class AggregationTests(unittest.TestCase):
    def test_known_reductions(self):
        result = summarize(fixture())
        np.testing.assert_array_equal(result['totals'],[-60.,0.,60.,120.])
        np.testing.assert_array_equal(result['position_means'],[50.,-20.])
        self.assertEqual((result['minimum'],result['maximum'],result['mean']),(-60.,120.,30.))
        self.assertAlmostEqual(result['std'],math.sqrt(4500.))
        self.assertEqual((result['scenario_count'],result['position_count']),(4,2))

    def test_scalar_reference(self):
        rows = fixture().tolist()
        totals = [sum(row) for row in rows]
        mean = sum(totals)/len(totals)
        result = summarize(fixture())
        np.testing.assert_allclose(result['totals'],totals,rtol=1e-12,atol=1e-12,equal_nan=False)
        self.assertAlmostEqual(result['std'],math.sqrt(sum((x-mean)**2 for x in totals)/len(totals)))

    def test_ddof_policy(self):
        self.assertAlmostEqual(summarize(fixture(),ddof=1)['std'],math.sqrt(6000.))
        for value in (True,1.,-1,2):
            with self.assertRaises(ValueError):
                summarize(fixture(),ddof=value)
        self.assertEqual(summarize(np.array([[1.,2.]]))['std'],0.)
        with self.assertRaises(ValueError):
            summarize(np.array([[1.,2.]]),ddof=1)

    def test_axis_and_keepdims(self):
        source = fixture()
        self.assertEqual(np.sum(source,axis=1).shape,(4,))
        self.assertEqual(np.sum(source,axis=0).shape,(2,))
        self.assertEqual(np.sum(source,axis=1,keepdims=True).shape,(4,1))
        self.assertEqual(float(np.sum(source)),120.)

    def test_missing_and_invalid_structure(self):
        for value in (np.zeros((0,2)),np.zeros((4,0)),np.array([1.,2.]),
                      np.array([[np.nan]]),np.array([[np.inf]])):
            with self.assertRaises(ValueError):
                summarize(value)
        for value in (fixture().tolist(),fixture().astype(np.float32)):
            with self.assertRaises(TypeError):
                summarize(value)

    def test_source_and_storage(self):
        source = fixture()
        before = source.copy()
        result = summarize(source)
        np.testing.assert_array_equal(source,before)
        for key in ('totals','position_means'):
            self.assertFalse(np.shares_memory(source,result[key]))

    def test_aggregate_variance_includes_joint_pattern(self):
        source = np.array([[-10.,10.],[10.,-10.]])
        self.assertEqual(summarize(source)['std'],0.)
        self.assertGreater(float(np.std(source,axis=0).sum()),0.)

    def test_overflow_and_error_restoration(self):
        before = np.geterr().copy()
        with self.assertRaises(FloatingPointError):
            summarize(np.array([[1e308,1e308],[1.,1.]]))
        with self.assertRaises(FloatingPointError):
            summarize(np.array([[1e200],[-1e200]]))
        self.assertEqual(np.geterr(),before)

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

## 6.7.13 Extensions Need Their Own Contracts

For weighted scenarios, require explicit nonnegative probabilities or weights and define normalization, zero-weight treatment, and missing-data interaction. Replacing mean with another function without documenting those decisions changes the question silently.

For time-series returns, distinguish descriptive observations from modeled future outcomes and state interval conventions. A standard deviation of same-currency P&L has currency units; it is not automatically percentage-return volatility. Variance would have squared currency units.

For percentile summaries, document the sample, axis, and interpolation/method choice before attaching a financial risk label. This section intentionally calculates no VaR, expected shortfall, confidence interval, or significance test.

## 6.7.14 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| Received one total instead of one per scenario | Omitted axis | Reduce positions explicitly with axis=1 |
| Received position-length output | Reduced scenario axis | Match axis to the intended question |
| Downstream broadcast follows wrong dimension | Lost axis | Inspect rank and use keepdims deliberately |
| ddof fails on one row | Scenario count and denominator | Choose a valid convention; do not suppress the error |
| Mean changes after missing-data filtering | Effective sample/count | Document the exclusion policy |
| Portfolio dispersion equals sum of individual values | Wrong aggregation order | Sum within scenario before describing totals |
| Finite inputs raise | Reduction or squared-deviation overflow | Review bounds and numerical representation |
| Scenario mean called expected profit | Missing probability/model assumptions | Keep the descriptive claim explicit |

## 6.7.16 Key Takeaways

Reduction axes encode the question being asked. Preserve units, labels, counts, and the distinction between adding positions and describing alternative scenarios.

Statistical conventions and missing-data policy are application decisions. Test known answers, denominator boundaries, joint patterns, and numerical failures before interpreting a concise summary as a financial conclusion.
