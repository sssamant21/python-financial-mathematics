## 6.14.1 Purpose

A finite, reproducible number can still lose information or fail an application's accuracy requirement. Precision review must examine representation, operation order, magnitude, numerical formulation, and comparison policy.

This section runs small deterministic experiments rather than claiming one dtype or tolerance solves every financial calculation. It extends the return-linking example with a numerically useful formulation and compares it with an independently constructed high-precision reference.

## 6.14.2 Learning Objectives

1. Distinguish floating-point spacing from an application tolerance.
2. Demonstrate irreversible cast loss and order-sensitive addition.
3. Use log1p/expm1 for a supported small-change calculation.
4. Require explicit shape, finite-value, and tolerance policies when comparing results.
5. Separate numerical agreement from monetary rounding and financial materiality.
6. State limitations of a more stable formulation without presenting it as exact arithmetic.

## 6.14.3 Precision, Range, and Spacing

float64 has finite precision and finite range. np.finfo reports properties of the representation; its eps describes the distance from 1 to the next larger representable value. It is not a uniform error allowance for every magnitude or algorithm.

np.spacing examines local spacing. Near 1e16, the spacing exceeds 1, and adding 1 to that float64 value does not change the stored result. The test demonstrates the lost increment directly.

A larger dtype cannot recover information already discarded by a smaller one. Converting integer 16,777,217 through float32 and back to int64 produces 16,777,216 in the fixture. Keep identifiers and exact counts out of floating conversions unless their supported range is deliberate.

Changing a displayed number of decimal places changes presentation, not the stored representation or the accuracy of previous operations.

## 6.14.4 Addition Order and Cancellation

The test compares (1e16+1)+(-1e16) with (1e16+(-1e16))+1. The first gives 0 and the second gives 1 in the tested representation. Algebraic associativity does not guarantee floating-point associativity.

math.fsum gives 1 for the same three supplied floats and is useful as a separate scalar accumulation reference for this fixture. It is not an exact-decimal accounting engine or a universal replacement for every array reduction.

NumPy reductions can use different accumulation strategies depending on operation, layout, and axis. Do not require bitwise agreement between every summation route merely because the real-number formulas agree. Conversely, do not loosen a tolerance to hide a real logic error.

For financial netting, small residuals among large positive and negative amounts deserve particular review. Finiteness and plausible formatted cents do not establish that economically important low-order information survived.

## 6.14.5 A Small Linked-Return Experiment

For simple returns r_i greater than -1, the mathematical linked return is:

```math
R=\prod_i(1+r_i)-1
 =\exp\!\left(\sum_i\log(1+r_i)\right)-1.
```

For small changes, NumPy's log1p(r) and expm1(x) are designed to evaluate log(1+r) and exp(x)-1 without first discarding the small increment through ordinary addition/subtraction near one.

The lab uses three returns of 1e-17. In the direct expression, 1+1e-17 rounds to 1, so the product-minus-one is 0. The log1p/expm1 route returns approximately 3e-17. A Decimal calculation at precision 60, initialized from explicit decimal text, supplies an independent reference for that synthetic case.

This demonstrates one benefit on a chosen fixture. It does not prove the transformed method always has lower error, avoids every overflow, or produces exact decimal results. Summation still rounds, the exponential can overflow, and a result very close to -1 can lose relative information about its gross factor.

## 6.14.6 Supported Return Domain

linked_return accepts 1–10000 finite one-dimensional float64 entries in [-0.5,0.5]. This narrower teaching domain is deliberate; it is not a universal return restriction and does not silently clip unsupported data.

The function computes expm1(sum(log1p(returns))) under local signal handling and checks the scalar result is finite. Long positive paths can still overflow, and that failure is tested. Local settings restore the caller's error policy after failure.

The calculation inherits Section 6.9's consecutive-interval price-only interpretation. It introduces no annualization, cash-flow, distribution, or rebalancing convention. It does not replace Section 6.9's retained gross-factor vector for every use case.

## 6.14.7 Explicit Comparison Criteria

The agrees helper requires equal-shape finite float64 vectors and explicit tolerances. It uses the reference vector to set the relative scale:

```math
|a-b|\leq\mathrm{atol}+\mathrm{rtol}|b|.
```

| Parameter | Meaning | Review question |
|---|---|---|
| atol | Absolute error allowance in output units | What near-zero discrepancy can be accepted? |
| rtol | Relative allowance based on the reference | What proportional discrepancy can be accepted? |
| reference | Chosen comparison baseline | Is it independently trustworthy? |
| shape | Required matching structure | Would broadcasting hide a wrong output? |
| finite policy | NaN/infinity rejected | Is this a complete numerical result? |

The helper accepts exact Python float tolerances in [0,1] and input magnitudes up to 1e100. These are defensive lab boundaries, not NumPy-wide requirements. It rejects NaN and infinity before comparison, so matching invalid outputs cannot masquerade as success.

The isclose criterion is reference-oriented; exchanging arguments can change a relative comparison. The lab names that role rather than assuming a symmetric error metric.

## 6.14.8 Near Zero and Financial Materiality

On the tested defaults, np.isclose(1e-9,0) is true because the default absolute tolerance dominates. With rtol=0 and atol=1e-12, the explicit helper returns false. Neither setting is universally correct: the appropriate choice depends on output units and consequences.

A tolerance for a dimensionless return differs from a tolerance for a currency amount, instrument quantity, or solver residual. Document units and the justification. A tolerance chosen to accept all existing test failures has no independent meaning.

Numerical tolerance, display rounding, accounting rounding, and financial materiality are separate decisions. A model can meet a software comparison criterion while still failing its business requirement. Review known-answer and invariant checks before interpreting approximate agreement.

## 6.14.9 Exact Arithmetic and Input Provenance

Use explicit decimal text when constructing a decimal reference for intended decimal values. Converting an already approximated float does not reconstruct the original text or its exact intended amount.

Decimal and scaled integers can support deliberately exact monetary policies within their own bounds, contexts, and rounding stages. An object array containing Decimal values does not automatically behave like a native float64 analytical kernel in performance or storage.

A high-precision reference is evidence only for the calculation and inputs it actually represents. Precision cannot repair wrong units, misaligned identifiers, missing cash flows, or an economically incorrect formula.

## 6.14.11 File — precision_lab.py

```python
"""Small numerical experiments with explicit domains and comparison rules."""
import numpy as np


def linked_return(returns: np.ndarray) -> float:
    """Compute expm1(sum(log1p(r))) for a bounded simple-return vector.

    1–10000 finite float64 entries in [-0.5, 0.5]. No annualization or cash flows.
    Raises on signaled arithmetic errors; no guarantee for arbitrary magnitudes.
    """
    if type(returns) is not np.ndarray or returns.dtype != np.dtype('float64'):
        raise TypeError('returns must be an exact float64 ndarray')
    if returns.ndim != 1 or not 1 <= returns.size <= 10000:
        raise ValueError('expected 1 to 10000 returns')
    if not np.isfinite(returns).all() or (np.abs(returns) > .5).any():
        raise ValueError('returns must be finite and in [-0.5, 0.5]')
    with np.errstate(over='raise',under='raise',invalid='raise',divide='raise'):
        result = float(np.expm1(np.sum(np.log1p(returns),dtype=np.float64)))
    if not np.isfinite(result):
        raise ValueError('nonfinite linked return')
    return result


def agrees(actual: np.ndarray, reference: np.ndarray, *, rtol: float, atol: float) -> bool:
    """Compare same-shape finite float64 vectors; reference sets relative scale.

    Entries abs <= 1e100; exact float tolerances in [0,1]. No broadcasting or NaNs.
    This is a numerical predicate, not a financial-materiality decision.
    """
    for value in (actual,reference):
        if type(value) is not np.ndarray or value.dtype != np.dtype('float64'):
            raise TypeError('expected exact float64 arrays')
        if value.ndim != 1 or value.size == 0:
            raise ValueError('expected nonempty vectors')
        if not np.isfinite(value).all() or (np.abs(value) > 1e100).any():
            raise ValueError('comparison inputs outside finite lab bounds')
    if actual.shape != reference.shape:
        raise ValueError('comparison shapes must match')
    if any(type(x) is not float or not np.isfinite(x) or not 0 <= x <= 1 for x in (rtol,atol)):
        raise ValueError('tolerances must be finite exact floats in [0,1]')
    return bool(np.isclose(actual,reference,rtol=rtol,atol=atol,equal_nan=False).all())


def main() -> None:
    tiny = np.full(3,1e-17,dtype=np.float64)
    naive = float(np.prod(1.+tiny)-1.)
    stable = linked_return(tiny)
    print(f'float64 epsilon near 1: {np.finfo(np.float64).eps:.6e}')
    print(f'Naive tiny linked return: {naive:.6e}')
    print(f'log1p/expm1 tiny linked return: {stable:.6e}')
    print('Default near-zero isclose:',bool(np.isclose(1e-9,0.)))
    print('Explicit near-zero agreement:',agrees(np.array([1e-9]),np.array([0.]),rtol=0.,atol=1e-12))


if __name__ == '__main__':
    main()
```

The numerical predicate returns a boolean only after enforcing its structure/domain contract. It does not assign a universal accuracy policy to callers. The functions do not modify source arrays.

## 6.14.12 File — test_precision_lab.py

```python
from decimal import Decimal,localcontext
import math
import unittest
import numpy as np
from precision_lab import agrees,linked_return

class PrecisionTests(unittest.TestCase):
    def test_tiny_return_decimal_reference(self):
        values = np.full(3,1e-17)
        with localcontext() as context:
            context.prec = 60
            expected = float((Decimal(1)+Decimal('1e-17'))**3-Decimal(1))
        self.assertEqual(float(np.prod(1.+values)-1.),0.)
        self.assertTrue(math.isclose(linked_return(values),expected,rel_tol=1e-15,abs_tol=0.))

    def test_ordinary_and_zero_returns(self):
        self.assertAlmostEqual(linked_return(np.array([.1,-.1,.1])),.089)
        self.assertEqual(linked_return(np.zeros(3)),0.)

    def test_tolerance_scale(self):
        self.assertTrue(bool(np.isclose(1e-9,0.)))
        self.assertFalse(agrees(np.array([1e-9]),np.array([0.]),rtol=0.,atol=1e-12))
        self.assertTrue(agrees(np.array([100.000001]),np.array([100.]),rtol=1e-7,atol=0.))
        with self.assertRaises(ValueError):
            agrees(np.array([1.,1.]),np.array([1.]),rtol=0.,atol=0.)

    def test_invalid_comparisons(self):
        for bad in (np.array([np.nan]),np.array([np.inf])):
            with self.assertRaises(ValueError):
                agrees(bad,np.array([0.]),rtol=0.,atol=0.)
        for tolerance in (True,-1.,float('nan'),2.):
            with self.assertRaises(ValueError):
                agrees(np.array([1.]),np.array([1.]),rtol=tolerance,atol=0.)

    def test_cast_loss_and_spacing(self):
        source = np.array([16777217],dtype=np.int64)
        self.assertEqual(int(source.astype(np.float32).astype(np.int64)[0]),16777216)
        self.assertGreater(float(np.spacing(np.float64(1e16))),1.)
        self.assertEqual(np.float64(1e16)+np.float64(1.),np.float64(1e16))

    def test_accumulation_order(self):
        a,b,c = 1e16,1.,-1e16
        self.assertEqual((a+b)+c,0.)
        self.assertEqual((a+c)+b,1.)
        self.assertEqual(math.fsum([a,b,c]),1.)

    def test_return_domain_and_storage(self):
        for values in (np.array([-.5001]),np.array([np.nan]),np.array([]),np.array([[.1]])):
            with self.assertRaises(ValueError):
                linked_return(values)
        with self.assertRaises(TypeError):
            linked_return(np.array([0,1]))
        source = np.array([.1,-.1])
        before = source.copy()
        linked_return(source)
        np.testing.assert_array_equal(source,before)

    def test_overflow_restores_settings(self):
        before = np.geterr().copy()
        with self.assertRaises(FloatingPointError):
            linked_return(np.full(10000,.5))
        self.assertEqual(np.geterr(),before)

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

## 6.14.14 A Practical Review Procedure

First validate identities, units, timing, and formula. Then inspect dtype, bounds, intermediate operations, and possible cancellation or extreme ratios. Choose independent known values or a suitably constructed high-precision reference.

State absolute/relative comparison rules in output units and check shape and finiteness separately. Exercise boundary and failure cases. Record environment and algorithm details when the result must be reproduced, including any reduction-order assumptions.

If an error persists, diagnose its source before increasing precision or relaxing criteria. The root cause may be representation, algorithm, conditioning, data, or the financial model itself.

## 6.14.15 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| Tiny linked change becomes zero | Addition/subtraction near one | Consider log1p/expm1 under a supported domain |
| Larger dtype preserves wrong value | Earlier narrowing conversion | Preserve original representation before loss |
| Close-to-zero error passes unexpectedly | Absolute tolerance | Justify a scale-aware explicit policy |
| Different sum routes disagree | Magnitude and accumulation order | Compare against independent evidence, not formatted output |
| NaN values compare as acceptable | Missing-data/finiteness policy | Reject incomplete results explicitly |
| Stable formulation overflows | Output/intermediate magnitude | Review bounds and failure semantics |
| Two decimal places called exact money | Display versus arithmetic | Define a monetary representation and rounding policy |
| Tolerance widened repeatedly | Unexplained failures | Diagnose formula, alignment, and numerical source first |

## 6.14.17 Key Takeaways

Precision depends on representation, scale, algorithm, and operation order. More careful formulas can preserve small information without providing exact or unlimited arithmetic.

Use independent references and explicit comparison policies. Keep numerical agreement, accounting rules, and financial materiality distinct and reviewable.
