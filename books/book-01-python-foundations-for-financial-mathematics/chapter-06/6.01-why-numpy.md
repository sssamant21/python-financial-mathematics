## 6.1.1 Purpose

The first five chapters established explicit inputs, reusable functions, validation, and reproducible environments. NumPy adds an array-based vocabulary for applying numerical operations across observations and scenarios. Those engineering habits still apply.

This section motivates arrays through a small synthetic price-change calculation. It introduces the benefit and the obligations together: a compact expression needs explicit shape, dtype, alignment, units, and comparison rules.

## 6.1.2 Learning Objectives

1. Explain why numerical workloads use arrays.
2. Contrast Python sequence operations with elementwise arithmetic.
3. Identify shape, dtype, and positional alignment as separate contracts.
4. Check a numerical implementation against a scalar reference and known answer.
5. Recognize when ordinary Python structures or Decimal remain appropriate.
6. Avoid unsupported performance and precision claims.

## 6.1.3 What NumPy Contributes

NumPy provides multidimensional arrays and numerical operations. Many numeric operations execute in compiled implementations, reducing repeated Python-level dispatch. It also supplies a common array interface used throughout scientific Python.

For this book, the central benefit is an explicit representation of numerical structure. A vector can represent one observation per instrument; a table can represent time by instrument; a scenario matrix can represent scenario by exposure. Assign those meanings before calculating.

| Workload | Possible representation | Question to settle first |
|---|---|---|
| One price per instrument | One-dimensional array | Which instrument occupies each position? |
| Prices across dates | Two-dimensional array | Are rows dates or instruments? |
| Scenario outcomes | Scenario-by-instrument array | Which axis does each parameter apply to? |
| Heterogeneous security metadata | Dictionaries or records alongside numeric data | How are identifiers aligned? |

Array shape captures dimensions, not business meaning. An array of length three cannot tell whether its entries are prices, quantities, rates, or dates. Documentation and validation must supply that meaning.

## 6.1.4 Lists and Arrays Express Different Operations

Python lists remain useful for collecting records and mixed metadata. Repeating a list does not multiply its numerical entries. For example, `[2, 4] * 2` produces `[2, 4, 2, 4]`. An integer array with the same entries multiplied by 2 produces numerical entries 4 and 8.

Similarly, adding lists concatenates them, whereas adding compatible numeric arrays performs elementwise arithmetic. Choose the representation that matches the intended operation. A change from list to array can change program semantics even when the printed values initially look similar.

An array's dtype defines its element representation. This lab explicitly uses float64 and rejects object, integer, boolean, and float32 inputs. That strict teaching policy keeps conversion decisions visible. It is not a universal requirement for every NumPy API.

## 6.1.5 A Small Financial Question

For three synthetic assets, compare start and end prices in the same currency and per-unit convention. For each position define the price-only fractional change:

\[
r_i = \frac{P_{i,\mathrm{end}}}{P_{i,\mathrm{start}}} - 1.
\]

This is the definition used by the experiment. Dividends, fees, FX movements, corporate actions, and differing observation intervals are excluded. The output is not annualized and does not claim to be total investment return.

| Identifier | Start price | End price | Expected fractional change |
|---|---|---|---|
| ASSET-A | 100.00 | 105.00 | 0.05 |
| ASSET-B | 80.00 | 76.00 | -0.05 |
| ASSET-C | 50.00 | 50.00 | 0.00 |

The caller is responsible for aligning both arrays to this identifier order. Equal shapes cannot detect that end prices were accidentally sorted differently. Keep identifiers alongside numerical arrays and validate alignment at the ingestion boundary.

## 6.1.6 Vectorization and Broadcasting

The expression `end / start - 1.0` applies the same transformation across aligned prices. This is vectorized array arithmetic: the operation is expressed over arrays rather than written as a Python loop over positions.

NumPy can also combine certain unequal shapes through broadcasting. This lab deliberately requires equal nonempty one-dimensional shapes, preventing an unintended broadcast from silently changing the question. Later sections develop the general rules.

Vectorization does not mean there is no iteration internally, that all work uses multiple CPU cores, or that a GPU is involved. It also does not automatically validate units or missing values. A short expression can still implement the wrong model.

## 6.1.7 Numerical Policy

float64 is a binary floating-point representation. The lab uses it for approximate analytical ratios and tests small known results with explicit tolerances. It does not promise exact decimal accounting arithmetic.

The API requires finite prices, strictly positive starts, and nonnegative ends. An end price of zero is valid and gives -1.0. Missing prices are rejected rather than filled with zero. A zero start is rejected rather than interpreted as an infinite valid return.

The calculation raises on overflow, divide-by-zero, and invalid arithmetic inside a local errstate context. Underflow is explicitly ignored: an extremely small end/start ratio may collapse to zero and yield -1.0 at available precision. This is a limitation of the chosen representation, not evidence that a tiny positive price was literally zero. Precision-sensitive applications need additional bounds or another numerical policy.

Return comparisons here use rtol=1e-12 and atol=1e-12, with NaNs disallowed. This is a teaching tolerance for the small known examples, not a general financial materiality threshold. Shape and dtype are checked separately. Comparison tolerances must suit the scale and consequences of the calculation.

## 6.1.9 File — numpy_motivation.py

```python
"""Array-based synthetic price changes with explicit positional contracts."""
import numpy as np


def price_returns(start: np.ndarray, end: np.ndarray) -> np.ndarray:
    """Return end/start - 1 for aligned one-dimensional float64 prices.

    Prices share currency and units; start > 0, end >= 0, all finite.
    No dividends, fees, FX, annualization, or missing-price imputation.
    Caller must align instrument identifiers before passing arrays.
    """
    for name, value in (('start', start), ('end', end)):
        if type(value) is not np.ndarray:
            raise TypeError(f'{name} must be an exact ndarray')
        if value.dtype != np.dtype('float64'):
            raise TypeError(f'{name} must have float64 dtype')
        if value.ndim != 1 or value.size == 0:
            raise ValueError(f'{name} must be a nonempty one-dimensional array')
        if not np.isfinite(value).all():
            raise ValueError(f'{name} must contain finite prices')
    if start.shape != end.shape:
        raise ValueError('price arrays must have equal shape')
    if (start <= 0).any() or (end < 0).any():
        raise ValueError('start must be positive and end nonnegative')
    with np.errstate(over='raise', divide='raise', invalid='raise', under='ignore'):
        result = end / start - 1.0
    if not np.isfinite(result).all():
        raise ValueError('nonfinite result')
    return result


def main() -> None:
    ids = ('ASSET-A', 'ASSET-B', 'ASSET-C')
    start = np.array([100.0, 80.0, 50.0], dtype=np.float64)
    end = np.array([105.0, 76.0, 50.0], dtype=np.float64)
    result = price_returns(start, end)
    reference = [finish / begin - 1.0 for begin, finish in zip(start.tolist(), end.tolist())]
    np.testing.assert_allclose(result, reference, rtol=1e-12, atol=1e-12, equal_nan=False)
    for sid, change in zip(ids, result):
        print(f'{sid}: {change:.2%}')
    print('Shape:', result.shape)
    print('Dtype:', result.dtype)


if __name__ == '__main__':
    main()
```

The function returns a new result and preserves inputs. Type hints are documentation, while the body enforces the supported runtime contract. The exact-ndarray check intentionally excludes subclasses, including specialized array types whose behavior could differ.

The scalar reference converts the already validated example arrays to Python lists and performs the same formula position by position. Agreement is useful implementation evidence; the independently derived expected values in the tests provide an additional check.

## 6.1.10 File — test_numpy_motivation.py

```python
import unittest
import numpy as np
from numpy_motivation import price_returns


class MotivationTests(unittest.TestCase):
    def test_known_values_and_shape(self):
        actual = price_returns(np.array([100.,80.,50.]), np.array([105.,76.,50.]))
        self.assertEqual(actual.shape, (3,))
        self.assertEqual(actual.dtype, np.dtype('float64'))
        np.testing.assert_allclose(actual, [.05,-.05,0.], rtol=1e-12, atol=1e-12, equal_nan=False)

    def test_scalar_reference(self):
        start = np.array([4.,8.,16.,32.])
        end = np.array([5.,6.,16.,40.])
        expected = [b/a-1 for a,b in zip(start.tolist(),end.tolist())]
        np.testing.assert_allclose(price_returns(start,end), expected,
                                   rtol=1e-12, atol=1e-12, equal_nan=False)

    def test_no_mutation_or_alias(self):
        start,end = np.array([2.,4.]),np.array([3.,5.])
        before = (start.copy(),end.copy())
        result = price_returns(start,end)
        np.testing.assert_array_equal(start,before[0])
        np.testing.assert_array_equal(end,before[1])
        self.assertFalse(np.shares_memory(result,start))
        self.assertFalse(np.shares_memory(result,end))

    def test_zero_end_price(self):
        np.testing.assert_array_equal(price_returns(np.array([10.]),np.array([0.])),[-1.])

    def test_shape_prevents_broadcasting(self):
        for end in (np.array([1.]),np.array([[1.,2.]]),np.array([])):
            with self.assertRaises(ValueError):
                price_returns(np.array([1.,2.]),end)

    def test_types_and_dtypes(self):
        for start in ([1.],np.array([1]),np.array([True]),np.array([1.],dtype=np.float32),
                      np.array([1.],dtype=object)):
            with self.assertRaises(TypeError):
                price_returns(start,np.array([2.]))

    def test_domain_and_nonfinite(self):
        for start,end in (([0.],[1.]),([-1.],[1.]),([1.],[-1.]),
                          ([np.nan],[1.]),([1.],[np.inf])):
            with self.assertRaises(ValueError):
                price_returns(np.array(start),np.array(end))

    def test_overflow_fails_and_settings_restored(self):
        before = np.geterr().copy()
        with self.assertRaises(FloatingPointError):
            price_returns(np.array([1e-300]),np.array([1e300]))
        self.assertEqual(np.geterr(),before)


if __name__ == '__main__':
    unittest.main(verbosity=2)
```

## 6.1.12 Performance: A Question to Measure

NumPy can be useful when the same arithmetic is applied across many numerical entries. For a three-element demonstration, clarity and correctness are the point; no speed advantage is claimed or measured.

A later benchmark should compare equivalent work, include or deliberately exclude conversion costs, verify output agreement first, repeat measurements, and record hardware and software context. Separate one-time setup from repeated computation. Section 6.15 addresses computational performance in more detail.

Array expressions may allocate intermediate arrays and outputs. A shape mistake can create far more data than intended. Evaluate peak memory as well as time when increasing dataset or scenario size. Do not infer whole-program memory use from the payload size of one array.

## 6.1.13 Choosing the Tool

| Situation | Reasonable starting point | Design consideration |
|---|---|---|
| Repeated numerical operations over aligned observations | NumPy numeric arrays | Shape, dtype, finite values, units |
| Small heterogeneous records | Python dictionaries/lists | Schema and identity |
| Exact decimal monetary policy | Decimal or a deliberately scaled integer design | Rounding stages, bounds, overflow |
| Labeled tabular alignment | Explicit identity mapping; later pandas | Join and missing-data policy |
| A few scalar calculations | Ordinary Python functions | Simplicity and validation |

These tools can coexist. Validate records and identifiers in ordinary Python, then pass deliberate numeric arrays to an analytical kernel. Using an object array of Decimal instances does not automatically provide the performance characteristics of native numeric array operations.

## 6.1.14 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| No module named numpy | Selected interpreter/environment | Install through that interpreter's -m pip |
| Attribute errors from local numpy.py | Import origin and filename | Rename the conflicting local file |
| Wrong numerical pairing | Identifier order | Align records before forming arrays |
| Shape error | One-dimensional equal-length contract | Correct data organization explicitly |
| Dtype error | Integer/object/float32 construction | Choose and validate conversion at the boundary |
| NaN or infinity rejected | Missing or invalid price input | Resolve data policy; do not silently coerce |
| Overflow exception | Ratio magnitude | Review bounds and representation |
| Rounded display looks exact | Presentation versus stored value | Inspect numerical comparisons and policy |

## 6.1.16 Key Takeaways

NumPy helps express repeated numerical operations through arrays. A useful array calculation still needs shape, dtype, alignment, units, domain validation, and numerical checks.

Choose arrays for a clear computational reason. Keep the explicit financial contracts and reproducibility habits developed in earlier chapters as the code becomes more compact.
