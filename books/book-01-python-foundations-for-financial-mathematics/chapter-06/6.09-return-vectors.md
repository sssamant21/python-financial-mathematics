## 6.9.1 Purpose

A price vector describes observations; a return vector describes intervals between observations. Keeping that distinction explicit prevents off-by-one labeling and incorrect aggregation across time.

This section calculates synthetic price-only interval returns and linked growth for one asset. It builds on the one-interval example in Section 6.1 and the timing discipline of Section 6.8. It does not estimate expected returns or investment risk.

## 6.9.2 Learning Objectives

1. Derive N-1 interval returns from N prices.
2. Carry start and end timing labels with each return.
3. Distinguish simple returns, gross factors, and linked growth.
4. Demonstrate why adding interval simple returns does not generally give the linked return.
5. Validate prices, chronology, representation, and numerical results.
6. State the exclusions and limits of price-only calculations.

## 6.9.3 Price and Timing Contract

The input describes one asset using consistently defined, same-currency per-unit prices. Periods are integer offsets in one caller-defined unit, strictly increasing within [0, 1000000]. Prices are finite and strictly positive float64 values. There must be 2–10000 aligned observations.

| Observation offset | Price | Interval ending here | Simple price change |
|---|---|---|---|
| 0 | 100.00 | None | None |
| 1 | 110.00 | 0 to 1 | 10% |
| 3 | 99.00 | 1 to 3 | -10% |
| 4 | 108.90 | 3 to 4 | 10% |

There is no return before the first observation. The implementation does not prepend a zero, which would invent an additional interval observation.

Offsets are not parsed calendar dates or day-count fractions. The gap from 1 to 3 remains explicit. It produces one observed endpoint return over that interval, not two fabricated one-period returns. Completeness, corporate-action consistency, identity, currency, and quote conventions remain caller responsibilities.

## 6.9.4 Define Gross and Simple Returns

For adjacent positive prices P_(k-1) and P_k, this experiment defines:

\[
g_k=\frac{P_k}{P_{k-1}},\qquad r_k=g_k-1.
\]

The gross factor g is dimensionless; the simple return r is a fractional change. A stored 0.10 displays as 10%, while a gross factor of 1.10 describes the same interval ratio.

The vectorized expressions are `prices[1:] / prices[:-1]` and `gross - 1.0`. Each slice contains N-1 entries. Output interval labels are `periods[:-1]` and `periods[1:]`, respectively.

These are price-only returns. Dividends, coupons, fees, external investor cash flows, FX effects, and financing are not added. A distribution or split can require a deliberate adjusted-data or cash-flow convention. Do not mix raw and adjusted prices and call the result comparable performance.

## 6.9.5 Link Across Consecutive Observed Intervals

Define growth from the first supplied price through interval k as:

\[
G_k=\prod_{j=1}^{k}g_j,\qquad R_{0,k}=G_k-1.
\]

For the example, gross factors are 1.10, 0.90, and 1.10. Linked growth is 1.10, 0.99, and 1.089, giving a final price-only return of 8.9%. The sum of simple returns is 10%, which is a different calculation.

Adjacent ratios telescope algebraically, so linked growth should agree with P_k/P_0 under the stated single-asset price-only contract. The tests compare both routes with a tolerance; finite-precision operation order can produce small differences.

The implementation applies np.cumprod to gross factors directly. It does not reconstruct them with 1+simple after subtracting one, which could discard information for very small positive ratios. No initial growth entry of one is returned; every growth entry aligns with an actual interval end.

## 6.9.6 Irregular Intervals and Interpretation

Changing offsets from [0, 1, 3, 4] to [0, 10, 30, 40] while retaining prices changes interval timing but not these endpoint ratios. The output labels record that change. No per-unit-time normalization occurs.

Comparing interval means or dispersion across unequal durations requires another statistical and timing contract. An array of three returns is not automatically a daily or annual series. Do not annualize by assuming a frequency that was never established.

This path is also different from a cross-sectional return vector of several instruments over one common interval. The same one-dimensional shape can represent either structure, so meaning must remain in the API and labels. This section handles time intervals for one asset only.

## 6.9.7 Zero, Missing, and Negative Prices

The API rejects zero prices everywhere, including the final observation, to preserve a strictly positive path contract. A separate design could permit a terminal zero and a final -100% return, while still rejecting a zero denominator. That extension needs explicit terminal-event handling and tests.

Negative quotes occur in some specialized markets, but ordinary positive-price relative-return assumptions do not apply automatically. This function deliberately excludes them rather than pretending one formula serves every instrument.

NaN and infinity fail. Dropping a missing middle price changes the interval from adjacent observations to a longer bridge. If bridging is intended, preserve the longer labels and document the policy. Filling a missing price with zero or forward-filling without explanation changes the financial data.

## 6.9.8 Numerical and Storage Policy

The kernel requires exact int64 timing and float64 price arrays without implicit casting. It checks nonempty aligned vectors, bounds, and strictly increasing periods before division.

Local floating-point handling raises on signaled overflow, underflow, divide, or invalid operations. Final finite checks supplement that policy. Finite positive prices alone do not guarantee representable ratios or linked products.

Float64 is approximate. A very small positive gross factor can yield a simple return rounded to -1.0 after subtraction, even though the original ratio was positive. The separately retained gross vector avoids treating the displayed simple return as sufficient evidence of an exact terminal loss. Signal checks do not detect every cancellation or precision limitation.

The output timing labels are copies, and calculated vectors do not share input storage. Mutating one returned vector does not recompute the others. Recalculate from the intended source path after edits.

## 6.9.10 File — return_vectors.py

```python
"""Build interval-aligned price-only returns for one synthetic asset."""
import numpy as np


def return_path(periods: np.ndarray, prices: np.ndarray) -> dict[str, np.ndarray]:
    """Return interval endpoints, gross/simple returns, and linked growth.

    2–10000 strictly increasing int64 offsets in [0,1000000]; finite strictly
    positive float64 prices. Caller supplies one consistently adjusted asset,
    currency/unit convention, and complete observations. No distributions,
    fees, external cash flows, FX, annualization, or calendar inference.
    """
    if type(periods) is not np.ndarray or periods.dtype != np.dtype('int64'):
        raise TypeError('periods must be an exact int64 ndarray')
    if type(prices) is not np.ndarray or prices.dtype != np.dtype('float64'):
        raise TypeError('prices must be an exact float64 ndarray')
    if periods.ndim != 1 or prices.ndim != 1 or periods.shape != prices.shape:
        raise ValueError('periods and prices must be equal-shape vectors')
    if not 2 <= prices.size <= 10000:
        raise ValueError('expected 2 to 10000 price observations')
    if (periods < 0).any() or (periods > 1000000).any() or (periods[1:] <= periods[:-1]).any():
        raise ValueError('periods must be increasing within lab bounds')
    if not np.isfinite(prices).all() or (prices <= 0).any():
        raise ValueError('prices must be finite and strictly positive')
    with np.errstate(over='raise',under='raise',invalid='raise',divide='raise'):
        gross = prices[1:] / prices[:-1]
        simple = gross - 1.0
        growth = np.cumprod(gross,dtype=np.float64)
    if not all(np.isfinite(x).all() for x in (gross,simple,growth)):
        raise ValueError('nonfinite return output')
    return {'start_periods':periods[:-1].copy(),'end_periods':periods[1:].copy(),
            'gross':gross,'simple':simple,'growth':growth}


def main() -> None:
    periods = np.array([0,1,3,4],dtype=np.int64)
    prices = np.array([100.,110.,99.,108.9],dtype=np.float64)
    result = return_path(periods,prices)
    print('Intervals:',list(zip(result['start_periods'].tolist(),result['end_periods'].tolist())))
    print('Simple returns:',[f'{x:.2%}' for x in result['simple']])
    print('Growth from first price:',[f'{x:.6f}' for x in result['growth']])
    print(f'Linked price-only return: {result["growth"][-1]-1:.2%}')
    print(f'Sum of simple returns: {result["simple"].sum():.2%}')


if __name__ == '__main__':
    main()
```

The application prints interval tuples before percentages to make the labeling visible. The sum of returns is printed only as a deliberate comparison, not as a supported substitute for linked performance.

## 6.9.11 File — test_return_vectors.py

```python
import unittest
import numpy as np
from return_vectors import return_path


def inputs():
    return np.array([0,1,3,4],dtype=np.int64),np.array([100.,110.,99.,108.9])

class ReturnTests(unittest.TestCase):
    def test_known_path_and_alignment(self):
        result = return_path(*inputs())
        np.testing.assert_array_equal(result['start_periods'],[0,1,3])
        np.testing.assert_array_equal(result['end_periods'],[1,3,4])
        np.testing.assert_allclose(result['simple'],[.1,-.1,.1],rtol=1e-12,atol=1e-12,equal_nan=False)
        np.testing.assert_allclose(result['growth'],[1.1,.99,1.089],rtol=1e-12,atol=1e-12,equal_nan=False)
        self.assertAlmostEqual(float(result['simple'].sum()),.1)
        self.assertAlmostEqual(float(result['growth'][-1]-1),.089)

    def test_scalar_and_endpoint_references(self):
        periods,prices = inputs()
        values = prices.tolist()
        gross = [b/a for a,b in zip(values[:-1],values[1:])]
        product,expected = 1.,[]
        for value in gross:
            product *= value
            expected.append(product)
        result = return_path(periods,prices)
        np.testing.assert_allclose(result['growth'],expected,rtol=1e-12,atol=1e-12,equal_nan=False)
        np.testing.assert_allclose(result['growth'],prices[1:]/prices[0],rtol=1e-12,atol=1e-12,equal_nan=False)

    def test_constant_and_single_interval(self):
        result = return_path(np.array([0,5],dtype=np.int64),np.array([7.,7.]))
        self.assertEqual(result['simple'].shape,(1,))
        np.testing.assert_array_equal(result['simple'],[0.])
        np.testing.assert_array_equal(result['growth'],[1.])

    def test_timing_not_annualized(self):
        result = return_path(np.array([0,10,30,40],dtype=np.int64),inputs()[1])
        np.testing.assert_array_equal(result['simple'],return_path(*inputs())['simple'])
        np.testing.assert_array_equal(result['end_periods'],[10,30,40])

    def test_period_contract(self):
        for value in ([0,1,1,4],[0,3,1,4],[-1,1,3,4],[0,1,3,1000001]):
            with self.assertRaises(ValueError):
                return_path(np.array(value,dtype=np.int64),inputs()[1])
        for periods,prices in ((np.array([0],dtype=np.int64),np.array([1.])),
                               (inputs()[0],np.array([[1.,2.,3.,4.]]))):
            with self.assertRaises(ValueError):
                return_path(periods,prices)

    def test_dtype_and_price_domain(self):
        with self.assertRaises(TypeError):
            return_path(inputs()[0].astype(np.float64),inputs()[1])
        with self.assertRaises(TypeError):
            return_path(inputs()[0],inputs()[1].astype(np.float32))
        for value in (0.,-1.,np.nan,np.inf):
            prices = inputs()[1]
            prices[-1] = value
            with self.assertRaises(ValueError):
                return_path(inputs()[0],prices)

    def test_source_preservation_and_storage(self):
        periods,prices = inputs()
        before = (periods.copy(),prices.copy())
        result = return_path(periods,prices)
        np.testing.assert_array_equal(periods,before[0])
        np.testing.assert_array_equal(prices,before[1])
        for output in result.values():
            self.assertFalse(np.shares_memory(output,periods))
            self.assertFalse(np.shares_memory(output,prices))

    def test_numerical_failure_restores_policy(self):
        before = np.geterr().copy()
        for values in ([1e-300,1e300],[1e300,1e-300]):
            with self.assertRaises(FloatingPointError):
                return_path(np.array([0,1],dtype=np.int64),np.array(values))
        self.assertEqual(np.geterr(),before)

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

## 6.9.13 Review Before Using a Return Vector

Identify whether the vector runs across time, instruments, or scenarios. For a time path, retain interval boundaries, price conventions, missing-data treatment, and the distinction between price-only and total return.

Arithmetic means, linked growth, and sums answer different questions. The mean of historical observations is not automatically an expected future return. For portfolios, beginning weights, rebalancing, cash flows, and exposure definitions introduce further requirements; Section 6.10 introduces weight vectors without erasing those distinctions.

Log returns, annualization, distributions, and broader performance measurement are developed in later chapters. No such convention is implied by the convenience of a NumPy expression here.

## 6.9.14 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| N prices assigned N returns | Invented leading observation | Return N-1 intervals with endpoint labels |
| Linked result differs from summed returns | Additive versus multiplicative operation | Link gross factors under the stated contract |
| Large jump near a corporate action | Raw/adjusted price consistency | Apply a documented data convention |
| Irregular series called daily returns | Actual interval labels | Preserve durations and avoid implicit annualization |
| Missing observation silently bridged | Filtering policy | Document the longer interval or reject incomplete data |
| Zero final price rejected | Strictly positive path policy | Design a tested terminal-zero extension separately |
| Ratio overflows or underflows | Input magnitude and representation | Review numerical bounds before reuse |
| Rounded simple return is -100% | Gross factor and precision | Distinguish approximate representation from a literal zero price |

## 6.9.16 Key Takeaways

Return vectors describe intervals, not isolated price observations. Preserve endpoint labels and numerical conventions with the values.

Link gross factors when measuring consecutive price-only growth under this contract. Keep timing, distributions, precision, and performance claims explicit rather than assuming that array arithmetic settles them.
