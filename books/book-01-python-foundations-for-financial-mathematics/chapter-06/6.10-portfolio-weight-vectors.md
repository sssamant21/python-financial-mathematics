## 6.10.1 Purpose

A weight vector connects position values to their share of a stated portfolio denominator. Its meaning depends on valuation time, included holdings, currency, identity order, and the treatment of cash or borrowing.

This section builds long-only opening-value weights and combines aligned one-interval price returns under explicit simplifying assumptions. It does not implement portfolio optimization, rebalancing, leverage accounting, or investment recommendations.

## 6.10.2 Learning Objectives

1. Construct weights from nonnegative opening position values.
2. Distinguish normalization from validation of supplied weights.
3. Align weights and returns by instrument identity, not merely length.
4. Derive per-position contributions and verify the portfolio value bridge.
5. State the scope of a long-only fully represented portfolio.
6. Keep tolerance, cash, timing, and ownership decisions explicit.

## 6.10.3 Define the Denominator

For nonnegative opening values v_i with positive total V, this experiment defines:

\[
V=\sum_i v_i,\qquad w_i=\frac{v_i}{V}.
\]

All values must share a currency and valuation instant. The vector must include every component intended in the denominator. In the example, that includes a cash position with an explicitly supplied zero interval return.

| Identifier | Opening value | Opening weight | Interval price return | Contribution |
|---|---|---|---|---|
| A | 600 | 0.60 | 0.10 | 0.060 |
| B | 300 | 0.30 | -0.05 | -0.015 |
| CASH | 100 | 0.10 | 0.00 | 0.000 |
| Total | 1000 | 1.00 | — | 0.045 |

The cash return is an example assumption, not a claim that cash always earns zero. Omitting cash and dividing only by 900 would describe weights within the invested subset, not weights of the stated 1000 portfolio.

Zero-valued positions are allowed. An all-zero vector is rejected because it provides no positive denominator. Negative values are rejected under this long-only model.

## 6.10.4 Contributions Over One Common Interval

Given beginning weights and compatible one-interval simple price returns r_i, define contributions c_i and the portfolio price return:

\[
c_i=w_i r_i,\qquad r_p=\sum_i c_i.
\]

For the example, 0.60*0.10 + 0.30*(-0.05) + 0.10*0 = 0.045. The 0.060 contribution is six percentage points of portfolio return; it is not the instrument's own ten-percent return.

Under the stated no-trade/no-flow assumptions, ending values are v_i*(1+r_i). They sum to 660+285+100=1045, so 1045/1000-1=0.045. The test independently checks this value bridge.

The contract excludes distributions, fees, external investor cash flows, FX, financing, and trade activity. It uses the same price-only return convention for every component. Extending to total returns or other accounting conventions requires consistent inputs and revised assumptions.

## 6.10.5 Opening Weights Are Not Closing Weights

Use weights measured at the beginning of the return interval for this calculation. Closing weights already reflect price changes. Substituting them changes the arithmetic and can introduce hindsight into a historical calculation.

Without rebalancing, weights generally drift across intervals. Reusing the same vector over a sequence can describe an implicitly rebalanced strategy rather than the original fixed holdings. Rebalancing timing, costs, and external cash flows need a separate path model.

This kernel handles one interval only. It does not link portfolio returns across time or infer trade instructions from a target allocation.

## 6.10.6 Normalize Values, Validate Weights

The two public functions serve different purposes. weights_from_values deliberately divides values by their sum. contributions accepts weights already expressed as fractions and checks that they sum near one; it never silently renormalizes them.

| Supplied input | Treatment |
|---|---|
| Values [600, 300, 100] | Normalize deliberately to [0.6, 0.3, 0.1] |
| Weights [0.6, 0.3, 0.1] | Accept |
| Weights [60, 30, 10] | Reject; not fractional weights |
| Weights [0.5, 0.3, 0.1] | Reject; incomplete under this contract |
| Negative component | Reject; long-only restriction |
| Near-one floating sum | Accept within declared absolute tolerance, preserve supplied values |

A near-one acceptance tolerance is not a hidden correction step. The result includes the observed weight_sum so the caller can inspect the accepted vector. If exact normalization is required, make that an explicit transformation and retain its provenance.

## 6.10.7 Identity and Alignment

Both functions require exact tuples of unique nonempty unpadded instrument IDs matching vector length. contributions requires the return IDs to match the weight IDs in exactly the same order.

A reordered return vector can have the correct shape yet produce the wrong portfolio result. This API rejects a different ID order rather than silently joining or sorting. Use an explicit upstream alignment operation and verify that no instruments are missing or duplicated.

The kernel cannot detect returns incorrectly attached to otherwise matching labels. Nor can it establish that returns share the same interval, currency treatment, or price convention. Those are data-boundary responsibilities.

## 6.10.8 Limits of Long-Only Weights

Signed exposure vectors from Section 6.5 serve a different purpose. A long-short portfolio can have net exposure different from gross exposure, and a zero or tiny net-value denominator can make naive normalization undefined or unstable.

Do not normalize signed positions with this long-only helper, take absolute values to bypass its checks, or assume a sum of one alone proves that borrowing and collateral are correctly represented. Define denominator, cash, liabilities, and financing explicitly in a separate model.

Likewise, values must already be comparable amounts in one currency. Share counts alone are not value weights, and mixed-currency values require a stated conversion convention before aggregation.

## 6.10.9 Numerical Policy

Vectors are exact one-dimensional float64 ndarrays with 1–10000 finite entries. Weights must lie in [0,1], and simple returns must be at least -1 under the nonnegative ending-value convention used here.

The sum check uses np.isclose with rtol=0 and atol=1e-12 against one. This is a chosen dimensionless numerical tolerance, not a financial loss threshold. Each component must still satisfy the domain constraints.

Arithmetic uses float64 and local signal handling that raises on overflow, underflow, invalid operations, and division errors. A finite-input sum can overflow, as the test demonstrates. No clipping, NaN skipping, or zero-weight exemption hides invalid return entries.

Outputs remain approximate. Strict signal handling does not detect every rounding error or establish general accuracy for extreme magnitudes. The known small example and scalar/value-bridge checks support bounded claims.

## 6.10.11 File — weight_vectors.py

```python
"""Long-only beginning-value weights and one-interval price-return contributions."""
import numpy as np


def labels(ids: tuple[str, ...], size: int) -> None:
    if type(ids) is not tuple or len(ids) != size:
        raise ValueError('identifier tuple must match vector length')
    if any(type(s) is not str or not s or s.strip() != s for s in ids):
        raise ValueError('identifiers must be nonempty unpadded text')
    if len(set(ids)) != size:
        raise ValueError('identifiers must be unique')


def vector(value: np.ndarray) -> None:
    if type(value) is not np.ndarray or value.dtype != np.dtype('float64'):
        raise TypeError('expected an exact float64 ndarray')
    if value.ndim != 1 or not 1 <= value.size <= 10000:
        raise ValueError('expected a vector with 1 to 10000 entries')
    if not np.isfinite(value).all():
        raise ValueError('vector must be finite')


def weights_from_values(values: np.ndarray, ids: tuple[str, ...]) -> np.ndarray:
    """Normalize nonnegative same-currency opening values; positive total required."""
    vector(values)
    labels(ids,values.size)
    if (values < 0).any():
        raise ValueError('this model requires nonnegative values')
    with np.errstate(over='raise',under='raise',invalid='raise',divide='raise'):
        total = float(np.sum(values,dtype=np.float64))
        if total <= 0:
            raise ValueError('positive total value required')
        result = values / total
    if not np.isfinite(result).all():
        raise ValueError('nonfinite weights')
    return result


def contributions(weights: np.ndarray, ids: tuple[str, ...],
                  returns: np.ndarray, return_ids: tuple[str, ...]) -> dict[str, object]:
    """Use opening long-only weights and aligned simple price returns >= -1.

    Same interval/currency convention; no trades, external flows, distributions,
    fees, financing, or FX. Near-one weights accepted without renormalization.
    """
    vector(weights)
    vector(returns)
    labels(ids,weights.size)
    labels(return_ids,returns.size)
    if weights.shape != returns.shape or ids != return_ids:
        raise ValueError('return identity/order must exactly match weights')
    if (weights < 0).any() or (weights > 1).any() or (returns < -1).any():
        raise ValueError('unsupported weights or returns')
    with np.errstate(over='raise',under='raise',invalid='raise',divide='raise'):
        weight_sum = float(np.sum(weights,dtype=np.float64))
        if not np.isclose(weight_sum,1.,rtol=0.,atol=1e-12):
            raise ValueError('weights must sum to one within absolute tolerance 1e-12')
        parts = weights * returns
        total = float(np.sum(parts,dtype=np.float64))
    if not np.isfinite(parts).all() or not np.isfinite(total):
        raise ValueError('nonfinite contributions')
    return {'ids':ids,'contributions':parts,'portfolio_return':total,'weight_sum':weight_sum}


def main() -> None:
    ids = ('A','B','CASH')
    values = np.array([600.,300.,100.])
    returns = np.array([.1,-.05,0.])
    weights = weights_from_values(values,ids)
    result = contributions(weights,ids,returns,ids)
    print('IDs:',ids)
    print('Opening weights:',[f'{x:.2%}' for x in weights])
    print('Return contributions:',[f'{x:.2%}' for x in result['contributions']])
    print(f'Portfolio price return: {result["portfolio_return"]:.2%}')
    print(f'Weight sum: {result["weight_sum"]:.12f}')


if __name__ == '__main__':
    main()
```

The small labels/vector helpers centralize this lab's validation contracts. No source array is modified. Computed weights and contribution arrays have storage independent of their inputs.

The returned record contains the aligned IDs, per-component contributions, scalar portfolio return, and observed weight sum. It does not preserve a complete valuation or research audit record.

## 6.10.12 File — test_weight_vectors.py

```python
import unittest
import numpy as np
from weight_vectors import weights_from_values,contributions

IDS = ('A','B','CASH')

class WeightTests(unittest.TestCase):
    def test_known_weights_and_contributions(self):
        weights = weights_from_values(np.array([600.,300.,100.]),IDS)
        np.testing.assert_allclose(weights,[.6,.3,.1],rtol=0,atol=1e-15,equal_nan=False)
        result = contributions(weights,IDS,np.array([.1,-.05,0.]),IDS)
        np.testing.assert_allclose(result['contributions'],[.06,-.015,0.],rtol=0,atol=1e-15,equal_nan=False)
        self.assertAlmostEqual(result['portfolio_return'],.045)

    def test_value_bridge_and_scalar_reference(self):
        values = np.array([600.,300.,100.])
        returns = np.array([.1,-.05,0.])
        weights = weights_from_values(values,IDS)
        actual = contributions(weights,IDS,returns,IDS)['portfolio_return']
        self.assertAlmostEqual(actual,sum(w*r for w,r in zip(weights.tolist(),returns.tolist())))
        ending = sum(v*(1+r) for v,r in zip(values.tolist(),returns.tolist()))
        self.assertAlmostEqual(actual,ending/float(values.sum())-1.)

    def test_identity_not_only_length(self):
        with self.assertRaises(ValueError):
            contributions(np.array([.6,.3,.1]),IDS,np.array([.1,-.05,0.]),('B','A','CASH'))
        with self.assertRaises(ValueError):
            weights_from_values(np.array([1.,2.,3.]),('A','A','C'))

    def test_value_domain(self):
        for values in ([0.,0.,0.],[-1.,2.,3.],[np.nan,2.,3.],[np.inf,2.,3.]):
            with self.assertRaises(ValueError):
                weights_from_values(np.array(values),IDS)
        with self.assertRaises(TypeError):
            weights_from_values(np.array([1,2,3]),IDS)

    def test_weight_sum_without_silent_normalization(self):
        for weights in ([60.,30.,10.],[.5,.3,.1],[-.1,.6,.5]):
            with self.assertRaises(ValueError):
                contributions(np.array(weights),IDS,np.zeros(3),IDS)
        supplied = np.array([.6,.3,.1+5e-13])
        result = contributions(supplied,IDS,np.ones(3),IDS)
        self.assertEqual(result['portfolio_return'],result['weight_sum'])
        self.assertGreater(result['weight_sum'],1.)

    def test_zero_weight_and_total_loss(self):
        result = contributions(np.array([1.,0.,0.]),IDS,np.array([-1.,0.,0.]),IDS)
        self.assertEqual(result['portfolio_return'],-1.)
        for returns in ([0.,np.nan,0.],[0.,-1.01,0.]):
            with self.assertRaises(ValueError):
                contributions(np.array([1.,0.,0.]),IDS,np.array(returns),IDS)

    def test_shape_source_and_storage(self):
        values,returns = np.array([600.,300.,100.]),np.array([.1,-.05,0.])
        weights = weights_from_values(values,IDS)
        result = contributions(weights,IDS,returns,IDS)
        self.assertFalse(np.shares_memory(weights,values))
        self.assertFalse(np.shares_memory(result['contributions'],weights))
        np.testing.assert_array_equal(values,[600.,300.,100.])
        np.testing.assert_array_equal(returns,[.1,-.05,0.])
        with self.assertRaises(ValueError):
            contributions(weights,IDS,np.array([[.1,-.05,0.]]),IDS)

    def test_overflow_restores_policy(self):
        before = np.geterr().copy()
        with self.assertRaises(FloatingPointError):
            weights_from_values(np.array([1e308,1e308]),('A','B'))
        self.assertEqual(np.geterr(),before)

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

## 6.10.15 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| Sum is 100 | Percent values passed as fractions | Convert explicitly at the input boundary |
| Weights sum below one | Missing cash or holdings | Complete the denominator or define a different contract |
| Correct length, wrong return | ID order or source labels | Align explicitly before calculation |
| All-zero values fail | No positive denominator | Supply a meaningful portfolio or handle the empty-value case separately |
| Signed values rejected | Long-only policy | Design gross/net/financing semantics separately |
| Repeated-period results seem too favorable | Closing weights or hidden rebalancing | Use correct interval-opening information |
| Zero-weight missing return fails | Full-input validation | Resolve the missing input explicitly |
| Accepted sum differs slightly from one | Absolute tolerance without renormalization | Inspect weight_sum and choose any correction deliberately |

## 6.10.17 Key Takeaways

Weights require a stated denominator, valuation time, and complete aligned identity set. Normalize raw values only when intended; validate supplied weights without hiding errors through automatic correction.

Beginning weights combine compatible one-interval returns under explicit assumptions. Cash, short positions, drift, and rebalancing require deliberate treatment beyond a sum-to-one check.
