## 6.13.1 Purpose

Random draws are inputs to an experiment. Their distribution, generator, state, shape, and allocation to logical tasks should be explicit rather than hidden in global application state.

This section draws synthetic standard-normal innovation matrices and tests local reproducibility. It does not calibrate asset returns, simulate prices, estimate risk, or validate a Monte Carlo model. Those tasks require additional assumptions developed later in the book.

## 6.13.2 Learning Objectives

1. Create and pass an explicit NumPy Generator.
2. Distinguish a seed from the current generator state.
3. Preserve draw method, shape, and call-order evidence.
4. Restore a local checkpoint for continuation.
5. Spawn reproducible logical streams without claiming a proof of independence.
6. Separate deterministic execution checks from statistical model validation.

## 6.13.3 Generator, Bit Generator, and Seed

NumPy separates the Generator interface for distribution draws from the BitGenerator supplying pseudorandom bits. The lab explicitly constructs Generator(PCG64(seed)) so the algorithm choice is visible.

The seed initializes a fresh stream. The current state identifies where that stream has progressed. Calling a draw method consumes state, so reusing one generator is different from constructing a new one with the original seed before every call.

| Item | Role in this lab | Record or policy |
|---|---|---|
| Generator | Distribution-draw interface | Pass explicitly to the function |
| PCG64 | Chosen bit generator | Name the algorithm |
| Seed | Fresh-stream initialization | Exact nonnegative integer below 2**128 |
| Current state | Continuation point | Copy deliberately when checkpointing |
| Draw request | standard_normal | Preserve method, dtype, shape, and order |

The seed bound is this API's teaching contract, not a statement that every NumPy seeding interface accepts only that range. Booleans and floating values fail instead of being coerced into integer seeds.

## 6.13.4 Innovations Are Not a Financial Model

The output has shape (scenario, factor), with standard-normal numerical innovations. Their parameters are those of the requested distribution; no financial units, calibrated means, volatilities, correlations, horizon, or market observations are supplied.

A standard-normal draw is not automatically an asset return. In particular, an additive normal-return model can produce values below -100%. A positive-price model, dependence structure, and treatment of tails require deliberate design. Scaling the innovations by a number alone does not establish a valid market model.

The small fixture is for generator mechanics. Its empirical mean need not be zero and its empirical standard deviation need not be one. Do not make a unit test demand exact population moments from a handful of random values.

## 6.13.5 State Ownership at the Function Boundary

innovations accepts a caller-owned Generator and positive exact integer dimensions. It checks the one-million-cell budget before drawing. Validation failures therefore leave the stream untouched, as the test verifies.

Successful calls advance the supplied generator intentionally. The function does not reseed it internally. The caller can maintain continuity across batches or deliberately create fresh streams for independent experiment runs.

Avoid a module-level generator that unrelated functions consume implicitly. Avoid constructing the same freshly seeded stream inside each worker or each loop iteration unless identical repeated draws are specifically intended. Explicit state ownership makes those decisions reviewable.

A runtime allocation or library failure after drawing begins is not promised to roll back state. The no-consumption guarantee applies to the validation failures checked before the draw request.

## 6.13.6 What the Repeat Test Establishes

Two fresh PCG64 generators with the same seed and identical draw requests produce matching arrays in the tested environment. The test verifies that local behavior directly.

For a broader reproducibility record, retain NumPy version/build, generator type, seed or checkpoint, draw method, dtype, requested shape, call order, and task assignment. NumPy's stream-compatibility conditions are strict; do not promise identical draws across upgrades, builds, machines, or altered call patterns.

Even changing a vectorized draw into many scalar calls is a change to the request sequence. Do not assume it preserves a stream unless that behavior is established for the intended supported workflow.

The extra-draw test inserts rng.random() before standard_normal and observes different later values. It demonstrates why an exploratory diagnostic draw can alter an experiment when both consume the same generator.

## 6.13.7 Checkpoint and Continue

The reference test deep-copies rng.bit_generator.state after an initial batch. It then draws another batch, restores the saved state into another PCG64 generator, and verifies the continuation matches.

The checkpoint is copied to avoid relying on alias behavior of a mutable state record. Restore only into a compatible bit-generator setup and record the environment. This in-memory test does not define a durable cross-version checkpoint format or trusted storage workflow.

For persistent research evidence, preserve the surrounding code, configuration, input data, state schema/version context, and logical progress marker. A generator state alone does not identify which scenarios have already been processed or saved.

## 6.13.8 Spawn Logical Streams Deliberately

The test creates a SeedSequence from a root seed, spawns two children, and constructs one PCG64 Generator per child. Repeating that setup reproduces each child's batch locally. The two tested batches differ.

SeedSequence spawning is designed to produce streams that are independent with very high probability. A test that two small arrays differ does not prove statistical independence. It checks the implemented stream mapping and repeat behavior, not the generator's statistical quality.

Map children to stable logical tasks such as batch IDs, rather than whichever operating-system worker happens to run first. Record child allocation order and the call sequence within each task. Changing task partitioning or child assignment can change results even if the root seed remains the same.

The tests run serially. They demonstrate stream construction, not live multiprocessing, distributed scheduling, or thread-safety acceptance. Never copy one initialized mutable generator into every worker and assume that creates distinct streams.

## 6.13.9 Reuse Draws for a Controlled Comparison

The final test generates one innovation matrix z, then compares 0.01*z and 0.02*z. The same underlying draws make the change in scale explicit, and neither transformation mutates z.

This is a controlled coupling of two illustrative assumptions, not independent experiments. Such a shared-draw design can be useful for comparing implementations or scenarios, but its statistical implications depend on the estimator. No variance-reduction guarantee or financial calibration is established here.

Keep the untransformed innovation snapshot when a comparison must be rerun exactly. If an assumption changes the number or order of random draws, sharing only a seed may no longer preserve the intended coupling.

## 6.13.11 File — random_lab.py

```python
"""Explicit pseudorandom generators and synthetic innovation matrices."""
import numpy as np


def make_rng(seed: int) -> np.random.Generator:
    """Create a fresh PCG64 stream from an exact nonnegative integer seed."""
    if type(seed) is not int or not 0 <= seed < 2**128:
        raise ValueError('seed must be an exact int in [0, 2**128)')
    return np.random.Generator(np.random.PCG64(seed))


def innovations(rng: np.random.Generator, scenarios: int, factors: int) -> np.ndarray:
    """Draw standard-normal innovations, shape (scenario, factor).

    Caller owns RNG state: successful draws advance it. Max 1000000 cells.
    Draws have no calibrated financial units, correlations, or return model.
    """
    if type(rng) is not np.random.Generator:
        raise TypeError('rng must be an exact numpy Generator')
    if any(type(x) is not int or x < 1 for x in (scenarios,factors)):
        raise ValueError('dimensions must be positive exact ints')
    if scenarios*factors > 1000000:
        raise ValueError('innovation matrix exceeds cell budget')
    return rng.standard_normal(size=(scenarios,factors),dtype=np.float64)


def main() -> None:
    seed = 20261022
    first = innovations(make_rng(seed),4,2)
    repeat = innovations(make_rng(seed),4,2)
    print('NumPy:',np.__version__)
    print('Bit generator: PCG64')
    print('Seed:',seed)
    print('Axes: scenario, factor')
    print('Shape:',first.shape)
    print('First row:',[f'{x:.6f}' for x in first[0]])
    print('Fresh-stream repeat equal:',bool(np.array_equal(first,repeat)))


if __name__ == '__main__':
    main()
```

make_rng supplies the explicit PCG64 baseline. innovations also accepts an explicitly constructed Generator with another bit generator; a caller choosing that route must record the different algorithm and cannot expect the demo's stream.

The one-million-cell bound limits output shape, not total process memory or the statistical quality of a sample. No automatic resampling or filtering discards values that look inconvenient.

## 6.13.12 File — test_random_lab.py

```python
from copy import deepcopy
import unittest
import numpy as np
from random_lab import make_rng,innovations

class RandomTests(unittest.TestCase):
    def test_same_seed_same_call(self):
        first,second = innovations(make_rng(42),4,3),innovations(make_rng(42),4,3)
        np.testing.assert_array_equal(first,second)
        self.assertEqual(first.dtype,np.dtype('float64'))
        self.assertEqual(first.shape,(4,3))
        self.assertTrue(np.isfinite(first).all())

    def test_state_advances(self):
        rng = make_rng(42)
        first = innovations(rng,4,3)
        second = innovations(rng,4,3)
        self.assertFalse(np.array_equal(first,second))
        np.testing.assert_array_equal(first,innovations(make_rng(42),4,3))

    def test_state_checkpoint(self):
        rng = make_rng(77)
        innovations(rng,2,2)
        saved = deepcopy(rng.bit_generator.state)
        expected = innovations(rng,3,2)
        restored = make_rng(0)
        restored.bit_generator.state = deepcopy(saved)
        np.testing.assert_array_equal(expected,innovations(restored,3,2))

    def test_validation_does_not_consume_stream(self):
        rng,reference = make_rng(10),make_rng(10)
        for shape in ((0,2),(True,2),(2.,2),(1001,1000)):
            with self.assertRaises(ValueError):
                innovations(rng,*shape)
        np.testing.assert_array_equal(innovations(rng,2,2),innovations(reference,2,2))

    def test_seed_and_generator_types(self):
        for seed in (-1,True,1.,2**128):
            with self.assertRaises(ValueError):
                make_rng(seed)
        with self.assertRaises(TypeError):
            innovations(42,2,2)

    def test_spawned_logical_streams(self):
        def batches():
            children = np.random.SeedSequence(100).spawn(2)
            return [innovations(np.random.Generator(np.random.PCG64(child)),3,2)
                    for child in children]
        first,second = batches(),batches()
        for a,b in zip(first,second):
            np.testing.assert_array_equal(a,b)
        self.assertFalse(np.array_equal(first[0],first[1]))

    def test_extra_draw_changes_later_values(self):
        rng = make_rng(123)
        rng.random()
        after = innovations(rng,3,2)
        baseline = innovations(make_rng(123),3,2)
        self.assertFalse(np.array_equal(after,baseline))

    def test_shared_draws_for_two_assumptions(self):
        z = innovations(make_rng(44),5,2)
        baseline = z.copy()
        low,high = .01*z,.02*z
        np.testing.assert_array_equal(z,baseline)
        np.testing.assert_allclose(high,2*low,rtol=1e-15,atol=0,equal_nan=False)
        self.assertFalse(np.shares_memory(low,z))

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

## 6.13.14 Test Mechanics and Statistical Assumptions Separately

Deterministic tests are appropriate for shape, dtype, state ownership, replay, and stream assignment. Distributional validation is a separate task requiring a justified sample design and acceptance criteria. A random test can fail by chance, so do not introduce an unexplained tight empirical-moment threshold.

For financial simulation, validate calibration, dependence, horizon, path dynamics, and numerical transformations separately. Reproducibly generating random values can reproduce a misspecified model just as reliably as a good one.

This generator is used for numerical experimentation. It is not a credential or security-token generator. Choosing a seed is not a privacy or unpredictability control.

## 6.13.15 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| Every batch repeats | Generator recreated with same seed | Keep one explicit stream or spawn deliberate children |
| Same seed but different result | Method, shape, call order, environment | Compare the full random-draw protocol |
| Debug print changes results | Diagnostic consumed shared RNG | Separate diagnostic stream or reuse saved draws |
| Workers receive identical batches | Generator copied/reseeded identically | Assign explicit child streams to logical tasks |
| Checkpoint replays wrong work | RNG state without task progress | Preserve both state and logical completion metadata |
| Tiny sample lacks exact zero mean | Population versus sample | Test deterministic mechanics separately |
| Bigger run changes old outputs | Request size or partition changed | Preserve and review the intended protocol |
| Synthetic values called market forecasts | Missing calibrated model | State what distribution inputs actually represent |

## 6.13.17 Key Takeaways

Random number generation has an explicit stateful protocol. Pass generators deliberately, record draw requests, and distinguish initialization from continuation.

Local replay, spawned-stream mapping, and statistical model validation answer different questions. A seed supports reproducibility only as part of the complete experiment record.
