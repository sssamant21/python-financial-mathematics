## 6.5.1 Purpose

Vectorization expresses repeated arithmetic over numerical arrays. The benefit is useful only when the array expression preserves the intended financial calculation, identity alignment, and numerical behavior.

This section implements synthetic fixed-quantity position marks and price-only changes. It compares known answers and a scalar reference before making any performance claim. It does not build a complete portfolio accounting engine.

## 6.5.2 Learning Objectives

1. Translate a per-position arithmetic contract into elementwise expressions.
2. Validate equal shapes before an unintended broadcast can change the calculation.
3. Explain signed quantities and the scope of price-only P&L.
4. Compare vectorized and scalar results with explicit numerical criteria.
5. Preserve source data and reject unsupported numerical results.
6. Distinguish native array operations from np.vectorize convenience wrapping.

## 6.5.3 Define the Calculation First

For each aligned position i, hold quantity q_i constant across an observation interval and define:

```math
V_{i,0}=q_i P_{i,0},\qquad
V_{i,1}=q_i P_{i,1},\qquad
\Delta V_i=q_i(P_{i,1}-P_{i,0}).
```

Here q is signed, and both prices use the same currency and per-unit convention. These equations define this experiment's marks and price-only change. They exclude trades, dividends, coupons, fees, financing, FX, and corporate-action adjustments.

A negative quantity represents a short exposure in this simplified arithmetic. Its negative mark is not a complete account-equity statement: cash proceeds, collateral, margin, and financing are outside scope. No portfolio total or return denominator is calculated.

| Position | Quantity | Start price | End price | Opening mark | Closing mark | Price-only change |
|---|---|---|---|---|---|---|---|
| LONG-A | 10 | 100 | 105 | 1000 | 1050 | 50 |
| SHORT-B | -5 | 80 | 76 | -400 | -380 | 20 |
| FLAT-C | 0 | 50 | 52 | 0 | 0 | 0 |

Derive these values independently. The short position gains 20 under the stated contract because -5 multiplied by the price change -4 is +20. Zero quantity does not authorize ignoring invalid source data.

## 6.5.4 Translate the Contract to Arrays

The three expressions are `quantity * start`, `quantity * end`, and `quantity * (end - start)`. Each input is a nonempty one-dimensional float64 vector with the same shape. One output entry corresponds to one input position.

NumPy's native numerical operators apply these operations across entries. A ufunc provides elementwise array behavior with support for features such as dtype handling and broadcasting. This API deliberately rejects unequal shapes before arithmetic, keeping one-to-one alignment explicit.

Position labels stay outside the numerical kernel. The caller must align quantities and both price arrays using the same identifiers. Equal length alone cannot detect that one vector was sorted differently. Section 6.4 provides an identifier-aware selection pattern.

## 6.5.5 Validation and Failure Policy

| Input or result | Policy |
|---|---|
| Object/type | Exact ndarray, native float64 |
| Rank and size | One-dimensional, nonempty |
| Shape | All three vectors equal |
| Quantities | Finite; positive, negative, and zero allowed |
| Prices | Finite and nonnegative |
| Arithmetic signals | Raise on overflow, underflow, divide, or invalid |
| Returned arrays | Finite, independent of caller inputs |

Zero prices are allowed because no price divides another price here. That differs from a return function with a strictly positive starting-price requirement. Apply the operation's contract rather than copying validation rules blindly.

The strict underflow policy rejects signaled tiny computations rather than silently accepting zeroed products. It is a choice for this lab. Not every approximation loss raises a floating-point signal, and finite results do not prove adequate precision. The final finite check supplements domain validation; it does not certify arbitrary magnitudes as financially meaningful.

Any failing operation raises before a result dictionary is returned. Intermediate arrays may have been allocated, but caller arrays remain unmodified. The local errstate context restores the caller's error-handling policy even after failure.

## 6.5.6 Numerical Agreement Is Not Decimal Exactness

float64 supports approximate analytical computation. The integer-valued known fixture has exact representable inputs and outputs, so its tests use exact equality. A second fixture with decimal fractions uses rtol=1e-12 and atol=1e-12 with NaNs disallowed.

Those tolerances are limited to the chosen small examples. They are not accounting rounding rules or general financial materiality thresholds. Derive a comparison policy for each application, especially when magnitudes, cancellation, or aggregation change.

The direct price-change expression q*(end-start) and the alternative closing-opening are algebraically equivalent but can round differently in finite precision. The API explicitly chooses the former. Do not silently switch formulas and assume bitwise equality across all inputs. A scalar implementation using the same formula is useful implementation evidence; independently calculated known answers provide another line of checking.

## 6.5.7 Vectorization Does Not Mean np.vectorize

np.vectorize offers an array-friendly interface around a Python callable. It is primarily a convenience tool and does not turn arbitrary Python code into the native numeric kernel used by ordinary float64 array arithmetic.

Use native operators when they express the intended calculation clearly. Retain Python control flow where it communicates validation or business rules better. In this lab the small loop validates three named inputs; the repeated per-position arithmetic uses arrays.

There is no benchmark in this section. Shorter code does not establish a speedup, multithreading, or GPU execution. Section 6.15 addresses measurements. Array expressions can also allocate temporary results, so time and memory require separate evaluation.

## 6.5.9 File — vectorized_marks.py

```python
"""Synthetic fixed-quantity marks and price-only changes, one row per position."""
import numpy as np


def position_changes(quantity: np.ndarray, start: np.ndarray,
                     end: np.ndarray) -> dict[str, np.ndarray]:
    """Return start/end marks and price-only P&L for aligned float64 vectors.

    Quantity is signed, unchanged over the interval, and finite. Prices are
    finite and nonnegative in one currency/per-unit convention. No cash flows,
    fees, FX, financing, trade activity, or corporate-action adjustment.
    Caller guarantees identity alignment. No portfolio aggregation performed.
    """
    for name, value in (('quantity',quantity),('start',start),('end',end)):
        if type(value) is not np.ndarray or value.dtype != np.dtype('float64'):
            raise TypeError(f'{name} must be an exact float64 ndarray')
        if value.ndim != 1 or value.size == 0:
            raise ValueError(f'{name} must be a nonempty vector')
        if not np.isfinite(value).all():
            raise ValueError(f'{name} must be finite')
    if quantity.shape != start.shape or start.shape != end.shape:
        raise ValueError('all vectors must have equal shape')
    if (start < 0).any() or (end < 0).any():
        raise ValueError('prices must be nonnegative')
    with np.errstate(over='raise',divide='raise',invalid='raise',under='raise'):
        opening = quantity * start
        closing = quantity * end
        pnl = quantity * (end - start)
    if not all(np.isfinite(value).all() for value in (opening,closing,pnl)):
        raise ValueError('nonfinite output')
    return {'opening':opening,'closing':closing,'pnl':pnl}


def main() -> None:
    ids = ('LONG-A','SHORT-B','FLAT-C')
    quantity = np.array([10.,-5.,0.],dtype=np.float64)
    start = np.array([100.,80.,50.],dtype=np.float64)
    end = np.array([105.,76.,52.],dtype=np.float64)
    result = position_changes(quantity,start,end)
    for index,sid in enumerate(ids):
        print(f'{sid}: opening={result["opening"][index]:.2f}, '
              f'closing={result["closing"][index]:.2f}, pnl={result["pnl"][index]:.2f}')
    print('Result shape:',result['pnl'].shape)


if __name__ == '__main__':
    main()
```

The function returns one array for each named quantity. No input is reused as an output buffer. The application prints only after the complete calculation succeeds; formatted amounts are a display choice, not stored fixed-scale accounting values.

## 6.5.10 File — test_vectorized_marks.py

```python
import unittest
import numpy as np
from vectorized_marks import position_changes


def inputs():
    return np.array([10.,-5.,0.]),np.array([100.,80.,50.]),np.array([105.,76.,52.])

class VectorizedTests(unittest.TestCase):
    def test_known_long_short_flat(self):
        result = position_changes(*inputs())
        for key,expected in {'opening':[1000.,-400.,0.],
                             'closing':[1050.,-380.,0.],'pnl':[50.,20.,0.]}.items():
            self.assertEqual(result[key].shape,(3,))
            self.assertEqual(result[key].dtype,np.dtype('float64'))
            np.testing.assert_array_equal(result[key],expected)

    def test_scalar_reference(self):
        q = np.array([.5,-2.25,3.])
        p0 = np.array([3.1,4.7,9.2])
        p1 = np.array([3.3,4.4,9.1])
        result = position_changes(q,p0,p1)
        reference = [(a*b,a*c,a*(c-b)) for a,b,c in zip(q.tolist(),p0.tolist(),p1.tolist())]
        for index,key in enumerate(('opening','closing','pnl')):
            np.testing.assert_allclose(result[key],[row[index] for row in reference],
                                       rtol=1e-12,atol=1e-12,equal_nan=False)

    def test_source_preservation_and_output_storage(self):
        source = inputs()
        before = tuple(value.copy() for value in source)
        result = position_changes(*source)
        for current,original in zip(source,before):
            np.testing.assert_array_equal(current,original)
        for output in result.values():
            for value in source:
                self.assertFalse(np.shares_memory(output,value))
        self.assertFalse(np.shares_memory(result['opening'],result['closing']))

    def test_equal_prices_and_zero_prices(self):
        result = position_changes(np.array([2.,-3.]),np.array([0.,4.]),np.array([0.,4.]))
        np.testing.assert_array_equal(result['pnl'],[0.,0.])

    def test_shape_rejects_broadcasting(self):
        for q in (np.array([1.]),np.array([[1.,2.,3.]]),np.array([])):
            with self.assertRaises(ValueError):
                position_changes(q,inputs()[1],inputs()[2])

    def test_types(self):
        for q in ([1.,2.,3.],np.array([1,2,3]),np.array([True,False,True]),
                  np.array([1.,2.,3.],dtype=np.float32)):
            with self.assertRaises(TypeError):
                position_changes(q,inputs()[1],inputs()[2])

    def test_domain_even_for_flat_position(self):
        for bad in (np.nan,np.inf,-1.):
            with self.assertRaises(ValueError):
                position_changes(np.array([0.]),np.array([bad]),np.array([1.]))
        with self.assertRaises(ValueError):
            position_changes(np.array([np.inf]),np.array([1.]),np.array([1.]))

    def test_numerical_failure_restores_error_policy(self):
        before = np.geterr().copy()
        for q,p0,p1 in ((1e308,2.,2.),(1e-300,1e-300,1e-300)):
            with self.assertRaises(FloatingPointError):
                position_changes(np.array([q]),np.array([p0]),np.array([p1]))
        self.assertEqual(np.geterr(),before)

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

## 6.5.12 Extend Without Changing the Question Silently

To add distributions, trades, fees, or FX, define new inputs and equations first. State timing, signs, units, and whether quantities change. Update known answers and independent reference calculations before replacing the kernel.

To add scenarios, specify which axis means scenario and which means position. General broadcasting is developed in Section 6.6. Do not bypass the current equal-shape check by reshaping inputs until the desired scenario model is documented.

To aggregate positions, decide whether units and currencies are compatible and which output is being summed. Section 6.7 develops reductions. A numerical sum is not automatically a meaningful account total.

## 6.5.13 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| Shape unexpectedly expands | Unequal inputs and broadcasting | Enforce the declared shape contract |
| Short exposure shows negative mark | Signed-quantity convention | Interpret mark separately from cash/account equity |
| P&L differs from complete account change | Excluded cash flows or activity | Extend the financial contract explicitly |
| Flat position hides invalid data | Validation skipped for zeros | Validate all supplied inputs |
| Tiny product raises | Strict underflow policy | Review numerical bounds and policy |
| Printed cents agree but raw results differ | Formatting and finite precision | Compare unformatted values with justified criteria |
| Wrapped Python function is slow | np.vectorize convenience wrapper | Measure equivalent native-array alternatives |
| Source changes after calculation | In-place output or shared storage | Preserve the documented ownership contract |

## 6.5.15 Key Takeaways

Vectorization should preserve an explicit per-position calculation. Validate identity, units, shape, representation, and numerical domain before applying concise array expressions.

Known answers, scalar comparisons, and failure tests support different claims. Keep the scope of financial results and performance evidence clear as the implementation grows.
