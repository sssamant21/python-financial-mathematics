## 6.2.1 Purpose

An array is more than a container of displayed numbers. Its dimensions, element representation, and relationship to underlying storage determine how it behaves. A financial application must add an explicit interpretation for each axis and a policy for preserving source data.

This section builds a validated snapshot of a synthetic date-by-instrument price table. It emphasizes inspection and ownership before the later sections develop creation routines, indexing, broadcasting, and calculations.

## 6.2.2 Learning Objectives

1. Describe an ndarray using shape, ndim, size, dtype, itemsize, and nbytes.
2. Distinguish a scalar, vector, row, column, and table.
3. Define axis meaning independently from shape.
4. Explain assignment, shared views, and explicit numeric copies.
5. Validate label lengths, uniqueness, and numerical domain.
6. State what array validation cannot establish about financial observations.

## 6.2.3 The Array Object

An ndarray combines numerical storage with metadata describing how to interpret and access its entries. One dtype describes the element representation; axes organize the entries. A two-dimensional ndarray remains the ordinary array type used in this chapter, not the separate np.matrix class.

| Attribute | Question answered | Lab value |
|---|---|---|
| ndim | How many axes? | 2 |
| shape | How long is each axis? | (2, 3) |
| size | How many elements? | 6 |
| dtype | What is the element representation? | float64 |
| itemsize | How many bytes per element? | 8 |
| nbytes | How many bytes of element payload? | 48 |

The 48-byte value describes this array's element payload. It excludes labels, Python-object overhead, and other live arrays. It is not total process memory or a guarantee of a distinct allocation: multiple views can describe overlapping storage.

## 6.2.4 Shape Is a Contract

The following shapes represent different structures even when some contain the same number of values.

| Shape | ndim | Interpretation in a deliberately chosen API |
|---|---|---|
| () | 0 | One scalar observation |
| (3,) | 1 | One vector of three observations |
| (1, 3) | 2 | One row containing three observations |
| (3, 1) | 2 | Three rows with one observation each |
| (2, 3) | 2 | Two dates by three instruments in this lab |
| (0, 3) | 2 | Empty date axis; rejected here |

A one-dimensional vector is not automatically a row or a column. Adding an axis changes its structure. Reshaping is a deliberate design choice, not a generic repair for a failed shape check. Section 6.4 develops indexing and related operations.

The lab rejects every rank except two, including a zero-dimensional array holding one valid price. That does not make scalar arrays invalid in NumPy generally; it makes them outside this table API.

## 6.2.5 Give Axes Financial Meaning

The source table is:

| Observation label | ASSET-A | ASSET-B | ASSET-C |
|---|---|---|---|
| 2026-01-05 | 100.00 | 80.00 | 50.00 |
| 2026-01-06 | 105.00 | 76.00 | 50.00 |

Axis 0 means observation date; axis 1 means instrument. Labels are separate immutable tuples, and their lengths must match the corresponding axes. The function validates their shape and uniqueness but cannot establish that the caller assigned prices to the correct labels.

Date labels are treated as nonempty text. This example does not parse dates, verify chronological order, check market calendars, or validate actual instrument identifiers. Transposing numerical data requires corresponding changes to axis interpretation and labels; the test using a transposed source checks mechanical copying, not a claim that instruments become economic dates.

All prices are synthetic, nonnegative, finite, and assumed to share a currency and per-unit convention. No prices are aggregated or valued here. Currency, corporate-action treatment, observation timestamps, and data provenance remain caller responsibilities.

## 6.2.6 Validate Before Taking the Snapshot

The public price_snapshot function accepts an exact float64 ndarray with two nonempty axes and two exact tuples of unique nonempty unpadded string labels. It returns a writable independent C-order numeric copy.

| Condition | Failure behavior | Reason |
|---|---|---|
| Wrong object or dtype | TypeError | No hidden conversion policy |
| Wrong rank or empty axis | ValueError | Table contract requires observations and instruments |
| Label length mismatch | ValueError | Axis cannot be fully labeled |
| Duplicate or invalid label | ValueError | Identity must be explicit |
| Negative or nonfinite price | ValueError | Unsupported numerical domain |

Zero prices are allowed in this snapshot. A later return calculation may require strictly positive start prices, as Section 6.1 did. Validation rules belong to the operation: a valid stored observation is not automatically a valid denominator.

A snapshot provides independence from later ordinary source-array mutation. It is not a lock, a transaction, or a timestamped data capture. The caller must prevent concurrent modification during validation and copying when that matters.

## 6.2.7 Assignment, Views, and Copies

`alias = prices` binds another name to the same object. A basic slice such as `prices[:, :2]` shares numeric storage with the source. A numeric `prices.copy()` duplicates its values into independent storage. The lab demonstrates each relationship by changing one view entry.

A copy is appropriate when a scenario or stored snapshot must preserve the baseline. A view is useful when shared changes are intended and documented. Copying everything indiscriminately can consume unnecessary memory; sharing everything can corrupt assumptions. State the required ownership behavior at each boundary.

The independence claim here applies to native float64 storage. An object array can contain references to mutable Python objects, so copying the array's reference slots does not imply recursively copying those objects. This API rejects object dtype.

## 6.2.8 Conversion Does Not Imply Independence

np.asarray can return an existing compatible array without copying it. The test verifies that behavior for the exact source array used here. Therefore converting an input to an ndarray is not sufficient evidence that the caller's storage is protected.

If independence is required, request and verify a deliberate copy. This lab uses prices.copy(order='C') after validation. Read-only and noncontiguous source arrays are accepted because the function only reads them and returns its own writable copy. The output's C-order layout is an implementation contract, not a financial property.

## 6.2.10 File — array_contracts.py

```python
"""Inspect and snapshot synthetic date-by-instrument price arrays."""
import numpy as np


def price_snapshot(prices: np.ndarray, dates: tuple[str, ...],
                   instruments: tuple[str, ...]) -> np.ndarray:
    """Validate a nonempty float64 table and return independent numeric storage.

    Axis 0 is observation date; axis 1 is instrument. Labels are unique,
    nonempty unpadded text. Caller guarantees chronology, alignment, currency,
    per-unit convention, and any corporate-action policy. Zero prices allowed.
    """
    if type(prices) is not np.ndarray or prices.dtype != np.dtype('float64'):
        raise TypeError('prices must be an exact float64 ndarray')
    if prices.ndim != 2 or 0 in prices.shape:
        raise ValueError('prices must be a nonempty two-dimensional table')
    for name, labels, length in (('dates', dates, prices.shape[0]),
                                 ('instruments', instruments, prices.shape[1])):
        if type(labels) is not tuple:
            raise TypeError(f'{name} must be a tuple')
        if len(labels) != length:
            raise ValueError(f'{name} length does not match its axis')
        if any(type(label) is not str or not label or label.strip() != label for label in labels):
            raise ValueError(f'{name} labels must be nonempty unpadded text')
        if len(set(labels)) != length:
            raise ValueError(f'{name} labels must be unique')
    if not np.isfinite(prices).all() or (prices < 0).any():
        raise ValueError('prices must be finite and nonnegative')
    return prices.copy(order='C')


def main() -> None:
    dates = ('2026-01-05', '2026-01-06')
    instruments = ('ASSET-A', 'ASSET-B', 'ASSET-C')
    prices = np.array([[100.,80.,50.], [105.,76.,50.]], dtype=np.float64)
    snapshot = price_snapshot(prices, dates, instruments)
    print('Axes: date, instrument')
    print('Shape:', snapshot.shape)
    print('Dimensions:', snapshot.ndim)
    print('Elements:', snapshot.size)
    print('Dtype:', snapshot.dtype)
    print('Bytes per element:', snapshot.itemsize)
    print('Element bytes:', snapshot.nbytes)
    alias = prices
    view = prices[:, :2]
    independent = prices.copy()
    view[0, 0] = 999.
    print('Alias sees change:', bool(alias[0, 0] == 999.))
    print('Snapshot preserved:', bool(snapshot[0, 0] == 100.))
    print('Copy preserved:', bool(independent[0, 0] == 100.))


if __name__ == '__main__':
    main()
```

The demo intentionally mutates a source view only after the snapshot has been returned. The API itself does not modify the source. Label validation precedes allocation of the output copy.

## 6.2.11 File — test_array_contracts.py

```python
import unittest
import numpy as np
from array_contracts import price_snapshot

DATES = ('2026-01-05', '2026-01-06')
IDS = ('ASSET-A', 'ASSET-B', 'ASSET-C')


def fixture():
    return np.array([[100.,80.,50.],[105.,76.,50.]], dtype=np.float64)


class ArrayTests(unittest.TestCase):
    def test_attributes(self):
        result = price_snapshot(fixture(),DATES,IDS)
        self.assertEqual((result.ndim,result.shape,result.size),(2,(2,3),6))
        self.assertEqual(result.dtype,np.dtype('float64'))
        self.assertEqual((result.itemsize,result.nbytes),(8,48))
        np.testing.assert_array_equal(result,fixture())

    def test_independent_snapshot(self):
        source = fixture()
        result = price_snapshot(source,DATES,IDS)
        self.assertFalse(np.shares_memory(source,result))
        source[0,0] = 1.
        self.assertEqual(result[0,0],100.)
        result[1,0] = 2.
        self.assertEqual(source[1,0],105.)

    def test_alias_view_and_copy(self):
        source = fixture()
        alias, view, copy = source, source[:, :2], source.copy()
        self.assertIs(alias,source)
        self.assertTrue(np.shares_memory(view,source))
        view[0,0] = 999.
        self.assertEqual(alias[0,0],999.)
        self.assertEqual(copy[0,0],100.)

    def test_rank_and_empty_shapes(self):
        for value in (np.array(1.),np.array([1.,2.]),np.zeros((0,3)),np.zeros((2,0)),
                      np.zeros((1,2,3))):
            with self.assertRaises(ValueError):
                price_snapshot(value,DATES,IDS)

    def test_label_contract(self):
        for dates,ids in ((DATES,IDS[:2]),(DATES,('A','A','B')), (('',DATES[1]),IDS),
                          (DATES,(' A','B','C')), ((1,2),IDS)):
            with self.assertRaises(ValueError):
                price_snapshot(fixture(),dates,ids)
        with self.assertRaises(TypeError):
            price_snapshot(fixture(),list(DATES),IDS)

    def test_type_and_numeric_domain(self):
        for value in (fixture().tolist(),fixture().astype(np.float32),fixture().astype(object)):
            with self.assertRaises(TypeError):
                price_snapshot(value,DATES,IDS)
        for value in (-1.,np.nan,np.inf):
            source = fixture()
            source[0,0] = value
            with self.assertRaises(ValueError):
                price_snapshot(source,DATES,IDS)
        source = fixture()
        source[0,0] = 0.
        self.assertEqual(price_snapshot(source,DATES,IDS)[0,0],0.)

    def test_noncontiguous_and_readonly_source(self):
        source = fixture().T
        source.flags.writeable = False
        result = price_snapshot(source,IDS,DATES)
        np.testing.assert_array_equal(result,source)
        self.assertTrue(result.flags.c_contiguous)
        self.assertTrue(result.flags.writeable)
        self.assertFalse(np.shares_memory(source,result))

    def test_asarray_is_not_copy_guarantee(self):
        source = fixture()
        wrapped = np.asarray(source)
        self.assertIs(wrapped,source)
        copied = np.array(source,copy=True)
        self.assertFalse(np.shares_memory(copied,source))


if __name__ == '__main__':
    unittest.main(verbosity=2)
```

Eight discovered test methods should pass. The tests cover independent storage in both mutation directions, shared source/view behavior, rank rejection, label identity, dtype/domain rules, and a transposed read-only source.

The read-only test demonstrates that a writable result can be produced without changing the source's write permission. It does not make the original array writable. The snapshot is intentionally mutable; independence and immutability are different properties.

No tolerance is needed to compare these copied fixture values: the copy must preserve their stored representations. Later arithmetic may require explicit tolerances and separate checks for nonfinite results.

## 6.2.13 A Review Procedure for Array APIs

Before accepting a numerical table into a financial function, write down its axis meaning, expected rank, shape constraints, numerical representation, and domain. Then specify who owns the storage and whether the function may modify it.

Finally review identity and units outside the array. Matching dimensions and valid float64 entries cannot detect a mislabeled instrument, incorrect currency, stale price, or reversed observation order. Preserve those checks at the data boundary rather than assuming NumPy performs them.

## 6.2.14 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| Baseline changes after scenario edit | Alias or shared view | Copy deliberately at the scenario boundary |
| asarray result changes source | Storage reuse | Do not treat conversion as copy evidence |
| Rank check fails | Scalar/vector/row/column distinction | Construct the intended table explicitly |
| Label length mismatch | Axis meanings and ordering | Correct labels and data together |
| Copy uses extra memory | Snapshot policy and dataset size | Retain independence only where required |
| Object-array copy retains nested changes | Referenced Python objects | Use native numeric representation or design deep-copy policy |
| Nonfinite price rejected | Source data quality | Resolve missing/invalid data explicitly |
| Zero accepted here but rejected later | Operation-specific domain | Apply the downstream financial contract |

## 6.2.16 Key Takeaways

Inspect structure and state its meaning before calculating. An array API should define shape, dtype, domain, label alignment, and ownership.

Assignment, views, conversion, and copying have different storage implications. Test the relationship the caller needs, and keep financial identity and provenance checks explicit.
