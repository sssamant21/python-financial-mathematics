## 6.6.1 Purpose

Broadcasting lets arrays with compatible shapes participate in one calculation. In financial work, the important question is which axis each quantity is meant to vary along.

This section constructs a scenario-by-position table of synthetic price-only changes. It introduces singleton axes deliberately, checks an allocation budget, and compares the result with nested scalar arithmetic. No portfolio aggregation or scenario probability is implied.

## 6.6.2 Learning Objectives

1. Predict broadcast output shapes before calculating.
2. Use explicit singleton axes for scenario and position roles.
3. Detect silent errors when different axis lengths happen to match.
4. Distinguish broadcast input views from allocated arithmetic outputs.
5. Validate domain, numerical behavior, and output size.
6. Preserve the financial scope of a common-shock experiment.

## 6.6.3 Shape Compatibility

Compare dimensions from the right. Aligned dimensions must match or one must be 1; missing leading dimensions act as 1. Compatibility permits an operation, but does not establish its business meaning.

| Shapes | Broadcast result | Interpretation to review |
|---|---|---|
| (3,) and () | (3,) | One scalar applied to three positions |
| (4, 3) and (3,) | (4, 3) | A position vector reused across four rows |
| (4, 1) and (1, 3) | (4, 3) | Four scenarios crossed with three positions |
| (4,) and (3,) | Incompatible | Neither dimension is singleton |
| (3,) and (3,) | (3,) | Elementwise pairing, not all combinations |

Use np.broadcast_shapes to inspect compatibility without allocating a result table. The shape check itself cannot tell whether an axis means scenario, date, or instrument.

## 6.6.4 Define the Scenario Contract

Carry forward signed fixed quantities q and nonnegative prices P from Section 6.5. For each scenario s, apply one common proportional price shock h_s to every instrument:

\[
P'_{s,i}=P_i(1+h_s),\qquad
\Delta V_{s,i}=(q_iP_i)h_s.
\]

These equations define this experiment. Shocks are decimal fractions, not percentage-point shifts to a yield. A shock of -0.10 means a ten-percent price decrease. The lower bound -1 prevents a negative hypothetical price under this convention. There is no finite upper bound beyond representability and the output budget.

The kernel calculates the second expression directly, using (q*P)*h. It does not build or return shocked prices, subtract two computed marks, or claim bitwise equivalence with alternative arithmetic orders.

Quantities do not change. Fees, distributions, FX, financing, trades, margin, and corporate actions are excluded. A common proportional shock is an illustrative assumption, not a calibrated stress model, correlation model, or forecast. No probabilities or portfolio totals are supplied.

## 6.6.5 Assign Axis Roles Explicitly

| Quantity | Incoming shape | Calculation shape | Axis meaning |
|---|---|---|---|
| quantity | (N,) | Used to build marks (N,) | Position |
| price | (N,) | Used to build marks (N,) | Position |
| marks = quantity*price | (N,) | (1, N) | One reusable row of position marks |
| shocks | (S,) | (S, 1) | One shock per scenario row |
| output | — | (S, N) | Scenario, position |

`shocks[:, None]` introduces the position singleton axis. `marks[None, :]` introduces the scenario singleton axis. Their multiplication produces every scenario-position combination.

The labels remain caller-owned. Align quantity and price identities before entering the kernel and retain shock labels in their original order. Shape compatibility cannot correct mislabeled or reordered data.

## 6.6.6 The Silent Equal-Length Error

Suppose there are three shocks and three positions. Writing `marks * shocks` produces shape (3,), pairing shock 0 with position 0, shock 1 with position 1, and shock 2 with position 2. It runs successfully but answers a different question from the required nine combinations.

The tests include this equal-length trap and a four-scenario, two-position case. The unequal case helps expose accidental assumptions that a square fixture alone can hide. Check values, shape, and axis interpretation together.

Do not transpose or reshape inputs solely to silence an error. Write the intended output-axis contract first and derive the singleton placement from it.

## 6.6.7 Known Scenario Results

Opening signed marks are [1000, -400, 0]. Apply shocks [-0.10, 0.00, 0.10].

| Scenario shock | Long mark 1000 | Short mark -400 | Flat mark 0 |
|---|---|---|---|
| -0.10 | -100 | 40 | 0 |
| 0.00 | 0 | 0 | 0 |
| 0.10 | 100 | -40 | 0 |

A negative quantity makes a negative opening mark under this simplified convention. Multiplying it by a negative shock gives a positive price-only change. This does not describe total account equity or cash proceeds.

The output may display -0.0 in some zero entries because floating-point multiplication preserves a zero sign. This lab treats either zero sign as the same financial zero and does not normalize the stored result merely for display.

## 6.6.8 Memory and Ownership

Broadcasting can reuse input values without explicitly tiling them into full tables. np.broadcast_to exposes a read-only view that can share underlying storage; the test verifies that relationship and rejects direct writes through the view.

The arithmetic output is still allocated. A table with S scenarios and N positions contains S*N float64 entries, requiring 8*S*N element bytes, plus other live arrays and overhead. A cheap input view does not make a huge result free.

The API defaults to a maximum of 1,000,000 output cells and checks the Python-integer product before allocating the scenario result. This is a teaching allocation policy, not an operating-system memory reservation. Validation masks, marks, output checks, caller arrays, and other process memory are outside that cell count.

If larger work is required, design chunking and output retention around the downstream task. Reducing each chunk may avoid retaining a full table, but aggregation semantics belong to the next section and require their own tests.

## 6.6.9 Validation and Numerical Policy

Inputs must be exact nonempty one-dimensional float64 ndarrays with finite entries. Quantity and price shapes must match. Prices are nonnegative, shocks must be at least -1, and the output-cell budget must be a positive exact Python int; booleans are rejected.

Arithmetic raises on signaled overflow, underflow, divide, or invalid operations and checks that output values are finite. An overflowing opening mark fails even under a zero shock. This validates the declared operation order rather than silently rearranging it to avoid a failure.

Float64 remains approximate. Comparisons use rtol=1e-12 and atol=1e-12 for these small fixtures with NaNs disallowed. The tolerance is not a general financial materiality threshold. Signal handling and finite checks do not establish adequate precision for every possible input magnitude.

## 6.6.11 File — broadcasting_lab.py

```python
"""Apply common proportional price shocks across fixed positions."""
import numpy as np


def scenario_pnl(quantity: np.ndarray, price: np.ndarray,
                 shocks: np.ndarray, *, max_cells: int = 1000000) -> np.ndarray:
    """Return shape (scenarios, positions), using (q*p)*shock.

    Signed fixed quantities; nonnegative same-currency per-unit prices;
    common proportional shocks >= -1. No fees, cash flows, FX, or aggregation.
    Caller aligns quantity/price identities and retains scenario labels.
    """
    for name,value in (('quantity',quantity),('price',price),('shocks',shocks)):
        if type(value) is not np.ndarray or value.dtype != np.dtype('float64'):
            raise TypeError(f'{name} must be an exact float64 ndarray')
        if value.ndim != 1 or value.size == 0:
            raise ValueError(f'{name} must be a nonempty vector')
        if not np.isfinite(value).all():
            raise ValueError(f'{name} must be finite')
    if quantity.shape != price.shape:
        raise ValueError('quantity and price must align')
    if (price < 0).any() or (shocks < -1).any():
        raise ValueError('price must be nonnegative and shocks at least -1')
    if type(max_cells) is not int or max_cells < 1:
        raise ValueError('max_cells must be a positive exact int')
    if int(shocks.size) * int(price.size) > max_cells:
        raise ValueError('scenario output exceeds cell budget')
    with np.errstate(over='raise',under='raise',invalid='raise',divide='raise'):
        marks = quantity * price
        result = shocks[:,None] * marks[None,:]
    if not np.isfinite(result).all():
        raise ValueError('nonfinite scenario output')
    return result


def main() -> None:
    quantity = np.array([10.,-5.,0.])
    price = np.array([100.,80.,50.])
    shocks = np.array([-.1,0.,.1])
    result = scenario_pnl(quantity,price,shocks)
    print('Axes: scenario, position')
    print('Expanded shapes:',shocks[:,None].shape,price[None,:].shape)
    print('Output shape:',result.shape)
    print('Scenario P&L:',result.tolist())
    print('Output element bytes:',result.nbytes)


if __name__ == '__main__':
    main()
```

## 6.6.12 File — test_broadcasting_lab.py

```python
import unittest
import numpy as np
from broadcasting_lab import scenario_pnl


def inputs():
    return np.array([10.,-5.,0.]),np.array([100.,80.,50.]),np.array([-.1,0.,.1])

class BroadcastingTests(unittest.TestCase):
    def test_known_grid(self):
        result = scenario_pnl(*inputs())
        self.assertEqual(result.shape,(3,3))
        self.assertEqual(result.dtype,np.dtype('float64'))
        np.testing.assert_allclose(result,[[-100.,40.,0.],[0.,0.,0.],[100.,-40.,0.]],
                                   rtol=1e-12,atol=1e-12,equal_nan=False)

    def test_unequal_dimensions_and_scalar_reference(self):
        q,p = np.array([2.,-3.]),np.array([7.5,4.])
        shocks = np.array([-.2,0.,.1,.25])
        expected = [[(a*b)*s for a,b in zip(q.tolist(),p.tolist())] for s in shocks.tolist()]
        result = scenario_pnl(q,p,shocks)
        self.assertEqual(result.shape,(4,2))
        np.testing.assert_allclose(result,expected,rtol=1e-12,atol=1e-12,equal_nan=False)

    def test_axis_error_can_be_silent(self):
        q,p,s = inputs()
        wrong = (q*p)*s
        self.assertEqual(wrong.shape,(3,))
        self.assertNotEqual(wrong.shape,scenario_pnl(q,p,s).shape)
        self.assertEqual(scenario_pnl(np.array([2.]),np.array([5.]),np.array([.1])).shape,(1,1))

    def test_budget(self):
        self.assertEqual(scenario_pnl(*inputs(),max_cells=9).size,9)
        for budget in (8,0,-1,True,9.):
            with self.assertRaises(ValueError):
                scenario_pnl(*inputs(),max_cells=budget)

    def test_shape_and_dtype(self):
        for value in (np.array([]),np.array([[1.,2.,3.]])):
            with self.assertRaises(ValueError):
                scenario_pnl(inputs()[0],inputs()[1],value)
        with self.assertRaises(ValueError):
            scenario_pnl(np.array([1.]),inputs()[1],inputs()[2])
        with self.assertRaises(TypeError):
            scenario_pnl(inputs()[0],inputs()[1],np.array([0,1]))

    def test_domain_and_total_loss(self):
        for shocks in (np.array([-1.01]),np.array([np.nan]),np.array([np.inf])):
            with self.assertRaises(ValueError):
                scenario_pnl(inputs()[0],inputs()[1],shocks)
        np.testing.assert_array_equal(scenario_pnl(np.array([2.]),np.array([5.]),np.array([-1.])),[[-10.]])
        with self.assertRaises(ValueError):
            scenario_pnl(np.array([0.]),np.array([-1.]),np.array([0.]))

    def test_storage_and_readonly_broadcast_view(self):
        source = inputs()
        before = tuple(value.copy() for value in source)
        result = scenario_pnl(*source)
        for value,original in zip(source,before):
            np.testing.assert_array_equal(value,original)
            self.assertFalse(np.shares_memory(value,result))
        view = np.broadcast_to(source[1],(2,3))
        self.assertTrue(np.shares_memory(view,source[1]))
        self.assertFalse(view.flags.writeable)
        with self.assertRaises(ValueError):
            view[0,0] = 1.

    def test_numerical_failure_restores_policy(self):
        before = np.geterr().copy()
        with self.assertRaises(FloatingPointError):
            scenario_pnl(np.array([1e308]),np.array([2.]),np.array([0.]))
        self.assertEqual(np.geterr(),before)

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

The nested reference enumerates each shock and each aligned position explicitly. Its row order matches shocks and its column order matches quantities/prices. The one-scenario, one-position case retains both axes as (1, 1).

## 6.6.14 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| Expected grid, got vector | Equal-length position/shock pairing | Add singleton axes according to the contract |
| Broadcast error | Trailing dimensions | Predict compatible shapes before arithmetic |
| Scenarios applied along wrong axis | Axis meaning | Verify a nonsquare hand-calculated fixture |
| Broadcast view rejects assignment | Read-only shared view | Make a deliberate independent copy if mutation is needed |
| Cell-budget failure | S*N and max_cells | Reduce workload or design chunking deliberately |
| Large result despite small inputs | Cross-product size | Estimate output allocation, not only input sizes |
| Price shock below -1 rejected | Nonnegative hypothetical-price assumption | Review model scope rather than clipping silently |
| Zero shock still raises | Opening-mark overflow | Review numerical bounds and declared operation order |

## 6.6.16 Key Takeaways

Broadcasting is a shape mechanism. Financial meaning comes from deliberate axis roles, input alignment, units, and scenario assumptions.

Use singleton axes to express all-combination calculations, test nonsquare cases, and budget the actual output. Shared input views and independently allocated results have different ownership and memory implications.
