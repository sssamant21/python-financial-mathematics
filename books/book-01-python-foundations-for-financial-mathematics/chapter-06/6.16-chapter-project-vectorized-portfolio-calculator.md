## 6.16.1 Purpose

Build a small calculator that connects labeled holdings to vectorized scenario results. The project combines arrays, broadcasting, aggregation, weights, matrix products, validation, numerical limits, and acceptance tests. It is a calculation component with an executable demonstration, rather than a market-data application.

The central question is: given fixed opening holdings and several alternative closing-price scenarios, what happens to portfolio value in each scenario?

## 6.16.2 Learning Objectives

1. Define a financial contract before implementing array expressions.
2. Preserve asset identity and order across inputs.
3. Derive opening weights and asset return contributions.
4. Reconcile weighted returns with direct holdings valuation.
5. Reject malformed, unsupported, or numerically unsafe inputs.
6. Test an implementation with known answers and independent arithmetic.
7. Explain the difference between independent scenarios and a time path.
8. Keep reporting precision separate from calculation precision.

## 6.16.3 Project Contract

All quantities and prices are synthetic. Holdings are long-only, fixed throughout one common interval, and denominated in one currency with consistent per-unit price conventions. Fractional quantities are allowed. Opening prices must be strictly positive; closing prices may be zero, allowing total loss. At least one holding must have positive opening value.

There are no trades, deposits, withdrawals, distributions, fees, taxes, borrowing, shorts, FX conversions, or rebalancing. The asset named CASH in the demo is simply an instrument with a constant supplied price. The calculator does not assign special cash-account behavior based on its name.

Each scenario is an alternative end state from the same opening holdings. Rows are not successive dates. Do not compound the three demonstration returns or treat the scenario mean as an expected return: no probabilities or time sequence are supplied.

| Input | Shape | Meaning |
|---|---|---|
| assets | tuple of N strings | Ordered holding identities |
| quantities | (N,) | Fixed units held |
| opening_prices | (N,) | Common opening unit prices |
| scenario_assets | tuple of N strings | Explicit closing-price column identities |
| scenarios | tuple of S strings | Unique scenario row labels |
| closing_prices | (S,N) | One alternative closing-price row per scenario |

Both asset tuples must match exactly. The component rejects a mismatch rather than guessing a reordering. Shape agreement alone cannot establish identity. A caller can still mislabel a column; upstream data verification remains necessary.

## 6.16.4 Equations and Reconciliation

For asset i and scenario s:

- Opening asset value: v_i = q_i p_0i.
- Opening portfolio value: V_0 = sum_i v_i.
- Opening weight: w_i = v_i / V_0.
- Asset simple price return: R_si = p_si / p_0i − 1.
- Return contribution: C_si = w_i R_si.
- Portfolio return: r_s = sum_i C_si = (R @ w)_s.
- Ending value: V_s = sum_i q_i p_si = (P_1 @ q)_s.
- Price-only profit or loss: P&L_s = V_s − V_0.

In exact arithmetic, V_s = V_0(1+r_s). The implementation calculates ending values directly from holdings and prices, then uses tests to reconcile the two routes within explicit floating-point tolerances. This provides more useful evidence than checking only one expression against itself.

The contributions are dimensionless return contributions, measured in percentage points when multiplied by 100. They are not currency P&L. For the up scenario, contributions are 0.060, −0.015, and 0.000, summing to 0.045.

NumPy's matrix product uses the contracted inner dimension. Here (S,N) @ (N,) gives (S,). Multiplication by weights broadcasts (N,) across the rows of (S,N), preserving the contribution matrix. See the primary references for API details.

## 6.16.7 Calculator Implementation — portfolio.py

```python
"""Long-only, fixed-quantity, single-interval scenario calculator."""
from dataclasses import dataclass
import numpy as np

MAX_CELLS = 100_000


@dataclass(frozen=True)
class Report:
    assets: tuple
    scenarios: tuple
    opening_value: float
    weights: np.ndarray
    asset_returns: np.ndarray
    contributions: np.ndarray
    portfolio_returns: np.ndarray
    ending_values: np.ndarray
    pnl: np.ndarray


def labels(value, name):
    if not isinstance(value, tuple) or not value:
        raise ValueError(f"{name}: nonempty tuple required")
    if any(not isinstance(x, str) or not x or x != x.strip() for x in value):
        raise ValueError(f"{name}: nonempty, trimmed strings required")
    if len(set(value)) != len(value):
        raise ValueError(f"{name}: duplicate label")
    return value


def numeric(value, ndim, name):
    try:
        raw = np.asarray(value)
    except (ValueError, TypeError) as exc:
        raise ValueError(f"{name}: rectangular numeric input required") from exc
    if (raw.ndim != ndim or not raw.size or raw.size > MAX_CELLS
            or raw.dtype.kind not in "iuf"):
        raise ValueError(f"{name}: bounded real numeric array required")
    with np.errstate(over="raise", invalid="raise"):
        try:
            result = np.array(raw, dtype=np.float64, copy=True)
        except (ValueError, TypeError, FloatingPointError) as exc:
            raise ValueError(f"{name}: float64 conversion failed") from exc
    if not np.isfinite(result).all():
        raise ValueError(f"{name}: finite values required")
    return result


def calculate(assets, quantities, opening_prices, scenario_assets,
              scenarios, closing_prices):
    """Return independent scenario outcomes; no cash flows or rebalancing.

    Both asset-label tuples must match exactly in order. Quantities and
    prices are real numeric arrays/sequences. Boolean, text, object, and
    complex inferred dtypes are rejected; callers must not mix Booleans
    into numeric sequences, where NumPy inference can erase their type.
    """
    assets = labels(assets, "assets")
    scenario_assets = labels(scenario_assets, "scenario_assets")
    scenarios = labels(scenarios, "scenarios")
    if assets != scenario_assets:
        raise ValueError("asset identities and order must match")
    q = numeric(quantities, 1, "quantities")
    p0 = numeric(opening_prices, 1, "opening_prices")
    p1 = numeric(closing_prices, 2, "closing_prices")
    n = len(assets)
    if q.shape != (n,) or p0.shape != (n,) or p1.shape != (len(scenarios), n):
        raise ValueError("shape does not match labeled axes")
    if np.any(q < 0) or np.any(p0 <= 0) or np.any(p1 < 0):
        raise ValueError("require q >= 0, opening prices > 0, closing prices >= 0")
    try:
        with np.errstate(over="raise", divide="raise", invalid="raise", under="raise"):
            values = q * p0
            total = float(np.sum(values, dtype=np.float64))
            if total <= 0:
                raise ValueError("positive opening value required")
            weights = values / total
            returns = p1 / p0 - 1.0
            contributions = returns * weights
            portfolio_returns = returns @ weights
            ending_values = p1 @ q
            pnl = ending_values - total
    except FloatingPointError as exc:
        raise ValueError("calculation outside supported float64 range") from exc
    outputs = (weights, returns, contributions, portfolio_returns, ending_values, pnl)
    if not all(np.isfinite(x).all() for x in outputs):
        raise ValueError("nonfinite result")
    # Owned read-only arrays prevent routine accidental edits through the report.
    # This is an interface convention, not a security or deep-immutability boundary.
    for array in outputs:
        array.setflags(write=False)
    return Report(assets, scenarios, total, *outputs)


def demo():
    r = calculate(("ALPHA", "BETA", "CASH"), [6, 3, 1], [100, 100, 100],
                  ("ALPHA", "BETA", "CASH"), ("up", "down", "flat"),
                  [[110, 95, 100], [80, 105, 100], [100, 100, 100]])
    print(f"Opening value: {r.opening_value:.2f}")
    for name, ret, end, pnl in zip(r.scenarios, r.portfolio_returns,
                                  r.ending_values, r.pnl):
        print(f"{name}: return={ret:.2%}, ending={end:.2f}, pnl={pnl:.2f}")


if __name__ == "__main__":
    demo()
```

## 6.16.8 Validation and Ownership Decisions

The numeric helper accepts nonempty one- or two-dimensional real numeric inputs with inferred integer, unsigned-integer, or floating dtype. Text, object, complex, and Boolean dtypes are rejected. Numeric strings are not silently parsed. Mixed Boolean/numeric Python sequences can lose their Boolean identity during NumPy inference; callers must exclude such mixtures before this boundary. This teaching API is not a general-purpose schema validator for arbitrary untrusted data.

Every accepted numeric input is copied to float64. Calculations do not modify the caller's arrays. The report exposes read-only result arrays as protection against routine accidental writes. A frozen dataclass prevents ordinary field reassignment, but neither convention supplies deep or security-grade immutability.

The 100,000-cell limit applies separately to each numeric input. The closing matrix controls the dominant output shapes; the calculator avoids an extra scenario-by-asset-by-portfolio tensor. This bound is an educational workload policy, not a guarantee of peak memory consumption: constructing or converting the caller's input may already require allocation. Labels and Python object overhead are not included in a numeric cell budget.

Strict floating-point error handling rejects overflow, invalid operations, division errors, and detected underflow. It does not make float64 exact. Normal rounding still occurs; casting very large integers may lose precision without an exception. Use suitably scaled numeric inputs. The project is unsuitable for exact accounting ledgers, cent-exact settlement, or arbitrary extreme price ranges.

No rounding is applied to the stored results. The demo formats values only for display. Repeatedly rounding intermediate weights or returns can break reconciliation.

## 6.16.9 Acceptance Tests — test_portfolio.py

```python
import unittest
import numpy as np
from portfolio import calculate, MAX_CELLS


class PortfolioTests(unittest.TestCase):
    def run_case(self, **changes):
        args = dict(assets=("A", "B", "C"), quantities=[6, 3, 1],
                    opening_prices=[100, 100, 100], scenario_assets=("A", "B", "C"),
                    scenarios=("up", "down", "flat"),
                    closing_prices=[[110, 95, 100], [80, 105, 100], [100, 100, 100]])
        args.update(changes)
        return calculate(**args)

    def test_known_answers(self):
        r = self.run_case()
        self.assertEqual(r.opening_value, 1000)
        np.testing.assert_allclose(r.weights, [.6, .3, .1], rtol=0, atol=1e-12)
        np.testing.assert_allclose(r.portfolio_returns, [.045, -.105, 0], rtol=0, atol=1e-12)
        np.testing.assert_allclose(r.ending_values, [1045, 895, 1000], rtol=0, atol=1e-10)
        np.testing.assert_allclose(r.pnl, [45, -105, 0], rtol=0, atol=1e-10)

    def test_scalar_oracle_and_reconciliation(self):
        q, p0 = [2, 7, 0], [40, 12, 80]
        ends = [[44, 10, 90], [0, 0, 0]]
        r = self.run_case(quantities=q, opening_prices=p0,
                          scenarios=("mixed", "loss"), closing_prices=ends)
        total = sum(qi * pi for qi, pi in zip(q, p0))
        expected = [sum(qi * pi for qi, pi in zip(q, row)) for row in ends]
        np.testing.assert_allclose(r.ending_values, expected, rtol=1e-12, atol=1e-10)
        np.testing.assert_allclose(r.portfolio_returns,
                                   [(e-total)/total for e in expected], rtol=1e-12, atol=1e-12)
        np.testing.assert_allclose(r.contributions.sum(axis=1), r.portfolio_returns,
                                   rtol=1e-12, atol=1e-12)

    def test_column_permutation(self):
        r = self.run_case()
        other = self.run_case(assets=("C", "A", "B"), scenario_assets=("C", "A", "B"),
                              quantities=[1, 6, 3],
                              closing_prices=[[100, 110, 95], [100, 80, 105], [100, 100, 100]])
        np.testing.assert_allclose(other.portfolio_returns, r.portfolio_returns,
                                   rtol=1e-12, atol=1e-12)

    def test_labels_and_shapes(self):
        for change in [dict(scenario_assets=("B", "A", "C")), dict(assets=("A", "A", "C")),
                       dict(scenarios=("",)), dict(assets=["A", "B", "C"]),
                       dict(quantities=[1]), dict(closing_prices=[110, 95, 100]),
                       dict(closing_prices=[[1, 2], [3, 4]])]:
            with self.subTest(change=change), self.assertRaises(ValueError):
                self.run_case(**change)

    def test_invalid_numeric_and_domain(self):
        for change in [dict(quantities=[True, False, True]), dict(quantities=["6", "3", "1"]),
                       dict(quantities=[1j, 2, 3]), dict(quantities=[-1, 3, 1]),
                       dict(quantities=[0, 0, 0]), dict(opening_prices=[0, 100, 100]),
                       dict(opening_prices=[np.nan, 100, 100]),
                       dict(closing_prices=[[np.inf, 1, 1]] * 3),
                       dict(closing_prices=[[-1, 1, 1]] * 3)]:
            with self.subTest(change=change), self.assertRaises(ValueError):
                self.run_case(**change)

    def test_range_and_cell_limit(self):
        with self.assertRaises(ValueError):
            self.run_case(quantities=[1e308, 1, 1], opening_prices=[100, 100, 100])
        with self.assertRaises(ValueError):
            self.run_case(quantities=np.ones(MAX_CELLS + 1))

    def test_source_and_output_ownership(self):
        q = np.array([6., 3., 1.])
        r = self.run_case(quantities=q)
        q[0] = 99
        self.assertAlmostEqual(r.weights[0], .6)
        with self.assertRaises(ValueError):
            r.weights[0] = 0
        self.assertEqual(r.asset_returns.dtype, np.float64)
        self.assertEqual(r.contributions.shape, (3, 3))

    def test_single_asset_total_loss(self):
        r = calculate(("A",), [2], [50], ("A",), ("loss",), [[0]])
        self.assertEqual(r.portfolio_returns[0], -1)
        self.assertEqual(r.ending_values[0], 0)
        self.assertEqual(r.pnl[0], -100)


if __name__ == "__main__":
    unittest.main()
```

## 6.16.11 What the Tests Establish

| Check | Evidence |
|---|---|
| Known answers | Opening value, weights, scenario returns, ending values, P&L |
| Independent scalar route | Python holdings valuation reconciles with vectorized results |
| Contribution identity | Summed contributions agree with portfolio returns |
| Consistent column permutation | Reordering all aligned asset data preserves portfolio outcomes |
| Label and shape failures | Wrong order, duplicates, empty labels, vectors in matrix slots |
| Numeric and domain failures | Text, Boolean dtype, complex values, nonfinite and forbidden negatives |
| Range and size policies | Overflow and oversized numeric input fail |
| Ownership and edge case | Caller mutation isolation, ordinary read-only writes, one-asset total loss |

Return tolerances are dimensionless; value tolerances are in the fixture currency units. The tests use rtol and atol deliberately. They are suitable for these small synthetic fixtures, not universal thresholds for every portfolio size or numerical scale. There are no wall-clock performance assertions; Section 6.15 explains how to benchmark a specified boundary separately.

## 6.16.12 Troubleshooting

| Symptom | Likely explanation | Action |
|---|---|---|
| Asset order error | Closing columns use another ordering | Align columns explicitly and carry their labels together |
| Shape error | One scenario was passed as a vector | Use a matrix such as `[[110, 95, 100]]` and one row label |
| Positive opening value error | All quantities are zero | Supply an invested holding or handle an empty portfolio in a separate contract |
| Numeric dtype error | Prices were read as strings or objects | Parse and validate at the ingestion boundary |
| Range error | Unsupported magnitudes or tiny intermediate operations | Inspect units and scale; do not suppress the error blindly |
| Assignment fails | Report array is read-only | Make an explicit copy for separate analysis |
| Returns seem off by 100 | Percent display confused with decimal return | Store 0.045 and format as 4.50% |
| Reconciliation differs materially | Data conventions, alignment, or model assumptions differ | Verify units, currency, opening holdings, and omitted cash flows |
