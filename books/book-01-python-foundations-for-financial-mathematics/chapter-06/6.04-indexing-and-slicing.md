## 6.4.1 Purpose

Selecting the wrong observations can invalidate an otherwise correct calculation. An indexing expression must preserve the intended positions, axis meanings, labels, and ownership behavior.

This section selects instruments from a synthetic date-by-instrument price table. It compares elementary indexing patterns and implements a small identifier-aware boundary. It performs no valuation or investment screening.

## 6.4.2 Learning Objectives

1. Predict the values and shape of a selection.
2. Distinguish position selection from identifier lookup.
3. Preserve labels when filtering or reordering columns.
4. Compare paired coordinates with a rectangular cross product.
5. Use boolean masks on the intended axis.
6. Distinguish editing a selection copy from direct assignment into the source.

## 6.4.3 Source Table and Axis Contract

| Observation position | A | B | C |
|---|---|---|---|
| 0 | 100.00 | 80.00 | 50.00 |
| 1 | 105.00 | 76.00 | 51.00 |
| 2 | 103.00 | 78.00 | 52.00 |

Axis 0 contains three observation dates in caller-supplied order; axis 1 contains instruments A, B, C. Dates are not parsed in this lab. Negative position -1 means the final stored observation, which is only the latest date if the caller maintained chronological order.

Prices are synthetic, finite, nonnegative float64 values. Currency and per-unit conventions must already be consistent. Equal shape and valid numbers cannot prove that the labels were assigned correctly at ingestion.

## 6.4.4 Read the Expression Before Running

| Expression on this fixture | Result shape | Intended selection |
|---|---|---|
| prices[0, 1] | Scalar | Position 0, instrument B |
| prices[-1] | (3,) | Final stored observation |
| prices[:, 0] | (3,) | A across observations |
| prices[:, 0:1] | (3, 1) | A with a retained column axis |
| prices[0:2, :] | (2, 3) | First two observations |
| prices[::2, :] | (2, 3) | Observations 0 and 2 |
| prices[::-1, :] | (3, 3) | Reversed observation order |

The lab uses zero-based positions. Slice stops are excluded; an out-of-range slice can be empty, while an out-of-range integer index raises. A zero slice step is invalid. These behaviors need application-level interpretation: an empty interval may mean no data rather than a successful complete report.

Indexing a column with an integer removes that axis; a one-column slice retains it. Choose the rank required by downstream code instead of reshaping later to hide a mismatch.

## 6.4.5 Preserve Identity During Selection

The public select_instruments function takes a validated source table, its column IDs, and requested IDs. It resolves positions from IDs rather than requiring callers to remember column numbers.

Its contract requires exact tuples of unique nonempty unpadded strings. Source ID count must match the number of columns. Unknown or repeated requested IDs fail. The output order follows the request, so requesting C then A returns C then A across every observation.

An empty request is permitted and returns shape (number_of_dates, 0), with an empty label tuple. The nonempty source-table policy remains unchanged. This distinction makes empty selection explicit instead of inventing a placeholder instrument.

The returned numeric table is independent of the source. This boundary chooses an explicit copy for clarity even though the advanced selection already creates independent storage; the extra copy can be revisited when memory requirements justify it. The function reads all source values for validation, including unselected columns. Invalid unselected prices therefore still fail.

## 6.4.6 Coordinate Pairs or a Rectangle?

`prices[[0, 2], [0, 2]]` retrieves two coordinate pairs: (0, 0) and (2, 2), producing [100, 52]. That is not a two-by-two table.

For all combinations of observations 0 and 2 with instruments A and C, use `prices[np.ix_([0, 2], [0, 2])]`. The result is [[100, 50], [103, 52]]. np.ix_ expresses the cross product of axis selections.

Both are legitimate questions. In a financial table, selecting two dates and two instruments often means a rectangle, so a paired-coordinate expression can silently omit intended data. Test output shape as well as values.

## 6.4.7 Boolean Masks Need Axis Meaning

The demonstration mask `prices[-1] >= 80.0` has one entry per instrument. Applying it as `prices[:, mask]` retains all dates and selects qualifying columns. Apply the same mask to the ID sequence to preserve labels.

This threshold is an indexing exercise. Nominal prices across different instruments do not by themselves measure attractiveness, risk, or value. No investment rule is proposed.

A mask over the entire table answers a different question. `prices[prices >= 100.0]` collects matching individual values into a one-dimensional result, losing the table's date/instrument organization unless coordinates are preserved separately. The tests make this shape difference visible.

An incorrectly sized axis mask fails. A correctly sized but stale mask may select the wrong instruments after reordering; regenerate or realign the mask with its source identity. Parenthesize each comparison when combining array conditions with & or |, and use explicit any/all reductions when asking for one overall truth value.

## 6.4.8 Selection and Assignment Have Different Effects

Basic slices of these numeric arrays share storage. Editing such a view can edit the source. Advanced-index selection returns a copy, so editing that selected result does not update the original table.

Direct indexed assignment is different from editing a retrieved copy. The test shows that `source[:, [0, 2]][0, 0] = 999.0` edits a temporary selected array, while `source[0, [0, 2]] = [999.0, 888.0]` directly updates the intended source positions.

Prefer one clear assignment expression when a source update is intended. Use an independent copy when creating an experimental scenario. Avoid depending on chained indexing behavior that changes when one index changes from a slice to an integer array.

Repeated advanced indices also need care: an expression such as x[[0, 0]] += 1 is not a reliable way to count two increments at one location. Aggregation with repeated destinations requires a separately designed accumulation method. This selector rejects duplicate IDs and performs no accumulation.

## 6.4.10 File — indexing_lab.py

```python
"""Select synthetic price columns while preserving requested identifier order."""
import numpy as np


def select_instruments(prices: np.ndarray, ids: tuple[str, ...],
                       requested: tuple[str, ...]) -> tuple[np.ndarray, tuple[str, ...]]:
    """Return an independent date-by-requested-instrument table.

    Source: nonempty 2-D finite nonnegative float64 prices, unique column IDs.
    Requests are unique known IDs; an empty request returns shape (dates, 0).
    Caller guarantees date order, units, and original label/data alignment.
    """
    if type(prices) is not np.ndarray or prices.dtype != np.dtype('float64'):
        raise TypeError('prices must be an exact float64 ndarray')
    if prices.ndim != 2 or 0 in prices.shape:
        raise ValueError('source must be a nonempty 2-D table')
    if not np.isfinite(prices).all() or (prices < 0).any():
        raise ValueError('source prices must be finite and nonnegative')
    for labels in (ids, requested):
        if type(labels) is not tuple:
            raise TypeError('identifiers must be tuples')
        if any(type(s) is not str or not s or s.strip() != s for s in labels):
            raise ValueError('identifiers must be nonempty unpadded text')
        if len(set(labels)) != len(labels):
            raise ValueError('duplicate identifier')
    if len(ids) != prices.shape[1]:
        raise ValueError('source identifiers must match columns')
    positions = {sid: position for position, sid in enumerate(ids)}
    if any(sid not in positions for sid in requested):
        raise ValueError('unknown requested identifier')
    indices = np.array([positions[sid] for sid in requested], dtype=np.intp)
    return prices[:, indices].copy(), requested


def fixture() -> np.ndarray:
    return np.array([[100.,80.,50.],[105.,76.,51.],[103.,78.,52.]], dtype=np.float64)


def main() -> None:
    prices = fixture()
    ids = ('A','B','C')
    selected, labels = select_instruments(prices,ids,('C','A'))
    print('Requested IDs:', labels)
    print('Selected:', selected.tolist())
    print('Last date:', prices[-1].tolist())
    print('Column shapes:', prices[:,0].shape, prices[:,0:1].shape)
    print('Paired:', prices[[0,2],[0,2]].tolist())
    print('Rectangle:', prices[np.ix_([0,2],[0,2])].tolist())
    mask = prices[-1] >= 80.
    print('Latest-price mask:', mask.tolist())
    print('Masked IDs:', tuple(sid for sid,keep in zip(ids,mask) if keep))
    print('Masked table:', prices[:,mask].tolist())


if __name__ == '__main__':
    main()
```

The helper uses np.intp for positional indices. The explicit dtype also makes an empty request an integer index array rather than an accidentally inferred floating array. IDs remain text outside numerical storage.

## 6.4.11 File — test_indexing_lab.py

```python
import unittest
import numpy as np
from indexing_lab import fixture,select_instruments

IDS = ('A','B','C')

class IndexingTests(unittest.TestCase):
    def test_requested_order_and_independence(self):
        source = fixture()
        selected,labels = select_instruments(source,IDS,('C','A'))
        self.assertEqual(labels,('C','A'))
        np.testing.assert_array_equal(selected,[[50.,100.],[51.,105.],[52.,103.]])
        self.assertFalse(np.shares_memory(source,selected))
        selected[0,0] = 0.
        np.testing.assert_array_equal(source,fixture())

    def test_empty_and_one_column(self):
        self.assertEqual(select_instruments(fixture(),IDS,())[0].shape,(3,0))
        self.assertEqual(select_instruments(fixture(),IDS,('B',))[0].shape,(3,1))

    def test_identity_errors(self):
        for ids,request in ((IDS,('X',)),(IDS,('A','A')),(('A','A','C'),('A',)),
                            (('A','B'),('A',)),(IDS,(' A',))):
            with self.assertRaises(ValueError):
                select_instruments(fixture(),ids,request)
        with self.assertRaises(TypeError):
            select_instruments(fixture(),IDS,['A'])

    def test_source_contract(self):
        for source in (fixture().tolist(),fixture().astype(np.float32)):
            with self.assertRaises(TypeError):
                select_instruments(source,IDS,('A',))
        for source in (np.array([1.,2.,3.]),np.zeros((0,3)),np.full((3,3),np.nan)):
            with self.assertRaises(ValueError):
                select_instruments(source,IDS,('A',))

    def test_basic_slice_and_rank(self):
        source = fixture()
        self.assertEqual(source[:,0].shape,(3,))
        self.assertEqual(source[:,0:1].shape,(3,1))
        view = source[0:2,:]
        self.assertTrue(np.shares_memory(source,view))
        view[0,0] = 1.
        self.assertEqual(source[0,0],1.)
        self.assertEqual(source[99:100,:].shape,(0,3))
        with self.assertRaises(IndexError):
            _ = source[99]

    def test_pairs_versus_rectangle(self):
        source = fixture()
        np.testing.assert_array_equal(source[[0,2],[0,2]],[100.,52.])
        rectangle = source[np.ix_([0,2],[0,2])]
        np.testing.assert_array_equal(rectangle,[[100.,50.],[103.,52.]])
        self.assertFalse(np.shares_memory(source,rectangle))

    def test_boolean_selection_and_shape(self):
        source = fixture()
        mask = source[-1] >= 80.
        np.testing.assert_array_equal(source[:,mask],[[100.],[105.],[103.]])
        self.assertEqual(tuple(sid for sid,keep in zip(IDS,mask) if keep),('A',))
        with self.assertRaises(IndexError):
            _ = source[:,np.array([True,False])]
        self.assertEqual(source[source >= 100.].shape,(3,))

    def test_chained_copy_and_direct_assignment(self):
        source = fixture()
        source[:,[0,2]][0,0] = 999.
        self.assertEqual(source[0,0],100.)
        source[0,[0,2]] = [999.,888.]
        np.testing.assert_array_equal(source[0],[999.,80.,888.])

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

## 6.4.13 Review Before Downstream Calculation

After selection, inspect output rank and shape, label order, empty-result policy, and source-sharing behavior. When rows are filtered or reordered, apply the same operation to observation labels. When columns are filtered or reordered, apply it to instrument labels.

A positional selector does not validate chronology, exchange identifiers, currencies, or provenance. Nor does an independent copy create a concurrent transactional snapshot. Keep those guarantees separate and state which boundary enforces each one.

## 6.4.14 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| Expected rectangle, received vector | Paired advanced indices | Use np.ix_ for the intended cross product |
| Column rank unexpectedly reduced | Integer versus slice index | Retain the axis deliberately |
| Baseline changed after edit | Shared basic slice | Copy at the scenario boundary |
| Chained update has no source effect | Advanced-selection temporary | Use explicit direct assignment |
| Mask shape error | Mask axis/length | Align mask with the intended axis |
| Correct shape but wrong instrument | Stale label or mask order | Select values and identities together |
| Empty output passes silently | Slice/request policy | Handle no-match outcomes explicitly |
| Final row is not latest date | Observation order | Validate chronology before using positional language |

## 6.4.16 Key Takeaways

Indexing chooses observations and often changes rank or storage relationships. Predict those effects before applying financial calculations.

Preserve identifiers and observation labels with every selection. Distinguish pairs from rectangles, masks from labels, and retrieved copies from direct source assignment.
