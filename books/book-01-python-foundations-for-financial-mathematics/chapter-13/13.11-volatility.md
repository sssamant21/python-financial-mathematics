## Learning objectives

Define volatility as dispersion of period returns; distinguish population and sample standard deviations; compute rolling and annualized volatility; interpret the square-root-of-time assumption; introduce downside deviation, covariance, correlation, and portfolio diversification; build tested Python calculations and audit controls.

## 1. What volatility measures

**Return volatility** usually refers to the standard deviation of returns over a stated observation interval. It measures how widely observed returns vary around their average, not whether returns are positive or negative.

Volatility is a common measure of uncertainty, but it is not a complete measure of risk. It treats upside and downside deviations symmetrically and does not by itself capture liquidity risk, drawdown duration, tail losses, or the possibility of permanent capital impairment.

A volatility number is incomplete unless the return definition, observation frequency, sample window, and annualization convention are specified.

## 2. Return series and units

Consider five daily simple returns:

| Day | Return |
|---|---:|
| 1 | +2% |
| 2 | −1% |
| 3 | +3% |
| 4 | −2% |
| 5 | +1% |

Represent these in Python as decimal fractions:

```python
returns = [0.02, -0.01, 0.03, -0.02, 0.01]
```

The arithmetic mean daily return is:

**μ = (0.02−0.01+0.03−0.02+0.01)/5 = 0.006 = 0.6%.**

The volatility is calculated using deviations from this mean, not directly from zero.

## 3. Population versus sample volatility

For n observed returns R1,…,Rn and arithmetic mean μ:

**Population variance: σ² = Σ(Rt−μ)²/n.**

**Population volatility: σ = sqrt[Σ(Rt−μ)²/n].**

If the returns are treated as a sample for estimating an underlying return variance, the usual unbiased *sample variance* estimator is:

**s² = Σ(Rt−μ)²/(n−1).**

**Sample volatility: s = sqrt[Σ(Rt−μ)²/(n−1)].**

The sample variance estimator is unbiased under standard sampling assumptions; its square root is **not generally an unbiased estimator** of population standard deviation.

Use n for a descriptive population statistic and n−1 for a sample variance estimate. Always label which convention was used.

### Worked example A — Two observations

Returns are +10% and −10%.

Mean return: **0%**.

Sum of squared deviations: **0.10²+(−0.10)²=0.02**.

Population variance: **0.02/2=0.01**.

Population volatility: **sqrt(0.01)=10% per period**.

Sample variance: **0.02/(2−1)=0.02**.

Sample volatility: **sqrt(0.02)≈14.1421% per period**.

## 4. Worked five-day calculation

For the five daily returns above, μ=0.006.

| Return | Deviation from μ | Squared deviation |
|---:|---:|---:|
| +0.02 | +0.014 | 0.000196 |
| −0.01 | −0.016 | 0.000256 |
| +0.03 | +0.024 | 0.000576 |
| −0.02 | −0.026 | 0.000676 |
| +0.01 | +0.004 | 0.000016 |

Sum of squared deviations = **0.001720**.

Population variance = **0.001720/5 = 0.000344**.

Population volatility = **sqrt(0.000344)≈1.8547% daily**.

Sample variance = **0.001720/4 = 0.000430**.

Sample volatility = **sqrt(0.000430)≈2.0736% daily**.

## 5. Annualizing volatility

Under assumptions that period returns have constant variance and are uncorrelated, the variance of a sum over k periods is k times the one-period variance. Consequently:

**σ_annual ≈ σ_period × sqrt(k).**

For daily sample volatility of 1% and a **252-trading-day convention**:

**σ_annual≈0.01×sqrt(252)≈15.8745%.**

The square-root rule is an approximation, especially for compounded simple returns. It is more directly motivated by sums of log returns and assumptions about their covariance structure.

Do **not** multiply daily volatility by 252. That would be the wrong scaling for standard deviation under the stated assumptions.

### When square-root scaling can fail

If returns exhibit serial correlation, the variance of their sum includes covariance terms:

**Var(ΣXt) = ΣVar(Xt) + 2Σ_(i<j)Cov(Xi,Xj).**

Therefore, positive autocorrelation can increase multi-period volatility relative to the independent-return rule, while negative autocorrelation can reduce it. Volatility clustering, changing regimes, and heavy tails can further limit simple scaling.

## 6. Simple returns versus log returns

Volatility may be calculated from either simple or log returns, but the choice must be disclosed.

For positive gross factors:

**ℓ_t=ln(1+R_t).**

For small returns, log and simple returns are close; for large gains or losses, their dispersion can differ substantially.

A zero gross factor corresponds to a −100% simple return but does not have a finite logarithmic return. Avoid silently deleting total-loss observations when calculating log-return volatility.

## 7. Rolling volatility

A single full-sample standard deviation can hide changes over time. A **rolling volatility** calculation uses a moving window of recent returns.

For a 20-observation rolling sample volatility:

**s_t = std_sample(R_(t−19),...,R_t).**

The first 19 observations cannot produce a full 20-observation estimate. Do not silently substitute shorter windows unless that behavior is documented.

Rolling volatility responds to new observations but is sensitive to window size. A short window reacts quickly and can be noisy; a long window smooths recent changes.

## 8. Downside deviation

Standard deviation penalizes upside and downside surprises equally. **Downside deviation** instead focuses on observations below a target or minimum acceptable return (MAR).

One common definition is:

**DD = sqrt[(1/n)Σ min(0,Rt−MAR)²].**

For returns +10% and −10%, with MAR=0:

**DD = sqrt[(0²+(−0.10)²)/2] = sqrt(0.005) ≈ 7.0711%.**

This version divides by the total number of observations. Other methodologies use a different denominator or annualization policy. Document the convention before comparing downside deviation across systems.

## 9. Portfolio volatility and diversification

Portfolio volatility depends on asset variances **and covariances**. For two assets A and B with weights wA and wB:

**σp² = wA²σA² + wB²σB² + 2wAwBρσAσB**,

where ρ is the return correlation in [−1,1].

### Worked example B — Equal weights, zero correlation

Suppose both assets have volatility 20%, weights are 50% each, and correlation is zero:

**σp²=(0.5×0.2)²+(0.5×0.2)²=0.02**.

**σp=sqrt(0.02)≈14.1421%.**

If correlation were +1, portfolio volatility would be 20%. If correlation were −1 with equal volatilities and weights, the mathematical two-asset model gives zero volatility. Perfect negative correlation is a limiting idealization, not a reliable market assumption.

Diversification depends on co-movement, not merely on the number of assets held.

## 10. Realized versus forecast volatility

**Realized volatility** is calculated from observed historical returns. **Forecast volatility** is an estimate of future uncertainty produced by a model or judgment.

Historical standard deviation is not automatically a calibrated forecast. Forecast methods may include rolling windows, exponentially weighted moving averages, GARCH-family models, and option-implied measures. Their assumptions, data requirements, and failure modes differ.

The Python lab below focuses on transparent historical measures, not a predictive volatility model.

## 11. Numerical and data-quality safeguards

A production calculation should:

- Reject missing, non-finite, and nonnumeric observations.
- Require at least two observations for sample standard deviation.
- Preserve decimal-return units internally.
- Detect mismatched observation frequencies.
- Use split- and dividend-adjusted return series when appropriate.
- Avoid rounding individual returns before variance calculations.
- Flag stale prices and artificial zero returns from forward-filled valuations.
- Record the observation window, sample/population convention, and annualization basis.

## 12. Python hands-on lab

Save as **volatility.py** and run:

```bash

```

The standard-library implementation includes arithmetic means, population and sample volatility, rolling sample volatility, downside deviation, annualization, and two-asset portfolio volatility. It includes **12 reference unit tests**; independent runtime verification remains pending.

```python
import math
import statistics
import unittest

def checked(values, minimum=2):
    if len(values) < minimum:
        raise ValueError("insufficient observations")
    for x in values:
        if isinstance(x, bool) or not isinstance(x, (int, float)) or not math.isfinite(x):
            raise ValueError("returns must be finite numbers")
    return [float(x) for x in values]

def mean_return(returns):
    return math.fsum(checked(returns, 1)) / len(returns)

def population_volatility(returns):
    xs = checked(returns)
    mu = math.fsum(xs) / len(xs)
    return math.sqrt(math.fsum((x-mu)**2 for x in xs) / len(xs))

def sample_volatility(returns):
    xs = checked(returns)
    mu = math.fsum(xs) / len(xs)
    return math.sqrt(math.fsum((x-mu)**2 for x in xs) / (len(xs)-1))

def annualize_volatility(period_vol, periods_per_year):
    for x in (period_vol, periods_per_year):
        if isinstance(x, bool) or not isinstance(x, (int,float)) or not math.isfinite(x):
            raise ValueError("finite inputs required")
    if period_vol < 0 or periods_per_year <= 0:
        raise ValueError("invalid scale")
    return period_vol * math.sqrt(periods_per_year)

def downside_deviation(returns, target=0.0, sample=False):
    xs = checked(returns)
    if isinstance(target, bool) or not isinstance(target, (int,float)) or not math.isfinite(target):
        raise ValueError("invalid target")
    denominator = len(xs)-1 if sample else len(xs)
    return math.sqrt(math.fsum(min(0.0, x-target)**2 for x in xs) / denominator)

def rolling_sample_volatility(returns, window):
    xs = checked(returns)
    if isinstance(window, bool) or not isinstance(window,int) or window < 2 or window > len(xs):
        raise ValueError("invalid window")
    return [sample_volatility(xs[i-window:i]) for i in range(window,len(xs)+1)]

def portfolio_volatility(weight_a, sigma_a, weight_b, sigma_b, correlation):
    for x in (weight_a, sigma_a, weight_b, sigma_b, correlation):
        if isinstance(x,bool) or not isinstance(x,(int,float)) or not math.isfinite(x):
            raise ValueError("finite inputs required")
    if sigma_a < 0 or sigma_b < 0 or not -1 <= correlation <= 1:
        raise ValueError("invalid sigma or correlation")
    variance = (weight_a*sigma_a)**2 + (weight_b*sigma_b)**2 + 2*weight_a*weight_b*sigma_a*sigma_b*correlation
    return math.sqrt(max(0.0,variance))

class VolatilityTests(unittest.TestCase):
    def test_01_mean(self): self.assertAlmostEqual(mean_return([.1,-.1]),0)
    def test_02_population(self): self.assertAlmostEqual(population_volatility([.1,-.1]),.1)
    def test_03_sample(self): self.assertAlmostEqual(sample_volatility([.1,-.1]),math.sqrt(.02))
    def test_04_constant(self): self.assertEqual(sample_volatility([.03,.03,.03]),0)
    def test_05_annual(self): self.assertAlmostEqual(annualize_volatility(.01,252),.01*math.sqrt(252))
    def test_06_downside(self): self.assertAlmostEqual(downside_deviation([.1,-.1]),math.sqrt(.005))
    def test_07_target(self): self.assertAlmostEqual(downside_deviation([.01,.03],.02),math.sqrt(.00005))
    def test_08_rolling(self): self.assertEqual(len(rolling_sample_volatility([.1,.2,.3,.4],2)),3)
    def test_09_portfolio_zero_corr(self): self.assertAlmostEqual(portfolio_volatility(.5,.2,.5,.2,0),math.sqrt(.02))
    def test_10_perfect_corr(self): self.assertAlmostEqual(portfolio_volatility(.5,.2,.5,.2,1),.2)
    def test_11_perfect_hedge(self): self.assertAlmostEqual(portfolio_volatility(.5,.2,.5,.2,-1),0)
    def test_12_invalid(self):
        cases=[lambda:sample_volatility([.1]),lambda:population_volatility([float("nan"),.1]),
               lambda:annualize_volatility(.1,0),lambda:rolling_sample_volatility([.1,.2],1),
               lambda:portfolio_volatility(.5,.1,.5,.2,1.2)]
        for fn in cases:
            with self.assertRaises(ValueError):fn()

if __name__ == "__main__":
    rs=[.02,-.01,.03,-.02,.01]
    print("Sample daily volatility:",f"{sample_volatility(rs):.4%}")
    print("Annualized volatility (252-day convention):",
          f"{annualize_volatility(sample_volatility(rs),252):.4%}")
    unittest.main(verbosity=2)
```

## 15. Production and SRE considerations

- Monitor missing, stale, and late-arriving price observations.
- Keep price-return and total-return methodologies separate.
- Store sample window, observation frequency, and annualization convention.
- Reconcile calculations against a second implementation on representative data.
- Watch for false zero returns caused by stale marks.
- Detect structural breaks and extreme observations rather than automatically removing them.
- Maintain test coverage for zero variance, small samples, and invalid correlations.
- Treat volatility alerts as diagnostic signals, not standalone evidence of financial loss.
- Preserve reproducible source snapshots and calculation versions.
