## Learning objectives

Compute simple (arithmetic) returns from successive prices; distinguish dollar and percentage changes; calculate total simple returns with cash distributions and costs; link simple returns across periods; explain recovery asymmetry and the arithmetic-versus-compounded distinction; and implement validated calculations in Python.

## 1. Definition

A **simple return** measures the percentage change in investment value over a specified period. Given a strictly positive beginning price P0 and a nonnegative ending price P1:

**R = (P1−P0)/P0 = P1/P0−1.**

The numerator is the dollar price change; the denominator is the capital initially exposed to that change. A simple return is dimensionless and can be reported as a decimal or percentage.

The term *arithmetic return* is often used as a synonym for a simple period return. It does **not** mean that multi-period returns should be added rather than compounded.

### Worked example A — Gain

A share rises from $80 to $92.

**R=(92−80)/80=0.15=15%.**

Dollar gain=$12; percentage gain=15%.

### Worked example B — Loss

A share falls from $80 to $68.

**R=(68−80)/80=−0.15=−15%.**

Dollar loss=−$12; percentage loss=−15%.

## 2. Gross return factor

The **gross return factor** is:

**G = 1+R = P1/P0.**

For a +15% simple return, G=1.15. For a −15% simple return, G=0.85.

The gross return factor is useful for compounding because **successive factors multiply**.

For an unlevered long-only asset with nonnegative ending price, **R ≥ −100%**. Leverage, short positions, and liability exposures require a different model and may have returns below −100% relative to posted capital.

## 3. Return versus dollar change

Two assets can have identical dollar gains but very different percentage returns.

| Beginning value | Ending value | Dollar gain | Simple return |
|---:|---:|---:|---:|
| $50 | $55 | $5 | 10% |
| $500 | $505 | $5 | 1% |
| $5,000 | $5,005 | $5 | 0.1% |

Percentage returns normalize by beginning capital, but comparing returns also requires matching observation windows, currencies, risk exposures, and fee conventions.

## 4. Total simple return

If an asset pays cash income D during the holding period and investor-borne costs C are not already included in ending value:

**R_total=(P1−P0+D−C)/P0.**

For a share purchased at $100, valued at $105 at the end of the period, with a $3 dividend and $1 cost:

**R_price=(105−100)/100=5%.**

**R_total=(105−100+3−1)/100=7%.**

The formula assumes a single holding period, no external investor contributions or withdrawals, and no interim reinvestment of the cash distribution. When dividends are reinvested, or cash flows occur at different times, a return-index or subperiod-linking methodology is needed.

## 5. Simple returns from a price series

For observed prices P0,P1,…,Pn, calculate:

**R_t = P_t/P_(t−1)−1** for t=1,…,n.

Example:

| Time | Price | Simple return |
|---|---:|---:|
| 0 | $100 | — |
| 1 | $110 | +10% |
| 2 | $99 | −10% |
| 3 | $108.90 | +10% |

These are **period-by-period** returns, not cumulative returns measured from the original $100.

The endpoint return is:

**108.90/100−1=8.9%.**

## 6. Multi-period linking

With no external cash flows and consistent valuations:

**1+R_total = (1+R1)(1+R2)…(1+Rn).**

Therefore:

**R_total=∏(1+R_t)−1.**

For +10%, −10%, and +10%:

**(1.10)(0.90)(1.10)−1=8.9%.**

Adding the simple returns gives 10%, which is **not** the compounded cumulative return.

For a price-only series with valid nonzero intermediate prices, the factors telescope:

**∏[P_t/P_(t−1)] = P_n/P_0.**

Thus, linked simple price returns reconcile with the endpoint price return. This identity provides an excellent test invariant.

## 7. Arithmetic average versus compound growth

For period returns R1,…,Rn, the arithmetic mean is:

**R_arithmetic=(R1+…+Rn)/n.**

The geometric mean, when all gross return factors are positive, is:

**R_geometric=[∏(1+R_t)]^(1/n)−1.**

For +10% and −10%:

**Arithmetic mean = 0%.**

**Geometric mean = sqrt(0.99)−1 ≈ −0.5013%.**

The arithmetic mean describes an average one-period observation. The geometric mean describes an equivalent constant compound growth rate over the observations. Their distinct uses are examined in Section 13.8.

## 8. Loss and recovery asymmetry

If capital declines by fraction L, where 0<L<1, the return required to recover the original capital is:

**R_recovery = 1/(1−L)−1 = L/(1−L).**

For a 20% loss:

**R_recovery=0.20/0.80=25%.**

For a 50% loss:

**R_recovery=0.50/0.50=100%.**

This asymmetry is a consequence of the smaller post-loss capital base.

## 9. Cross-currency returns

Suppose an asset earns local-currency simple return R_local and the investor's domestic-currency value of one local-currency unit changes by R_FX.

Then:

**1+R_domestic=(1+R_local)(1+R_FX).**

If the asset gains 8% locally and the local currency depreciates 2% against the investor's domestic currency:

**R_domestic=1.08×0.98−1=5.84%.**

The FX quote direction is essential. Reversing the exchange-rate quotation without transforming the FX return produces the wrong answer.

## 10. Edge cases and data quality

- A beginning price of zero makes the standard simple-return formula undefined.
- Missing, stale, or nonpositive prices should be investigated; the introductory long-only model rejects negative prices.
- A zero ending value corresponds to a −100% price return.
- Splits and distributions must be handled to avoid artificial price-return jumps.
- An extreme return can reflect bad data, a corporate action, or a genuine market move.
- Compare returns over the same intervals, currencies, and fee bases.
- Never interpret a simple price return as a total return when distributions are relevant.
- For multiple observations, distinguish arithmetic averaging from geometric linking.

## 11. Python hands-on lab

Save the following as **simple_returns.py** and run `python simple_returns.py` and `python -m compileall -q simple_returns.py`.

The lab computes simple and total returns, wealth changes, linked returns, arithmetic averages, FX-adjusted returns, and returns from price series. It includes **12 reference unit tests**; independent runtime verification remains pending.

```python
import math
import unittest

def number(x, label):
    if isinstance(x, bool) or not isinstance(x, (int, float)) or not math.isfinite(x):
        raise ValueError(f'{label} must be finite numeric')

def simple_return(start, end):
    number(start, 'start'); number(end, 'end')
    if start <= 0 or end < 0:
        raise ValueError('start must be positive; end cannot be negative')
    return end / start - 1

def total_return(start, end, distribution=0.0, cost=0.0):
    for name, value in [('start', start), ('end', end), ('distribution', distribution), ('cost', cost)]:
        number(value, name)
    if start <= 0 or end < 0 or distribution < 0 or cost < 0:
        raise ValueError('invalid long-only cash flows')
    return (end - start + distribution - cost) / start

def wealth_after(start, r):
    number(start, 'start'); number(r, 'return')
    if start < 0 or r < -1:raise ValueError('invalid wealth or return')
    return start * (1 + r)

def link_returns(returns):
    if not returns:raise ValueError('returns required')
    factor = 1.0
    for r in returns:
        number(r, 'return')
        if r < -1:raise ValueError('simple return below -100%')
        factor *= 1 + r
    return factor - 1

def arithmetic_average(returns):
    if not returns:raise ValueError('returns required')
    for r in returns:number(r, 'return')
    return math.fsum(returns) / len(returns)

def fx_converted_return(local_return, fx_return):
    for x in (local_return, fx_return):
        number(x, 'return')
        if x < -1:raise ValueError('gross return cannot be negative')
    return (1 + local_return) * (1 + fx_return) - 1

def period_returns(prices):
    if len(prices) < 2:raise ValueError('two or more prices required')
    return [simple_return(a, b) for a, b in zip(prices, prices[1:])]

class Tests(unittest.TestCase):
    def test_01_gain(self):self.assertAlmostEqual(simple_return(100, 112), .12)
    def test_02_loss(self):self.assertAlmostEqual(simple_return(100, 88), -.12)
    def test_03_flat(self):self.assertEqual(simple_return(100, 100), 0)
    def test_04_total_loss(self):self.assertEqual(simple_return(100, 0), -1)
    def test_05_distribution(self):self.assertAlmostEqual(total_return(100, 105, 3), .08)
    def test_06_cost(self):self.assertAlmostEqual(total_return(100, 105, 3, 1), .07)
    def test_07_wealth(self):self.assertAlmostEqual(wealth_after(100, .12), 112)
    def test_08_compound(self):self.assertAlmostEqual(link_returns([.1, -.1]), -.01)
    def test_09_average(self):self.assertAlmostEqual(arithmetic_average([.1, -.1]), 0)
    def test_10_fx(self):self.assertAlmostEqual(fx_converted_return(.08, -.02), .0584)
    def test_11_price_series(self):
        x = period_returns([100, 110, 99]);self.assertEqual(len(x), 2)
        self.assertAlmostEqual(link_returns(x), -.01)
    def test_12_validation(self):
        cases = [lambda:simple_return(0, 10), lambda:simple_return(100, -1),
                 lambda:link_returns([]),lambda:link_returns([-.2, -1.1]),
                 lambda:arithmetic_average([]),lambda:period_returns([100])]
        for fn in cases:
            with self.assertRaises(ValueError):fn()

if __name__ == '__main__':
    prices = [100, 110, 99, 108.9]
    returns = period_returns(prices)
    print('Prices:', prices)
    print('Simple period returns:', [round(x, 6) for x in returns])
    print('Arithmetic mean:', arithmetic_average(returns))
    print('Linked return:', link_returns(returns))
    print('Endpoint return:', simple_return(prices[0], prices[-1]))
    unittest.main(verbosity=2)
```

## 14. Production and SRE considerations

Financial return pipelines require more than correct arithmetic:

- Preserve raw prices and the source timestamp.
- Record adjustment factors for corporate actions.
- Track missing or late data separately from valid zero returns.
- Make time-zone and trading-calendar assumptions explicit.
- Define return periods consistently across instruments.
- Validate price-to-return reconciliation as a pipeline quality gate.
- Record the price source and currency for auditability.
- Alert on implausible outliers without silently replacing genuine market movements.
