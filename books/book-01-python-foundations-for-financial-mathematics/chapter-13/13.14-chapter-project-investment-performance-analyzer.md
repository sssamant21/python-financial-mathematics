## Project brief

Build a reproducible **Investment Performance Analyzer** that calculates, reconciles, and reports the investment return and risk measures introduced in Sections 13.1–13.13. The project is intended as a realistic, audit-friendly Python foundation for investment analytics, not a trading recommendation or a production-certified performance engine.

The analyzer will support simple and compound returns, arithmetic and geometric averages, annualized volatility, maximum drawdown, Sharpe ratio, exact time-weighted return (TWR), and periodic money-weighted return (IRR). A later production extension can add dated XIRR, dividend-aware ledgers, fees, and multi-currency valuation.

## 1. Architecture and requirements

The project separates **input data**, **calculation functions**, **validation**, **reconciliation**, and **reporting**.

| Layer | Responsibility | Key control |
|---|---|---|
| Ingestion | Read periodic returns, valuations, and external flows | Validate types, ordering, and units |
| Returns | Calculate simple, cumulative, arithmetic, and geometric returns | Reconstruct terminal wealth |
| Risk | Calculate sample volatility, drawdown, Sharpe | Document frequency and convention |
| Flow analysis | Calculate exact TWR and periodic IRR | Distinguish manager from investor perspective |
| Reporting | Emit a reproducible scorecard | Record assumptions and QA evidence |

### Functional acceptance requirements

1. Reject empty and non-finite input series.
2. Reject nonpositive starting valuations and long-only returns below −100%.
3. Use decimal fractions internally; format percentages only for presentation.
4. Compute arithmetic and geometric returns independently.
5. Reconcile geometric growth with the cumulative return.
6. Use sample standard deviation for volatility.
7. Calculate drawdown from a compounded wealth index.
8. Match risk-free rate frequency to return frequency.
9. Distinguish external investor flows from investment income.
10. Reject IRR brackets without a sign change.
11. Report undefined risk ratios explicitly.
12. Provide deterministic unit tests and auditable worked examples.

## 2. Dataset A — Periodic strategy returns

Use these six **monthly simple total returns**, already adjusted for distributions:

| Month | Strategy | Benchmark |
|---|---:|---:|
| 1 | +3% | +2% |
| 2 | −2% | −1% |
| 3 | +4% | +3% |
| 4 | −1% | −2% |
| 5 | +2% | +1% |
| 6 | +1% | +1% |

Assume a monthly risk-free return of **0.2%** and 12 periods per year.

The strategy's arithmetic mean monthly return is:

**A=(3−2+4−1+2+1)%/6=7%/6≈1.1667%.**

The cumulative gross factor is:

**1.03×0.98×1.04×0.99×1.02×1.01**.

The cumulative return is that product minus one, and the geometric mean monthly return is the sixth root of the product minus one.

## 3. Dataset B — Exact time-weighted return

A portfolio starts with $100:

| Event | Pre-flow valuation | External flow afterward |
|---|---:|---:|
| First valuation | $110 | +$50 |
| Final valuation | $144 | $0 |

The first return is **110/100−1=+10%**.

After the contribution, the second period opens at $160; its return is **144/160−1=−10%**.

**Exact TWR = 1.10×0.90−1=−1%.**

The ending balance is $144, but the naive balance change of +44% includes a $50 contribution and is not the investment return.

## 4. Dataset C — Periodic investor cash flows

The investor-perspective cash flows associated with Dataset B are:

| Period | Cash flow |
|---|---:|
| 0 | −$100 |
| 1 | −$50 |
| 2 | +$144 |

Periodic IRR solves:

**−100−50/(1+r)+144/(1+r)²=0.**

The root is approximately **−2.25% per period**. TWR and IRR differ because they measure distinct economic questions, and their reporting horizons must be aligned.

## 5. Return calculations

For simple period returns r_i:

**Cumulative return = ∏(1+r_i)−1.**

**Arithmetic mean = Σr_i/n.**

**Geometric mean = [∏(1+r_i)]^(1/n)−1.**

For all r_i greater than −100%, a stable log-domain implementation is:

```python
math.expm1(math.fsum(math.log1p(r) for r in returns) / len(returns))
```

A −100% period is handled separately because its log return is undefined, although the compounded gross factor is zero.

## 6. Risk calculations

The analyzer uses sample standard deviation:

**s = sqrt[Σ(r_i−A)²/(n−1)].**

Annualized volatility is approximated by **s×sqrt(12)** for monthly returns under the usual scaling assumptions.

Drawdown uses a compounded wealth index:

**W_t=W_(t−1)(1+r_t)**.

**DD_t=W_t/max(W_0,...,W_t)−1.**

**Maximum drawdown=min_t DD_t.**

Sharpe ratio uses periodic excess return and sample volatility:

**Sharpe_annual≈[A−r_f,monthly]/s×sqrt(12)**.

This approximation assumes suitable return behavior; serial correlation and nonstationarity can invalidate the simple scaling.

## 7. Audit and reconciliation invariants

A reliable implementation must check:

- **Compound identity:** (1+geometric_mean)^n ≈ 1+cumulative_return.
- **Wealth identity:** ending wealth ≈ opening wealth × (1+cumulative_return).
- **Drawdown bounds:** −1 ≤ drawdown ≤ 0 for nonnegative long-only wealth.
- **AM–GM inequality:** arithmetic mean ≥ geometric mean for valid long-only gross factors.
- **Flow neutrality:** exact TWR excludes investor deposits and withdrawals from investment gains.
- **IRR residual:** NPV at the solved IRR is approximately zero.
- **Undefined denominator:** zero volatility, zero downside deviation, and zero drawdown must not be silently reported as meaningful ratios.

For reconciliation, use an absolute or relative tolerance appropriate to the numerical scale. Avoid assuming exact binary floating-point equality for calculated returns.

## 8. Python reference implementation

```bash

```

The implementation uses only the Python standard library and includes **12 reference unit tests**. Independent runtime execution and editorial verification remain pending.

```python
import math
import unittest

def finite(x):
    if isinstance(x, bool) or not isinstance(x, (int, float)) or not math.isfinite(x):
        raise ValueError("finite numeric input required")
    return float(x)

def returns_from_values(values):
    vs = [finite(v) for v in values]
    if len(vs) < 2 or any(v <= 0 for v in vs):
        raise ValueError("at least two positive valuations required")
    return [vs[i]/vs[i-1]-1 for i in range(1,len(vs))]

def link(returns):
    rs = [finite(x) for x in returns]
    if not rs or any(x < -1 for x in rs):
        raise ValueError("invalid returns")
    return math.prod(1+r for r in rs)-1

def arithmetic(returns):
    rs = [finite(x) for x in returns]
    if not rs: raise ValueError("empty returns")
    return math.fsum(rs)/len(rs)

def geometric(returns):
    rs = [finite(x) for x in returns]
    if not rs or any(x < -1 for x in rs): raise ValueError("invalid returns")
    if any(x == -1 for x in rs): return -1.0
    return math.expm1(math.fsum(math.log1p(r) for r in rs)/len(rs))

def sample_vol(returns):
    rs = [finite(x) for x in returns]
    if len(rs)<2: raise ValueError("at least two returns required")
    avg = arithmetic(rs)
    return math.sqrt(math.fsum((r-avg)**2 for r in rs)/(len(rs)-1))

def drawdowns(returns):
    rs = [finite(x) for x in returns]
    if any(r < -1 for r in rs): raise ValueError("invalid return")
    wealth = peak = 1.0
    result = [0.0]
    for r in rs:
        wealth *= 1+r
        peak = max(peak,wealth)
        result.append(wealth/peak-1)
    return result

def sharpe(returns, risk_free_period=0.0, periods_per_year=12):
    rs = [finite(x) for x in returns]
    rf = finite(risk_free_period)
    k = finite(periods_per_year)
    if k<=0: raise ValueError("invalid frequency")
    vol = sample_vol(rs)
    if vol==0: raise ValueError("undefined Sharpe: zero volatility")
    return (arithmetic(rs)-rf)/vol*math.sqrt(k)

def twr(initial, events):
    opening = finite(initial)
    if opening<=0 or not events: raise ValueError("invalid opening or events")
    factors=[]
    for i,(pre_flow,flow) in enumerate(events):
        pre_flow,flow=finite(pre_flow),finite(flow)
        if pre_flow<0: raise ValueError("negative valuation")
        if i==len(events)-1 and flow!=0: raise ValueError("final flow must be zero")
        factors.append(pre_flow/opening)
        opening=pre_flow+flow
        if i<len(events)-1 and opening<=0: raise ValueError("nonpositive post-flow value")
    return math.prod(factors)-1

def npv(rate, flows):
    rate=finite(rate)
    fs=[finite(f) for f in flows]
    if rate<=-1 or len(fs)<2: raise ValueError("invalid IRR input")
    return math.fsum(f/(1+rate)**i for i,f in enumerate(fs))

def irr(flows, low=-.9, high=1.0):
    fs=[finite(f) for f in flows]
    if not any(f<0 for f in fs) or not any(f>0 for f in fs):
        raise ValueError("IRR requires positive and negative cash flows")
    lo,hi=finite(low),finite(high)
    if lo<=-1 or hi<=lo: raise ValueError("invalid bracket")
    a,b=npv(lo,fs),npv(hi,fs)
    if a==0: return lo
    if b==0: return hi
    if a*b>0: raise ValueError("no bracketed root; check multiple roots")
    for _ in range(300):
        mid=(lo+hi)/2
        fm=npv(mid,fs)
        if abs(fm)<1e-10 or hi-lo<1e-12: return mid
        if a*fm<=0: hi,b=mid,fm
        else: lo,a=mid,fm
    raise RuntimeError("IRR failed to converge")

def report(returns, risk_free_period=0):
    rs=[finite(x) for x in returns]
    return {"arithmetic":arithmetic(rs),"geometric":geometric(rs),
            "cumulative":link(rs),"sample_volatility":sample_vol(rs),
            "maximum_drawdown":min(drawdowns(rs)),
            "annualized_sharpe":sharpe(rs,risk_free_period)}

class AnalyzerTests(unittest.TestCase):
    def test_01_simple_returns(self): self.assertEqual(returns_from_values([100,110,99]),[.1,-.1])
    def test_02_arithmetic(self): self.assertAlmostEqual(arithmetic([.2,-.1]),.05)
    def test_03_geometric(self): self.assertAlmostEqual(geometric([.2,-.1]),math.sqrt(1.08)-1)
    def test_04_link(self): self.assertAlmostEqual(link([.2,-.1]),.08)
    def test_05_total_loss(self): self.assertEqual(geometric([.1,-1]),-1)
    def test_06_volatility(self): self.assertAlmostEqual(sample_vol([.1,-.1]),math.sqrt(.02))
    def test_07_drawdown(self): self.assertAlmostEqual(min(drawdowns([.2,-.25])),-.25)
    def test_08_sharpe(self): self.assertAlmostEqual(sharpe([.1,-.1]),0)
    def test_09_twr(self): self.assertAlmostEqual(twr(100,[(110,50),(144,0)]),-.01)
    def test_10_irr(self): self.assertAlmostEqual(irr([-100,110]),.1)
    def test_11_reconciliation(self):
        rs=[.04,-.02,.03]
        self.assertAlmostEqual((1+geometric(rs))**len(rs),1+link(rs))
    def test_12_invalid(self):
        for fn in (lambda:returns_from_values([100,0]),
                   lambda:report([.1]),lambda:irr([100,200]),
                   lambda:twr(100,[(100,-100),(0,0)])):
            with self.assertRaises(ValueError): fn()

if __name__ == "__main__":
    sample=[.03,-.02,.04,-.01,.02,.01]
    for key,value in report(sample,.002).items():
        print(f"{key}: {value:.6f}")
    unittest.main(verbosity=2)
```

## 9. Sample report interpretation

A report for Dataset A should include:

- Arithmetic and geometric mean monthly returns.
- Linked cumulative six-month return.
- Monthly sample volatility and annualized volatility.
- Maximum drawdown over the six-month observation path.
- Annualized Sharpe ratio with monthly risk-free rate 0.2%.
- Source return frequency, currency, and fee basis.
- Observation count and methodology version.

A separate flow-analysis report should show **Dataset B exact TWR = −1%** and **Dataset C periodic IRR ≈ −2.25%**. Do not mix the return streams or imply that the same values measure the same horizon without a clear convention.

## 10. Failure-mode and troubleshooting scenarios

| Symptom | Likely cause | Corrective action |
|---|---|---|
| Geometric mean disagrees with cumulative return | Wrong exponent or return units | Recompute product and n-th root |
| Sharpe is enormous | Near-zero volatility or frequency mismatch | Validate denominator and risk-free conversion |
| Drawdown changes after a deposit | Raw account balance used | Rebuild flow-adjusted wealth index |
| IRR solver fails | No sign-changing bracket or multiple roots | Inspect cash flows and scan candidate brackets |
| NaN in report | Missing or non-finite observations | Reject or explicitly remediate source data |
| Annualized volatility inconsistent | Different trading/calendar convention | Declare k and sampling frequency |
| Portfolio TWR differs from investor IRR | Different flow sensitivity | Explain economic interpretation |
| Inconsistent dates | Late or out-of-order transactions | Sort and validate chronology before computing |
