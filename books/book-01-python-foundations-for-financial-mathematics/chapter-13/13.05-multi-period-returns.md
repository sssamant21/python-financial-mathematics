## 1. Why single-period returns are not enough

An investment held over multiple periods experiences gains and losses on a changing capital base. Each period's return applies to the **wealth remaining at the start of that period**, not necessarily to the original investment.

Let V_(t−1) be beginning wealth and V_t ending wealth for period t. Assuming no external contributions or withdrawals and consistent treatment of distributions:

**R_t = V_t / V_(t−1) − 1**.

The associated gross factor is **G_t=1+R_t**.

For n consecutive periods:

**V_n=V_0∏\[t=1..n\](1+R_t)**.

The cumulative multi-period simple return is therefore:

**R_(0,n)=∏\[t=1..n\](1+R_t)−1**.

## 2. Derivation of the compounding rule

For two periods:

**V_1=V_0(1+R_1)**.

**V_2=V_1(1+R_2)=V_0(1+R_1)(1+R_2)**.

Dividing by V_0 and subtracting one:

**R_(0,2)=(1+R_1)(1+R_2)−1**.

Expanding:

**R_(0,2)=R_1+R_2+R_1R_2**.

The interaction term **R_1R_2** explains why adding simple returns generally gives the wrong multi-period result.

### Worked example A — Gain followed by loss

An asset gains 20% and then loses 20%.

**G_total=1.20×0.80=0.96**.

**R_total=−4%**.

An initial $1,000 ends at **$960**, despite the arithmetic sum of the two returns being zero.

## 3. Wealth paths

A wealth path reports the hypothetical investment value after each return.

Starting with $10,000 and earning +10%, −10%, +5%, and −2%:

| Period | Return | Gross factor | End-of-period wealth |
|---|---:|---:|---:|
| 0 | — | — | $10,000.00 |
| 1 | +10% | 1.10 | $11,000.00 |
| 2 | −10% | 0.90 | $9,900.00 |
| 3 | +5% | 1.05 | $10,395.00 |
| 4 | −2% | 0.98 | $10,187.10 |

**Cumulative return = 10,187.10 / 10,000 − 1 = 1.871%.**

A wealth path helps reveal intermediate drawdowns and recovery dynamics that a final cumulative return alone does not show.

## 4. Return indices and rebasing

A **total-return index** can begin at an arbitrary base value such as 100 or 1,000:

**Index_0=100**.

**Index_t=Index_(t−1)(1+R_t)**.

For returns +5%, −2%, and +4%, an index beginning at 100 follows:

**100 → 105 → 102.9 → 107.016**.

The cumulative return is **7.016%**.

Changing the starting index base from 100 to 1,000 changes the displayed index levels, but not the returns.

A price-return index excludes distributions; a total-return index must specify the treatment of dividends, coupons, and reinvestment.

## 5. Endpoint-price reconciliation

For a strictly positive price series P0,…,Pn with no distributions or adjustments omitted:

**1+R_t=P_t/P_(t−1)**.

Multiplying gives:

**∏(1+R_t)=P_n/P_0**.

The intermediate prices cancel. This telescoping identity provides a valuable QA invariant.

For prices $100, $110, $99, and $108.90:

- Period returns: +10%, −10%, +10%.
- Linked gross factor: 1.10×0.90×1.10=1.089.
- Endpoint gross factor: 108.90/100=1.089.
- Cumulative return: **8.9%**.

This reconciliation assumes the same price adjustments, units, and timestamps are used throughout.

## 6. Arithmetic sum versus compound return

For +10%, −10%, +5%, and −2%:

**Arithmetic sum = 10%−10%+5%−2%=3%.**

**Compounded return = 1.10×0.90×1.05×0.98−1=1.871%.**

The arithmetic sum can approximate cumulative return when individual returns are sufficiently small and interaction terms are negligible, but it is not generally exact.

The arithmetic **mean** is a different statistic:

**R_arithmetic_mean = (ΣR_t)/n**.

It summarizes average period returns; it does not directly measure realized cumulative growth.

## 7. Geometric average return

The **geometric mean** is the constant period return that reproduces the same final wealth:

**R_geo = [∏(1+R_t)]^(1/n)−1**.

For +10% and −10%:

**R_geo=sqrt(0.99)−1≈−0.5013% per period**.

The arithmetic mean is 0%. The geometric mean captures the compounding drag of alternating gains and losses.

For a long-only series containing a −100% return, the compounded ending wealth is zero, and the equivalent geometric mean return is −100%.

## 8. Annualizing multi-period returns

If n observations span T years, the annualized effective return is:

**R_annual = (1+R_cumulative)^(1/T)−1**,

provided cumulative gross return is positive.

For regularly spaced periods with k periods per year, **T=n/k**, so:

**R_annual = [∏(1+R_t)]^(k/n)−1**.

For two consecutive annual returns of +10% each:

**R_cumulative=1.1²−1=21%**.

**R_annual=(1.21)^(1/2)−1=10%**.

An assumed 252 trading days per year is a convention, not an exact statement about every calendar year. Short sample annualizations can be unstable and should be labeled clearly.

## 9. Logarithmic linking

When every gross factor is strictly positive:

**ln(1+R_cumulative)=Σ ln(1+R_t)**.

For small returns, Python's `math.log1p` and `math.expm1` can improve numerical accuracy. Log linking is particularly useful for long return series, but it cannot directly represent a −100% return because ln(0) is undefined.

## 10. External cash flows and time-weighted linking

Suppose a portfolio begins at $100, grows to $110, receives a new investor contribution of $50, and then falls 10% from $160 to $144.

The investment subperiod returns are:

**First period: 110/100−1=+10%.**

**Second period: 144/160−1=−10%.**

The linked **time-weighted return** is:

**(1.10)(0.90)−1=−1%.**

A naive endpoint calculation **144/100−1=+44%** wrongly treats the $50 contribution as investment performance.

In practice, external cash flows must be timestamped and subperiod valuation conventions established. Exact time-weighted performance standards and approximations are covered in Section 13.9.

## 11. Multi-period returns across assets

A portfolio's one-period simple return with beginning-period weights w_i is:

**R_portfolio,t=Σw_(i,t−1)R_(i,t)**,

assuming a self-financing, unlevered portfolio and consistent timing.

To calculate multi-period portfolio return, first determine **each period's portfolio return**, accounting for weight drift or rebalancing, then compound across time:

**R_portfolio,cumulative=∏(1+R_portfolio,t)−1**.

Do not multiply different assets' same-period gross factors as though they were successive periods.

Use Python 3.9 or later and its standard library; no previous listing or external data is required. Inputs are interpreted as decimal text. The lab links exact rational factors and uses a local Decimal context for equivalent rates before reporting checked floats. Use the return-input route to represent a total loss; the price series helper requires strictly positive observations. The lab implements cumulative return, wealth-path construction, endpoint reconciliation, geometric means, annualization, and introductory time-weighted linking. It includes **12 reference unit tests**. Independent runtime verification remains pending.

```python
import math
import unittest
from decimal import Context, Decimal, DecimalException, localcontext
from fractions import Fraction

def _number(value,label,positive=False,signed=False):
    if isinstance(value,bool) or not isinstance(value,(int,float)):
        raise ValueError(f"invalid {label}")
    try:
        finite=math.isfinite(value)
    except OverflowError:
        finite=False
    if not finite or (not signed and value<0) or (positive and value==0):
        raise ValueError(f"invalid {label}")
    return Fraction(str(value))

_MIN_FLOAT=Fraction(math.ulp(0.0))

def _report(value,label):
    try:
        if 0<abs(value)<_MIN_FLOAT:
            raise OverflowError
        result=float(value)
    except OverflowError as exc:
        raise ValueError(f"{label} outside supported range") from exc
    if not math.isfinite(result):
        raise ValueError(f"{label} outside supported range")
    return result

def finite_number(x,name):
    _number(x,name,signed=True)

def _return(value):
    r=_number(value,"return",signed=True)
    if r<-1:
        raise ValueError("gross return cannot be negative in this model")
    return r

def _reported_return(value):
    result=_report(value,"return")
    if value>-1 and result==-1:
        raise ValueError("positive gross return rounds to total loss")
    return result

def _linked(returns):
    factors=[1+_return(r) for r in returns]
    if not factors:
        raise ValueError("returns required")
    return math.prod(factors),len(factors)

def _equivalent(factor,years):
    try:
        with localcontext(Context(prec=750)):
            g=Decimal(factor.numerator)/Decimal(factor.denominator)
            t=Decimal(years.numerator)/Decimal(years.denominator)
            result=(g.ln()/t).exp()-1
    except DecimalException as exc:
        raise ValueError("equivalent return outside supported range") from exc
    if result==-1:
        raise ValueError("positive gross return rounds to total loss")
    return _reported_return(result)

def valid_return(r):
    return float(_return(r))

def cumulative_return(returns):
    return _reported_return(_linked(returns)[0]-1)

def wealth_path(initial,returns):
    balance=_number(initial,"initial wealth",positive=True)
    factors=[1+_return(r) for r in returns]
    if not factors:
        raise ValueError("returns required")
    wealth=[_report(balance,"initial wealth")]
    for factor in factors:
        balance*=factor
        wealth.append(_report(balance,"wealth"))
    return wealth

def price_returns(prices):
    values=[_number(p,"price",positive=True) for p in prices]
    if len(values)<2:
        raise ValueError("at least two prices required")
    return [_reported_return((b-a)/a) for a,b in zip(values,values[1:])]

def geometric_mean(returns):
    factor,count=_linked(returns)
    return -1.0 if factor==0 else _equivalent(factor,Fraction(count))

def annualized_return(returns,periods_per_year):
    frequency=_number(periods_per_year,"periods per year",positive=True)
    factor,count=_linked(returns)
    return -1.0 if factor==0 else _equivalent(factor,count/frequency)

def time_weighted(subperiod_returns):
    return cumulative_return(subperiod_returns)

def endpoint_return(start,end):
    a=_number(start,"start",positive=True)
    b=_number(end,"end")
    return _reported_return((b-a)/a)

class MultiPeriodTests(unittest.TestCase):
    def test_01_one_period(self): self.assertAlmostEqual(cumulative_return([.1]), .1)
    def test_02_two_periods(self): self.assertAlmostEqual(cumulative_return([.1,-.1]), -.01)
    def test_03_three_periods(self): self.assertAlmostEqual(cumulative_return([.1,-.1,.1]), .089)
    def test_04_zero_return(self): self.assertEqual(cumulative_return([0,0]), 0)
    def test_05_total_loss(self): self.assertEqual(cumulative_return([.1,-1,.2]), -1)
    def test_06_wealth_path(self): self.assertEqual(len(wealth_path(100,[.1,-.1])),3)
    def test_07_wealth_endpoint(self): self.assertAlmostEqual(wealth_path(100,[.1,-.1])[-1],99)
    def test_08_price_reconciliation(self):
        prices=[100,110,99,108.9]
        self.assertAlmostEqual(cumulative_return(price_returns(prices)),endpoint_return(prices[0],prices[-1]))
    def test_09_geometric(self): self.assertAlmostEqual(geometric_mean([.1,-.1]),math.sqrt(.99)-1)
    def test_10_annualization(self): self.assertAlmostEqual(annualized_return([.1,.1],1),.1)
    def test_11_twr(self): self.assertAlmostEqual(time_weighted([.1,-.1]),-.01)
    def test_12_invalid(self):
        cases=[lambda:cumulative_return([]),lambda:cumulative_return([-1.01]),
               lambda:wealth_path(0,[.1]),lambda:price_returns([100,0]),
               lambda:annualized_return([.1],0),lambda:geometric_mean([])]
        for fn in cases:
            with self.assertRaises(ValueError):fn()
        self.assertEqual(cumulative_return([1e-30]),1e-30)
        with self.assertRaises(ValueError): annualized_return([-.99],252)

if __name__=='__main__':
    returns=[.10,-.10,.05,-.02]
    path=wealth_path(10000,returns)
    print('Wealth path:',[round(v,4) for v in path])
    print('Cumulative return:',f'{cumulative_return(returns):.4%}')
    print('Geometric mean per period:',f'{geometric_mean(returns):.4%}')
    unittest.main(verbosity=2)
```

## 13. Exercises with worked solutions

1. **Two gains:** +10%, then +10%. **Solution:** 1.1²−1=21%.
2. **Gain and loss:** +20%, then −20%. **Solution:** 1.2×0.8−1=−4%.
3. **Two losses:** −10%, then −10%. **Solution:** 0.9²−1=−19%.
4. **Three periods:** +10%, −10%, +10%. **Solution:** 1.1×0.9×1.1−1=8.9%.
5. **Four periods:** +10%, −10%, +5%, −2%. **Solution:** 1.01871−1=1.871%.
6. **Wealth:** $10,000 at cumulative +1.871%. **Solution:** $10,187.10.
7. **Index rebasing:** Base 100, return +5%. **Solution:** Index=105.
8. **Index loss:** Index 105, return −2%. **Solution:** Index=102.9.
9. **Index recovery:** Index 102.9, return +4%. **Solution:** Index=107.016.
10. **Endpoint:** Price $100 to $108.90. **Solution:** 8.9%.
11. **Arithmetic sum:** +10%, −10%, +5%, −2%. **Solution:** 3%; not equal to compounded 1.871%.
12. **Geometric mean:** +10%, −10%. **Solution:** sqrt(0.99)−1≈−0.5013%.
13. **Annualization:** 21% over two years. **Solution:** 10% annual effective.
14. **Total loss:** +20%, then −100%, then +50%. **Solution:** Cumulative −100%; wealth remains zero.
15. **Contribution:** Portfolio $100→$110, then $50 contribution. **Solution:** First subperiod return +10%; contribution is not return.
16. **Post-contribution:** $160→$144. **Solution:** −10% second subperiod return.
17. **Time-weighted:** Link +10% and −10%. **Solution:** −1%.
18. **QA invariant:** Why should linked price returns match Pn/P0−1? **Solution:** Intermediate price ratios cancel when multiplied.

## 15. Production and SRE considerations

- Record time zones, trading calendars, market-close conventions, and data sources.
- Apply corporate-action adjustments before generating price returns.
- Keep external contributions and withdrawals separate from investment gains.
- Track the distinction between price-return and total-return indices.
- Preserve sufficient numerical precision before display rounding.
- Test linked-versus-endpoint reconciliation.
- Avoid silently dropping zero-wealth events or invalid observations.
- Define how missing dates and stale prices are handled.
- Distinguish portfolio weight drift from periodic rebalancing.
