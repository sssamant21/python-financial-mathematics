## Learning objectives

Define logarithmic (continuously compounded) returns; convert between simple, gross, and log returns; derive time additivity; explain numerical stability and the −100% boundary; distinguish log returns from portfolio arithmetic; and implement reliable Python calculations.

## 1. Definition

For a strictly positive beginning price P0 and ending price P1, the **logarithmic return** is:

**ℓ = ln(P1/P0).**

If the simple return is **R=P1/P0−1**, then:

**ℓ = ln(1+R).**

Conversely:

**R = exp(ℓ)−1.**

The logarithmic return is sometimes called the **continuously compounded return**. It is a transformation of the observed price ratio, not an assertion that the investment literally compounds continuously.

### Worked example A — Positive return

A share rises from $100 to $110.

Simple return: **R=10%**.

Log return: **ℓ=ln(1.10)≈0.09531018**, or about **9.5310 log-percent units**.

Log and simple returns are different numerical measures of the same price change.

### Worked example B — Negative return

A share falls from $100 to $90.

Simple return: **R=−10%**.

Log return: **ℓ=ln(0.90)≈−0.10536052**.

For equal-sized positive and negative simple returns, log-return magnitudes are not symmetric.

## 2. Derivation from gross factors

Recall the gross return factor:

**G=1+R=P1/P0.**

Taking the natural logarithm:

**ℓ=ln(G)=ln(1+R).**

Because the natural logarithm converts products into sums, log returns have a particularly useful property over time.

For consecutive price observations P0,P1,…,Pn:

**Σ[t=1..n] ℓ_t = Σ ln(P_t/P_(t−1)).**

Using logarithm rules:

**Σ ℓ_t = ln[∏ P_t/P_(t−1)] = ln(P_n/P_0).**

Therefore **log returns are additive across consecutive time periods** when price observations are positive and the measurement conventions are consistent.

## 3. Worked multi-period example

An asset earns simple returns of +10%, −10%, and +10%.

| Period | Simple return | Gross factor | Log return |
|---|---:|---:|---:|
| 1 | +10% | 1.10 | ln(1.10) ≈ +0.09531018 |
| 2 | −10% | 0.90 | ln(0.90) ≈ −0.10536052 |
| 3 | +10% | 1.10 | ln(1.10) ≈ +0.09531018 |

The cumulative gross factor is:

**1.10×0.90×1.10=1.089.**

The cumulative simple return is **8.9%**.

The cumulative log return is:

**ln(1.089)≈0.085259.**

Summing the three period log returns produces the same cumulative log return, up to floating-point rounding.

## 4. Why log returns are not the same as simple returns

The Taylor expansion around R=0 is:

**ln(1+R)=R−R²/2+R³/3−…**, for |R|<1.

For small simple returns, **ℓ≈R**. The difference becomes more material for large movements.

| Simple return | Log return, approximately |
|---:|---:|
| +1% | +0.9950% |
| +10% | +9.5310% |
| +50% | +40.5465% |
| −10% | −10.5361% |
| −50% | −69.3147% |

A log return is not a percentage of beginning capital in the same direct sense as a simple return. Convert back to simple returns when reporting realized percentage wealth changes.

## 5. The −100% boundary

A simple return of −100% has gross factor zero.

**ln(0)** is not a finite real number. Therefore a finite log return requires:

**R > −1**, equivalently **P1/P0 > 0**.

As R approaches −1 from above, ln(1+R) approaches negative infinity.

A zero-price endpoint may be a valid total-loss observation in a long-only simple-return series, but it cannot be represented by a finite log return. Do not silently substitute zero or a missing value.

## 6. Continuous compounding interpretation

Suppose a value grows from V0 to VT over T years with constant continuously compounded rate g:

**VT=V0 exp(gT).**

Solving for g:

**g=ln(VT/V0)/T.**

For a cumulative gross factor of 1.21 over two years:

**g=ln(1.21)/2≈0.09531018 per year.**

The equivalent annual-effective simple rate is:

**exp(g)−1=10%.**

The continuously compounded rate and effective annual rate are equivalent descriptions of the same total growth, not numerically identical percentages.

## 7. Additivity across time versus aggregation across assets

Log returns **add across sequential periods** for the same evolving investment.

But a portfolio's one-period simple return with beginning-value weights w_i is:

**R_p=Σw_iR_i**.

Its log return is:

**ℓ_p=ln(1+Σw_iR_i)**.

In general:

**ℓ_p ≠ Σw_i ln(1+R_i).**

For example, two equally weighted assets return +20% and −20%. Portfolio simple return is zero; portfolio log return is zero. Weighted asset log returns instead equal **0.5ln(1.2)+0.5ln(0.8)=0.5ln(0.96)**, a negative number. They are not interchangeable.

## 8. Currency conversion

If a local-currency asset's simple return is R_a and the domestic-currency value of the local currency changes by R_fx:

**1+R_dom=(1+R_a)(1+R_fx).**

Taking logs gives:

**ℓ_dom=ℓ_a+ℓ_fx.**

For an 8% local asset gain and 2% local currency depreciation:

**ℓ_dom=ln(1.08)+ln(0.98)=ln(1.0584)**.

The domestic simple return is **5.84%**.

The FX quote direction must be consistent: the currency factor here is domestic currency per unit of local currency.

## 9. Mean log returns and geometric growth

For n strictly positive period gross factors, the arithmetic mean of log returns is:

**mean(ℓ) = (1/n)Σ ln(1+R_t).**

Exponentiating:

**exp[mean(ℓ)]−1 = [∏(1+R_t)]^(1/n)−1**.

This is exactly the geometric mean simple return. Thus, the mean log return is the log of the geometric mean gross factor.

However, the arithmetic mean of simple returns is generally different. Its use in expected return modeling is distinct from compound-growth estimation.

## 10. Numerical stability in Python

For small R, directly evaluating `math.log(1+R)` can lose precision when floating-point rounding makes 1+R indistinguishable from one. Use:

```python
math.log1p(R)
```

For converting a small log return ℓ back to a simple return, prefer:

```python
math.expm1(ell)
```

These functions are designed for improved accuracy near zero. They do not remove the need for domain checks, finite-value validation, or explicit handling of zero gross factors.

## 11. Python hands-on lab

Save the following as **logarithmic_returns.py**. Run `python logarithmic_returns.py` and `python -m compileall -q logarithmic_returns.py`.

The lab implements simple/log conversions, log returns from price ratios, time aggregation, annualized log growth, and currency conversion. It contains **12 reference unit tests**. Independent runtime verification remains pending.

```python
import math
import unittest

def check(value, label):
    if isinstance(value, bool) or not isinstance(value, (int, float)) or not math.isfinite(value):
        raise ValueError(f'{label} must be a finite number')

def log_from_simple(r):
    check(r, 'simple return')
    if r <= -1: raise ValueError('log return requires positive gross factor')
    return math.log1p(r)

def simple_from_log(ell):
    check(ell, 'log return')
    result = math.expm1(ell)
    if not math.isfinite(result): raise ValueError('converted return overflow')
    return result

def log_from_prices(start, end):
    check(start, 'start'); check(end, 'end')
    if start <= 0 or end <= 0: raise ValueError('strictly positive prices required')
    return math.log(end / start)

def sum_log_returns(returns):
    if not returns: raise ValueError('nonempty returns required')
    return math.fsum(log_from_simple(r) for r in returns)

def linked_simple(returns):
    return simple_from_log(sum_log_returns(returns))

def log_return_series(prices):
    if len(prices) < 2: raise ValueError('at least two prices required')
    return [log_from_prices(a, b) for a, b in zip(prices, prices[1:])]

def annualized_log(log_growth, years):
    check(log_growth, 'log growth'); check(years, 'years')
    if years <= 0: raise ValueError('years must be positive')
    return log_growth / years

def domestic_log_return(local_simple, fx_simple):
    return log_from_simple(local_simple) + log_from_simple(fx_simple)

class LogReturnTests(unittest.TestCase):
    def test_01_positive(self): self.assertAlmostEqual(log_from_simple(.10), math.log(1.1))
    def test_02_negative(self): self.assertAlmostEqual(log_from_simple(-.20), math.log(.8))
    def test_03_zero(self): self.assertEqual(log_from_simple(0), 0)
    def test_04_inverse(self): self.assertAlmostEqual(simple_from_log(log_from_simple(.08)), .08)
    def test_05_price_ratio(self): self.assertAlmostEqual(log_from_prices(100, 110), math.log(1.1))
    def test_06_additivity(self):
        self.assertAlmostEqual(sum_log_returns([.1, -.1]), math.log(.99))
    def test_07_linked(self): self.assertAlmostEqual(linked_simple([.1, -.1]), -.01)
    def test_08_series(self):
        x = log_return_series([100, 110, 99])
        self.assertEqual(len(x), 2)
        self.assertAlmostEqual(math.fsum(x), math.log(.99))
    def test_09_annualize(self): self.assertAlmostEqual(annualized_log(math.log(1.21), 2), math.log(1.1))
    def test_10_fx(self):
        self.assertAlmostEqual(simple_from_log(domestic_log_return(.08, -.02)), .0584)
    def test_11_small_return(self):
        self.assertAlmostEqual(log_from_simple(1e-10), 1e-10, places=18)
    def test_12_invalid(self):
        cases = [lambda:log_from_simple(-1), lambda:log_from_simple(-1.2),
                 lambda:log_from_prices(100, 0), lambda:log_return_series([100]),
                 lambda:sum_log_returns([]), lambda:annualized_log(.1, 0),
                 lambda:log_from_simple(float('nan'))]
        for fn in cases:
            with self.assertRaises(ValueError): fn()

if __name__ == '__main__':
    prices = [100, 110, 99, 108.9]
    logs = log_return_series(prices)
    print('Prices:', prices)
    print('Log returns:', [round(x, 8) for x in logs])
    print('Sum of log returns:', math.fsum(logs))
    print('Endpoint log return:', log_from_prices(prices[0], prices[-1]))
    print('Linked simple return:', simple_from_log(math.fsum(logs)))
    unittest.main(verbosity=2)
```

## 14. Production considerations

- Apply corporate-action adjustments before constructing price-based log returns.
- Use consistent time windows, time zones, and currency conventions.
- Reject missing, stale, or invalid prices rather than fabricating returns.
- Distinguish zero-price events from missing data.
- Avoid aggregating asset log returns as if they were portfolio log returns.
- Use `log1p` and `expm1` for numerical accuracy near zero.
- Record any filtering of extreme returns, including the business rationale.
- Validate that linked returns reconcile with endpoint wealth.

## 15. Completion and next section

Log returns transform multiplicative wealth growth into additive changes across time. Their properties are especially useful for time-series analysis, statistical modeling, and continuous-compounding mathematics, provided their domains and aggregation rules are respected.
