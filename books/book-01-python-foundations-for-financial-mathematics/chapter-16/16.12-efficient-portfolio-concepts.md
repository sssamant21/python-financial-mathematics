## Learning objectives

Define feasible and efficient portfolios; distinguish the global minimum-variance portfolio from the efficient frontier; identify mean–variance dominance; solve target-return and risk-budget questions; interpret the Sharpe ratio and capital allocation; and implement a transparent, constrained grid-search reference in standard-library Python.

## 1. From portfolio arithmetic to portfolio choice

Earlier sections established how portfolio expected return and volatility depend on weights, asset means, and covariance. Portfolio selection adds a decision: **which feasible weights should an investor choose?**

For n assets, let **w** denote portfolio weights, **μ** the expected-return vector, and **Σ** the covariance matrix. Under fixed one-period weights:

**μₚ=wᵀμ**, and **σₚ²=wᵀΣw**.

These are forecasts based on estimated inputs. The mathematics is exact for the specified model, but the inputs are uncertain.

## 2. Feasible portfolio set

A portfolio is **feasible** if its weights satisfy the chosen constraints.

For a fully invested long-only portfolio:

**Σᵢwᵢ=1** and **wᵢ≥0**.

Additional constraints may limit sector weights, leverage, turnover, liquidity, position sizes, or exposure to individual issuers.

The feasible set is a mathematical representation of what the investor can actually hold. Changing constraints changes the opportunity set and its efficient boundary.

## 3. The mean–variance opportunity set

Each feasible portfolio maps to a point in expected-return/risk space:

**(σₚ, μₚ)**.

Plotting all feasible portfolios reveals the tradeoffs available under the chosen universe and assumptions.

A high-return portfolio can also be high-risk. A low-risk portfolio may have lower expected return. Efficiency asks whether one portfolio is **unambiguously worse** than another under the two selected criteria.

## 4. Mean–variance dominance

Portfolio A **dominates** portfolio B when:

**μ_A≥μ_B** and **σ_A²≤σ_B²**,

with at least one strict inequality.

For example:

| Portfolio | Expected return | Variance | Interpretation |
|---|---:|---:|---|
| A | 8% | .020 | Dominates B |
| B | 6% | .030 | Dominated |
| C | 9% | .040 | Tradeoff versus A |

A dominates B because it offers both a higher expected return and lower variance. Neither A nor C dominates the other: C offers more expected return at more risk.

Mean–variance dominance is conditional on the two modeled criteria; investors may also care about taxes, liquidity, tail risk, and nonfinancial objectives.

## 5. The efficient set and efficient frontier

The **mean–variance efficient set** contains feasible portfolios not dominated by another feasible portfolio.

The **efficient frontier** is the boundary of the attainable mean–variance region that gives the greatest expected return for a specified variance, or the least variance for a specified expected-return requirement, subject to the chosen constraints.

A portfolio can be feasible without being efficient. A low-return/high-risk allocation may be dominated by a better combination of the same assets.

The efficient frontier is not a guarantee of future outperformance.

## 6. The global minimum-variance portfolio

The **global minimum-variance (GMV) portfolio** minimizes:

**min_w wᵀΣw**

subject to the relevant feasibility constraints.

The GMV portfolio has the smallest modeled variance in the feasible set, regardless of expected return.

For two assets with σ_A=.2, σ_B=.3, and zero covariance:

**w_A,GMV=.09/(.04+.09)=.09/.13≈.6923**.

**w_B,GMV≈.3077**.

The minimum variance is:

**(.04×.09)/(.04+.09)=.0036/.13≈.0276923**.

Thus **σ_GMV≈16.64%**.

This is the analytical optimum for this simple two-asset example, not a numerical grid approximation.

## 7. Minimum variance for a required expected return

A common constrained formulation is:

**min_w wᵀΣw**

subject to:

**wᵀμ≥μ_target**, **Σᵢwᵢ=1**, and **wᵢ≥0**.

For two assets with μ_A=.08 and μ_B=.04:

**μₚ=.04+.04w_A**.

A target of 7% requires:

**.04+.04w_A≥.07**, so **w_A≥.75**.

A target of 10% is infeasible in this long-only two-asset universe because neither asset has an expected return above 8%.

## 8. The upper efficient branch

For two assets with different expected returns and a nondegenerate covariance matrix, the opportunity set generally contains a lower-return branch and a higher-return branch around the GMV point.

When higher expected return requires more of asset A, the branch extending from the GMV allocation toward greater A exposure may form the efficient frontier, subject to the feasible interval and the actual expected-return ordering.

Do not assume every point with a high weight in one asset is efficient. Test dominance against the entire feasible set.

## 9. Variance versus volatility as the risk axis

Variance and volatility rank portfolios identically because square root is increasing for nonnegative values.

Thus a portfolio with minimum variance also has minimum volatility. The shape of the frontier changes when the horizontal axis uses σ rather than σ², but the underlying dominance ordering does not.

Volatility is generally easier to interpret because it is measured in the same units as returns.

## 10. Introducing a risk-free asset

A hypothetical risk-free asset offers a known payoff over a specified horizon and currency. With a risky portfolio and a risk-free asset, combinations can be formed by varying the fraction invested in the risky portfolio.

If risky-portfolio expected return is μ_R, volatility σ_R, and the risk-free rate is r_f, then for risky allocation y:

**μ_C=r_f+y(μ_R−r_f)**,

**σ_C=|y|σ_R**,

under the simplified assumption that the risk-free asset has zero return variance and covariance over the matched horizon.

Borrowing and lending rates may differ, and leveraged positions have financing and collateral constraints.

## 11. Sharpe ratio

For positive volatility:

**Sharpe=(μₚ−r_f)/σₚ**.

If μₚ=.08, r_f=.02, and σₚ=.20:

**Sharpe=(.08−.02)/.20=.30**.

This is an expected Sharpe ratio under the assumed inputs, not an observed performance statistic.

A zero-volatility portfolio requires separate handling; the usual ratio divides by zero. Sharpe ratios also do not fully describe skewness, tail risk, or nonlinear payoffs.

## 12. Capital allocation line intuition

Under frictionless borrowing/lending at a common risk-free rate, combinations of a fixed risky portfolio and the risk-free asset trace a line in expected-return/volatility space.

Its slope is the risky portfolio's Sharpe ratio when y≥0. Among feasible risky portfolios, the maximum-Sharpe portfolio defines the steepest such line under the assumptions.

This **tangency portfolio** is distinct from the GMV portfolio in general. Both depend on the expected-return and covariance estimates and the allowed investment universe.

## 13. Constraints change efficiency

Real portfolio constraints may include:

- Long-only or limited short selling.
- Maximum position, sector, and country exposures.
- Minimum cash and liquidity buffers.
- Gross and net leverage limits.
- Turnover budgets and trading costs.
- Issuer, duration, currency, or credit-quality limits.
- Tax, regulatory, or mandate restrictions.

A portfolio efficient in an unconstrained model may be infeasible for a real account.

## 14. Discrete grids versus continuous optimization

A simple way to explore an efficient set is to enumerate feasible weight vectors on a grid.

For two assets with weights in increments of .1, the grid contains **11 portfolios**. For three assets with weights in increments of .25, it contains **15 portfolios**.

A grid is transparent and useful for teaching, but it is only an approximation to a continuous optimization problem. The true optimum may lie between grid points, and the number of grid portfolios grows rapidly with asset count and resolution.

## 15. Pareto filtering

After generating candidate portfolios:

1. Compute expected return and variance for each.
2. Compare each candidate with every other candidate.
3. Remove candidates dominated on both criteria.
4. Keep nondominated portfolios as the **grid-efficient subset**.
5. Sort the remaining points by volatility or expected return for presentation.

Floating-point tolerances must be documented. A coarse grid can produce a jagged approximation even when the continuous efficient frontier is smooth.

## 16. Estimation uncertainty and optimizer instability

Expected-return estimates are particularly noisy. Small changes in forecasts can create large changes in optimized weights.

Covariance estimates can also be unstable when assets are highly correlated or the sample is small.

Practical controls include shrinkage, exposure limits, regularization, turnover penalties, scenario testing, and out-of-sample evaluation. A mathematically optimal allocation for an unreliable forecast is not necessarily a sensible investment.

## 17. Stress testing the frontier

The efficient frontier depends on assumptions about μ and Σ. It should be recalculated under alternative scenarios:

- Correlations rise during a market shock.
- Equity volatility increases.
- Expected returns fall.
- Cash yields change.
- A major asset becomes illiquid.
- Borrowing costs rise.
- Transaction costs constrain rebalancing.

Compare both frontier shape and portfolio weight sensitivity. A fragile frontier is a warning about model dependence.

## 18. Python reference implementation

Save as `efficient_portfolio_concepts.py`. This standard-library reference evaluates long-only portfolios, enumerates simplex weight grids, filters dominated portfolios, finds a grid minimum-variance portfolio, solves a minimum-variance target-return requirement over the grid, and computes Sharpe ratios. It includes **12 reference unit tests**.

```python
import math
import unittest
from fractions import Fraction
from decimal import Decimal, localcontext

def exact(x):
    if type(x) not in (int,float):
        raise ValueError("finite int/float required; booleans excluded")
    try:
        if not math.isfinite(x):
            raise ValueError("finite int/float required")
    except OverflowError as exc:
        raise ValueError("input outside finite float range") from exc
    return Fraction(x) if type(x) is int else Fraction(str(x))

def report(x):
    try:
        value=float(x)
    except (OverflowError,ValueError) as exc:
        raise ValueError("unreportable numeric result") from exc
    if not math.isfinite(value) or (x != 0 and value == 0):
        raise ValueError("unreportable numeric result")
    return value

def root(x):
    with localcontext() as ctx:
        ctx.prec=80
        return (Decimal(x.numerator)/Decimal(x.denominator)).sqrt()

def psd(a):
    # Exact Schur complements; a zero pivot must have an all-zero row.
    a=[row[:] for row in a]
    for k in range(len(a)):
        pivot=a[k][k]
        if pivot<0:
            return False
        if pivot==0:
            if any(a[k][j]!=0 for j in range(k+1,len(a))):
                return False
            continue
        for i in range(k+1,len(a)):
            for j in range(i,len(a)):
                a[i][j]-=a[i][k]*a[k][j]/pivot
                a[j][i]=a[i][j]
    return True

def _covariance(cov,tolerance=1e-10):
    relative=exact(tolerance)
    if relative<0 or relative>Fraction(1,10**6):
        raise ValueError("relative tolerance must be in [0,1e-6]")
    n=None
    if not isinstance(cov,(list,tuple)) or not cov:
        raise ValueError("nonempty square covariance required")
    if n is None:
        n=len(cov)
    if len(cov)!=n or any(not isinstance(row,(list,tuple)) or len(row)!=n for row in cov):
        raise ValueError("square aligned covariance required")
    a=[[exact(x) for x in row] for row in cov]
    if any(a[i][i]<0 for i in range(n)):
        raise ValueError("negative asset variance")
    scale=max(a[i][i] for i in range(n))
    tolerance=scale*relative
    for i in range(n):
        for j in range(i+1,n):
            if abs(a[i][j]-a[j][i])>max(abs(a[i][j]),abs(a[j][i]))*relative+tolerance:
                raise ValueError("covariance must be symmetric within stated tolerance")
            a[i][j]=a[j][i]=(a[i][j]+a[j][i])/2
    if any(a[i][i]==0 and any(a[i][j]!=0 for j in range(n)) for i in range(n)):
        raise ValueError("zero variance requires zero covariance row")
    shifted=[[a[i][j]+(tolerance if i==j else 0) for j in range(n)] for i in range(n)]
    if not psd(shifted):
        raise ValueError("covariance is not PSD within scale-relative tolerance")
    return a,tolerance

def _numbers(values,name):
    if not isinstance(values,(list,tuple)) or not values:
        raise ValueError(name+" must be a nonempty list/tuple")
    return [exact(x) for x in values]

def evaluate(weights,means,covariance):
    w=_numbers(weights,"weights");mu=_numbers(means,"means")
    c,_=_covariance(covariance)
    if len(w)!=len(mu) or len(w)!=len(c):
        raise ValueError("dimensions must agree")
    budget=sum(w)
    if min(w)<0 or abs(budget-1)>Fraction(1,10**10):
        raise ValueError("long-only unit budget required")
    w=[x/budget for x in w]
    expectation=sum(w[i]*mu[i] for i in range(len(w)))
    variance=sum(w[i]*c[i][j]*w[j] for i in range(len(w)) for j in range(len(w)))
    if variance<0:
        raise ValueError("negative exact requested variance")
    displayed=tuple(report(x) for x in w)
    if not math.isclose(math.fsum(displayed),1,rel_tol=0,abs_tol=1e-10):
        raise ValueError("reported weights lose budget reconciliation")
    return {"weights":displayed,"expected_return":report(expectation),
            "variance":report(variance),"volatility":report(root(variance))}

def simplex_grid(n,steps):
    if type(n) is not int or n<1 or type(steps) is not int or steps<1:
        raise ValueError("n and steps must be positive integers")
    def rec(remaining,count):
        if count==1:
            yield (remaining,)
        else:
            for k in range(remaining+1):
                for tail in rec(remaining-k,count-1):
                    yield (k,)+tail
    for parts in rec(steps,n):
        yield tuple(k/steps for k in parts)

def candidates(means,covariance,steps=20):
    _numbers(means,"means")
    return [evaluate(w,means,covariance) for w in simplex_grid(len(means),steps)]

def _record(p):
    if not isinstance(p,dict) or not all(key in p for key in ("expected_return","variance")):
        raise ValueError("candidate needs expected_return and variance")
    mu=exact(p["expected_return"]);variance=exact(p["variance"])
    if variance<0:
        raise ValueError("candidate variance must be nonnegative")
    return mu,variance

def _records(portfolios,allow_empty=False):
    if not isinstance(portfolios,(list,tuple)) or (not portfolios and not allow_empty):
        raise ValueError("finite candidate list/tuple required")
    for p in portfolios:
        _record(p)
    return portfolios

def _tolerance(tol):
    value=exact(tol)
    if value<0:
        raise ValueError("nonnegative finite tolerance required")
    return value

def dominates(a,b,tol=0):
    am,av=_record(a);bm,bv=_record(b);t=_tolerance(tol)
    return am>=bm-t and av<=bv+t and (am>bm+t or av<bv-t)

def efficient_subset(portfolios,tol=0):
    portfolios=_records(portfolios,allow_empty=True);_tolerance(tol)
    return [p for p in portfolios if not any(dominates(q,p,tol) for q in portfolios if q is not p)]

def min_variance_portfolio(portfolios):
    portfolios=_records(portfolios)
    return min(portfolios,key=lambda p:(_record(p)[1],-_record(p)[0]))

def min_variance_for_target(portfolios,target,tol=0):
    portfolios=_records(portfolios);target=exact(target);t=_tolerance(tol)
    feasible=[p for p in portfolios if _record(p)[0]>=target-t]
    if not feasible:
        raise ValueError("target infeasible on supplied candidates")
    return min_variance_portfolio(feasible)

def sharpe_ratio(expected_return,volatility,risk_free):
    mu,sigma,rf=(exact(x) for x in (expected_return,volatility,risk_free))
    if sigma<=0:
        raise ValueError("positive volatility required")
    return report((mu-rf)/sigma)

class EfficientTests(unittest.TestCase):
    MU=[.08,.04]
    C=[[.04,0],[0,.09]]
    def test_01_return(self):
        self.assertAlmostEqual(evaluate([.5,.5],self.MU,self.C)["expected_return"],.06)
    def test_02_variance(self):
        self.assertAlmostEqual(evaluate([.5,.5],self.MU,self.C)["variance"],.0325)
    def test_03_volatility(self):
        self.assertAlmostEqual(evaluate([.5,.5],self.MU,self.C)["volatility"],math.sqrt(.0325))
    def test_04_grid_count(self):self.assertEqual(len(list(simplex_grid(2,10))),11)
    def test_05_three_asset_count(self):self.assertEqual(len(list(simplex_grid(3,4))),15)
    def test_06_sum(self):
        self.assertTrue(all(math.isclose(sum(w),1) for w in simplex_grid(3,4)))
    def test_07_dominance(self):
        a={"expected_return":.08,"variance":.02}
        b={"expected_return":.06,"variance":.03}
        self.assertTrue(dominates(a,b))
        self.assertFalse(dominates(b,a))
    def test_08_nondominance(self):
        a={"expected_return":.08,"variance":.04}
        b={"expected_return":.06,"variance":.02}
        self.assertFalse(dominates(a,b))
    def test_09_min_variance(self):
        p=min_variance_portfolio(candidates(self.MU,self.C,13))
        self.assertAlmostEqual(p["weights"][0],9/13)
    def test_10_target(self):
        p=min_variance_for_target(candidates(self.MU,self.C,20),.07)
        self.assertGreaterEqual(p["expected_return"],.07-1e-12)
    def test_11_sharpe(self):self.assertAlmostEqual(sharpe_ratio(.08,.2,.02),.3)
    def test_12_invalid(self):
        for fn in (lambda:evaluate([.5,.4],self.MU,self.C),
                   lambda:list(simplex_grid(2,0)),
                   lambda:min_variance_for_target(candidates(self.MU,self.C,4),.2),
                   lambda:sharpe_ratio(.08,0,.02)):
            with self.assertRaises(ValueError):fn()

if __name__=="__main__":
    grid=candidates([.08,.04],[[.04,0],[0,.09]],20)
    print("Grid minimum variance:",min_variance_portfolio(grid))
    print("Grid efficient count:",len(efficient_subset(grid)))
    unittest.main(verbosity=2)
```

**Important boundaries:** This is a finite reported-candidate grid search, not continuous quadratic programming or future-performance acceptance. Integer/displayed-decimal rational calculations and 80-digit Decimal roots precede float output. Every required field must remain finite and preserve a nonzero exact value or `ValueError` is deliberate. Weight budgets accepted within `1e-10` are explicitly normalized and displayed weights checked for unit reconciliation. `evaluate` returns variance as well as SD, so an unreportable variance rejects the report even if SD alone would be representable.

The full covariance screen uses rational Schur complements on covariance plus `delta*I`, `delta=1e-10*max(diagonal)`, following Section 16.7. Accepted within-tolerance asymmetric pairs are averaged; negative diagonals/nonzero zero-variance rows reject. Requested negative exact forms reject rather than clip. Numerical screening is not exact PSD/model certification, and exact arithmetic does not cure economic conditioning or uncertain inputs.

Default dominance and target filtering now use `tol=0`: exact comparisons of the supplied finite candidate metrics under the displayed-decimal policy. This avoids erasing small tradeoffs or silently accepting a below-target return. Explicit positive `tol` selects an approximate rule: in `dominates` the same numerical tolerance applies separately in return and squared-return units; the rule can permit a slight worsening of one criterion and need not be transitive. Such output is a tolerance-filtered set, not a strict Pareto guarantee. Target `tol>0` explicitly relaxes the return requirement by that amount. Tolerances must be finite and nonnegative. Candidate records are validated for finite mean/nonnegative variance; externally supplied records are not thereby proven feasible in any portfolio universe.

## 21. Troubleshooting

| Symptom | Likely cause | Corrective action |
|---|---|---|
| No feasible portfolio reaches target | Target too high for constraints | Revise target or feasible universe |
| Grid optimum differs from analytical result | Coarse weight grid | Increase resolution or use validated optimizer |
| Efficient frontier contains dominated points | Incorrect dominance logic | Compare both mean and variance |
| Weights are extreme | Noisy expected-return estimates | Apply estimation controls and constraints |
| Negative portfolio variance | Invalid covariance matrix | Verify PSD and input ordering |
| Sharpe ratio divides by zero | Zero-volatility candidate | Handle undefined ratio explicitly |
| Results change dramatically under stress | Model sensitivity | Report scenario-dependent allocations |
| Apparent superior return ignores costs | Frictionless model | Include financing, fees, and turnover |
| High dimensional grid is slow | Combinatorial growth | Use appropriate constrained optimization |
