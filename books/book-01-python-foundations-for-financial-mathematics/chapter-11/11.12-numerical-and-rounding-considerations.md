## Learning objectives

## 1. Why numerical details matter

Loan formulas look exact on paper, but implementations operate with finite precision and currency units. A small per-period rounding difference can accumulate over hundreds of installments. An incorrect rounding or payoff policy can create residual balances, incorrect interest totals, and reconciliation failures.

A reliable financial model must state its **rate convention**, **calculation precision**, **currency rounding policy**, and **final-payment rule**.

## 2. Binary floating-point is not exact decimal currency

Most Python `float` values are binary approximations. For example, decimal fractions such as 0.1 cannot generally be represented exactly as finite binary fractions.

Do not test floating-point loan calculations using unrestricted exact equality. Instead, use an appropriate tolerance for model-level calculations and an explicit decimal currency type when exact cent reconciliation is required.

```python
import math
print(0.1 + 0.2 == 0.3)        # False in binary floating point
print(math.isclose(0.1+0.2,0.3)) # True with an appropriate tolerance
```

## 3. Cancellation in the level-payment formula

The familiar fixed-rate payment formula is:

**A = Lr/[1-(1+r)^(-n)]** for r>0.

When r is very small, the denominator subtracts two numbers close to one, which can cause **catastrophic cancellation** and loss of significant digits.

Use the equivalent stable expression:

**A = Lr/[-expm1(-n log1p(r))].**

Here `log1p(r)` accurately evaluates log(1+r) for small r, and `expm1(x)` accurately evaluates exp(x)-1 near zero.

At r=0, use the exact limit **A=L/n** rather than divide by zero.

## 4. Worked example: very small interest rate

Consider $10,000 principal, 360 monthly payments, and an extremely small positive periodic rate of 10^(-12).

The zero-interest reference payment is:

**10000/360 ≈ $27.77777778.**

The stable formula approaches this value smoothly as r approaches zero. A naive implementation can lose precision because **1-(1+r)^(-360)** is very close to zero.

The Python lab checks that the stable result remains finite and close to the zero-rate limit.

## 5. Display rounding versus calculation rounding

Two distinct operations are often confused:

- **Display rounding:** Keep full precision internally, show amounts to two decimals in reports.
- **Contractual cent rounding:** Round specific monetary amounts to cents at specified points in the actual payment and interest process.

If a report shows a payment of $443.21, the internal mathematical payment may be slightly different. Summing displayed rounded amounts can disagree by a cent with a total calculated from unrounded values.

Do not round every intermediate value merely because a user interface displays two decimals.

## 6. Decimal arithmetic and rounding mode

Python's `decimal.Decimal` represents decimal values and supports explicit rounding rules. For this chapter, the illustrative contractual policy is **ROUND_HALF_UP** to the nearest cent.

```python
from decimal import Decimal, ROUND_HALF_UP
print(Decimal("1.005").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))
# 1.01
```

This is only one possible policy. Lenders may use other rounding modes, daily interest accrual, and different payment posting rules. The precise convention must come from the applicable contract or servicing specification.

## 7. A cent-rounded amortization policy

The reference implementation uses these explicit rules:

1. Start with principal rounded to cents.
2. Compute the theoretical installment from the booked principal and exact decimal rate text. Use rational arithmetic to decide half-cent ties.
3. Round the regular installment to cents once.
4. At each period, round opening balance × periodic rate to cents.
5. Apply the regular installment, capped at the amount due.
6. In the final contractual period, adjust payment to the exact remaining balance plus accrued interest.
7. Check that final balance is zero and total principal repaid equals original cent-rounded principal.

The final installment adjustment prevents a residual cent balance from being left behind. A principal that rounds to zero is outside this policy. If the capped payment retires the loan early, subsequent rows contain zeros.

The algorithm raises an error if a regular payment would be less than the rounded interest due, because the example is limited to nonnegative-amortization schedules.

## 8. Reconciliation identities

For each row k:

**Payment(k) = Interest(k) + Principal(k).**

**Closing(k) = Opening(k) - Principal(k).**

**Opening(k+1) = Closing(k).**

For the full schedule:

**Sum Principal(k) = Original Principal.**

**Sum Payment(k) - Sum Interest(k) = Original Principal.**

**Final Closing Balance = 0.00.**

With a consistent Decimal cent policy, these are exact decimal equalities, not floating-point approximations.

## 9. Additional numerical edge cases

**Long terms:** Test hundreds of periods and ensure that payoff occurs without accumulating an unexplained balance.

**High periodic rates:** Validate finite inputs and test that the payment formula remains numerically stable for supported values.

**Tiny principal amounts:** Ensure a rounded scheduled payment does not become zero while interest is accruing. Reject unsupported negative-amortization outcomes or implement an explicit policy.

**Extra payments:** Cap extra principal at the remaining amount due; otherwise a negative loan balance may result.

**Zero-interest loans:** Handle separately to avoid a division-by-zero error.

**Irregular dates:** Equal-period formulas do not directly model actual-day interest conventions.

```python
"""Loan numerics: stable payment formulas and explicit cent rounding."""
import math
import unittest
from decimal import Decimal
from fractions import Fraction

def validate(L,r,n):
    if any(isinstance(v,bool) or not isinstance(v,(int,float)) or not math.isfinite(v) for v in (L,r)):
        raise ValueError("nonfinite loan input")
    if L<=0 or r<0 or isinstance(n,bool) or not isinstance(n,int) or n<=0:
        raise ValueError("invalid principal, rate, or term")

def _positive(value, label):
    if not math.isfinite(value) or value <= 0:
        raise ValueError(f"{label} outside supported range")
    return value

def _loss(log_rate, periods):
    try:
        return _positive(-math.expm1(-periods*log_rate), "discount loss")
    except OverflowError as exc:
        raise ValueError("discount loss outside supported range") from exc

def stable_payment(L,r,n):
    validate(L,r,n)
    if r == 0:
        amount = L/n
    elif n == 1:
        amount = L*(1+r)
    else:
        amount = L*(r/_loss(math.log1p(r),n))
    return _positive(amount,"payment")

def naive_payment(L,r,n):
    validate(L,r,n)
    return L/n if r==0 else L*r/(1-(1+r)**(-n))

def _round_cents(value):
    # Round an amount expressed in cents, breaking ties away from zero.
    sign = -1 if value < 0 else 1
    numerator, denominator = abs(value).as_integer_ratio()
    return sign*((2*numerator+denominator)//(2*denominator))

def _from_cents(cents):
    whole, remainder = divmod(abs(cents), 100)
    sign = "-" if cents < 0 else ""
    return Decimal(f"{sign}{whole}.{remainder:02d}")

def cents(x):
    return _from_cents(_round_cents(Fraction(str(x))*100))

def cents_schedule(L,r,n):
    principal,rate,periods=L,r,n
    validate(principal, rate, periods)
    balance = _round_cents(Fraction(str(principal))*100)
    if balance == 0:
        raise ValueError("booked opening must be at least one cent")
    periodic_rate = Fraction(str(rate))
    if periodic_rate == 0:
        regular = _round_cents(Fraction(balance, periods))
    else:
        discount = (1+periodic_rate)**(-periods)
        regular = _round_cents(balance*periodic_rate/(1-discount))
    rows = []
    for k in range(1, periods+1):
        opening = balance
        interest = _round_cents(opening*periodic_rate)
        due = opening+interest
        paid = due if k == periods else min(regular, due)
        if paid < interest:
            raise ValueError("payment would cause negative amortization")
        repaid = paid-interest
        balance = opening-repaid
        rows.append(dict(k=k, opening=_from_cents(opening), payment=_from_cents(paid),
                         interest=_from_cents(interest), principal=_from_cents(repaid),
                         closing=_from_cents(balance)))
    return rows

def reconcile(rows,original):
    # Explicit checks survive Python -O; use exact arithmetic regardless of
    # the caller's Decimal context precision.
    booked=Fraction(cents(original))
    if not rows or booked<=0:
        raise ValueError("schedule must contain rows for positive booked principal")
    previous=booked
    total=Fraction(0)
    for k,row in enumerate(rows,1):
        values=[row[name] for name in ("opening","interest","payment","principal","closing")]
        if any(not isinstance(v,Decimal) or not v.is_finite() for v in values):
            raise ValueError(f"nonfinite or non-Decimal amount in row {k}")
        opening,interest,paid,principal,closing=map(Fraction,values)
        if any(v<0 or (100*v).denominator!=1 for v in (opening,interest,paid,principal,closing)):
            raise ValueError(f"invalid cent amount in row {k}")
        if row["k"]!=k or opening!=previous or paid!=interest+principal or closing!=opening-principal:
            raise ValueError(f"row {k} does not reconcile")
        previous=closing
        total+=principal
    if previous!=0 or total!=booked:
        raise ValueError("schedule does not reconcile at maturity")
    return True

class Tests(unittest.TestCase):
    def test_01_zero_rate(self): self.assertEqual(stable_payment(1200,0,12),100)
    def test_02_standard(self):
        self.assertAlmostEqual(stable_payment(10000,.005,24),naive_payment(10000,.005,24))
    def test_03_small_rate(self):
        p=stable_payment(10000,1e-12,360)
        self.assertTrue(math.isfinite(p))
        self.assertAlmostEqual(p,10000/360,places=6)
    def test_04_round_half_up(self): self.assertEqual(cents("1.005"),Decimal("1.01"))
    def test_05_row_count(self): self.assertEqual(len(cents_schedule(10000,.005,24)),24)
    def test_06_reconcile(self): self.assertTrue(reconcile(cents_schedule(10000,.005,24),10000))
    def test_07_zero_rate_schedule(self):
        rows=cents_schedule(1200,0,12)
        self.assertTrue(reconcile(rows,1200))
        self.assertTrue(all(x["interest"]==0 for x in rows))
    def test_08_final_payment(self):
        rows=cents_schedule(10000,.005,24)
        self.assertEqual(rows[-1]["payment"],rows[-1]["opening"]+rows[-1]["interest"])
    def test_09_sum_interest(self):
        rows=cents_schedule(10000,.005,24)
        self.assertEqual(sum((x["payment"] for x in rows),Decimal("0"))-Decimal("10000.00"),
                         sum((x["interest"] for x in rows),Decimal("0")))
    def test_10_continuity(self):
        rows=cents_schedule(10000,.005,24)
        self.assertEqual(rows[1]["opening"],rows[0]["closing"])
    def test_11_one_period(self): self.assertTrue(reconcile(cents_schedule(1000,.01,1),1000))
    def test_12_invalid(self):
        for a in ((0,.01,12),(100,-.01,12),(100,.01,0),(100,float("nan"),12)):
            with self.assertRaises(ValueError): stable_payment(*a)
        with self.assertRaises(ValueError): cents_schedule(.004,0,2)
        with self.assertRaises(ValueError): reconcile([],100)
        self.assertEqual(cents_schedule(.15,0,6)[0]["payment"],Decimal("0.03"))

if __name__=="__main__":
    print("Stable payment:",stable_payment(10000,.005,24))
    rows=cents_schedule(10000,.005,24)
    print("Regular installment:",rows[0]["payment"],"final:",rows[-1]["payment"])
    print("Reconciled:",reconcile(rows,10000))
    unittest.main(verbosity=2)
```

## 11. Exercises with worked answers

1. **Float representation:** Why is 0.1 not always exact as a Python float? **Answer:** Binary floating-point cannot exactly represent many decimal fractions.
2. **Stable formula:** Rewrite the annuity denominator using `log1p` and `expm1`. **Answer:** -expm1(-n log1p(r)).
3. **Zero rate:** What is A for L=$1,200 and n=12 when r=0? **Answer:** $100.
4. **Display rounding:** Must displayed two-decimal values be used internally? **Answer:** No; retain calculation precision unless the contract specifies rounding.
5. **Cent rounding:** Round 1.005 to cents using ROUND_HALF_UP. **Answer:** 1.01.
6. **First interest:** What is interest on $10,000 at 0.5%? **Answer:** $50.00.
7. **Principal identity:** State the row identity. **Answer:** Payment = Interest + Principal.
8. **Balance identity:** State the closing-balance identity. **Answer:** Closing = Opening - Principal.
9. **Continuity:** What must next month's opening balance equal? **Answer:** The prior month's closing balance.
10. **Principal total:** What should the sum of principal reductions equal? **Answer:** The original principal booked to cents.
11. **Final adjustment:** Why may the last installment differ? **Answer:** Rounding can leave a small residual amount due.
12. **Exact cent validation:** Should a Decimal-based cent schedule require an approximate zero final balance? **Answer:** No; require exactly 0.00 under the specified policy.
13. **Rate convention:** Why must rate units match payment intervals? **Answer:** Using an annual rate as a monthly rate changes interest and payment calculations incorrectly.
14. **Real lender:** Does the educational rounding policy necessarily match the lender's system? **Answer:** No; contractual conventions must be verified.
