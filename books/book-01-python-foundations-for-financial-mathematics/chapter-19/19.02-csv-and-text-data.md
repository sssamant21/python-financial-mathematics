## Learning objectives

Read and write CSV and delimited text; specify encoding, delimiters and quoting; validate headers, rows and financial values; distinguish missing values from zero; preserve decimal precision and source lineage; and identify common ingestion failures.

## 1. Why CSV needs a contract

CSV is widely used for prices, positions, transactions and reports. It represents fields as text; the file itself does not establish financial units, data types, timestamps, missing-value meanings or source accuracy.

Before parsing, document the encoding, delimiter, quote rules, header, schema, date format, numeric conventions, currency, price type and missing-value policy. Define the record key, source and version, and whether records can be revised.

## 2. Synthetic price file

~~~csv
instrument,date,close,currency
EXAMPLE,2026-01-05,100.00,USD
EXAMPLE,2026-01-06,101.50,USD
~~~

The simple return is 101.50/100.00−1=**.015**, or 1.5%. This assumes comparable closes for the same instrument and currency. The dates do not establish when the data were published or available to a historical strategy.

## 3. Delimiters, quoting and line endings

CSV commonly uses a comma; TSV uses a tab. A quoted field may contain a delimiter, quote or newline. For example:

~~~csv
instrument,description,close
EXAMPLE,"Example, Class A",100.00
~~~

Splitting a line on commas incorrectly breaks the quoted description. Use a CSV parser configured for the source dialect. Python's `csv` module supports delimiters and quoting; open text files with `newline=""` as documented for correct newline handling.

A line in the file is not necessarily one logical record because quoted fields can contain newlines.

## 4. Encoding and BOM

Specify the expected encoding rather than relying on a machine default. UTF-8 is common, but a supplier may use another encoding. A UTF-8 byte order mark (BOM) can appear at the start of a header; Python's `utf-8-sig` decoder removes it when present.

Do not silently replace undecodable bytes without a policy: replacement can alter instrument names or identifiers. Preserve original bytes where permitted and record any decoding error.

~~~python
import csv

with open("prices.csv", "r", encoding="utf-8-sig", newline="") as file:
    rows = list(csv.DictReader(file))
~~~

This snippet only reads records; it does not validate their schema or financial meaning.

## 5. Headers and schema

Validate required columns, duplicate headers, unexpected columns and row width. Decide whether column names are case-sensitive and whether extra columns are allowed. A duplicate header can silently overwrite a field when interpreted as a dictionary; reject it before mapping records.

A row key might be (instrument, observation date, price type, venue), but the correct key depends on the dataset. Multiple venues, corrections or versions may legitimately produce more than one record per date.

## 6. Numeric types and precision

CSV fields arrive as strings. For decimal financial values, `Decimal("101.50")` preserves the supplied decimal value. Constructing `Decimal` from a binary float can preserve an unintended binary approximation instead.

Define decimal separators, thousands separators, sign conventions, scale and rounding. Reject nonfinite values such as NaN and infinity where they are not allowed. A negative yield can be valid even though a particular price field must be positive.

## 7. Missing and malformed values

An empty field, a missing column, a source marker such as `NA`, and a true numeric zero are different. Define which markers are missing and whether to reject, quarantine or retain them. Do not silently convert missing prices to zero.

Decide what happens to malformed rows: fail the batch, quarantine records with reasons, or apply an explicitly approved correction. Retain line or record context and source identity. A CSV parser may report the physical line reached, which can differ from the number of logical records when fields contain newlines.

## 8. Dates, times and availability

An ISO date such as 2026-01-06 identifies a calendar date, not an instant. For timestamped data, specify timezone and daylight-saving handling. Distinguish event, effective, publication and ingestion times.

A file named for a trading day may have been published later or subsequently corrected. Historical backtests require point-in-time information; the date column alone does not prevent look-ahead bias.

## 9. Writing CSV

Use `csv.writer` or `csv.DictWriter` to quote fields correctly. Specify encoding and newline behavior. Document output column order, format and version. If the file will be opened in spreadsheet software, consider how that software interprets formulas and leading characters in untrusted text according to your organization's export policy.

~~~python
import csv

with open("output.csv", "w", encoding="utf-8", newline="") as file:
    writer = csv.DictWriter(file, fieldnames=["instrument","close"])
    writer.writeheader()
    writer.writerow({"instrument":"EXAMPLE","close":"101.50"})
~~~

Writing a syntactically valid file does not establish that its contents are financially correct.

## 10. Large files and performance

Process rows incrementally when possible instead of loading an entire file into memory. Validate while streaming and record counts for accepted and rejected records. Exact global duplicate detection or sorting may require additional memory, disk or a database; do not claim a streaming design checks every global constraint unless it actually does.

Measure throughput and peak memory using representative inputs. Preserve original data and transformation metadata where permitted.

## 11. Lineage and checksums

A raw-byte checksum can help identify the exact input used. Hash the original bytes before decoding when byte-for-byte identity matters. Record the algorithm, source, retrieval time, schema, code version and output identity.

A checksum proves neither correctness nor authenticity on its own. Different newline encodings or BOMs change raw-byte hashes even when decoded content looks similar.

## 12. Reference implementation

Save as `csv_financial_data.py`. This example validates a synthetic UTF-8 CSV with a narrow schema. It rejects extra and duplicate headers, malformed rows, duplicate keys and nonpositive prices. The duplicate-key set consumes memory proportional to distinct keys.

~~~python
import csv
import hashlib
import io
from datetime import date
from decimal import Decimal, InvalidOperation
import unittest

FIELDS = ("instrument","date","close","currency")

def parse_csv(raw):
    if not isinstance(raw, bytes):
        raise ValueError("raw bytes required")
    try:
        text = raw.decode("utf-8-sig")
    except UnicodeDecodeError as exc:
        raise ValueError("invalid UTF-8") from exc
    reader = csv.DictReader(io.StringIO(text, newline=""), strict=True)
    if reader.fieldnames is None:
        raise ValueError("missing header")
    if len(reader.fieldnames) != len(set(reader.fieldnames)):
        raise ValueError("duplicate header")
    if set(reader.fieldnames) != set(FIELDS):
        raise ValueError("unexpected or missing columns")
    rows, seen = [], set()
    try:
        for row in reader:
            if None in row or any(row.get(k) is None for k in FIELDS):
                raise ValueError("wrong number of fields")
            instrument = row["instrument"].strip()
            currency = row["currency"].strip()
            if not instrument or currency != "USD":
                raise ValueError("instrument and USD currency required")
            try:
                day = date.fromisoformat(row["date"].strip())
                close = Decimal(row["close"].strip())
            except (ValueError, InvalidOperation) as exc:
                raise ValueError("invalid date or close") from exc
            if not close.is_finite() or close <= 0:
                raise ValueError("close must be positive and finite")
            key = (instrument,day)
            if key in seen:
                raise ValueError("duplicate instrument/date")
            seen.add(key)
            rows.append({"instrument":instrument,"date":day,
                         "close":close,"currency":currency})
    except csv.Error as exc:
        raise ValueError("invalid CSV syntax") from exc
    if not rows:
        raise ValueError("no data rows")
    return rows

def raw_sha256(raw):
    if not isinstance(raw,bytes):
        raise ValueError("raw bytes required")
    return hashlib.sha256(raw).hexdigest()

def simple_return(start,end):
    if not isinstance(start,Decimal) or not isinstance(end,Decimal):
        raise ValueError("Decimal prices required")
    if not start.is_finite() or not end.is_finite() or start <= 0 or end < 0:
        raise ValueError("positive start and nonnegative end required")
    return end/start-Decimal("1")

class CsvTests(unittest.TestCase):
    def setUp(self):
        self.raw=(b"instrument,date,close,currency\n"
                  b"EXAMPLE,2026-01-05,100.00,USD\n"
                  b"EXAMPLE,2026-01-06,101.50,USD\n")
    def test_parse(self):
        self.assertEqual(len(parse_csv(self.raw)),2)
    def test_return(self):
        rows=parse_csv(self.raw)
        self.assertEqual(simple_return(rows[0]["close"],rows[1]["close"]),Decimal(".015"))
    def test_bom(self):
        self.assertEqual(len(parse_csv(b"\xef\xbb\xbf"+self.raw)),2)
    def test_raw_hash(self):
        self.assertNotEqual(raw_sha256(self.raw),raw_sha256(b"\xef\xbb\xbf"+self.raw))
    def test_duplicate_header(self):
        with self.assertRaises(ValueError):
            parse_csv(b"instrument,date,close,close\nA,2026-01-01,1,2\n")
    def test_duplicate_key(self):
        with self.assertRaises(ValueError):
            parse_csv(self.raw.replace(b"2026-01-06",b"2026-01-05"))
    def test_missing_value(self):
        with self.assertRaises(ValueError):
            parse_csv(self.raw.replace(b"101.50",b""))
    def test_nonfinite_price(self):
        with self.assertRaises(ValueError):
            parse_csv(self.raw.replace(b"101.50",b"NaN"))
    def test_extra_field(self):
        with self.assertRaises(ValueError):
            parse_csv(self.raw.replace(b"101.50,USD",b"101.50,USD,extra"))
    def test_bad_encoding(self):
        with self.assertRaises(ValueError): parse_csv(b"\xff")

if __name__ == "__main__":
    example=(b"instrument,date,close,currency\n"
             b"EXAMPLE,2026-01-05,100.00,USD\n"
             b"EXAMPLE,2026-01-06,101.50,USD\n")
    rows=parse_csv(example)
    print("simple return:",simple_return(rows[0]["close"],rows[1]["close"]))
    print("raw sha256:",raw_sha256(example))
    unittest.main(verbosity=2)
~~~

This code reads all input bytes and stores parsed rows, so it is not a large-file streaming implementation. It assumes USD, one price per instrument/date, ISO dates and positive closes. It does not validate venue, price adjustment, publication time, file authenticity or spreadsheet safety.

## 15. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Header contains an unexpected first character | UTF-8 BOM | Verify encoding and use an appropriate decoder |
| Columns shift | Incorrect delimiter or quoting | Inspect dialect and parse with a CSV library |
| Price is missing or NaN | Empty field or invalid marker | Apply documented missing-data policy |
| Duplicate instrument/date | Correction, venue or retry | Review key and source version |
| Hash differs although text looks similar | BOM, encoding or newline changes | Compare raw bytes |
| Historical analysis sees future data | Publication time omitted | Check availability and revision history |
