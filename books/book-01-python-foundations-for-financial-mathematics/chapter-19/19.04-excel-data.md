## Learning objectives

Inspect financial workbooks, select sheets and ranges, distinguish formulas from cached values, parse dates and numeric cells, validate a documented schema, preserve source lineage, and identify spreadsheet-specific risks.

## 1. Excel as a financial data source

Workbooks are common for positions, prices, valuations and reconciliations. They can contain multiple sheets, formulas, formatting, hidden rows, merged cells and human-entered adjustments. A workbook is both a data container and potentially a calculation model.

Before ingestion, define the workbook version, worksheet, range, headers, data types, units, dates, formula policy, source and availability time. A visually formatted cell does not guarantee the stored value or meaning.

## 2. Workbook structure

A workbook contains worksheets; sheets contain cells addressed by row and column. Data may also appear in tables, named ranges or hidden sheets. A sheet's visible label or cell position can change between versions.

Document whether hidden rows and columns are included. Merged cells can leave values only in the top-left cell; do not assume every displayed cell contains a separate value. Avoid silently forward-filling blanks without an approved rule.

## 3. Synthetic example

The worksheet `Prices` contains:

| instrument | date | close | currency |
|---|---|---:|---|
| EXAMPLE | 2026-01-05 | 100.00 | USD |
| EXAMPLE | 2026-01-06 | 101.50 | USD |

For comparable closes, simple return is 101.50/100−1=**.015**, or 1.5%. This date is an observation date, not necessarily publication time or a timezone-aware event timestamp.

## 4. Formats and libraries

The modern `.xlsx` format is a workbook format; other extensions and legacy formats may require different tools or handling. Python libraries such as `openpyxl` can read and write `.xlsx` workbooks. Pandas can read spreadsheets through an appropriate engine, but type inference and missing-value behavior must be reviewed.

The following examples use `openpyxl`. Install it in an isolated environment and record the version during execution:

~~~bash
python -m pip install openpyxl
~~~

Only process files you are authorized to use. Treat untrusted workbooks and macros according to organizational policy.

## 5. Formulas and cached values

A formula cell contains an expression such as `=C2*2`. Spreadsheet applications may also store a cached result. `openpyxl` does **not** calculate formulas. With `data_only=False`, it reads formulas; with `data_only=True`, it reads cached values where available. A cache may be missing or stale.

Choose and document a formula policy. The reference implementation below rejects formulas in the imported data range. If cached results are used in another workflow, identify the calculation engine, recalculation time and validation process; cached output is not automatically current.

## 6. Numeric cells and precision

Excel numeric cells are commonly stored as floating-point values even when formatting displays two decimals. Formatting does not necessarily round the stored value. Converting a Python float with `Decimal(str(value))` captures its displayed Python decimal representation, not the original user's exact entry or an authoritative accounting value.

For exact decimal text, a contract can require string cells or a source that preserves decimal values explicitly. Define scale and rounding policy and reconcile with the system of record. Do not silently round intermediate calculations.

## 7. Dates and times

Spreadsheet dates may be stored as numeric serials with date formatting. Workbooks can use different date systems; libraries interpret them using workbook metadata, and legacy date-system quirks deserve attention. Some cells may be text instead of dates.

A date alone has no timezone or publication time. A datetime with a non-midnight time should not be silently treated as a date unless the contract permits it. For point-in-time analysis, retain information availability and revision history separately.

## 8. Data quality and schema

Check the sheet exists, headers are unique and expected, required cells are populated, data types are valid and record keys are unique. Define how blank rows, hidden content, merged cells, currency and price type are handled. A negative yield may be valid even when a specific close-price field must be positive.

A ticker can change or be reused. A duplicate instrument/date may be legitimate if venue, price type or version differs; choose the key for the actual dataset.

## 9. Safe ingestion and lineage

Read source workbooks without overwriting them. Record the original byte hash, source, retrieval time, workbook version, sheet, range, formula policy, code and library versions. A hash identifies bytes; it does not prove source correctness or authenticity.

Consider file size and resource limits for untrusted input. Do not execute workbook macros as part of ingestion. When exporting untrusted text for spreadsheet use, apply a documented formula-injection handling policy appropriate to the consuming application.

## 10. Reading with openpyxl

~~~python
from openpyxl import load_workbook

workbook = load_workbook("prices.xlsx", read_only=True, data_only=False)
try:
    sheet = workbook["Prices"]
    for row in sheet.iter_rows(values_only=True):
        print(row)
finally:
    workbook.close()
~~~

This only inspects rows. It does not validate formulas, hidden content, dates, identifiers or financial meaning. `read_only=True` can reduce memory use, but actual memory and processing behavior depend on workbook structure.

## 11. Reference implementation

Save as `excel_financial_data.py`. It reads a synthetic `Prices` sheet with exact headers. It rejects formulas in imported cells, blank or malformed records and duplicate instrument/date keys. It accepts ISO date strings or date/datetime cells at midnight and positive numeric or decimal-string prices.

~~~python
import hashlib
import math
from datetime import date, datetime, time
from decimal import Decimal, InvalidOperation
from io import BytesIO
import unittest
from openpyxl import Workbook, load_workbook

FIELDS=("instrument","date","close","currency")

def raw_sha256(raw):
    if not isinstance(raw,bytes):
        raise ValueError("raw bytes required")
    return hashlib.sha256(raw).hexdigest()

def parse_day(value):
    if isinstance(value,datetime):
        if value.tzinfo is not None or value.time() != time(0,0):
            raise ValueError("naive midnight datetime required")
        return value.date()
    if isinstance(value,date):
        return value
    if isinstance(value,str):
        try:
            return date.fromisoformat(value)
        except ValueError as exc:
            raise ValueError("invalid ISO date") from exc
    raise ValueError("date cell or ISO date string required")

def parse_price(value):
    if isinstance(value,bool) or not isinstance(value,(int,float,str,Decimal)):
        raise ValueError("numeric or decimal-string price required")
    if isinstance(value,float) and not math.isfinite(value):
        raise ValueError("finite price required")
    try:
        price=Decimal(str(value))
    except InvalidOperation as exc:
        raise ValueError("invalid decimal price") from exc
    if not price.is_finite() or price <= 0:
        raise ValueError("positive finite price required")
    return price

def parse_workbook(raw):
    if not isinstance(raw,bytes):
        raise ValueError("workbook bytes required")
    workbook=load_workbook(BytesIO(raw),read_only=True,data_only=False)
    try:
        if "Prices" not in workbook.sheetnames:
            raise ValueError("Prices sheet required")
        sheet=workbook["Prices"]
        rows=sheet.iter_rows()
        header=next(rows,None)
        if header is None or any(cell.data_type=="f" for cell in header):
            raise ValueError("valid header required")
        names=tuple(cell.value for cell in header)
        if names != FIELDS:
            raise ValueError("exact ordered headers required")
        records,seen=[],set()
        for row in rows:
            if all(cell.value is None for cell in row):
                continue
            if len(row)!=len(FIELDS) or any(cell.data_type=="f" for cell in row):
                raise ValueError("wrong width or formula in data")
            instrument,day,close,currency=(cell.value for cell in row)
            if not isinstance(instrument,str) or not instrument.strip() or currency!="USD":
                raise ValueError("instrument and USD currency required")
            day=parse_day(day)
            price=parse_price(close)
            key=(instrument.strip(),day)
            if key in seen:
                raise ValueError("duplicate instrument/date")
            seen.add(key)
            records.append({"instrument":key[0],"date":day,
                            "close":price,"currency":currency})
        if len(records)<2:
            raise ValueError("at least two records required")
        return records
    finally:
        workbook.close()

def simple_return(start,end):
    if not isinstance(start,Decimal) or not isinstance(end,Decimal):
        raise ValueError("Decimal prices required")
    if not start.is_finite() or not end.is_finite() or start<=0 or end<0:
        raise ValueError("positive start and nonnegative end required")
    return end/start-Decimal("1")

def example_workbook():
    workbook=Workbook()
    sheet=workbook.active
    sheet.title="Prices"
    sheet.append(list(FIELDS))
    sheet.append(["EXAMPLE","2026-01-05","100.00","USD"])
    sheet.append(["EXAMPLE","2026-01-06","101.50","USD"])
    buffer=BytesIO()
    workbook.save(buffer)
    workbook.close()
    return buffer.getvalue()

class ExcelTests(unittest.TestCase):
    def test_parse(self):
        self.assertEqual(len(parse_workbook(example_workbook())),2)
    def test_return(self):
        rows=parse_workbook(example_workbook())
        self.assertEqual(simple_return(rows[0]["close"],rows[1]["close"]),Decimal(".015"))
    def test_price_text(self):
        self.assertEqual(parse_price("101.50"),Decimal("101.50"))
    def test_bad_price(self):
        with self.assertRaises(ValueError): parse_price("NaN")
    def test_boolean_price(self):
        with self.assertRaises(ValueError): parse_price(True)
    def test_bad_date(self):
        with self.assertRaises(ValueError): parse_day("bad")
    def test_nonmidnight(self):
        with self.assertRaises(ValueError): parse_day(datetime(2026,1,1,12))
    def test_hash(self):
        raw=example_workbook()
        self.assertEqual(raw_sha256(raw),raw_sha256(raw))
    def test_formula_rejected(self):
        wb=Workbook()
        ws=wb.active
        ws.title="Prices"
        ws.append(list(FIELDS))
        ws.append(["EXAMPLE","2026-01-05","100","USD"])
        ws.append(["EXAMPLE","2026-01-06","=100+1.5","USD"])
        buf=BytesIO()
        wb.save(buf)
        wb.close()
        with self.assertRaises(ValueError): parse_workbook(buf.getvalue())
    def test_zero_start(self):
        with self.assertRaises(ValueError): simple_return(Decimal("0"),Decimal("1"))

if __name__ == "__main__":
    raw=example_workbook()
    records=parse_workbook(raw)
    print("return:",simple_return(records[0]["close"],records[1]["close"]))
    print("raw workbook sha256:",raw_sha256(raw))
    unittest.main(verbosity=2)
~~~

The implementation reads the workbook bytes into memory and stores all accepted rows and keys; it is not a bounded-memory ingestion pipeline. It skips entirely blank rows, includes rows regardless of visibility, requires the worksheet's used width to match four headers, and assumes USD and one price per instrument/date. Its synthetic workbook has no formulas. It does not validate publication times, corporate actions, workbook trust, external links, source authenticity or an exchange calendar.

For arbitrary workbooks, library-level parsing errors can also be raised. Apply appropriate resource limits and error handling at the ingestion boundary.

## 14. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Formula value is missing | No cached result | Inspect formula and approved recalculation workflow |
| Unexpected precision | Numeric storage differs from display formatting | Compare source system and rounding policy |
| Date shifts or parses incorrectly | Workbook date system or text ambiguity | Inspect metadata and cell type |
| Duplicate records | Key omits venue or revision | Review source contract and identity |
| More rows than expected | Hidden rows included | Define visibility policy explicitly |
| Memory grows on large files | Raw bytes and records retained | Design a bounded-memory ingestion pipeline |
