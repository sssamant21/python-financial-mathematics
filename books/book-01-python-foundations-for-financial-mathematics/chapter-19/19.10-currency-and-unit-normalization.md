## Learning objectives

Identify currencies, quote directions and financial units; convert decimal rates, percentages and basis points; normalize currency amounts with an explicitly defined FX quote; apply documented decimal and rounding rules; and preserve timestamps and provenance.

## 1. Why normalization matters

Financial records can express the same quantity in dollars or cents, decimal rates or percentages, and prices per share or per contract. Comparing or aggregating values without units can produce errors of 100 times or more.

Normalization converts representations under explicit rules. It does not establish that an FX rate is current, that a transaction was executable at that rate, or that a source value is correct.

## 2. Currency and denomination

Record currency, unit and amount together. In this section's illustrative USD convention, 100 cents equal 1 dollar, so **10,000 cents = 100 dollars**. Currency minor units and cash-rounding practices vary; do not assume every currency uses two decimal places.

A currency code identifies a currency, but the contract should also specify whether a value is an amount, a price per unit, a notional or another quantity.

## 3. Decimal rates, percentages and basis points

- 5% = **.05** in decimal units.
- 100 basis points = **1 percentage point = .01** in decimal units.
- 1 basis point = **.0001** in decimal units.

A move from 5% to 6% is +1 percentage point or +100 bp; it is a 20% relative increase in the rate. These statements are different. Compounding, day count and horizon must also be stated where relevant.

## 4. FX quote direction

Suppose an FX quote is **1.10 USD per EUR**. EUR 100 converts to **USD 110** by multiplication. The reciprocal is approximately **.9090909 EUR per USD**; converting USD 110 at that reciprocal gives approximately EUR 100.

Do not invert a quote based on a label alone. Record base currency, quote currency, units, bid/ask or midpoint, source, observation time and availability time. The applicable executable rate may differ from an indicative mid-rate.

## 5. FX example and P&L

An asset remains worth EUR 100. If USD per EUR falls from 1.10 to 1.05, its USD value changes from 110 to 105, producing **−5 USD** currency P&L, before fees and other effects.

This example holds the EUR asset value constant. A real valuation must account for asset-price movement, position changes, transaction costs and the appropriate rate and timing.

## 6. Time alignment and point-in-time data

An FX rate and a price must be appropriate to the same valuation purpose and time. Distinguish market event time, publication or availability time and retrieval time. A daily close, intraday quote and settlement rate are not automatically interchangeable.

Stale rates, mismatched timezones or later corrections can distort comparisons and introduce look-ahead bias. Preserve raw values and source versions where permitted.

## 7. Decimal precision and rounding

Parse decimal text using `Decimal` when a decimal arithmetic contract requires it. Define precision, rounding mode and when rounding occurs. Repeated intermediate rounding can change results. A reciprocal can be non-terminating; calculate with a documented context and round only at a specified boundary.

This section's code uses an explicit local decimal context for conversions and rounds USD amounts to cents with half-even rounding only when requested. It is an illustration, not a universal settlement rule. Minor units, cash rounding and legal requirements differ.

## 8. Validation and missing values

Validate currency and unit labels, finite decimal inputs, positive FX rates, quote direction and required timestamps. Do not silently assume missing currency, replace a missing rate with zero, or invert an unknown quote. Negative amounts can represent liabilities or short positions; negative FX rates are not valid under this example's contract.

Check source conventions and reconcile converted totals to an independent benchmark. A syntactically valid currency code does not establish that the amount or rate is correct.

## 9. Contract and provenance

Record original value, original currency and unit, normalized value, rate, quote direction, rate type, observation and availability times, source, code version, decimal context and rounding policy. Preserve raw input where permitted.

A checksum identifies the bytes hashed; it does not prove that a rate is accurate, current or authorized for use.

## 10. Reference implementation

Save as `currency_unit_normalization.py`. It operates on decimal strings, uses a fixed local precision, and requires a quote explicitly stated as target units per one source unit. It does not fetch live FX data or validate timestamps.

~~~python
from decimal import Decimal, InvalidOperation, ROUND_HALF_EVEN, localcontext
import unittest

def decimal_text(value):
    if not isinstance(value,str) or not value.strip():
        raise ValueError("nonempty decimal text required")
    try:
        number=Decimal(value)
    except InvalidOperation as exc:
        raise ValueError("invalid decimal text") from exc
    if not number.is_finite():
        raise ValueError("finite decimal required")
    return number

def percent_to_decimal(value):
    with localcontext() as ctx:
        ctx.prec=28
        return decimal_text(value)/Decimal("100")

def basis_points_to_decimal(value):
    with localcontext() as ctx:
        ctx.prec=28
        return decimal_text(value)/Decimal("10000")

def cents_to_dollars(value):
    with localcontext() as ctx:
        ctx.prec=28
        return decimal_text(value)/Decimal("100")

def convert_target_per_source(amount,rate):
    # rate = target-currency units per one source-currency unit.
    amount_value=decimal_text(amount)
    rate_value=decimal_text(rate)
    if rate_value<=0:
        raise ValueError("positive FX rate required")
    with localcontext() as ctx:
        ctx.prec=28
        return amount_value*rate_value

def reciprocal(rate):
    value=decimal_text(rate)
    if value<=0:
        raise ValueError("positive FX rate required")
    with localcontext() as ctx:
        ctx.prec=28
        return Decimal("1")/value

def round_usd_cents(amount):
    value=decimal_text(amount)
    with localcontext() as ctx:
        ctx.prec=28
        return value.quantize(Decimal(".01"),rounding=ROUND_HALF_EVEN)

class UnitTests(unittest.TestCase):
    def test_percent(self):
        self.assertEqual(percent_to_decimal("5"),Decimal(".05"))
    def test_basis_points(self):
        self.assertEqual(basis_points_to_decimal("100"),Decimal(".01"))
    def test_one_basis_point(self):
        self.assertEqual(basis_points_to_decimal("1"),Decimal(".0001"))
    def test_cents(self):
        self.assertEqual(cents_to_dollars("10000"),Decimal("100"))
    def test_fx(self):
        self.assertEqual(convert_target_per_source("100","1.10"),Decimal("110.00"))
    def test_reciprocal(self):
        self.assertAlmostEqual(reciprocal("1.10"),Decimal("0.9090909090909090909090909091"))
    def test_fx_pnl(self):
        self.assertEqual(convert_target_per_source("100","1.05")-
                         convert_target_per_source("100","1.10"),Decimal("-5.00"))
    def test_negative_amount(self):
        self.assertEqual(convert_target_per_source("-100","1.10"),Decimal("-110.00"))
    def test_round_half_even(self):
        self.assertEqual(round_usd_cents("1.005"),Decimal("1.00"))
    def test_invalid_rate(self):
        with self.assertRaises(ValueError): convert_target_per_source("100","0")
    def test_nonfinite(self):
        with self.assertRaises(ValueError): decimal_text("NaN")
    def test_missing(self):
        with self.assertRaises(ValueError): decimal_text(None)

if __name__ == "__main__":
    print("5 percent:",percent_to_decimal("5"))
    print("100 EUR in USD:",convert_target_per_source("100","1.10"))
    print("USD per EUR reciprocal:",reciprocal("1.10"))
    unittest.main(verbosity=2)
~~~

The code's quote convention is supplied by the caller; it does not verify currency labels, date, rate source, bid/ask, fees or market availability. Decimal context may round results that exceed its precision; extreme inputs can raise decimal arithmetic exceptions. Do not treat this example as a settlement or accounting system.

## 13. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Value is 100 times too large | Percent, cents or decimal units confused | Verify unit labels and conversion |
| FX conversion is inverted | Quote direction misunderstood | State target units per source unit |
| Round-trip differs slightly | Reciprocal and rounding precision | Inspect decimal context and rounding boundary |
| P&L differs from source | Different rate time, bid/ask or fees | Align valuation conventions |
| Corrected rate changes history | Availability or revision omitted | Review point-in-time lineage |
| Currency is missing | Incomplete source contract | Reject or quarantine according to policy |
