## Learning objectives

Read financial JSON safely; distinguish objects, arrays and scalar types; validate a documented schema; preserve decimal text; handle duplicate keys, missing values and nonstandard numeric constants; and record source identity and time semantics.

## 1. JSON in financial workflows

JSON commonly carries API responses, configuration, event messages and nested instrument records. It provides syntax for objects, arrays, strings, numbers, booleans and null; it does not define a financial schema, currency, units, publication time or data quality.

A syntactically valid response can still be incomplete, stale or economically incorrect. Define a contract before parsing: required fields, types, allowed values, timestamps, numeric representation, versioning and error handling.

## 2. Synthetic example

~~~json
{
  "instrument": "EXAMPLE",
  "observation_date": "2026-01-06",
  "close": "101.50",
  "currency": "USD",
  "price_type": "unadjusted_close"
}
~~~

The value `"101.50"` is a string containing decimal text. The date is an observation date, not automatically a publication timestamp. The example is synthetic and has no live market connection.

## 3. Objects and arrays

An object maps keys to values; an array holds an ordered list. A response might contain metadata and an array of observations:

~~~json
{
  "source": "synthetic",
  "observations": [
    {"date": "2026-01-05", "close": "100.00"},
    {"date": "2026-01-06", "close": "101.50"}
  ]
}
~~~

Do not assume array order implies event-time order unless the source contract says so. Pagination, corrections and duplicate records require explicit handling.

## 4. Missing, null and zero

These cases differ:

- Missing key: the field is absent.
- `null`: the key exists with no value.
- `0`: a numeric zero.
- `""`: an empty string.

A required positive price should not silently treat any of these as another. Decide whether to reject, quarantine or retain missing data and record the reason.

## 5. Numbers and decimal precision

A JSON number has a textual representation, but Python's default JSON decoder converts fractional numbers to binary floating-point. For financial quantities where decimal arithmetic is required, one option is to require a decimal string and parse with `Decimal`; another is to configure a parser's numeric hooks with a documented schema.

`Decimal` is not a complete financial policy: set appropriate precision, rounding, scale, units and currency. Avoid treating booleans as prices merely because Python's `bool` is a subclass of `int`.

For prices 100.00 and 101.50, the simple return is **.015**, or 1.5%, assuming comparable values and a positive starting price.

## 6. Nonstandard numbers and duplicate keys

JSON standards do not define NaN or Infinity as numeric literals. Python's default decoder can accept these extensions unless configured otherwise. Reject nonstandard constants when the contract requires strict JSON.

Duplicate object names are ambiguous for downstream systems: some parsers keep one value. A financial ingestion contract should define a policy; this section rejects duplicates at any object level.

## 7. Dates, timestamps and availability

An ISO date identifies a calendar date; it does not by itself provide event time, timezone or publication time. Record when information became available, not only the period it describes. Corrections and revisions can change historical data; a current response does not automatically reconstruct what was known at an earlier decision time.

## 8. Parsing and validation

Separate syntax parsing from schema and financial validation. Check top-level type, required and extra fields, key types, allowed currencies, date format and numeric domains. Reject malformed or unsupported records with actionable errors; do not silently replace missing values with zero.

Schemas can evolve. Record schema version, source and transformation version, and define how unknown fields and older records are handled.

## 9. API responses

An API can return an error object, an empty array, partial pages or revised records instead of the expected observations. Check status and response contract, pagination and source-specific limits. Record retrieval time and relevant response metadata without exposing credentials.

A successful HTTP response alone does not prove that the dataset is complete or that a quote is current.

## 10. Lineage and raw bytes

Retain permitted raw responses separately from transformed data. Hash the original bytes if byte identity matters, and record source, retrieval time, schema and code version. A digest detects changes in hashed bytes; it does not prove authenticity, correctness or authorization.

Whitespace and key order can change raw-byte hashes without changing a JSON object's interpreted values. A canonicalization policy must be explicit if semantic equivalence is needed.

## 11. Resource limits and security

Untrusted JSON can be large or deeply nested. Set limits appropriate to the environment, handle decoding and parser errors, and avoid logging secrets or sensitive payloads. Do not evaluate JSON as Python code. Use a JSON parser, not `eval`.

## 12. Reference implementation

Save as `financial_json_data.py`. This standard-library example accepts a small UTF-8 JSON object with a strict schema and a decimal-string close. It rejects duplicate keys and nonstandard constants. It does not perform live API calls.

~~~python
import hashlib
import json
from datetime import date
from decimal import Decimal, InvalidOperation
import unittest

FIELDS = {"instrument","observation_date","close","currency","price_type"}

def reject_duplicates(pairs):
    result = {}
    for key,value in pairs:
        if key in result:
            raise ValueError("duplicate JSON key")
        result[key] = value
    return result

def reject_constant(value):
    raise ValueError("nonstandard numeric constant: " + value)

def parse_record(raw):
    if not isinstance(raw,bytes):
        raise ValueError("raw bytes required")
    try:
        text=raw.decode("utf-8")
        obj=json.loads(text,object_pairs_hook=reject_duplicates,
                       parse_constant=reject_constant)
    except (UnicodeDecodeError,json.JSONDecodeError) as exc:
        raise ValueError("invalid UTF-8 or JSON") from exc
    if not isinstance(obj,dict) or set(obj) != FIELDS:
        raise ValueError("expected object with exact fields")
    if any(not isinstance(obj[k],str) for k in FIELDS):
        raise ValueError("all fields must be strings")
    instrument=obj["instrument"].strip()
    if not instrument or obj["currency"] != "USD":
        raise ValueError("instrument and USD currency required")
    if obj["price_type"] != "unadjusted_close":
        raise ValueError("unsupported price type")
    try:
        day=date.fromisoformat(obj["observation_date"])
        price=Decimal(obj["close"])
    except (ValueError,InvalidOperation) as exc:
        raise ValueError("invalid date or price") from exc
    if not price.is_finite() or price <= 0:
        raise ValueError("positive finite close required")
    return {"instrument":instrument,"observation_date":day,
            "close":price,"currency":obj["currency"],
            "price_type":obj["price_type"]}

def simple_return(start,end):
    if not isinstance(start,Decimal) or not isinstance(end,Decimal):
        raise ValueError("Decimal prices required")
    if not start.is_finite() or not end.is_finite() or start <= 0 or end < 0:
        raise ValueError("positive start and nonnegative end required")
    return end/start-Decimal("1")

def raw_sha256(raw):
    if not isinstance(raw,bytes):
        raise ValueError("raw bytes required")
    return hashlib.sha256(raw).hexdigest()

class JsonTests(unittest.TestCase):
    def setUp(self):
        self.raw=(b'{"instrument":"EXAMPLE","observation_date":"2026-01-06",'
                  b'"close":"101.50","currency":"USD","price_type":"unadjusted_close"}')
    def test_parse(self):
        self.assertEqual(parse_record(self.raw)["close"],Decimal("101.50"))
    def test_return(self):
        self.assertEqual(simple_return(Decimal("100"),Decimal("101.50")),Decimal(".015"))
    def test_hash(self):
        self.assertEqual(raw_sha256(self.raw),raw_sha256(self.raw))
    def test_duplicate(self):
        with self.assertRaises(ValueError):
            parse_record(self.raw.replace(b'"close":"101.50"',b'"close":"101.50","close":"99"'))
    def test_missing(self):
        with self.assertRaises(ValueError):
            parse_record(b'{"instrument":"EXAMPLE"}')
    def test_null(self):
        with self.assertRaises(ValueError):
            parse_record(self.raw.replace(b'"101.50"',b'null'))
    def test_numeric_not_string(self):
        with self.assertRaises(ValueError):
            parse_record(self.raw.replace(b'"101.50"',b'101.50'))
    def test_nan(self):
        with self.assertRaises(ValueError):
            parse_record(self.raw.replace(b'"101.50"',b'NaN'))
    def test_bad_date(self):
        with self.assertRaises(ValueError):
            parse_record(self.raw.replace(b'2026-01-06',b'not-a-date'))
    def test_invalid_encoding(self):
        with self.assertRaises(ValueError): parse_record(b'\xff')

if __name__ == "__main__":
    example=(b'{"instrument":"EXAMPLE","observation_date":"2026-01-06",'
             b'"close":"101.50","currency":"USD","price_type":"unadjusted_close"}')
    record=parse_record(example)
    print("record:",record)
    print("return:",simple_return(Decimal("100"),record["close"]))
    print("raw sha256:",raw_sha256(example))
    unittest.main(verbosity=2)
~~~

The parser intentionally requires USD, exact fields and decimal-string prices; a real contract may differ. It does not enforce input-size limits, exchange calendars, corporate actions, source authenticity or point-in-time correctness. Numeric JSON prices are rejected under this particular contract rather than silently converted.

## 15. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Duplicate key error | Conflicting fields in source | Inspect raw response and source contract |
| Close rejected | Null, numeric type or invalid decimal | Check the schema and source representation |
| Hash changes with same values | Whitespace, encoding or key order changed | Compare raw bytes and canonicalization policy |
| Missing records | Pagination or filtering | Review API contract and retrieval evidence |
| Historical result uses future data | Availability time omitted | Review publication and revision timestamps |
| Parsing exhausts resources | Oversized or deeply nested input | Apply appropriate limits |
