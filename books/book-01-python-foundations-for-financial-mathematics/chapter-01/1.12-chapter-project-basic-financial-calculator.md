2. compound interest and future value,
3. percentage change,

## 1.12.4 Establishing the Numerical Policy

```python
from decimal import Decimal, ROUND_HALF_UP

MONEY_QUANTUM = Decimal("0.01")
ROUNDING_MODE = ROUND_HALF_UP
```

`MONEY_QUANTUM` represents the two-decimal-place monetary scale used by this project's examples. `ROUNDING_MODE` specifies the project's example rounding rule. These values are **not universal financial standards**. Different currencies, securities, contracts, tax systems, accounting policies, and regulatory environments may require different scales and rounding rules.

```python
def round_money(value):
    return value.quantize(
        MONEY_QUANTUM,
        rounding=ROUNDING_MODE,
    )
```

Centralizing numerical policy makes it visible, reviewable, testable, and easier to change.

## 1.12.5 Understanding the Decimal Calculation Lifecycle

Using `Decimal` does not mean that calculations have unlimited precision. Decimal arithmetic operates under an active **decimal context**, which includes a precision setting and other arithmetic behavior.

```text
Decimal representation
        │
        ▼
Decimal context precision
        │
        ▼
Calculation
        │
        ▼
Required rounding stage
        │
        ▼
quantize()
        │
        ▼
Display formatting
```

The default decimal context is sufficient for the ordinary educational examples in this project. However, final `quantize()` controls the requested output exponent and rounding behavior; it does not restore precision already lost during earlier arithmetic. Production applications should choose working precision according to their numerical requirements.

## 1.12.6 Numerical Validity vs. Business Validity

A value can be syntactically valid Python input while still being inappropriate for a particular financial product. Negative interest rates or balances can be legitimate in some financial contexts, while a particular product may prohibit them.

> **Numerical validity and business validity are different concerns.**

This calculator validates important mathematical requirements, but it does not attempt to encode the business rules of every possible financial product.

## 1.12.7 Reading Finite Decimal Input

`Decimal` supports special values such as `NaN`, `Infinity`, and `-Infinity`. Those values are useful in some numerical environments but are not appropriate as ordinary inputs to this calculator.

```python
def read_decimal(prompt):
    value = Decimal(input(prompt).strip())

    if not value.is_finite():
        raise ValueError(
            "Financial input must be finite."
        )

    return value
```

This provides one location for reading input, converting it to `Decimal`, and rejecting non-finite numerical values.

## 1.12.8 Calculation 1 — Simple Interest

A common simple-interest model is:

\[
I=P\times r\times t
\]

where \(P\) is principal, \(r\) is the annual interest rate expressed as a decimal, \(t\) is time in years, and \(I\) is interest. The ending amount is:

\[
A=P+I
\]

For a $10,000 principal, 5% annual rate, and three years:

\[
I=10000\times0.05\times3=1500
\]

and \(A=11500\).

```python
principal = Decimal("10000.00")
annual_rate = Decimal("0.05")
years = Decimal("3")

interest = principal * annual_rate * years
ending_balance = principal + interest

interest = round_money(interest)
ending_balance = round_money(ending_balance)
```

## 1.12.9 Converting Percentage Input

Users commonly enter `5` to mean 5%, while the formula requires `0.05`.

```python
rate_percent = read_decimal(
    "Annual interest rate (%): "
)
annual_rate = rate_percent / Decimal("100")
```

Confusing `5` and `0.05` changes the calculation by a factor of 100.

## 1.12.10 Displaying Simple-Interest Results

```python
print()
print("SIMPLE INTEREST RESULTS")
print("-" * 30)
print(f"Principal:      ${principal:,.2f}")
print(f"Interest:       ${interest:,.2f}")
print(f"Ending Balance: ${ending_balance:,.2f}")
```

Formatting improves presentation. It does not define the financial calculation or its rounding policy.

## 1.12.11 Calculation 2 — Compound Interest and Future Value

A common future-value model is:

\[
FV=PV(1+r)^n
\]

where \(PV\) is present value, \(r\) is the rate per compounding period, \(n\) is the number of compounding periods, and \(FV\) is future value.

```python
present_value = Decimal("10000.00")
annual_rate = Decimal("0.05")
years = 10

future_value = (
    present_value
    * (Decimal("1") + annual_rate) ** years
)
future_value = round_money(future_value)
```

Under these assumptions, the result is approximately `$16,288.95`.

## 1.12.12 Generalizing Compounding Frequency

A common generalized model is:

\[
FV=PV\left(1+\frac{r}{m}\right)^{mt}
\]

where \(r\) is the nominal annual rate, \(m\) is compounding periods per year, and \(t\) is years.

```python
present_value = Decimal("10000.00")
annual_rate = Decimal("0.05")
years = 10
periods_per_year = 12

periodic_rate = annual_rate / Decimal(periods_per_year)
number_of_periods = periods_per_year * years

future_value = (
    present_value
    * (Decimal("1") + periodic_rate)
    ** number_of_periods
)
```

This educational calculation assumes a constant nominal annual rate, regular compounding, no intermediate deposits or withdrawals, and final-value rounding under the project's example policy. A real financial product may use different conventions.

## 1.12.13 Rounding Stage and Compound Interest

The preceding implementation calculates the future value and rounds only the final result. A real account or contract may instead require interest to be calculated, rounded, and posted during every period. These approaches can produce different ending balances.

> **The required rounding stage must come from the financial specification governing the calculation.**

The calculator uses final-value rounding because that matches the mathematical model being taught—not because final-only rounding is universally correct.

## 1.12.14 Calculation 3 — Percentage Change

\[
\text{Percentage Change}=\frac{New-Old}{Old}\times100
\]

For an old value of $125 and new value of $140, the percentage change is 12%.

```python
old_value = Decimal("125")
new_value = Decimal("140")

percentage_change = (
    (new_value - old_value)
    / old_value
    * Decimal("100")
)
```

## 1.12.15 Protecting Against Division by Zero

```python
if old_value == Decimal("0"):
    print(
        "Percentage change cannot be calculated "
        "when the original value is zero."
    )
else:
    percentage_change = (
        (new_value - old_value)
        / old_value
        * Decimal("100")
    )
```

> **Validate the mathematical assumptions of a formula before evaluating it.**

A negative nonzero starting value is mathematically permitted by the expression, but percentage-change interpretation can become domain-dependent. Production applications should define the intended financial meaning.

## 1.12.16 Calculation 4 — Investment Profit or Loss

A simplified investment profit/loss calculation is:

\[
P/L=(SellingPrice-PurchasePrice)\times Quantity
\]

```python
purchase_price = Decimal("50.00")
selling_price = Decimal("58.00")
quantity = Decimal("100")

profit_loss = (
    selling_price - purchase_price
) * quantity

if profit_loss > Decimal("0"):
    status = "PROFIT"
elif profit_loss < Decimal("0"):
    status = "LOSS"
else:
    status = "BREAK-EVEN"
```

`Decimal` is intentionally used for quantity because financial assets can sometimes support fractional quantities. A specific product may instead require whole-number quantities or another precision rule.

## 1.12.17 Profit/Loss Percentage

\[
Investment=PurchasePrice\times Quantity
\]

\[
Return=\frac{Profit/Loss}{Investment}\times100
\]

```python
initial_investment = purchase_price * quantity

if initial_investment != Decimal("0"):
    return_percent = (
        profit_loss
        / initial_investment
        * Decimal("100")
    )
```

This simplified model excludes commissions, taxes, dividends, financing costs, bid-ask spreads, corporate actions, and transaction timing.

## 1.12.18 Calculation 5 — Transaction Fee

Suppose a fee is charged **in addition to** the transaction amount:

\[
Fee=Amount\times Rate
\]

```python
transaction_amount = Decimal("1250.75")
fee_rate = Decimal("0.0125")
fee = round_money(transaction_amount * fee_rate)
total_paid = round_money(transaction_amount + fee)
```

Under the project's rounding policy, the fee is `$15.63`. This is only one fee model. Some systems deduct fees from proceeds, use tiered schedules, apply minimum or maximum charges, or follow other contractual rules.

## 1.12.19 Calculation 6 — Financial Reconciliation

```python
system_a = Decimal("1250000.00")
system_b = Decimal("1250000.01")
tolerance = Decimal("0.01")

difference = abs(system_a - system_b)

if difference <= tolerance:
    print("Values reconcile")
else:
    print("Reconciliation exception")
```

The `$0.01` tolerance is illustrative. A reconciliation tolerance must come from the applicable business, accounting, contractual, operational, or control requirement.

## 1.12.20 Do Not Round Reconciliation Differences Automatically

The program compares `difference <= tolerance` using the actual `Decimal` difference. It does not automatically round `difference` before comparing it with the tolerance.

> **Do not introduce additional rounding into reconciliation logic unless the reconciliation specification explicitly requires it.**

## 1.12.21 Complete Basic Financial Calculator

The following program integrates the Chapter 1 concepts into one runnable application. It intentionally uses a procedural structure so that the implementation can be understood primarily with concepts introduced so far.

```python
from decimal import (
    Decimal,
    InvalidOperation,
    ROUND_HALF_UP,
)

MONEY_QUANTUM = Decimal("0.01")
ROUNDING_MODE = ROUND_HALF_UP


def round_money(value):
    return value.quantize(
        MONEY_QUANTUM,
        rounding=ROUNDING_MODE,
    )


def read_decimal(prompt):
    value = Decimal(input(prompt).strip())
    if not value.is_finite():
        raise ValueError(
            "Financial input must be finite."
        )
    return value


print("=" * 50)
print("BASIC FINANCIAL CALCULATOR")
print("=" * 50)
print("1. Simple Interest")
print("2. Compound Interest / Future Value")
print("3. Percentage Change")
print("4. Investment Profit or Loss")
print("5. Transaction Fee")
print("6. Financial Reconciliation")
print("=" * 50)

choice = input("Select calculation: ").strip()

try:
    if choice == "1":
        principal = read_decimal("Principal amount: ")
        rate_percent = read_decimal(
            "Annual interest rate (%): "
        )
        years = read_decimal("Number of years: ")
        rate = rate_percent / Decimal("100")
        interest = principal * rate * years
        ending_balance = principal + interest
        interest = round_money(interest)
        ending_balance = round_money(ending_balance)

        print()
        print("SIMPLE INTEREST RESULTS")
        print("-" * 30)
        print(f"Principal:      ${principal:,.2f}")
        print(f"Interest:       ${interest:,.2f}")
        print(f"Ending Balance: ${ending_balance:,.2f}")

    elif choice == "2":
        present_value = read_decimal("Present value: ")
        rate_percent = read_decimal(
            "Annual interest rate (%): "
        )
        years = int(input("Number of years: ").strip())
        periods_per_year = int(
            input("Compounding periods per year: ").strip()
        )

        if years < 0:
            print(
                "Number of years cannot be negative "
                "for this calculator model."
            )
        elif periods_per_year <= 0:
            print(
                "Compounding periods must be greater "
                "than zero."
            )
        else:
            annual_rate = rate_percent / Decimal("100")
            periodic_rate = (
                annual_rate / Decimal(periods_per_year)
            )
            number_of_periods = periods_per_year * years
            future_value = (
                present_value
                * (Decimal("1") + periodic_rate)
                ** number_of_periods
            )
            future_value = round_money(future_value)

            print()
            print("FUTURE VALUE RESULTS")
            print("-" * 30)
            print(f"Present Value: ${present_value:,.2f}")
            print(f"Future Value:  ${future_value:,.2f}")

    elif choice == "3":
        old_value = read_decimal("Original value: ")
        new_value = read_decimal("New value: ")

        if old_value == Decimal("0"):
            print(
                "Percentage change cannot be calculated "
                "when the original value is zero."
            )
        else:
            percentage_change = (
                (new_value - old_value)
                / old_value
                * Decimal("100")
            )
            print(
                "Percentage Change: "
                f"{percentage_change:.2f}%"
            )

    elif choice == "4":
        purchase_price = read_decimal(
            "Purchase price per unit: "
        )
        selling_price = read_decimal(
            "Selling price per unit: "
        )
        quantity = read_decimal("Quantity: ")

        profit_loss = (
            selling_price - purchase_price
        ) * quantity
        profit_loss = round_money(profit_loss)
        initial_investment = purchase_price * quantity

        if profit_loss > Decimal("0"):
            status = "PROFIT"
        elif profit_loss < Decimal("0"):
            status = "LOSS"
        else:
            status = "BREAK-EVEN"

        print()
        print(f"Status: {status}")
        print(f"Profit/Loss: ${profit_loss:,.2f}")

        if initial_investment != Decimal("0"):
            return_percent = (
                profit_loss
                / initial_investment
                * Decimal("100")
            )
            print(f"Return: {return_percent:.2f}%")

    elif choice == "5":
        transaction_amount = read_decimal(
            "Transaction amount: "
        )
        fee_percent = read_decimal("Fee rate (%): ")
        fee_rate = fee_percent / Decimal("100")
        fee = round_money(
            transaction_amount * fee_rate
        )
        total_paid = round_money(
            transaction_amount + fee
        )

        print()
        print("TRANSACTION FEE RESULTS")
        print("-" * 30)
        print(
            "Transaction Amount: "
            f"${transaction_amount:,.2f}"
        )
        print(f"Fee:                ${fee:,.2f}")
        print(f"Total Paid:         ${total_paid:,.2f}")

    elif choice == "6":
        system_a = read_decimal("System A amount: ")
        system_b = read_decimal("System B amount: ")
        tolerance = read_decimal(
            "Allowed reconciliation tolerance: "
        )

        if tolerance < Decimal("0"):
            print("Tolerance cannot be negative.")
        else:
            difference = abs(system_a - system_b)

            print()
            print("RECONCILIATION RESULTS")
            print("-" * 30)
            print(f"System A:   ${system_a:,.2f}")
            print(f"System B:   ${system_b:,.2f}")
            print(f"Difference: ${difference:,.2f}")
            print(f"Tolerance:  ${tolerance:,.2f}")

            if difference <= tolerance:
                print("Status: WITHIN TOLERANCE")
            else:
                print("Status: RECONCILIATION EXCEPTION")

    else:
        print("Invalid calculator selection.")

except InvalidOperation:
    print(
        "Invalid numeric input. Please enter valid numbers."
    )
except ValueError as error:
    print(f"Invalid input: {error}")
```

## 1.12.26 Testing the Calculator

A calculator should not be validated with only one successful example. Important cases include valid and invalid decimal input, `NaN`, `Infinity`, zero interest, zero and negative years, invalid compounding frequency, percentage-change increases/decreases/no-change/zero denominator, profit/loss/break-even, fractional quantities, transaction-fee rounding boundaries, reconciliation below/at/above tolerance, negative tolerance, and rounding midpoint boundaries.

Testing should verify both mathematical correctness and policy behavior.

## 1.12.27 Boundary Testing

Boundaries are particularly important in financial calculations. For reconciliation, test differences below, equal to, and above tolerance. For rounding, test just below, exactly at, and just above a midpoint. For percentage change, test an original value of zero.

> **Test where the behavior changes, not only where the calculation is easy.**
