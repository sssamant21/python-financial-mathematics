## 1.6.1 From a Financial Formula to an Executable Program

Consider compound growth:

\[
FV=P(1+r)^n
\]

where \(FV\) is future value, \(P\) is principal, \(r\) is the **effective interest rate per compounding period**, and \(n\) is the number of those compounding periods.

For \(P=1000\), \(r=0.05\), and \(n=3\):

\[
FV=1000(1.05)^3=1157.625
\]

The fundamental progression is **financial problem → mathematical model → Python program → numerical result**.

## 1.6.2 Your First Program

Create `future_value.py`:

```python
principal = 1_000.0
rate = 0.05
periods = 3

future_value = principal * (1 + rate) ** periods

print(future_value)
```

Run:

```bash
python future_value.py
```

Expected output:

```text
1157.625
```

## 1.6.3 Assignment and Numeric Literals

In:

```python
principal = 1_000.0
```

Python's assignment statement binds the name `principal` to the resulting object/value. Underscores are permitted in numeric literals and can improve readability, so `1000.0` and `1_000.0` represent the same numeric value.

For financial programs, separators make large quantities easier to inspect:

```python
notional = 10_000_000.0
```

## 1.6.4 Variables Should Communicate Financial Meaning

Prefer descriptive names:

```python
principal = 1_000.0
rate = 0.05
periods = 3
```

over cryptic names when clarity matters. Useful names include `interest_rate`, `rate_per_period`, `cash_flow`, `discount_rate`, and `portfolio_value`.

PEP 8 generally recommends lowercase names with underscores for ordinary functions and variables, such as `calculate_future_value`.

## 1.6.5 Python Names Are Case-Sensitive

`rate`, `Rate`, and `RATE` are different names. Consistent naming helps keep quantitative code understandable and reviewable.

## 1.6.6 Integers and Floating-Point Numbers

```python
periods = 3
rate = 0.05

print(type(periods))
print(type(rate))
```

Typical output:

```text
<class 'int'>
<class 'float'>
```

Python `float` uses binary floating-point representation. Many decimal fractions cannot be represented exactly in binary floating point. Therefore `0.05` is convenient decimal source notation, but readers should not infer exact internal decimal representation.

## 1.6.7 Percentages and Decimal Rates

A rate of 5% means:

\[
5\%=\frac{5}{100}=0.05
\]

Thus:

```python
rate = 0.05
```

represents 5% when the financial model expects a decimal rate. Python itself does not know that this number represents an interest rate; the financial model supplies that meaning.

## 1.6.8 Rate and Period Units Must Match

For \(FV=P(1+r)^n\), the rate \(r\) and period count \(n\) must use compatible periods. An effective annual rate naturally pairs with a number of years in this simplified model; an effective monthly rate pairs with months.

A program can be syntactically valid while mixing incompatible financial units.

## 1.6.9 Do Not Automatically Divide Every Annual Rate by 12

The relationship

\[
r_{monthly}=\frac{r_{annual}}{12}
\]

is not a universal conversion rule. The correct conversion depends on how the quoted annual rate is defined.

If \(r_a\) is an annual effective rate and \(r_m\) is the equivalent monthly effective rate:

\[
(1+r_m)^{12}=1+r_a
\]

so:

\[
r_m=(1+r_a)^{1/12}-1
\]

Detailed rate conventions are covered later. The rule here is: **rate conversion depends on the rate convention**.

## 1.6.10 Arithmetic Operators

In:

```python
future_value = principal * (1 + rate) ** periods
```

`+` means addition, `*` multiplication, and `**` exponentiation.

Thus `(1 + rate) ** periods` represents \((1+r)^n\).

## 1.6.11 Python Uses `**`, Not `^`, for Exponentiation

Incorrect:

```python
(1 + rate) ^ periods
```

Correct:

```python
(1 + rate) ** periods
```

For applicable operands, `^` is bitwise exclusive OR; Python uses `**` for exponentiation.

## 1.6.12 Parentheses and Precedence

\[
(1.05)^3=1.157625
\]

while:

\[
1+(0.05)^3=1.000125
\]

These are different financial calculations. Parentheses communicate the intended mathematical structure. Python also defines operator-precedence rules, but quantitative code should favor readability rather than rely unnecessarily on a reader remembering every rule.

## 1.6.13 Displaying the Result

```python
print(future_value)
```

produces an unexplained number. A label adds context:

```python
print("Future value:", future_value)
```

A useful principle is **numerical result + context = more useful output**.

## 1.6.14 Formatted String Literals

Python f-strings allow expressions to be embedded in strings:

```python
print(f"Future value: {future_value}")
```

For financial display:

```python
print(f"Future value: ${future_value:,.2f}")
```

For this Python `float`, the displayed result is:

```text
Future value: $1,157.62
```

## 1.6.15 Display Formatting Is Not a Financial Rounding Policy

`f"{future_value:,.2f}"` asks Python to display the floating-point value with two digits after the decimal point. It does not establish a universal financial rounding rule.

Financial applications may have contractual, accounting, currency-specific, regulatory, or calculation-specific rounding policies. Therefore **Python display formatting is not the same as a financial rounding policy**.

Later sections cover binary floating point, `round()`, `decimal.Decimal`, rounding modes, currency calculations, and numerical error.

## 1.6.16 Percentage Formatting

```python
rate = 0.05
print(f"Interest rate: {rate:.2%}")
```

outputs:

```text
Interest rate: 5.00%
```

The underlying variable remains `0.05`. Stored/computed value and displayed representation are distinct concepts.

## 1.6.17 A More Useful First Program

```python
principal = 1_000.0
rate_per_period = 0.05
periods = 3

future_value = principal * (1 + rate_per_period) ** periods

print(f"Principal: ${principal:,.2f}")
print(f"Rate per period: {rate_per_period:.2%}")
print(f"Periods: {periods}")
print(f"Future value: ${future_value:,.2f}")
```

Possible output:

```text
Principal: $1,000.00
Rate per period: 5.00%
Periods: 3
Future value: $1,157.62
```

The name `rate_per_period` makes an important assumption visible in the code.

## 1.6.18 Comments Should Explain Meaning

Useful:

```python
# Effective interest rate per modeled compounding period
rate_per_period = 0.05
```

Less useful:

```python
# Set rate to 0.05
rate_per_period = 0.05
```

Comments should add financial or computational meaning rather than merely repeat the code.

## 1.6.19 Financial Models Have Assumptions

The simple relationship \(FV=P(1+r)^n\) assumes, for this example, that the effective rate per period is constant, rate and period count use compatible periods, compounding follows the modeled period, and no additional deposits, withdrawals, fees, or taxes are modeled.

A useful principle is:

\[
\text{Financial Model}=\text{Formula}+\text{Definitions}+\text{Assumptions}
\]

A mathematically correct calculation can still be inappropriate if its assumptions do not match the actual problem.

## 1.6.20 Validate the Result Independently

Do not assume a program is correct merely because it runs.

\[
1.05^3=1.157625
\]

and:

\[
1000(1.157625)=1157.625
\]

The Python result should agree with the independently expected result.

## 1.6.21 Floating-Point Comparison

Exact equality is not generally appropriate for every floating-point computation. Python provides `math.isclose()` for testing whether values are close according to relative and absolute tolerances:

```python
import math

future_value = 1_000.0 * (1 + 0.05) ** 3
expected_value = 1_157.625

print(math.isclose(future_value, expected_value))
```

Tolerance selection and numerical testing are covered later. The principle is: **numerical validation is not blind exact equality**.

## 1.6.22 Our First Financial Function

```python
def calculate_future_value(principal, rate_per_period, periods):
    return principal * (1 + rate_per_period) ** periods
```

Use it:

```python
future_value = calculate_future_value(
    principal=1_000.0,
    rate_per_period=0.05,
    periods=3,
)

print(f"Future value: ${future_value:,.2f}")
```

This provides a reusable computational representation of the financial relationship.

## 1.6.23 Scenario Analysis

```python
def calculate_future_value(principal, rate_per_period, periods):
    return principal * (1 + rate_per_period) ** periods

fv_3_percent = calculate_future_value(1_000.0, 0.03, 3)
fv_5_percent = calculate_future_value(1_000.0, 0.05, 3)
fv_7_percent = calculate_future_value(1_000.0, 0.07, 3)

print(f"3%: ${fv_3_percent:,.2f}")
print(f"5%: ${fv_5_percent:,.2f}")
print(f"7%: ${fv_7_percent:,.2f}")
```

This is our first simple example of scenario analysis.

## 1.6.24 Separate Calculation from Presentation

A calculation function should return a numeric result:

```python
def calculate_future_value(principal, rate_per_period, periods):
    return principal * (1 + rate_per_period) ** periods
```

Formatting can occur separately. This allows the result to feed another calculation, a test, table, chart, notebook, report, API, or financial application.

## 1.6.25 The Quantitative Programming Workflow

1. Define the financial problem.
2. Define the mathematical model.
3. Define variables and units.
4. State assumptions.
5. Implement the model.
6. Execute it.
7. Validate independently.
8. Present and interpret the result.

In compact form:

\[
\boxed{\text{Problem}\rightarrow\text{Model}\rightarrow\text{Units}\rightarrow\text{Assumptions}\rightarrow\text{Code}\rightarrow\text{Validation}\rightarrow\text{Interpretation}}
\]

## 1.6.26 Common Beginner Mistakes

- Writing `5` instead of `0.05` when the model expects a decimal 5% rate.
- Using `^` instead of `**` for exponentiation.
- Mixing incompatible rate and time units.
- Assuming annual rate divided by 12 is universally correct.
- Confusing display formatting with financial rounding.
- Assuming decimal-looking floats are exact.
- Trusting a program merely because it executes.

The core warning is: **runs successfully does not imply financially correct**.

## 1.6.28 Key Takeaways

1. Financial relationships can be translated into executable Python.
2. Variables should communicate financial meaning and conventional Python code generally uses `snake_case` for ordinary functions and variables.
3. `int` and `float` are distinct numeric types; Python `float` uses binary floating-point representation.
4. A 5% rate is represented as `0.05` when the model expects a decimal rate.
5. Rate and period definitions must be compatible, and rate conversion depends on the quoted-rate convention.
6. Python uses `**` for exponentiation, not `^`.
7. f-strings provide convenient formatted output, but display formatting is not a financial rounding policy.
8. Financial formulas should be accompanied by definitions, units, and assumptions.
9. Program results should be independently validated; `math.isclose()` provides a standard approximate-comparison tool.
10. Python functions allow financial calculations to be reused, and calculation should generally remain separate from presentation.
11. Programming makes scenario analysis straightforward.
12. Successful execution does not guarantee mathematical or financial correctness.
