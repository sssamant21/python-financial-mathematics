## 1.8.1 From Financial Values to Financial Calculations

Section 1.7 introduced variables, numeric types, units, dates, and financial data representation. The next step is to perform calculations with those values.

```python
principal = 10_000
annual_rate = 0.05
years = 3

interest = principal * annual_rate
future_value = principal * (1 + annual_rate) ** years
```

The computational progression is:

**Financial Values + Operators → Expressions → Financial Results**

Operators provide the basic bridge between mathematical formulas and executable financial calculations.

## 1.8.2 Arithmetic Operators

| Operator | Meaning | Example |
|---|---|---|
| `+` | Addition | `a + b` |
| `-` | Subtraction | `a - b` |
| `*` | Multiplication | `a * b` |
| `/` | True division | `a / b` |
| `//` | Floor division for the built-in numeric examples considered here | `a // b` |
| `%` | Remainder/modulo | `a % b` |
| `**` | Exponentiation | `a ** b` |
| `+x` | Unary positive | `+x` |
| `-x` | Unary negative | `-x` |

For introductory financial mathematics, the most frequently used arithmetic operators are `+`, `-`, `*`, `/`, and `**`.

## 1.8.3 Addition and Financial Compatibility

Suppose two compatible cash flows are `500` and `750`:

```python
cash_flow_1 = 500
cash_flow_2 = 750
total_cash_flow = cash_flow_1 + cash_flow_2
```

The result is `1250`. But financial arithmetic requires more than compatible Python types. Adding a USD amount directly to a EUR amount can be computationally valid while lacking a meaningful monetary interpretation unless an explicit currency-conversion rule is applied.

**Computationally Valid ≠ Financially Valid.** Financial meaning and units remain part of the calculation.

## 1.8.4 Subtraction

```python
revenue = 125_000
expenses = 90_000
net_amount = revenue - expenses
```

The result is `35000`.

Subtraction also measures absolute changes:

```python
initial_price = 100.0
final_price = 108.0
price_change = final_price - initial_price
```

The result is `8.0`. This is an absolute price change, not yet a relative return.

## 1.8.5 Multiplication

For a simple one-period interest example, if `P = 10,000` and `r = 0.05`, then `I = Pr`:

```python
principal = 10_000
annual_rate = 0.05
interest = principal * annual_rate
```

The result is `500.0`. If a model expects a decimal rate, 5% must be represented as `0.05`; the numeric value `5` is not automatically interpreted by Python as 5%.

## 1.8.6 True Division — `/`

```python
portfolio_value = 100_000
position_value = 25_000
weight = position_value / portfolio_value
```

The result is `0.25`, representing a portfolio weight of 25%. Calculation representation and display representation are distinct; `weight * 100` gives `25.0` for percentage display.

## 1.8.7 Division by Zero

```python
position_value = 25_000
portfolio_value = 0
weight = position_value / portfolio_value
```

For these built-in numeric operands, Python raises `ZeroDivisionError`. The corresponding mathematical quantity is undefined. Financial programs must consider the valid mathematical domain before performing an operation.

**Valid Python Syntax ≠ Valid Mathematical Domain.**

## 1.8.8 Floor Division — `//`

For Python's built-in integer and floating-point numeric operands, `//` performs floor division.

```python
17 // 5  # 3
17 / 5   # 3.4
```

The distinction matters. `/` is commonly intended for financial ratios, rates, averages, and discount factors. Other numeric types can define related operations according to their documented semantics; do not assume every detail is identical across numeric types.

## 1.8.9 The Remainder Operator — `%`

For a positive-integer example:

```python
17 % 5  # 2
```

One programming use is decomposing integer periods:

```python
months = 29
full_years = months // 12
remaining_months = months % 12
```

This yields two full years and five remaining months. Real financial date calculations can involve calendars, contractual rules, and day-count conventions, so simple integer decomposition must not replace those conventions unless the model explicitly permits it.

## 1.8.10 Exponentiation — `**`

Python uses `**` for exponentiation:

```python
2 ** 3  # 8
```

Python does not use `^` for exponentiation; `^` is a bitwise XOR operator.

**Python exponentiation = `**`.**

## 1.8.11 Compound Growth

Under a simplified annual-compounding model:

`FV = P(1 + r)^n`

```python
principal = 10_000
annual_rate = 0.05
years = 3
future_value = principal * (1 + annual_rate) ** years
```

The result is `11,576.25`. This demonstrates direct translation from mathematical notation into Python.

## 1.8.12 Present Value

Under the same simplified assumptions:

`PV = FV / (1 + r)^n`

```python
future_value = 10_000
annual_rate = 0.05
years = 3
present_value = future_value / (1 + annual_rate) ** years
```

The expression combines addition, exponentiation, and division.

## 1.8.13 Absolute and Relative Change

```python
initial_price = 100.0
final_price = 108.0
absolute_change = final_price - initial_price
relative_change = (final_price - initial_price) / initial_price
```

The absolute change is `8`; the relative change is `0.08`, or 8%. The denominator in a relative measure is part of the financial definition and should not be chosen casually.

## 1.8.14 Gain and Loss

```python
purchase_value = 50_000
current_value = 53_500
gain = current_value - purchase_value
gain_rate = gain / purchase_value
```

The gain is `3,500`; the simple relative gain measured against purchase value is `0.07`, or 7%.

**Difference → Normalize by Defined Base → Relative Measure.**

## 1.8.15 Unary Positive and Negative Operators

```python
cash_inflow = 1_000
cash_outflow = -250
net_cash_flow = cash_inflow + cash_outflow
```

The result is `750`. Sign conventions are modeling conventions and must be documented.

## 1.8.16 Augmented Assignment

Python provides augmented assignment such as `+=`, `-=`, `*=`, `/=`, and `**=`.

```python
balance = 1_000
balance += 250
```

For this simple immutable numeric example, the numeric result is the same as `balance = balance + 250`. In general, augmented assignment is not identical to textual rewriting: its target is evaluated once and some objects can support in-place behavior.

## 1.8.17 A Simple Balance Update

```python
balance = 10_000
deposit = 1_000
withdrawal = 500
balance += deposit
balance -= withdrawal
```

The result is `10,500`. A production financial ledger may additionally depend on transaction ordering, settlement state, currency, fees, timestamps, reversals, and accounting rules. This example is a mathematical model, not a complete ledger implementation.

## 1.8.18 Operator Precedence

```python
result = 100 + 20 * 3
```

Multiplication binds more tightly than addition, so the result is `160`. Python defines a broader operator-precedence hierarchy. Section 1.9 develops expressions and precedence in greater depth.

## 1.8.19 Parentheses and Mathematical Intent

```python
future_value = principal * (1 + rate) ** periods
present_value = future_value / ((1 + rate) ** periods)
```

Even when Python's precedence already gives the intended result, parentheses can improve human readability.

**Use parentheses to communicate mathematical intent.**

## 1.8.20 Translating a Formula Step by Step

For `FV = P(1 + r)^n`:

```python
growth_factor = 1 + annual_rate
accumulation_factor = growth_factor ** years
future_value = principal * accumulation_factor
```

This decomposition exposes intermediate quantities and can make validation easier.

## 1.8.21 Intermediate Values and Validation

Readable intermediate variables such as `growth_factor`, `accumulation_factor`, and `future_value` map directly to the mathematical structure and can be inspected independently.

**Readable Financial Code Is Easier to Validate.**

## 1.8.22 Operators and Operand Types

Operators are not restricted to financial numbers:

```python
"USD " + "100"
[1, 2] + [3, 4]
```

Operator behavior depends on operand types and the operations those types support.

**Operator + Operand Types → Operation Behavior.**

## 1.8.23 `Decimal` and Financial Operators

```python
from decimal import Decimal

principal = Decimal("10000.00")
rate = Decimal("0.05")
interest = principal * rate
future_value = principal * (Decimal("1") + rate) ** 3
```

The financial formula is unchanged while the numerical representation differs. `Decimal("0.05")` exactly represents that decimal input, but subsequent arithmetic remains governed by decimal arithmetic rules, including context precision and rounding where applicable.

**Decimal Representation ≠ Unlimited Arithmetic Precision.**

Detailed numerical precision and rounding policy is reserved for Section 1.11.

## 1.8.24 Units Remain Part of Every Operation

```python
principal_usd = 10_000
rate_decimal = 0.05
interest_usd = principal_usd * rate_decimal
```

Conceptually, `USD × dimensionless rate = USD`. By contrast, an expression resembling `USD + years` has no ordinary financial interpretation merely because both values are represented by numbers.

**Type Compatibility Alone ≠ Dimensional Correctness.**

## 1.8.25 Basis-Point Calculations

One basis point is one hundredth of one percentage point:

`1 bp = 0.0001`, so `100 bp = 0.01 = 1%`.

```python
spread_bps = 125
spread_decimal = spread_bps / 10_000
base_rate = 0.04
total_rate = base_rate + spread_decimal
```

Thus `125 bp = 0.0125 = 1.25%`, and the total rate is `0.0525 = 5.25% = 525 bp`.

**Normalize Units → Perform Arithmetic.**

## 1.8.26 Percentage Increase

```python
old_value = 100
new_value = 115
increase = new_value - old_value
increase_rate = increase / old_value
```

The absolute increase is `15`; the relative increase is `0.15`, or 15%. Amount and rate answer different questions.

## 1.8.27 Applying a Percentage Change

```python
value = 100
increase_rate = 0.15
new_value = value * (1 + increase_rate)
```

The result is `115`. For a 15% decrease, `value * (1 - 0.15)` gives `85`.

## 1.8.28 Successive Percentage Changes

A 10% increase followed by a 10% decrease does not return a value to its starting point:

```python
value = 100
value = value * (1 + 0.10)
value = value * (1 - 0.10)
```

The result is `99.0` because `1.10 × 0.90 = 0.99`.

**Successive Relative Changes Compound Multiplicatively.**

## 1.8.29 A First Portfolio Calculation

```python
stock_value = 60_000
bond_value = 30_000
cash_value = 10_000
portfolio_value = stock_value + bond_value + cash_value

stock_weight = stock_value / portfolio_value
bond_weight = bond_value / portfolio_value
cash_weight = cash_value / portfolio_value
```

The weights are `0.60`, `0.30`, and `0.10`, which sum to `1` for this fully allocated example. Full portfolio mathematics is developed later in the book.

## 1.8.30 A First Weighted Return Calculation

For a simplified two-asset, single-period example:

```python
stock_weight = 0.60
stock_return = 0.08
bond_weight = 0.40
bond_return = 0.03

portfolio_return = (
    stock_weight * stock_return
    + bond_weight * bond_return
)
```

The result is `0.06`, or 6%. This example intentionally omits external cash flows, rebalancing, transaction costs, and multi-period performance measurement.

## 1.8.31 A Financial Calculation Pipeline

**Inputs → Validate → Normalize Units → Calculate → Validate Result → Interpret**

For example, 125 basis points can be validated, normalized to `0.0125`, added to a `0.04` base rate, and interpreted as `0.0525 = 5.25%`.

Arithmetic is only one stage in a financially correct computation.

## 1.8.32 Common Operator Mistakes

1. **Using `^` for exponentiation.** Use `**`.
2. **Using `//` accidentally.** Ratios normally require `/` unless flooring is intended.
3. **Mixing percentage and decimal-rate representations.** If 5% is intended as a decimal rate, use `0.05`, not `5`.
4. **Ignoring units.** Numerically adding incompatible currencies or dimensions does not create a meaningful result.
5. **Ignoring denominator validity.** Relative measures require a valid denominator.
6. **Confusing absolute and relative change.** `new - old` differs from `(new - old) / old`.
7. **Assuming executable code means correct finance.** A valid Python expression can implement the wrong financial model.

**Syntactic Correctness < Numerical Correctness < Financial Correctness.**

## 1.8.33 Worked Example — Investment Growth

Suppose `P = 25,000`, `r = 0.06`, and `n = 5`. Under a simplified annual-compounding model:

```python
principal = 25_000
annual_rate = 0.06
years = 5

growth_factor = 1 + annual_rate
accumulation_factor = growth_factor ** years
future_value = principal * accumulation_factor
growth_amount = future_value - principal
total_relative_growth = growth_amount / principal

print(future_value)
print(growth_amount)
print(total_relative_growth)
```

This example combines `+`, `-`, `*`, `/`, and `**` and maps directly to the mathematical sequence `1+r`, `(1+r)^n`, `P(1+r)^n`, `FV-P`, and `(FV-P)/P`.

## 1.8.35 Key Takeaways

1. Operators transform financial values into executable expressions.
2. The principal arithmetic operators include `+`, `-`, `*`, `/`, `//`, `%`, and `**`.
3. `/` and `//` perform fundamentally different operations.
4. Python uses `**`, not `^`, for exponentiation.
5. Financial addition and subtraction require compatible meaning and units.
6. Multiplication commonly combines monetary values with rates or factors.
7. Division is central to ratios, weights, rates, and relative changes.
8. A denominator must lie within the valid mathematical and financial domain of the formula.
9. Parentheses help communicate mathematical intent.
10. Intermediate values can improve readability, debugging, and validation.
11. Operator behavior depends on operand types.
12. Augmented assignment is convenient but has semantics beyond simple textual substitution.
13. `Decimal` provides decimal arithmetic but does not imply unlimited precision.
14. Percentage, decimal-rate, and basis-point representations must be distinguished.
15. Absolute and relative changes represent different quantities.
16. Successive percentage changes compound multiplicatively.
17. Correct Python syntax does not guarantee correct financial mathematics.
18. Units, conventions, numerical representation, and financial meaning remain part of every operation.

**Financial Formula → Meaningful Inputs → Normalized Units → Python Expression → Validated Result → Financial Interpretation**
