## 2. Solution Conventions

Unless a solution states otherwise:

```python
from decimal import Decimal, InvalidOperation, ROUND_HALF_EVEN, ROUND_HALF_UP

MONEY_QUANTUM = Decimal("0.01")
ROUNDING_MODE = ROUND_HALF_UP


def round_money(value):
    return value.quantize(MONEY_QUANTUM, rounding=ROUNDING_MODE)
```

When an exact decimal literal is intended, construct it from a string, such as `Decimal("0.1")`, rather than from a binary float. Unless a model explicitly allows otherwise, examples reject `NaN`, `Infinity`, and `-Infinity` using `is_finite()`.

`ROUND_HALF_UP` with a quantum of `Decimal("0.01")` is an instructional policy where explicitly specified; it is not a universal financial rule. Unless a model explicitly requires intermediate posting or rounding, calculate first, derive dependent calculations, apply required numerical rounding, and then format for presentation. Display-rounded values should not silently become computational inputs.

`Decimal` provides decimal representation, but arithmetic remains subject to the active decimal context, including precision, rounding behavior, flags, and traps. Using `Decimal` does not imply unlimited precision for every intermediate calculation.

The solutions distinguish Python-valid, numerically valid, mathematically valid, valid-under-the-model, and financially meaningful inputs.

## Solution 16 — Floating-Point Observation

`0.1 + 0.2` commonly displays `0.30000000000000004`, while:

```python
Decimal("0.1") + Decimal("0.2")
```

produces `Decimal('0.3')`. Binary floating-point and decimal arithmetic have different representation characteristics.

| 125.675 | 125.68 | 125.68 |

## Solution 18 — Centralized Rounding Policy

| Input | Result |
|---:|---:|
| 12.345 | 12.35 |

# Part XII — Input Validation Solutions

## Solution 41 — Invalid Decimal Input

Malformed decimal construction such as `Decimal("abc")` signals `InvalidOperation`. Under Python's normal default decimal context, `InvalidOperation` is trapped, so an exception is raised. If the trap is disabled, the operation can instead produce `NaN` while recording the condition in the context flags.

## Solution 42 — Non-Finite Values

`Decimal("NaN")`, `Decimal("Infinity")`, and `Decimal("-Infinity")` all return `False` from `is_finite()`. The Chapter 1 financial models reject these values.

## Solution 43 — Reusable Decimal Input

```python
def read_decimal(prompt):
```

## Solution 48 — Explicit Rounding Policy

The teaching point is policy visibility, not that `round()` is universally wrong.

# Part XIV — Applied Problem Reference Implementations

## Applied Problem 1 — Savings Growth Calculator

### Model

\[
FV=PV\left(1+\frac{r}{m}\right)^{mt}
\]

This instructional implementation assumes finite decimal inputs, nonnegative time, positive compounding frequency, a positive periodic growth factor, a whole number of discrete compounding periods, and final monetary rounding for presentation. Treatment of stub periods, fractional periods, day-count conventions, or contractual posting rules requires additional specification.

```python
from decimal import Decimal, InvalidOperation, ROUND_HALF_UP

MONEY_QUANTUM = Decimal("0.01")


def round_money(value):
    return value.quantize(MONEY_QUANTUM, rounding=ROUND_HALF_UP)


def read_decimal(prompt):
    value = Decimal(input(prompt).strip())
    if not value.is_finite():
        raise ValueError("Input must be finite.")
    return value


try:
    present_value = read_decimal("Initial deposit: ")
    annual_rate_percent = read_decimal("Annual rate (%): ")
    years = read_decimal("Years: ")
    periods_per_year = int(input("Compounding periods per year: ").strip())

    if years < 0:
        raise ValueError("Years cannot be negative in this savings-growth model.")
    if periods_per_year <= 0:
        raise ValueError("Compounding frequency must be positive.")

    annual_rate = annual_rate_percent / Decimal("100")
    m = Decimal(periods_per_year)
    periodic_rate = annual_rate / m
    growth_factor = Decimal("1") + periodic_rate

    if growth_factor <= 0:
        raise ValueError("Periodic growth factor must be positive for this model.")

    total_periods_decimal = Decimal(periods_per_year) * years
    if total_periods_decimal != total_periods_decimal.to_integral_value():
        raise ValueError("This reference implementation requires a whole number of discrete compounding periods.")

    total_periods = int(total_periods_decimal)
    future_value = present_value * growth_factor ** total_periods
    total_growth = future_value - present_value

    print("Initial value:", f"${round_money(present_value):,.2f}")
    print("Future value:", f"${round_money(future_value):,.2f}")
    print("Total growth:", f"${round_money(total_growth):,.2f}")
except (InvalidOperation, ValueError):
    print("Invalid financial input.")
```

The whole-period restriction is intentional. For example, 1.5 years with monthly compounding produces 18 periods and is acceptable; an input producing fractional periods requires an additional model rule.

## Applied Problem 2 — Investment Trade Calculator

This instructional model assumes nonnegative purchase/selling prices, positive quantity, nonnegative fee rate, fees charged independently on purchase and sale values, and each fee posted at cent precision.

```text
transaction value
       ↓
raw fee
       ↓
apply fee rounding policy
       ↓
posted fee
       ↓
total cost / net proceeds
       ↓
profit or loss
       ↓
return
```

```python
from decimal import Decimal, InvalidOperation, ROUND_HALF_UP

MONEY_QUANTUM = Decimal("0.01")


def round_money(value):
    return value.quantize(MONEY_QUANTUM, rounding=ROUND_HALF_UP)


def read_decimal(prompt):
    value = Decimal(input(prompt).strip())
    if not value.is_finite():
        raise ValueError("Input must be finite.")
    return value


try:
    purchase_price = read_decimal("Purchase price: ")
    selling_price = read_decimal("Selling price: ")
    quantity = read_decimal("Quantity: ")
    fee_percent = read_decimal("Fee rate (%): ")

    if purchase_price < 0:
        raise ValueError("Purchase price cannot be negative in this model.")
    if selling_price < 0:
        raise ValueError("Selling price cannot be negative in this model.")
    if quantity <= 0:
        raise ValueError("Quantity must be positive in this model.")
    if fee_percent < 0:
        raise ValueError("Fee rate cannot be negative in this model.")

    fee_rate = fee_percent / Decimal("100")
    purchase_value = purchase_price * quantity
    sale_value = selling_price * quantity
    purchase_fee = round_money(purchase_value * fee_rate)
    sale_fee = round_money(sale_value * fee_rate)
    total_cost = purchase_value + purchase_fee
    net_sale_proceeds = sale_value - sale_fee
    raw_net_profit_loss = net_sale_proceeds - total_cost

    return_percent = None if total_cost == 0 else raw_net_profit_loss / total_cost * Decimal("100")

    print("Purchase value:", f"${round_money(purchase_value):,.2f}")
    print("Sale value:", f"${round_money(sale_value):,.2f}")
    print("Purchase fee:", f"${purchase_fee:,.2f}")
    print("Sale fee:", f"${sale_fee:,.2f}")
    print("Net profit/loss:", f"${round_money(raw_net_profit_loss):,.2f}")
    print("Return:", "undefined" if return_percent is None else f"{return_percent:.2f}%")
except (InvalidOperation, ValueError):
    print("Invalid financial input.")
```

Because the model treats rounded fees as posted fees, they intentionally become downstream computational inputs.

## Applied Problem 3 — Account Reconciliation Checker

The model uses `Difference = |SystemA - SystemB|` and declares reconciliation when `Difference <= Tolerance`. The actual difference is compared before display rounding.

```python
from decimal import Decimal, InvalidOperation


def read_decimal(prompt):
    value = Decimal(input(prompt).strip())
    if not value.is_finite():
        raise ValueError("Input must be finite.")
    return value


try:
    system_a = read_decimal("System A balance: ")
    system_b = read_decimal("System B balance: ")
    tolerance = read_decimal("Tolerance: ")

    if tolerance < 0:
        raise ValueError("Tolerance cannot be negative.")

    difference = abs(system_a - system_b)
    reconciled = difference <= tolerance

    print("Difference:", difference)
    print("Tolerance:", tolerance)
    print("Status:", "RECONCILED" if reconciled else "RECONCILIATION EXCEPTION")
except (InvalidOperation, ValueError):
    print("Invalid financial input.")
```

| A | B | Tolerance | Difference | Result |
|---:|---:|---:|---:|---|
| 1000.000 | 1000.000 | 0.01 | 0.000 | RECONCILED |
| 1000.000 | 1000.006 | 0.01 | 0.006 | RECONCILED |
| 1000.000 | 1000.010 | 0.01 | 0.010 | RECONCILED |
| 1000.000 | 1000.011 | 0.01 | 0.011 | EXCEPTION |

# Part XVI — Chapter 1 Capstone Reference Implementation

This is a **Chapter 1 reference implementation**, not a production-ready financial application. It intentionally remains procedural and limited to concepts developed through Chapter 1.

```python
from decimal import Decimal, InvalidOperation, ROUND_HALF_UP

MONEY_QUANTUM = Decimal("0.01")
ROUNDING_MODE = ROUND_HALF_UP


def round_money(value):
    return value.quantize(MONEY_QUANTUM, rounding=ROUNDING_MODE)


def read_decimal(prompt):
    value = Decimal(input(prompt).strip())
    if not value.is_finite():
        raise ValueError("Financial input must be finite.")
    return value


print("Financial Calculation Console")
print("1. Simple Interest")
print("2. Compound Interest")
print("3. Percentage Change")
print("4. Investment Profit/Loss")
print("5. Transaction Fee")
print("6. Reconciliation")
choice = input("Choose an option: ").strip()

try:
    if choice == "1":
        principal = read_decimal("Principal: ")
        rate_percent = read_decimal("Annual rate (%): ")
        years = read_decimal("Years: ")
        rate = rate_percent / Decimal("100")
        interest = principal * rate * years
        ending_balance = principal + interest
        print("Interest:", f"${round_money(interest):,.2f}")
        print("Ending balance:", f"${round_money(ending_balance):,.2f}")

    elif choice == "2":
        present_value = read_decimal("Present value: ")
        rate_percent = read_decimal("Annual rate (%): ")
        periods = int(input("Compounding periods: ").strip())
        if periods < 0:
            raise ValueError("Periods cannot be negative in this model.")
        rate = rate_percent / Decimal("100")
        growth_factor = Decimal("1") + rate
        if growth_factor <= 0:
            raise ValueError("Growth factor must be positive in this model.")
        future_value = present_value * growth_factor ** periods
        print("Future value:", f"${round_money(future_value):,.2f}")

    elif choice == "3":
        old_value = read_decimal("Old value: ")
        new_value = read_decimal("New value: ")
        if old_value == 0:
            raise ValueError("Starting value cannot be zero.")
        percentage_change = (new_value - old_value) / old_value * Decimal("100")
        print("Percentage change:", f"{percentage_change:.2f}%")

    elif choice == "4":
        purchase_price = read_decimal("Purchase price: ")
        selling_price = read_decimal("Selling price: ")
        quantity = read_decimal("Quantity: ")
        if purchase_price < 0:
            raise ValueError("Purchase price cannot be negative in this model.")
        if selling_price < 0:
            raise ValueError("Selling price cannot be negative in this model.")
        if quantity <= 0:
            raise ValueError("Quantity must be positive in this model.")
        initial_investment = purchase_price * quantity
        raw_profit_loss = (selling_price - purchase_price) * quantity
        print("Profit/Loss:", f"${round_money(raw_profit_loss):,.2f}")
        if initial_investment == 0:
            print("Return: undefined")
        else:
            return_percent = raw_profit_loss / initial_investment * Decimal("100")
            print("Return:", f"{return_percent:.2f}%")

    elif choice == "5":
        transaction_amount = read_decimal("Transaction amount: ")
        fee_percent = read_decimal("Fee rate (%): ")
        if transaction_amount < 0:
            raise ValueError("Transaction amount cannot be negative in this model.")
        if fee_percent < 0:
            raise ValueError("Fee rate cannot be negative in this model.")
        fee_rate = fee_percent / Decimal("100")
        raw_fee = transaction_amount * fee_rate
        posted_fee = round_money(raw_fee)
        total_paid = transaction_amount + posted_fee
        print("Fee:", f"${posted_fee:,.2f}")
        print("Total paid:", f"${round_money(total_paid):,.2f}")

    elif choice == "6":
        system_a = read_decimal("System A balance: ")
        system_b = read_decimal("System B balance: ")
        tolerance = read_decimal("Tolerance: ")
        if tolerance < 0:
            raise ValueError("Tolerance cannot be negative.")
        difference = abs(system_a - system_b)
        reconciled = difference <= tolerance
        print("Difference:", difference)
        print("Status:", "RECONCILED" if reconciled else "RECONCILIATION EXCEPTION")

    else:
        print("Invalid menu option.")

except (InvalidOperation, ValueError):
    print("Invalid financial input.")
```

# Part XVIII — Reflection Answer Guide

**Why is formula translation more than typing mathematics?** Implementation must define numerical representation, units, validation, assumptions, rounding policy, rounding stage, and output interpretation.

**Why can numerical representation affect results?** Computers use finite numerical representations; binary floating-point and decimal arithmetic have different characteristics.

**Decimal representation vs. context precision:** `Decimal` provides decimal representation, while the active decimal context governs arithmetic precision, rounding behavior, flags, and traps.

**Why should rounding policy be explicit?** Different rounding rules can produce different results at midpoint boundaries.

**Why does rounding stage matter?** A rounded value reused in later calculations can change subsequent results.

**Why are calculation and formatting different?** Calculation determines a numerical result; formatting determines how it is displayed.

**Why validate denominators?** Division is undefined when the denominator is zero.

**Numerical validity vs. model validity:** A number can be representable and mathematically computable while violating the assumptions of a financial model.

**Why avoid undocumented reconciliation rounding?** Premature rounding can change whether a control passes or fails.

**Why test boundaries?** Defects frequently appear around zero, equality thresholds, rounding midpoints, invalid input, and domain limits.

**Why preserve computational values?** Presentation rounding should not silently alter subsequent calculations unless the specification requires the rounded value to be posted and reused.
