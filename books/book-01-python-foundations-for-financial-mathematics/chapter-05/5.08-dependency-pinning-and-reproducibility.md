## 5.8.1 Purpose

A fresh environment solves installation separation, but it does not determine which dependency versions or artifact files will be installed. Reproducible financial work also needs identified inputs, implementation versions, model parameters, and numeric policies.

This section makes a narrow repeatability claim measurable: install the same original wheel artifacts into two fresh environments on one runtime and compare independently checked application output. A negative test changes a wheel's bytes while retaining its version and verifies that pip rejects it against the recorded hash.

## 5.8.2 Learning Objectives

You should be able to:

1. Distinguish version constraints, exact pins, and artifact hashes.
2. Pin direct and transitive dependencies for a concrete installation target.
3. Explain why a requirements inventory alone does not reproduce an analysis.
4. Run hash-checked installs from a controlled local artifact set.
5. Verify installed metadata, origin, and financial behavior after recreation.
6. Separate same-runtime evidence from cross-platform guarantees.
7. Review an intentional dependency update with regression evidence.

## 5.8.3 Levels of Evidence

| Record | Question it answers | What remains unspecified |
|---|---|---|
| Version range | Which versions are eligible? | Exact chosen version and artifact |
| Exact == pin | Which version label is requested? | Which platform artifact and exact bytes |
| Artifact hash | Which bytes are approved? | Whether those bytes implement a correct model |
| Environment record | Which runtime/platform/tooling was used? | Input data and application configuration |
| Application checks | Did selected contracts produce expected outcomes? | Untested paths and other platforms |
| Analysis record | Which source, data, parameters, and policies were used? | External facts not captured by that record |

A version label can have multiple wheels for different platforms and Python versions. A pin alone does not choose one universal artifact. Record a suitable artifact set for each intended target rather than assuming one installation file covers every system.

## 5.8.4 Pin the Dependency Closure

Pinning only the top-level application may leave its transitive dependencies free to change. For this lab, both the report fixture and its unit-validator dependency are listed explicitly with version 1.0.0 and a SHA-256 hash for each wheel.

Pip hash-checking requires a complete compatible set of requirements under its rules. Dependencies cannot be silently introduced without the required version/hash information. This lab leaves dependency resolution enabled; it does not use --no-deps to hide an incomplete specification.

A requirements file is an installation input for pip. An installed freeze inventory can help inspect a successful environment, but it does not by itself select all platform artifacts or record source data, Python, external libraries, and numeric settings. A constraint narrows a candidate choice and does not itself request installation.

## 5.8.5 Hashes and Artifact Availability

The lab uses --require-hashes, --only-binary=:all:, --no-index, --no-cache-dir, and a local --find-links directory. Pins choose the fixture versions; hashes check approved bytes; the local directory supplies those bytes without a package index or source build.

Hashes must come from a reviewed artifact selection. A matching digest does not establish the correctness or trustworthiness of arbitrary code. Generating a new hash for an unexplained changed wheel merely approves the changed bytes; it does not investigate the change.

Retain approved artifacts or an appropriate durable source for them. A requirement whose wheel is unavailable cannot recreate an environment just because its hash is known. Wheel compatibility, interpreter versions, and build dependencies also matter outside this pure-Python exercise.

## 5.8.6 Financial Reproducibility Contract

The synthetic report labels a quantity as instrument_units. It accepts exact finite nonnegative Decimal input, including zero and fractions. It performs no quantity arithmetic, currency conversion, or valuation.

The behavior check fixes the input text 12.50 and independently expects output [instrument_units, 12.50]. It records the input digest, validates rejection of incorrect types and nonfinite/negative values, and checks that imported source resides in the environment being tested.

A real analysis must additionally preserve relevant financial assumptions: quantity/price units, cash-flow perspective, observation dates, valuation convention, rounding/precision policy, reference data and model version, and external source provenance. Equal dependency versions are not sufficient evidence for equal financial meaning.

## 5.8.8 Complete Repeatability Lab

```python
"""Install identical pinned/hashed fixtures twice and reject changed bytes."""

import hashlib
import json
from pathlib import Path
import platform
import shutil
import sys
from tempfile import TemporaryDirectory
import textwrap
import venv
from zipfile import ZipFile

from pip_dependency_lab import (
    REPORT_SOURCE, UNIT_SOURCE, fixture_wheel, pip_args, require, run,
)

BEHAVIOR = '''
from decimal import Decimal
from importlib.metadata import version
from pathlib import Path
import json, sys
import book1_report_demo
import book1_unit_demo

assert Path(book1_report_demo.__file__).resolve().is_relative_to(Path(sys.prefix).resolve())
assert Path(book1_unit_demo.__file__).resolve().is_relative_to(Path(sys.prefix).resolve())
input_text = "12.50"
label, quantity = book1_report_demo.labeled_quantity(Decimal(input_text))
assert label == "instrument_units"
assert str(quantity) == "12.50"
assert book1_report_demo.labeled_quantity(Decimal("0")) == ("instrument_units", Decimal("0"))
for bad in (None, True, 1, 1.5, "1"):
    try:
        book1_report_demo.labeled_quantity(bad)
    except TypeError:
        pass
    else:
        raise AssertionError("invalid type accepted")
for token in ("NaN", "sNaN", "Infinity", "-Infinity", "-1"):
    try:
        book1_report_demo.labeled_quantity(Decimal(token))
    except ValueError:
        pass
    else:
        raise AssertionError("invalid domain accepted")
print(json.dumps({
    "versions": {"book1-report-demo": version("book1-report-demo"),
                 "book1-unit-demo": version("book1-unit-demo")},
    "input": input_text, "output": [label, str(quantity)],
}, sort_keys=True))
'''


def digest(path: Path) -> str:
    return hashlib.sha256(path.read_bytes()).hexdigest()


def interpreter(directory: Path) -> Path:
    return directory / ("Scripts/python.exe" if sys.platform == "win32" else "bin/python")


def install_arguments(wheels: Path, requirements: Path) -> list[str]:
    return pip_args(
        "install", "--no-index", "--no-cache-dir", "--only-binary=:all:",
        "--require-hashes", "--find-links", str(wheels), "-r", str(requirements),
    )


def inspect_behavior(python: Path, work: Path) -> dict[str, object]:
    result = run(python, work, ["-I", "-c", textwrap.dedent(BEHAVIOR)])
    decoded = json.loads(result.stdout)
    require(isinstance(decoded, dict), "behavior record must be an object")
    return dict(decoded)


def main() -> int:
    with TemporaryDirectory(prefix="book1-repro58-") as directory:
        root = Path(directory)
        wheels = root / "approved_wheels"
        wheels.mkdir()
        work = root / "work"
        work.mkdir()
        unit = fixture_wheel(wheels, "book1-unit-demo", "book1_unit_demo", UNIT_SOURCE)
        report = fixture_wheel(wheels, "book1-report-demo", "book1_report_demo", REPORT_SOURCE,
                               "book1-unit-demo==1.0.0")
        requirements = root / "requirements-pinned.txt"
        requirements.write_text(
            f"book1-report-demo==1.0.0 --hash=sha256:{digest(report)}\n"
            f"book1-unit-demo==1.0.0 --hash=sha256:{digest(unit)}\n",
            encoding="utf-8",
        )
        approved_hashes = {path.name: digest(path) for path in (unit, report)}
        first, second = root / "environment_a", root / "environment_b"
        builder = venv.EnvBuilder(with_pip=True, system_site_packages=False)
        print("SETUP: creating two fresh environments", flush=True)
        builder.create(first)
        builder.create(second)
        python_a, python_b = interpreter(first), interpreter(second)
        tools = {
            "a": run(python_a, work, pip_args("--version")).stdout.strip(),
            "b": run(python_b, work, pip_args("--version")).stdout.strip(),
        }
        run(python_a, work, install_arguments(wheels, requirements))
        run(python_a, work, pip_args("check"))
        first_result = inspect_behavior(python_a, work)
        expected = {
            "versions": {"book1-report-demo": "1.0.0", "book1-unit-demo": "1.0.0"},
            "input": "12.50", "output": ["instrument_units", "12.50"],
        }
        require(first_result == expected, "first result differs from independent expected value")
        print("FIRST INSTALL: pins, hashes, metadata, origin, and behavior passed", flush=True)

        changed = root / "changed_wheels"
        changed.mkdir()
        for artifact in (unit, report):
            shutil.copyfile(artifact, changed / artifact.name)
        changed_report = changed / report.name
        # A ZIP comment changes artifact bytes while keeping a valid wheel archive.
        with ZipFile(changed_report, "a") as archive:
            archive.comment = b"deliberately changed artifact for negative test"
        require(digest(changed_report) != approved_hashes[report.name], "artifact did not change")
        failure = run(python_b, work, install_arguments(changed, requirements), expected_code=1)
        diagnostic = (failure.stdout + failure.stderr).lower()
        require("hash" in diagnostic and "book1" in diagnostic,
                "expected hash rejection was not identified")
        run(python_b, work, ["-I", "-c", (
            "from importlib.util import find_spec; "
            "assert find_spec('book1_report_demo') is None"
        )])
        print("NEGATIVE CHECK: changed artifact rejected against approved hash", flush=True)

        run(python_b, work, install_arguments(wheels, requirements))
        run(python_b, work, pip_args("check"))
        second_result = inspect_behavior(python_b, work)
        require(second_result == expected, "second result differs from expected value")
        require(first_result == second_result, "recreated environments disagree")
        require({path.name: digest(path) for path in (unit, report)} == approved_hashes,
                "approved artifact store changed")
        print("SECOND INSTALL: identical approved artifacts reproduce selected behavior", flush=True)
        evidence = {
            "python": platform.python_version(), "implementation": platform.python_implementation(),
            "platform": platform.platform(), "pip": tools,
            "requirements_sha256": digest(requirements), "wheel_sha256": approved_hashes,
            "unit_source_sha256": hashlib.sha256(UNIT_SOURCE.encode("utf-8")).hexdigest(),
            "report_source_sha256": hashlib.sha256(REPORT_SOURCE.encode("utf-8")).hexdigest(),
            "input_sha256": hashlib.sha256(b"12.50").hexdigest(),
            "result": first_result,
        }
        print(json.dumps(evidence, indent=2, sort_keys=True))
    print("PASS: two local installs verified and temporary resources cleaned up")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

## 5.8.9 Run and Read the Evidence

Windows PowerShell:

```powershell
py -3 reproducibility_lab.py
```

Linux or macOS:

```bash
python3 reproducibility_lab.py
```

Expected stages: SETUP, FIRST INSTALL, NEGATIVE CHECK, SECOND INSTALL, an evidence JSON object, and the final PASS line. The expected hash failure is captured and checked rather than printed as a successful installation.

The script changes only a ZIP comment, so it demonstrates artifact-byte identity separately from code behavior. Pip should reject that wheel even though its distribution/version and executable source remain the same. Do not bypass the check by updating the requirement's hash during investigation.

Both financial results are checked against an independently stated expected value, not merely compared with each other. This prevents two identically wrong results from being the sole acceptance criterion.

## 5.8.10 What This Reproduces

The lab reuses the exact approved wheel files within one run. It does not claim that independently regenerating those fixtures produces identical wheel bytes: archive timestamps and other build details can change artifact hashes.

The printed environment paths and some platform/tool details differ between environments or runs. Compare deliberately selected invariants rather than demanding the entire evidence JSON be byte-identical. A useful real evidence record also identifies the application commit and relevant source/input artifacts; retain those alongside the requirements and approved wheels.

These two environments use one base runtime on one machine. The pure-Python fixture avoids compiled dependency concerns. This is not evidence for equivalent behavior on other operating systems, CPU architectures, Python versions, numerical libraries, or production datasets.

## 5.8.11 Updating Dependencies Deliberately

For an intentional update, select compatible candidate versions in a new environment, obtain reviewed artifacts, regenerate the complete installation specification, and run dependency checks plus meaningful financial regressions. Review changed outputs against expected model behavior before replacing the prior baseline.

Preserve the prior specification and artifacts so the old behavior remains reconstructible. A changed hash should have an explainable cause; it is not a reason by itself to approve a new artifact. Build-system dependencies and platform constraints require their own records when source builds are involved.

## 5.8.12 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| Top-level version same but output changed | Transitive versions, source/data/model policy | Capture complete relevant inputs and rerun regressions |
| Hash mismatch | Artifact bytes and source provenance | Investigate; restore the approved artifact |
| Hash mode rejects a dependency | Incomplete pinned/hash specification | Add the reviewed compatible dependency artifact |
| Fresh install cannot find wheel | Artifact availability and target compatibility | Retain suitable approved artifacts |
| Install succeeds but imported file is local source | Working directory and module origin | Verify installed behavior outside source tree |
| Two evidence files differ | Runtime paths versus meaningful invariants | Compare selected fields with explicit acceptance criteria |
| Wheel rebuild has a different digest | Build metadata/timestamps/toolchain | Distinguish repeatable install from reproducible build |

## 5.8.14 Key Takeaways

Pin compatible versions, identify approved artifact bytes, and verify fresh installed behavior. Preserve the runtime, source, inputs, and financial policies needed to interpret the result.

Repeatability is a scoped claim supported by evidence. Two matching local installations are useful evidence, but they do not establish universal financial or platform equivalence.
