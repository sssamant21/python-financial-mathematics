## 5.3.1 Purpose

The standard library provides general tools for dates, decimal values, files, interchange formats, and testing. Using those tools avoids rebuilding basic infrastructure while leaving financial meaning explicit in your application.

This section surveys useful modules and combines a few in a small schedule-import lab. The program reads synthetic JSON, validates every event, and produces a fresh canonical representation. It demonstrates that successful parsing is only the first step toward valid financial input.

## 5.3.2 Learning Objectives

You should be able to:

1. Distinguish built-ins, standard-library modules, and third-party packages.
2. Select library tools for a concrete financial programming task.
3. Separate JSON syntax from application schema validation.
4. Preserve decimal text without a binary-float intermediate.
5. Validate explicit calendar-date formats.
6. Read UTF-8 files through pathlib and test with temporary files.
7. State what library behavior does not establish about financial correctness.

## 5.3.3 What Is Included?

Built-in names such as len, dict, and sorted are available without an import. Modules such as decimal and json are distributed as part of Python's standard library and are imported when needed. NumPy, pandas, and SciPy are third-party projects, introduced later in this book.

Standard-library availability can depend on the Python distribution, version, and platform. Consult the documentation matching your runtime rather than assuming every module exists in every environment. This lab uses APIs available in Python 3.10 or later and needs no third-party runtime package.

## 5.3.4 A Practical Module Map

| Need | Module | Application responsibility |
|---|---|---|
| Decimal values and controlled arithmetic | decimal | Units, precision, rounding, and finiteness policy |
| Calendar dates and times | datetime | Date format, time zones, settlement and calendar conventions |
| Paths and file access | pathlib | Intended location, encoding, permissions, and overwrite policy |
| JSON interchange | json | Required fields, types, duplicates, and financial validation |
| Delimited records | csv | Column schema, dialect, and numeric parsing |
| Grouping and counts | collections | Identity scope and meaning of counts |
| Iterator tools | itertools | Ordering, exhaustion, and size assumptions |
| Numerical functions | math, statistics | Valid domains, units, and interpretation |
| Automated checks | unittest | Independent expected outcomes and useful failure cases |
| Disposable test resources | tempfile | Resource lifetime and cleanup |

This map identifies candidate tools, not a complete financial platform. A date class does not know exchange holidays; a statistics function does not detect biased input; a JSON decoder does not verify a portfolio schema.

## 5.3.5 Decimal and Date Boundaries

Run the three introductory Python blocks in order in one session.

```python
from decimal import Decimal
from datetime import date

amount = Decimal("12.50")
payment_date = date.fromisoformat("2028-02-29")
assert str(amount) == "12.50"
assert payment_date.isoformat() == "2028-02-29"
```

Constructing Decimal from supplied decimal text avoids first converting through float. Arithmetic still needs a numeric context and rounding policy; this lab performs no amount arithmetic.

The lab accepts exactly YYYY-MM-DD. It checks that spelling before calling fromisoformat because the library may accept additional ISO forms. The date constructor/parser verifies calendar validity; no holiday adjustment or year-fraction calculation is implied.

## 5.3.6 JSON Is a Transport Representation

```python
import json

encoded = json.dumps({"payment_date": payment_date.isoformat(), "amount": str(amount)})
parsed = json.loads(encoded)
assert parsed == {"payment_date": "2028-02-29", "amount": "12.50"}
assert isinstance(parsed["amount"], str)
```

The wire schema uses strings for amounts and dates. Default JSON encoding does not automatically preserve Decimal and date objects as those Python types. Explicit conversion documents the intended representation.

A numeric JSON amount is rejected by the lab even if it looks correct. This is a chosen interchange contract, not a claim that JSON numbers cannot be decoded using a custom Decimal parser. Likewise, a parseable string such as Infinity is not an acceptable financial amount here.

## 5.3.7 Files and Resource Lifetime

```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as directory:
    path = Path(directory) / "sample.json"
    path.write_text(encoded, encoding="utf-8")
    assert json.loads(path.read_text(encoding="utf-8")) == parsed
```

Path constructs the location; read_text and write_text perform I/O. The example uses a disposable directory so it does not overwrite an existing report. File errors are not converted into empty schedules: absent input and an intentionally empty schedule mean different things.

## 5.3.8 Lab Contract — Read a Dated Schedule

Save the complete block below as standard_library_lab.py. It is independent of earlier lab files.

| Item | Rule |
|---|---|
| Wire document | JSON object with exactly schedule_id, currency, events |
| schedule_id and event_id | Exact nonempty unpadded strings |
| currency | USD or EUR, one currency per schedule |
| Perspective | Investor: negative paid, positive received; fixed by this lab contract |
| events | JSON array of objects with exactly event_id, payment_date, amount |
| Event identity | Unique across the supplied schedule |
| payment_date | String spelled YYYY-MM-DD and a valid calendar date |
| amount | Nonempty unpadded Decimal-parsable string, finite; signed and zero accepted |
| Duplicate JSON member names | Rejected at every object level before schema validation |
| Nonstandard NaN/Infinity JSON tokens | Rejected before schema validation |
| Canonical result | Fresh wrapper, date objects, Decimal amounts, events in source order |
| Empty events | Accepted; schedule metadata preserved |
| File read | Explicit UTF-8; file/encoding exceptions propagate |

Amount text deliberately follows Decimal's accepted syntax after the padding check. This is not a fixed two-decimal currency format and may include exponents. A stricter lexical policy is an exercise. No totals, discounting, payment generation, or conversion is performed.

The JSON parser's default handling of repeated member names can conceal earlier fields. The object_pairs_hook below rejects collisions, which is distinct from rejecting repeated event IDs across otherwise separate objects.

## 5.3.9 Complete Runnable Lab

```python
"""Use standard-library parsing and files with an explicit schedule contract."""

from datetime import date
from decimal import Decimal, InvalidOperation
from pathlib import Path
import json
import re
from tempfile import TemporaryDirectory
import unittest


def unique_object(pairs: list[tuple[str, object]]) -> dict[str, object]:
    result: dict[str, object] = {}
    for key, value in pairs:
        if key in result:
            raise ValueError(f"duplicate JSON member: {key}")
        result[key] = value
    return result


def reject_constant(token: str) -> object:
    raise ValueError(f"nonstandard JSON constant: {token}")


def checked_text(value: object, label: str) -> str:
    if type(value) is not str:
        raise TypeError(f"{label} must be a string")
    if not value or value.strip() != value:
        raise ValueError(f"{label} must be nonempty and unpadded")
    return value


def parse_schedule(payload: object) -> dict[str, object]:
    """Parse a complete wire schedule; retain signed finite amounts and order.

    Raises JSONDecodeError for malformed JSON, TypeError for wrong schema
    types, and ValueError for schema/domain/identity violations.
    """
    if type(payload) is not str:
        raise TypeError("payload must be a string")
    decoded: object = json.loads(
        payload, object_pairs_hook=unique_object, parse_constant=reject_constant,
    )
    if not isinstance(decoded, dict):
        raise TypeError("schedule must be an object")
    if set(decoded) != {"schedule_id", "currency", "events"}:
        raise ValueError("schedule has incorrect fields")
    schedule_id = checked_text(decoded["schedule_id"], "schedule_id")
    currency = checked_text(decoded["currency"], "currency")
    if currency not in {"USD", "EUR"}:
        raise ValueError("currency must be USD or EUR")
    source_events = decoded["events"]
    if not isinstance(source_events, list):
        raise TypeError("events must be an array")
    seen: set[str] = set()
    events: list[dict[str, object]] = []
    for row in source_events:
        if not isinstance(row, dict):
            raise TypeError("event must be an object")
        if set(row) != {"event_id", "payment_date", "amount"}:
            raise ValueError("event has incorrect fields")
        event_id = checked_text(row["event_id"], "event_id")
        date_text = checked_text(row["payment_date"], "payment_date")
        if re.fullmatch(r"[0-9]{4}-[0-9]{2}-[0-9]{2}", date_text) is None:
            raise ValueError("payment_date must use YYYY-MM-DD")
        payment_date = date.fromisoformat(date_text)
        amount_text = checked_text(row["amount"], "amount")
        try:
            amount = Decimal(amount_text)
        except InvalidOperation as exc:
            raise ValueError("amount is not valid Decimal text") from exc
        if not amount.is_finite():
            raise ValueError("amount must be finite")
        if event_id in seen:
            raise ValueError(f"duplicate event_id: {event_id}")
        seen.add(event_id)
        events.append({"event_id": event_id, "payment_date": payment_date, "amount": amount})
    return {"schedule_id": schedule_id, "currency": currency,
            "perspective": "investor", "events": events}


def read_schedule(path: Path) -> dict[str, object]:
    """Read UTF-8 JSON and apply the same schema; preserve file errors."""
    return parse_schedule(path.read_text(encoding="utf-8"))


def wire_schedule() -> dict[str, object]:
    return {
        "schedule_id": "SCH-01", "currency": "USD", "events": [
            {"event_id": "E0", "payment_date": "2027-01-15", "amount": "-1000"},
            {"event_id": "E1", "payment_date": "2028-02-29", "amount": "0"},
            {"event_id": "E2", "payment_date": "2028-02-29", "amount": "1040.00"},
        ],
    }


class StandardLibraryTests(unittest.TestCase):
    def test_exact_canonical_values(self) -> None:
        result = parse_schedule(json.dumps(wire_schedule()))
        self.assertEqual(result, {
            "schedule_id": "SCH-01", "currency": "USD", "perspective": "investor", "events": [
                {"event_id": "E0", "payment_date": date(2027, 1, 15), "amount": Decimal("-1000")},
                {"event_id": "E1", "payment_date": date(2028, 2, 29), "amount": Decimal("0")},
                {"event_id": "E2", "payment_date": date(2028, 2, 29), "amount": Decimal("1040.00")},
            ],
        })
        rows = result["events"]
        if not isinstance(rows, list):
            self.fail("events must be a list")
        self.assertEqual(str(rows[2]["amount"]), "1040.00")

    def test_empty_and_independent_calls(self) -> None:
        source = wire_schedule()
        source["events"] = []
        self.assertEqual(parse_schedule(json.dumps(source)), {
            "schedule_id": "SCH-01", "currency": "USD", "perspective": "investor", "events": []
        })
        first = parse_schedule(json.dumps(wire_schedule()))
        first["events"] = []
        second = parse_schedule(json.dumps(wire_schedule()))
        self.assertNotEqual(first, second)
        self.assertEqual(wire_schedule()["schedule_id"], "SCH-01")

    def test_duplicate_json_members_and_constants(self) -> None:
        for payload in (
            '{"schedule_id":"A","schedule_id":"B","currency":"USD","events":[]}',
            '{"schedule_id":"A","currency":"USD","events":[{"event_id":"E","event_id":"F"}]}',
            '{"schedule_id":"A","currency":"USD","events":NaN}',
            '{"schedule_id":"A","currency":"USD","events":Infinity}',
        ):
            with self.subTest(payload=payload):
                with self.assertRaises(ValueError):
                    parse_schedule(payload)

    def test_date_spelling_and_calendar(self) -> None:
        for date_text in ("20270228", "2027-2-28", "2027-02-29", "2027-01-15T00:00:00", " 2027-01-15"):
            payload = {"schedule_id": "A", "currency": "USD", "events": [
                {"event_id": "E", "payment_date": date_text, "amount": "1"}
            ]}
            with self.subTest(date_text=date_text):
                with self.assertRaises(ValueError):
                    parse_schedule(json.dumps(payload))

    def test_amount_text_and_domain(self) -> None:
        for amount in ("NaN", "sNaN", "Infinity", "-Infinity", "bad", "", " 1"):
            payload = {"schedule_id": "A", "currency": "USD", "events": [
                {"event_id": "E", "payment_date": "2027-01-15", "amount": amount}
            ]}
            with self.subTest(amount=amount):
                with self.assertRaises(ValueError):
                    parse_schedule(json.dumps(payload))
        for invalid_amount in (None, True, 1, 1.5):
            payload = {"schedule_id": "A", "currency": "USD", "events": [
                {"event_id": "E", "payment_date": "2027-01-15", "amount": invalid_amount}
            ]}
            with self.assertRaises(TypeError):
                parse_schedule(json.dumps(payload))

    def test_schema_and_json_errors(self) -> None:
        with self.assertRaises(TypeError):
            parse_schedule(b"{}")
        with self.assertRaises(json.JSONDecodeError):
            parse_schedule("{")
        with self.assertRaises(TypeError):
            parse_schedule("[]")
        with self.assertRaises(ValueError):
            parse_schedule("{}")
        for currency in ("GBP", "usd", " USD"):
            with self.assertRaises(ValueError):
                parse_schedule(json.dumps({"schedule_id": "A", "currency": currency, "events": []}))
        with self.assertRaises(ValueError):
            parse_schedule('{"schedule_id":"A","currency":"USD","events":[{}]}')

    def test_duplicate_event_ids_and_invalid_later_event(self) -> None:
        for final in (
            {"event_id": "E0", "payment_date": "2030-01-01", "amount": "1"},
            {"event_id": "BAD", "payment_date": "2030-01-01", "amount": "NaN"},
        ):
            with self.assertRaises(ValueError):
                parse_schedule(json.dumps({"schedule_id": "A", "currency": "USD", "events": [
                    {"event_id": "E0", "payment_date": "2027-01-01", "amount": "1"}, final,
                ]}))

    def test_utf8_file_and_missing_file(self) -> None:
        with TemporaryDirectory() as directory:
            path = Path(directory) / "schedule.json"
            source = wire_schedule()
            source["schedule_id"] = "SCH-é"
            path.write_text(json.dumps(source, ensure_ascii=False), encoding="utf-8")
            self.assertEqual(read_schedule(path)["schedule_id"], "SCH-é")
            with self.assertRaises(FileNotFoundError):
                read_schedule(Path(directory) / "missing.json")

    def test_file_decoding_error(self) -> None:
        with TemporaryDirectory() as directory:
            path = Path(directory) / "invalid.json"
            path.write_bytes(b"\xff")
            with self.assertRaises(UnicodeDecodeError):
                read_schedule(path)


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

Expected result: nine test methods pass and the runner reports `OK`. Subtests cover additional invalid inputs. Temporary files are created in disposable directories and cleaned up when their context exits.

The canonical result preserves a negative initial event, an explicit zero event, and a positive event. Two events share the leap-day date and remain distinct. The source event order is retained, rather than silently sorted or netted.

JSONDecodeError is a ValueError subclass, so an application may choose to catch it separately when distinguishing malformed syntax from schema problems. This lab deliberately leaves file and encoding failures visible to the caller.

## 5.3.11 Boundaries and Next Steps

This is a small local-input demonstration. It does not set payload size, nesting, or numeric-token length limits for an external ingestion service. Resource limits and operational error handling must be specified when adapting it to that setting.

Likewise, a valid date and finite amount do not establish that a payment was authorized, settled, complete, or correctly valued. Keep source provenance and financial policies alongside the validated representation.

The standard library can support much of a small application's infrastructure. The next section organizes reusable financial utilities; later chapters introduce specialized analytical libraries when their data models and operations are needed.

## 5.3.12 Troubleshooting

| Symptom | Cause to inspect | Correction |
|---|---|---|
| Decimal/date cannot be JSON encoded | Unsupported default wire types | Convert fields under an explicit wire schema |
| JSON parses but data is invalid | Syntax confused with schema | Validate fields, types, identity, and domain |
| Earlier field disappears | Repeated JSON member name | Reject duplicate members during decoding |
| Amount acquires float artifacts | Conversion passed through float | Parse decimal text directly |
| Invalid calendar date rejected | Impossible day/month combination | Correct the source rather than coercing the date |
| Missing file becomes empty report | Broad error suppression | Preserve the I/O failure |
| Unexpected imported library | Local filename shadows dependency | Inspect module origin and rename the collision |

## 5.3.14 Key Takeaways

Use standard-library tools for general parsing, dates, decimal representation, paths, and tests. Keep financial schema and policy decisions explicit around those tools.

Parsing, validation, and file handling have different failure modes. Preserve those distinctions and test the boundaries before adding financial calculations.
