## 5.5.1 Purpose

A package organizes related modules under one import namespace. It gives a growing application room for separate validation, transformations, and an entry point without placing every function in one file.

This section builds a regular local import package named finance_lab. It captures validated holdings and reports active identifiers. The financial contract remains small so the lab can focus on package layout, absolute and relative imports, the public facade, and package execution.

## 5.5.2 Learning Objectives

You should be able to:

1. Distinguish a module, an import package, and an installable distribution.
2. Build a regular package using __init__.py.
3. Use explicit relative imports inside a package.
4. Expose a small public API without wildcard imports.
5. Launch a package with -m and __main__.py.
6. Diagnose launch-directory and missing-parent-package errors.
7. Test package behavior and the resolved package location.

## 5.5.3 Import Package Versus Distribution

An import package is a namespace containing modules and possibly subpackages. For this regular source package, the finance_lab directory contains __init__.py and sibling modules. Python also supports namespace packages without that file; this lab deliberately uses the regular form.

A distribution is software prepared for installation. Its installation name need not match its import-package name, and one distribution can provide several import packages. Creating this directory does not build a wheel, register a distribution, or install anything into an environment.

The lab runs directly from its parent directory. Dependency installation follows in Section 5.6, environments in 5.7, and a reusable package project in 5.12.

## 5.5.4 Package Layout

Create these five files under a new working directory. The table gives paths relative to that directory; use the exact names and underscores.

| Relative path | Responsibility |
|---|---|
| finance_lab/__init__.py | Small public facade |
| finance_lab/holdings.py | Validation and immutable capture |
| finance_lab/views.py | Active-ID transformation |
| finance_lab/__main__.py | Guarded executable demonstration |
| test_finance_lab.py | Public API and process tests |

The test file sits beside the finance_lab directory, not inside it. Open the terminal in that parent working directory. Do not create a finance_lab.py file alongside the directory; competing names can resolve to unexpected code.

## 5.5.5 Absolute and Relative Imports

Outside the package, `from finance_lab import active_ids` uses the documented facade. `from finance_lab.holdings import capture_holdings` names the implementation module explicitly.

Inside views.py, `from .holdings import capture_holdings` means the sibling holdings module in the current package. The dot describes package context, not a relative filesystem path from the current working directory. Package imports are not paths containing slashes or .py suffixes.

Run the application with `python -m finance_lab` from the package's parent directory. Running finance_lab/__main__.py directly as a file does not supply the same package context for its explicit relative import. Do not repair that difference by inserting arbitrary paths into sys.path; use the documented package launch.

## 5.5.6 Initialization and Public API

Importing a regular package initializes its __init__.py. Keep that file small: the lab imports two functions for convenient public access and declares their names in __all__. That declaration documents wildcard export selection; it does not block access to other modules or make functions private.

Submodules are not all automatically loaded simply because their files exist. This facade imports the modules needed for its public functions. Importing the facade also initializes those modules, so they must avoid application work at top level.

Dependencies flow from facade to implementation, and from views to holdings. The holdings module does not import the facade back. This keeps the dependency relationship straightforward and avoids relying on partially initialized facade names.

## 5.5.7 Financial Contract

| Item | Rule |
|---|---|
| Input | List of dictionaries with exactly security_id and quantity |
| security_id | Exact nonempty unpadded str; unique in input |
| quantity | Exact finite nonnegative Decimal instrument units |
| capture_holdings | Tuple of scalar pairs in source order, including zero |
| active_ids | Tuple of IDs with quantity > 0, in source order |
| Empty input | Empty tuple |
| Failure | TypeError for wrong types; ValueError for schema/domain/duplicate violations |
| Ownership | Source records unchanged and not retained |
| Import | No application output |

This remains a single aggregate-holdings component, without prices, currency conversion, lot identity, or valuation. All rows are validated before active selection. The package name does not strengthen the financial model or provide a security boundary.

## 5.5.8 File 1 — finance_lab/holdings.py

```python
"""Validate and capture aggregate instrument quantities."""

from decimal import Decimal

Holding = tuple[str, Decimal]
Snapshot = tuple[Holding, ...]


def capture_holdings(value: object) -> Snapshot:
    """Return ordered immutable scalar pairs under a nonnegative-units policy.

    Validate every row, reject duplicate IDs, preserve valid zero holdings.
    No source mutation, arithmetic, price lookup, or valuation is performed.
    """
    if not isinstance(value, list):
        raise TypeError("holdings must be a list")
    rows: list[Holding] = []
    seen: set[str] = set()
    for index, row in enumerate(value):
        if not isinstance(row, dict):
            raise TypeError(f"holding {index} must be a dictionary")
        if set(row) != {"security_id", "quantity"}:
            raise ValueError(f"holding {index} has incorrect fields")
        sid = row["security_id"]
        quantity = row["quantity"]
        if type(sid) is not str:
            raise TypeError("security_id must be an exact str")
        if not sid or sid.strip() != sid:
            raise ValueError("security_id must be nonempty and unpadded")
        if type(quantity) is not Decimal:
            raise TypeError("quantity must be an exact Decimal")
        if not quantity.is_finite() or quantity < 0:
            raise ValueError("quantity must be finite and nonnegative")
        if sid in seen:
            raise ValueError(f"duplicate security_id: {sid}")
        seen.add(sid)
        rows.append((sid, quantity))
    return tuple(rows)
```

## 5.5.9 File 2 — finance_lab/views.py

```python
"""Derive holdings views using the sibling validation module."""

from .holdings import capture_holdings


def active_ids(value: object) -> tuple[str, ...]:
    """Return strictly positive holding IDs after full validation."""
    snapshot = capture_holdings(value)
    return tuple(sid for sid, quantity in snapshot if quantity > 0)
```

The sibling import creates a dependency on the implementation's contract. The module does not duplicate its validation or import a runner to obtain sample data.

## 5.5.10 File 3 — finance_lab/__init__.py

```python
"""Public API for the local finance_lab teaching package."""

from .holdings import capture_holdings as capture_holdings
from .views import active_ids as active_ids

__all__ = ["capture_holdings", "active_ids"]
```

The explicit re-exports also communicate intent to static type checkers. Consumers can use the facade while implementation helpers and module boundaries evolve, provided the public behavior remains compatible.

## 5.5.11 File 4 — finance_lab/__main__.py

```python
"""Entry point for python -m finance_lab."""

from decimal import Decimal
from .views import active_ids


def main() -> int:
    source = [
        {"security_id": "SEC-B", "quantity": Decimal("0")},
        {"security_id": "SEC-A", "quantity": Decimal("12.5")},
        {"security_id": "SEC-C", "quantity": Decimal("3")},
    ]
    print("Package active IDs: " + ", ".join(active_ids(source)))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

This __main__.py supplies package execution behavior. It is separate from __init__.py, which initializes the import namespace. The guard also prevents explicit normal import of finance_lab.__main__ from running the demonstration.

## 5.5.12 File 5 — test_finance_lab.py

```python
"""Test public financial contracts and regular-package launch behavior."""

from decimal import Decimal
from pathlib import Path
import subprocess
import sys
import unittest

from finance_lab import active_ids, capture_holdings

LAB_DIR = Path(__file__).resolve().parent


def fixture() -> list[dict[str, object]]:
    return [
        {"security_id": "SEC-B", "quantity": Decimal("0")},
        {"security_id": "SEC-A", "quantity": Decimal("12.5")},
        {"security_id": "SEC-C", "quantity": Decimal("3")},
    ]


def launch(*arguments: str) -> subprocess.CompletedProcess[str]:
    return subprocess.run(
        [sys.executable, *arguments], cwd=LAB_DIR, text=True,
        capture_output=True, check=False, timeout=10,
    )


class PackageTests(unittest.TestCase):
    def test_public_values_and_empty(self) -> None:
        self.assertEqual(capture_holdings(fixture()), (
            ("SEC-B", Decimal("0")), ("SEC-A", Decimal("12.5")), ("SEC-C", Decimal("3"))
        ))
        self.assertEqual(active_ids(fixture()), ("SEC-A", "SEC-C"))
        self.assertEqual(capture_holdings([]), ())
        self.assertEqual(active_ids([]), ())

    def test_source_ownership(self) -> None:
        source = fixture()
        snapshot = capture_holdings(source)
        self.assertEqual(source, fixture())
        source[0]["quantity"] = Decimal("99")
        source.append({"security_id": "NEW", "quantity": Decimal("1")})
        self.assertEqual(snapshot[0], ("SEC-B", Decimal("0")))
        self.assertEqual(len(snapshot), 3)

    def test_schema_and_amounts(self) -> None:
        with self.assertRaises(TypeError):
            capture_holdings(())
        with self.assertRaises(ValueError):
            capture_holdings([{}])
        with self.assertRaises(TypeError):
            capture_holdings([None])
        for quantity in (None, True, 1, 1.5, "1"):
            with self.subTest(quantity=quantity):
                with self.assertRaises(TypeError):
                    active_ids([{"security_id": "A", "quantity": quantity}])
        for value in ("NaN", "sNaN", "Infinity", "-Infinity", "-1"):
            with self.assertRaises(ValueError):
                capture_holdings([{"security_id": "A", "quantity": Decimal(value)}])
        for sid in ("", " A", "A "):
            with self.assertRaises(ValueError):
                capture_holdings([{"security_id": sid, "quantity": Decimal("0")}])

    def test_duplicate_and_excluded_invalid(self) -> None:
        with self.assertRaises(ValueError):
            active_ids([
                {"security_id": "A", "quantity": Decimal("0")},
                {"security_id": "A", "quantity": Decimal("1")},
            ])
        source = fixture() + [{"security_id": "BAD", "quantity": "invalid"}]
        before = [dict(row) for row in source]
        with self.assertRaises(TypeError):
            active_ids(source)
        self.assertEqual(source, before)

    def test_facade_and_relative_import_identity(self) -> None:
        result = launch("-c", (
            "import finance_lab\n"
            "from finance_lab import holdings, views\n"
            "assert finance_lab.capture_holdings is holdings.capture_holdings\n"
            "assert finance_lab.active_ids is views.active_ids\n"
            "assert views.capture_holdings is holdings.capture_holdings\n"
            "assert finance_lab.__all__ == ['capture_holdings', 'active_ids']\n"
        ))
        self.assertEqual(result.returncode, 0, result.stderr)
        self.assertEqual(result.stdout, "")
        self.assertEqual(result.stderr, "")

    def test_quiet_import_and_origin(self) -> None:
        result = launch("-c", (
            "import finance_lab, finance_lab.__main__\n"
            "from pathlib import Path\n"
            "assert Path(finance_lab.__file__).resolve() == Path('finance_lab/__init__.py').resolve()\n"
            "assert finance_lab.__package__ == 'finance_lab'\n"
        ))
        self.assertEqual(result.returncode, 0, result.stderr)
        self.assertEqual(result.stdout, "")
        self.assertEqual(result.stderr, "")

    def test_package_launch(self) -> None:
        result = launch("-m", "finance_lab")
        self.assertEqual(result.returncode, 0, result.stderr)
        self.assertEqual(result.stdout, "Package active IDs: SEC-A, SEC-C\n")
        self.assertEqual(result.stderr, "")

    def test_direct_file_has_no_package_context(self) -> None:
        result = launch("finance_lab/__main__.py")
        self.assertNotEqual(result.returncode, 0)
        self.assertEqual(result.stdout, "")
        self.assertIn("ImportError", result.stderr)
        self.assertIn("relative import", result.stderr)


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

The final test is an intentional failing child launch, not a failure of the suite. It checks the relative-import error so an unrelated crash cannot satisfy the test merely by returning a nonzero exit code.

Child-process strings execute namespace inspections at runtime. Static checking of this file does not type-check those strings; the suite verifies their execution and output. Financial validation tests call the public facade normally.

## 5.5.14 Review the Boundaries

The public facade is an API choice, not a guarantee that implementation paths never change or cannot be imported. Keep facade exports few and avoid making package import initialize applications, load portfolios, or perform expensive work unexpectedly.

Adding a folder alone does not create versioning, dependency isolation, test discovery, or distribution metadata. Those require deliberate project decisions. The current package is a self-contained teaching layout, not a published distribution.

The quantity functions repeat an established contract to keep this section runnable independently. A maintained application should choose one authoritative implementation and refactor its callers rather than retain several drifting copies.

## 5.5.15 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| No module named finance_lab | Parent directory and interpreter | Run the stated commands from the package parent |
| Relative import has no known parent | Submodule launched as a plain file | Use python -m finance_lab |
| Facade function missing | __init__.py exports and actual package origin | Add explicit re-export or correct resolved source |
| Unexpected initialization output | __init__.py or dependency top-level calls | Keep import initialization small and quiet |
| Partially initialized module | Circular dependency through facade | Import implementation dependencies directly within package |
| Wrong package loaded | Name collision or stale interpreter | Inspect __file__, correct layout, restart |
| pip cannot install this directory | No distribution configuration | Follow later packaging workflow; local import is separate |

## 5.5.17 Key Takeaways

Packages organize modules under an import namespace. Use explicit dependency direction, a small facade, and package-aware launches so callers do not depend on accidental working-directory behavior.

A runnable local package is a foundation for distribution and environment management. It does not by itself install, version, or validate a financial application.
