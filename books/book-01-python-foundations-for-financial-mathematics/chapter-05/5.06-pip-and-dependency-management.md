## 5.6.1 Purpose

A financial program depends on more than its own source. It may require an installed distribution, a compatible version of another distribution, and an interpreter that can import them. Installation success and financial correctness are separate checks.

This section introduces interpreter-specific pip commands, direct and transitive dependencies, requirements and constraints, and installed-environment inspection. Its runnable lab creates two tiny local wheel fixtures, installs one with its dependency, deliberately breaks that dependency, detects the failure, and repairs the environment. All package changes occur in a temporary virtual environment.

## 5.6.2 Learning Objectives

You should be able to:

1. Invoke pip through the intended interpreter.
2. Distinguish distribution names from import names.
3. Explain direct, transitive, runtime, and development dependencies.
4. Distinguish installation requirements, constraints, and installed inventories.
5. Inspect versions, locations, and declared dependency compatibility.
6. Test installed code independently of the source working directory.
7. Diagnose and repair a missing dependency in an isolated lab.

## 5.6.3 Bind pip to an Interpreter

Use `python -m pip` with the interpreter that will run the application. A bare pip executable can belong to a different Python installation. Inspect `python -m pip --version` and the interpreter's sys.executable when investigating a mismatch.

The lab invokes its temporary environment's interpreter by full path and never activates it. Activation mainly changes shell command lookup; it is not required when an interpreter path is explicit. Section 5.7 develops environment management in detail.

Standard-library modules such as decimal do not need separate pip installation. An import name can differ from a distribution name, so do not guess an installation requirement solely from an import statement.

## 5.6.4 Name the Dependency Relationship

| Kind | Meaning | Example in the lab |
|---|---|---|
| Direct dependency | Explicitly requested by the caller/project | book1-report-demo |
| Transitive dependency | Required by a requested distribution | book1-unit-demo, required by report demo |
| Runtime dependency | Needed for application behavior | Report's imported quantity validator |
| Development dependency | Used for development checks | A separate type checker, outside this lab runtime |

The example distribution names contain hyphens; their import packages use underscores. Version 1.0.0 is a synthetic fixture version, not a recommendation about any external package.

Pip resolves declared requirements against available candidates. Compatible metadata does not establish that a package is suitable, trustworthy, or financially correct. Application tests must exercise the chosen versions and relevant input contracts.

## 5.6.5 Requirements, Constraints, and Inventories

A requirements file lists items to install. A constraints file limits eligible versions of named distributions but does not request their installation by itself. Runtime dependency metadata belongs to the distribution so downstream installations can discover it.

The lab creates requirements.txt containing book1-report-demo==1.0.0 and installs it with -r. Its wheel metadata declares book1-unit-demo==1.0.0, which pip finds in the local wheel directory without an index.

`pip list` and `pip show` inspect installed distributions. `pip freeze` produces a requirements-format inventory of installed state; it is not by itself a complete cross-platform lock or record of all reproducibility inputs. Version pinning and repeatability are developed in Section 5.8.

## 5.6.6 What Checks Establish

`pip check` checks installed distributions against their declared dependency requirements. A successful check does not execute the financial API. Conversely, importing a package successfully does not prove all declared requirements are compatible.

The lab verifies both metadata and behavior. Its quantity validator accepts exact finite nonnegative Decimal units, including zero and fractions; it rejects other types and invalid domains. The report helper returns a label/value pair and performs no amount arithmetic or valuation.

A missing module can be caused by the wrong interpreter, a missing distribution, an import-name mismatch, or shadowing by a local file. Inspect the actual imported path and distribution metadata before reinstalling indiscriminately.

## 5.6.7 Installation Scope and Sources

Use a dedicated environment for application dependencies. Do not repair this exercise by modifying system Python or bypassing an externally managed environment restriction. If the distribution lacks venv or ensurepip support, obtain those components using that distribution's supported setup process.

For real projects, choose an approved package source and review exact distribution identities and versions. Installing source distributions can execute build tooling. This exercise avoids downloads and build backends: it generates original local pure-Python wheel fixtures, then uses --no-index and --find-links for every install.

The fixture generator is included only to make pip behavior reproducible offline. It is not a replacement for a maintained build backend or the package-project workflow in Section 5.12. Do not publish these fixture wheels to an index.

## 5.6.8 Lab Plan

Save the complete next block as pip_dependency_lab.py in an ordinary working directory. Use Python 3.10 or later with venv/ensurepip available. No externally downloaded package is required.

| Stage | Verification |
|---|---|
| Environment | New temporary interpreter; pip is available |
| Local install | Requirement resolves both original wheels without index access |
| Metadata | Both installed versions are 1.0.0 |
| Installed behavior | Valid and invalid Decimal cases pass outside source directories |
| Inventory | pip list, show, freeze expose the installed fixtures |
| Broken state | Removing the required unit distribution makes pip check fail |
| Repair | Reinstalling from requirements restores the dependency and behavior |
| Cleanup | Explicitly uninstall both fixtures, then temporary-directory cleanup |

Commands in the script are passed as argument lists without shell execution. It prints stage results; any unexpected return code or unmet assertion stops the lab. The expected dependency failure is checked for the missing distribution's name so an unrelated pip failure cannot pass that stage.

## 5.6.9 Complete Runnable Lab

```python
"""Offline pip installation, dependency failure, and repair in a temp venv."""

import base64
import csv
import hashlib
import io
import json
import os
from pathlib import Path
import subprocess
from tempfile import TemporaryDirectory
import textwrap
import venv
from zipfile import ZipFile, ZIP_DEFLATED

UNIT_SOURCE = '''
from decimal import Decimal


def checked_quantity(value: object) -> Decimal:
    if type(value) is not Decimal:
        raise TypeError("quantity must be an exact Decimal")
    if not value.is_finite() or value < 0:
        raise ValueError("quantity must be finite and nonnegative")
    return value
'''

REPORT_SOURCE = '''
from book1_unit_demo import checked_quantity


def labeled_quantity(value: object) -> tuple[str, object]:
    return ("instrument_units", checked_quantity(value))
'''

BEHAVIOR_CHECK = '''
from decimal import Decimal
from importlib.metadata import version
from pathlib import Path
import sys
import book1_report_demo

assert version("book1-report-demo") == "1.0.0"
assert version("book1-unit-demo") == "1.0.0"
assert Path(book1_report_demo.__file__).resolve().is_relative_to(Path(sys.prefix).resolve())
for value in (Decimal("0"), Decimal("12.5")):
    assert book1_report_demo.labeled_quantity(value) == ("instrument_units", value)
for bad in (None, True, 1, 1.5, "1"):
    try:
        book1_report_demo.labeled_quantity(bad)
    except TypeError:
        pass
    else:
        raise AssertionError("invalid type accepted")
for token in ("NaN", "sNaN", "Infinity", "-Infinity", "-1"):
    try:
        book1_report_demo.labeled_quantity(Decimal(token))
    except ValueError:
        pass
    else:
        raise AssertionError("invalid domain accepted")
print("installed behavior passed")
'''


def require(condition: bool, message: str) -> None:
    if not condition:
        raise AssertionError(message)


def fixture_wheel(
    directory: Path, distribution: str, import_name: str,
    source: str, dependency: str | None = None,
) -> Path:
    """Create a narrow pure-Python wheel fixture, with hashes in RECORD."""
    stem = distribution.replace("-", "_")
    info = f"{stem}-1.0.0.dist-info"
    metadata = (
        f"Metadata-Version: 2.1\nName: {distribution}\nVersion: 1.0.0\n"
        "Requires-Python: >=3.10\n"
    )
    if dependency is not None:
        metadata += f"Requires-Dist: {dependency}\n"
    metadata += "\nOriginal offline teaching fixture.\n"
    files = {
        f"{import_name}/__init__.py": textwrap.dedent(source).encode("utf-8"),
        f"{info}/METADATA": metadata.encode("utf-8"),
        f"{info}/WHEEL": (
            "Wheel-Version: 1.0\nGenerator: book1-local-fixture\n"
            "Root-Is-Purelib: true\nTag: py3-none-any\n"
        ).encode("utf-8"),
    }
    record = io.StringIO(newline="")
    writer = csv.writer(record, lineterminator="\n")
    for name, data in files.items():
        digest = base64.urlsafe_b64encode(hashlib.sha256(data).digest()).rstrip(b"=").decode("ascii")
        writer.writerow([name, "sha256=" + digest, str(len(data))])
    writer.writerow([f"{info}/RECORD", "", ""])
    files[f"{info}/RECORD"] = record.getvalue().encode("utf-8")
    wheel = directory / f"{stem}-1.0.0-py3-none-any.whl"
    with ZipFile(wheel, "w", compression=ZIP_DEFLATED) as archive:
        for name, data in files.items():
            archive.writestr(name, data)
    return wheel


def run(
    python: Path, cwd: Path, arguments: list[str], *, expected_code: int = 0,
) -> subprocess.CompletedProcess[str]:
    # Isolate child tools from inherited pip options and Python path overrides.
    child_env = {
        key: value for key, value in os.environ.items()
        if not key.startswith("PIP_") and key not in {"PYTHONPATH", "PYTHONHOME"}
    }
    child_env["PIP_CONFIG_FILE"] = os.devnull
    result = subprocess.run(
        [str(python), *arguments], cwd=cwd, env=child_env,
        capture_output=True, text=True, check=False, timeout=60,
    )
    require(result.returncode == expected_code,
            f"Unexpected exit {result.returncode} for {arguments}:\n{result.stdout}\n{result.stderr}")
    return result


def pip_args(*arguments: str) -> list[str]:
    return ["-m", "pip", "--isolated", "--disable-pip-version-check", *arguments]


def main() -> int:
    with TemporaryDirectory(prefix="book1-pip56-") as directory:
        root = Path(directory)
        wheels = root / "wheels"
        wheels.mkdir()
        work = root / "work"
        work.mkdir()
        environment = root / "environment"
        venv.EnvBuilder(with_pip=True).create(environment)
        python = environment / ("Scripts/python.exe" if os.name == "nt" else "bin/python")
        result = run(python, work, pip_args("--version"))
        print("ENVIRONMENT: " + result.stdout.strip())
        fixture_wheel(wheels, "book1-unit-demo", "book1_unit_demo", UNIT_SOURCE)
        fixture_wheel(wheels, "book1-report-demo", "book1_report_demo", REPORT_SOURCE,
                      "book1-unit-demo==1.0.0")
        requirements = root / "requirements.txt"
        requirements.write_text("book1-report-demo==1.0.0\n", encoding="utf-8")
        install = pip_args("install", "--no-index", "--find-links", str(wheels),
                           "-r", str(requirements))
        run(python, work, install)
        run(python, work, pip_args("check"))
        result = run(python, work, ["-c", textwrap.dedent(BEHAVIOR_CHECK)])
        require(result.stdout.strip() == "installed behavior passed", "behavior output mismatch")
        print("INSTALL: dependency resolution, metadata, origin, and behavior passed")

        inventory = json.loads(run(python, work, pip_args("list", "--format=json")).stdout)
        versions = {row["name"].lower(): row["version"] for row in inventory}
        require(versions.get("book1-report-demo") == "1.0.0", "report missing from list")
        require(versions.get("book1-unit-demo") == "1.0.0", "unit dependency missing from list")
        shown = run(python, work, pip_args("show", "book1-report-demo")).stdout.lower()
        require("book1-unit-demo" in shown, "show did not expose dependency")
        frozen = run(python, work, pip_args("freeze")).stdout.lower().splitlines()
        require("book1-report-demo==1.0.0" in frozen, "report missing from freeze")
        require("book1-unit-demo==1.0.0" in frozen, "unit dependency missing from freeze")
        print("INVENTORY: list, show, and freeze passed")

        run(python, work, pip_args("uninstall", "-y", "book1-unit-demo"))
        broken = run(python, work, pip_args("check"), expected_code=1)
        require("book1-unit-demo" in (broken.stdout + broken.stderr).lower(),
                "failure did not identify the missing dependency")
        print("BROKEN STATE: expected pip check failure detected")

        run(python, work, install)
        run(python, work, pip_args("check"))
        run(python, work, ["-c", textwrap.dedent(BEHAVIOR_CHECK)])
        print("REPAIR: requirements reinstall and installed behavior passed")
        run(python, work, pip_args("uninstall", "-y", "book1-report-demo", "book1-unit-demo"))
        run(python, work, pip_args("check"))
        run(python, work, ["-c", (
            "from importlib.util import find_spec; "
            "assert find_spec('book1_report_demo') is None; "
            "assert find_spec('book1_unit_demo') is None"
        )])
        print("CLEANUP: both fixture distributions removed")
    print("PASS: temporary environment cleaned up")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

Windows PowerShell:

```powershell
py -3 pip_dependency_lab.py
```

Linux or macOS:

```bash

```

The run may take longer than previous in-memory tests because it creates an environment and launches pip several times. Expected stage labels are ENVIRONMENT, INSTALL, INVENTORY, BROKEN STATE, REPAIR, CLEANUP, and the final PASS line. The pip version/path in ENVIRONMENT depends on the interpreter's bundled environment tooling.

The missing-dependency stage deliberately uninstalls a distribution required by the report fixture. Pip uninstall does not automatically repair downstream dependents. A nonzero pip check result at that stage is expected and verified. Unexpected command failures stop execution and include captured output.

The behavior check imports from a separate empty working directory and verifies the package resides within the temporary interpreter's prefix. Source files are stored only inside wheel archives, so the check cannot pass by importing a sibling source directory accidentally.

## 5.6.11 Read the Commands Used by the Lab

| Operation | Meaning |
|---|---|
| environment-python -m pip --version | Identify the pip attached to that interpreter |

These are command patterns; the runnable script supplies full interpreter and directory paths. It intentionally does not use --no-deps, because resolving and restoring the dependency is the central lesson.

## 5.6.12 Dependency Failures and Change Review

A resolver conflict means the requested versions and available candidates cannot satisfy the declared requirements under the current interpreter/platform conditions. Read the conflicting requirements before loosening version bounds. An arbitrary upgrade may change financial results even if installation succeeds.

Test an intentional version change in a new environment, run metadata checks and application tests, and preserve the selected dependency information. Do not treat pip check as a vulnerability scanner, artifact provenance verifier, or numeric regression test.

This lab's wheel files contain original simple source and no build hooks. A real release should use a maintained build backend and a reviewed dependency source. Creating an installable artifact is distinct from proving its output is financially correct.

## 5.6.13 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| pip command uses wrong Python | Interpreter path and pip --version | Use the intended interpreter with -m pip |
| Import fails after install | Import name, environment, and loaded path | Verify distribution/import mapping and interpreter |
| venv creation fails | venv/ensurepip availability | Use supported Python distribution setup |
| No matching distribution | Python/platform compatibility and available versions | Check requirements and artifact compatibility |
| pip check reports missing unit demo | Intentional broken stage or incomplete install | Reinstall the lab requirements from local wheels |
| Import works from source only | Working-directory shadowing | Test installed code from a separate directory |
| Requirements installed but finance tests fail | Behavioral incompatibility or model assumptions | Investigate regression; metadata compatibility is separate |

## 5.6.15 Key Takeaways
