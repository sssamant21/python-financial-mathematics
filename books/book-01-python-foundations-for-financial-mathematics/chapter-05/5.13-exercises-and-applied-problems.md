## 5.13.1 Purpose and Working Rules

These twenty chapter-wide problems assess reusable code, imports, packaging, environments, configuration, and evidence. Work from the completed Section 5.12 project for coding tasks. Preserve its original version and apply extensions in a separate working copy.

Use synthetic fixtures only. Keep the same USD inflow contract unless a question explicitly asks for a proposed change. An environment label is not authorization, an install success is not financial validation, and an output digest is not a complete research record.

The coding tasks add four tests to the existing eight-test project. The companion contains a complete insertion block and instructions; conceptual tasks require written answers rather than invented execution evidence.

## 5.13.2 Deliverables and Assessment

Submit numbered answers, the extended test file, a verifier transcript, interpreter/backend versions, and a short limitation statement. Each problem is worth five points, for a total of 100: two for a correct result or design, two for reasoning/evidence, and one for assumptions and limits. This is an educational rubric, not a professional certification.

| Problems | Focus | Expected work |
|---|---|---|
| 1–5 | Modules, imports, interpreters, recreation | Design and diagnostic reasoning; quiet-import test |
| 6–10 | Dependencies, artifacts, layouts, configuration | Evidence distinctions and external-path test |
| 11–15 | Failure handling, authorization, numerical meaning | Invalid-input and byte-identity tests; hand calculation |
| 16–20 | Research limits, compatibility, handoff | Review responses and integrated acceptance report |
