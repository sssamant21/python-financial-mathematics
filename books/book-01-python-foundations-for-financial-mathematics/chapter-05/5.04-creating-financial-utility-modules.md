## 5.4.1 Purpose

A useful financial module groups operations that share one clear domain contract. A file called utils.py that mixes payment validation, console prompts, database writes, and pricing makes dependencies and assumptions difficult to review.

This section develops schedule_utils.py: a small module for validating and selecting dated cash-flow records. The application supplies data and the cutoff date; the module returns values without printing, reading files, or consulting the clock. A separate runner handles display.

The emphasis is reusable design. No discounting, interest accrual, currency conversion, or amount aggregation is introduced.

## 5.4.2 Learning Objectives

You should be able to:

1. Choose a module boundary around a coherent financial responsibility.
2. Define a small public API and distinguish internal helpers.
3. Document schema, units, sign, ordering, and failure behavior.
4. Keep I/O and implicit application state outside reusable transformations.
5. Validate complete inputs before selection.
6. Test baseline preservation, deterministic output, and caller integration.

## 5.4.3 Define the Contract Before the File

The module operates on one supplied schedule. Its currency applies to every event, and its perspective is explicitly investor: negative amounts are payments and positive amounts are receipts. Zero events remain valid.

The selection operation is named events_on_or_after. Its inclusive boundary is visible in the name. “Future events” would be ambiguous without an observation date and a decision about events due on that date.

The cutoff is a required argument. Calling date.today inside the utility would make results depend on when and where it runs. Selection by date does not establish whether a payment has settled or remains outstanding.

## 5.4.4 Public API and Internal Helpers

| Function | Responsibility | Returned order |
|---|---|---|
| normalize_schedule(value) | Validate and reconstruct a schedule | payment_date then event_id ascending |
| events_on_or_after(value, cutoff) | Validate complete schedule and select inclusively | Same chronological order |
| _checked_text(value, label) | Internal scalar check | Not a report operation |
| _event_key(event) | Internal sorting key | Date/ID comparison |
| _schedule_record(...) | Internal reconstruction | Preserves supplied tuple sequence |

The underscore marks helpers as implementation details by convention; it is not access control. Callers should depend on the documented public functions. Changing the accepted schema, sign rule, duplicate policy, or selection boundary changes the API even if function names remain unchanged.

For this short module, repeating a validation call would be clearer than introducing a mutable validation cache. Optimize only when measured workloads justify the extra state and invalidation rules.

## 5.4.5 Separate Three Responsibilities

| Layer | Example | Owns |
|---|---|---|
| Input boundary | JSON/file adapter from Section 5.3 | Parsing, encoding, external format |
| Domain utility | schedule_utils.py | In-memory schema, identity, ordering, selection |
| Application | run_schedule.py | Fixture or input source, cutoff choice, display |

The lab uses in-memory objects to isolate the domain module. It does not require the prior section's file. An adapter can later supply the same fields after parsing, but a successful parse must not bypass the utility's contract.

Keep dependencies directed from caller to utility. The utility should not import its runner or tests; that would couple reusable logic to application startup and can create circular imports.

## 5.4.6 Lab Schema and Ownership

Create a fresh directory containing the three source files below. Use Python 3.10 or later; the standard library is sufficient.

| Item | Contract |
|---|---|
| Schedule fields | Exactly schedule_id, currency, perspective, events |
| schedule_id, event_id | Exact nonempty unpadded str |
| currency | USD or EUR |
| perspective | Exactly investor |
| events | List of dictionaries with exactly event_id, payment_date, amount |
| payment_date and cutoff | Exact date objects; datetime and subclasses rejected |
| amount | Exact finite Decimal; negative, zero, positive accepted |
| Identity | event_id unique across the schedule; repeated dates accepted |
| Cutoff | Inclusive: payment_date >= cutoff |
| Empty selection | Wrapper and metadata retained, events empty |
| Output ownership | Fresh wrapper/list/event dictionaries; immutable scalars may be shared |
| Failure | TypeError for types; ValueError for schema/domain/identity violations |

No output is returned until all supplied events pass validation. Events earlier than the cutoff are still checked. There is no partial success or silent rejection list in this API.

## 5.4.7 File 1 — Domain Utility Module

Save as schedule_utils.py:

```python
"""Validated investor cash-flow representations; no application I/O on import.

Public API: normalize_schedule and events_on_or_after.
Amounts remain signed finite Decimal values in one supplied currency.
These functions neither value payments nor determine settlement status.
"""

from datetime import date
from decimal import Decimal

Event = tuple[date, str, Decimal]


def _checked_text(value: object, label: str) -> str:
    if type(value) is not str:
        raise TypeError(f"{label} must be an exact str")
    if not value or value.strip() != value:
        raise ValueError(f"{label} must be nonempty and unpadded")
    return value


def _validated(value: object) -> tuple[str, str, list[Event]]:
    if not isinstance(value, dict):
        raise TypeError("schedule must be a dictionary")
    if set(value) != {"schedule_id", "currency", "perspective", "events"}:
        raise ValueError("schedule has incorrect fields")
    schedule_id = _checked_text(value["schedule_id"], "schedule_id")
    currency = _checked_text(value["currency"], "currency")
    if currency not in {"USD", "EUR"}:
        raise ValueError("currency must be USD or EUR")
    perspective = _checked_text(value["perspective"], "perspective")
    if perspective != "investor":
        raise ValueError("perspective must be investor")
    source = value["events"]
    if not isinstance(source, list):
        raise TypeError("events must be a list")
    events: list[Event] = []
    seen: set[str] = set()
    for index, row in enumerate(source):
        if not isinstance(row, dict):
            raise TypeError(f"event {index} must be a dictionary")
        if set(row) != {"event_id", "payment_date", "amount"}:
            raise ValueError(f"event {index} has incorrect fields")
        event_id = _checked_text(row["event_id"], f"event {index} ID")
        payment_date = row["payment_date"]
        if type(payment_date) is not date:
            raise TypeError(f"event {index} payment_date must be an exact date")
        amount = row["amount"]
        if type(amount) is not Decimal:
            raise TypeError(f"event {index} amount must be an exact Decimal")
        if not amount.is_finite():
            raise ValueError(f"event {index} amount must be finite")
        if event_id in seen:
            raise ValueError(f"duplicate event_id: {event_id}")
        seen.add(event_id)
        events.append((payment_date, event_id, amount))
    return schedule_id, currency, events


def _event_key(event: Event) -> tuple[date, str]:
    return event[0], event[1]


def _schedule_record(schedule_id: str, currency: str, events: list[Event]) -> dict[str, object]:
    return {
        "schedule_id": schedule_id, "currency": currency, "perspective": "investor",
        "events": [
            {"event_id": event_id, "payment_date": payment_date, "amount": amount}
            for payment_date, event_id, amount in events
        ],
    }


def normalize_schedule(value: object) -> dict[str, object]:
    """Return a fresh schedule ordered by date then ID; validate every event.

    Retain distinct same-day events, signed finite Decimal amounts, and zeros.
    Raise TypeError for wrong types and ValueError for other contract failures.
    """
    schedule_id, currency, events = _validated(value)
    return _schedule_record(schedule_id, currency, sorted(events, key=_event_key))


def events_on_or_after(value: object, cutoff: object) -> dict[str, object]:
    """Return a fresh chronological schedule selected at an inclusive date.

    Validate every source event, even those excluded by cutoff. Preserve parent
    metadata for an empty selection. No implicit clock or settlement policy.
    """
    if type(cutoff) is not date:
        raise TypeError("cutoff must be an exact date")
    schedule_id, currency, events = _validated(value)
    selected = [event for event in events if event[0] >= cutoff]
    return _schedule_record(schedule_id, currency, sorted(selected, key=_event_key))
```

The private validation helper returns only checked scalar fields and event tuples. Both public functions reconstruct outputs through one helper, reducing opportunities for ordering or ownership behavior to drift.

The function annotations communicate returned shape; runtime checks enforce accepted values. A dict[str, object] result is intentionally flexible for this stage of the book, so callers need a type check before indexing an events value as a list when using strict static checking.

## 5.4.8 File 2 — Application Runner

Save as run_schedule.py:

```python
"""Choose input and cutoff outside the reusable schedule utility."""

from datetime import date
from decimal import Decimal
import schedule_utils


def sample_schedule() -> dict[str, object]:
    return {
        "schedule_id": "SCH-01", "currency": "USD", "perspective": "investor",
        "events": [
            {"event_id": "E2", "payment_date": date(2028, 1, 15), "amount": Decimal("1000")},
            {"event_id": "E0", "payment_date": date(2027, 1, 15), "amount": Decimal("-1000")},
            {"event_id": "E1", "payment_date": date(2028, 1, 15), "amount": Decimal("0")},
        ],
    }


def main() -> int:
    report = schedule_utils.events_on_or_after(sample_schedule(), date(2028, 1, 15))
    rows = report["events"]
    if not isinstance(rows, list):
        raise TypeError("report events must be a list")
    ids = [str(row["event_id"]) for row in rows]
    print("Selected event IDs: " + ", ".join(ids))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

The selected event IDs are E1 and E2. E1's zero amount does not remove it from a date-based selection. E0 is earlier than the cutoff but still must be valid before the utility returns a result.

The sample_schedule function belongs to the runner solely as demonstration input. A real application should supply its identified source data rather than placing a mutable portfolio or schedule in utility-module globals.

## 5.4.9 File 3 — Contract and Integration Tests

Save as test_schedule_utils.py:

```python
"""Verify public behavior without depending on private helper implementations."""

from datetime import date, datetime
from decimal import Decimal
from pathlib import Path
import subprocess
import sys
import unittest

from run_schedule import sample_schedule
import schedule_utils

LAB_DIR = Path(__file__).resolve().parent


def with_events(events: object) -> dict[str, object]:
    result = sample_schedule()
    result["events"] = events
    return result


def output_events(schedule: dict[str, object]) -> list[dict[str, object]]:
    value = schedule["events"]
    if not isinstance(value, list):
        raise TypeError("events must be a list")
    # Tests consume the public schema, not an internal tuple representation.
    rows: list[dict[str, object]] = []
    for item in value:
        if not isinstance(item, dict):
            raise TypeError("event must be a dictionary")
        rows.append(item)
    return rows


class UtilityTests(unittest.TestCase):
    def test_exact_normalized_schedule(self) -> None:
        self.assertEqual(schedule_utils.normalize_schedule(sample_schedule()), {
            "schedule_id": "SCH-01", "currency": "USD", "perspective": "investor", "events": [
                {"event_id": "E0", "payment_date": date(2027, 1, 15), "amount": Decimal("-1000")},
                {"event_id": "E1", "payment_date": date(2028, 1, 15), "amount": Decimal("0")},
                {"event_id": "E2", "payment_date": date(2028, 1, 15), "amount": Decimal("1000")},
            ],
        })

    def test_inclusive_selection_and_empty(self) -> None:
        report = schedule_utils.events_on_or_after(sample_schedule(), date(2028, 1, 15))
        self.assertEqual(output_events(report), [
            {"event_id": "E1", "payment_date": date(2028, 1, 15), "amount": Decimal("0")},
            {"event_id": "E2", "payment_date": date(2028, 1, 15), "amount": Decimal("1000")},
        ])
        expected = {"schedule_id": "SCH-01", "currency": "USD", "perspective": "investor", "events": []}
        self.assertEqual(schedule_utils.events_on_or_after(sample_schedule(), date(2028, 1, 16)), expected)
        self.assertEqual(schedule_utils.normalize_schedule(with_events([])), expected)

    def test_source_and_result_independence(self) -> None:
        source = sample_schedule()
        one = schedule_utils.normalize_schedule(source)
        two = schedule_utils.events_on_or_after(source, date(2027, 1, 1))
        self.assertEqual(source, sample_schedule())
        self.assertEqual(one, two)
        output_events(one)[0]["amount"] = Decimal("99")
        self.assertEqual(source, sample_schedule())
        self.assertEqual(output_events(two)[0]["amount"], Decimal("-1000"))

    def test_duplicate_identity_across_dates(self) -> None:
        with self.assertRaises(ValueError):
            schedule_utils.normalize_schedule(with_events([
                {"event_id": "A", "payment_date": date(2027, 1, 1), "amount": Decimal("0")},
                {"event_id": "A", "payment_date": date(2028, 1, 1), "amount": Decimal("1")},
            ]))

    def test_exact_date_boundaries(self) -> None:
        for cutoff in (None, "2028-01-15", datetime(2028, 1, 15)):
            with self.assertRaises(TypeError):
                schedule_utils.events_on_or_after(sample_schedule(), cutoff)
        with self.assertRaises(TypeError):
            schedule_utils.normalize_schedule(with_events([
                {"event_id": "A", "payment_date": datetime(2027, 1, 1), "amount": Decimal("0")}
            ]))

    def test_amount_domains(self) -> None:
        for amount in (None, True, 1, 1.5, "1"):
            with self.subTest(amount=amount):
                with self.assertRaises(TypeError):
                    schedule_utils.normalize_schedule(with_events([
                        {"event_id": "A", "payment_date": date(2027, 1, 1), "amount": amount}
                    ]))
        for value in ("NaN", "sNaN", "Infinity", "-Infinity"):
            with self.assertRaises(ValueError):
                schedule_utils.normalize_schedule(with_events([
                    {"event_id": "A", "payment_date": date(2027, 1, 1), "amount": Decimal(value)}
                ]))

    def test_schema_and_metadata(self) -> None:
        with self.assertRaises(TypeError):
            schedule_utils.normalize_schedule([])
        with self.assertRaises(ValueError):
            schedule_utils.normalize_schedule({})
        with self.assertRaises(TypeError):
            schedule_utils.normalize_schedule(with_events(None))
        with self.assertRaises(ValueError):
            schedule_utils.normalize_schedule(with_events([{}]))
        for field, value in (("currency", "GBP"), ("perspective", "issuer"), ("schedule_id", " ")):
            source = sample_schedule()
            source[field] = value
            with self.assertRaises(ValueError):
                schedule_utils.normalize_schedule(source)

    def test_excluded_invalid_event_still_rejected(self) -> None:
        source = with_events([
            {"event_id": "VALID", "payment_date": date(2028, 1, 15), "amount": Decimal("1")},
            {"event_id": "BAD", "payment_date": date(2020, 1, 1), "amount": "missing"},
        ])
        before = source["events"]
        with self.assertRaises(TypeError):
            schedule_utils.events_on_or_after(source, date(2028, 1, 15))
        self.assertIs(source["events"], before)
        self.assertEqual(output_events(source)[0]["amount"], Decimal("1"))

    def test_quiet_import_and_application(self) -> None:
        for arguments, expected in (
            (("-c", "import schedule_utils; import run_schedule"), ""),
            (("run_schedule.py",), "Selected event IDs: E1, E2\n"),
            (("-m", "run_schedule"), "Selected event IDs: E1, E2\n"),
        ):
            with self.subTest(arguments=arguments):
                result = subprocess.run(
                    [sys.executable, *arguments], cwd=LAB_DIR, text=True,
                    capture_output=True, check=False, timeout=10,
                )
                self.assertEqual(result.returncode, 0, result.stderr)
                self.assertEqual(result.stdout, expected)
                self.assertEqual(result.stderr, "")


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

The tests use public results rather than calling internal helpers. This permits implementation changes while retaining contract checks. Fresh-process tests verify that imports do not print the demo and that the runner actually integrates with the utility.

## 5.4.11 Reuse and Change Management

A utility becomes reusable when callers can predict its behavior from its contract and tests. Its small size alone is not enough. Keep shared rules in one location, avoid caller-specific branches, and do not return sentinel values that make errors look like legitimate financial output.

When changing a contract, list affected callers and update their tests. Switching from inclusive to exclusive cutoff or dropping zero events would change results without necessarily producing an exception. Add explicit boundary examples before such changes.

This module repeats representation ideas from Chapter 4 deliberately as an independent runnable lab. In a maintained application, consolidate a single chosen implementation rather than letting multiple copied utility files evolve independently.

## 5.4.12 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| Result changes with execution date | Utility reads current clock | Require an explicit cutoff |
| Utility prints while being imported | Application work at top level | Move display to a guarded runner |
| Same-day event disappears | Date incorrectly treated as unique | Preserve event identity and multiplicity |
| Invalid excluded record is ignored | Selection before validation | Validate complete source first |
| Baseline changes through a report | Shared mutable record | Reconstruct output containers |
| Helpers become caller dependencies | Undocumented internal imports | Use public API and review caller needs |
| New API rule breaks a report silently | Boundary policy changed | Add explicit compatibility and result tests |
