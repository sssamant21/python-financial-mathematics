## 5.7.1 Purpose

Two financial projects may need different dependency sets. A virtual environment gives each project its own installation location while using a chosen base Python. It helps prevent an installation for one project from silently changing another project's dependencies.

This section explains interpreter selection, activation, environment identity, and recreation. The automated lab creates two disposable environments, demonstrates import separation, and recreates one without losing application source. No network access or external distribution is required.

## 5.7.2 Learning Objectives

You should be able to:

1. Create an environment from an explicitly chosen Python.
2. Run its interpreter without activation.
3. Inspect sys.executable, sys.prefix, and sys.base_prefix.
4. Explain package isolation and its limits.
5. Keep source and dependency specifications outside disposable environments.
6. Recreate an environment rather than copying its directory.
7. Diagnose terminal, editor, and notebook interpreter mismatches.

## 5.7.3 What an Environment Contains

A venv records a relationship to a base Python installation and provides its own site-packages location. With the default configuration, it does not include the base installation's third-party site-packages. The standard library remains available through its base Python.

Activation changes shell command lookup so python commonly selects the environment interpreter. It does not create the environment or make that interpreter usable only in the activated shell. Calling the environment interpreter by path works directly.

Environments are disposable and location-dependent. Keep application source, input data, tests, and dependency records outside them. Recreate an environment at a new location rather than treating its directory as a portable application artifact.

## 5.7.4 Create and Inspect Manually

In a new project working directory, choose the base interpreter deliberately. The following commands create a local environment named .venv; do not run creation over a directory that already contains important work.

Windows PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable); print(sys.prefix); print(sys.base_prefix)"
.\.venv\Scripts\python.exe -m pip --version
```

Linux or macOS:

```bash
python3 -m venv .venv
./.venv/bin/python -c "import sys; print(sys.executable); print(sys.prefix); print(sys.base_prefix)"
./.venv/bin/python -m pip --version
```

These are manual setup patterns, separate from the automated temporary lab below. The paths will vary by project and Python installation. Use a version-specific launcher or interpreter path when a project requires a particular Python version; the broad commands above select the local default matching that invocation.

The environment's sys.prefix normally differs from sys.base_prefix. Do not infer environment identity only from a terminal prompt. On systems using executable symlinks, resolving the executable's real filesystem path can lead back to the base binary; inspect runtime prefixes as well.

## 5.7.5 Optional Activation

In PowerShell, the activation script is .\.venv\Scripts\Activate.ps1. In bash or zsh, use `source .venv/bin/activate`. The shell's deactivate command reverses activation changes. If PowerShell policy prevents script activation, the explicit interpreter path above still works without changing execution policy.

A notebook kernel or editor may continue to use a different interpreter after terminal activation. Select the environment in that tool and inspect sys.executable inside the actual running program. Installing into a terminal's environment does not change an already-running notebook kernel automatically.

The VIRTUAL_ENV shell variable is not a reliable universal test: explicit-path execution works without setting it. Use the interpreter's own runtime information.

## 5.7.6 Isolation Has a Scope

| Concern | What venv provides or requires |
|---|---|
| Project package installations | Separate site-packages by default |
| Base Python version | Chosen when environment is created |
| Standard library | Supplied through base Python |
| --system-site-packages | Deliberately exposes base/system site-packages |
| Source working directory | Can still affect ordinary import resolution |
| PYTHONPATH and custom startup code | Can alter import behavior unless controlled |
| Files, network, credentials, permissions | Not isolated as a security sandbox |
| Dependency versions and numerical results | Must still be specified and tested |

The lab uses child interpreters with -I to reduce current-directory, user-site, and Python environment-variable interference during import probes. This deliberately tests environment-local modules rather than the default behavior of every editor or shell configuration. It does not turn Python into a security boundary.

## 5.7.7 Lab Design and Fixture Limits

Save the complete next block as virtual_environment_lab.py. It needs Python 3.10 or later with venv available.

The lab creates environments without pip because its subject is interpreter and import separation, not installation. Section 5.6 already demonstrates real pip installation and repair. Omitting pip here also avoids any ensurepip prerequisite for this automated exercise.

To make import isolation visible without downloads, the script copies a tiny original marker module into the exact purelib directory reported by each child interpreter. This simulates an environment-local import artifact; it is not a pip-installed distribution and has no distribution metadata. Real projects should install distributions with appropriate tooling rather than manually copy modules into site-packages.

The marker identifies an environment label and validates a finite nonnegative Decimal quantity. It performs no arithmetic or valuation. Its source recipe lives outside both environments so the lab can recreate the artifact after deleting an environment.

## 5.7.8 Complete Runnable Lab

```python
"""Verify two temporary venvs and recreation without external installations."""

import json
import os
from pathlib import Path
import shutil
import subprocess
import sys
from tempfile import TemporaryDirectory
import textwrap
import venv

MODULE_NAME = "book1_environment_marker_57"
MARKER_SOURCE = '''
from decimal import Decimal

ENVIRONMENT_LABEL = {label!r}


def checked_quantity(value: object) -> Decimal:
    if type(value) is not Decimal:
        raise TypeError("quantity must be an exact Decimal")
    if not value.is_finite() or value < 0:
        raise ValueError("quantity must be finite and nonnegative")
    return value
'''

INFO_CODE = '''
import json, sys, sysconfig
print(json.dumps({
    "executable": sys.executable,
    "prefix": sys.prefix,
    "base_prefix": sys.base_prefix,
    "purelib": sysconfig.get_path("purelib"),
    "isolated": sys.flags.isolated,
}))
'''

BEHAVIOR_CODE = '''
from decimal import Decimal
from pathlib import Path
import sys
import book1_environment_marker_57 as marker

assert Path(marker.__file__).resolve().is_relative_to(Path(sys.prefix).resolve())
for value in (Decimal("0"), Decimal("12.5")):
    assert marker.checked_quantity(value) == value
for value in (None, True, 1, 1.5, "1"):
    try:
        marker.checked_quantity(value)
    except TypeError:
        pass
    else:
        raise AssertionError("invalid quantity type accepted")
for token in ("NaN", "sNaN", "Infinity", "-Infinity", "-1"):
    try:
        marker.checked_quantity(Decimal(token))
    except ValueError:
        pass
    else:
        raise AssertionError("invalid quantity domain accepted")
print(marker.ENVIRONMENT_LABEL)
'''


def require(condition: bool, message: str) -> None:
    if not condition:
        raise AssertionError(message)


def interpreter(environment: Path) -> Path:
    return environment / ("Scripts/python.exe" if os.name == "nt" else "bin/python")


def child(python: Path, cwd: Path, code: str) -> str:
    result = subprocess.run(
        [str(python), "-I", "-c", textwrap.dedent(code)],
        cwd=cwd, text=True, capture_output=True, check=False, timeout=30,
    )
    require(result.returncode == 0, f"Child failed:\n{result.stdout}\n{result.stderr}")
    require(result.stderr == "", f"Unexpected child stderr: {result.stderr}")
    return result.stdout.strip()


def environment_info(environment: Path, work: Path) -> dict[str, object]:
    result = json.loads(child(interpreter(environment), work, INFO_CODE))
    require(isinstance(result, dict), "runtime info must be a dictionary")
    return dict(result)


def path_field(info: dict[str, object], name: str) -> Path:
    value = info[name]
    require(isinstance(value, str), f"{name} must be a string")
    return Path(str(value)).resolve()


def check_environment(environment: Path, work: Path) -> dict[str, object]:
    info = environment_info(environment, work)
    require(path_field(info, "prefix") == environment.resolve(), "prefix mismatch")
    require(path_field(info, "prefix") != path_field(info, "base_prefix"), "not a venv")
    require(path_field(info, "purelib").is_relative_to(environment.resolve()), "purelib outside venv")
    require(info["isolated"] == 1, "child did not use isolated mode")
    config = (environment / "pyvenv.cfg").read_text(encoding="utf-8").lower()
    require("include-system-site-packages = false" in config, "system packages enabled")
    return info


def require_marker_absent(environment: Path, work: Path) -> None:
    code = (
        "from importlib.util import find_spec; "
        f"assert find_spec({MODULE_NAME!r}) is None"
    )
    child(interpreter(environment), work, code)


def copy_marker(recipe: Path, info: dict[str, object], label: str) -> None:
    target = path_field(info, "purelib") / f"{MODULE_NAME}.py"
    require(not target.exists(), "marker target unexpectedly exists")
    source = recipe.read_text(encoding="utf-8").format(label=label)
    target.write_text(source, encoding="utf-8")


def main() -> int:
    with TemporaryDirectory(prefix="book1-venv57-") as directory:
        root = Path(directory).resolve()
        work = root / "work"
        work.mkdir()
        recipe = root / "marker_recipe.txt"
        recipe.write_text(textwrap.dedent(MARKER_SOURCE), encoding="utf-8")
        environment_a, environment_b = root / "environment_a", root / "environment_b"
        builder = venv.EnvBuilder(with_pip=False, system_site_packages=False)
        builder.create(environment_a)
        builder.create(environment_b)
        info_a = check_environment(environment_a, work)
        info_b = check_environment(environment_b, work)
        require(path_field(info_a, "prefix") != path_field(info_b, "prefix"), "prefixes overlap")
        require_marker_absent(environment_a, work)
        require_marker_absent(environment_b, work)
        print("IDENTITY: two distinct venv prefixes and local purelib directories passed", flush=True)

        copy_marker(recipe, info_a, "A")
        require(child(interpreter(environment_a), work, BEHAVIOR_CODE) == "A", "A label mismatch")
        require_marker_absent(environment_b, work)
        print("ISOLATION: A marker is usable in A and absent from B", flush=True)

        copy_marker(recipe, info_b, "B")
        require(child(interpreter(environment_b), work, BEHAVIOR_CODE) == "B", "B label mismatch")
        require(child(interpreter(environment_a), work, BEHAVIOR_CODE) == "A", "A changed after B setup")
        print("INDEPENDENCE: same module name resolves to each environment's own artifact", flush=True)

        # Delete only this script's known temporary A environment after children exit.
        require(environment_a.parent == root and environment_a.name == "environment_a",
                "unexpected deletion target")
        shutil.rmtree(environment_a)
        require(recipe.is_file(), "source recipe lost with environment")
        builder.create(environment_a)
        recreated = check_environment(environment_a, work)
        require_marker_absent(environment_a, work)
        require(child(interpreter(environment_b), work, BEHAVIOR_CODE) == "B", "B changed during recreation")
        print("RECREATE: fresh A has no marker; source recipe and B are preserved", flush=True)

        copy_marker(recipe, recreated, "A")
        require(child(interpreter(environment_a), work, BEHAVIOR_CODE) == "A", "rebuilt A failed")
        print("REBUILD: restored artifact passes valid/invalid financial input checks", flush=True)
    print("PASS: both temporary environments cleaned up")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

## 5.7.9 Run and Inspect

Windows PowerShell:

```powershell
py -3 virtual_environment_lab.py
```

Linux or macOS:

```bash
python3 virtual_environment_lab.py
```

Expected stage labels: IDENTITY, ISOLATION, INDEPENDENCE, RECREATE, REBUILD, and final PASS. The five stage checks include repeated valid/invalid quantity checks in child interpreters. They are workflow assertions, not a counted unittest suite.

Both environments can import a module with the same name and different labels. Deleting and recreating A removes A's artifact while leaving the source recipe and B intact. The recipe then restores A's teaching behavior. Every child uses an explicit interpreter path without activation.

The script deletes only its own known temporary A environment, then the temporary-directory context removes the remaining disposable resources. Do not adapt its deletion call to an existing project path without establishing that directory's ownership and contents.

## 5.7.10 Keep the Right Things in Version Control

Keep application code, tests, dependency specifications, and environment-creation instructions in the repository. Exclude .venv and other generated environment directories. Do not store project source inside the environment to make imports work.

Record the Python implementation/version and relevant platform information alongside dependency records. A venv does not freeze operating-system libraries, CPU behavior, source data, timestamps, or numeric context. Reproducibility requires those additional decisions when they affect results.

For a dependency correction, preserve the source and recreate a new environment from reviewed specifications rather than relying on undocumented manual repairs. The next section develops version pinning and repeatable installation evidence.

## 5.7.11 Common Operational Problems

| Symptom | Inspect | Correction |
|---|---|---|
| Package installed but notebook import fails | Kernel's sys.executable | Select/restart the intended kernel |
| Terminal prompt shows venv but wrong program runs | Actual interpreter and shell lookup | Invoke environment Python explicitly |
| Environment imports unexpected packages | system-site setting, path overrides, startup code | Recreate with intended isolation; inspect import origin |
| Copied environment breaks | Embedded paths and base Python relationship | Recreate at destination |
| Activation blocked in PowerShell | Script policy | Use explicit python.exe path without activation |
| Standard-library import fails unexpectedly | Local shadowing or broken base installation | Inspect module origin and base runtime |
| Source disappeared during cleanup | Code stored inside generated environment | Keep source outside disposable directories |

## 5.7.13 Key Takeaways

Use explicit interpreter identity and separate dependency locations for project environments. Activation is convenient shell setup, while direct interpreter paths give an unambiguous execution target.

Treat environments as disposable. Preserve source and recreation specifications outside them, and test the recreated application's behavior rather than assuming a directory copy is reproducible.
