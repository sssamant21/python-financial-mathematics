## 5.9.1 Purpose

A clear directory layout tells a reviewer where reusable logic, application startup, tests, and input examples belong. It also makes the intended launch directory explicit so imports and file paths do not work only by accident.

This section builds a small flat-layout project with a package, a command-line entry point, tests, and a synthetic input fixture. The lab runs from the project root without installation. Installed-package validation and distribution configuration remain separate concerns.

## 5.9.2 Learning Objectives

You should be able to:

1. Separate source, tests, documentation, fixtures, and generated state.
2. Compare flat and src layouts without treating either as universally best.
3. Specify the working directory for launch and test discovery.
4. Distinguish import resolution from data-path resolution.
5. Keep environments and generated artifacts outside tracked source.
6. Verify a layout through an executable application and discovered tests.

## 5.9.3 Assign Responsibilities Before Creating Folders

| Category | Responsibility | Example |
|---|---|---|
| Package source | Reusable domain logic | financial_layout/quantities.py |
| Entry point | Arguments, input access, display | financial_layout/__main__.py |
| Tests | Public contracts and application integration | tests/test_layout.py |
| Synthetic fixtures | Small reproducible teaching inputs | fixtures/holdings.json |
| Documentation | Setup and exact commands | README.md |
| Generated state | Environments, bytecode, temporary results | Excluded using .gitignore |

Avoid creating empty folders for every possible future feature. Start with responsibilities the current project actually has. This application prints a report and therefore needs no persistent reports directory yet.

The fixture contains only synthetic identifiers and quantities. Real financial or personal data needs an explicit storage and access policy; a directory named fixtures is not evidence that arbitrary data is suitable for a repository.

## 5.9.4 Flat Layout and src Layout

In a flat layout, the import-package directory is directly under the project root. This makes the current lab easy to launch locally, but can let tests import working-tree code even when a distribution is incomplete.

In a src layout, importable source sits below src/. That generally requires installing the project into an environment or another deliberate import setup. It helps distinguish installed code from incidental project-root files. An editable installation and a regular wheel installation still exercise different deployment paths.

This lab uses flat layout deliberately and makes no installed-distribution claim. A maintained package project can use src layout with a documented build/install process, as developed in Section 5.12. Do not add sys.path edits merely to make an unexplained layout pass its tests.

## 5.9.6 Input and Path Contracts

The JSON fixture is a list of records with exactly security_id and quantity. IDs must be exact nonempty unpadded strings unique within the input. Quantity must be a nonempty unpadded string accepted by Decimal, finite and nonnegative. Zero and fractional instrument units are valid; positive IDs are returned in source order.

Numeric JSON quantities are rejected, so the wire format does not pass amounts through binary floats. Decimal text syntax is intentionally broader than fixed-scale currency text. This is a quantity view, not an economic-exposure ranking or valuation.

An --input argument names a file. Relative input paths resolve against the caller's current working directory; absolute paths name the file directly. The program does not search upward for a repository root or silently substitute the fixture if a path is wrong.

For this flat local project, launch from the project root so Python can discover financial_layout. An absolute input path solves data location, not package discovery. Installation would be needed for a separate installed-use workflow.

## 5.9.11 File 5 — financial_layout/quantities.py

```python
"""Select active IDs from validated wire records without file I/O."""

from decimal import Decimal, InvalidOperation


def active_ids(value: object) -> tuple[str, ...]:
    """Validate every row; return positive-quantity IDs in source order.

    Wire quantities are strings representing finite nonnegative Decimal units.
    Raises TypeError for wrong types, ValueError for other contract failures.
    """
    if not isinstance(value, list):
        raise TypeError("holdings must be a list")
    checked: list[tuple[str, Decimal]] = []
    seen: set[str] = set()
    for index, row in enumerate(value):
        if not isinstance(row, dict):
            raise TypeError(f"holding {index} must be a dictionary")
        if set(row) != {"security_id", "quantity"}:
            raise ValueError(f"holding {index} has incorrect fields")
        sid = row["security_id"]
        if type(sid) is not str:
            raise TypeError("security_id must be an exact str")
        if not sid or sid.strip() != sid:
            raise ValueError("security_id must be nonempty and unpadded")
        quantity_text = row["quantity"]
        if type(quantity_text) is not str:
            raise TypeError("quantity must be decimal text")
        if not quantity_text or quantity_text.strip() != quantity_text:
            raise ValueError("quantity text must be nonempty and unpadded")
        try:
            quantity = Decimal(quantity_text)
        except InvalidOperation as exc:
            raise ValueError("quantity text is invalid") from exc
        if not quantity.is_finite() or quantity < 0:
            raise ValueError("quantity must be finite and nonnegative")
        if sid in seen:
            raise ValueError(f"duplicate security_id: {sid}")
        seen.add(sid)
        checked.append((sid, quantity))
    return tuple(sid for sid, quantity in checked if quantity > 0)
```

## 5.9.12 File 6 — financial_layout/__main__.py

```python
"""Read one explicit UTF-8 input path and display validated active IDs."""

import argparse
import json
from pathlib import Path

from .quantities import active_ids


def _unique_object(pairs: list[tuple[str, object]]) -> dict[str, object]:
    result: dict[str, object] = {}
    for key, value in pairs:
        if key in result:
            raise ValueError(f"duplicate JSON member: {key}")
        result[key] = value
    return result


def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--input", type=Path, required=True)
    args = parser.parse_args(argv)
    payload: object = json.loads(
        args.input.read_text(encoding="utf-8"), object_pairs_hook=_unique_object,
    )
    ids = active_ids(payload)
    print("Active IDs: " + ", ".join(ids))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

Duplicate JSON members are rejected before dictionary construction can hide them. Malformed JSON, file errors, and invalid financial inputs remain visible as failed invocations; the application never replaces them with an empty success report.

The parser accepts no output path because the application prints to stdout. Full configuration precedence and environment separation follow in Section 5.10.

## 5.9.13 File 7 — tests/test_layout.py

```python
"""Verify local layout, explicit data paths, and public financial contracts."""

import json
from pathlib import Path
import subprocess
import sys
from tempfile import TemporaryDirectory
import unittest

from financial_layout.quantities import active_ids

PROJECT_ROOT = Path(__file__).resolve().parents[1]
FIXTURE = PROJECT_ROOT / "fixtures" / "holdings.json"


def fixture() -> list[dict[str, object]]:
    return [
        {"security_id": "SEC-B", "quantity": "0"},
        {"security_id": "SEC-A", "quantity": "12.5"},
        {"security_id": "SEC-C", "quantity": "3"},
    ]


def application(*arguments: str) -> subprocess.CompletedProcess[str]:
    return subprocess.run(
        [sys.executable, "-m", "financial_layout", *arguments],
        cwd=PROJECT_ROOT, capture_output=True, text=True, check=False, timeout=10,
    )


class LayoutTests(unittest.TestCase):
    def test_expected_fixture_and_selection(self) -> None:
        self.assertEqual(json.loads(FIXTURE.read_text(encoding="utf-8")), fixture())
        self.assertEqual(active_ids(fixture()), ("SEC-A", "SEC-C"))
        self.assertEqual(active_ids([]), ())

    def test_source_and_order(self) -> None:
        source = fixture()
        self.assertEqual(active_ids(source), ("SEC-A", "SEC-C"))
        self.assertEqual(source, fixture())
        self.assertEqual(active_ids(list(reversed(source))), ("SEC-C", "SEC-A"))

    def test_domain_and_identity(self) -> None:
        for quantity in ("NaN", "sNaN", "Infinity", "-Infinity", "-1", "bad", "", " 1"):
            with self.subTest(quantity=quantity):
                with self.assertRaises(ValueError):
                    active_ids([{"security_id": "A", "quantity": quantity}])
        for quantity in (None, True, 1, 1.5):
            with self.assertRaises(TypeError):
                active_ids([{"security_id": "A", "quantity": quantity}])
        with self.assertRaises(ValueError):
            active_ids([{"security_id": "A", "quantity": "0"},
                        {"security_id": "A", "quantity": "1"}])
        with self.assertRaises(ValueError):
            active_ids([{}])

    def test_invalid_later_record(self) -> None:
        source = fixture() + [{"security_id": "BAD", "quantity": None}]
        before = [dict(row) for row in source]
        with self.assertRaises(TypeError):
            active_ids(source)
        self.assertEqual(source, before)

    def test_relative_and_absolute_fixture_paths(self) -> None:
        for path in ("fixtures/holdings.json", str(FIXTURE)):
            with self.subTest(path=path):
                result = application("--input", path)
                self.assertEqual(result.returncode, 0, result.stderr)
                self.assertEqual(result.stdout, "Active IDs: SEC-A, SEC-C\n")
                self.assertEqual(result.stderr, "")

    def test_input_outside_project(self) -> None:
        with TemporaryDirectory() as directory:
            path = Path(directory) / "external.json"
            path.write_text('[{"security_id":"OTHER","quantity":"2"}]', encoding="utf-8")
            result = application("--input", str(path))
            self.assertEqual(result.returncode, 0, result.stderr)
            self.assertEqual(result.stdout, "Active IDs: OTHER\n")

    def test_missing_and_invalid_file_fail_without_report(self) -> None:
        with TemporaryDirectory() as directory:
            path = Path(directory) / "missing.json"
            missing = application("--input", str(path))
            self.assertNotEqual(missing.returncode, 0)
            self.assertEqual(missing.stdout, "")
            self.assertIn("FileNotFoundError", missing.stderr)
            path.write_text('[{"security_id":"A","quantity":"1","quantity":"2"}]', encoding="utf-8")
            invalid = application("--input", str(path))
            self.assertNotEqual(invalid.returncode, 0)
            self.assertEqual(invalid.stdout, "")
            self.assertIn("duplicate JSON member", invalid.stderr)

    def test_import_origin_and_quiet_initialization(self) -> None:
        code = (
            "import financial_layout, financial_layout.__main__\n"
            "from pathlib import Path\n"
            "assert Path(financial_layout.__file__).resolve() == Path('financial_layout/__init__.py').resolve()\n"
        )
        result = subprocess.run(
            [sys.executable, "-c", code], cwd=PROJECT_ROOT,
            capture_output=True, text=True, check=False, timeout=10,
        )
        self.assertEqual(result.returncode, 0, result.stderr)
        self.assertEqual(result.stdout, "")
        self.assertEqual(result.stderr, "")


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

Tests locate their fixture from their own file location. That is appropriate for this fixed source-test layout; it is not a deployment rule for installed package data. The application instead receives its input path explicitly.

## 5.9.15 Maintain the Layout as It Grows

Introduce build configuration when the project needs installation, not by confusing the local import directory with a distribution. Separate runtime and development dependency specifications when their roles differ. Keep environment recreation and command instructions close to the source.

For later reports, decide whether output is disposable, a reproducibility artifact, or authoritative input to another process. Retain identifiers and provenance as required; do not rely on folder names to communicate financial meaning.

A structural refactor should preserve public behavior. Moving validation code into a subpackage should not silently change duplicate policy, amount parsing, active selection, or error semantics. Run the public tests after moving files.

## 5.9.16 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| No module named financial_layout | Launch directory/interpreter | Run documented local command from project root |
| Fixture not found | Caller-relative path | Use stated relative path or explicit absolute input |
| Zero tests run | Discovery start directory and test names | Use -s tests and test_*.py naming |
| Tests pass locally but installed package fails | Working-tree imports hide packaging gaps | Add regular installed-artifact tests in packaging workflow |
| Source disappears with environment cleanup | Code placed under .venv | Keep source outside generated state |
| Import triggers report | Entry-point work at import time | Keep main guarded |
| Fixture silently substituted | Hidden root search/default fallback | Require explicit input and propagate errors |

## 5.9.18 Key Takeaways

Give each directory a clear responsibility and document the root-relative launch/test workflow. Treat source imports and data paths as separate mechanisms.

Verify structure through discovered tests and real application launches. Keep environments disposable and add installed-package evidence when the project becomes a distribution.
