## Solution 1 — Module responsibilities

Separate a pure transformation module, a CLI module for arguments/file access, and a guarded entry point. Importing defines functions and constants without reading caller files or printing a report. The caller supplies explicit bytes or records. This makes imports safe to reuse in tests and notebooks; it does not make arbitrary imported code a security sandbox.

## Solution 2 — Import names and distribution names

book1-financial-inflows is the distribution name used by packaging metadata; financial_inflows is the Python import package; financial-inflows is the installed console command. pyproject.toml connects the console command to financial_inflows.cli:main. Use importlib.metadata.version with the distribution name. Do not infer the import spelling from a hyphenated distribution name.

## Solution 3 — Quiet import acceptance

The companion ExtensionTests.test_quiet_import launches the installed interpreter with -I and imports both modules. It checks successful exit and empty stdout/stderr. This catches visible startup work. It does not prove absence of every possible filesystem access; stronger side-effect assertions would need instrumentation or controlled fixtures.

## Solution 4 — Interpreter selection

Use the intended interpreter by absolute path and invoke -m pip through it. Record sys.executable, Python version, and the installed package origin. Activation only changes shell lookup behavior. The Section 5.12 verifier uses explicit interpreter paths and does not depend on activation.

## Solution 5 — Environment recreation

Virtual environments contain interpreter/path relationships and generated scripts that need not remain valid when moved. Retain the supported Python/platform description, exact dependency requirements and approved artifacts, source revision, build instructions, effective settings, fixtures, and acceptance tests. Recreate and validate a fresh environment; a requirements file alone is not a complete machine snapshot.

## Solution 6 — Build versus runtime dependencies

pip is an installation/build frontend in this workflow, setuptools is the declared build backend, Decimal comes from the Python standard library, and book1-financial-inflows is the built application distribution. The runtime requires no third-party library. A backend needed to create a wheel is not automatically an application dependency. The verifier prepares the backend separately before the offline build.

## Solution 7 — Version pins and artifact identity

Retain approved artifacts and their digests, verify against a separately trusted record, and record platform/build context. A version pin identifies a requested release; a digest distinguishes exact bytes. Neither proves economic correctness or author identity by itself. Regenerating the expected digest from an unexpected artifact and immediately approving it defeats the comparison.

## Solution 8 — Flat versus src layout

The checkout root can make local source importable independently of installed contents. Build a regular wheel, install it in a fresh runtime, run copied tests outside the checkout, remove source path overrides, and inspect import origin. Section 5.12 does this. A src layout encourages deliberate installation but does not itself guarantee a correct build.

This demonstrates explicit external file access with an installed package. It does not demonstrate bundled package resources, remote access, or arbitrary filesystem permissions.

## Solution 10 — Configuration precedence

With valid values, EUR wins and its source is cli. Under the all-layer validation policy, an empty environment value fails even though the CLI could otherwise override it. Presence differs from absence. This strict policy exposes stale settings and must remain documented; a winner-only policy would yield different behavior.

A production CLI can replace tracebacks with bounded error messages while retaining nonzero status and no success report. Do not turn invalid input into a zero-total success.

## Solution 12 — Environment labels and authorization

No remote boundary is exercised by these local labs.

## Solution 13 — Rounding stage

Sum-then-round gives 30.010, then 30.01. Half-even rounding of each input gives 10.00 and 20.00 because each halfway case selects an even final cent digit; the sum is 30.00. The difference is 0.01. State the required stage instead of assuming that two deterministic procedures mean the same thing.

## Solution 14 — Numerical context

The core creates a fresh Context with precision 28 and ROUND_HALF_EVEN inside localcontext, so caller precision, rounding, and traps do not govern the arithmetic. At most 1,000 values of at most 1,000,000 with four fractional digits fit comfortably. The existing installed context test sets a hostile caller context and still expects 30.01. Reassess the precision argument before adding divisions, powers, or larger bounds.

## Solution 15 — Bytes versus meaning

ExtensionTests.test_hash_identity_is_not_semantic_identity compares original bytes with original-plus-newline. SHA-256 differs while JSON decoding and the result agree. Exact byte provenance and semantic outcome answer different questions. Preserve both snapshots when investigating; do not silently rewrite them to force digest equality.

## Reference Extension Block — Problems 3, 9, 11, and 15

Insert this entire class into Section 5.12's tests/test_inflows.py immediately before its final `if __name__ == '__main__':` guard. It uses the existing unittest/json imports, analyze import, and DATA/CONFIG constants. Retain all eight original tests.

```python
class ExtensionTests(unittest.TestCase):
    def test_quiet_import(self):
        import subprocess
        import sys
        result = subprocess.run([sys.executable, '-I', '-c',
            'import financial_inflows, financial_inflows.cli'],
            capture_output=True, text=True, timeout=10)
        self.assertEqual(result.returncode, 0, result.stderr)
        self.assertEqual((result.stdout, result.stderr), ('', ''))

    def test_invalid_cli_has_no_report(self):
        from pathlib import Path
        import subprocess
        import sys
        from tempfile import TemporaryDirectory
        with TemporaryDirectory() as directory:
            data, config = Path(directory)/'data.json', Path(directory)/'config.json'
            data.write_bytes(b'[]')
            config.write_bytes(CONFIG)
            result = subprocess.run([sys.executable, '-I', '-m', 'financial_inflows',
                '--input', str(data), '--config', str(config)],
                capture_output=True, text=True, timeout=10)
            self.assertNotEqual(result.returncode, 0)
            self.assertEqual(result.stdout, '')
            self.assertIn('expected 1 to 1000 inflows', result.stderr)

    def test_absolute_external_cli_paths(self):
        from pathlib import Path
        import subprocess
        import sys
        from tempfile import TemporaryDirectory
        with TemporaryDirectory() as directory:
            root = Path(directory).resolve()
            data, config = root/'data.json', root/'config.json'
            data.write_bytes(DATA)
            config.write_bytes(CONFIG)
            result = subprocess.run([sys.executable, '-I', '-m', 'financial_inflows',
                '--input', str(data), '--config', str(config)],
                cwd=root, capture_output=True, text=True, timeout=10)
            self.assertEqual(result.returncode, 0, result.stderr)
            self.assertEqual(json.loads(result.stdout)['total'], '30.01')

    def test_hash_identity_is_not_semantic_identity(self):
        import hashlib
        changed = DATA + b'\n'
        self.assertNotEqual(hashlib.sha256(DATA).hexdigest(),
                            hashlib.sha256(changed).hexdigest())
        self.assertEqual(analyze(DATA, CONFIG), analyze(changed, CONFIG))
```
