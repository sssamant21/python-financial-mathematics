## 5.10.1 Purpose

A reproducible program needs an explicit account of the settings that influenced its execution. Changing a shell variable should not silently change the interpretation of a financial report. This section separates reusable code, non-secret configuration, deployment identity, and credentials.

The lab resolves settings and reports their sources. It does not connect to a service, process client data, calculate prices, or make financial transactions.

## 5.10.2 Learning Objectives

1. Distinguish interpreter environments from application environments.
2. Define and test configuration precedence.
3. Validate text before converting it to domain types.
4. Pass resolved settings explicitly instead of reading global state throughout a program.
5. Track non-secret configuration provenance.
6. Explain why environment labels and virtual environments do not enforce access boundaries.

## 5.10.3 Four Different Meanings of Environment

| Concern | Example | What it controls |
|---|---|---|
| Python environment | Project .venv | Interpreter and installed dependencies |
| Application environment | development, test, production | Declared operating context |
| Process environment | FINLAB_CURRENCY | Text inherited by a process |
| Security boundary | Separate accounts, permissions, storage | Authorized resource access |

A virtual environment does not prevent production network access. A string saying development does not stop a program from using production credentials. Real separation requires resource and identity controls, reviewed outside this local lab.

Promote the same reviewed code between contexts, supplying the intended configuration explicitly. Avoid maintaining a separate copy of calculation code for each environment.

## 5.10.4 Configuration Contract

This example uses three non-secret settings. Every supplied value must be an exact string from the stated set; whitespace and aliases are rejected.

| Key | Allowed text | Default | Process variable |
|---|---|---|---|
| environment | development, test, production | development | FINLAB_ENVIRONMENT |
| currency | USD, EUR | USD | FINLAB_CURRENCY |
| decimal_places | 0, 2, 4 | 2 | FINLAB_DECIMAL_PLACES |

Currency is only a report label here. Selecting EUR does not convert USD amounts. Decimal places is a demonstration setting, not a complete rounding or accounting policy; no amount is rounded in this application. A real model must specify units, conversion sources, dates, numerical precision, and rounding independently.

## 5.10.5 Resolution Rules

From lowest to highest priority: built-in defaults, required JSON file, recognized process variables, explicit command-line overrides. Missing individual keys use lower layers. A missing file fails, even if overrides provide every key.

All supplied recognized values are validated before a result is returned, including shadowed values. Thus an invalid file currency cannot be hidden by a valid command-line currency. This is an intentional strict policy. Another policy is possible, but must be documented and tested.

Empty text is supplied text, not absence. Unknown JSON and programmatic override keys fail. Unrelated process variables are ignored because the process environment also contains operating-system settings. Misspelled FINLAB variables are not detected by this implementation; check spelling during review.

The file is a UTF-8 JSON object. Values remain strings so all layers share one wire contract. Duplicate members fail. There is no automatic .env loading, interpolation, configuration-directory search, or implicit environment-specific file selection. The --config path resolves against the caller's working directory.

## 5.10.6 Lab Files

Create a fresh directory with the following four sibling files. Requires Python 3.10 or later and no third-party dependencies. This is a standalone lab, separate from Section 5.9's package.

| File | Responsibility |
|---|---|
| configuration.py | Load, validate, resolve, and return settings |
| config_demo.py | CLI and process-environment boundary |
| development.json | Non-secret example settings |
| test_configuration.py | Unit and subprocess acceptance tests |

The frozen dataclass below is a small record with generated initialization and ordinary assignment protection. It is not a general security or deep-immutability mechanism. Its fields here are strings, an integer, and a tuple of string pairs. Type annotations do not replace runtime validation.

## 5.10.7 File — configuration.py

```python
"""Resolve explicit, non-secret configuration without import-time I/O."""
from collections.abc import Mapping
from dataclasses import dataclass
import json
from pathlib import Path

KEYS = {'environment', 'currency', 'decimal_places'}
ENV_KEYS = {'environment': 'FINLAB_ENVIRONMENT', 'currency': 'FINLAB_CURRENCY',
            'decimal_places': 'FINLAB_DECIMAL_PLACES'}
DEFAULTS = {'environment': 'development', 'currency': 'USD', 'decimal_places': '2'}

@dataclass(frozen=True)
class Settings:
    environment: str
    currency: str
    decimal_places: int
    sources: tuple[tuple[str, str], ...]


def unique_object(pairs: list[tuple[str, object]]) -> dict[str, object]:
    result: dict[str, object] = {}
    for key, value in pairs:
        if key in result:
            raise ValueError('duplicate configuration key')
        result[key] = value
    return result


def resolve(path: Path, environ: Mapping[str, str],
            overrides: Mapping[str, str]) -> Settings:
    """Precedence: defaults < required JSON file < environment < CLI.

    Validate every supplied recognized value, including shadowed values.
    No mutation, credentials, remote access, or financial calculation.
    """
    payload = json.loads(path.read_text(encoding='utf-8'), object_pairs_hook=unique_object)
    if type(payload) is not dict or set(payload) - KEYS:
        raise ValueError('configuration must be an object with known keys')
    if set(overrides) - KEYS:
        raise ValueError('unknown command-line configuration key')
    selected = dict(DEFAULTS)
    sources = {key: 'default' for key in KEYS}
    layers = [('file', payload),
              ('environment', {key: environ[name] for key, name in ENV_KEYS.items() if name in environ}),
              ('cli', dict(overrides))]
    for source, layer in layers:
        for key, value in layer.items():
            if type(value) is not str:
                raise ValueError(f'{key} must be text')
            allowed = {'environment': {'development', 'test', 'production'},
                       'currency': {'USD', 'EUR'}, 'decimal_places': {'0', '2', '4'}}
            if value not in allowed[key]:
                raise ValueError(f'invalid {key} in {source}')
            selected[key] = value
            sources[key] = source
    return Settings(selected['environment'], selected['currency'],
                    int(selected['decimal_places']), tuple(sorted(sources.items())))
```

## 5.10.8 File — config_demo.py

```python
"""Display resolved non-secret settings; perform no financial transaction."""
import argparse
import json
import os
from pathlib import Path
from configuration import resolve


def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(description=__doc__, allow_abbrev=False)
    parser.add_argument('--config', type=Path, required=True)
    for key in ('environment', 'currency', 'decimal_places'):
        parser.add_argument('--' + key.replace('_', '-'))
    args = parser.parse_args(argv)
    overrides = {key: getattr(args, key) for key in
                 ('environment', 'currency', 'decimal_places') if getattr(args, key) is not None}
    settings = resolve(args.config, dict(os.environ), overrides)
    print(json.dumps({'environment': settings.environment, 'currency': settings.currency,
                      'decimal_places': settings.decimal_places,
                      'sources': dict(settings.sources)}, sort_keys=True))
    return 0


if __name__ == '__main__':
    raise SystemExit(main())
```

## 5.10.10 File — test_configuration.py

```python
from dataclasses import FrozenInstanceError
import json
from pathlib import Path
import subprocess
import sys
from tempfile import TemporaryDirectory
import unittest
from configuration import resolve

ROOT = Path(__file__).resolve().parent

class ConfigurationTests(unittest.TestCase):
    def resolve_text(self, text='{}', env=None, cli=None):
        with TemporaryDirectory() as directory:
            path = Path(directory) / 'settings.json'
            path.write_text(text, encoding='utf-8')
            return resolve(path, {} if env is None else env, {} if cli is None else cli)

    def test_defaults(self):
        settings = self.resolve_text()
        self.assertEqual((settings.environment, settings.currency, settings.decimal_places),
                         ('development', 'USD', 2))
        self.assertEqual(set(dict(settings.sources).values()), {'default'})

    def test_precedence_and_provenance(self):
        settings = self.resolve_text('{"currency":"EUR","decimal_places":"4"}',
                                     {'FINLAB_CURRENCY': 'USD'}, {'currency': 'EUR'})
        self.assertEqual(settings.currency, 'EUR')
        self.assertEqual(settings.decimal_places, 4)
        self.assertEqual(dict(settings.sources),
                         {'environment': 'default', 'currency': 'cli', 'decimal_places': 'file'})

    def test_environment_override(self):
        settings = self.resolve_text('{}', {'FINLAB_ENVIRONMENT':'test', 'FINLAB_DECIMAL_PLACES':'0'})
        self.assertEqual(settings.environment, 'test')
        self.assertEqual(settings.decimal_places, 0)
        self.assertEqual(dict(settings.sources)['environment'], 'environment')

    def test_invalid_values_including_shadowed(self):
        for value in ('', ' USD', 'usd', 'GBP', None, True, 2):
            with self.subTest(value=value), self.assertRaises(ValueError):
                self.resolve_text(json.dumps({'currency':value}), {}, {'currency':'USD'})
        for value in ('-1', '02', '2.0', '3', ''):
            with self.assertRaises(ValueError):
                self.resolve_text('{}', {'FINLAB_DECIMAL_PLACES':value})
        with self.assertRaises(ValueError):
            self.resolve_text('{}', {'FINLAB_ENVIRONMENT':'prod'})

    def test_schema_and_duplicate_rejection(self):
        for text in ('[]', 'null', '{"curreny":"USD"}', '{"currency":"USD","currency":"EUR"}'):
            with self.assertRaises(ValueError):
                self.resolve_text(text)
        with self.assertRaises(ValueError):
            self.resolve_text('{}', {}, {'unknown':'x'})

    def test_missing_or_malformed_file(self):
        with TemporaryDirectory() as directory:
            with self.assertRaises(FileNotFoundError):
                resolve(Path(directory)/'absent.json', {}, {})
        with self.assertRaises(json.JSONDecodeError):
            self.resolve_text('{')

    def test_isolation_and_immutable_result(self):
        env = {'FINLAB_CURRENCY':'EUR', 'UNRELATED':'ignored'}
        cli = {'environment':'test'}
        before = (dict(env), dict(cli))
        settings = self.resolve_text('{}', env, cli)
        self.assertEqual((env, cli), before)
        with self.assertRaises(FrozenInstanceError):
            settings.currency = 'USD'
        self.assertEqual(self.resolve_text().currency, 'USD')

    def test_cli_and_failure_have_expected_output(self):
        env = __import__('os').environ.copy()
        for name in ('FINLAB_ENVIRONMENT','FINLAB_CURRENCY','FINLAB_DECIMAL_PLACES'):
            env.pop(name, None)
        result = subprocess.run([sys.executable, 'config_demo.py', '--config', 'development.json',
                                 '--currency', 'EUR'], cwd=ROOT, env=env,
                                capture_output=True, text=True, timeout=10)
        self.assertEqual(result.returncode, 0, result.stderr)
        self.assertEqual(json.loads(result.stdout)['sources']['currency'], 'cli')
        env['FINLAB_CURRENCY'] = ''
        failed = subprocess.run([sys.executable, 'config_demo.py', '--config', 'development.json'],
                                cwd=ROOT, env=env, capture_output=True, text=True, timeout=10)
        self.assertNotEqual(failed.returncode, 0)
        self.assertEqual(failed.stdout, '')
        self.assertIn('invalid currency in environment', failed.stderr)

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

## 5.10.11 Run and Inspect Provenance

Run from the directory containing the four files. First clear any FINLAB variables left from an earlier experiment so the baseline is predictable.

Windows PowerShell:

```powershell
Remove-Item Env:FINLAB_ENVIRONMENT -ErrorAction SilentlyContinue
Remove-Item Env:FINLAB_CURRENCY -ErrorAction SilentlyContinue
Remove-Item Env:FINLAB_DECIMAL_PLACES -ErrorAction SilentlyContinue
py -3 config_demo.py --config development.json --currency EUR
py -3 -m unittest discover -v
```

Linux or macOS:

```bash
unset FINLAB_ENVIRONMENT FINLAB_CURRENCY FINLAB_DECIMAL_PLACES
python3 config_demo.py --config development.json --currency EUR
python3 -m unittest discover -v
```

Expected application output:

```json
{"currency": "EUR", "decimal_places": 2, "environment": "development", "sources": {"currency": "cli", "decimal_places": "file", "environment": "file"}}
```

Eight discovered tests should pass. The defaults test uses an empty temporary JSON object, while the CLI test uses the complete example file. Equal values can have different provenance: USD from a file is still file-sourced even when it equals the default.

Now demonstrate a process override.

Windows PowerShell:

```powershell
$env:FINLAB_ENVIRONMENT = 'test'
try {
    py -3 config_demo.py --config development.json
} finally {
    Remove-Item Env:FINLAB_ENVIRONMENT -ErrorAction SilentlyContinue
}
```

Linux or macOS:

```bash
FINLAB_ENVIRONMENT=test python3 config_demo.py --config development.json
```

The resolved environment becomes test, sourced from environment. The POSIX inline assignment applies to that invocation. PowerShell cleanup removes the demonstration variable; if you had a meaningful previous value, preserve and restore it instead of using these fresh-shell steps.

Try --decimal-places 3. It fails before any successful report is printed. Try removing --config: argument parsing rejects the invocation. The lab leaves exceptions visible for diagnosis; a production CLI can add carefully bounded error handling while preserving nonzero exit status.

## 5.10.12 Keep Side Effects at the Boundary

Importing configuration.py defines code; it does not read a file or inspect the current process environment. The entry point takes a snapshot of process variables and passes it into the resolver. Tests supply ordinary mappings and do not need to modify global process state.

Resolve once at startup and pass the resulting Settings record to downstream functions. Repeated hidden reads can make one execution observe inconsistent settings. This example intentionally combines file loading and resolution in one boundary function; a larger project can separate those steps while keeping the same public contracts.

The source map records the winning layer, not a full audit trail. It does not include file hashes, code revision, dependency versions, rejected candidates, or effective numerical context. Section 5.11 develops broader research reproducibility. Do not treat this small JSON report as complete execution provenance.

## 5.10.13 Secrets and Deployment Separation

Only the three allowlisted non-secret values are displayed. Do not extend the report by dumping os.environ or arbitrary configuration dictionaries. Credentials belong in a separately designed secret-delivery workflow with appropriate permissions and rotation. Process variables are a transport mechanism, not a guarantee of confidentiality.

Keep real credentials out of committed examples and command-line arguments. An ignored local file is still a local file requiring appropriate access controls, and ignore rules do not remove previously committed material. This lab needs no credentials or .env file.

For an application that accesses remote data, review environment identity together with endpoint, account, dataset, and permissions. A production label in this demo enables no special action. It is not an approval mechanism. Tests should use synthetic fixtures and identities restricted to the resources they need.

## 5.10.14 Troubleshooting

| Symptom | Cause to inspect | Action |
|---|---|---|
| Unexpected currency | Inherited variable or CLI option | Inspect the winning source and controlled launch environment |
| Empty variable fails | Empty is present, not missing | Remove it or supply allowed text |
| Valid CLI still fails | Invalid lower layer | Correct the stale source under the strict policy |
| Configuration missing | Wrong caller-relative path | Supply the intended path explicitly |
| Numeric JSON setting fails | Shared wire contract requires text | Use "2", not 2 |
| Production label appears in test | Inherited context | Isolate launch variables and verify resource identity separately |
| Zero tests discovered | Wrong directory or naming | Run from the four-file lab root |

## 5.10.16 Key Takeaways

Configuration is an explicit input contract. Document precedence, missing-value behavior, type conversion, and validation of shadowed values. Resolve at a boundary, record useful non-secret provenance, and pass the result into the program.

Keep interpreter isolation, application labels, process variables, and resource authorization conceptually separate. They solve different problems.
