## 5.11.1 Purpose

A research result is useful when another person can identify its inputs, understand its assumptions, rerun its code, and assess whether the conclusion survives meaningful changes. Saving a notebook or pinning dependencies addresses only part of that task.

This section builds a small evidence-producing experiment. It aggregates two synthetic USD cash inflows under an explicit rounding policy, records hashes of the exact bytes consumed, and checks repeated execution. It makes no investment recommendation and estimates no market parameter.

## 5.11.2 Learning Objectives

1. Define the scope of a reproducibility claim.
2. Preserve data, source, effective settings, and runtime evidence.
3. Distinguish equal results from identical input bytes.
4. Control numerical context and rounding stages.
5. Test a known answer before interpreting a result.
6. Recognize financial research risks that deterministic execution cannot resolve.

## 5.11.3 State the Claim Before Running

This book uses the following working distinctions. Terminology varies across disciplines; record your project's definitions explicitly.

| Claim | Question | Evidence in this lab |
|---|---|---|
| Repeat execution | Does the same local workflow produce the same artifact? | Two subprocess runs compared byte for byte |
| Input identity | Did runs consume identical input bytes? | SHA-256 of the bytes passed to analysis |
| Numerical agreement | Do outputs satisfy an agreed comparison rule? | Exact fixed-scale total against a known answer |
| Independent reproduction | Can another environment recover the result? | Not established by local tests alone |
| Scientific robustness | Does a conclusion survive alternative defensible assumptions? | Not established by deterministic repetition |

A repeatable implementation can repeat a mistake. The expected answer and the policy behind it must be reviewed separately from execution mechanics.

## 5.11.4 Research Record

| Item | Preserve | Why it matters |
|---|---|---|
| Question | Same-currency total of supplied synthetic inflows | Limits what the answer means |
| Input snapshot | Exact local JSON bytes | Remote data can change |
| Schema and units | USD nonnegative amount text; unique IDs | Prevents ambiguous aggregation |
| Method | Sum full supplied precision, then round once | Defines the rounding stage |
| Effective settings | Currency, scale, rounding | Makes assumptions inspectable |
| Code | Source snapshot and reviewed revision | Identifies implementation |
| Runtime | Python implementation/version and OS | Supports environment comparison |
| Validation | Known answer, invalid cases, repeat runs | States what was checked |
| Limitations | No FX, discounting, stochastic simulation, or remote data | Prevents overinterpretation |

Archive source and input files with the result. A hash identifies bytes for comparison; it does not recover missing files, prove economic correctness, or authenticate their author. A hash stored beside editable data is not an independent trust anchor.

## 5.11.5 Financial and Numerical Contract

The fixture contains USD 10.005 and USD 20.005. Their sum is USD 30.010, reported as 30.01 after one rounding step to cents using ROUND_HALF_EVEN. Rounding each inflow to cents first would give 10.00 plus 20.00, or 30.00. Both procedures are deterministic, but they implement different policies.

The lab chooses sum-then-round as a teaching contract, not as a universal accounting rule. It treats inputs as nonnegative same-currency inflows without timing. It does not compute present value, net cash flow including outflows, foreign-exchange value, return, or profitability.

Input amounts use ordinary nonnegative decimal text with up to four fractional digits, at most seven integer digits, and a maximum of 1,000,000 each. There must be between one and 1,000 records. IDs must be unique nonempty unpadded strings. Additional fields, duplicate JSON members, mixed currencies, numeric amount values, scientific notation, nonfinite values, and negative amounts fail.

These bounds keep the largest total at 1,000,000,000 with at most four fractional places. A fresh Decimal context with precision 28 is ample for this bounded aggregation. It also fixes rounding independently of the caller's settings. This argument does not extend automatically to arbitrary powers, divisions, or unbounded datasets.

## 5.11.7 File — research.py

```python
"""Reproduce a synthetic same-currency cash-inflow aggregation."""
import argparse
from decimal import Context, Decimal, ROUND_HALF_EVEN, localcontext
import hashlib
import json
from pathlib import Path
import platform
import re


def digest(raw: bytes) -> str:
    return hashlib.sha256(raw).hexdigest()


def unique_object(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError('duplicate JSON member')
        result[key] = value
    return result


def decode(raw: bytes):
    return json.loads(raw.decode('utf-8'), object_pairs_hook=unique_object)


def analyze(data_raw: bytes, config_raw: bytes) -> dict:
    config = decode(config_raw)
    if config != {'currency': 'USD', 'rounding': 'ROUND_HALF_EVEN', 'scale': '0.01'}:
        raise ValueError('unsupported configuration')
    rows = decode(data_raw)
    if type(rows) is not list or not 1 <= len(rows) <= 1000:
        raise ValueError('expected 1 to 1000 inflows')
    seen = set()
    amounts = []
    for row in rows:
        if type(row) is not dict or set(row) != {'id', 'currency', 'amount'}:
            raise ValueError('incorrect inflow schema')
        sid = row['id']
        if type(sid) is not str or not sid or sid.strip() != sid or sid in seen:
            raise ValueError('invalid or duplicate id')
        if row['currency'] != 'USD':
            raise ValueError('mixed or unsupported currency')
        text = row['amount']
        if type(text) is not str or re.fullmatch(r'(0|[1-9][0-9]{0,6})(\.[0-9]{1,4})?', text) is None:
            raise ValueError('invalid amount text')
        value = Decimal(text)
        if value > Decimal('1000000'):
            raise ValueError('inflow exceeds lab bound')
        seen.add(sid)
        amounts.append(value)
    # A fresh context prevents caller precision, rounding, or flags from leaking in.
    with localcontext(Context(prec=28, rounding=ROUND_HALF_EVEN)):
        total = sum(amounts, Decimal('0'))
        rounded = total.quantize(Decimal('0.01'))
    return {'currency': 'USD', 'count': len(rows), 'total': format(rounded, '.2f'),
            'method': 'sum_then_round', 'rounding': 'ROUND_HALF_EVEN'}


def bundle(data_raw: bytes, config_raw: bytes, source_raw: bytes) -> dict:
    result = analyze(data_raw, config_raw)
    return {'schema_version': 1, 'result': result,
            'evidence': {'input_sha256': digest(data_raw),
                         'config_sha256': digest(config_raw),
                         'source_sha256': digest(source_raw),
                         'python': platform.python_version(),
                         'implementation': platform.python_implementation(),
                         'system': platform.system(),
                         'third_party_runtime_dependencies': []}}


def main(argv=None) -> int:
    parser = argparse.ArgumentParser(description=__doc__, allow_abbrev=False)
    parser.add_argument('--input', type=Path, required=True)
    parser.add_argument('--config', type=Path, required=True)
    parser.add_argument('--output', type=Path, required=True)
    args = parser.parse_args(argv)
    # Read each input once: hash and analyze the same bytes.
    data_raw = args.input.read_bytes()
    config_raw = args.config.read_bytes()
    source_raw = Path(__file__).read_bytes()
    report = bundle(data_raw, config_raw, source_raw)
    encoded = json.dumps(report, sort_keys=True, indent=2, allow_nan=False) + '\n'
    # Exclusive create: never overwrite inputs or an earlier research result.
    with args.output.open('x', encoding='utf-8', newline='\n') as stream:
        stream.write(encoded)
    return 0


if __name__ == '__main__':
    raise SystemExit(main())
```

## 5.11.10 File — test_research.py

```python
from decimal import Inexact, ROUND_DOWN, localcontext
import json
from pathlib import Path
import subprocess
import sys
from tempfile import TemporaryDirectory
import unittest
from research import analyze, bundle, digest

ROOT = Path(__file__).resolve().parent
DATA = (ROOT / 'inflows.json').read_bytes()
CONFIG = (ROOT / 'settings.json').read_bytes()
SOURCE = (ROOT / 'research.py').read_bytes()

class ResearchTests(unittest.TestCase):
    def test_known_answer_and_policy(self):
        result = analyze(DATA, CONFIG)
        self.assertEqual(result['total'], '30.01')
        self.assertEqual(result['count'], 2)
        self.assertEqual(result['method'], 'sum_then_round')
        # Rounding each 10.005 and 20.005 first would instead yield 30.00.

    def test_context_isolation(self):
        expected = analyze(DATA, CONFIG)
        with localcontext() as context:
            context.prec = 2
            context.rounding = ROUND_DOWN
            context.traps[Inexact] = True
            self.assertEqual(analyze(DATA, CONFIG), expected)
            self.assertEqual(context.prec, 2)
            self.assertTrue(context.traps[Inexact])

    def test_repeat_bundle(self):
        self.assertEqual(bundle(DATA, CONFIG, SOURCE), bundle(DATA, CONFIG, SOURCE))

    def test_byte_identity_versus_result(self):
        changed = DATA + b'\n'
        self.assertNotEqual(digest(DATA), digest(changed))
        self.assertEqual(analyze(DATA, CONFIG), analyze(changed, CONFIG))

    def test_changed_data_and_source(self):
        changed = DATA.replace(b'10.005', b'11.005')
        self.assertEqual(analyze(changed, CONFIG)['total'], '31.01')
        self.assertNotEqual(bundle(DATA, CONFIG, SOURCE)['evidence']['source_sha256'],
                            bundle(DATA, CONFIG, SOURCE+b'\n')['evidence']['source_sha256'])

    def test_invalid_records(self):
        baseline = json.loads(DATA)
        for amount in ('NaN', '-1', '1e2', ' 1', '1000001', '1.00001', 1, None):
            rows = [dict(baseline[0], amount=amount)]
            with self.subTest(amount=amount), self.assertRaises(ValueError):
                analyze(json.dumps(rows).encode(), CONFIG)
        for rows in ([], baseline*2, [dict(baseline[0], currency='EUR')], [{}]):
            with self.assertRaises(ValueError):
                analyze(json.dumps(rows).encode(), CONFIG)

    def test_config_and_duplicate_members(self):
        with self.assertRaises(ValueError):
            analyze(DATA, CONFIG.replace(b'ROUND_HALF_EVEN', b'ROUND_DOWN'))
        with self.assertRaises(ValueError):
            analyze(b'[{"id":"A","id":"B"}]', CONFIG)

    def test_cli_rerun_and_no_overwrite(self):
        with TemporaryDirectory() as directory:
            paths = [Path(directory)/name for name in ('a.json', 'b.json')]
            for path in paths:
                result = subprocess.run([sys.executable, str(ROOT/'research.py'),
                    '--input', str(ROOT/'inflows.json'), '--config', str(ROOT/'settings.json'),
                    '--output', str(path)], capture_output=True, text=True, timeout=10)
                self.assertEqual(result.returncode, 0, result.stderr)
            self.assertEqual(paths[0].read_bytes(), paths[1].read_bytes())
            before = paths[0].read_bytes()
            failed = subprocess.run([sys.executable, str(ROOT/'research.py'),
                '--input', str(ROOT/'inflows.json'), '--config', str(ROOT/'settings.json'),
                '--output', str(paths[0])], capture_output=True, text=True, timeout=10)
            self.assertNotEqual(failed.returncode, 0)
            self.assertEqual(paths[0].read_bytes(), before)

    def test_invalid_input_creates_no_report(self):
        with TemporaryDirectory() as directory:
            bad, output = Path(directory)/'bad.json', Path(directory)/'out.json'
            bad.write_text('[]', encoding='utf-8')
            result = subprocess.run([sys.executable, str(ROOT/'research.py'),
                '--input', str(bad), '--config', str(ROOT/'settings.json'), '--output', str(output)],
                capture_output=True, text=True, timeout=10)
            self.assertNotEqual(result.returncode, 0)
            self.assertFalse(output.exists())

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

## 5.11.11 Execute the Experiment

Use output names that do not already exist. The application opens output with exclusive creation and will fail rather than overwrite an input or a previous result.

Windows PowerShell:

```powershell
py -3 research.py --input inflows.json --config settings.json --output run-a.json
py -3 research.py --input inflows.json --config settings.json --output run-b.json
py -3 -c "from pathlib import Path; assert Path('run-a.json').read_bytes() == Path('run-b.json').read_bytes(); print('Identical run artifacts')"
py -3 -m unittest discover -v
```

Linux or macOS:

python3 research.py --input inflows.json --config settings.json --output run-a.json

python3 -c "from pathlib import Path; assert Path('run-a.json').read_bytes() == Path('run-b.json').read_bytes(); print('Identical run artifacts')"

The surrounding evidence includes input, configuration, and source SHA-256 digests, Python version and implementation, system name, and an empty third-party-runtime-dependency list. Digests depend on your exact files, including line endings. Runtime fields depend on your machine. Do not copy another machine's digests as if they described your files.

To repeat manually, choose new output names or intentionally remove only the generated result files you no longer need. Tests use temporary directories and leave the supplied input snapshots unchanged.

## 5.11.12 Interpret Differences

| Observation | Interpretation | Next check |
|---|---|---|
| Same result, different input hash | Different bytes may encode equal data | Compare snapshots; identify whitespace versus substantive edits |
| Different result, same input/config hashes | Code or runtime may differ | Compare source and runtime evidence; rerun known-answer tests |
| Same result, different source hash | Code bytes changed, perhaps only formatting | Review the code change rather than accepting output alone |
| Same hashes, surprising economics | Input identity does not establish assumptions | Review units, scope, data selection, and model |
| Different full artifact across OS | Runtime evidence is deliberately machine-dependent | Compare numerical result separately and document the supported claim |

The artifact is stable only for the stated files and recorded runtime fields. It is not a standardized cross-language canonical JSON format. The source digest covers research.py, not tests, this manuscript, a full repository, or an interpreter binary. Retain a reviewed repository revision and dependency/build evidence in a larger workflow.

Reading data once ensures the hash and calculation use the same byte snapshot. The source file is read as evidence at runtime; its hash is not an attestation that no process modified code before or during execution. This lab assumes a controlled local working directory.

## 5.11.13 Preserve a Research Bundle

Keep the four source/input files, generated result, test evidence, and a short research note together under a deliberate retention policy. Record the question, reviewed revision, exact command, comparison criteria, and deviations from the documented setup.

Section 5.8 covers dependency artifacts and hashes. Include those when third-party code becomes part of the experiment. An installed-package list alone does not preserve the interpreter, platform libraries, external services, or source data. The empty dependency list here describes this lab's imports; it is not a scan or certification of your entire machine.

Output creation is exclusive but not crash-atomic. Validation failures occur before output creation; an I/O failure during writing could leave an incomplete new file. A larger workflow can write to a temporary file and publish only after successful completion, with a clearly designed replacement policy. Never treat file existence alone as successful execution.

## 5.11.14 Financial Research Beyond Deterministic Code

Before interpreting a market-data experiment, record which information was available at each decision time, how revisions and corporate actions were handled, and why instruments entered or left the sample. Reproducing today's corrected dataset does not establish that the same data was available historically.

Document missing observations, identifiers, time zones, calendars, currency conventions, fees, and model assumptions. Distinguish an observed result from a hypothesis selected after examining many alternatives. Use an evaluation design appropriate to the question and report unsuccessful checks as well as successful ones. These are review questions for later empirical work; this synthetic aggregation does not test a trading strategy.

If later experiments use randomness, record the generator, seed, software versions, draw order, and parallelization policy. A seed alone does not guarantee identical results across algorithms or execution plans. This experiment avoids randomness entirely.

A notebook should rerun from a fresh kernel in documented order. Move shared logic into tested modules and preserve the data snapshot rather than relying on interactive state or a live endpoint. A successfully executed notebook remains subject to the same assumptions and evidence requirements as a script.

## 5.11.15 Troubleshooting

| Symptom | Inspect | Correction |
|---|---|---|
| FileExistsError | Output already exists | Choose a fresh result filename |
| Different hash after checkout | Line endings or file edits | Preserve and compare exact consumed bytes |
| Total expected as 30.00 | Rounding stage | Apply the documented sum-then-round policy |
| Unsupported configuration | Currency, scale, rounding, extra keys | Use the complete supplied policy |
| Invalid amount | Grammar, units, bound, JSON type | Correct input explicitly; never silently coerce |
| Different runtime evidence | Python implementation/version or OS | Compare result separately and record environment difference |
| Result file exists but is incomplete | Write failure | Check process exit and parse the artifact |

## 5.11.17 Key Takeaways

A reproducible workflow preserves a question, exact inputs, explicit assumptions, source, runtime evidence, and validation criteria. Check numerical meaning independently of artifact identity.

Control hidden state, retain input snapshots, and compare outcomes at the level your claim requires. Repeated execution supports a bounded computational claim; broader financial conclusions require additional evidence and review.
