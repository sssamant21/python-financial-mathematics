## 5.1.3 A Module Gives Definitions a Home

For this section, a source module is a .py file containing definitions and statements. Python also supplies other module forms, including built-in and extension modules. We will work with ordinary source files.

Save reusable logic in holdings_core.py and access its functions through the holdings_core name. That name identifies a module object; its attributes include the functions defined by the file.

A script describes how code is launched. The same source file can be imported as a module or run directly as a script. A package organizes modules under a package namespace; package layout is developed in Section 5.5.

## 5.1.4 Namespaces and Qualified Access

In the lab, `import holdings_core` binds a module name in the caller. The expression `holdings_core.active_ids(...)` makes the function's origin visible. A caller can have its own variable named holdings without replacing the core module's function-local variables.

A module namespace is not an access-control boundary. Callers can inspect attributes and can rebind module attributes. Uppercase names conventionally mark constants; the spelling does not enforce immutability.

The core below avoids a mutable module-level portfolio. Each call receives its data explicitly. That keeps a report from depending on the contents left behind by an earlier call.

## 5.1.5 What Happens During Import

An initial normal import executes a module's top-level statements. Function definitions bind function objects; their bodies run only when called. Imports and other top-level expressions can still perform work.

Normal repeated imports under the same name reuse the cached module in the interpreter. Importing again is not a general way to rerun a demonstration or pick up file edits. Restart a development interpreter after changes when a clean state is needed.

The lab's core imports Decimal and defines functions, but does not print reports, request user input, or change application data during import. That is a deliberate module contract rather than a property automatically provided by Python.

## 5.1.6 Direct Execution and the Main Guard

When the runner is imported normally its __name__ is run_holdings. When launched as the top-level program, its __name__ is __main__. The guard invokes main only for that top-level execution:

```python
if __name__ == "__main__":
    raise SystemExit(main())
```

This is a pattern excerpt; the complete runnable runner appears below. Its main function constructs synthetic input, calls the core, prints one result, and returns zero for a successful process exit.

The guard does not skip the rest of the file during import. Unguarded top-level print statements or function calls would still run. Keep the application work inside main and put only the entry-point invocation under the guard.

## 5.1.8 Lab Input and Output Contract

The module handles one supplied aggregate-holdings list, using the previous chapter's narrow domain rules.

| Item | Rule |
|---|---|
| Input | List of records with exactly security_id and quantity |
| security_id | Exact nonempty unpadded str, unique within input |
| quantity | Exact finite nonnegative Decimal instrument units |
| capture_holdings | Tuple of scalar ID/quantity pairs in source order |
| active_ids | Tuple of strictly positive holding IDs in source order |
| Zero | Valid, captured, omitted only from active_ids |
| Empty | Empty tuple from both functions |
| Failure | TypeError for types; ValueError for schema/domain/duplicates |
| Ownership | Source dictionaries not retained or changed |
| Import behavior | No application output or demonstration execution |

All rows are validated before active selection. An invalid later or zero-like record cannot be hidden by a filter. No quantity arithmetic, price lookup, valuation, or currency conversion is performed.

## 5.1.9 File 1 — Reusable Core

Save as holdings_core.py:

```python
"""Validated aggregate-holdings views with no application work at import."""

from decimal import Decimal

Holding = tuple[str, Decimal]
Snapshot = tuple[Holding, ...]


def capture_holdings(value: object) -> Snapshot:
    """Capture ordered scalar holdings; reject duplicates and invalid quantities.

    Quantity is finite nonnegative Decimal instrument units, not market value.
    Source records are never changed or retained in the result.
    """
    if not isinstance(value, list):
        raise TypeError("holdings must be a list")
    result: list[Holding] = []
    seen: set[str] = set()
    for index, row in enumerate(value):
        if not isinstance(row, dict):
            raise TypeError(f"holding {index} must be a dictionary")
        if set(row) != {"security_id", "quantity"}:
            raise ValueError(f"holding {index} has incorrect fields")
        security_id = row["security_id"]
        quantity = row["quantity"]
        if type(security_id) is not str:
            raise TypeError(f"holding {index} security_id must be an exact str")
        if not security_id or security_id.strip() != security_id:
            raise ValueError(f"holding {index} security_id is blank or padded")
        if type(quantity) is not Decimal:
            raise TypeError(f"holding {index} quantity must be an exact Decimal")
        if not quantity.is_finite() or quantity < 0:
            raise ValueError(f"holding {index} quantity must be finite and nonnegative")
        if security_id in seen:
            raise ValueError(f"duplicate security_id: {security_id}")
        seen.add(security_id)
        result.append((security_id, quantity))
    return tuple(result)


def active_ids(value: object) -> tuple[str, ...]:
    """Return positive-quantity IDs in source order after complete validation."""
    snapshot = capture_holdings(value)
    return tuple(security_id for security_id, quantity in snapshot if quantity > 0)
```

Calling active_ids delegates validation to capture_holdings. The shared function keeps the two public operations consistent. The module-level aliases describe the pair and snapshot types; they do not store a portfolio or enforce validation by themselves.

## 5.1.10 File 2 — Demonstration Runner

Save as run_holdings.py:

```python
"""Demonstrate holdings_core when launched as a program."""

from decimal import Decimal
import holdings_core


def main() -> int:
    holdings = [
        {"security_id": "SEC-B", "quantity": Decimal("0")},
        {"security_id": "SEC-A", "quantity": Decimal("12.5")},
        {"security_id": "SEC-C", "quantity": Decimal("3")},
    ]
    ids = holdings_core.active_ids(holdings)
    print("Active IDs: " + ", ".join(ids))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

A terminal run prints `Active IDs: SEC-A, SEC-C`. Importing run_holdings defines main without calling it. Running the core file directly produces no application output because it contains no entry-point call.

## 5.1.11 File 3 — Tests

Save as test_holdings_modules.py:

```python
"""Verify holdings contracts and fresh-process module behavior."""

from decimal import Decimal
from pathlib import Path
import subprocess
import sys
import unittest

import holdings_core

LAB_DIR = Path(__file__).resolve().parent


def sample_holdings() -> list[dict[str, object]]:
    return [
        {"security_id": "SEC-B", "quantity": Decimal("0")},
        {"security_id": "SEC-A", "quantity": Decimal("12.5")},
        {"security_id": "SEC-C", "quantity": Decimal("3")},
    ]


def launch(*arguments: str) -> subprocess.CompletedProcess[str]:
    return subprocess.run(
        [sys.executable, *arguments], cwd=LAB_DIR, text=True,
        capture_output=True, check=False, timeout=10,
    )


class ModuleTests(unittest.TestCase):
    def test_values_and_empty(self) -> None:
        source = sample_holdings()
        self.assertEqual(holdings_core.capture_holdings(source), (
            ("SEC-B", Decimal("0")), ("SEC-A", Decimal("12.5")), ("SEC-C", Decimal("3"))
        ))
        self.assertEqual(holdings_core.active_ids(source), ("SEC-A", "SEC-C"))
        self.assertEqual(holdings_core.capture_holdings([]), ())
        self.assertEqual(holdings_core.active_ids([]), ())

    def test_source_independence(self) -> None:
        source = sample_holdings()
        captured = holdings_core.capture_holdings(source)
        self.assertEqual(source, sample_holdings())
        source[1]["quantity"] = Decimal("99")
        source.append({"security_id": "SEC-D", "quantity": Decimal("1")})
        self.assertEqual(captured, (
            ("SEC-B", Decimal("0")), ("SEC-A", Decimal("12.5")), ("SEC-C", Decimal("3"))
        ))

    def test_validation(self) -> None:
        for quantity in (None, True, 1, 1.5, "1"):
            with self.subTest(quantity=quantity):
                with self.assertRaises(TypeError):
                    holdings_core.active_ids([{"security_id": "A", "quantity": quantity}])
        for value in ("NaN", "sNaN", "Infinity", "-Infinity", "-1"):
            with self.assertRaises(ValueError):
                holdings_core.capture_holdings([{"security_id": "A", "quantity": Decimal(value)}])
        with self.assertRaises(ValueError):
            holdings_core.capture_holdings([{}])
        with self.assertRaises(TypeError):
            holdings_core.capture_holdings(())
        for sid in ("", " A", "A "):
            with self.assertRaises(ValueError):
                holdings_core.capture_holdings([{"security_id": sid, "quantity": Decimal("0")}])

    def test_duplicate_and_invalid_later_row(self) -> None:
        with self.assertRaises(ValueError):
            holdings_core.active_ids([
                {"security_id": "A", "quantity": Decimal("0")},
                {"security_id": "A", "quantity": Decimal("1")},
            ])
        source = sample_holdings() + [{"security_id": "BAD", "quantity": "invalid"}]
        before = [dict(row) for row in source]
        with self.assertRaises(TypeError):
            holdings_core.active_ids(source)
        self.assertEqual(source, before)

    def test_fresh_import_is_quiet(self) -> None:
        # A fresh interpreter avoids passing merely because imports were cached.
        result = launch("-c", "import holdings_core; import run_holdings")
        self.assertEqual(result.returncode, 0, result.stderr)
        self.assertEqual(result.stdout, "")
        self.assertEqual(result.stderr, "")

    def test_script_and_module_launch(self) -> None:
        for arguments in (("run_holdings.py",), ("-m", "run_holdings")):
            with self.subTest(arguments=arguments):
                result = launch(*arguments)
                self.assertEqual(result.returncode, 0, result.stderr)
                self.assertEqual(result.stdout, "Active IDs: SEC-A, SEC-C\n")
                self.assertEqual(result.stderr, "")

    def test_namespace_cache_and_origin(self) -> None:
        result = launch("-c", (
            "import holdings_core; import holdings_core as again; "
            "from pathlib import Path; "
            "assert holdings_core is again; "
            "assert holdings_core.__name__ == 'holdings_core'; "
            "assert Path(holdings_core.__file__).resolve() == Path('holdings_core.py').resolve(); "
            "assert callable(holdings_core.active_ids)"
        ))
        self.assertEqual(result.returncode, 0, result.stderr)
        self.assertEqual(result.stdout, "")
        self.assertEqual(result.stderr, "")

    def test_core_direct_execution_is_quiet(self) -> None:
        result = launch("holdings_core.py")
        self.assertEqual(result.returncode, 0, result.stderr)
        self.assertEqual(result.stdout, "")
        self.assertEqual(result.stderr, "")


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

The child-process helper uses the same interpreter as the test runner and an explicit working directory. It captures output and checks the return code, so an import error cannot masquerade as a successful quiet import. Its timeout prevents a misplaced input prompt from hanging the test indefinitely.

The quiet-import test checks observed output and successful initialization, not every possible filesystem or network side effect. Review the core's top-level statements as well. Python may create bytecode cache files under its normal configuration; this is not application report execution.

## 5.1.13 Common Problems

| Symptom | Inspect | Correction |
|---|---|---|
| ModuleNotFoundError for holdings_core | File name and launch directory | Keep sibling lab files together and use stated commands |
| AttributeError after import | Actual module path and saved code | Inspect __file__ and spelling; remove name collisions |
| Demo prints during import | Unguarded top-level work | Put application work in main and guard its invocation |
| Edits appear ignored | Cached module in a long-running interpreter | Restart and rerun the lab |
| Decimal import fails unexpectedly | Local decimal.py or decimal directory | Rename the conflicting local file and restart |
| Same portfolio state leaks across calls | Mutable global state | Pass holdings explicitly and return fresh results |
| Core script prints nothing | No application entry point in core | Run run_holdings.py for the demonstration |

## 5.1.15 Key Takeaways

A module gives reusable definitions a namespace. Keep application execution explicit so importing a module does not unexpectedly run a report.
