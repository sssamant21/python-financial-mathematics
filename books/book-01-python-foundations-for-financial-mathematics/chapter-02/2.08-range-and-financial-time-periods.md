## 2.8.1 Why Financial Models Need Period Sequences

Many financial models are organized around discrete periods: years, months, quarters, payment numbers, coupon periods, or scenario steps. Python's built-in `range()` type provides a compact way to generate integer sequences that can represent those period labels.

For example:

```python
for year in range(1, 6):
    print(year)
```

produces the period labels:

```text
1
2
3
4
5
```

The important distinction is that `range()` creates integer values. The financial meaning of those integers—years, months, payment numbers, or another period convention—comes from the model.

```text
integer sequence from range()
            ↓
model-defined interpretation
            ↓
financial time periods
```

## 2.8.2 The Basic Form of `range()`

Python supports these common forms:

```python
range(stop)
range(start, stop)
range(start, stop, step)
```

The `stop` value is excluded.

```python
list(range(5))
```

produces:

```python
[0, 1, 2, 3, 4]
```

while:

```python
list(range(1, 6))
```

produces:

```python
[1, 2, 3, 4, 5]
```

This half-open interval behavior is fundamental when mapping Python ranges to financial timelines.

## 2.8.3 Zero-Based and One-Based Financial Timelines

Financial mathematics commonly distinguishes time `0` from future periods.

A timeline may be written as:

```text
t = 0    t = 1    t = 2    t = 3
  |--------|--------|--------|
 today    year 1   year 2   year 3
```

If the model includes the valuation date, a useful Python range is:

```python
for period in range(0, 4):
    print(period)
```

If the calculation applies only to future periods 1 through 3:

```python
for period in range(1, 4):
    print(period)
```

Choosing between zero-based and one-based periods is therefore not merely a programming preference. It must match the timing convention of the financial model.

## 2.8.4 Modeling Annual Periods

Suppose an investment compounds annually for five years. The future compounding periods can be represented as:

```python
for year in range(1, 6):
    print(f"Year {year}")
```

The loop executes five times because the upper bound `6` is excluded.

A simple balance evolution can then be modeled as:

```python
from decimal import Decimal

balance = Decimal("10000.00")
annual_rate = Decimal("0.05")

for year in range(1, 6):
    balance *= Decimal("1") + annual_rate
    print(year, balance)
```

Here `range()` controls the sequence of annual periods. The compounding equation determines the financial state transition.

## 2.8.5 Period Numbers and Compound Growth

For a principal `P`, periodic rate `r`, and period number `t`, compound growth can be expressed as:

```text
FV_t = P(1 + r)^t
```

A period sequence can be used to evaluate the balance at multiple points:

```python
from decimal import Decimal

principal = Decimal("5000.00")
rate = Decimal("0.04")

for period in range(0, 6):
    future_value = principal * (Decimal("1") + rate) ** period
    print(period, future_value)
```

Including period `0` is meaningful because:

```text
FV_0 = P(1 + r)^0 = P
```

The initial principal is therefore naturally represented at time zero.

## 2.8.6 Modeling Monthly Periods

A one-year monthly model contains 12 monthly intervals. If months are numbered 1 through 12:

```python
for month in range(1, 13):
    print(month)
```

For a multi-year monthly model:

```python
years = 3
months = years * 12

for month in range(1, months + 1):
    print(month)
```

The expression `months + 1` compensates for the exclusive upper bound so that the final intended month is included.

This pattern is common:

```python
range(1, number_of_periods + 1)
```

when financial periods are labeled starting at 1.

## 2.8.7 Modeling Quarterly and Other Periodic Frequencies

The same approach works for other discrete frequencies.

For eight quarterly periods:

```python
for quarter in range(1, 9):
    print(quarter)
```

For 24 semi-monthly payment periods:

```python
for payment_number in range(1, 25):
    print(payment_number)
```

The integer sequence itself does not encode calendar semantics. A model must explicitly define what one increment means.

```text
step of 1
   ↓
one year? one month? one quarter? one payment?
   ↓
defined by the financial model
```

## 2.8.8 Using the `step` Argument

The third argument to `range()` controls the integer increment:

```python
range(start, stop, step)
```

For example:

```python
list(range(0, 13, 3))
```

produces:

```python
[0, 3, 6, 9, 12]
```

If the integers represent months, these values could be interpreted as quarterly checkpoints across one year.

```python
for month in range(0, 13, 3):
    print(f"Checkpoint at month {month}")
```

The step size describes spacing in the integer sequence. Its financial interpretation still belongs to the model.

## 2.8.9 Countdown Periods

A negative step allows a range to move backward:

```python
for periods_remaining in range(5, 0, -1):
    print(periods_remaining)
```

This produces:

```text
5
4
3
2
1
```

Such a sequence can be useful when expressing remaining payment periods, years to maturity, or backward-oriented scenario logic.

The stop value remains excluded, even when the step is negative.

## 2.8.10 Payment Schedules

Suppose a loan has 12 scheduled payments. Payment numbers can be generated as:

```python
number_of_payments = 12

for payment_number in range(1, number_of_payments + 1):
    print(f"Payment {payment_number}")
```

A simplified balance model might be:

```python
from decimal import Decimal

balance = Decimal("12000.00")
payment = Decimal("1000.00")

for payment_number in range(1, 13):
    balance -= payment
    print(payment_number, balance)
```

This example intentionally omits interest so that the role of period generation remains clear. A production loan model would need to define interest accrual, payment timing, rounding, fees, and other contractual rules.

## 2.8.11 Discounting Across Periods

Period numbers are especially useful in present-value calculations.

For a cash flow `CF_t` received at period `t`, a basic discrete discounting relationship is:

```text
PV_t = CF_t / (1 + r)^t
```

A sequence of future periods can be paired with cash flows:

```python
from decimal import Decimal

cash_flows = [
    Decimal("200.00"),
    Decimal("300.00"),
    Decimal("500.00"),
]
rate = Decimal("0.05")

present_value = Decimal("0")

for period, cash_flow in zip(range(1, len(cash_flows) + 1), cash_flows):
    present_value += cash_flow / (Decimal("1") + rate) ** period

print(present_value)
```

The `range()` sequence supplies period numbers `1`, `2`, and `3`, while the cash-flow list supplies the corresponding amounts.

This requires an explicit timing assumption: the first cash flow is treated as occurring at period 1, not at period 0.

## 2.8.12 `range()` Versus Iterating Directly Over Financial Data

If a calculation only needs each cash-flow value, direct iteration is usually clearer:

```python
for cash_flow in cash_flows:
    ...
```

If both the period number and value are needed, Python's `enumerate()` is often appropriate:

```python
for period, cash_flow in enumerate(cash_flows, start=1):
    ...
```

A `range()` is most natural when the period sequence itself drives the model:

```python
for period in range(1, number_of_periods + 1):
    ...
```

The choice should reflect what the loop conceptually represents rather than forcing every financial sequence into an index-based pattern.

## 2.8.13 Off-by-One Errors in Financial Models

One of the most important risks when using `range()` is an off-by-one error.

Consider:

```python
for year in range(1, 5):
    print(year)
```

This processes only years 1 through 4—not year 5.

For five one-based periods, use:

```python
range(1, 6)
```

or:

```python
number_of_periods = 5
range(1, number_of_periods + 1)
```

An off-by-one error can materially change a financial result by adding or omitting a compounding, discounting, contribution, payment, or fee period.

Before implementing a loop, write the intended timeline explicitly:

```text
intended periods: 1, 2, 3, 4, 5
Python range:      range(1, 6)
```

## 2.8.14 Timing Conventions Must Be Explicit

Two models with identical cash-flow amounts can produce different results if their timing assumptions differ.

For example:

```text
Model A: first cash flow occurs at t = 0
Model B: first cash flow occurs at t = 1
```

The corresponding period sequences might be:

```python
range(0, len(cash_flows))
```

and:

```python
range(1, len(cash_flows) + 1)
```

Neither is universally correct. Correctness depends on the financial contract, valuation convention, and model specification.

This is why period indexing should be treated as part of financial model design, not merely loop syntax.

## 2.8.15 `range()` Is Not a Calendar

A `range()` represents integers, not dates.

```python
range(1, 13)
```

can represent twelve monthly periods conceptually, but it does not know:

- which calendar months are involved,
- month lengths,
- leap years,
- weekends or holidays,
- business-day conventions,
- settlement calendars,
- actual payment dates, or
- day-count conventions.

When a financial calculation depends on actual dates rather than abstract period numbers, date-aware tools and explicit financial calendar rules are required.

This distinction prevents a common modeling mistake:

```text
period number ≠ calendar date
```

## 2.8.16 `range()` Objects Are Reusable Integer Sequences

A `range` object can be stored and reused:

```python
periods = range(1, 6)

for period in periods:
    print(period)
```

It can also be converted to a list when the concrete values are useful for inspection:

```python
periods = list(range(1, 6))
print(periods)
```

producing:

```python
[1, 2, 3, 4, 5]
```

For ordinary iteration, conversion to a list is usually unnecessary. Keeping the `range` object preserves the direct expression of the intended integer progression.

## 2.8.17 Validation of Period Inputs

Financial models should validate period counts before constructing loops.

For example:

```python
number_of_periods = 12

if number_of_periods <= 0:
    raise ValueError("number_of_periods must be positive")

for period in range(1, number_of_periods + 1):
    print(period)
```

Depending on the model, validation may also need to confirm that the period count is an integer and that it satisfies contractual or system limits.

A loop that executes successfully is not evidence that the financial input was valid.

## 2.8.18 Production Modeling Guidance

When using `range()` in financial code:

1. Define whether the timeline begins at period `0` or period `1`.
2. Remember that the stop bound is excluded.
3. Name the period variable according to its meaning: `year`, `month`, `quarter`, `payment_number`, or `period`.
4. Keep period generation separate from the financial formula when possible.
5. Validate the number of periods before iteration.
6. State the timing convention for cash flows explicitly.
7. Do not treat integer period labels as calendar dates.
8. Test boundary cases, especially the first and final periods.
9. Verify that the number of loop executions matches the financial specification.
10. Prefer direct iteration or `enumerate()` when an artificial numeric index is unnecessary.

## 2.8.19 Common Failure Patterns

### Failure Pattern 1 — Missing the Final Period

```python
range(1, 12)
```

does not include `12`.

### Failure Pattern 2 — Accidental Extra Period

A model intended for periods `0` through `11` should not use:

```python
range(0, 13)
```

because it includes period `12`.

### Failure Pattern 3 — Wrong Timing Origin

Using period `0` when the first cash flow occurs at period `1` changes discounting exponents and therefore valuation.

### Failure Pattern 4 — Treating Period Numbers as Dates

An integer sequence cannot implement real calendar conventions by itself.

### Failure Pattern 5 — Using Indexing When Direct Iteration Is Clearer

```python
for i in range(len(cash_flows)):
    cash_flow = cash_flows[i]
```

may be less expressive than:

```python
for cash_flow in cash_flows:
    ...
```

or:

```python
for period, cash_flow in enumerate(cash_flows, start=1):
    ...
```

## 2.8.20 Worked Example — Investment Growth Schedule

Consider an investment of `$10,000` earning a constant annual rate of `5%` for five periods.

```python
from decimal import Decimal

principal = Decimal("10000.00")
rate = Decimal("0.05")
number_of_periods = 5

for period in range(0, number_of_periods + 1):
    balance = principal * (Decimal("1") + rate) ** period
    print(f"Period {period}: {balance:.2f}")
```

Conceptually:

```text
Period 0 → initial value
Period 1 → one compounding period
Period 2 → two compounding periods
...
Period 5 → five compounding periods
```

The use of `range(0, number_of_periods + 1)` is deliberate because the schedule displays both the initial valuation point and all five future periods.

## 2.8.21 Worked Example — Contribution Schedule

Suppose an investor contributes `$500` at the end of each month for 12 months. The payment labels can be generated as:

```python
from decimal import Decimal

monthly_contribution = Decimal("500.00")
number_of_months = 12
cumulative_contributions = Decimal("0")

for month in range(1, number_of_months + 1):
    cumulative_contributions += monthly_contribution
    print(month, cumulative_contributions)
```

This example tracks contributions only; it does not model investment returns. Its purpose is to show how a one-based monthly sequence aligns with twelve end-of-month contributions.

## 2.8.22 Worked Example — Periodic Discount Factors

Discount factors can be generated across a sequence of periods:

```python
from decimal import Decimal

rate = Decimal("0.06")
number_of_periods = 5

for period in range(1, number_of_periods + 1):
    discount_factor = Decimal("1") / (Decimal("1") + rate) ** period
    print(period, discount_factor)
```

The period number directly controls the exponent. An indexing mistake therefore becomes a valuation mistake.

This relationship reinforces the key principle of the section:

```text
correct period sequence
        ↓
correct exponent / timing
        ↓
correct financial interpretation
```

## 2.8.23 Section Checklist

Before using `range()` for financial periods, verify:

- What does each integer represent?
- Does the timeline begin at `0` or `1`?
- Is the final intended period included?
- Is the stop bound correctly adjusted?
- Does the first cash flow occur at the assumed time?
- Are period counts validated?
- Are actual calendar dates required instead?
- Would direct iteration or `enumerate()` express the model more clearly?
- Have the first, last, and zero-period cases been tested?

## 2.8.24 Key Takeaways

- `range()` generates integer sequences that are useful for discrete financial periods.
- The stop bound is exclusive.
- `range(1, n + 1)` is a common pattern for one-based periods `1` through `n`.
- `range(0, n + 1)` can represent a valuation point at time zero plus `n` future periods.
- The financial meaning of a period number must be defined by the model.
- Off-by-one errors can become material valuation errors.
- Period indexing and cash-flow timing conventions must agree.
- `range()` is not a substitute for calendar-aware date modeling.
- Direct iteration and `enumerate()` are often clearer when the financial data itself drives the loop.
