## Project Objective

Build an Investment Scenario Analyzer that projects an investment under several annual-return assumptions and determines whether each scenario reaches a specified target within a finite time horizon.

The project integrates Boolean expressions, comparisons, `if`/`elif`/`else`, financial decision rules, `for` loops, stopping-condition reasoning, `range()`, nested control flow, `break`, `continue`, defensive validation, `Decimal`, financial state management, scenario classification, structured results, reconciliation, and explainable reporting.

> **A financial model should make its assumptions, state transitions, stopping rules, validation rules, and outcomes explicit.**

## Business Question

Under several constant annual-return assumptions, how long would it take the modeled investment balance to reach a specified target?

For every supplied return scenario, the analyzer determines whether the scenario is supported, whether the target is reached, the first modeled year in which it is reached, and the balance when scenario processing ends.

## Financial Model

Let `B_t` be the investment balance at the end of year `t`, `B_0` the initial investment, `r` the constant annual return for one scenario, and `C` the fixed annual contribution.

The project uses the end-of-year contribution convention:

`B_t = B_(t-1) * (1 + r) + C`

The modeled sequence is beginning-of-year balance → apply annual return → add end-of-year contribution → ending balance. A beginning-of-period contribution would require a different recurrence.

## Model Assumptions

The educational model assumes one initial investment, one fixed annual contribution, annual compounding, end-of-year contributions, one constant annual return within each scenario, multiple return scenarios, one nominal target balance, and a finite projection horizon. Taxes, fees, withdrawals, inflation adjustment, intra-year cash flows, stochastic returns, and changing contribution schedules are excluded.

A 7% scenario means 7% is applied in every modeled year for that scenario. It is a sensitivity assumption, not a forecast of realized annual returns. All balances, contributions, and the target are nominal amounts.

## Numerical and Rounding Policy

The model uses `Decimal` and does not quantize the balance to cents after each annual update. Internal Decimal precision is retained through the projection, while two-decimal formatting is used only for reporting.

Target attainment is determined using the internal Decimal balance, not the formatted display balance. A production implementation may instead require quantization at period or transaction boundaries; if target attainment is defined using rounded balances, quantization must occur before comparison.

## Canonical Implementation

```python
from decimal import Decimal

initial_investment = Decimal("25000.00")
annual_contribution = Decimal("5000.00")
target_balance = Decimal("100000.00")

maximum_years = 20
maximum_supported_years = 100
early_target_threshold_years = 10

return_scenarios = [
    Decimal("0.03"),
    Decimal("0.05"),
    Decimal("0.07"),
    Decimal("0.09"),
]

errors = []

if not initial_investment.is_finite():
    errors.append("Initial investment must be finite.")
elif initial_investment <= 0:
    errors.append("Initial investment must be greater than zero.")

if not annual_contribution.is_finite():
    errors.append("Annual contribution must be finite.")
elif annual_contribution < 0:
    errors.append("Annual contribution cannot be negative.")

if not target_balance.is_finite():
    errors.append("Target balance must be finite.")
elif target_balance <= 0:
    errors.append("Target balance must be greater than zero.")

if not isinstance(maximum_years, int) or isinstance(maximum_years, bool):
    errors.append("Maximum years must be an integer.")
elif maximum_years <= 0:
    errors.append("Maximum years must be greater than zero.")
elif maximum_years > maximum_supported_years:
    errors.append("Maximum years exceeds the supported model horizon.")

if errors:
    print("Input Validation Errors")
    print("-" * 60)
    for error in errors:
        print(f"- {error}")
else:
    results = []
    rejections = []

    total_scenarios = len(return_scenarios)
    evaluated_scenarios = 0
    rejected_scenarios = 0
    target_reached_scenarios = 0
    target_not_reached_scenarios = 0

    for annual_return in return_scenarios:
        if not isinstance(annual_return, Decimal):
            rejected_scenarios += 1
            rejections.append({
                "annual_return": annual_return,
                "reason": "Return must be Decimal.",
            })
            continue

        if not annual_return.is_finite():
            rejected_scenarios += 1
            rejections.append({
                "annual_return": annual_return,
                "reason": "Return must be finite.",
            })
            continue

        if annual_return <= Decimal("-1"):
            rejected_scenarios += 1
            rejections.append({
                "annual_return": annual_return,
                "reason": "Return must exceed -100% for this model.",
            })
            continue

        evaluated_scenarios += 1
        balance = initial_investment
        target_year = None

        if balance >= target_balance:
            target_year = 0
        else:
            for year in range(1, maximum_years + 1):
                balance *= Decimal("1") + annual_return
                balance += annual_contribution

                # Target attainment uses the internal Decimal balance.
                if balance >= target_balance:
                    target_year = year
                    break

        if target_year is None:
            target_not_reached_scenarios += 1
            outcome = "Target not reached"
        else:
            target_reached_scenarios += 1

            if target_year == 0:
                outcome = "Target already reached"
            elif target_year <= early_target_threshold_years:
                outcome = (
                    "Target reached within "
                    f"{early_target_threshold_years} years"
                )
            else:
                outcome = (
                    "Target reached after "
                    f"{early_target_threshold_years} years"
                )

        results.append({
            "annual_return": annual_return,
            "target_year": target_year,
            "ending_balance": balance,
            "outcome": outcome,
        })

    assert evaluated_scenarios + rejected_scenarios == total_scenarios
    assert (
        target_reached_scenarios + target_not_reached_scenarios
        == evaluated_scenarios
    )
    assert len(results) == evaluated_scenarios
    assert len(rejections) == rejected_scenarios

    print()
    print("Investment Scenario Results")
    print("-" * 60)

    for result in results:
        print(f"Return: {result['annual_return']:.1%}")
        print(f"Outcome: {result['outcome']}")

        if result["target_year"] is not None:
            print(f"Target year: {result['target_year']}")

        print(f"Balance: ${result['ending_balance']:,.2f}")
        print()

    if rejections:
        print("Rejected Scenarios")
        print("-" * 60)

        for rejection in rejections:
            print(f"Return: {rejection['annual_return']}")
            print(f"Reason: {rejection['reason']}")
            print()

    print("Scenario Summary")
    print("-" * 60)
    print(f"Total scenarios: {total_scenarios}")
    print(f"Evaluated: {evaluated_scenarios}")
    print(f"Rejected: {rejected_scenarios}")
    print(f"Target reached: {target_reached_scenarios}")
    print(f"Target not reached: {target_not_reached_scenarios}")
```

`ending_balance` means the balance at the point where scenario processing ends—either the first target-crossing year or the final modeled year when the target is not reached.

## Control-Flow Architecture

Shared assumptions are validated before scenario processing. Each scenario is then validated for representation, finite value, and model domain. Rejected scenarios are recorded before `continue`. Accepted scenarios reset independent state, check period 0, and then project years `1` through `maximum_years`. The balance receives the constant annual return and end-of-year contribution before the internal balance is compared with the target. The first target crossing records the year and executes `break`. Results are classified, stored, reconciled, and reported.

## Scenario Analysis Versus Forecasting

The project varies `r` while holding the other assumptions constant. This is a simple one-factor scenario or sensitivity analysis. Scenario assumptions do not establish probabilities, expected market returns, or forecast confidence.

An earliest target-reaching scenario should not be described as the "best investment." It only reaches the modeled target earliest under the supplied assumptions. If multiple scenarios reach the target in the same year, tie behavior should be explicitly defined rather than silently determined by iteration order.

## Testing and Boundary Cases

Important tests include typical inputs, a target already reached at period 0, zero contribution, zero return, supported negative returns, returns at or below -100%, `NaN`, positive and negative infinity, invalid horizons, target not reached, target reached in the final year, an empty scenario collection, and a case where display rounding differs from the internal target comparison.

Important boundaries include initial investment zero, contribution zero, target equal to the initial investment, return exactly -1, return just above -1, one-year horizon, maximum supported horizon, target reached in year 1, target reached in the final year, and target missed by a very small internal amount.

## Reconciliation

The model verifies these internal invariants:

- evaluated scenarios + rejected scenarios = total scenarios;
- target reached + target not reached = evaluated scenarios;
- number of stored results = evaluated scenarios;
- number of stored rejections = rejected scenarios.

These assertions verify internal program consistency and are not substitutes for external-input validation.

## Common Failure Patterns

Common failures include calculating before validation, failing to reset scenario state, applying contributions at the wrong time, undocumented rounding, comparing formatted values, off-by-one period errors, ignoring period 0, continuing after the first target crossing, silent scenario rejection, treating zero return as missing, accepting non-finite rates, shared mutable scenario state, magic classification boundaries, describing the highest-return assumption as the best investment, ignoring ties, missing reconciliation, treating scenarios as forecast probabilities, and ignoring the nominal/inflation distinction.

## Key Takeaways

Financial timing, rounding, validation, state initialization, loop boundaries, stopping conditions, and classification rules are all part of the model specification. Scenario returns are assumptions rather than forecasts. Each scenario requires independent state. Period 0 is meaningful. `continue` can represent explicit scenario rejection, while `break` can represent a financial stopping rule. Structured results and reconciliation make the model easier to audit and extend.

> **A financial model should make its assumptions, state transitions, stopping rules, validation rules, and outcomes explicit.**
