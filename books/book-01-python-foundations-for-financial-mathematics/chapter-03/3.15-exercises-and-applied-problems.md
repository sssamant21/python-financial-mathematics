## 3.15.1 Purpose and Prerequisites

These 20 exercises consolidate Sections 3.1–3.14. They assess function interfaces, financial meaning, numerical policy, and verification.

Save the three project files from Section 3.14 before attempting the applied work. Use Python 3.10 or later and Decimal values constructed from strings. Preserve the project's fixed 40-digit policy rather than changing it silently.

The [companion solutions](solutions/3.15-solutions-and-reference-implementations.md) provide a numbered answer for every exercise and an executable verification module.

## 3.15.2 Submission Requirements

For explanatory questions, state the behavior and the reason. For calculations, show the financial timeline and an independently reasoned expected result before calling the library.

Submit implementations, selected tests, actual output, Python version, and numerical assumptions. A displayed amount alone is insufficient evidence.

## 3.15.3 Exercises 1–5 — Function Inputs and Outputs

### Exercise 1 — Parameters and Arguments

For a call to future_value with principal 1000, periodic_rate 0.05, and periods 2, identify the parameters, arguments, and returned quantity. State the valuation time and currency interpretation.

### Exercise 2 — Printing Versus Returning

Explain why a function that only prints a calculated amount produces None when its call is assigned to a variable. Propose a calculation/reporting separation.

### Exercise 3 — Keyword-Only Interface

Write the Section 3.14 future_value call for 1000 at 5% for two periods. Explain why supplying the rate and horizon positionally fails.

### Exercise 4 — Missing Result

A function returns a positive gain only when ending_amount exceeds starting_amount and otherwise reaches its end. Explain the zero-gain and loss outcomes. Propose a signed-gain expression for the no-intermediate-cash-flow case.

### Exercise 5 — Default and Explicit None

Given a parameter periods=1, compare omission, periods=0, and periods=None. Does a default validate an integer count? Explain.

## 3.15.4 Exercises 6–10 — Scope, Types, and Contracts

### Exercise 6 — Mutable Default

Explain why def append_flow(amount, flows=[]) can mix observations across calls. Give a corrected implementation that creates a fresh list for omitted input. State what happens to an explicitly supplied list.

### Exercise 7 — Scope Failure

Explain why assigning rate = rate + spread inside a function can raise UnboundLocalError even when a module-global rate exists. Propose an explicit-input alternative.

### Exercise 8 — Type-Hint Limits

For periodic_rate: Decimal and periods: int, identify four facts that the annotations do not enforce. Include finite values and Boolean period counts.

### Exercise 9 — Financial Docstring

Draft the contract for present_value, including valuation time, same-currency output, sign convention, periodic rate meaning, supported horizon, zero-horizon validation, numerical policy, exclusions, and failure behavior.

### Exercise 10 — Local State and Mutation

Explain why rebinding a local Decimal parameter does not change the caller's variable, while appending to a list supplied as a parameter changes the caller-visible list.

## 3.15.5 Exercises 11–15 — Financial Calculations

### Exercise 11 — Accumulation

Compute FV of 2000 at an effective 4% annual rate for three annual periods. Verify using the project function. Show the multiplication independently.

### Exercise 12 — Discounting

Discount 144 due after two periods at an effective rate of 20% per period. Explain why 144 multiplied by 1.2 squared answers a different question.

### Exercise 13 — Nominal Conversion

Convert a nominal annual rate of 8% compounded quarterly to a quarterly effective rate. Then calculate the effective annual rate. Show both relationships and verify both values.

### Exercise 14 — Composition

Use present_value_from_nominal to discount 104.04 due after two quarters at the Exercise 13 nominal quotation. Write both a staged calculation and a wrapper call, and compare the results with a justified tolerance.

### Exercise 15 — Supported Negative Rate

Find FV of 1000 for one period at -10%, then discount the result using the same rate. Explain why the associated discount factor exceeds one.

## 3.15.6 Exercises 16–20 — Reliability and Applied Review

### Exercise 16 — Validation Matrix

For the project present_value function, test a string amount, NaN rate at zero horizon, Boolean horizon, and horizon 1001. State the expected exception classes.

### Exercise 17 — Context Preservation

Run a project valuation with low caller precision, ROUND_DOWN, and an enabled Inexact trap. Verify the returned result agrees with a reference call and the caller's settings, flags, and traps remain unchanged.

### Exercise 18 — Detect a Defect

In a temporary copy, replace present-value division by multiplication. State an independent known-value test that detects the defect. Restore the correct code afterward.

### Exercise 19 — Reproduction Record

List the information needed to reproduce a financial result beyond just its amount and rate. Explain why matching output does not establish financial correctness.

### Exercise 20 — Final Integration Case

Use the Chapter 3 project to calculate the following educational scenario:

- Period-0 principal: 1000.
- Nominal annual quotation: 12%, compounded monthly.
- Horizon: 12 monthly periods.
- No intervening cash flows, fees, taxes, or currency conversion.

Report the effective monthly rate, effective annual rate, future value, and recovered present value. Keep computation numeric and format only the final report. Add a test for a zero horizon and an invalid frequency.

## 3.15.8 Working Method

Attempt the reasoning before opening the solutions. Do not change expected values to match a failed implementation without rechecking the derivation.

Run applied tests from a clean working directory. Keep deliberate defects in temporary copies, preserve the canonical project, and record why each failure occurs.

The companion module verifies selected solution behavior, not every possible answer or input. Equivalent solutions can be accepted when their contracts are explicit and their evidence is sound.
