## 3.13.1 Purpose

Financial tests should verify the documented model, not simply repeat the implementation's expression.

This section builds a standard-library unittest suite around fixed_present_value from Section 3.12. It checks independent known values, boundaries, invalid inputs, directional behavior, reproducibility, and context preservation.

The function remains unchanged. Separating its implementation from the test module demonstrates how to test an existing contract rather than quietly changing the model to make a test pass.

## 3.13.2 Learning Objectives

You should be able to:

1. Translate a financial contract into test cases.
2. Choose independent expected values.
3. Use unittest assertions, exception checks, and subtests.
4. Apply a documented Decimal tolerance.
5. Verify numerical-state preservation.
6. Demonstrate that a deliberate defect is detected.
7. Report results without implying complete model certification.

## 3.13.3 Start with the Contract

The function under test discounts a finite nonnegative Decimal amount using a constant effective periodic rate greater than -1 and matching integer periods from 0 through 1000, excluding bool.

It returns the period-0 equivalent in the original currency. It performs no currency conversion, intermediate cash-flow modeling, or explicit currency quantization.

Section 3.12 fixes its internal numerical context at precision 40 with specified rounding, limits, flags, and traps. The tests should verify that the caller's context is preserved, rather than assuming ambient arithmetic governs this function.

## 3.13.4 Design a Test Matrix

| Category | Example | Evidence |
|---|---|---|
| Known value | 125 discounted one period at 25% | Exactly 100 |
| Multiple periods | 121 discounted two periods at 10% | Exactly 100 |
| Boundary | Zero periods | Amount preserved after validation |
| Boundary | Zero amount or rate | Documented zero behavior |
| Supported negative rate | 900 discounted one period at -10% | Exactly 1000 |
| Representation | String amount, float rate, bool count | TypeError |
| Domain | NaN, negative amount, rate -1 | ValueError |
| Numerical failure | Extreme growth factor | Overflow |
| Qualitative | Higher positive discount rate | Lower PV |
| Isolation | Different caller settings | Same result; unchanged settings and flags |

These examples are independently reasoned from simple accumulation relationships. They are not obtained by calling another implementation that shares the same helper.

## 3.13.5 Assertions and Test Structure

A unittest test case groups related test methods. Each method begins with test_ and should return None.

assertEqual compares expected values, assertIsInstance checks representation, assertLess and assertGreater express direction, and assertRaises verifies failure behavior.

subTest labels cases inside a loop so a failing input can be identified without hiding other cases in that method.

unittest assertion methods remain active under Python optimization. They are different from the bare assert statements used in earlier instructional labs. Production input validation should still use explicit guards and exceptions.

## 3.13.6 Exact Values and Tolerances

Use exact equality when the known result is representable and the chosen calculation reaches it under the documented policy.

For a nonterminating result, compare the error against an explicitly justified tolerance. Do not convert Decimal values to float merely to compare them.

The suite uses 100/3 as a rational reference: discounting 100 one period at rate 2 gives 100/3. A separate 60-digit context computes the reference; the tested function uses 40 digits.

The 1e-36 absolute tolerance is suitable for that particular result scale and precision. It is not a general currency threshold. A broader library should define relative and absolute tolerances appropriate to each quantity.

## 3.13.7 Hands-On Lab — Test the Existing Function

First save the complete Section 3.12 lab as reproducibility_lab.py. Save the following test module beside it as test_financial_functions.py.

Both files must be in the current working directory. The test imports the function without running Section 3.12's entry-point demonstrations.

```python
"""Contract tests for the Section 3.12 fixed-policy present value."""

from decimal import (
    Decimal,
    Inexact,
    Overflow,
    ROUND_DOWN,
    getcontext,
    localcontext,
)
import unittest

from reproducibility_lab import fixed_present_value


class TestPresentValue(unittest.TestCase):
    """Check the public financial and numerical contract."""

    def test_known_values(self) -> None:
        cases = [
            ("125", "0.25", 1, "100"),
            ("121", "0.10", 2, "100"),
            ("900", "-0.10", 1, "1000"),
        ]
        for amount, rate, periods, expected in cases:
            with self.subTest(amount=amount, rate=rate, periods=periods):
                actual = fixed_present_value(
                    Decimal(amount),
                    periodic_rate=Decimal(rate),
                    periods=periods,
                )
                self.assertEqual(actual, Decimal(expected))
                self.assertIsInstance(actual, Decimal)

    def test_zero_boundaries(self) -> None:
        self.assertEqual(
            fixed_present_value(
                Decimal("100"), periodic_rate=Decimal("0.05"), periods=0
            ),
            Decimal("100"),
        )
        self.assertEqual(
            fixed_present_value(
                Decimal("100"), periodic_rate=Decimal("0"), periods=10
            ),
            Decimal("100"),
        )
        self.assertEqual(
            fixed_present_value(
                Decimal("0"), periodic_rate=Decimal("0.05"), periods=10
            ),
            Decimal("0"),
        )

    def test_horizon_upper_boundary(self) -> None:
        self.assertEqual(
            fixed_present_value(
                Decimal("100"), periodic_rate=Decimal("0"), periods=1000
            ),
            Decimal("100"),
        )
        with self.assertRaises(ValueError):
            fixed_present_value(
                Decimal("100"), periodic_rate=Decimal("0"), periods=1001
            )

    def test_wrong_representations(self) -> None:
        # Objects deliberately violate the static signature. The targeted
        # ignores document the runtime-boundary purpose of these calls.
        with self.assertRaises(TypeError):
            fixed_present_value(
                "100", periodic_rate=Decimal("0.05"), periods=2  # type: ignore[arg-type]
            )
        with self.assertRaises(TypeError):
            fixed_present_value(
                Decimal("100"), periodic_rate=0.05, periods=2  # type: ignore[arg-type]
            )
        with self.assertRaises(TypeError):
            fixed_present_value(
                Decimal("100"), periodic_rate=Decimal("0.05"), periods=1.5  # type: ignore[arg-type]
            )
        with self.assertRaises(TypeError):
            fixed_present_value(
                Decimal("100"), periodic_rate=Decimal("0.05"), periods=True
            )

    def test_invalid_amounts(self) -> None:
        for amount in ("-1", "NaN", "Infinity", "-Infinity"):
            with self.subTest(amount=amount):
                with self.assertRaises(ValueError):
                    fixed_present_value(
                        Decimal(amount),
                        periodic_rate=Decimal("0.05"),
                        periods=2,
                    )

    def test_invalid_rates_even_at_zero_horizon(self) -> None:
        for rate in ("-1", "-1.01", "NaN", "Infinity", "-Infinity"):
            with self.subTest(rate=rate):
                with self.assertRaises(ValueError):
                    fixed_present_value(
                        Decimal("100"),
                        periodic_rate=Decimal(rate),
                        periods=0,
                    )

    def test_negative_horizon(self) -> None:
        with self.assertRaises(ValueError):
            fixed_present_value(
                Decimal("100"), periodic_rate=Decimal("0.05"), periods=-1
            )

    def test_discount_direction(self) -> None:
        low_rate = fixed_present_value(
            Decimal("100"), periodic_rate=Decimal("0.03"), periods=2
        )
        high_rate = fixed_present_value(
            Decimal("100"), periodic_rate=Decimal("0.07"), periods=2
        )
        longer = fixed_present_value(
            Decimal("100"), periodic_rate=Decimal("0.03"), periods=3
        )
        self.assertLess(high_rate, low_rate)
        self.assertLess(longer, low_rate)

    def test_nonterminating_reference(self) -> None:
        with localcontext() as context:
            context.prec = 60
            context.traps[Inexact] = False
            expected = Decimal("100") / Decimal("3")
            actual = fixed_present_value(
                Decimal("100"), periodic_rate=Decimal("2"), periods=1
            )
            self.assertLessEqual(abs(actual - expected), Decimal("1e-36"))

    def test_repetition_and_order_independence(self) -> None:
        rates = [Decimal("0.03"), Decimal("0.07")]
        first = [
            fixed_present_value(
                Decimal("1000"), periodic_rate=r, periods=2
            )
            for r in rates
        ]
        second = [
            fixed_present_value(
                Decimal("1000"), periodic_rate=r, periods=2
            )
            for r in reversed(rates)
        ]
        self.assertEqual(first, list(reversed(second)))
        self.assertEqual(
            first[0],
            fixed_present_value(
                Decimal("1000"), periodic_rate=rates[0], periods=2
            ),
        )

    def test_caller_context_preserved_on_success(self) -> None:
        reference = fixed_present_value(
            Decimal("1000"), periodic_rate=Decimal("0.037"), periods=17
        )
        with localcontext() as outer:
            outer.prec = 6
            outer.rounding = ROUND_DOWN
            outer.Emin = -9
            outer.Emax = 9
            outer.traps[Inexact] = True
            outer.flags[Inexact] = True
            flags_before = dict(outer.flags)
            traps_before = dict(outer.traps)
            settings_before = (
                outer.prec, outer.rounding, outer.Emin, outer.Emax,
                outer.capitals, outer.clamp,
            )
            actual = fixed_present_value(
                Decimal("1000"), periodic_rate=Decimal("0.037"), periods=17
            )
            self.assertEqual(actual, reference)
            self.assertIs(getcontext(), outer)
            self.assertEqual(dict(outer.flags), flags_before)
            self.assertEqual(dict(outer.traps), traps_before)
            self.assertEqual(
                (
                    outer.prec, outer.rounding, outer.Emin, outer.Emax,
                    outer.capitals, outer.clamp,
                ),
                settings_before,
            )

    def test_context_restored_after_arithmetic_failure(self) -> None:
        with localcontext() as outer:
            flags_before = dict(outer.flags)
            traps_before = dict(outer.traps)
            with self.assertRaises(Overflow):
                fixed_present_value(
                    Decimal("1000"),
                    periodic_rate=Decimal("1e999999"),
                    periods=2,
                )
            self.assertIs(getcontext(), outer)
            self.assertEqual(dict(outer.flags), flags_before)
            self.assertEqual(dict(outer.traps), traps_before)


if __name__ == "__main__":
    unittest.main()
```

## 3.13.8 Prove a Test Can Detect a Defect

In a temporary copy of the Section 3.12 module, change the result calculation from division by growth to multiplication by growth.

Run the suite against that temporary copy. The independent known-value test must fail: 125 multiplied by 1.25 is 156.25, whereas the documented present value is 100.

Restore the correct implementation and confirm the suite passes. Keep the canonical manuscript unchanged.

This is a small manual mutation exercise. It demonstrates that selected tests detect one consequential defect; it is not a complete mutation-testing campaign.

## 3.13.9 Do Not Mirror the Implementation

A test that computes expected = amount / (1 + rate) ** periods using the same policy can reproduce the exact formula error being investigated.

Use simple hand-checkable cases, a separately reasoned reference, and properties that follow from assumptions. A round trip using a shared wrong factor may still pass.

Tests should explain what financial promise failed, not merely that an internal helper was called.

## 3.13.10 Test Isolation and State

Use localcontext for test-specific numerical experiments so one test does not contaminate another.

Avoid relying on a previous method to create data or configure precision. A test should pass when run alone as well as in the complete suite.

Run one selected test with:

```bash
python3 -m unittest -v test_financial_functions.TestPresentValue.test_known_values
```

On Windows, replace python3 with py. A test depending on execution order is an unresolved reliability problem.

## 3.13.11 Interpreting Failures and Errors

A failure usually means an assertion's expectation was not satisfied. An error means an unexpected exception interrupted execution. Both require investigation.

First establish that the expected value matches the documented model. Then inspect units, signs, horizon, numerical policy, and implementation.

Do not loosen tolerances merely to obtain a green result. If a tolerance changes, record the numerical justification and confirm it does not conceal a financial defect.

## 3.13.12 Software Tests and Model Review

A passing suite supports the implemented contract for selected cases. It cannot establish that the discount rate is appropriate, input data is correct, or the model fits a real product.

Code coverage can reveal unexecuted paths but cannot prove useful assertions or financial correctness. Static checking, doctests, unit tests, numerical analysis, and model review provide different evidence.

The current suite has no network, production data, or external service dependencies. More extensive engineering validation is developed in Chapter 20.

## 3.13.14 Troubleshooting Guide

| Symptom | Likely cause | Correction |
|---|---|---|
| No tests discovered | Names or command are wrong | Use test_ methods and the stated module |
| ImportError for reproducibility_lab | Prerequisite file missing or misplaced | Save both files in the same working directory |
| Decimal test differs slightly | Precision or rounding expectation differs | Review the policy and justified tolerance |
| Invalid call is accepted | Runtime guard missing | Implement the documented boundary check |
| Suite passes but hand calculation fails | Expected value mirrors wrong code | Add independent known values |
| Test passes only after another test | Shared state or ordering dependency | Localize setup and context |
| Wrong defect is reported as expected failure | Exception scope is too broad | Keep assertRaises around the intended operation |
| More digits are accepted without explanation | Tolerance was weakened | Document the numerical rationale |

## 3.13.15 Key Takeaways

Test the financial contract with independent known values, boundary cases, explicit failures, and numerical-state checks.

Passing tests are evidence with a defined scope. Combine them with financial assumptions and model review, and demonstrate that consequential defects are actually detected.
