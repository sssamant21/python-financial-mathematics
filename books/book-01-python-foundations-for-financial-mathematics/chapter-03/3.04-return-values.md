## 3.4.1 Purpose

Section 3.3 explained how arguments supply inputs to function parameters. This section explains how an ordinary synchronous function supplies an output to its caller.

A financial calculation becomes reusable when its result can be assigned, compared, tested, or passed into another calculation. Displaying a number is useful for a person; returning a value makes it available to the rest of the program.

The examples use ordinary functions, not generators or asynchronous functions. Detailed function composition belongs in Section 3.11, pure functions in Section 3.12, and systematic testing in Section 3.13.

## 3.4.2 Learning Objectives

After this section, you should be able to:

1. Return a calculated value and capture it at the call site.
2. Explain the difference between returning, printing, and formatting.
3. Recognize explicit and implicit `None` results.
4. Explain how an early return changes function execution.
5. Preserve meaningful zero values and distinguish them from missing results.
6. Describe a financial output's units, valuation time, numerical representation, and failure behavior.
7. Run a small verification lab covering successful and unsuccessful calculation paths.

## 3.4.3 A First Returned Financial Value

For a single amount growing at a constant effective rate per period:

```math
FV = PV(1+r)^n.
```

Here, `PV` is the amount at period 0, `r` is the effective rate per modeled period, and `n` is the number of matching periods. There are no intermediate contributions or withdrawals.

```python
from decimal import Decimal


def future_value(present_value, periodic_rate, periods):
    amount = present_value * (Decimal("1") + periodic_rate) ** periods
    return amount


result = future_value(
    Decimal("1000"),
    Decimal("0.05"),
    2,
)

assert result == Decimal("1102.50")
print(f"Future value: {result:.2f}")
```

Expected display:

```text
Future value: 1102.50
```

The expression in the call evaluates to a Decimal result. Assignment binds `result` to that returned object. The local name `amount` need not match the caller's name `result`.

This introductory function assumes already validated Decimal amounts and rates, with a nonnegative integer period count. A guarded version appears in the lab.

## 3.4.4 Return an Expression Directly

A temporary variable is optional:

```python
def net_cash_flow(inflow, outflow):
    return inflow - outflow


net_amount = net_cash_flow(Decimal("1200"), Decimal("950"))
assert net_amount == Decimal("250")
```

Both inputs must represent amounts in the same currency and accounting period. A negative net cash flow is a valid signed result, not automatically an error.

Choose a local variable when it helps explain an intermediate calculation. A one-expression return is appropriate when its meaning is already clear.

## 3.4.5 Printing Does Not Supply the Printed Amount to the Caller

Consider this intentionally incomplete implementation:

```python
def display_net_cash_flow(inflow, outflow):
    print(inflow - outflow)


captured = display_net_cash_flow(Decimal("1200"), Decimal("950"))
assert captured is None
```

The screen shows `250`, but `captured` is `None`. The function reaches its end without returning the calculated amount.

A calculation and its presentation can be written separately:

```python
net_amount = net_cash_flow(Decimal("1200"), Decimal("950"))
print(f"Net cash flow: {net_amount:.2f}")
```

| Operation | Purpose | Result available to caller |
|---|---|---|
| `return amount` | Supply a calculation result | The object represented by `amount` |
| `print(amount)` | Write a display | The call to `print` returns `None` |
| `f"{amount:.2f}"` | Create formatted text | A string |
| Function reaches its end | Finish without an explicit result | `None` |

A function may both print and return, but callers should not need to parse its display to recover its financial result.

## 3.4.6 Explicit and Implicit None

These ordinary functions all return `None` on their executed paths:

```python
def no_result_explicit():
    return None


def no_result_bare():
    return


def no_result_implicit():
    pass


assert no_result_explicit() is None
assert no_result_bare() is None
assert no_result_implicit() is None
```

A bare `return` exits immediately. Falling off the end exits only after the preceding statements finish.

Use `None` deliberately when absence is part of the output contract. Do not let it appear accidentally because a branch forgot to return.

## 3.4.7 A Missing Return Can Hide in a Branch

This example contains a deliberate defect:

```python
def positive_gain_only(starting_amount, ending_amount):
    if ending_amount > starting_amount:
        return ending_amount - starting_amount


assert positive_gain_only(Decimal("100"), Decimal("120")) == Decimal("20")
assert positive_gain_only(Decimal("100"), Decimal("100")) is None
assert positive_gain_only(Decimal("100"), Decimal("80")) is None
```

If the intended operation is signed investment gain, the unconditional implementation is clearer:

```python
def investment_gain(starting_amount, ending_amount):
    return ending_amount - starting_amount
```

It returns positive gain, zero gain, or a negative loss under the same output meaning. This amount-based illustration excludes intervening cash flows; it is not a total-return calculation.

## 3.4.8 Return Ends the Current Invocation

When a `return` executes, the ordinary function stops executing its normal body and supplies its result to the caller. Statements after it on that path are not reached.

```python
def target_reached(balance, target):
    return balance >= target


assert target_reached(Decimal("100"), Decimal("100")) is True
assert target_reached(Decimal("99"), Decimal("100")) is False
```

A return inside a loop exits the whole function, whereas `break` exits only the loop. A `continue` advances to the next loop iteration.

Python also executes applicable `finally` cleanup before completing a return. Exception handling is developed later; avoid putting return statements in cleanup blocks because they can replace a pending result or suppress an exception.

## 3.4.9 Early Returns and Financial Boundaries

An early return can express a meaningful boundary:

```python
def first_target_period(balances, target):
    for period, balance in enumerate(balances):
        if balance >= target:
            return period
    return None


assert first_target_period(
    [Decimal("100"), Decimal("110"), Decimal("121")],
    Decimal("110"),
) == 1
```

The list contains period-end balances beginning with the period-0 balance. The output is the first qualifying period index. `None` means the target is absent from the supplied observations, not that it can never be reached.

An empty collection also returns `None` under this contract. The example assumes finite Decimal balances and a finite Decimal target already validated at the boundary.

## 3.4.10 Zero Is Not Missing

The target may already be met at period 0:

```python
period = first_target_period([Decimal("100")], Decimal("100"))
assert period == 0

if period is None:
    print("Target not reached in supplied observations.")
else:
    print(f"First target period: {period}")
```

Using `if not period:` here would conflate period 0 with absence. The same problem occurs when zero cash flow, zero return, or zero remaining balance is a valid financial result.

Use `is None` when testing this explicit absence marker.

## 3.4.11 Return Values Have Financial Meaning

A numeric output is incomplete without its interpretation.

| Contract element | Example for future value |
|---|---|
| Quantity | Accumulated amount |
| Time | End of the specified number of periods |
| Currency | Same currency as the input principal |
| Rate convention | Constant effective rate per period |
| Cash-flow timing | Principal at period 0; no later cash flows |
| Representation | Decimal |
| Numerical policy | Arithmetic follows the active Decimal context |
| Quantization | No explicit rounding to a currency increment |
| Display | Applied by the caller |
| Failure | Invalid supported inputs raise an exception |

Two functions may return the same number while representing different valuation dates or currencies. Matching Python types alone cannot establish financial compatibility.

## 3.4.12 Preserve Numeric Results for Further Calculation

```python
amount = future_value(Decimal("1000"), Decimal("0.05"), 2)
display_amount = f"{amount:.2f}"

assert isinstance(amount, Decimal)
assert isinstance(display_amount, str)
assert amount - Decimal("1000") == Decimal("102.50")
```

Formatting creates text. Return the numeric object from the computational function and format it at the reporting boundary.

Decimal arithmetic has finite precision governed by its context. Returning a Decimal does not make every calculation exact or automatically establish a business rounding policy. If a contract requires cent-level quantization, specify where it occurs and which rounding mode applies.

## 3.4.13 One Returned Object Can Contain Several Results

Python can package related values in a tuple:

```python
def investment_summary(starting_amount, ending_amount):
    gain = ending_amount - starting_amount
    return ending_amount, gain


ending_amount, gain = investment_summary(
    Decimal("1000"),
    Decimal("1100"),
)
assert ending_amount == Decimal("1100")
assert gain == Decimal("100")
```

The function returns one tuple containing two objects. The caller unpacks it into two names. Order is part of this interface.

A dictionary can name the fields:

```python
def named_investment_summary(starting_amount, ending_amount):
    return {
        "ending_amount": ending_amount,
        "gain": ending_amount - starting_amount,
    }


summary = named_investment_summary(Decimal("1000"), Decimal("1100"))
assert summary["gain"] == Decimal("100")
```

Chapter 4 develops these structures in detail. Keep an output shape stable across successful paths: callers should not unexpectedly receive a number for one success and a display string for another.

## 3.4.14 Returning an Object Does Not Automatically Copy It

```python
def same_schedule(cash_flows):
    return cash_flows


original = [Decimal("100"), Decimal("200")]
returned = same_schedule(original)
assert returned is original

returned.append(Decimal("300"))
assert len(original) == 3
```

The function returns the same list object. A caller can therefore observe later mutations through either reference. Output ownership and mutation rules matter for shared cash-flow schedules.

Decimal objects are immutable, but a list containing Decimal objects remains mutable. Copying and pure-function design are developed later.

## 3.4.15 Failure Should Not Masquerade as a Financial Result

Returning zero for an invalid calculation can produce a plausible but incorrect valuation. Returning an error string from a normally numeric function also forces callers to handle incompatible output types.

This section's guarded calculation raises `TypeError` for unsupported input representations and `ValueError` for unsupported values. It returns a Decimal when the calculation succeeds. An exception means no normal result is delivered on that path.

An optional result such as `first_target_period` uses `None` for a documented, nonexceptional absence. Choose the contract based on the operation's meaning.

## 3.4.16 Hands-On Lab — Verify a Return Contract

Save the following complete program as `return_values_lab.py`. It uses only the Python standard library.

The guarded model supports finite, nonnegative Decimal principal; a finite Decimal effective periodic rate greater than -100%; and an integer period count from 0 through 1000. Booleans are rejected as period counts even though Python treats `bool` as a subclass of `int`.

The horizon cap is a teaching model's explicit operating limit, not a universal financial restriction. Decimal overflow and other arithmetic signals remain governed by the active context.

```python
from decimal import Decimal


def future_value(present_value, periodic_rate, periods):
    if not isinstance(present_value, Decimal):
        raise TypeError("present_value must be Decimal")
    if not isinstance(periodic_rate, Decimal):
        raise TypeError("periodic_rate must be Decimal")
    if not isinstance(periods, int) or isinstance(periods, bool):
        raise TypeError("periods must be an integer, excluding bool")

    if not present_value.is_finite() or present_value < 0:
        raise ValueError("present_value must be finite and nonnegative")
    if not periodic_rate.is_finite() or periodic_rate <= Decimal("-1"):
        raise ValueError("periodic_rate must be finite and greater than -1")
    if not 0 <= periods <= 1000:
        raise ValueError("periods must be between 0 and 1000")

    return present_value * (Decimal("1") + periodic_rate) ** periods


def first_target_period(balances, target):
    for period, balance in enumerate(balances):
        if balance >= target:
            return period
    return None


def printed_amount(amount):
    print(f"Displayed amount: {amount:.2f}")


amount = future_value(Decimal("1000"), Decimal("0.05"), 2)
assert isinstance(amount, Decimal)
assert amount == Decimal("1102.50")

assert future_value(Decimal("1000"), Decimal("0"), 10) == Decimal("1000")
assert future_value(Decimal("1000"), Decimal("0.05"), 0) == Decimal("1000")
assert future_value(Decimal("0"), Decimal("0.05"), 10) == Decimal("0")
assert future_value(Decimal("1000"), Decimal("-0.10"), 1) == Decimal("900")

assert first_target_period([Decimal("100")], Decimal("100")) == 0
assert first_target_period(
    [Decimal("100"), Decimal("110"), Decimal("121")], Decimal("110")
) == 1
assert first_target_period([Decimal("100")], Decimal("101")) is None
assert first_target_period([], Decimal("100")) is None

captured = printed_amount(amount)
assert captured is None

invalid_cases = [
    (1000, Decimal("0.05"), 2, TypeError),
    (Decimal("1000"), 0.05, 2, TypeError),
    (Decimal("1000"), Decimal("0.05"), True, TypeError),
    (Decimal("1000"), Decimal("0.05"), 2.5, TypeError),
    (Decimal("-1"), Decimal("0.05"), 2, ValueError),
    (Decimal("NaN"), Decimal("0.05"), 2, ValueError),
    (Decimal("1000"), Decimal("Infinity"), 2, ValueError),
    (Decimal("1000"), Decimal("-1"), 2, ValueError),
    (Decimal("1000"), Decimal("-1.01"), 2, ValueError),
    (Decimal("1000"), Decimal("0.05"), -1, ValueError),
    (Decimal("1000"), Decimal("0.05"), 1001, ValueError),
]

for principal, rate, periods, expected_error in invalid_cases:
    try:
        future_value(principal, rate, periods)
    except expected_error:
        pass
    else:
        raise AssertionError("Expected input rejection")

print(f"Computed future value: {amount:.2f}")
print("PASS: return-value checks")
```

Run on Windows:

```powershell
py return_values_lab.py
```

Run on macOS or Linux:

```bash
python3 return_values_lab.py
```

Expected output:

```text
Displayed amount: 1102.50
Computed future value: 1102.50
PASS: return-value checks
```

Run normally, without Python's `-O` option, because optimization removes these instructional assertions. External input rejection uses exceptions and does not depend on assertions.

The lab checks known values and output semantics; it does not certify the model for production financial decisions.

## 3.4.18 Common Failure Patterns

| Symptom | Likely cause | Correction |
|---|---|---|
| Calculation displays correctly but assignment contains None | Function prints and falls through | Return the numeric calculation |
| Only some inputs produce a result | Missing return on a branch | Review every normal exit path |
| Period 0 is reported as absent | Truthiness used for an optional index | Check `is None` |
| Invalid input becomes a zero valuation | Error encoded as a valid numeric value | Use explicit failure behavior |
| Later arithmetic fails on formatted output | Function returns display text | Preserve numeric output |
| Caller data changes unexpectedly | Returned mutable object is shared | Document ownership or design an appropriate copy |
| Number is correct but interpretation is wrong | Currency, timing, or rate convention omitted | Specify the financial output contract |

## 3.4.19 Key Takeaways

A return value connects a function's computation to its caller. A printed value serves a different purpose. Ordinary functions that finish without an explicit value return None, and every successful path should satisfy the documented output contract.

Financial outputs need meaning beyond their Python type: quantity, time, units, conventions, numerical policy, and failure behavior. Preserve valid zero values, keep display formatting at the reporting boundary, and verify boundary cases.
