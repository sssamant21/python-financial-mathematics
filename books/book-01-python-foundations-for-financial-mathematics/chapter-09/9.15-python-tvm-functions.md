## Learning objectives

Build a coherent, reusable Python API for the time value of money (TVM); enforce rate and time units; implement present value, future value, nominal/effective conversion, continuous compounding, inverse rate and time solvers, and net present value; and verify cross-function identities with automated tests.

## Why a reusable TVM module?

Earlier sections introduced formulas individually. A reusable module prevents repeated ad hoc calculations and makes financial assumptions explicit. Functions should accept a clearly defined rate convention, use consistent units, reject invalid inputs, and produce results that can be checked against known examples and inverse identities.

This chapter uses **decimal rates**: 6% is entered as `0.06`, not `6`. Times are **years** unless a function explicitly states otherwise. The `frequency` argument is the positive integer number of equal compounding periods per year. All monetary amounts are illustrative signed floating-point values, not a production ledger's fixed-point accounting amounts.

## API and mathematical contract

| Function | Purpose | Mathematical contract |
|---|---|---|
| `future_value(P,j,t,m)` | Discrete accumulation | \(P(1+j/m)^{mt}\) |
| `present_value(F,j,t,m)` | Discrete discounting | \(F(1+j/m)^{-mt}\) |
| `continuous_future_value(P,r,t)` | Continuous accumulation | \(Pe^{rt}\) |
| `continuous_present_value(F,r,t)` | Continuous discounting | \(Fe^{-rt}\) |
| `effective_annual(j,m)` | Nominal to effective | \((1+j/m)^m-1\) |
| `nominal_from_effective(e,m)` | Effective to nominal | \(m[(1+e)^{1/m}-1]\) |
| `solve_nominal_rate(P,F,t,m)` | Implied nominal annual rate | \(m[(F/P)^{1/(mt)}-1]\) |
| `solve_years(P,F,j,m)` | Implied nonnegative years | \(\ln(F/P)/[m\ln(1+j/m)]\) |
| `net_present_value(flows,j,m)` | Value dated signed cash flows | \(\sum_i C_i(1+j/m)^{-mt_i}\) |

The discrete formulas use the mathematical extension to fractional years. Real contractual posting rules may restrict accrual to complete periods or require an explicitly chosen stub-period convention.

## Design principles

**1. One rate convention per function.** The discrete functions accept a nominal annual rate and frequency. Continuous functions accept a continuously compounded annual rate. Do not mix them without conversion.

**2. Explicit time coordinates.** Every cash flow in the NPV function is a `(year, amount)` pair, including any initial investment at year zero. The function does not silently subtract a separate initial cost.

**3. Signed cash flows.** Outflows are negative and inflows positive. This convention makes project comparisons and reconciliation transparent.

**4. Reversible calculations.** Where the values are representable, discounting an accumulated amount should recover the initial amount. Solving a rate and applying it back to the same model should recover the final balance.

**5. Safe failure modes.** Reject booleans masquerading as numbers, nonfinite values, unsupported growth factors, nonpositive frequencies, and impossible inverse problems. Avoid quietly returning a meaningless result.

## Worked example: investment growth

For 1,000 USD, 6% nominal annually, monthly conversion, and two years:

\[
FV=1000(1+0.06/12)^{24}\approx1127.1598.
\]

The balance is approximately **1,127.16 USD**. Discounting the unrounded future value with the same rate and horizon recovers 1,000 USD.

## Worked example: net present value

An illustrative project costs 1,000 USD immediately and returns 1,100 USD after one year. With a 10% effective annual discount rate:

\[
NPV=-1000+\frac{1100}{1.10}=0.
\]

The project breaks even at that modeled discount rate. This is a valuation identity, not a decision rule that accounts for uncertainty, taxes, or capital constraints.

## Numerical engineering notes

Use `math.log1p` for \(\ln(1+x)\) when \(x\) is small, `math.expm1` for \(e^x-1\), and `math.fsum` to reduce summation error across discounted cash flows. A positive finite mathematical accumulation factor may still overflow or underflow in binary floating-point; this implementation raises errors for those cases. The API does not attempt high-precision currency accounting, vectorization, a yield curve, or day-count-aware schedules. Those are deliberate future extensions.

The NPV function accepts an iterable of `(time, amount)` pairs and retains individual event dates. An empty iterable has a modeled NPV of zero. Negative cash-flow times are rejected because this educational API values nonnegative dates relative to time zero.

```python
"""A reusable, standard-library time-value-of-money module."""
import math
from numbers import Real
import unittest

def _finite(value, label):
    if isinstance(value, bool) or not isinstance(value, Real):
        raise TypeError(f"{label} must be real")
    try:
        value = float(value)
    except OverflowError as exc:
        raise ValueError(f"{label} outside float range") from exc
    if not math.isfinite(value):
        raise ValueError(f"{label} must be finite")
    return value

def _years(value):
    t = _finite(value, "years")
    if t < 0:
        raise ValueError("years must be nonnegative")
    return t

def _frequency(value):
    if isinstance(value, bool) or not isinstance(value, int):
        raise TypeError("frequency must be an integer")
    if value <= 0:
        raise ValueError("frequency must be positive")
    return value

def _log_factor(rate, frequency):
    r = _finite(rate, "nominal annual rate")
    m = _frequency(frequency)
    periodic = r / m
    if r != 0 and periodic == 0:
        raise ValueError("periodic rate underflow")
    if periodic <= -1:
        raise ValueError("periodic growth factor must be positive")
    result = m * math.log1p(periodic)
    if not math.isfinite(result):
        raise ValueError("log growth outside float range")
    return result

def _scale(amount, exponent):
    amount = _finite(amount, "amount")
    if not math.isfinite(exponent):
        raise ValueError("exponent outside float range")
    try:
        factor = math.exp(exponent)
    except OverflowError as exc:
        raise ValueError("growth factor overflow") from exc
    if factor == 0 or not math.isfinite(factor):
        raise ValueError("growth factor underflow or overflow")
    result = amount * factor
    if not math.isfinite(result) or (amount != 0 and result == 0):
        raise ValueError("scaled amount underflow or overflow")
    return result

def future_value(present, nominal_rate, years, frequency=1):
    return _scale(present, _years(years) * _log_factor(nominal_rate, frequency))

def present_value(future, nominal_rate, years, frequency=1):
    return _scale(future, -_years(years) * _log_factor(nominal_rate, frequency))

def continuous_future_value(present, continuous_rate, years):
    return _scale(present, _finite(continuous_rate, "continuous rate") * _years(years))

def continuous_present_value(future, continuous_rate, years):
    return _scale(future, -_finite(continuous_rate, "continuous rate") * _years(years))

def effective_annual(nominal_rate, frequency=1):
    try:
        value = math.expm1(_log_factor(nominal_rate, frequency))
    except OverflowError as exc:
        raise ValueError("effective rate overflow") from exc
    if not math.isfinite(value) or value <= -1:
        raise ValueError("effective rate outside supported range")
    return value

def nominal_from_effective(effective_rate, frequency=1):
    e = _finite(effective_rate, "effective rate")
    m = _frequency(frequency)
    if e <= -1:
        raise ValueError("effective annual growth must be positive")
    result = m * math.expm1(math.log1p(e) / m)
    if not math.isfinite(result):
        raise ValueError("nominal rate outside supported range")
    return result

def _log_balance_ratio(present, future):
    p, f = _finite(present, "present"), _finite(future, "future")
    if p == 0 or f == 0 or (p > 0) != (f > 0):
        raise ValueError("nonzero balances must have matching signs")
    return math.log(abs(f)) - math.log(abs(p))

def solve_nominal_rate(present, future, years, frequency=1):
    t = _years(years)
    m = _frequency(frequency)
    if t == 0:
        raise ValueError("rate is not identifiable at zero horizon")
    result = m * math.expm1(_log_balance_ratio(present, future) / (m*t))
    if not math.isfinite(result) or result / m <= -1:
        raise ValueError("implied rate outside supported range")
    return result

def solve_years(present, future, nominal_rate, frequency=1):
    growth = _log_factor(nominal_rate, frequency)
    change = _log_balance_ratio(present, future)
    if growth == 0:
        raise ValueError("zero growth gives no unique finite time")
    years = change / growth
    if not math.isfinite(years) or years < 0:
        raise ValueError("no finite nonnegative solution")
    return years

def net_present_value(cash_flows, nominal_rate, frequency=1):
    """Sequence of (time_in_years, signed_cash_flow) pairs."""
    growth = _log_factor(nominal_rate, frequency)
    terms = []
    for year, amount in cash_flows:
        terms.append(_scale(amount, -_years(year) * growth))
    total = math.fsum(terms)
    if not math.isfinite(total):
        raise ValueError("NPV outside supported range")
    return total

class TVMTests(unittest.TestCase):
    def test_01_future_value(self):
        self.assertAlmostEqual(future_value(1000, .1, 2), 1210)
    def test_02_present_value(self):
        self.assertAlmostEqual(present_value(1210, .1, 2), 1000)
    def test_03_monthly(self):
        self.assertAlmostEqual(future_value(1000, .06, 2, 12),
                               1000*(1+.06/12)**24)
    def test_04_continuous(self):
        f = continuous_future_value(1000, .04, 3)
        self.assertAlmostEqual(continuous_present_value(f, .04, 3), 1000)
    def test_05_rate_conversion(self):
        self.assertAlmostEqual(nominal_from_effective(
            effective_annual(.06, 12), 12), .06)
    def test_06_solve_rate_and_time(self):
        self.assertAlmostEqual(solve_nominal_rate(1000, 1210, 2), .1)
        self.assertAlmostEqual(solve_years(1000, 1210, .1), 2)
    def test_07_npv_and_signed_flows(self):
        self.assertAlmostEqual(net_present_value(
            [(0, -1000), (1, 1100)], .1), 0, places=9)
        self.assertAlmostEqual(future_value(-100, .1, 1), -110)
    def test_08_validation(self):
        with self.assertRaises(ValueError):
            future_value(100, -1, 2)
        with self.assertRaises(TypeError):
            future_value(100, .05, 2, 12.0)
        with self.assertRaises(ValueError):
            solve_years(100, 110, 0)
        with self.assertRaises(ValueError):
            solve_nominal_rate(100, 110, 0)
        with self.assertRaises(ValueError):
            net_present_value([(0, 100), (-1, 200)], .05)
        with self.assertRaises(TypeError):
            effective_annual(True, 12)

if __name__ == "__main__":
    print(f"FV: {future_value(1000, .06, 2, 12):,.2f}")
    print(f"EAR: {effective_annual(.06, 12):.6%}")
    unittest.main(verbosity=2)
```

## Exercises with answers

1. **Future value:** What is 2,000 USD after two years at 5% effective annually? **Answer:** \(2000(1.05)^2=2205\) USD.
2. **Present value:** What is 2,205 USD due in two years worth at 5% effective annually? **Answer:** 2,000 USD.
3. **Rate conversion:** Convert 6% nominal monthly into an effective annual rate. **Answer:** \((1+.06/12)^{12}-1\approx6.16778119\%\).
4. **Continuous:** Compute the value of 500 USD after three years at 4% continuous. **Answer:** \(500e^{0.12}\approx563.75\) USD.
5. **NPV:** Value a 100 USD cost now and 110 USD received after one year at 10% effective annual. **Answer:** Zero NPV.
6. **Design:** Why include the initial cost as a dated negative cash flow? **Answer:** It prevents double subtraction, preserves a complete audit trail, and makes valuation dates explicit.
