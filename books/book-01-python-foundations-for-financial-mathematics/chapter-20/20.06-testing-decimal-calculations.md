## Learning objectives

Construct decimal values deliberately; specify precision, rounding and scale; test exact and rounded results; check invalid and nonfinite inputs; and distinguish decimal representation from financial model correctness.

## 1. Why test decimal calculations?

Decimal arithmetic can represent decimal inputs such as 0.10 exactly, making it useful for some accounting, reporting and settlement calculations. It does not make every division exact, choose the correct financial convention, or eliminate the need to test rounding and boundaries.

A financial contract should specify currency, units, calculation precision, rounding mode and rounding point. Different legal or business contexts can require different policies; the examples below use a teaching policy, not a universal standard.

## 2. Construct from text

Use `Decimal("0.10")` when the supplied value is decimal text. Constructing `Decimal` from a binary float preserves the float's exact value, which can differ from the intended decimal fraction.

~~~python
from decimal import Decimal

print(Decimal("0.1"))
print(Decimal(0.1))
~~~

Both are Decimal objects, but their values differ because the float was already approximated.

## 3. Precision and scale

Decimal context precision limits significant digits in arithmetic. Scale concerns decimal places in a representation or fixed-decimal contract; they are not the same. `quantize` can apply a specified exponent and rounding mode.

A division such as 1/3 is non-terminating in decimal and must be rounded at finite precision. Record the active context and do not assume constructing Decimal makes all calculations exact.

## 4. Rounding modes

For this chapter's examples, round to two decimal places with **ROUND_HALF_EVEN**:

- 1.005 → 1.00.
- 1.015 → 1.02.

With **ROUND_HALF_UP**, 1.005 → 1.01. The appropriate policy depends on the use case and contract. Decide when rounding occurs: rounding each intermediate line can differ from rounding a final total.

## 5. Known-value tests

For cash amount 100.00 and rate .05, one-period simple interest is 5.0000 before any presentation rounding. A price moving from 100.00 to 101.50 has simple return .015, or 1.5%.

Test the numerical value and, if the output contract requires a particular exponent or text format, test that representation separately. Decimal equality treats 1.0 and 1.00 as numerically equal even though their exponents differ.

## 6. Invalid and nonfinite values

Define behavior for malformed strings, NaN, infinity, missing values, zero denominators and invalid types. The reference example accepts decimal strings, rejects nonfinite values, and raises explicit exceptions.

Decimal contexts also contain flags and traps. A trapped signal can raise an exception; flags can indicate rounded or inexact operations. Tests should check these where the application contract depends on them.

## 7. Context isolation

Use `localcontext` to define precision and rounding for a calculation without intentionally changing the caller's active context. Record the context and input representation for reproducibility.

Finite precision and exponent limits can still cause decimal exceptions. The example does not claim to support every possible magnitude or replace a full accounting policy.

## 8. Independent benchmarks and invariants

Derive expected values independently: 100×.05=5; 101.50/100−1=.015. Test that doubling principal doubles simple interest under a fixed rate, and that zero rate gives zero interest.

Do not compute expected results using the same function under test. Unit tests do not establish that a rate, currency, timing or rounding policy is appropriate for a real instrument.

## 9. Reference implementation

Save as `decimal_calculation_tests.py`. It uses only the Python standard library and fixes the local arithmetic context for its examples.

~~~python
from decimal import Decimal, InvalidOperation, ROUND_HALF_EVEN, ROUND_HALF_UP, localcontext
import unittest

def decimal_text(value):
    if not isinstance(value,str) or not value.strip():
        raise ValueError("nonempty decimal text required")
    try:
        number=Decimal(value)
    except InvalidOperation as exc:
        raise ValueError("invalid decimal text") from exc
    if not number.is_finite():
        raise ValueError("finite decimal required")
    return number

def simple_interest(principal,rate):
    p,r=decimal_text(principal),decimal_text(rate)
    with localcontext() as ctx:
        ctx.prec=28
        ctx.rounding=ROUND_HALF_EVEN
        return p*r

def simple_return(start,end):
    a,b=decimal_text(start),decimal_text(end)
    if a<=0 or b<0:
        raise ValueError("positive start and nonnegative end required")
    with localcontext() as ctx:
        ctx.prec=28
        ctx.rounding=ROUND_HALF_EVEN
        return b/a-Decimal("1")

def round_cents(value,mode):
    amount=decimal_text(value)
    if mode not in (ROUND_HALF_EVEN,ROUND_HALF_UP):
        raise ValueError("unsupported rounding mode")
    with localcontext() as ctx:
        ctx.prec=28
        return amount.quantize(Decimal(".01"),rounding=mode)

class DecimalTests(unittest.TestCase):
    def test_interest(self):
        self.assertEqual(simple_interest("100.00",".05"),Decimal("5.0000"))
    def test_zero_rate(self):
        self.assertEqual(simple_interest("100","0"),Decimal("0"))
    def test_scaling(self):
        self.assertEqual(simple_interest("200",".05"),2*simple_interest("100",".05"))
    def test_return(self):
        self.assertEqual(simple_return("100.00","101.50"),Decimal(".015"))
    def test_zero_end(self):
        self.assertEqual(simple_return("100","0"),Decimal("-1"))
    def test_half_even_down(self):
        self.assertEqual(round_cents("1.005",ROUND_HALF_EVEN),Decimal("1.00"))
    def test_half_even_up(self):
        self.assertEqual(round_cents("1.015",ROUND_HALF_EVEN),Decimal("1.02"))
    def test_half_up(self):
        self.assertEqual(round_cents("1.005",ROUND_HALF_UP),Decimal("1.01"))
    def test_exponent(self):
        self.assertEqual(round_cents("1",ROUND_HALF_EVEN).as_tuple().exponent,-2)
    def test_zero_start(self):
        with self.assertRaises(ValueError): simple_return("0","1")
    def test_nan(self):
        with self.assertRaises(ValueError): decimal_text("NaN")
    def test_infinity(self):
        with self.assertRaises(ValueError): decimal_text("Infinity")
    def test_wrong_type(self):
        with self.assertRaises(ValueError): decimal_text(0.1)
    def test_bad_mode(self):
        with self.assertRaises(ValueError): round_cents("1","invalid")

if __name__ == "__main__":
    unittest.main(verbosity=2)
~~~

The implementation permits negative principal or rate for simple interest because its example contract does not prohibit them; real contracts must specify their domains. It does not model currency-specific minor units, fees, taxes or dates. Decimal exceptions for extreme values are not comprehensively handled.

## 10. Twelve-step hands-on lab

1. Record the currency, scale, precision, rounding mode and intended rounding point.
2. Compare Decimal constructed from `"0.1"` and from float `0.1`.
3. Calculate simple interest on 100.00 at .05.
4. Independently calculate the 1.5% return for 100→101.50.
5. Compare half-even and half-up rounding of 1.005.
6. Compare numerical equality of 1.0 and 1.00 with their exponents.
7. Test a zero starting price and nonfinite inputs.
8. Test a non-terminating division under two precision settings.
9. Verify a local context does not intentionally alter the caller's configured context.
10. Document where intermediate rounding could change a total.
11. Run the reference tests and retain actual output and Python version.
12. Record unsupported magnitudes, currencies and conventions for later Book 1 QA.

## 12. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Unexpected decimal digits | Decimal constructed from a float | Inspect source representation |
| One-cent mismatch | Different rounding mode or rounding point | Compare documented policies |
| Division differs between environments | Context precision differs | Set and record local context |
| Quantize raises an exception | Precision or exponent constraints | Review supported magnitude and traps |
| Same numeric value has different formatting | Different exponents | Test output representation separately |
| Tests pass but settlement differs | Business or currency convention mismatch | Reconcile against the governing specification |
