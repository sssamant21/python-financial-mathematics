## Learning objectives

Identify financial and numerical boundaries; partition valid and invalid inputs; test values on and around boundaries; handle nonfinite numbers and empty data; and document expected behavior without assuming that a passing test covers every case.

## 1. Why boundaries matter

Defects often appear where a formula changes behavior, a denominator approaches zero, an input becomes invalid or a dataset becomes empty. A typical example is discounting at an annual effective rate r, where the model requires r>−1.

Define the domain before writing tests. A boundary in one model may not be a boundary in another: negative interest rates can be valid, while a zero starting price makes a simple-return ratio undefined.

## 2. Equivalence partitions

Group inputs that should receive the same treatment, then choose representative cases:

| Input | Partition under this section's PV model | Example |
|---|---|---|
| Rate | Valid above −1 | −.05, 0, .10 |
| Rate | Invalid at or below −1 | −1, −1.01 |
| Periods | Nonnegative integers | 0, 1 |
| Periods | Negative or non-integer | −1, 1.5 |
| Cash flow | Finite numeric | −100, 0, 100 |
| Cash flow | Nonfinite or wrong type | NaN, infinity, text |

Test on both sides of a boundary and at the boundary itself. Values close to −1 may be mathematically valid but can still create numerical overflow for large horizons; state numerical limits separately from mathematical domains.

## 3. Zero rate and zero periods

For PV=C/(1+r)ⁿ, r=0 gives PV=C for finite C and valid n. At n=0, PV=C for a valid rate. These are useful known-value tests.

Some formulas, such as annuity expressions divided by r, require an explicit zero-rate limit. Do not assume that an implementation handles a removable singularity unless tested.

## 4. Negative rates and cash flows

At r=−.05, the PV of 95 in one period is 95/.95=100. Rejecting all negative rates would be incorrect for this stated model.

Negative cash flows can represent outflows. For C=−110 and r=.10 for one period, PV=−100. Domain validation should not reject a sign merely because it is negative unless the business contract requires it.

## 5. Return boundaries

For simple return R=(end−start)/start, a positive start is required under this section's contract. An ending value of zero is allowed and gives R=−1. A negative ending asset price is rejected by this example; other financial quantities may have different domains.

A missing value is not zero. Null, empty, malformed and nonfinite values should be handled under the data contract rather than silently coerced.

## 6. Nonfinite values and types

NaN and infinities can propagate through arithmetic and invalidate comparisons. Test them explicitly. Python treats `bool` as a subclass of `int`; the reference contract deliberately rejects booleans as numeric inputs and as period counts.

A production implementation should also define behavior for Decimal values, arrays and other numeric types if they are supported. This instructional implementation accepts only built-in int and float inputs.

## 7. Numerical extremes

Very large exponents can overflow, while tiny values can underflow to zero. A valid mathematical input may be unrepresentable at the chosen precision. Tests should distinguish domain rejection, explicit numerical failure and documented approximation behavior.

The reference code catches exponential overflow and rejects nonfinite results. It does not guarantee detection of every underflow or cancellation case.

## 8. Empty and single-element collections

A function that estimates sample variance generally needs at least two observations under the usual N−1 formula. A cash-flow function may define an empty list as zero or reject it; either behavior must be explicit. This section's `sample_mean` rejects an empty list and accepts one finite value.

Do not infer population uncertainty from one sample or from a constant sample alone.

## 9. Time and market boundaries

Dates at month end, leap days, holidays, timezone transitions and settlement cutoffs need domain-specific rules. A valid calendar date is not necessarily a trading day; a local time can be ambiguous or nonexistent during daylight-saving transitions.

This section's code does not implement calendars, timestamps or settlement conventions. Test those boundaries separately when the system supports them.

## 10. Reference implementation

Save as `boundary_cases.py`. It contains simple functions and boundary tests using Python's standard library.

~~~python
import math
import unittest

def finite_number(value):
    return type(value) in (int,float) and math.isfinite(value)

def present_value(cashflow,rate,periods):
    if not finite_number(cashflow) or not finite_number(rate) or rate<=-1:
        raise ValueError("finite cash flow and rate > -1 required")
    if type(periods) is not int or periods<0:
        raise ValueError("nonnegative integer periods required")
    try:
        result=cashflow*math.exp(-periods*math.log1p(rate))
    except OverflowError as exc:
        raise ValueError("discount calculation overflow") from exc
    if not math.isfinite(result):
        raise ValueError("nonfinite present value")
    return result

def simple_return(start,end):
    if not all(finite_number(x) for x in (start,end)) or start<=0 or end<0:
        raise ValueError("positive start and nonnegative end required")
    return end/start-1

def sample_mean(values):
    vals=list(values)
    if not vals or not all(finite_number(x) for x in vals):
        raise ValueError("nonempty finite values required")
    return math.fsum(vals)/len(vals)

class BoundaryTests(unittest.TestCase):
    def test_zero_rate(self):
        self.assertEqual(present_value(100,0,1),100)
    def test_zero_periods(self):
        self.assertEqual(present_value(100,.05,0),100)
    def test_valid_negative_rate(self):
        self.assertTrue(math.isclose(present_value(95,-.05,1),100,abs_tol=1e-10))
    def test_rate_at_boundary(self):
        with self.assertRaises(ValueError): present_value(100,-1,1)
    def test_rate_below_boundary(self):
        with self.assertRaises(ValueError): present_value(100,-1.01,1)
    def test_negative_cashflow(self):
        self.assertTrue(math.isclose(present_value(-110,.1,1),-100,abs_tol=1e-10))
    def test_negative_periods(self):
        with self.assertRaises(ValueError): present_value(100,.05,-1)
    def test_bool_period(self):
        with self.assertRaises(ValueError): present_value(100,.05,True)
    def test_zero_start(self):
        with self.assertRaises(ValueError): simple_return(0,100)
    def test_zero_end(self):
        self.assertEqual(simple_return(100,0),-1)
    def test_nonfinite(self):
        with self.assertRaises(ValueError): simple_return(100,float("nan"))
    def test_empty(self):
        with self.assertRaises(ValueError): sample_mean([])
    def test_single(self):
        self.assertEqual(sample_mean([100]),100)
    def test_infinity(self):
        with self.assertRaises(ValueError): present_value(100,float("inf"),1)

if __name__ == "__main__":
    unittest.main(verbosity=2)
~~~

This code uses binary floats and intentionally rejects bool and other numeric types. It does not implement financial dates, currencies, fees or every extreme input. `math.isclose` uses both relative and absolute tolerances unless explicitly set; the examples above use its default relative tolerance in addition to the supplied absolute tolerance.

## 13. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Negative rate rejected | Overly broad validation | Compare with model domain |
| Zero NPV treated as error | Invalid sentinel design | Separate valid value from failure |
| Nonfinite result propagates | Missing input or output checks | Validate finite values and numerical limits |
| Boundary test passes unexpectedly | Wrong inequality or broad tolerance | Inspect contract and comparison |
| Date works locally but not elsewhere | Calendar or timezone assumption | Record source and temporal policy |
| All tests pass but production fails | Untested scale, data or integration | Expand representative boundary coverage |
