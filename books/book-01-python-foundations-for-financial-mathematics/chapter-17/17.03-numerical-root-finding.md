## Learning objectives

Formulate financial equations as scalar root problems, establish valid domains and brackets, derive bisection, Newton, and secant updates, compare convergence behavior, detect nonconvergence and multiple roots, use SciPy's root-finding interfaces, and independently validate financial results.

## 1. The root-finding problem

A numerical root solver seeks a value x satisfying **f(x)=0**. Many finance problems are naturally inverse problems: given a price, solve for a yield; given cash flows, solve for an internal rate of return; given a model price, solve for implied volatility; or given a calibration target, solve for a parameter.

A root is not necessarily unique, and some equations have no root in the economically admissible domain. The correct domain and conventions must be defined before choosing an algorithm.

## 2. From financial equations to residual functions

For periodic cash flows CF₀,...,CFₙ:

**NPV(r)=Σₜ₌₀ⁿ CFₜ/(1+r)ᵗ**.

To find IRR, define **f(r)=NPV(r)** and solve f(r)=0.

For a bond pricing function P(y) and observed market price Pm, define **f(y)=P(y)−Pm**.

For implied volatility, define **f(σ)=model_price(σ)−market_price**, with σ constrained to an appropriate positive domain.

**Good modeling practice:** Scale residuals, specify units, and test that the function is finite over the intended search region.

## 3. Existence, continuity, and brackets

The intermediate value theorem says that if f is continuous on [a,b] and f(a) and f(b) have opposite signs, at least one root exists in (a,b).

This gives the foundation for bracketed solvers.

However:

- A sign-changing interval does not guarantee uniqueness.
- A function may have a root without a sign change, such as f(x)=(x−1)².
- A discontinuity can produce opposite endpoint signs without any root, such as f(x)=1/x over [−1,1].
- The financial domain can exclude otherwise valid mathematical roots.

## 4. Bisection algorithm

Given a valid sign-changing bracket [a,b]:

1. Calculate midpoint **m=a+(b−a)/2**.
2. Evaluate f(m).
3. If f(m)=0, return m.
4. Otherwise retain the half interval whose endpoints have opposite signs.
5. Repeat until a documented stopping criterion is met.

For **f(x)=x²−2** on [1,2], the first midpoint is 1.5 with f(1.5)=.25, so the next bracket is [1,1.5]. The second midpoint is 1.25 with f(1.25)=−.4375, so the next bracket is [1.25,1.5].

## 5. Bisection convergence and error bounds

Starting with interval width L=b−a, after n iterations the retained bracket has width **L/2ⁿ**.

The midpoint of that bracket is within at most **L/2ⁿ⁺¹** of any root contained in it.

Bisection has predictable linear convergence. It is often a good baseline for independently checking a faster method.

A small interval is an x-error guarantee under valid bracketing; a small residual alone is not the same guarantee.

## 6. Newton's method

For differentiable f, Newton's method uses the tangent-line update:

**xₖ₊₁=xₖ−f(xₖ)/f′(xₖ)**.

For f(x)=x²−2 starting at x₀=1:

**x₁=1−(−1)/2=1.5**.

Then:

**x₂=1.5−(.25)/3≈1.416667**.

Newton's method can converge quadratically near a simple root when its assumptions hold. But a poor initial guess, zero derivative, discontinuity, or invalid iterate can cause failure.

## 7. Secant method

The secant method approximates the derivative from two prior points:

**xₖ₊₁=xₖ−f(xₖ)(xₖ−xₖ₋₁)/[f(xₖ)−f(xₖ₋₁)]**.

It avoids explicit derivatives and often converges faster than bisection near a simple root, but does not preserve a sign-changing bracket.

If consecutive function values are equal, the secant denominator vanishes and the update cannot be computed.

## 8. Convergence comparison

| Method | Inputs | Typical local convergence | Main advantage | Main limitation |
|---|---|---|---|---|
| Bisection | Continuous sign-changing bracket | Linear | Reliable bracket reduction | Slower; no root without sign change |
| Newton | Initial guess and derivative | Quadratic near a simple root | Fast local convergence | Can diverge or leave domain |
| Secant | Two initial guesses | Superlinear, ≈1.618 order | No derivative required | Not guaranteed to stay in domain |
| Brent-type | Continuous sign-changing bracket | Often faster than bisection | Safeguarded and efficient | Still needs a valid bracket |

Convergence rates describe mathematical behavior under assumptions, not a universal guarantee for every financial equation.

## 9. Stopping criteria and solver diagnostics

A solver should record at least:

- The method and its inputs.
- The root estimate.
- The residual f(root).
- Iteration count.
- Convergence status.
- Bracket or initial guesses.
- Absolute and relative tolerances.
- Any warnings, invalid domains, or failures.

**Residual tolerance:** |f(x)|≤εf.

**Step or bracket tolerance:** a sufficiently small change in x or a sufficiently narrow bracket.

A tiny residual does not always mean the root is accurate, particularly for a flat function. A tiny step does not establish convergence if the residual remains large.

## 10. Financial example — simple IRR

An investment costs $100 and returns $110 in one year.

**f(r)=−100+110/(1+r)**.

For r=.10, f(.10)=0.

A bisection solver with a bracket spanning .10 should recover the root, and a Newton or secant solver can be compared against the analytic answer.

The reference implementation restricts discount rates to r>−1.

## 11. Multiple IRRs

Consider cash flows **[-100,230,-132]**.

Their NPV equation is:

**−100+230/(1+r)−132/(1+r)²=0**.

The two solutions are **r=.10** and **r=.20**.

A solver operating on a single bracket can return one of these roots but does not establish uniqueness. A financial report should inspect cash-flow sign changes, scan economically relevant intervals where appropriate, and explain any ambiguity.

## 12. Bond yield and price monotonicity

For conventional positive bond cash flows discounted at a single yield, modeled price typically declines as yield rises over the valid domain. This monotonicity can help establish a unique yield in a bracket.

For unusual cash-flow patterns, embedded options, or nonstandard conventions, that property may not hold in the same simple form.

Always align clean versus dirty price, coupon schedule, day-count convention, compounding frequency, and settlement date.

## 13. Implied volatility as a root problem

A vanilla option's implied volatility is often defined by:

**model_price(σ)−market_price=0**.

The numerical solver must enforce volatility domain constraints and verify that the market price is compatible with the model's no-arbitrage bounds.

At very low vega, implied volatility can be ill-conditioned: a small price change can imply a large volatility change.

## 14. Sensitivity and conditioning

For a simple root x* with f′(x*)≠0, a small residual perturbation δf produces approximately:

**δx≈−δf/f′(x*)**.

Thus a small derivative can magnify root uncertainty.

In bond pricing, yield sensitivity depends on price-yield slope. In option implied volatility, sensitivity depends on vega. Solver precision and market-data uncertainty should be distinguished.

## 15. Domain and scaling controls

Rates may have constraints such as r>−1 under integer-period discounting. Volatility must be nonnegative. Some model parameters have upper bounds.

Scaling can improve numerical behavior. For example, dividing a bond pricing residual by a suitable price scale yields a dimensionless relative residual, but the scaling convention must be recorded.

Do not silently clamp invalid iterates and report convergence without checking the original equation.

## 16. SciPy interfaces

SciPy provides well-tested numerical methods. Representative usage:

```python
from scipy.optimize import root_scalar

def f(x):
    return x*x - 2.0

bracketed = root_scalar(f, bracket=[1.0, 2.0], method="brentq")
assert bracketed.converged
assert abs(f(bracketed.root)) < 1e-10

newton_result = root_scalar(
    f, x0=1.0, fprime=lambda x: 2.0*x, method="newton"
)
assert newton_result.converged
assert abs(f(newton_result.root)) < 1e-10
```

This snippet requires SciPy to be installed. The full reference implementation below uses only the standard library to make the algorithms transparent. Later sections apply SciPy to specific financial problems.

## 17. Complete standard-library reference implementation

Save as `numerical_root_finding.py`. It implements bisection, Newton, secant, periodic-cash-flow NPV, and bracketed IRR, with **12 reference unit tests**.

```python
"""Chapter 17.3: safeguarded scalar root-finding reference."""
import math
import unittest

def valid(x):
    return type(x) in (int,float) and math.isfinite(x)

def bisection(f,a,b,xtol=1e-12,ftol=1e-12,max_iter=200):
    if not all(valid(x) for x in (a,b,xtol,ftol)) or a>=b or xtol<=0 or ftol<0 or type(max_iter) is not int or max_iter<1:
        raise ValueError("invalid bounds or tolerances")
    fa,fb=f(a),f(b)
    if not valid(fa) or not valid(fb):raise ValueError("nonfinite endpoint")
    if fa==0:return {"root":a,"residual":0.0,"iterations":0,"converged":True,"bracket":(a,b)}
    if fb==0:return {"root":b,"residual":0.0,"iterations":0,"converged":True,"bracket":(a,b)}
    if (fa>0)==(fb>0):raise ValueError("no sign change")
    for i in range(1,max_iter+1):
        m=a+(b-a)/2
        fm=f(m)
        if not valid(fm):raise ValueError("nonfinite function value")
        if fm==0 or (b-a)/2<=xtol:
            return {"root":m,"residual":fm,"iterations":i,"converged":True,"bracket":(a,b)}
        if (fm>0)==(fa>0):a,fa=m,fm
        else:b,fb=m,fm
    raise RuntimeError("bisection iteration limit")

def newton(f,df,x0,domain=None,xtol=1e-12,ftol=1e-10,max_iter=100):
    if not valid(x0) or not valid(xtol) or not valid(ftol) or xtol<=0 or ftol<0 or type(max_iter) is not int or max_iter<1:
        raise ValueError("invalid Newton inputs")
    x=x0
    for i in range(max_iter+1):
        if domain is not None and not domain(x):raise ValueError("iterate outside domain")
        fx=f(x)
        if not valid(fx):raise ValueError("nonfinite function value")
        if abs(fx)<=ftol:
            return {"root":x,"residual":fx,"iterations":i,"converged":True}
        if i==max_iter:break
        dfx=df(x)
        if not valid(dfx) or abs(dfx)<1e-14:raise ValueError("zero or invalid derivative")
        step=fx/dfx
        next_x=x-step
        if not valid(next_x):raise ValueError("nonfinite Newton step")
        # A small step alone does not certify a root: residual must be checked.
        x=next_x
    raise RuntimeError("Newton iteration limit")

def secant(f,x0,x1,xtol=1e-12,ftol=1e-10,max_iter=100):
    if not all(valid(x) for x in (x0,x1,xtol,ftol)) or x0==x1 or xtol<=0 or ftol<0 or type(max_iter) is not int or max_iter<1:
        raise ValueError("invalid secant inputs")
    y0,y1=f(x0),f(x1)
    if not valid(y0) or not valid(y1):raise ValueError("nonfinite function")
    for i in range(1,max_iter+1):
        if abs(y1)<=ftol:return {"root":x1,"residual":y1,"iterations":i-1,"converged":True}
        if y1==y0:raise ValueError("zero secant slope")
        x2=x1-y1*(x1-x0)/(y1-y0)
        if not valid(x2):raise ValueError("nonfinite secant step")
        y2=f(x2)
        if not valid(y2):raise ValueError("nonfinite function")
        if abs(y2)<=ftol:return {"root":x2,"residual":y2,"iterations":i,"converged":True}
        x0,y0,x1,y1=x1,y1,x2,y2
    raise RuntimeError("secant iteration limit")

def npv(rate,flows):
    if not valid(rate) or rate<=-1 or not isinstance(flows,(list,tuple)) or len(flows)<2 or any(not valid(c) for c in flows):
        raise ValueError("finite rate > -1 and finite cash flows required")
    return math.fsum(c/(1+rate)**t for t,c in enumerate(flows))

def irr_bracketed(flows,lo=-.9,hi=1):
    if lo<=-1:raise ValueError("invalid discount-rate domain")
    return bisection(lambda r:npv(r,flows),lo,hi)

class RootFindingTests(unittest.TestCase):
    def test_01_bisection(self):self.assertAlmostEqual(bisection(lambda x:x*x-2,0,2)["root"],math.sqrt(2),places=9)
    def test_02_newton(self):self.assertAlmostEqual(newton(lambda x:x*x-2,lambda x:2*x,1)["root"],math.sqrt(2),places=9)
    def test_03_secant(self):self.assertAlmostEqual(secant(lambda x:x*x-2,1,2)["root"],math.sqrt(2),places=9)
    def test_04_irr(self):self.assertAlmostEqual(irr_bracketed([-100,110])["root"],.1,places=9)
    def test_05_endpoint(self):self.assertEqual(bisection(lambda x:x-1,1,2)["iterations"],0)
    def test_06_bad_bracket(self):
        with self.assertRaises(ValueError):bisection(lambda x:x*x+1,-1,1)
    def test_07_zero_derivative(self):
        with self.assertRaises(ValueError):newton(lambda x:x*x+1,lambda x:2*x,0)
    def test_08_domain(self):
        with self.assertRaises(ValueError):newton(lambda x:x+2,lambda x:1,0,domain=lambda x:x>-1)
    def test_09_secant_slope(self):
        with self.assertRaises(ValueError):secant(lambda x:1,0,1)
    def test_10_npv(self):self.assertAlmostEqual(npv(.1,[-100,110]),0)
    def test_11_multi_irr(self):
        self.assertAlmostEqual(npv(.1,[-100,230,-132]),0,places=9)
        self.assertAlmostEqual(npv(.2,[-100,230,-132]),0,places=9)
    def test_12_iteration_limit(self):
        with self.assertRaises(RuntimeError):bisection(lambda x:x*x-2,0,2,xtol=1e-16,max_iter=1)

if __name__=="__main__":
    print("Bisection:",bisection(lambda x:x*x-2,0,2))
    print("Newton:",newton(lambda x:x*x-2,lambda x:2*x,1))
    print("Secant:",secant(lambda x:x*x-2,1,2))
    print("IRR:",irr_bracketed([-100,110]))
    unittest.main(verbosity=2)
```

## 20. Troubleshooting

| Symptom | Likely cause | Corrective action |
|---|---|---|
| No bracket sign change | Root absent, even multiplicity, or poor bracket | Inspect function and domain |
| Sign change but no root | Discontinuity or singularity | Check continuity before bracketing |
| Newton derivative zero | Flat point or invalid starting guess | Choose another start or bracketed method |
| Newton leaves rate domain | Unconstrained step | Use bounds or safeguarded solver |
| Secant denominator zero | Equal function values | Restart or use bracketed method |
| Different IRR results | Multiple roots | Inspect NPV across plausible rates |
| Residual small but root uncertain | Ill-conditioned equation | Sensitivity analysis and stronger checks |
| Solver stops at iteration limit | Nonconvergence | Report failure; revise method and tolerances |
| Nonfinite function value | Overflow or invalid discounting | Validate inputs and scale |
| Code exists but runtime evidence absent | QA deferred | Execute and record tests during QA |
