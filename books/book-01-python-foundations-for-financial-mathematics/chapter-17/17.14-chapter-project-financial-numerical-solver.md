## Project goals

Build an educational numerical engine to price periodic cash flows, solve for a rate, inspect convergence and repricing, and evaluate rate sensitivity. The project combines root finding, numerical stability, error analysis, validation and financial interpretation from Sections 17.1–17.13.

By completing it, you should be able to:

- Define cash-flow timing and rate conventions before calculating.
- Compute NPV with annual effective discounting and validate input domains.
- Solve a bracketed root using SciPy and inspect the status and residual.
- Distinguish rate tolerance from price tolerance.
- Compare results against independently derived benchmarks and perturb inputs.
- Document assumptions, evidence, limitations and unresolved risks.

## 1. Scenario

An investment costs 100 at time zero and pays 110 after one year. At a 10% annual effective rate:

**NPV = −100 + 110/(1 + 0.10) = 0.**

The project calculates NPV at a chosen rate, searches for a rate that makes NPV zero, and reports the result and diagnostics. It also calculates an approximate change in NPV for a one-basis-point increase in rate.

A decimal rate of 0.10 is 10%; one basis point is 0.0001 in decimal rate units. Rates and cash flows must use consistent periods.

## 2. Scope and assumptions

Cash flows are a sequence [C₀, C₁, …, Cₙ], with Cₜ occurring at the end of period t and C₀ at time zero. For a periodic effective rate r > −1:

**NPV(r) = Σₜ Cₜ/(1+r)ᵗ.**

The code uses the same rate for all periods, no fees or taxes unless included in the flows, and no dates, accrual or day-count rules. It is an educational periodic cash-flow solver, not a production bond-pricing system.

A sign-changing bracket for a continuous NPV function establishes at least one root in that interval, not uniqueness. Multiple IRRs can exist for nonconventional cash flows. The chosen bracket identifies only the root found there and is not a recommendation.

## 3. Architecture and acceptance criteria

The engine has four responsibilities: validate inputs, calculate NPV, solve inside a specified bracket, and report diagnostics. For the baseline example:

| Check | Expected outcome |
|---|---|
| NPV at 10% | Approximately zero |
| Root in [0, 0.2] | Approximately 0.10 |
| Repricing residual | Within the explicitly selected currency tolerance |
| NPV at 11% | Approximately −0.9009009 |
| Invalid rate ≤ −1 | Clear exception |
| No sign change in bracket | Clear exception |

The numerical tolerance on the rate and the acceptance tolerance on NPV have different units. A solver may converge by its rate criterion while the price residual still exceeds the independent financial threshold.

## 5. Reference implementation

Save as `financial_solver.py`. The implementation preserves integer/displayed-decimal periodic arithmetic, checks input domains, reports SciPy solver diagnostics and checks the final currency residual separately.

~~~python
"""Educational periodic solver with exact model arithmetic and finite reports."""
import math
from dataclasses import dataclass
from fractions import Fraction
from scipy.optimize import root_scalar

def _number(x):
    if type(x) not in (int,float):
        raise ValueError("finite int/float required; booleans excluded")
    try:
        if not math.isfinite(x):
            raise ValueError("finite number required")
    except OverflowError as exc:
        raise ValueError("number outside finite float range") from exc
    return Fraction(x) if type(x) is int else Fraction(str(x))

def _float(x):
    try:
        value=float(x)
    except (ValueError,OverflowError) as exc:
        raise ValueError("unreportable numeric result") from exc
    if not math.isfinite(value) or (x!=0 and value==0):
        raise ValueError("unreportable numeric result")
    return value

def _coordinate(x):
    exact=_number(x);value=_float(exact)
    if type(x) is int and _number(value)!=exact:
        raise ValueError("integer coordinate not representable under float callback protocol")
    return value

def _call(f,x):
    if not callable(f):
        raise ValueError("callable required")
    value=f(x)
    _number(value)
    return value

def finite_number(value):
    try:_number(value)
    except ValueError:return False
    return True

def validate_flows(cashflows):
    try:values=tuple(cashflows)
    except TypeError as exc:raise ValueError("iterable cashflows required") from exc
    if len(values)<2:raise ValueError("at least two cashflows required")
    for value in values:_number(value)
    return values

def _npv_exact(flows,rate):
    if rate<=-1:raise ValueError("periodic effective rate > -1 required")
    return sum(c/(1+rate)**t for t,c in enumerate(flows))

def npv(cashflows,rate):
    flows=tuple(map(_number,validate_flows(cashflows)));rate=_number(rate)
    return _float(_npv_exact(flows,rate))

@dataclass(frozen=True)
class SolveReport:
    rate: float
    residual: float
    converged: bool
    iterations: int
    function_calls: int
    method: str
    bracket: tuple
    rate_xtol: float
    residual_tolerance: float
    residual_accepted: bool
    residual_scale: float = 1.0
    callback_units: str = "currency"

def solve_rate(cashflows,lower,upper,rate_xtol=1e-12,
               residual_tolerance=1e-8,maxiter=100):
    flows=tuple(map(_number,validate_flows(cashflows)))
    lower=_coordinate(lower);upper=_coordinate(upper)
    xtol=_number(rate_xtol);tolerance=_number(residual_tolerance)
    if lower<=-1 or lower>=upper or xtol<=0 or tolerance<0 or type(maxiter) is not int or maxiter<1:
        raise ValueError("invalid bracket, tolerance or iteration budget")
    scale=max(abs(c) for c in flows)
    if scale==0:raise ValueError("all-zero cashflows: rate is non-identifiable")
    left=_npv_exact(flows,_number(lower));right=_npv_exact(flows,_number(upper))
    if left==0 or right==0:
        root=lower if left==0 else upper
        return SolveReport(root,0.0,True,0,2,"endpoint",(lower,upper),_float(xtol),_float(tolerance),True)
    if (left>0)==(right>0):raise ValueError("bracket endpoints must have opposite NPV signs")
    def objective(rate):
        # Internal SciPy coordinates are converted to Python floats explicitly.
        return _float(_npv_exact(flows,_number(float(rate)))/scale)
    result=root_scalar(objective,bracket=(lower,upper),method="brentq",xtol=_float(xtol),maxiter=maxiter)
    if not result.converged:raise RuntimeError("solver did not converge: "+str(result.flag))
    rate=float(result.root);exact_residual=_npv_exact(flows,_number(rate))
    return SolveReport(rate,_float(exact_residual),bool(result.converged),int(result.iterations),
                       int(result.function_calls),"brentq",(lower,upper),_float(xtol),_float(tolerance),
                       abs(exact_residual)<=tolerance,_float(scale),"NPV / max_abs_cashflow")

def one_bp_change(cashflows,rate):
    """Exact model NPV(rate +1/10000) minus NPV(rate), then float report."""
    flows=tuple(map(_number,validate_flows(cashflows)));rate=_number(rate)
    return _float(_npv_exact(flows,rate+Fraction(1,10000))-_npv_exact(flows,rate))

def main():
    flows = [-100.0, 110.0]
    report = solve_rate(flows, 0.0, 0.2)
    print("cash flows:", flows)
    print("NPV at 10%:", npv(flows, 0.10))
    print("root report:", report)
    print("NPV at 11%:", npv(flows, 0.11))
    print("NPV change for +1 bp:", one_bp_change(flows, 0.10))
    if not report.residual_accepted:
        raise RuntimeError("converged, but price residual exceeds tolerance")

if __name__ == "__main__":
    main()
~~~

`function_calls` in a Brent report is SciPy's count for normalized callbacksNPV/max_abs_cashflow; independent exact bracket checks and the final currency residual calculation are not included. `residual_scale` records that model scale and `callback_units` distinguishes normalized callbacks from currency residuals. Endpoint reports use two exact endpoint evaluations and no iterative solver; their default scale1/currency units describe that path.

**Numeric/input/reporting contract:** Finite Python int/float inputs only, excluding booleans. Input flow iterables are materialized once before repeated use. Integer/displayed-decimal arithmetic is rational through NPV, bracket signs, exact1/10000 rate increment and the whole finite sensitivity difference. SciPy receives representable Python-float rate coordinates; integer bounds that cannot retain their identity reject. All-zero flows reject as non-identifiable rather than arbitrarily selecting an endpoint. No all-root enumeration is implied.

Required nonzero computed reports/callbacks must stay finite and nonzero or raise ValueError; unreportable currency residuals may reject even after a good rate solve. Final float output cannot preserve every small increment in a large nonzero result, and supplied floats may already be rounded. Normalization does not alter rate units or the independently chosen currency acceptance threshold. `residual_accepted` compares the unrounded model residual with that threshold; convergence alone never forces acceptance. These are scoped implementation safeguards, not arbitrary conditioning/model/production certification.

## 6. Reference tests

Save as `test_financial_solver.py` next to the implementation.

~~~python
import unittest
from financial_solver import npv, solve_rate, one_bp_change

class SolverTests(unittest.TestCase):
    def test_known_npv(self):
        self.assertAlmostEqual(npv([-100, 110], .1), 0, places=10)
    def test_known_root_and_residual(self):
        result = solve_rate([-100, 110], 0, .2)
        self.assertTrue(result.converged)
        self.assertAlmostEqual(result.rate, .1, places=9)
        self.assertTrue(result.residual_accepted)
    def test_zero_rate(self):
        self.assertEqual(npv([-100, 110], 0), 10)
    def test_higher_rate(self):
        self.assertAlmostEqual(npv([-100, 110], .11), -100+110/1.11)
    def test_one_bp_direction(self):
        self.assertLess(one_bp_change([-100, 110], .1), 0)
    def test_invalid_rate(self):
        with self.assertRaises(ValueError):
            npv([-100, 110], -1)
    def test_invalid_bracket(self):
        with self.assertRaises(ValueError):
            solve_rate([-100, 110], .2, .3)
    def test_endpoint_root(self):
        result = solve_rate([-100, 100], 0, .2)
        self.assertEqual(result.rate, 0)
        self.assertEqual(result.iterations, 0)
    def test_nonfinite_input(self):
        with self.assertRaises(ValueError):
            npv([-100, float("nan")], .1)
    def test_scaling(self):
        self.assertAlmostEqual(npv([-200,220], .05),
                               2*npv([-100,110], .05))
    def test_multiple_roots_by_bracket(self):
        flows = [-100, 230, -132]
        self.assertAlmostEqual(solve_rate(flows, .05, .15).rate, .1, places=8)
        self.assertAlmostEqual(solve_rate(flows, .15, .25).rate, .2, places=8)
    def test_residual_acceptance_is_separate(self):
        result = solve_rate([-100,110], 0, .2, residual_tolerance=1e-8)
        self.assertEqual(result.residual_accepted,
                         abs(result.residual) <= 1e-8)

if __name__ == "__main__":
    unittest.main(verbosity=2)
~~~

## 7. Worked financial examples

### A. Baseline

At r = 0.10, the value of the future 110 is 100 and NPV is zero. A root found in [0, 0.2] should be near 0.10. Record both the returned rate and the repricing residual; do not infer accuracy solely from the success flag.

### B. Rate stress

At r = 0.11, NPV = −100 + 110/1.11 ≈ −0.9009009. A higher rate lowers the PV of a positive future cash flow. This property is not universal for cash flows of arbitrary sign.

### C. One basis point

At 10%, the change for +1 bp is:

**−100 + 110/1.1001 − 0 ≈ −0.00909.**

This is the finite price change for a specific +1 bp move, in cash-flow units. It is not a claim that the change is constant for larger rate shifts.

### D. Multiple roots

For [−100, 230, −132], multiplying NPV by (1+r)² gives −100(1+r)² + 230(1+r) − 132 = 0. The roots are 10% and 20%. Brackets [0.05, 0.15] and [0.15, 0.25] isolate them separately. A bracket enclosing both may have same-sign endpoints and fail even though roots exist within it.

## 10. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| No sign change | Bracket misses root or contains multiple roots | Inspect NPV over valid intervals and assumptions |
| Convergence but residual too large | Rate tolerance or conditioning | Review residual units, sensitivity and tolerance |
| Unexpected root | Multiple IRRs or invalid economic domain | Examine other brackets and cash-flow signs |
| Overflow | Extreme rate or horizon | Review units, domain and numerical representation |
| Import error | SciPy unavailable in active environment | Verify interpreter, environment and installation |
| Values differ from bond system | Different timing or pricing conventions | Compare settlement, accrual, compounding and price definitions |
| Test evidence missing | QA deferred | Run and retain outputs in the planned validation phase |
