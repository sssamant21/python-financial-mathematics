## Learning objectives

Explain why numerical methods are central to financial mathematics; distinguish analytic solutions from approximations; recognize root-finding, optimization, integration, interpolation, and calibration problems; identify domain, convergence, precision, and model-risk limitations; and implement small reproducible reference solvers in Python.

## 1. Motivation: financial equations rarely stay simple

Financial mathematics begins with formulas such as compound interest and present value. Many practical problems reverse those formulas or combine them with constraints. Given a market price, one may need to infer a bond yield. Given a set of securities and a risk mandate, one may need to choose portfolio weights. Given a payoff and a probability distribution, one may need to evaluate an expectation.

Some problems have closed-form solutions. Others do not, or the analytic formula is numerically unstable or impractical. **Numerical methods** approximate answers using a finite sequence of arithmetic operations.

The central engineering question is not merely whether a solver returns a number. It is whether the number is **mathematically meaningful, sufficiently accurate, economically plausible, reproducible, and consistent with the original constraints**.

## 2. Closed-form versus numerical solutions

A **closed-form solution** expresses an answer using a finite combination of familiar operations and functions.

For a single future cash flow:

**PV=FV/(1+r)ᵗ.**

Solving for r gives:

**r=(FV/PV)^(1/t)−1**.

For irregular cash flows, the rate is generally defined implicitly:

**0=ΣₜCFₜ/(1+r)ᵗ.**

The solution may require a numerical root-finding algorithm.

An analytic expression is not automatically more accurate in finite-precision arithmetic; stability matters.

## 3. Numerical root finding

Root finding solves:

**f(x)=0.**

In finance, examples include yield to maturity, internal rate of return, implied volatility, and model calibration residuals.

A **bracketed** method such as bisection starts with an interval [a,b] where f is continuous and the endpoint values have opposite signs. The method repeatedly halves the interval.

Under these conditions, a root exists in the bracket. If f is discontinuous, a sign change does not by itself guarantee a root.

## 4. Worked example — internal rate of return

An investment costs $100 today and pays $110 in one year.

**NPV(r)=−100+110/(1+r).**

Set NPV(r)=0:

**r=.10=10%.**

This example has a simple analytic answer, so it is ideal for verifying a numerical solver. A correct root finder should recover 10% and a near-zero NPV residual.

For multiple cash flows, the equation is more complicated. With changes in cash-flow sign, multiple IRRs may exist.

## 5. Why IRR can be ambiguous

Consider cash flows **[-100,230,-132]**.

Setting NPV=0 and multiplying by (1+r)² gives:

**−100(1+r)²+230(1+r)−132=0.**

This quadratic has roots **r=.10** and **r=.20**.

A numerical solver can return either depending on its bracket and starting conditions. Reporting one root as *the* IRR without inspecting the cash-flow pattern can be misleading.

## 6. Bisection, Newton, and Brent-type methods

**Bisection** is simple and robust when a valid continuous sign-changing bracket exists. It converges linearly and does not require derivatives.

**Newton's method** updates:

**xₖ₊₁=xₖ−f(xₖ)/f′(xₖ).**

It can converge rapidly near a well-behaved root but may diverge when the derivative is small, the initial guess is poor, or the iteration leaves the valid domain.

**Brent-type methods** combine bracketing reliability with faster interpolation-based steps. SciPy provides implementations that are preferable to a hand-built reference for many practical workflows, once their assumptions and diagnostics are understood.

## 7. Numerical optimization

Optimization chooses inputs that minimize or maximize an objective.

Examples:

- Minimize portfolio variance subject to weight limits.
- Maximize expected utility under risk and liquidity constraints.
- Calibrate model parameters to observed market prices.
- Minimize hedge error.
- Minimize transaction costs subject to target exposures.

A generic constrained problem is:

**minimize f(x) subject to gᵢ(x)≤0 and hⱼ(x)=0.**

A solver result must be checked for objective quality **and** constraint feasibility.

## 8. Portfolio optimization example

For weights w and covariance Σ:

**minimize wᵀΣw**

subject to:

**Σᵢwᵢ=1, wᵢ≥0, wᵢ≤uᵢ.**

With valid PSD covariance and linear constraints, this is a convex quadratic program. Adding discrete lots, cardinality restrictions, or certain nonlinear penalties may make the problem more difficult.

The optimizer should not be trusted unless covariance assumptions, weight conventions, and constraints are validated independently.

## 9. Numerical integration

Integration computes accumulated quantities or expectations.

A financial expectation can be written:

**E[g(X)]=∫g(x)p(x)dx**,

where p(x) is a probability density and g(x) is a payoff.

When the integral lacks a convenient analytic form, numerical quadrature approximates it.

The **trapezoidal rule** on a uniform grid approximates:

**∫ₐᵇf(x)dx≈h[f(a)/2+Σᵢ₌₁ᴺ⁻¹f(a+ih)+f(b)/2]**,

where **h=(b−a)/N**.

For f(x)=x on [0,1], the trapezoidal rule is exact and returns .5. For f(x)=x², it converges to 1/3 as the grid is refined.

## 10. Interpolation and curve construction

Market data may provide bond yields or discount factors only at a limited set of maturities. Pricing a security at an intermediate date requires an interpolation convention.

Possible approaches include linear interpolation, cubic splines, and monotonicity-preserving methods. The interpolated quantity also matters: interpolating yields, discount factors, or log discount factors generally gives different results.

**Curve construction** often solves several equations so modeled prices reproduce market quotes while respecting market conventions and appropriate shape constraints.

## 11. Calibration and inverse problems

A forward model predicts a price from parameters:

**P_model(θ).**

Calibration reverses the problem by choosing θ to match observed prices:

**minimize Σᵢweightᵢ[P_model,i(θ)−P_market,i]².**

Calibration may be nonunique, ill-conditioned, or sensitive to noisy quotes. A tiny pricing residual does not prove that parameters are economically meaningful.

## 12. Numerical accuracy and error sources

Important error categories include:

- **Model error:** the model is an imperfect description of reality.
- **Input error:** market data and estimates are noisy or incorrect.
- **Discretization error:** continuous equations are approximated on a finite grid.
- **Roundoff error:** floating-point operations have finite precision.
- **Iteration error:** a solver stops before the mathematical limit.
- **Implementation error:** code does not match the intended formula.

These errors require different remedies. Increasing iteration count does not repair an incorrect financial model.

## 13. Convergence and stopping criteria

A solver should stop based on explicit, documented criteria.

For bisection, after n iterations, a starting interval of width L has remaining width **L/2ⁿ**. The midpoint is within at most **L/2ⁿ⁺¹** of a root contained in that interval.

Root residual **|f(x)|** and root error **|x−x*|** are different quantities. A small residual does not necessarily imply a small root error if the function is very flat near the root.

Use tolerances that respect units, problem scale, and model sensitivity.

## 14. Numerical stability and conditioning

A **stable algorithm** limits unnecessary amplification of arithmetic errors.

A **well-conditioned problem** changes modestly when inputs change modestly. A problem can be ill-conditioned even when solved by a stable algorithm.

For example, inferring a yield from a nearly insensitive price can be difficult: a small market-price error may produce a large yield error.

Subtracting nearly equal large numbers can also cause cancellation and loss of relative precision.

## 15. Validation before interpretation

For every numerical finance result:

1. Validate input dimensions, units, and domains.
2. Check whether the problem is well-posed and whether a solution exists.
3. Use a known-value analytic example where available.
4. Inspect solver status, iteration count, and warnings.
5. Substitute the solution into the original equation.
6. Verify portfolio and other constraints independently.
7. Compare results across tolerances or grid sizes.
8. Run sensitivity and scenario analysis.
9. Record assumptions, versions, and data provenance.
10. Do not label a draft reference implementation production-certified.

## 16. SciPy learning path

## 17. Standard-library reference implementation

Save as `why_numerical_methods_are_needed.py`. This educational file demonstrates NPV, bisection root finding, a bracketed IRR, trapezoidal integration, and simple grid optimization. It includes **12 reference unit tests**.

```python
"""Chapter 17.1: numerical methods motivation, standard-library reference."""
import math
import unittest

def npv(rate, cashflows):
    if not isinstance(cashflows,(list,tuple)) or len(cashflows)<2:
        raise ValueError("cashflows must contain initial and future amounts")
    if type(rate) not in (int,float) or not math.isfinite(rate) or rate<=-1:
        raise ValueError("finite rate > -1 required")
    if any(type(c) not in (int,float) or not math.isfinite(c) for c in cashflows):
        raise ValueError("finite cashflows required")
    return math.fsum(c/(1+rate)**t for t,c in enumerate(cashflows))

def bisection(f,lo,hi,tolerance=1e-12,max_iter=200):
    if any(type(x) not in (int,float) or not math.isfinite(x) for x in (lo,hi,tolerance)):
        raise ValueError("finite bounds and tolerance required")
    if not lo<hi or tolerance<=0 or type(max_iter) is not int or max_iter<=0:
        raise ValueError("invalid interval or stopping rule")
    flo=f(lo);fhi=f(hi)
    if not math.isfinite(flo) or not math.isfinite(fhi):
        raise ValueError("nonfinite endpoint")
    if flo==0:return {"root":lo,"iterations":0,"residual":0.0}
    if fhi==0:return {"root":hi,"iterations":0,"residual":0.0}
    if flo*fhi>0:raise ValueError("endpoints must bracket a sign change")
    for i in range(1,max_iter+1):
        mid=(lo+hi)/2
        fm=f(mid)
        if not math.isfinite(fm):raise ValueError("nonfinite function value")
        if fm==0 or (hi-lo)/2<=tolerance:
            return {"root":mid,"iterations":i,"residual":fm}
        if (flo<0 and fm<0) or (flo>0 and fm>0):
            lo=mid;flo=fm
        else:hi=mid
    raise RuntimeError("iteration limit reached")

def irr(cashflows,lo=-.9,hi=1.0):
    # Only returns a root within the supplied sign-changing bracket.
    return bisection(lambda r:npv(r,cashflows),lo,hi)

def trapezoid(f,a,b,steps):
    if type(steps) is not int or steps<1 or not all(
        type(x) in (int,float) and math.isfinite(x) for x in (a,b)
    ) or not a<b:
        raise ValueError("finite ordered bounds and positive integer steps")
    h=(b-a)/steps
    vals=[f(a+i*h) for i in range(steps+1)]
    if any(type(x) not in (int,float) or not math.isfinite(x) for x in vals):
        raise ValueError("finite integrand required")
    return h*(.5*vals[0]+math.fsum(vals[1:-1])+.5*vals[-1])

def grid_minimize(f,lo,hi,steps):
    if type(steps) is not int or steps<1 or not lo<=hi:
        raise ValueError("invalid grid")
    candidates=[lo+(hi-lo)*i/steps for i in range(steps+1)]
    values=[f(x) for x in candidates]
    if any(type(v) not in (int,float) or not math.isfinite(v) for v in values):
        raise ValueError("finite objective required")
    index=min(range(len(values)),key=lambda i:values[i])
    return {"x":candidates[index],"value":values[index],
            "grid_spacing":(hi-lo)/steps}

class NumericalMotivationTests(unittest.TestCase):
    def test_01_npv(self):self.assertAlmostEqual(npv(.1,[-100,110]),0)
    def test_02_irr(self):self.assertAlmostEqual(irr([-100,110])["root"],.1,places=9)
    def test_03_bisection(self):self.assertAlmostEqual(bisection(lambda x:x*x-2,0,2)["root"],math.sqrt(2),places=9)
    def test_04_exact_endpoint(self):self.assertEqual(bisection(lambda x:x-1,1,2)["iterations"],0)
    def test_05_bad_bracket(self):
        with self.assertRaises(ValueError):bisection(lambda x:x*x+1,-1,1)
    def test_06_bad_rate(self):
        with self.assertRaises(ValueError):npv(-1,[-100,110])
    def test_07_trapezoid_linear(self):self.assertAlmostEqual(trapezoid(lambda x:x,0,1,20),.5)
    def test_08_trapezoid_quadratic(self):self.assertAlmostEqual(trapezoid(lambda x:x*x,0,1,1000),1/3,places=6)
    def test_09_grid(self):self.assertAlmostEqual(grid_minimize(lambda x:(x-.3)**2,0,1,10)["x"],.3)
    def test_10_grid_spacing(self):self.assertAlmostEqual(grid_minimize(lambda x:x*x,-1,1,10)["grid_spacing"],.2)
    def test_11_iteration_limit(self):
        with self.assertRaises(RuntimeError):bisection(lambda x:x*x-2,0,2,1e-15,1)
    def test_12_multiple_irr_warning(self):
        self.assertAlmostEqual(npv(0,[-100,230,-132]),-2)
        self.assertAlmostEqual(npv(.1,[-100,230,-132]),0,places=8)
        self.assertAlmostEqual(npv(.2,[-100,230,-132]),0,places=8)

if __name__=="__main__":
    print("IRR example:",irr([-100,110]))
    print("Integral:",trapezoid(lambda x:x*x,0,1,1000))
    print("Grid:",grid_minimize(lambda x:(x-.3)**2,0,1,10))
    unittest.main(verbosity=2)
```

## 20. Troubleshooting

| Symptom | Likely cause | Corrective action |
|---|---|---|
| Root finder rejects bracket | No endpoint sign change | Inspect function and choose a valid bracket |
| Solver returns economically invalid rate | Domain not enforced | Validate rate bounds |
| IRR differs between runs | Multiple roots or different brackets | Inspect NPV profile and all plausible roots |
| Newton iteration diverges | Poor initial guess or small derivative | Use safeguarded/bracketed method |
| Optimization violates limits | Constraints omitted or scaled poorly | Check final weights independently |
| Integral changes with grid size | Discretization error | Refine grid and study convergence |
| Yield curve differs across systems | Different interpolation conventions | Align curve methodology |
| Tiny residual but implausible parameter | Ill-conditioned inverse problem | Run sensitivity analysis |
| Numerical output differs by scale | Tolerance mismatch | Use unit-aware absolute/relative tolerances |
| Reference code exists but has no runtime evidence | Tests not executed | Record actual runs during QA |
