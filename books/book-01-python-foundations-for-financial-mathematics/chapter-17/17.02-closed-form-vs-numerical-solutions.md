## Learning objectives

By the end of this section, readers can distinguish analytic formulas from numerical algorithms, identify when financial problems require inversion or approximation, compare precision and stability, implement independent closed-form and numerical checks, and interpret solver results without confusing convergence with economic validity.

## 1. What is a closed-form solution?

A **closed-form solution** expresses the unknown directly through a finite sequence of mathematical operations and recognized functions. For example, compound growth is

**FV=PV(1+r)ᵗ**.

If PV, FV, and t are known and positive, the periodic growth rate is

**r=(FV/PV)^(1/t)−1**.

This inversion is analytic; no iterative solver is necessary. For PV=$100, FV=$121, and t=2, r=10%.

A formula can be analytically correct yet numerically fragile. Implementations must still consider overflow, underflow, cancellation, and input domains.

## 2. What is a numerical solution?

A numerical method approximates a mathematical quantity through a finite algorithm. Typical outputs include a root, integral, interpolated value, or constrained optimum.

For an equation **f(x)=0**, a root solver generates trial values until a stopping rule is met. For an integral, quadrature evaluates the integrand at selected points and combines the values. For optimization, an algorithm searches for an objective minimum subject to constraints.

A numerical answer should be accompanied by a residual, tolerance, convergence status, and independent interpretation.

## 3. Comparison table

| Dimension | Closed-form | Numerical |
|---|---|---|
| Result | Explicit expression | Approximate computed value |
| Existence | Depends on solvability | Depends on problem and algorithm |
| Error | Floating-point evaluation and model error | Plus discretization/iteration error |
| Speed | Often low cost for simple formulas | May require many evaluations |
| Flexibility | Limited by available formulas | Handles more complex models |
| Multiple solutions | May reveal roots explicitly | May return only one solution |
| Validation | Check domains and substitutions | Also check convergence, residuals, constraints |
| Financial example | Future value of a deposit | IRR of irregular cash flows |

**Decision principle:** Prefer a correct, stable closed-form expression when available; otherwise use an appropriate numerical method, ideally cross-checked against an analytic special case.

## 4. Worked example — future value and implied rate

Suppose $100 grows to $121 over two years.

Forward calculation:

**FV=100(1.10)²=121**.

Inverse calculation:

**r=(121/100)^(1/2)−1=.10**.

The corrected code forms FV/PV exactly under its integer/displayed-decimal input policy, then evaluates the inverse using Decimal logarithm/exponential with precision increased for small relative differences. This retains integer-offset rate differences and avoids intermediate float ratio overflow. An implied rate that rounds to −1 despite positive future value is rejected as unreportable.

## 5. Worked example — ordinary annuity

For a payment C at the end of each period, positive integer n, and periodic rate r≠0:

**PV=C[1−(1+r)^(-n)]/r**.

At r=0, **PV=Cn**.

The equivalent finite sum is:

**PV=Σₜ₌₁ⁿ C/(1+r)ᵗ**.

The closed-form expression is efficient, while the direct sum provides an independent numerical check. For ordinary float implementations, `log1p` and `expm1` can avoid cancellation. This corrected educational reference instead evaluates the geometric closed form with rational intermediates, independently cross-checked against a direct rational discounted-payment sum. It does not subtract nearly equal rounded floats.

## 6. Worked example — bond yield as an inverse problem

A bond's price can be computed from a known yield by discounting its promised cash flows:

**P(y)=Σₜ CFₜ/(1+y)ᵗ**,

for compatible cash-flow timing and yield convention.

Given the market price Pm, the inverse problem is:

**f(y)=P(y)−Pm=0**.

For a single cash flow, the yield may have a closed-form solution. For multiple coupons and irregular dates, numerical root finding is often more practical.

The solver must respect the discounting convention, coupon frequency, accrued interest treatment, day-count basis, and valid yield domain.

## 7. Internal rate of return

For periodic cash flows CF₀,...,CFₙ, the IRR equation is:

**NPV(r)=Σₜ₌₀ⁿ CFₜ/(1+r)ᵗ=0**.

The simple investment [-100,110] has IRR=10%.

For [-100,230,-132], the NPV equation has **two valid real roots**, 10% and 20%. A root finder that returns 10% has not established uniqueness.

If all cash flows are zero, every valid rate is a root, so a unique IRR is not identifiable. If no real root exists in the economically admissible domain, reporting an IRR would be misleading.

## 8. Closed-form polynomial roots versus general solvers

A quadratic equation **ax²+bx+c=0** has roots:

**x=[−b±√(b²−4ac)]/(2a)**.

For **x²−3x+2=0**, roots are 1 and 2.

A naive quadratic implementation can lose precision through cancellation. The Python reference uses a more stable formula based on

**q=−½[b+sign(b)√(b²−4ac)]**,

then obtains roots **q/a** and **c/q** when safe, taking sign(b)=+1 when b=0. A zero discriminant is handled directly.

This illustrates a critical distinction: *analytic formula* does not necessarily mean *numerically stable evaluation*.

## 9. Bisection as a numerical baseline

Suppose f is continuous on [a,b] and f(a) and f(b) have opposite signs. The intermediate value theorem guarantees at least one root inside the interval.

Bisection repeatedly halves the bracket. After n interval halvings, a starting width L shrinks to **L/2ⁿ**; the midpoint error is bounded by **L/2ⁿ⁺¹**, assuming a root remains bracketed.

Advantages: simple implementation, predictable convergence, no derivative needed.

Limitations: requires a valid bracket, can be slower than more sophisticated methods, and does not identify all roots.

## 10. Newton's method and its tradeoffs

Newton's iteration is:

**xₖ₊₁=xₖ−f(xₖ)/f′(xₖ)**.

For f(x)=x²−2 starting at x=1, the next estimate is 1.5.

Newton's method can converge rapidly near a simple root but can fail when the derivative is zero, the initial guess is poor, or the iteration leaves the allowed financial domain. Safeguarded methods and bracketing are useful in risk-sensitive applications.

## 11. Analytic integration versus quadrature

For f(x)=x²,

**∫₀¹ x²dx=1/3** analytically.

The trapezoidal rule with N intervals approximates the same quantity:

**T_N=h[f(0)/2+Σᵢ₌₁ᴺ⁻¹f(ih)+f(1)/2]**, where h=1/N.

For this smooth function, increasing N reduces discretization error. The exact integral is an independent benchmark for testing the numerical algorithm.

Finance applications include discounted continuous cash flows, expected payoffs, probability calculations, and numerical option valuation.

## 12. Analytic versus numerical optimization

The unconstrained minimum of **f(x)=(x−.3)²** is x=.3.

If a constraint requires **x∈[.5,1]**, the constrained optimum is x=.5.

Real portfolio optimization may involve many weights, a covariance matrix, issuer and sector caps, transaction costs, and turnover limits. Numerical constrained optimization is generally more flexible than deriving a closed-form solution for each mandate.

Even if an algorithm reports success, independently check budget constraints, bounds, risk units, and objective value.

## 13. Model calibration and curve construction

Financial model calibration seeks parameters θ that match market prices. This may be expressed as:

**minimize Σᵢ ωᵢ[P_model,i(θ)−P_market,i]²**.

Curve construction can involve sequential or simultaneous root finding, interpolation, and constrained optimization.

A small pricing residual does not prove that inferred parameters are unique or stable. Parameter sensitivity, data quality, and financial conventions remain essential.

## 14. Error taxonomy

| Error type | Example | Remedy |
|---|---|---|
| Modeling | Wrong coupon timing | Correct financial specification |
| Input | Stale market price | Improve data controls |
| Roundoff | Cancellation near zero | Use stable formulas and scaling |
| Iteration | Solver stops too early | Adjust tolerance and inspect status |
| Discretization | Coarse integration grid | Refine grid and compare |
| Conditioning | Yield highly sensitive to price | Sensitivity and uncertainty analysis |
| Implementation | Incorrect asset ordering | Independent tests and reviews |

Numerical precision cannot repair a wrong financial model.

## 15. Accuracy, residual, and conditioning

A root solver may report a small residual **|f(x̂)|**, but this is not the same as a small root error **|x̂−x*|**. When f is flat near its root, small residuals can correspond to substantial uncertainty in the root.

Use absolute and relative tolerances appropriate to the units. For example, a price residual of $0.000001 is not a statement that the yield is accurate to one-millionth.

Compare with independent calculations and test how outputs respond to small input perturbations.

## 16. Choosing an approach in practice

1. Define the economic quantity and its domain.
2. Determine whether a stable closed-form expression exists.
3. Use analytic special cases as benchmarks.
4. If solving numerically, identify roots, integrals, or optimization structure.
5. Choose an algorithm consistent with continuity, differentiability, convexity, and constraints.
6. Scale variables and tolerances appropriately.
7. Inspect convergence status and residuals.
8. Check for multiple solutions and invalid domains.
9. Recompute the original financial equation.
10. Record assumptions, software versions, and independent validation evidence.

Later Chapter 17 sections will introduce SciPy's root-finding, optimization, integration, and interpolation capabilities.

## 17. Complete standard-library reference implementation

Save as `closed_form_vs_numerical_solutions.py`. This educational reference includes compound interest, analytic implied rates, annuity PV cross-checks, a stable quadratic solver, bisection, numerical IRR, and trapezoidal integration, with **12 reference unit tests**.

```python
"""Chapter 17.2: closed-form and numerical comparisons, standard-library reference."""
import math
import unittest
from fractions import Fraction
from decimal import Decimal, localcontext

def _number(x):
    if type(x) not in (int,float):
        raise ValueError("finite int/float required; booleans excluded")
    try:
        if not math.isfinite(x):
            raise ValueError("finite number required")
    except OverflowError as exc:
        raise ValueError("number outside finite float range") from exc
    return Fraction(x) if type(x) is int else Fraction(str(x))

def _float(x):
    try:
        value=float(x)
    except (ValueError,OverflowError) as exc:
        raise ValueError("unreportable numeric result") from exc
    if not math.isfinite(value) or (x!=0 and value==0):
        raise ValueError("unreportable numeric result")
    return value

def _coordinate(x):
    exact=_number(x);value=_float(exact)
    if type(x) is int and _number(value)!=exact:
        raise ValueError("integer coordinate not representable under float callback protocol")
    return value

def _call(f,x):
    if not callable(f):
        raise ValueError("callable required")
    value=f(x)
    _number(value)
    return value

def _cashflows(cashflows):
    if not isinstance(cashflows,(list,tuple)) or len(cashflows)<2:
        raise ValueError("initial and future cashflows required")
    return [_number(x) for x in cashflows]

def _npv(rate,cashflows):
    rate=_number(rate);cashflows=_cashflows(cashflows)
    if rate<=-1:
        raise ValueError("rate > -1 required")
    return _float(sum(c/(1+rate)**t for t,c in enumerate(cashflows)))

def _bisection(f,lo,hi,tolerance=1e-12,max_iter=200):
    lo=_coordinate(lo);hi=_coordinate(hi);tol=_number(tolerance)
    if lo>=hi or tol<=0 or type(max_iter) is not int or max_iter<=0:
        raise ValueError("ordered float coordinates and positive stopping rule required")
    flo=_call(f,lo);fhi=_call(f,hi)
    def result(x,value,i,a,b,radius,reason):
        return {"root":x,"iterations":i,"residual":value,"bracket":(a,b),
                "x_error_bound":_float(radius),"interval_halvings":max(0,i-1),"termination":reason}
    if flo==0:return result(lo,flo,0,lo,lo,Fraction(0),"endpoint_callback_zero")
    if fhi==0:return result(hi,fhi,0,hi,hi,Fraction(0),"endpoint_callback_zero")
    if (flo>0)==(fhi>0):
        raise ValueError("endpoints must have opposite signs")
    for i in range(1,max_iter+1):
        left=Fraction.from_float(lo);right=Fraction.from_float(hi)
        mid=float((left+right)/2);fm=_call(f,mid)
        radius=max(Fraction.from_float(mid)-left,right-Fraction.from_float(mid))
        if fm==0:return result(mid,fm,i,mid,mid,Fraction(0),"midpoint_callback_zero")
        if radius<=tol:return result(mid,fm,i,lo,hi,radius,"interval_tolerance")
        if mid==lo or mid==hi:
            raise RuntimeError("float coordinates exhausted before requested tolerance")
        if (flo>0)==(fm>0):
            lo=mid;flo=fm
        else:
            hi=mid
    raise RuntimeError("iteration limit reached")

def _irr(cashflows,lo=-.9,hi=1.0):
    if all(x==0 for x in _cashflows(cashflows)):
        raise ValueError("all-zero cashflows: IRR is non-identifiable")
    return _bisection(lambda r:npv(r,cashflows),lo,hi)

def _grid(lo,hi,steps,allow_equal=False):
    lo=_coordinate(lo);hi=_coordinate(hi)
    if type(steps) is not int or steps<1 or (lo>hi if allow_equal else lo>=hi):
        raise ValueError("ordered finite bounds and positive integer steps required")
    left=Fraction.from_float(lo);right=Fraction.from_float(hi)
    if lo==hi:return [lo],Fraction(0)
    spacing=(right-left)/steps
    points=[float(left+i*spacing) for i in range(steps+1)]
    if any(points[i]>=points[i+1] for i in range(steps)):
        raise ValueError("grid refinement exceeds distinct float coordinates")
    return points,spacing

def _trapezoid(f,a,b,steps):
    points,h=_grid(a,b,steps)
    vals=[_number(_call(f,x)) for x in points]
    return _float(h*(vals[0]/2+sum(vals[1:-1])+vals[-1]/2))

def finite(x):
    try:
        _number(x)
    except ValueError:
        return False
    return True

def _periods(n,zero=False):
    if type(n) is not int or n<(0 if zero else 1):
        raise ValueError("valid integer period count required")
    return n

def _decimal(x):
    return Decimal(x.numerator)/Decimal(x.denominator)

def future_value(principal,rate,periods):
    principal=_number(principal);rate=_number(rate);periods=_periods(periods,zero=True)
    if rate<=-1:
        raise ValueError("rate > -1 required")
    return _float(principal*(1+rate)**periods)

def implied_rate(principal,future,periods):
    p=_number(principal);f=_number(future);n=_periods(periods)
    if p<=0 or f<=0:
        raise ValueError("positive amounts required")
    delta=(f-p)/p
    if delta==0:return 0.0
    leading=max(0,len(str(delta.denominator))-len(str(abs(delta.numerator))))
    with localcontext() as ctx:
        ctx.prec=80+leading+len(str(n))
        ratio=f/p
        rate=(_decimal(ratio).ln()/Decimal(n)).exp()-1
        result=_float(rate)
    if result<=-1:
        raise ValueError("positive future value cannot report rate -1")
    return result

def npv(rate,flows):
    return _npv(rate,flows)

def bisect(f,a,b,tol=1e-12,limit=200):
    return _bisection(f,a,b,tol,limit)["root"]

def irr(flows,a=-.9,b=1):
    return _irr(flows,a,b)["root"]

def quadratic(a,b,c):
    a,b,c=(_number(x) for x in (a,b,c))
    if a==0:
        raise ValueError("quadratic coefficient a must be nonzero")
    disc=b*b-4*a*c
    if disc<0:
        raise ValueError("no real roots")
    if disc==0:
        value=_float(-b/(2*a));return (value,value)
    with localcontext() as ctx:
        ctx.prec=80
        root_disc=_decimal(disc).sqrt()
        q=-(_decimal(b)+(root_disc if b>=0 else -root_disc))/2
        return (_float(q/_decimal(a)),_float(_decimal(c)/q))

def annuity_pv(payment,rate,periods):
    payment=_number(payment);rate=_number(rate);n=_periods(periods)
    if rate<=-1:
        raise ValueError("rate > -1 required")
    value=payment*n if rate==0 else payment*(1-(1+rate)**(-n))/rate
    return _float(value)

def annuity_pv_sum(payment,rate,periods):
    payment=_number(payment);rate=_number(rate);n=_periods(periods)
    if rate<=-1:
        raise ValueError("rate > -1 required")
    return _float(sum(payment/(1+rate)**t for t in range(1,n+1)))

def trapezoid(f,a,b,n):
    return _trapezoid(f,a,b,n)

class Tests(unittest.TestCase):
    def test_01_fv(self):self.assertAlmostEqual(future_value(100,.1,2),121)
    def test_02_inverse(self):self.assertAlmostEqual(implied_rate(100,121,2),.1)
    def test_03_npv(self):self.assertAlmostEqual(npv(.1,[-100,110]),0)
    def test_04_irr(self):self.assertAlmostEqual(irr([-100,110]),.1,places=9)
    def test_05_quadratic(self):
        roots=quadratic(1,-3,2)
        self.assertAlmostEqual(min(roots),1)
        self.assertAlmostEqual(max(roots),2)
    def test_06_annuity(self):
        self.assertAlmostEqual(annuity_pv(100,.05,5),annuity_pv_sum(100,.05,5))
    def test_07_zero_rate(self):self.assertEqual(annuity_pv(100,0,5),500)
    def test_08_integral(self):self.assertAlmostEqual(trapezoid(lambda x:x,0,1,10),.5)
    def test_09_convergence(self):
        e1=abs(trapezoid(lambda x:x*x,0,1,10)-1/3)
        e2=abs(trapezoid(lambda x:x*x,0,1,20)-1/3)
        self.assertLess(e2,e1)
    def test_10_bad_bracket(self):
        with self.assertRaises(ValueError):bisect(lambda x:x*x+1,-1,1)
    def test_11_bad_rate(self):
        with self.assertRaises(ValueError):npv(-1,[-100,110])
    def test_12_multiple_roots(self):
        self.assertAlmostEqual(npv(.1,[-100,230,-132]),0,places=9)
        self.assertAlmostEqual(npv(.2,[-100,230,-132]),0,places=9)

if __name__=="__main__":
    print("Closed-form rate:",implied_rate(100,121,2))
    print("Numerical IRR:",irr([-100,110]))
    print("Annuity cross-check:",annuity_pv(100,.05,5),annuity_pv_sum(100,.05,5))
    unittest.main(verbosity=2)
```

**Validation boundary:** Standard-library educational comparison, not a continuous optimizer, all-IRR enumerator, financial calibration engine or certification. Forward compounding, NPV and the closed-form geometric annuity use integer/displayed-decimal rational arithmetic before finite float reporting. The direct annuity sum is a separate finite discounted-payment algorithm. Required nonzero outputs that would become zero and nonfinite outputs raise `ValueError`.

Implied rates use Decimal precision increased for small relative amount differences/large period counts; quadratic discriminants are exact rational quantities and stable-q roots use80-digit Decimal arithmetic before reporting. This avoids overflow/underflow of the discriminant, but does not prove that noisy coefficients or financially inferred parameters are well-conditioned. Both quadratic roots must be reportable; negative discriminants reject. An implied rate at or below−1 after rounding rejects despite positive input amounts.

Bisection/quadrature use the corrected finite-float callback protocol from Section17.1, stable coordinate construction, distinct-node checks, typed finite callbacks and stagnation/iteration failure. Public `bisect`/`irr` retain scalar-root returns here; residual substitution is recorded independently, not presented as a complete solver-status interface. ## 20. Troubleshooting

| Symptom | Explanation | Corrective action |
|---|---|---|
| Analytic and numerical answers differ | Units, conventions, or precision | Reconcile assumptions and intermediate values |
| IRR solver fails to bracket | No sign change or poor interval | Inspect NPV curve and select justified bracket |
| Two IRR answers appear | Multiple cash-flow sign changes | Report all economically relevant roots |
| Newton iteration diverges | Poor start or small derivative | Use safeguarded bracketed method |
| Annuity formula unstable near zero rate | Subtracting nearly equal numbers | Use log1p/expm1 or zero-rate limit |
| Quadratic roots inaccurate | Catastrophic cancellation | Use stable root formula |
| Integral depends strongly on N | Discretization error | Study grid convergence |
| Optimization violates a limit | Constraints missing or unchecked | Validate final solution independently |
| Residual tiny but parameter implausible | Ill-conditioning or wrong model | Check sensitivity and model assumptions |
| Code supplied but no test evidence | Runtime validation deferred | Execute and record evidence during QA |
