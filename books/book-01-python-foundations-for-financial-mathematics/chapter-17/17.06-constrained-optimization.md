## 1. Why constraints matter

An unconstrained mathematical optimum is often not an investable decision. Portfolio mandates can impose long-only holdings, position caps, sector limits, liquidity restrictions, target returns, turnover budgets, and leverage limits.

Constrained optimization finds the best decision **among feasible decisions**. A candidate with a better objective value but a violated risk limit is not an acceptable solution.

## 2. General mathematical formulation

The standard constrained minimization problem is:

**minimize f(x)**

subject to

**hⱼ(x)=0**, for equality constraints,

**gᵢ(x)≤0**, for inequality constraints,

and optional variable bounds **l≤x≤u**.

The feasible set is the collection of all x satisfying every constraint. If that set is empty, no optimizer can produce a valid solution.

## 3. Equality constraints

An equality constraint requires an exact relationship, within a documented numerical tolerance.

For a fully invested portfolio:

**Σᵢwᵢ=1**.

For two assets, **wB=1−wA**, allowing the problem to be reduced to one variable.

Other examples include cash-flow balance, liability matching, and prescribed hedge exposure.

## 4. Inequality constraints

An inequality restricts the allowed region without requiring equality.

For long-only weights:

**wᵢ≥0**, equivalently **−wᵢ≤0**.

For an asset cap:

**wA≤.4**, equivalently **wA−.4≤0**.

For a sector cap:

**Σᵢ∈sector wᵢ≤.3**.

The sign convention matters when interpreting Lagrange multipliers and KKT conditions.

## 5. Feasible sets and infeasibility

Suppose two assets must sum to 1, and each has a maximum weight of .4.

Then **wA+wB≤.8**, which contradicts **wA+wB=1**. The problem is infeasible.

A well-engineered optimization workflow checks simple feasibility conditions before calling a numerical solver, and reports infeasibility rather than silently relaxing policy.

## 6. Bound reduction for two assets

Let w denote the weight in asset A, so B has weight 1−w.

Suppose

**minA≤w≤maxA**

and

**minB≤1−w≤maxB**.

Combining bounds gives:

**lower=max(minA,1−maxB)**,

**upper=min(maxA,1−minB)**.

The feasible interval exists only if **lower≤upper**.

This reduction provides a transparent, independently checkable benchmark for a general constrained optimizer.

## 7. Portfolio variance objective

For two assets with variances A=σA², B=σB², and covariance C:

**V(w)=Aw²+B(1−w)²+2Cw(1−w)**.

Its derivative is

**V′(w)=2(A+B−2C)w−2(B−C)**.

When **A+B−2C>0**, the unconstrained minimum occurs at

**w*=(B−C)/(A+B−2C)**.

With interval constraints, the constrained optimum is the projection of w* onto the feasible interval.

If the covariance matrix is PSD and the denominator is zero, the portfolio variance is constant over budget-feasible weights, so the minimum is nonunique.

## 8. Worked example — position cap changes the optimum

Let **A=.04**, **B=.09**, and **C=0**.

The unconstrained minimum-variance weight in A is:

**w*=.09/(.04+.09)=9/13≈.6923077**.

Suppose policy imposes **wA≤.4** and both weights must be nonnegative.

The feasible interval is [0,.4]. Since the unconstrained minimum is outside the interval, the constrained optimum is:

**wA=.4, wB=.6**.

The variance becomes:

**V=.04(.4)²+.09(.6)²=.0064+.0324=.0388**.

The uncapped minimum variance is approximately .0276923. The increase in variance is the cost, under this model, of the binding concentration limit.

## 9. Active constraints and slack

For an inequality **g(x)≤0**, define slack **s=−g(x)**.

- **Active constraint:** s=0.
- **Inactive constraint:** s>0.
- **Violation:** s<0.

At wA=.4 with a cap of .4, the upper-bound slack is zero: the cap is active.

At wA=.3, slack is .1: the cap is inactive.

Checking slacks independently is a simple and effective solver validation technique.

## 10. Lagrange multipliers

For an equality-constrained problem:

**minimize f(x) subject to h(x)=0**,

define the Lagrangian:

**L(x,λ)=f(x)+λh(x)**.

Under appropriate differentiability and regularity assumptions, an interior constrained optimum satisfies:

**∇ₓL(x,λ)=0**, together with **h(x)=0**.

The multiplier λ often has a sensitivity interpretation: it describes how the optimal objective changes when the associated constraint's right-hand side changes, subject to sign convention and regularity assumptions.

## 11. Karush–Kuhn–Tucker conditions

For differentiable inequalities written as **gᵢ(x)≤0**, the Lagrangian is:

**L(x,λ,μ)=f(x)+Σⱼλⱼhⱼ(x)+Σᵢμᵢgᵢ(x)**.

KKT conditions include:

1. **Primal feasibility:** hⱼ(x)=0 and gᵢ(x)≤0.
2. **Dual feasibility:** μᵢ≥0.
3. **Stationarity:** ∇f+Σλⱼ∇hⱼ+Σμᵢ∇gᵢ=0.
4. **Complementary slackness:** μᵢgᵢ(x)=0.

KKT conditions are necessary for many local optima under constraint qualifications. In convex problems with suitable conditions, they also characterize global optimality.

## 12. Complementary slackness intuition

If a constraint is strictly inactive, gᵢ(x)<0, complementary slackness requires **μᵢ=0**.

A positive multiplier requires the corresponding constraint to be active.

An active constraint may nevertheless have a zero multiplier in a degenerate case. Therefore, **active does not always imply a strictly positive multiplier**.

## 13. Convex versus nonconvex constrained problems

If Σ is PSD, portfolio variance **wᵀΣw** is convex. Linear budget and box constraints form a convex feasible region.

Thus a local optimum of the long-only minimum-variance problem is global.

Constraints involving cardinality, discrete lots, and certain nonlinear transaction rules can make the feasible set nonconvex. Numerical solvers may then find only local solutions.

## 14. Return targets and exposure limits

A target expected return may be written:

**μᵀw≥R_target**.

A sector cap can be written:

**Aw≤b**,

where A selects and sums sector exposures.

These are linear constraints when μ and A are fixed. Their feasibility depends on the available assets and other restrictions.

For example, if all long-only assets have expected returns below 8%, a required expected return of at least 8% may be infeasible.

## 15. Turnover, costs, and leverage

A turnover constraint can take the form:

**Σᵢ|w_new,i−w_old,i|≤T_max**.

A gross leverage constraint can take the form:

**Σᵢ|wᵢ|≤L_max**.

Net budget **Σw=1** does not itself prevent leveraged long-short portfolios. For example, weights [1.2,−.2] have net exposure 1 but gross exposure 1.4.

Costs and turnover limits should be specified in compatible units and checked against the actual trade list.

## 16. Penalty methods versus hard constraints

A penalty approach adds a cost for violations:

**minimize f(x)+ρ×penalty(x)**.

Finite penalties do not automatically guarantee exact feasibility. For risk mandates, hard constraints are often more appropriate.

When soft constraints are used, clearly distinguish acceptable policy tradeoffs from non-negotiable limits.

## 17. SciPy SLSQP example

SciPy provides constrained numerical optimization through `scipy.optimize.minimize`.

```python
import numpy as np
from scipy.optimize import minimize

cov = np.array([[0.04, 0.0], [0.0, 0.09]])

def objective(w):
    return float(w @ cov @ w)

result = minimize(
    objective,
    x0=np.array([0.4, 0.6]),
    method="SLSQP",
    bounds=[(0.0, 0.4), (0.0, 1.0)],
    constraints=[
        {"type": "eq", "fun": lambda w: float(np.sum(w) - 1.0)}
    ],
    options={"ftol": 1e-12, "maxiter": 500},
)
if not result.success:
    raise RuntimeError(result.message)
assert abs(float(np.sum(result.x)) - 1.0) < 1e-8
assert -1e-8 <= result.x[0] <= 0.4 + 1e-8
assert abs(objective(result.x) - 0.0388) < 1e-7
```

This example requires NumPy and SciPy. The exact numerical output depends on solver tolerances and version; independent feasibility and objective checks are mandatory.

## 18. Complete standard-library reference implementation

Save as `constrained_optimization.py`. This reference solves the two-asset long-only minimum-variance problem analytically with box constraints, supplies a grid-search benchmark, calculates slacks, and includes **12 reference unit tests**.

```python
"""17.6 Constrained optimization: educational two-asset solver."""
import math
import unittest

def finite(x):
    return type(x) in (int,float) and math.isfinite(x)

def feasible_interval(cap_a=1.0,cap_b=1.0,min_a=0.0,min_b=0.0):
    vals=(cap_a,cap_b,min_a,min_b)
    if not all(finite(x) for x in vals):
        raise ValueError("nonfinite bound")
    if not all(0<=x<=1 for x in vals):
        raise ValueError("bounds outside [0,1]")
    if min_a>cap_a or min_b>cap_b:
        raise ValueError("inverted asset bounds")
    lo=max(min_a,1-cap_b)
    hi=min(cap_a,1-min_b)
    if lo>hi+1e-12:raise ValueError("infeasible portfolio")
    return lo,hi

def variance(weight_a,var_a,var_b,cov_ab):
    w=weight_a
    return w*w*var_a+(1-w)*(1-w)*var_b+2*w*(1-w)*cov_ab

def constrained_two_asset_gmv(var_a,var_b,cov_ab,
                              cap_a=1.0,cap_b=1.0,
                              min_a=0.0,min_b=0.0):
    if not all(finite(x) for x in (var_a,var_b,cov_ab)):
        raise ValueError("nonfinite covariance")
    if var_a<0 or var_b<0 or cov_ab*cov_ab>var_a*var_b+1e-12:
        raise ValueError("invalid two-asset covariance")
    lo,hi=feasible_interval(cap_a,cap_b,min_a,min_b)
    den=var_a+var_b-2*cov_ab
    if den<=1e-14:
        wa=(lo+hi)/2
        nonunique=True
    else:
        raw=(var_b-cov_ab)/den
        wa=min(hi,max(lo,raw))
        nonunique=False
    return {"weight_a":wa,"weight_b":1-wa,
            "variance":variance(wa,var_a,var_b,cov_ab),
            "feasible_interval":(lo,hi),"nonunique":nonunique}

def grid_solve(objective,lo,hi,steps=1000):
    if not all(finite(x) for x in (lo,hi)) or lo>hi or type(steps) is not int or steps<1:
        raise ValueError("invalid grid")
    best=None
    for i in range(steps+1):
        x=lo+(hi-lo)*i/steps
        y=objective(x)
        if not finite(y):raise ValueError("nonfinite objective")
        if best is None or y<best[1]:best=(x,y)
    return {"x":best[0],"value":best[1],"grid_spacing":(hi-lo)/steps}

def constraint_residuals(w_a,cap_a,cap_b,min_a=0,min_b=0):
    w_b=1-w_a
    return {"budget":w_a+w_b-1,
            "a_min_slack":w_a-min_a,
            "a_max_slack":cap_a-w_a,
            "b_min_slack":w_b-min_b,
            "b_max_slack":cap_b-w_b}

class ConstrainedTests(unittest.TestCase):
    def test_01_interval(self):self.assertEqual(feasible_interval(.4,1), (0,.4))
    def test_02_gmv(self):self.assertAlmostEqual(constrained_two_asset_gmv(.04,.09,0)["weight_a"],9/13)
    def test_03_cap(self):self.assertAlmostEqual(constrained_two_asset_gmv(.04,.09,0,cap_a=.4)["weight_a"],.4)
    def test_04_b_cap(self):self.assertAlmostEqual(constrained_two_asset_gmv(.04,.09,0,cap_b=.5)["weight_a"],9/13)
    def test_05_min_a(self):self.assertAlmostEqual(constrained_two_asset_gmv(.04,.09,0,min_a=.8)["weight_a"],.8)
    def test_06_infeasible(self):
        with self.assertRaises(ValueError):feasible_interval(.4,.4)
    def test_07_inverted(self):
        with self.assertRaises(ValueError):feasible_interval(.3,1,min_a=.5)
    def test_08_nonpsd(self):
        with self.assertRaises(ValueError):constrained_two_asset_gmv(.04,.09,.1)
    def test_09_nonunique(self):self.assertTrue(constrained_two_asset_gmv(.04,.04,.04)["nonunique"])
    def test_10_grid(self):self.assertAlmostEqual(grid_solve(lambda x:(x-.3)**2,.5,1,10)["x"],.5)
    def test_11_slacks(self):
        sl=constraint_residuals(.4,.4,1)
        self.assertAlmostEqual(sl["budget"],0)
        self.assertAlmostEqual(sl["a_max_slack"],0)
    def test_12_variance(self):self.assertAlmostEqual(variance(.5,.04,.09,0),.0325)

if __name__=="__main__":
    print("Unconstrained:",constrained_two_asset_gmv(.04,.09,0))
    print("Capped:",constrained_two_asset_gmv(.04,.09,0,cap_a=.4))
    unittest.main(verbosity=2)
```

## 21. Troubleshooting

| Symptom | Likely cause | Corrective action |
|---|---|---|
| Solver reports infeasible | Conflicting bounds or targets | Check feasible set before solving |
| Weights sum to 0.999 | Numerical tolerance | Inspect equality residual and acceptance threshold |
| Position exceeds cap | Constraint omitted or tolerance too loose | Check all slacks independently |
| Variance negative | Invalid covariance matrix | Validate PSD |
| Solver finds different answers | Nonconvexity or degeneracy | Check convexity and multiple starts |
| High turnover despite low variance | Turnover not modeled | Add appropriate trading constraints |
| Soft penalty permits violations | Finite penalty not sufficient | Use hard constraints for mandatory limits |
| KKT multipliers appear inconsistent | Wrong inequality sign convention | Re-derive Lagrangian consistently |
| No runtime evidence | QA intentionally deferred | Execute and retain tests during QA |
