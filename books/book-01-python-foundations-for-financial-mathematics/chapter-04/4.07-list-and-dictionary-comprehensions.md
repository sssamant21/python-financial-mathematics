## 4.7.1 Purpose

A comprehension constructs a collection from an iterable using an expression and optional selection conditions. It is useful when a financial transformation has a small, clear rule: select positive positions, extract instrument identifiers, or create a lookup from validated records.

Concise syntax does not establish valid financial inputs. A dictionary comprehension can also conceal duplicate identifiers by replacing earlier values. This section combines compact transformations with explicit validation and identity policies.

## 4.7.2 Learning Objectives

After completing this section, you should be able to:

1. Translate an append loop into a list comprehension.
2. Distinguish selection from conditional replacement.
3. Construct a dictionary without silently losing duplicate records.
4. Read nested comprehension clauses in loop order.
5. Explain which objects a comprehension creates and which it shares.
6. Keep validation and side effects in readable functions or loops.
7. Verify equivalence, ordering, empty inputs, and rejection behavior.

## 4.7.3 From a Loop to a List Comprehension

Run the introductory Python blocks in order in one session. All data is synthetic.

```python
from decimal import Decimal

quantities = [Decimal("12.5"), Decimal("0"), Decimal("3")]
positive_loop = []
for quantity in quantities:
    if quantity > 0:
        positive_loop.append(quantity)

positive = [quantity for quantity in quantities if quantity > 0]
assert positive == positive_loop == [Decimal("12.5"), Decimal("3")]
assert quantities == [Decimal("12.5"), Decimal("0"), Decimal("3")]
```

Read the comprehension as: visit each quantity, retain those above zero, and place each retained quantity in a new list. It preserves the traversal order of the selected items. It does not sort or deduplicate them.

The general form is `[expression for item in iterable if condition]`. The trailing condition is optional. For each visited item, the condition determines whether the result expression is evaluated and appended.

These quantities are already known to be valid finite Decimal values. Filtering on `quantity > 0` is not a substitute for checking type, finiteness, or the policy for negative positions.

## 4.7.4 Selection Versus Conditional Replacement

A trailing `if` selects items. An expression containing `if ... else ...` produces a value for every visited item.

```python
selected = [q for q in quantities if q > 0]
labels = ["positive" if q > 0 else "zero" for q in quantities]
assert len(selected) == 2
assert labels == ["positive", "zero", "positive"]

# Explicit comparison retains zero; truth testing would remove it.
zero_positions = [q for q in quantities if q == 0]
assert zero_positions == [Decimal("0")]
```

The label rule assumes nonnegative input. Applied to negative input it would incorrectly label a negative quantity as zero. Domain assumptions belong beside the transformation.

In financial data, zero can be meaningful. A condition such as `if amount` discards zero as well as other false values. Use an explicit business condition rather than truth testing when those distinctions matter.

## 4.7.5 Dictionary Comprehensions and Collisions

A dictionary comprehension uses `{key_expression: value_expression for item in iterable}`. Keys must be hashable. Each produced key identifies one dictionary entry.

```python
pairs = [("BOND-A", Decimal("12.5")), ("ETF-B", Decimal("3"))]
by_id = {instrument_id: quantity for instrument_id, quantity in pairs}
assert list(by_id) == ["BOND-A", "ETF-B"]
assert by_id["ETF-B"] == Decimal("3")

repeated = [("BOND-A", Decimal("12.5")), ("BOND-A", Decimal("2"))]
last_value = {instrument_id: quantity for instrument_id, quantity in repeated}
assert last_value == {"BOND-A": Decimal("2")}
```

The second example deliberately demonstrates information loss. Repeated keys retain the last assigned value; they do not add quantities or preserve lots. Replacing a value for an existing key does not move that key to a new insertion position.

Decide whether identity means instrument, account plus instrument, or individual tax lot before creating a lookup. The lab rejects repeated instrument IDs within its single-portfolio dataset. Aggregating lots is a separate transformation with its own unit and arithmetic rules.

## 4.7.6 Nested Clauses Follow Loop Order

Flattening can be expressed with more than one `for` clause. Read the clauses left to right as nested loops, while reading the result expression as the output record.

```python
portfolios = [
    {"portfolio_id": "P-1", "instrument_ids": ["BOND-A", "ETF-B"]},
    {"portfolio_id": "P-2", "instrument_ids": ["BOND-A"]},
    {"portfolio_id": "P-3", "instrument_ids": []},
]
flat = [
    (portfolio["portfolio_id"], instrument_id)
    for portfolio in portfolios
    for instrument_id in portfolio["instrument_ids"]
]
assert flat == [("P-1", "BOND-A"), ("P-1", "ETF-B"), ("P-2", "BOND-A")]
```

The outer portfolio is visited first, then each of its instruments. Preserve the portfolio identifier because instrument IDs may repeat across portfolios. The empty portfolio produces no rows; retain a separate parent table if the report must preserve empty portfolios.

Use an ordinary loop when additional nesting makes the relationship difficult to inspect. Compactness has little value if a reviewer cannot reconstruct the output contract.

## 4.7.7 New Containers and Shared Records

Creating a new list does not copy each selected record.

```python
records = [{"instrument_id": "BOND-A", "quantity": Decimal("12.5")}]
selected_records = [record for record in records]
assert selected_records is not records
assert selected_records[0] is records[0]

rebuilt_records = [
    {"instrument_id": record["instrument_id"], "quantity": record["quantity"]}
    for record in records
]
assert rebuilt_records[0] is not records[0]
rebuilt_records[0]["quantity"] = Decimal("99")
assert records[0]["quantity"] == Decimal("12.5")
```

Reconstruction creates independent record dictionaries for this schema. The retained strings and Decimal objects are immutable. Adding a mutable field, such as a list of tags, would require revisiting the ownership contract. Neither a comprehension nor a shallow dictionary copy automatically isolates all descendants.

## 4.7.8 Keep Construction Free of Hidden Work

Use comprehensions to build results. Do not build a throwaway list solely to call logging functions, write files, update source records, or send requests. An ordinary loop expresses those actions directly and allows clear failure handling.

List and dictionary comprehensions eagerly build their output containers. Memory use grows with the materialized output. They are not a promise of faster execution, and a list comprehension should not be called vectorization. Measure representative workloads before making performance claims.

Comprehension iteration variables have their own scope in Python 3. Still choose descriptive names; scope rules do not make deeply nested expressions easier to maintain.

## 4.7.9 Lab Contract — Validated Position Views

Save the complete next block as `comprehensions_lab.py` using Python 3.10 or later. It needs only the standard library.

The input represents one portfolio snapshot. The function does not accept lots, multiple portfolios, or mixed schemas.

| Input or output | Contract |
|---|---|
| Input | List of dictionaries with exactly instrument_id and quantity |
| instrument_id | Nonempty string without surrounding whitespace; case preserved |
| quantity | Finite nonnegative Decimal units; fractional and zero quantities allowed |
| Identity | Instrument IDs unique across the entire input, including zero positions |
| All records | Validated before selection; invalid zero or later records are rejected |
| active_rows | Fresh record dictionaries for strictly positive quantities, in input order |
| quantities_by_id | Lookup for active rows only; same insertion order |
| Empty input | Empty list and empty dictionary |
| Failure | TypeError for wrong types; ValueError for schema/domain/duplicate violations |
| Ownership | Source unchanged; returned mutable containers are independent |

The return value is a tuple containing the two views. The lookup omits valid zero positions deliberately; absence there means “not active in this view,” not “instrument never existed.” No prices, currency conversions, totals, or valuation are calculated.

Validation uses an explicit loop so errors identify a record and duplicates cannot disappear during dictionary construction. After validation, two comprehensions express the output rules. This separates the input contract from the selection policy.

## 4.7.10 Complete Runnable Lab

```python
"""Build active position views from a validated single-portfolio snapshot."""

from decimal import Decimal
import unittest


def build_active_views(
    value: object,
) -> tuple[list[dict[str, object]], dict[str, Decimal]]:
    """Validate every input row, reject duplicate IDs, then build fresh views.

    Quantity is finite nonnegative Decimal instrument units. Zero positions
    are valid but omitted from both returned views. No valuation is performed.
    Mutable input/output containers are not shared under this two-field schema.
    """
    if not isinstance(value, list):
        raise TypeError("positions must be a list")

    validated: list[tuple[str, Decimal]] = []
    seen: set[str] = set()
    for index, row in enumerate(value):
        if not isinstance(row, dict):
            raise TypeError(f"position {index} must be a dictionary")
        if set(row) != {"instrument_id", "quantity"}:
            raise ValueError(f"position {index} has incorrect fields")
        instrument_id = row["instrument_id"]
        quantity = row["quantity"]
        if not isinstance(instrument_id, str):
            raise TypeError(f"position {index} instrument_id must be a string")
        if not instrument_id or instrument_id.strip() != instrument_id:
            raise ValueError(f"position {index} instrument_id is blank or padded")
        if not isinstance(quantity, Decimal):
            raise TypeError(f"position {index} quantity must be Decimal")
        if not quantity.is_finite() or quantity < 0:
            raise ValueError(f"position {index} quantity must be finite and nonnegative")
        if instrument_id in seen:
            raise ValueError(f"duplicate instrument_id: {instrument_id}")
        seen.add(instrument_id)
        validated.append((instrument_id, quantity))

    active_rows: list[dict[str, object]] = [
        {"instrument_id": instrument_id, "quantity": quantity}
        for instrument_id, quantity in validated
        if quantity > 0
    ]
    quantities_by_id = {
        instrument_id: quantity
        for instrument_id, quantity in validated
        if quantity > 0
    }
    return active_rows, quantities_by_id


def sample_positions() -> list[dict[str, object]]:
    return [
        {"instrument_id": "BOND-A", "quantity": Decimal("12.5")},
        {"instrument_id": "CASH-RESERVE", "quantity": Decimal("0")},
        {"instrument_id": "ETF-B", "quantity": Decimal("3")},
    ]


class ComprehensionTests(unittest.TestCase):
    def test_values_order_and_loop_equivalence(self) -> None:
        source = sample_positions()
        rows, lookup = build_active_views(source)
        expected = [
            {"instrument_id": "BOND-A", "quantity": Decimal("12.5")},
            {"instrument_id": "ETF-B", "quantity": Decimal("3")},
        ]
        self.assertEqual(rows, expected)
        self.assertEqual(lookup, {"BOND-A": Decimal("12.5"), "ETF-B": Decimal("3")})
        self.assertEqual(list(lookup), ["BOND-A", "ETF-B"])
        loop_rows: list[dict[str, object]] = []
        for row in source:
            quantity = row["quantity"]
            if isinstance(quantity, Decimal) and quantity > 0:
                loop_rows.append(dict(row))
        self.assertEqual(rows, loop_rows)

    def test_empty_and_all_zero(self) -> None:
        self.assertEqual(build_active_views([]), ([], {}))
        self.assertEqual(build_active_views([
            {"instrument_id": "A", "quantity": Decimal("0")}
        ]), ([], {}))

    def test_duplicate_even_when_zero(self) -> None:
        for quantity in (Decimal("0"), Decimal("2")):
            with self.subTest(quantity=quantity):
                with self.assertRaises(ValueError):
                    build_active_views([
                        {"instrument_id": "A", "quantity": Decimal("0")},
                        {"instrument_id": "A", "quantity": quantity},
                    ])

    def test_quantity_type_and_domain(self) -> None:
        for quantity in (True, 1, 1.5, "2", None):
            with self.subTest(quantity=quantity):
                with self.assertRaises(TypeError):
                    build_active_views([{"instrument_id": "A", "quantity": quantity}])
        for text in ("NaN", "sNaN", "Infinity", "-Infinity", "-0.01"):
            with self.subTest(text=text):
                with self.assertRaises(ValueError):
                    build_active_views([{"instrument_id": "A", "quantity": Decimal(text)}])

    def test_structure_and_identity(self) -> None:
        invalid_inputs: list[object] = [None, {}, (), "positions"]
        for value in invalid_inputs:
            with self.subTest(value=value):
                with self.assertRaises(TypeError):
                    build_active_views(value)
        with self.assertRaises(TypeError):
            build_active_views([None])
        for row in ({}, {"instrument_id": "A"}, {
            "instrument_id": "A", "quantity": Decimal("0"), "extra": 1
        }):
            with self.subTest(row=row):
                with self.assertRaises(ValueError):
                    build_active_views([row])
        for instrument_id in ("", " A", "A ", " "):
            with self.subTest(instrument_id=instrument_id):
                with self.assertRaises(ValueError):
                    build_active_views([{
                        "instrument_id": instrument_id, "quantity": Decimal("0")
                    }])
        with self.assertRaises(TypeError):
            build_active_views([{"instrument_id": 1, "quantity": Decimal("0")}])

    def test_ownership_and_repeatability(self) -> None:
        source = sample_positions()
        rows, lookup = build_active_views(source)
        self.assertEqual(source, sample_positions())
        self.assertIsNot(rows, source)
        self.assertIsNot(rows[0], source[0])
        rows[0]["quantity"] = Decimal("99")
        lookup["ETF-B"] = Decimal("88")
        self.assertEqual(source, sample_positions())
        self.assertEqual(lookup["BOND-A"], Decimal("12.5"))
        self.assertEqual(rows[1]["quantity"], Decimal("3"))
        self.assertEqual(build_active_views(source), build_active_views(source))

    def test_invalid_later_record_does_not_mutate_source(self) -> None:
        source = sample_positions()
        source.append({"instrument_id": "BAD", "quantity": Decimal("NaN")})
        before_ids = [id(row) for row in source]
        with self.assertRaises(ValueError):
            build_active_views(source)
        self.assertEqual([id(row) for row in source], before_ids)
        self.assertEqual(source[:3], sample_positions())
        self.assertTrue(isinstance(source[3]["quantity"], Decimal))
        self.assertEqual(str(source[3]["quantity"]), "NaN")


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

## 4.7.12 Common Mistakes and Corrections

| Symptom | Likely cause | Correction |
|---|---|---|
| Position count shrinks unexpectedly | Duplicate dictionary keys | Validate identity before construction |
| Zero records vanish | Truth testing used for selection | State the comparison explicitly |
| Invalid records are silently ignored | Filtering used as validation | Validate the entire input first |
| Source records change | Selected dictionaries are shared | Reconstruct the schema's mutable containers |
| Empty portfolios disappear | Flattening emits only child rows | Preserve parent metadata separately |
| A label misclassifies negative data | Rule assumes nonnegative inputs | Validate the domain before applying the rule |
| Expression is hard to debug | Nested conditions and hidden actions | Use named helpers or ordinary loops |

## 4.7.14 Key Takeaways

Use comprehensions when a collection transformation has a clear expression and selection rule. Preserve traversal order deliberately, reject duplicate identities before dictionary construction, and state whether returned records share mutable objects.

Validation remains a separate responsibility. A short expression is useful only when its assumptions and output can be checked easily.
