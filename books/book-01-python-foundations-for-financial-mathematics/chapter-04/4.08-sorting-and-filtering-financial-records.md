## 4.8.1 Purpose

A report needs an explicit selection rule and ordering rule. “Largest positions” is incomplete unless the report defines the measurement, currency, threshold, tie handling, and number of rows.

This section builds a reproducible view of synthetic position values. The values are supplied observations, not prices calculated by the program. Validation precedes selection so an excluded record cannot conceal an invalid input.

## 4.8.2 Learning Objectives

You should be able to:

1. Choose between `sorted()` and `list.sort()`.
2. Define a named sorting key and a deterministic tie rule.
3. Apply inclusive thresholds and currency selection explicitly.
4. Distinguish stable ordering from input-independent ordering.
5. Validate all records before selecting a report subset.
6. Return independent records without changing source data.
7. Test exact order, boundary values, invalid inputs, and empty results.

## 4.8.3 Sorting Mechanics

`sorted()` returns a new list; `list.sort()` rearranges its receiver and returns `None`. A key function supplies each item's comparison value. Sorting is stable: equal keys retain their relative input order, including descending sorts. A tuple key compares components in sequence. These rules support explicit report ordering without comparing entire dictionaries.

Run the introductory Python blocks in order in one session.

```python
from decimal import Decimal
from operator import itemgetter

observations = [
    ("ZETA", Decimal("100")),
    ("BETA", Decimal("250")),
    ("ALPHA", Decimal("100")),
]
ascending = sorted(observations, key=itemgetter(1))
assert [row[0] for row in ascending] == ["ZETA", "ALPHA", "BETA"]
assert observations[0][0] == "ZETA"

working = list(observations)
result = working.sort(key=itemgetter(1), reverse=True)
assert result is None
assert [row[0] for row in working] == ["BETA", "ZETA", "ALPHA"]
```

Here itemgetter(1) extracts the supplied numeric value. The equal-valued ZETA and ALPHA records remain in source order. Sorting by string-formatted amounts would apply text ordering, so numeric fields must be validated and retained as numbers.

## 4.8.4 Stability and a Complete Tie Rule

Stable sorting is useful when input sequence is part of the contract. A report assembled from changing input order often needs a secondary identifier instead. Unique identities make that tie rule complete for this dataset.

To rank values descending and identifiers ascending, sort the identifier first and then perform a stable descending value sort. This avoids changing the direction of both fields together.

```python
by_identifier = sorted(observations, key=itemgetter(0))
ranked = sorted(by_identifier, key=itemgetter(1), reverse=True)
assert [row[0] for row in ranked] == ["BETA", "ALPHA", "ZETA"]

# A single reverse flag also reverses the identifier tie rule.
wrong_ties = sorted(observations, key=itemgetter(1, 0), reverse=True)
assert [row[0] for row in wrong_ties] == ["BETA", "ZETA", "ALPHA"]
```

The lab uses two passes with named functions. It does not negate Decimal values to construct a descending key. No amount arithmetic or rounding is needed for selection and ordering.

Identifier order is Python's case-sensitive string order. It is not a locale-aware display order or a financial priority ranking. The lab preserves identifier case rather than silently normalizing it.

## 4.8.5 Filter Before Limiting

The threshold in this section is inclusive: an amount equal to the minimum qualifies. A row limit is applied after currency selection, threshold selection, and final ordering.

```python
minimum = Decimal("100")
qualifying = [row for row in ranked if row[1] >= minimum]
assert [row[0] for row in qualifying[:2]] == ["BETA", "ALPHA"]
assert [row[0] for row in ranked[:0]] == []
assert [row for row in ranked if row[1] > Decimal("250")] == []
```

A limit of zero means no rows. It does not exempt the input from validation. Limiting the source before ranking answers a different question: the largest values among an arbitrary initial subset.

Currency labels are not conversion instructions. The lab selects one currency before comparing amounts for the report. It never ranks USD and EUR values together or computes their sum.

## 4.8.6 Validation, Missing Values, and Ownership

For this teaching report, missing fields, extra fields, nonfinite values, negative values, duplicate position IDs, and unsupported currencies are errors. Zero is valid. This is a deliberately narrow long-only, nonnegative-value snapshot; negative liabilities or short positions would require a revised domain contract.

Do not substitute zero for a missing amount using `row.get("market_value", 0)`. That would turn an unknown observation into a real numeric value. A production pipeline may instead quarantine incomplete records, but that policy should identify rejected rows and report their count.

A new sorted list can still share record dictionaries with its source. The lab validates into immutable tuples and reconstructs the returned dictionaries. Its ownership guarantee covers exactly three scalar fields. Nested mutable additions need a new copy policy.

## 4.8.7 Lab Contract — Ranked Position Report

Save the complete block below as `sorting_filtering_lab.py`. Use Python 3.10 or later; no third-party dependency is needed.

| Item | Rule |
|---|---|
| Dataset | One supplied snapshot with a common observation basis |
| Row schema | Exactly position_id, currency, market_value |
| position_id | Unique nonempty string without surrounding whitespace |
| currency | Exactly USD or EUR, as a string |
| market_value | Finite nonnegative Decimal amount in that row's currency |
| currency argument | USD or EUR |
| minimum argument | Finite nonnegative Decimal in the selected currency |
| limit argument | Nonnegative int; bool rejected |
| Selection | Selected currency and market_value >= minimum |
| Ordering | Value descending, then position_id ascending |
| Limit | Maximum rows after ordering; zero returns an empty view |
| Invalid input | TypeError for types; ValueError for schema/domain/identity errors |
| Ownership | No source mutation; fresh output list and row dictionaries |

Every row is checked, including rows in the other currency and rows below the threshold. The function returns no partial report on failure. It does not fetch prices, establish valuation dates, perform FX conversion, reconcile accounting balances, or certify the supplied values.

## 4.8.8 Complete Runnable Lab

```python
"""Validate a snapshot, select one currency, and rank supplied values."""

from decimal import Decimal
import unittest

Position = tuple[str, str, Decimal]


def checked_currency(value: object) -> str:
    if not isinstance(value, str):
        raise TypeError("currency must be a string")
    if value not in {"USD", "EUR"}:
        raise ValueError("currency must be USD or EUR")
    return value


def checked_amount(value: object, label: str) -> Decimal:
    if not isinstance(value, Decimal):
        raise TypeError(f"{label} must be Decimal")
    if not value.is_finite() or value < 0:
        raise ValueError(f"{label} must be finite and nonnegative")
    return value


def position_id_key(position: Position) -> str:
    return position[0]


def position_value_key(position: Position) -> Decimal:
    return position[2]


def ranked_positions(
    value: object,
    *,
    currency: object,
    minimum: object,
    limit: object,
) -> list[dict[str, object]]:
    """Return value-descending, ID-ascending rows under an inclusive threshold.

    Validate all rows before filtering, including for a zero limit.
    Supplied values are nonnegative Decimal amounts; no valuation is computed.
    """
    selected_currency = checked_currency(currency)
    threshold = checked_amount(minimum, "minimum")
    if isinstance(limit, bool) or not isinstance(limit, int):
        raise TypeError("limit must be an int, not bool")
    if limit < 0:
        raise ValueError("limit must be nonnegative")
    if not isinstance(value, list):
        raise TypeError("positions must be a list")

    validated: list[Position] = []
    seen: set[str] = set()
    for index, row in enumerate(value):
        if not isinstance(row, dict):
            raise TypeError(f"position {index} must be a dictionary")
        if set(row) != {"position_id", "currency", "market_value"}:
            raise ValueError(f"position {index} has incorrect fields")
        position_id = row["position_id"]
        if not isinstance(position_id, str):
            raise TypeError(f"position {index} ID must be a string")
        if not position_id or position_id.strip() != position_id:
            raise ValueError(f"position {index} ID is blank or padded")
        row_currency = checked_currency(row["currency"])
        amount = checked_amount(row["market_value"], f"position {index} value")
        if position_id in seen:
            raise ValueError(f"duplicate position_id: {position_id}")
        seen.add(position_id)
        validated.append((position_id, row_currency, amount))

    selected = [
        row for row in validated
        if row[1] == selected_currency and row[2] >= threshold
    ]
    # Sort the secondary key first; stability preserves it in primary ties.
    by_id = sorted(selected, key=position_id_key)
    ranked = sorted(by_id, key=position_value_key, reverse=True)
    return [
        {"position_id": pid, "currency": ccy, "market_value": amount}
        for pid, ccy, amount in ranked[:limit]
    ]


def sample_positions() -> list[dict[str, object]]:
    return [
        {"position_id": "ZETA", "currency": "USD", "market_value": Decimal("100")},
        {"position_id": "EU-1", "currency": "EUR", "market_value": Decimal("900")},
        {"position_id": "BETA", "currency": "USD", "market_value": Decimal("250")},
        {"position_id": "ALPHA", "currency": "USD", "market_value": Decimal("100")},
        {"position_id": "ZERO", "currency": "USD", "market_value": Decimal("0")},
    ]


class ReportTests(unittest.TestCase):
    def test_exact_report_and_boundary(self) -> None:
        report = ranked_positions(sample_positions(), currency="USD",
                                  minimum=Decimal("100"), limit=3)
        self.assertEqual(report, [
            {"position_id": "BETA", "currency": "USD", "market_value": Decimal("250")},
            {"position_id": "ALPHA", "currency": "USD", "market_value": Decimal("100")},
            {"position_id": "ZETA", "currency": "USD", "market_value": Decimal("100")},
        ])
        self.assertEqual(ranked_positions(sample_positions(), currency="USD",
                         minimum=Decimal("100.01"), limit=5), report[:1])

    def test_order_independent_ties_and_limit(self) -> None:
        original = sample_positions()
        report = ranked_positions(original, currency="USD", minimum=Decimal("0"), limit=2)
        reversed_report = ranked_positions(list(reversed(original)), currency="USD",
                                           minimum=Decimal("0"), limit=2)
        self.assertEqual(report, reversed_report)
        self.assertEqual([row["position_id"] for row in report], ["BETA", "ALPHA"])

    def test_currency_empty_and_zero(self) -> None:
        report = ranked_positions(sample_positions(), currency="EUR", minimum=Decimal("0"), limit=10)
        self.assertEqual([row["position_id"] for row in report], ["EU-1"])
        for source, threshold, limit in (([], Decimal("0"), 5),
                                         (sample_positions(), Decimal("251"), 5),
                                         (sample_positions(), Decimal("0"), 0)):
            self.assertEqual(ranked_positions(source, currency="USD", minimum=threshold, limit=limit), [])
        report = ranked_positions(sample_positions(), currency="USD", minimum=Decimal("0"), limit=10)
        self.assertEqual(report[-1]["position_id"], "ZERO")

    def test_arguments(self) -> None:
        for bad_limit in (True, 1.5, "2", None):
            with self.subTest(limit=bad_limit):
                with self.assertRaises(TypeError):
                    ranked_positions([], currency="USD", minimum=Decimal("0"), limit=bad_limit)
        with self.assertRaises(ValueError):
            ranked_positions([], currency="USD", minimum=Decimal("0"), limit=-1)
        with self.assertRaises(TypeError):
            ranked_positions([], currency=None, minimum=Decimal("0"), limit=1)
        with self.assertRaises(ValueError):
            ranked_positions([], currency="usd", minimum=Decimal("0"), limit=1)
        with self.assertRaises(TypeError):
            ranked_positions([], currency="USD", minimum=0, limit=1)
        for text in ("NaN", "sNaN", "Infinity", "-1"):
            with self.subTest(text=text):
                with self.assertRaises(ValueError):
                    ranked_positions([], currency="USD", minimum=Decimal(text), limit=1)

    def test_structure_identity_and_duplicates(self) -> None:
        bad_sources: list[object] = [None, {}, (), [None]]
        for source in bad_sources:
            with self.subTest(source=source):
                with self.assertRaises(TypeError):
                    ranked_positions(source, currency="USD", minimum=Decimal("0"), limit=1)
        for row in ({}, {"position_id": "A", "currency": "USD"}, {
            "position_id": "A", "currency": "USD", "market_value": Decimal("0"), "extra": 1
        }):
            with self.assertRaises(ValueError):
                ranked_positions([row], currency="USD", minimum=Decimal("0"), limit=1)
        for pid in ("", " A", "A "):
            with self.assertRaises(ValueError):
                ranked_positions([{"position_id": pid, "currency": "USD", "market_value": Decimal("0")}],
                                 currency="USD", minimum=Decimal("0"), limit=1)
        with self.assertRaises(TypeError):
            ranked_positions([{"position_id": 1, "currency": "USD", "market_value": Decimal("0")}],
                             currency="USD", minimum=Decimal("0"), limit=1)
        source = sample_positions()
        source.append(dict(source[0]))
        with self.assertRaises(ValueError):
            ranked_positions(source, currency="USD", minimum=Decimal("999"), limit=0)

    def test_invalid_excluded_values(self) -> None:
        for amount in (None, True, 1, 1.5, "100"):
            with self.subTest(amount=amount):
                with self.assertRaises(TypeError):
                    ranked_positions([{"position_id": "A", "currency": "EUR", "market_value": amount}],
                                     currency="USD", minimum=Decimal("999"), limit=0)
        for text in ("NaN", "sNaN", "Infinity", "-Infinity", "-0.01"):
            source = sample_positions()
            source.append({"position_id": "BAD", "currency": "EUR", "market_value": Decimal(text)})
            with self.subTest(text=text):
                with self.assertRaises(ValueError):
                    ranked_positions(source, currency="USD", minimum=Decimal("999"), limit=0)
        with self.assertRaises(ValueError):
            ranked_positions([{"position_id": "A", "currency": "GBP", "market_value": Decimal("0")}],
                             currency="USD", minimum=Decimal("0"), limit=1)

    def test_source_and_output_ownership(self) -> None:
        source = sample_positions()
        report = ranked_positions(source, currency="USD", minimum=Decimal("0"), limit=10)
        self.assertEqual(source, sample_positions())
        self.assertIsNot(report, source)
        self.assertIsNot(report[0], source[2])
        report[0]["market_value"] = Decimal("999")
        report.append({})
        self.assertEqual(source, sample_positions())
        repeat = ranked_positions(source, currency="USD", minimum=Decimal("0"), limit=10)
        self.assertEqual(repeat[0]["market_value"], Decimal("250"))


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

## 4.8.10 Operational Boundaries

A deterministic ordering rule does not freeze changing data. Reproducible reports also need an identified input snapshot, observation basis, and preserved selection parameters. Capture those outside this small function when integrating it into a reporting workflow.

Likewise, a stable sort does not remove duplicates. Identity validation is independent of ranking. If two accounts hold the same instrument, use distinct position IDs or define an appropriate composite identity.

Full sorting materializes the selected rows. For very large datasets, database ordering, streaming selection, or specialized top-k tools may be appropriate; their tie and consistency rules must match the report contract. This lab makes no performance benchmark claim.

## 4.8.11 Troubleshooting

| Problem | Cause to inspect | Correction |
|---|---|---|
| Source order changes unexpectedly | In-place sort used | Sort a separate view or use sorted |
| Result is None | Assigned the return of list.sort | Use the mutated list or sorted |
| Ties change between input snapshots | Only value used as key | Define an explicit secondary identity |
| Largest report misses a record | Limited before filtering/ranking | Apply the limit last |
| Equal minimum excluded | Strict greater-than comparison | Use the documented inclusive comparison |
| Currency values compared together | Currency selection omitted | Select one currency or implement explicit FX policy |
| Invalid excluded records go unnoticed | Validation performed after selection | Validate the entire input |
| Source record changes with report | Dictionary sharing | Reconstruct output records under a schema |

## 4.8.13 Key Takeaways

Define the measurement and selection boundary before ordering records. Validate all rows, select the intended currency and threshold, resolve ties explicitly, and apply the limit last.

Treat source ownership and snapshot reproducibility as separate contracts. A correctly ordered list cannot establish that its supplied financial values are correct.
