## 4.2.1 Purpose

A list stores an ordered, mutable sequence of objects. Financial examples include payment amounts, observed returns, scenario results, and identifiers.

Order and duplicates are preserved, but their financial meaning must be supplied by the model. Index 0 might represent period 0 or the first future payment; Python cannot decide which.

This section covers creation, indexing, slicing, updates, iteration, copying, and common list errors. Comprehensions, sorting financial records, and detailed cash-flow schedules follow later in this chapter.

## 4.2.2 Learning Objectives

You should be able to:

2. Use positive and negative indexes and half-open slices.
3. Distinguish append, extend, insert, remove, and pop.
4. Iterate while preserving period meaning.
5. Explain aliasing and shallow copies.
6. Validate a list of amounts and filter into a new list without changing its input.

## 4.2.3 Creating a Financial List

```python
from decimal import Decimal

cash_flows = [
    Decimal("-1000"),
    Decimal("400"),
    Decimal("400"),
    Decimal("400"),
]

assert len(cash_flows) == 4
assert cash_flows.count(Decimal("400")) == 3
```

For this example only, index 0 is a period-0 investment outflow. Indexes 1–3 are receipts at the ends of three successive equal periods. All amounts share a currency.

A list permits repeated values. Three equal receipts are not automatically duplicates to remove.

An empty list is written []. A list can hold mixed types, but a financial amount collection should normally enforce the intended representation rather than rely on that flexibility.

## 4.2.4 Indexing and Boundaries

```python
assert cash_flows[0] == Decimal("-1000")
assert cash_flows[1] == Decimal("400")
assert cash_flows[-1] == Decimal("400")

try:
    cash_flows[4]
except IndexError:
    pass
else:
    raise AssertionError("Expected out-of-range access")
```

Indexes begin at zero. A negative index counts from the end. Index -1 refers to the final item only when the list is nonempty.

Indexing an empty list raises IndexError. Check whether the list has the required observation before retrieving it. Do not invent a zero payment to conceal missing data.

## 4.2.5 Slices Are Half-Open

```python
future_receipts = cash_flows[1:4]
assert future_receipts == [Decimal("400"), Decimal("400"), Decimal("400")]
assert cash_flows[:1] == [Decimal("-1000")]
assert cash_flows[99:] == []
assert cash_flows[::-1][0] == cash_flows[-1]
```

The slice start is included and stop is excluded. Missing boundaries extend to the appropriate end. Out-of-range slice boundaries are clipped, unlike individual indexing.

A slice creates a new outer list. Its elements still reference the same objects as the source. Reversing order changes the implied timeline if positions encode dates or periods.

## 4.2.6 Adding Items

```python
receipts = [Decimal("100")]
receipts.append(Decimal("200"))
receipts.extend([Decimal("300"), Decimal("400")])
receipts.insert(0, Decimal("50"))

assert receipts == [
    Decimal("50"), Decimal("100"), Decimal("200"),
    Decimal("300"), Decimal("400"),
]
```

append adds one object, extend adds each item from an iterable, and insert places an object before the specified position.

Appending a list creates a nested list; extending by that list adds its individual members. Be deliberate about the required shape.

These operations mutate the list and return None. Do not assign the result of append back to the list variable.

## 4.2.7 Replacing and Removing Items

```python
revised = receipts.copy()
revised[0] = Decimal("75")
removed = revised.pop()
assert removed == Decimal("400")

revised.remove(Decimal("200"))
del revised[0]
assert revised == [Decimal("100"), Decimal("300")]
assert len(receipts) == 5
```

Assignment replaces an item at a position. pop removes and returns an item, using the final position by default. remove deletes the first equal value and raises ValueError when none exists. del deletes by position or slice. clear empties a list.

Removing an amount by value may select the wrong transaction when equal amounts occur repeatedly. Use a record's identifier when the business operation targets a specific transaction.

## 4.2.8 Membership and Search

The expression value in values tests membership; it does not return the matching position. index returns the first matching index and raises ValueError when absent.

An index of zero is a valid position. Avoid treating it as missing through a truthiness check.

Equality of amounts does not establish payment identity. A list of named records can preserve additional fields when amount-only lists are insufficient.

## 4.2.9 Iteration and Period Meaning

```python
observed_periods = []
for period, amount in enumerate(cash_flows):
    observed_periods.append(period)

assert observed_periods == [0, 1, 2, 3]
```

enumerate supplies positions with values. Its default start is zero. Use start=1 only when the first element actually represents period 1.

A list containing period-1 receipts should not be interpreted as beginning at period 0 merely because its first index is zero. Document the mapping.

Avoid adding or deleting items from the same list while iterating over it. A new result list is clearer for selection; the lab demonstrates that approach.

## 4.2.10 Aliasing Versus Copying

```python
source = [Decimal("100"), Decimal("200")]
alias = source
copied = source.copy()

alias.append(Decimal("300"))
assert len(source) == 3
assert len(copied) == 2
assert alias is source
assert copied is not source
```

Assignment does not copy a list. list.copy, slicing, and list(source) create shallow copies.

For a list of immutable Decimal amounts, replacing or appending an outer item in a copied list does not change the source list. If elements are mutable records or lists, those nested objects remain shared.

The repetition expression [record] * 3 repeats references to the same record. It does not create three independent mutable records. Section 4.6 explores nested structures further.

## 4.2.11 Common Financial Mistakes

A list does not enforce currency, chronological ordering, unique identifiers, or consistent period spacing.

Sorting an amount-only cash-flow list destroys the original period mapping. Removing repeated payments may discard real observations. Parallel lists of dates and amounts can become misaligned after an update.

For this introductory lab, amounts are assumed to share one currency and sign perspective. Dates, discounting, and portfolio valuation are deliberately excluded.

## 4.2.12 Hands-On Lab — Validate and Select Cash Flows

Save as lists_lab.py. It requires Python 3.10 or later and only the standard library.

The helper requires a list containing finite Decimal amounts. Signed and zero amounts are accepted. It returns a new list containing positive amounts in original order, preserving duplicate receipts.

Selection performs no monetary arithmetic. It neither changes the input nor sets a Decimal numerical policy. It does not turn the selected amounts into a complete cash-flow schedule: their original periods would need to be retained for valuation.

```python
"""List selection with explicit representation and ownership rules."""

from decimal import Decimal
import unittest


def positive_cash_flows(values: object) -> list[Decimal]:
    """Return positive flows from a list of finite Decimal amounts.

    Preserve order and duplicates; accept signed and zero source values.
    Assume one currency and perspective already established by the caller.
    Return a fresh list, including for empty input. Do not mutate input.
    Raise TypeError for list/element representations and ValueError for
    non-finite amounts. Validate all entries before returning a result.
    """
    if not isinstance(values, list):
        raise TypeError("values must be a list")
    selected: list[Decimal] = []
    for amount in values:
        if not isinstance(amount, Decimal):
            raise TypeError("each amount must be Decimal")
        if not amount.is_finite():
            raise ValueError("each amount must be finite")
        if amount > 0:
            selected.append(amount)
    return selected


class TestFinancialLists(unittest.TestCase):
    """Verify sequence behavior and selected cash-flow boundaries."""

    def test_order_and_duplicates(self) -> None:
        source = [
            Decimal("-1000"), Decimal("400"), Decimal("0"),
            Decimal("400"), Decimal("100"),
        ]
        before = source.copy()
        selected = positive_cash_flows(source)
        self.assertEqual(
            selected, [Decimal("400"), Decimal("400"), Decimal("100")]
        )
        self.assertEqual(source, before)
        self.assertIsNot(selected, source)

    def test_empty_and_no_receipts(self) -> None:
        empty: list[Decimal] = []
        result = positive_cash_flows(empty)
        self.assertEqual(result, [])
        self.assertIsNot(result, empty)
        self.assertEqual(
            positive_cash_flows([Decimal("-10"), Decimal("0")]), []
        )

    def test_invalid_values(self) -> None:
        for value in (None, (Decimal("100"),), "100"):
            with self.subTest(value=value):
                with self.assertRaises(TypeError):
                    positive_cash_flows(value)
        for invalid_item in ("100", 100.0, None):
            with self.subTest(value=invalid_item):
                with self.assertRaises(TypeError):
                    positive_cash_flows([Decimal("100"), invalid_item])
        for value in ("NaN", "Infinity", "-Infinity"):
            with self.subTest(value=value):
                with self.assertRaises(ValueError):
                    positive_cash_flows([Decimal("100"), Decimal(value)])

    def test_index_and_slice_boundaries(self) -> None:
        values = [Decimal("10"), Decimal("20"), Decimal("30")]
        self.assertEqual(values[-1], Decimal("30"))
        self.assertEqual(values[1:3], [Decimal("20"), Decimal("30")])
        self.assertEqual(values[99:], [])
        with self.assertRaises(IndexError):
            _ = values[3]

    def test_append_extend_and_pop(self) -> None:
        values = [Decimal("10")]
        values.append(Decimal("20"))
        values.extend([Decimal("30"), Decimal("40")])
        self.assertEqual(len(values), 4)
        self.assertEqual(values.pop(), Decimal("40"))
        self.assertEqual(values, [Decimal("10"), Decimal("20"), Decimal("30")])

    def test_shallow_copy(self) -> None:
        original = [{"amount": Decimal("100")}]
        copied = original.copy()
        self.assertIsNot(copied, original)
        self.assertIs(copied[0], original[0])
        copied[0]["amount"] = Decimal("200")
        self.assertEqual(original[0]["amount"], Decimal("200"))


if __name__ == "__main__":
    unittest.main()
```

Run on Windows:

```powershell
py -m unittest -v lists_lab
```

Run on macOS or Linux:

```bash
python3 -m unittest -v lists_lab
```

Expected summary: **6 tests, OK**. Subtests exercise additional invalid cases.

The helper validates every entry before returning. A valid positive first item does not hide an invalid later item. Intermediate selection stays local when an exception occurs.

## 4.2.13 Operational Boundaries

Lists are convenient for sequential processing and moderate in-memory collections. Repeated insertions or removals near the front can require shifting elements; a queue-oriented structure may fit a queue workload better.

Do not infer performance requirements from this small lab. Large numerical datasets later use NumPy and pandas where appropriate.

The annotation list[Decimal] describes expected contents for static tooling. Runtime validation remains necessary at an external boundary.

## 4.2.15 Troubleshooting Guide

| Symptom | Likely cause | Correction |
|---|---|---|
| List variable becomes None | Assigned a mutating method's result | Call the method without rebinding |
| IndexError | Missing observation or invalid position | Check the required boundary |
| ValueError from remove or index | Requested value absent | Handle absence deliberately |
| Repeated payment disappears | Duplicate amounts treated as duplicate events | Preserve transaction identity |
| Source list changes unexpectedly | Aliased list | Apply the ownership contract |
| Copied record changes the original | Shared nested object | Review shallow-copy limits |
| Valuation timeline shifts after filtering | Original positions discarded | Retain dates or period identifiers |
| Loop skips items after removal | Iterated list was mutated | Build a separate result list |

## 4.2.16 Key Takeaways

Lists preserve order and duplicates and allow in-place updates. Their positions need a documented financial interpretation.

Keep mutation, copying, validation, and identity explicit. Preserve period metadata when selecting or reorganizing cash flows.
