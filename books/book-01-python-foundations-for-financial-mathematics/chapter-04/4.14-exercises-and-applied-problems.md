## 4.14.1 Purpose and Submission Rules

These twenty chapter-wide exercises test representation, identity, validation, ordering, and ownership. Work through the problems before opening the [companion solutions](solutions/4.14-solutions-and-reference-implementations.md).

For programming answers, provide a function contract, independently stated expected values, a successful case, an empty/boundary case, and an invalid-input or ownership check where applicable. Preserve source data unless the problem explicitly asks you to demonstrate mutation.

Use Python 3.10 or later. All records are synthetic. Decimal quantities are instrument units; amounts in cash-flow examples are signed currency amounts from the investor perspective. No exercise requires prices, aggregation of unrelated units, FX conversion, or discounting.

## 4.14.2 Shared Holdings Contract

For Exercises 7–10, 12, and 16, a holdings input is a list of dictionaries containing exactly security_id and quantity. IDs are exact nonempty unpadded strings unique within this input. Quantities are exact finite nonnegative Decimal values. Zero and fractional units are valid. Wrong types raise TypeError; field/domain/duplicate errors raise ValueError.

Validate every row before selecting or returning a result. Returned mutable containers must not share record dictionaries with the source. Use the following fixture unless a problem specifies otherwise:

```python
from decimal import Decimal

holdings = [
    {"security_id": "SEC-B", "quantity": Decimal("0")},
    {"security_id": "SEC-A", "quantity": Decimal("12.5")},
    {"security_id": "SEC-C", "quantity": Decimal("3")},
]
```

This is an aggregate-position model, not a tax-lot model. Its ordering is source order unless the exercise defines a new order.

## 4.14.3 Foundations — Exercises 1–6

### Exercise 1 — Select a Representation

Choose structures for (a) a working list of payment events that may share a date, (b) a catalog lookup by unique security ID, (c) an immutable set of allowed currency labels, and (d) a holdings baseline containing only validated scalar pairs. Explain what each choice preserves and what it cannot establish about financial correctness.

### Exercise 2 — Mutation and Rebinding

Predict the contents of both names after each operation, then run this isolated example:

```python
original = [{"security_id": "A", "quantity": 1}]
other = original
other[0]["quantity"] = 2
other = []
```

The integer quantity is used only to demonstrate object behavior, outside the shared financial input contract. Explain the difference between changing a dictionary entry and rebinding other.

### Exercise 3 — Tuple Descendants

Explain why `({"quantity": 1},)` can expose a changed quantity. Propose a representation with no mutable descendants for a validated security ID and Decimal quantity. Explain why a type annotation alone does not freeze a list.

### Exercise 4 — Duplicate-Key Loss

Given pairs A/1, A/2, and B/0, all quantities Decimal, state the result of a dictionary comprehension keyed by ID and a set of IDs. Which information is lost? Why is neither result an aggregation of lots?

### Exercise 5 — Missing, Zero, and Empty

Explain the distinct meanings of a holding with quantity zero, a row lacking quantity, and a portfolio with no holdings. State which are valid under this chapter's contract and where portfolio identity should remain available.

### Exercise 6 — Identity Scope

Design keys for one aggregate holding per security per portfolio and for multiple lots of that security in the same portfolio. Explain why payment date alone is not sufficient cash-flow event identity.

## 4.14.4 Holdings Transformations — Exercises 7–12

### Exercise 7 — Immutable Capture

Implement `capture(value: object)` returning a tuple of (security_id, quantity) pairs under the shared contract. Preserve source order. The fixture result begins with SEC-B/0. Mutating the original dictionaries afterward must not change the capture. Reject duplicates before indexing.

### Exercise 8 — Active Records

Implement `active_rows(value: object)` returning fresh record dictionaries for strictly positive quantities, in source order. The fixture selects SEC-A then SEC-C. An invalid final row must be rejected even if an earlier valid subset could have been returned.

### Exercise 9 — Lookup View

Implement `quantity_lookup(value: object)` returning all validated IDs mapped to quantities, including zero holdings. Check the fixture's SEC-B value is Decimal zero. Explain whether editing the lookup updates the capture from Exercise 7.

### Exercise 10 — Deterministic ID Report

Implement `id_report(value: object)` returning fresh holding dictionaries sorted by ID ascending. The fixture order is SEC-A, SEC-B, SEC-C. Show that reversing input changes the captured order but does not change this report.

### Exercise 11 — Membership Reconciliation

Implement `compare_ids(expected: object, actual: object)` accepting two lists of exact nonempty unpadded string IDs. Repetitions are allowed because the function compares membership only. Return a dictionary with sorted missing and unexpected lists. For expected [A, B, B] and actual [B, C], return missing [A], unexpected [C]. Do not imply that this verifies quantities or duplicate records.

### Exercise 12 — Inclusive Subset

Implement `at_least(value: object, minimum: object)` selecting quantities greater than or equal to an exact finite nonnegative Decimal threshold. Preserve source order and return fresh records. With minimum 3, select SEC-A/12.5 and SEC-C/3. With minimum zero retain all rows. The caller must restrict use to quantities whose unit comparison is meaningful; do not describe the result as ranked economic exposure.

## 4.14.5 Cash-Flow Representation — Exercises 13–15

### Exercise 13 — Preserve Same-Day Events

Implement `group_events(value: object)` for a list of records with exactly event_id, payment_date, amount. Event IDs are exact nonempty unpadded strings unique in the list. Dates must be exact Python date objects, excluding datetime. Amounts must be exact finite Decimal values, and may be negative, zero, or positive.

Return a dictionary keyed by date with fresh event dictionaries in each list. Order dates ascending and events within a date by event_id ascending. Empty input returns an empty dictionary. Two events on the same date must remain separate. Test duplicate IDs across different dates and invalid later records. Currency and investor perspective are supplied by the surrounding schedule, not inferred by this function.

### Exercise 14 — Calendar and Model Time

Explain why period index 1 does not automatically mean one year, why a date is not an intraday settlement timestamp, and why adding thirty days is not a general monthly contractual schedule generator. Identify metadata needed before discounting a dated amount.

### Exercise 15 — Do Not Hide Unknown Data

Review a proposal to replace every missing amount with zero and to key a schedule by date to one amount. Identify two independent losses of meaning and propose a representation plus rejection policy that preserves source event identity.

## 4.14.6 Ownership and Project Integration — Exercises 16–20

### Exercise 16 — Independent Views

Using Exercises 7 and 9, return an immutable snapshot, a fresh lookup dictionary, and a frozenset of all IDs. Demonstrate source edits and lookup edits cannot change the snapshot or membership view. Explain how to rebuild all views after a corrected input snapshot.

### Exercise 17 — Extend the Manager with Lookup

Use the complete project module from Section 4.13, saved as portfolio_holdings_manager.py. Implement `find_holding(catalog, portfolio, security_id)` using the project's shared validation and text rules. Return a fresh security_id/quantity dictionary for an existing holding, including zero. Unknown or unheld IDs raise ValueError. Validate the complete input before returning.

### Exercise 18 — Scenario Sequence

Starting with the project's S0 fixture, add SEC-C/3 at S1, replace SEC-A with 20 at S2, then remove SEC-B at S3. Verify final source holding order SEC-A, SEC-C; report order SEC-A, SEC-C; and preservation of S0. Explain why replace uses an absolute quantity rather than a trade delta.

### Exercise 19 — Rejection Matrix

Write tests showing that the project rejects a duplicate add, a replacement for an unheld security, a repeated immediate snapshot label, a boolean quantity, an unsupported currency in an unused catalog row, and an unknown zero holding even in an active-only report. Each failed command must preserve its baseline.

### Exercise 20 — Design Review

Write a short review of a proposed production extension. Cover tax-lot identity, currency/price units, observation and catalog versions, missing references, source ownership, revision uniqueness, concurrent updates, persistence, and reproducibility. Explain what passing local tests establishes and which production claims still need evidence.
