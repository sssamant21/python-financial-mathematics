## 4.5.1 Purpose

A set represents distinct hashable objects without a positional or chronological order. Financial uses include checking whether required identifiers arrived, finding unexpected accounts, and comparing instrument universes.

A set intentionally discards multiplicity. That makes it useful for membership questions but insufficient for transaction histories or duplicate-count reconciliation.

This section develops set operations and a reconciliation lab that preserves duplicate evidence separately before comparing identifier membership.

## 4.5.2 Learning Objectives

You should be able to:

1. Construct empty and populated sets.
2. Use membership, union, intersection, and differences.
3. Distinguish membership equality from transaction equality.
4. Explain mutation, hashability, and frozenset.
5. Detect duplicates before conversion loses their counts.
6. Produce deterministic reports from unordered results.

## 4.5.3 Construction and Membership

```python
expected = {"P001", "P002", "P003"}
received = set(["P001", "P001", "P004"])

assert len(received) == 2
assert "P001" in received
assert "P002" not in received
assert isinstance({}, dict)
assert isinstance(set(), set)
```

Use set() for an empty set; {} creates an empty dictionary. A populated set literal uses comma-separated elements inside braces.

The repeated P001 becomes one member. The resulting set cannot tell whether it originally appeared twice or ten times.

Sets do not support indexing or slicing. Their iteration order must not be treated as an arrival sequence or a stable report order.

## 4.5.4 Comparing Identifier Universes

```python
missing = expected - received
unexpected = received - expected
matched = expected & received
all_ids = expected | received
different = expected ^ received

assert missing == {"P002", "P003"}
assert unexpected == {"P004"}
assert matched == {"P001"}
assert all_ids == {"P001", "P002", "P003", "P004"}
assert different == {"P002", "P003", "P004"}
```

| Operation | Meaning |
|---|---|
| A - B | Members of A absent from B |
| A & B | Members shared by both |
| A \| B | Members in either |
| A ^ B | Members in exactly one |
| A <= B | A is a subset of B |
| A.isdisjoint(B) | No shared members |

Difference is directional. Reversing expected and received reverses the question.

Subset operators express membership inclusion, not chronological or numeric ordering. Two sets can be incomparable by subset even though both contain valid identifiers.

## 4.5.5 Updating a Set

```python
reviewed = set()
reviewed.add("P001")
reviewed.update(["P002", "P003"])
reviewed.discard("P999")
reviewed.remove("P003")

assert reviewed == {"P001", "P002"}
```

add inserts one object. update inserts objects from an iterable. discard ignores an absent member, whereas remove raises KeyError for absence.

pop removes an arbitrary member; it does not mean the earliest or latest event. clear empties the set.

Mutating methods such as add return None. Do not replace a set variable with that method's result.

## 4.5.6 Hashability and frozenset

Set members must be hashable. Strings and suitable tuples are useful identifiers; lists and dictionaries cannot be ordinary set members.

A mutable set cannot itself be an ordinary set member. A frozenset is an immutable set and is hashable, so it can represent an immutable membership group when that fits the model.

Equal objects can collapse into one member, including equal numeric values across representations. For identifier processing, the lab requires strings and avoids mixed numeric/Boolean identifiers.

A set of amounts is rarely a substitute for a payment collection. Equal amounts can correspond to different payments and dates.

## 4.5.7 Copying and Ownership

Assignment aliases a set. set.copy creates a separate mutable set with the same members.

Hashable objects are not universally guaranteed to be deeply immutable under every user-defined design. This lab uses immutable strings, keeping member ownership simple.

A frozenset prevents membership edits; it does not establish provenance, financial correctness, or a durable audit record.

## 4.5.8 Membership Is Only One Reconciliation Dimension

Matching identifier sets do not prove matching amounts, currencies, dates, statuses, or counts.

For example, expected IDs P001 and P002 can match received IDs P001, P001, P002 after set conversion. A duplicate transaction remains unresolved even though no ID is missing.

The lab therefore reports duplicate IDs separately. It identifies which IDs repeat, not the complete number of excess occurrences. Counting and full record reconciliation require additional structures and policies.

## 4.5.9 Hands-On Lab — Reconcile Payment IDs

Save as sets_lab.py. It requires Python 3.10 or later and only the standard library.

Inputs are lists of nonblank string IDs, compared exactly and case-sensitively. The helper does not trim or normalize identifiers. Expected IDs must be unique; repeated received IDs are preserved as duplicate evidence in a separate report.

The result contains four fresh sets. It does not return arrival order, amounts, duplicate counts, or a transaction approval decision.

```python
"""Reconcile identifier membership without hiding duplicate evidence."""

import unittest


def _validated_ids(values: object, name: str) -> list[str]:
    """Return validated IDs in supplied order without normalization."""
    if not isinstance(values, list):
        raise TypeError(f"{name} must be a list")
    validated: list[str] = []
    for identifier in values:
        if not isinstance(identifier, str):
            raise TypeError("each identifier must be text")
        if not identifier.strip():
            raise ValueError("each identifier must be nonblank")
        validated.append(identifier)
    return validated


def reconcile_ids(
    expected: object,
    received: object,
) -> dict[str, set[str]]:
    """Return missing, unexpected, matched, and duplicate_received ID sets.

    Require list inputs of nonblank case-sensitive strings. Expected IDs
    must be unique. Preserve evidence of repeated received IDs separately
    before performing membership comparisons. Do not normalize, mutate
    inputs, reconcile amounts, or count excess occurrences.
    Raise TypeError for representations; ValueError for invalid values
    or duplicate expected IDs. Return fresh sets without an order promise.
    """
    expected_ids = _validated_ids(expected, "expected")
    received_ids = _validated_ids(received, "received")
    expected_set = set(expected_ids)
    if len(expected_set) != len(expected_ids):
        raise ValueError("expected identifiers must be unique")

    seen: set[str] = set()
    duplicates: set[str] = set()
    for identifier in received_ids:
        if identifier in seen:
            duplicates.add(identifier)
        seen.add(identifier)

    return {
        "missing": expected_set - seen,
        "unexpected": seen - expected_set,
        "matched": expected_set & seen,
        "duplicate_received": duplicates,
    }


class TestIdentifierSets(unittest.TestCase):
    """Verify membership, duplicate evidence, and validation."""

    def test_reconciliation(self) -> None:
        result = reconcile_ids(
            ["P001", "P002", "P003"],
            ["P001", "P001", "P004"],
        )
        self.assertEqual(result["missing"], {"P002", "P003"})
        self.assertEqual(result["unexpected"], {"P004"})
        self.assertEqual(result["matched"], {"P001"})
        self.assertEqual(result["duplicate_received"], {"P001"})

    def test_membership_match_still_reports_duplicate(self) -> None:
        result = reconcile_ids(["P001"], ["P001", "P001", "P001"])
        self.assertEqual(result["missing"], set())
        self.assertEqual(result["unexpected"], set())
        self.assertEqual(result["duplicate_received"], {"P001"})

    def test_empty_inputs(self) -> None:
        result = reconcile_ids([], [])
        self.assertTrue(all(not group for group in result.values()))
        self.assertEqual(reconcile_ids(["P001"], [])["missing"], {"P001"})
        self.assertEqual(reconcile_ids([], ["P002"])["unexpected"], {"P002"})

    def test_duplicate_expected_rejected(self) -> None:
        with self.assertRaises(ValueError):
            reconcile_ids(["P001", "P001"], [])

    def test_invalid_inputs(self) -> None:
        for invalid in ("P001", None, {"P001"}):
            with self.subTest(value=invalid):
                with self.assertRaises(TypeError):
                    reconcile_ids(invalid, [])
                with self.assertRaises(TypeError):
                    reconcile_ids([], invalid)
        with self.assertRaises(TypeError):
            reconcile_ids([], ["P001", 1])
        with self.assertRaises(ValueError):
            reconcile_ids([" "], [])
        with self.assertRaises(ValueError):
            reconcile_ids([], ["P001", ""])

    def test_ownership_and_case_policy(self) -> None:
        expected = ["P001"]
        received = ["p001"]
        result = reconcile_ids(expected, received)
        self.assertEqual(result["missing"], {"P001"})
        self.assertEqual(result["unexpected"], {"p001"})
        result["missing"].add("P999")
        self.assertEqual(expected, ["P001"])
        self.assertEqual(received, ["p001"])
        self.assertNotIn("P999", result["unexpected"])


if __name__ == "__main__":
    unittest.main()
```

Run on Windows:

```powershell
py -m unittest -v sets_lab
```

Run on macOS or Linux:

```bash
python3 -m unittest -v sets_lab
```

Expected summary: **6 tests, OK**. Subtests exercise additional invalid inputs.

This lab performs no monetary arithmetic and defines no valuation policy. A matching ID report is an input to further investigation, not proof that payments are financially reconciled.

## 4.5.10 Deterministic Presentation

After saving the lab, use sorted lists for repeatable textual output:

```python
from sets_lab import reconcile_ids

report = reconcile_ids(
    ["P001", "P002", "P003"],
    ["P001", "P001", "P004"],
)
display_missing = sorted(report["missing"])
assert display_missing == ["P002", "P003"]
```

Sorting strings supplies a deterministic lexical presentation for this example. It does not reconstruct arrival order or assign a business priority.

Do not assert an exact printed set representation in tests. Compare set equality when order is irrelevant, or sort under an explicitly chosen presentation rule.

## 4.5.11 Reconciliation Invariants

The missing and matched sets partition the expected identifier universe. The unexpected and matched sets partition the received membership universe.

These relationships help detect implementation errors. They still do not establish counts or payment values.

Duplicate_received can contain both expected and unexpected IDs. An unexpected ID repeated three times belongs in both relevant categories; the categories answer different questions.

Avoid removing duplicates from the source solely to make a reconciliation report appear clean. Investigate them under the dataset's correction or event policy.

## 4.5.13 Troubleshooting Guide

| Symptom | Likely cause | Correction |
|---|---|---|
| Duplicate evidence disappears | Converted to set before checking multiplicity | Preserve source observations and detect repeats |
| Printed order changes | Set iteration order treated as stable | Sort for presentation |
| Missing and unexpected reversed | Difference operands swapped | Label the two universes explicitly |
| Unhashable member error | List or dictionary inserted | Use a valid identity representation |
| Equal amounts collapse | Amount treated as transaction identity | Retain record identifiers |
| ID sets match but totals differ | Membership confused with full reconciliation | Compare counts, amounts, currency, and dates |
| Empty collection is a dictionary | Used {} | Use set() |

## 4.5.14 Key Takeaways

Sets answer distinct-membership questions and support useful comparisons. They discard multiplicity and do not preserve a financial timeline.

Validate identity conventions, keep duplicate evidence separately, and present unordered results deterministically when needed.
