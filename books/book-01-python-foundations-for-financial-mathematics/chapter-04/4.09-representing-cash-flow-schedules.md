## 4.9.1 Purpose

A cash-flow schedule connects amounts to times and identifies whose perspective determines their signs. A list of numbers alone cannot tell a reader when payments occur, which currency they use, or whether two equal payments are separate events.

This section develops a small dated schedule with explicit metadata and event identities. The lab validates, orders, and groups events without changing their amounts. Present-value calculations, day-count conventions, and contractual payment generation are developed later in the book.

## 4.9.2 Learning Objectives

You should be able to:

1. Distinguish list position, period number, and payment date.
2. Document sign, currency, and schedule perspective.
3. Preserve separate events sharing one date.
4. Validate event identity independently of date ordering.
5. Distinguish zero, missing payments, and empty schedules.
6. Build independent chronological and date-grouped views.
7. Test schema, dates, signed amounts, and preservation of events.

## 4.9.3 Amounts Need a Timeline

In a regular period model, the list index may represent time only if that convention is stated. Here period zero is the initial investment date, and each subsequent index is one equal model period later. The unit of a period must be supplied by the model.

Run these introductory Python blocks in order in one session.

```python
from datetime import date
from decimal import Decimal

period_amounts = [Decimal("-1000"), Decimal("40"), Decimal("1040")]
period_pairs = list(enumerate(period_amounts))
assert period_pairs == [
    (0, Decimal("-1000")),
    (1, Decimal("40")),
    (2, Decimal("1040")),
]
```

The synthetic example adopts the investor's perspective: negative means cash paid, positive means cash received. Reversing perspective requires an explicit transformation. It should not happen because a function guesses from a field name.

A dated schedule does not imply equal spacing. A calendar date also does not specify an intraday timestamp, settlement cutoff, holiday calendar, or discounting year fraction.

## 4.9.4 Records Preserve Event Meaning

An event needs an identity as well as a date and amount. Consider two receipts on the same day: a distribution and a principal repayment. The schedule should preserve both even if another report later presents their net amount.

```python
events = [
    {"event_id": "E-0", "payment_date": date(2027, 1, 15), "amount": Decimal("-1000")},
    {"event_id": "E-1", "payment_date": date(2027, 7, 15), "amount": Decimal("40")},
    {"event_id": "E-2", "payment_date": date(2028, 1, 15), "amount": Decimal("40")},
    {"event_id": "E-3", "payment_date": date(2028, 1, 15), "amount": Decimal("1000")},
]
assert events[2]["payment_date"] == events[3]["payment_date"]
assert events[2]["event_id"] != events[3]["event_id"]
```

The amounts are supplied teaching data, not a derived bond contract. The code does not establish contractual entitlement, accrual, or investment return.

A dictionary keyed only by date can overwrite earlier events. Instead use a list of event records or a dictionary whose values are lists of events.

```python
by_date = {}
for event in events:
    payment_date = event["payment_date"]
    by_date.setdefault(payment_date, []).append(dict(event))
assert len(by_date[date(2028, 1, 15)]) == 2
assert [event["event_id"] for event in by_date[date(2028, 1, 15)]] == ["E-2", "E-3"]
```

Grouping preserves the two original amounts. Netting would be a separate operation requiring a currency rule, precision policy, and decision about which identities remain available for audit.

## 4.9.5 Choose the Representation Deliberately

| Representation | Useful when | Required caution |
|---|---|---|
| List of amounts | Regular model periods | Define index zero and period unit |
| List of period/amount pairs | Explicit model periods | Validate period identity and spacing |
| List of dated records | Irregular dates or multiple events | Preserve event IDs and metadata |
| Date to list-of-records mapping | Inspecting daily events | Do not replace the list with one amount accidentally |

The lab uses a schedule dictionary containing metadata and an event list. Currency and perspective apply to every event in that schedule. Combining schedules first requires checking that those meanings agree.

## 4.9.6 Missing, Zero, and Empty Are Different

An explicit zero amount is a valid event in this teaching schema. It may preserve a placeholder whose meaning is documented elsewhere. A missing amount is a schema error, not a zero payment.

An empty event list is valid and retains the schedule metadata. It is not proof that no contractual obligations exist. Likewise, the absence of a date from the grouped view means no supplied event exists on that date; it does not establish completeness of the source.

Past and future dates are both accepted. This function does not decide whether an event is forecast, settled, overdue, canceled, or eligible for valuation. Those statuses need additional fields and contracts.

## 4.9.7 Lab Contract — Canonical Dated Schedule

Save the complete lab as `cash_flow_schedule_lab.py`. Use Python 3.10 or later with the standard library.

| Field or behavior | Contract |
|---|---|
| Outer schema | Exactly schedule_id, currency, perspective, events |
| schedule_id | Nonempty unpadded string |
| currency | USD or EUR; one currency per schedule |
| perspective | Exactly investor |
| events | List of dictionaries |
| Event schema | Exactly event_id, payment_date, amount |
| event_id | Nonempty unpadded string, unique within the schedule |
| payment_date | Python date, excluding datetime and subclasses |
| amount | Finite Decimal; negative, zero, and positive accepted |
| Order | Date ascending, then event_id ascending |
| Repeated dates | Accepted; every distinct event retained |
| Output | New schedule and new date-grouped event view |
| Ownership | Mutable containers shared with neither source nor the other output view |
| Failure | TypeError for wrong types; ValueError for schema/domain/identity violations |

The exact date-type policy avoids silently truncating timestamps. Parse external strings at a separate boundary under a documented input format. Python's date constructor rejects impossible calendar dates; this lab accepts already constructed date objects.

All events are validated before either output is returned. No amounts are added, negated, rounded, or discounted. The result is a normalized representation, not a valuation.

## 4.9.8 Complete Runnable Lab

```python
"""Preserve signed cash-flow events in chronological and grouped views."""

from datetime import date, datetime
from decimal import Decimal
import unittest

Event = tuple[date, str, Decimal]


def checked_identifier(value: object, label: str) -> str:
    if not isinstance(value, str):
        raise TypeError(f"{label} must be a string")
    if not value or value.strip() != value:
        raise ValueError(f"{label} must be nonempty and unpadded")
    return value


def event_key(event: Event) -> tuple[date, str]:
    return event[0], event[1]


def event_record(event: Event) -> dict[str, object]:
    payment_date, event_id, amount = event
    return {"event_id": event_id, "payment_date": payment_date, "amount": amount}


def normalize_schedule(
    value: object,
) -> tuple[dict[str, object], dict[date, list[dict[str, object]]]]:
    """Validate an investor schedule and return independent ordered views.

    One USD or EUR schedule; signed finite Decimal amounts are preserved.
    Repeated dates are allowed, repeated event IDs are rejected.
    """
    if not isinstance(value, dict):
        raise TypeError("schedule must be a dictionary")
    if set(value) != {"schedule_id", "currency", "perspective", "events"}:
        raise ValueError("schedule has incorrect fields")
    schedule_id = checked_identifier(value["schedule_id"], "schedule_id")
    currency = value["currency"]
    if not isinstance(currency, str):
        raise TypeError("currency must be a string")
    if currency not in {"USD", "EUR"}:
        raise ValueError("currency must be USD or EUR")
    perspective = value["perspective"]
    if not isinstance(perspective, str):
        raise TypeError("perspective must be a string")
    if perspective != "investor":
        raise ValueError("perspective must be investor")
    source_events = value["events"]
    if not isinstance(source_events, list):
        raise TypeError("events must be a list")

    validated: list[Event] = []
    seen: set[str] = set()
    for index, row in enumerate(source_events):
        if not isinstance(row, dict):
            raise TypeError(f"event {index} must be a dictionary")
        if set(row) != {"event_id", "payment_date", "amount"}:
            raise ValueError(f"event {index} has incorrect fields")
        event_id = checked_identifier(row["event_id"], f"event {index} ID")
        payment_date = row["payment_date"]
        if type(payment_date) is not date:
            raise TypeError(f"event {index} payment_date must be an exact date")
        amount = row["amount"]
        if not isinstance(amount, Decimal):
            raise TypeError(f"event {index} amount must be Decimal")
        if not amount.is_finite():
            raise ValueError(f"event {index} amount must be finite")
        if event_id in seen:
            raise ValueError(f"duplicate event_id: {event_id}")
        seen.add(event_id)
        validated.append((payment_date, event_id, amount))

    ordered = sorted(validated, key=event_key)
    normalized_events = [event_record(event) for event in ordered]
    grouped: dict[date, list[dict[str, object]]] = {}
    for event in ordered:
        grouped.setdefault(event[0], []).append(event_record(event))
    normalized: dict[str, object] = {
        "schedule_id": schedule_id,
        "currency": currency,
        "perspective": perspective,
        "events": normalized_events,
    }
    return normalized, grouped


def sample_schedule() -> dict[str, object]:
    return {
        "schedule_id": "SCH-01", "currency": "USD", "perspective": "investor",
        "events": [
            {"event_id": "E-3", "payment_date": date(2028, 1, 15), "amount": Decimal("1000")},
            {"event_id": "E-0", "payment_date": date(2027, 1, 15), "amount": Decimal("-1000")},
            {"event_id": "E-2", "payment_date": date(2028, 1, 15), "amount": Decimal("40")},
            {"event_id": "E-1", "payment_date": date(2027, 7, 15), "amount": Decimal("0")},
        ],
    }


def schedule_with_events(events: object) -> dict[str, object]:
    schedule = sample_schedule()
    schedule["events"] = events
    return schedule


class ScheduleTests(unittest.TestCase):
    def test_exact_order_and_grouping(self) -> None:
        normalized, grouped = normalize_schedule(sample_schedule())
        expected = [
            {"event_id": "E-0", "payment_date": date(2027, 1, 15), "amount": Decimal("-1000")},
            {"event_id": "E-1", "payment_date": date(2027, 7, 15), "amount": Decimal("0")},
            {"event_id": "E-2", "payment_date": date(2028, 1, 15), "amount": Decimal("40")},
            {"event_id": "E-3", "payment_date": date(2028, 1, 15), "amount": Decimal("1000")},
        ]
        self.assertEqual(normalized, {
            "schedule_id": "SCH-01", "currency": "USD", "perspective": "investor", "events": expected
        })
        self.assertEqual(list(grouped), [date(2027, 1, 15), date(2027, 7, 15), date(2028, 1, 15)])
        self.assertEqual(grouped[date(2028, 1, 15)], expected[2:])
        self.assertEqual(sum(len(rows) for rows in grouped.values()), 4)

    def test_empty_retains_metadata(self) -> None:
        normalized, grouped = normalize_schedule(schedule_with_events([]))
        self.assertEqual(normalized["schedule_id"], "SCH-01")
        self.assertEqual(normalized["events"], [])
        self.assertEqual(grouped, {})

    def test_duplicate_identity_across_dates(self) -> None:
        with self.assertRaises(ValueError):
            normalize_schedule(schedule_with_events([
                {"event_id": "A", "payment_date": date(2027, 1, 1), "amount": Decimal("1")},
                {"event_id": "A", "payment_date": date(2028, 1, 1), "amount": Decimal("2")},
            ]))

    def test_date_and_amount_validation(self) -> None:
        for bad_date in ("2027-01-01", None, datetime(2027, 1, 1)):
            with self.subTest(bad_date=bad_date):
                with self.assertRaises(TypeError):
                    normalize_schedule(schedule_with_events([
                        {"event_id": "A", "payment_date": bad_date, "amount": Decimal("0")}
                    ]))
        for amount in (None, True, 1, 1.5, "1"):
            with self.subTest(amount=amount):
                with self.assertRaises(TypeError):
                    normalize_schedule(schedule_with_events([
                        {"event_id": "A", "payment_date": date(2027, 1, 1), "amount": amount}
                    ]))
        for text in ("NaN", "sNaN", "Infinity", "-Infinity"):
            with self.subTest(text=text):
                with self.assertRaises(ValueError):
                    normalize_schedule(schedule_with_events([
                        {"event_id": "A", "payment_date": date(2027, 1, 1), "amount": Decimal(text)}
                    ]))

    def test_schema_and_metadata(self) -> None:
        with self.assertRaises(TypeError):
            normalize_schedule([])
        with self.assertRaises(ValueError):
            normalize_schedule({})
        with self.assertRaises(TypeError):
            normalize_schedule(schedule_with_events(None))
        with self.assertRaises(TypeError):
            normalize_schedule(schedule_with_events([None]))
        with self.assertRaises(ValueError):
            normalize_schedule(schedule_with_events([{"event_id": "A"}]))
        for field, bad, error in (
            ("currency", "GBP", ValueError), ("currency", None, TypeError),
            ("perspective", "issuer", ValueError), ("perspective", 1, TypeError),
            ("schedule_id", " ", ValueError), ("schedule_id", 1, TypeError),
        ):
            with self.subTest(field=field):
                source = sample_schedule()
                source[field] = bad
                with self.assertRaises(error):
                    normalize_schedule(source)
        for event_id in ("", " A", "A "):
            with self.assertRaises(ValueError):
                normalize_schedule(schedule_with_events([
                    {"event_id": event_id, "payment_date": date(2027, 1, 1), "amount": Decimal("0")}
                ]))

    def test_independent_output_views(self) -> None:
        source = sample_schedule()
        normalized, grouped = normalize_schedule(source)
        rows = normalized["events"]
        self.assertIsInstance(rows, list)
        if not isinstance(rows, list):
            self.fail("events must be list")
        rows[0]["amount"] = Decimal("99")
        grouped[date(2028, 1, 15)][0]["amount"] = Decimal("88")
        self.assertEqual(source, sample_schedule())
        self.assertEqual(grouped[date(2027, 1, 15)][0]["amount"], Decimal("-1000"))
        self.assertEqual(rows[2]["amount"], Decimal("40"))
        fresh, _ = normalize_schedule(source)
        self.assertNotEqual(normalized, fresh)

    def test_invalid_later_event_preserves_source(self) -> None:
        source = schedule_with_events([
            {"event_id": "A", "payment_date": date(2027, 1, 1), "amount": Decimal("1")},
            {"event_id": "B", "payment_date": date(2028, 1, 1), "amount": "missing"},
        ])
        original_events = source["events"]
        with self.assertRaises(TypeError):
            normalize_schedule(source)
        self.assertIs(source["events"], original_events)
        self.assertEqual(source["events"], [
            {"event_id": "A", "payment_date": date(2027, 1, 1), "amount": Decimal("1")},
            {"event_id": "B", "payment_date": date(2028, 1, 1), "amount": "missing"},
        ])


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

## 4.9.10 Representation Is Not Discounting

A calendar interval can be measured in days, but mapping it to model years requires a stated convention. An integer index is not automatically a year fraction. Likewise, adding a fixed number of days is not a general contractual monthly schedule generator.

This section accepts dates already supplied by the caller. Holiday adjustment, end-of-month rules, accrual periods, payment status, and principal/coupon classification would require an expanded schema and policy. Preserve the source events when deriving any aggregated or valued view so that transformations remain inspectable.

## 4.9.11 Troubleshooting

| Symptom | Likely cause | Correction |
|---|---|---|
| One same-day payment disappears | Date used as a unique event key | Store a list per date |
| Initial investment appears as a receipt | Perspective/sign policy changed | Record the perspective explicitly |
| A missing payment becomes zero | Default amount inserted | Validate required fields |
| Timestamp silently loses time | Automatic date truncation | Reject or explicitly normalize at the boundary |
| Source changes when report changes | Shared record dictionaries | Reconstruct each output view |
| Event appears twice | Duplicate identity accepted | Validate IDs across the whole schedule |
| Empty output loses context | Metadata stored only in child rows | Preserve the schedule wrapper |

## 4.9.13 Key Takeaways

A usable cash-flow schedule preserves time, amount, currency, perspective, and event identity. Repeated dates are valid and should not erase payments.

Keep representation, aggregation, payment generation, and valuation as separately specified transformations. Validate all events and preserve source ownership before deriving report views.
