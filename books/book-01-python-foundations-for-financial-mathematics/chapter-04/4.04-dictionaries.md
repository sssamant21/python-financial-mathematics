## 4.4.1 Purpose

A dictionary maps unique keys to values. It can represent a financial record with named fields or an index from a financial identifier to an observation.

Those roles have different contracts. A payment record might contain amount and currency fields; an identifier index might map payment IDs to records. Neither structure automatically enforces financial validity or prevents silent replacement of an existing value.

This section develops dictionary operations and an index-building lab that rejects duplicate identifiers instead of overwriting them.

## 4.4.2 Learning Objectives

You should be able to:

1. Create, access, update, and remove dictionary entries.
2. Distinguish required lookup from optional lookup.
3. Iterate over keys, values, and key/value pairs.
4. Explain insertion order, key uniqueness, and shallow-copy behavior.
5. Reject duplicate identifiers before information is overwritten.
6. Define a clear dictionary ownership and validation contract.

## 4.4.3 Named Financial Fields

```python
from decimal import Decimal

payment = {
    "payment_id": "P001",
    "amount": Decimal("100"),
    "currency": "USD",
}

assert payment["amount"] == Decimal("100")
assert "currency" in payment
assert "USD" not in payment
assert "USD" in payment.values()
```

Membership in a dictionary tests keys. Use values when the question concerns stored values.

The example is a compact record, not the full five-field schema from Section 4.1. Its contract assumes one signed investor-perspective amount: positive receipt, negative payment, and zero allowed.

A dictionary permits arbitrary supported values; field names alone do not validate them.

## 4.4.4 Required and Optional Lookup

```python
assert payment.get("reference") is None
assert payment.get("reference", "unprovided") == "unprovided"

try:
    payment["reference"]
except KeyError:
    pass
else:
    raise AssertionError("Expected required-field lookup failure")
```

Index lookup raises KeyError when a key is absent. get returns its default, which is None unless specified.

If None is itself a valid stored value, get without a distinct sentinel cannot distinguish absence from an explicit None. Use membership when that distinction matters.

Do not use record.get("amount", Decimal("0")) to silently replace a missing required financial amount. Zero and unknown are different meanings.

## 4.4.5 Inserting and Replacing Entries

```python
revised = payment.copy()
revised["reference"] = "invoice-01"
revised["amount"] = Decimal("125")
revised.update({"currency": "EUR"})

assert revised["amount"] == Decimal("125")
assert payment["amount"] == Decimal("100")
```

Assigning to a new key inserts it; assigning to an existing key replaces its value. update can replace multiple entries and returns None.

The currency update above demonstrates Python behavior. Changing a currency label does not convert an amount economically. A real currency conversion requires an explicit rate, direction, and valuation convention.

A dictionary literal or constructor with repeated equal keys retains one resulting entry. Detect duplicates before construction when retaining all source observations matters.

## 4.4.6 Removing Entries

```python
removed_reference = revised.pop("reference")
assert removed_reference == "invoice-01"

del revised["currency"]
assert "currency" not in revised
```

pop returns the removed value; a default can be supplied for an absent key. del removes a required existing key. clear removes all entries.

Removing a required field can make a formerly valid record invalid. Revalidate a revised record before calculation or storage.

## 4.4.7 Iteration and Views

```python
field_names = []
for field_name, value in payment.items():
    field_names.append(field_name)

assert field_names == ["payment_id", "amount", "currency"]
```

A plain loop over a dictionary iterates keys. keys, values, and items return views associated with the dictionary; those views reflect later dictionary changes.

Use list(mapping.items()) when an independent outer sequence snapshot is needed. That does not deep-copy mutable values.

Avoid adding or deleting keys while iterating over the same dictionary. Such changes can raise RuntimeError or disrupt traversal. Build a separate result or iterate an appropriate snapshot.

## 4.4.8 Order and Identity

Python dictionaries preserve insertion order. Replacing an existing value does not move its key to a new insertion position; deleting and reinserting a key places it at the end.

Insertion order is not proof of chronological order, price priority, or financial identity. Store dates and identifiers explicitly.

Dictionary equality compares entries rather than using insertion order as a financial sequence. Use an ordered observation collection when positional order itself is part of the model.

## 4.4.9 Keys and Hashability

Keys must be hashable. Strings are useful for identifiers. A tuple can form a compound key when its elements are hashable.

A list cannot be a key. Equal keys such as 1, True, and 1.0 can refer to the same dictionary entry. This is one reason the lab requires nonblank string identifiers.

An account/instrument pair may be a suitable compound key only if it matches the dataset's identity scope. A symbol alone may not identify an instrument across venues or historical changes.

## 4.4.10 Copying and Ownership

Assignment aliases a dictionary. copy makes a new outer dictionary but shares referenced values.

The lab constructs new inner records containing only strings and Decimal values, which are immutable. It therefore isolates record-key replacement from the source without needing a deep copy.

Adding nested mutable fields later would require revisiting that guarantee. A shallow copy is not automatically an immutable audit snapshot.

## 4.4.11 Hands-On Lab — Build an Identifier Index Safely

Save as dictionaries_lab.py. It requires Python 3.10 or later and only the standard library.

Input is a list of records with exactly payment_id, amount, and currency. Currency is USD or EUR for this teaching allowlist. Amounts are finite Decimal values and may be signed or zero.

Identifiers are nonblank strings compared exactly and case-sensitively. Whitespace is not normalized. Duplicate identifiers are rejected even when all other fields match. Production corrections or versioned events need a separate policy.

```python
"""Build a validated payment index without silent identifier replacement."""

from decimal import Decimal
import unittest


def index_payments(records: object) -> dict[str, dict[str, object]]:
    """Return a fresh ID-to-record index from a list of compact payments.

    Require exact fields payment_id, amount, currency. ID is nonblank
    text, amount finite Decimal, currency USD/EUR. Preserve source
    insertion order and signed/zero amounts; do not aggregate currencies.
    Reject duplicate IDs. Do not normalize or mutate source records.
    Return new outer and inner dictionaries containing immutable values.
    Raise TypeError for representations and ValueError for schema/domain.
    """
    if not isinstance(records, list):
        raise TypeError("records must be a list")
    result: dict[str, dict[str, object]] = {}
    for record in records:
        if not isinstance(record, dict):
            raise TypeError("each record must be a dictionary")
        if set(record) != {"payment_id", "amount", "currency"}:
            raise ValueError("record fields do not match the schema")

        identifier = record["payment_id"]
        amount = record["amount"]
        currency = record["currency"]

        if not isinstance(identifier, str):
            raise TypeError("payment_id must be text")
        if not identifier.strip():
            raise ValueError("payment_id must be nonblank")
        if not isinstance(amount, Decimal):
            raise TypeError("amount must be Decimal")
        if not amount.is_finite():
            raise ValueError("amount must be finite")
        if not isinstance(currency, str):
            raise TypeError("currency must be text")
        if currency not in ("USD", "EUR"):
            raise ValueError("unsupported currency")
        if identifier in result:
            raise ValueError("duplicate payment_id")

        result[identifier] = {
            "payment_id": identifier,
            "amount": amount,
            "currency": currency,
        }
    return result


def sample_payment() -> dict[str, object]:
    """Return a fresh invented compact payment."""
    return {
        "payment_id": "P001",
        "amount": Decimal("100"),
        "currency": "USD",
    }


class TestPaymentIndex(unittest.TestCase):
    """Check indexing, validation, identity, and ownership."""

    def test_index_and_order(self) -> None:
        first = sample_payment()
        second = {
            "payment_id": "P002",
            "amount": Decimal("-25"),
            "currency": "EUR",
        }
        result = index_payments([first, second])
        self.assertEqual(list(result), ["P001", "P002"])
        self.assertEqual(result["P002"]["amount"], Decimal("-25"))

    def test_duplicate_rejected(self) -> None:
        first = sample_payment()
        duplicate = sample_payment()
        with self.assertRaisesRegex(ValueError, "duplicate"):
            index_payments([first, duplicate])
        self.assertEqual(first["amount"], Decimal("100"))

    def test_copy_isolation(self) -> None:
        source = sample_payment()
        result = index_payments([source])
        self.assertIsNot(result["P001"], source)
        result["P001"]["amount"] = Decimal("200")
        self.assertEqual(source["amount"], Decimal("100"))

    def test_empty_and_zero(self) -> None:
        self.assertEqual(index_payments([]), {})
        source = sample_payment()
        source["amount"] = Decimal("0")
        self.assertEqual(index_payments([source])["P001"]["amount"], Decimal("0"))

    def test_schema_and_representations(self) -> None:
        with self.assertRaises(TypeError):
            index_payments({})
        with self.assertRaises(TypeError):
            index_payments(["P001"])
        source = sample_payment()
        del source["amount"]
        with self.assertRaises(ValueError):
            index_payments([source])
        source = sample_payment()
        source["ammount"] = Decimal("100")
        with self.assertRaises(ValueError):
            index_payments([source])
        for field, value in (("payment_id", 1), ("amount", "100"), ("currency", None)):
            with self.subTest(field=field):
                invalid = sample_payment()
                invalid[field] = value
                with self.assertRaises(TypeError):
                    index_payments([invalid])

    def test_invalid_domain_after_valid_record(self) -> None:
        for field, value in (
            ("payment_id", " "),
            ("amount", Decimal("NaN")),
            ("amount", Decimal("Infinity")),
            ("currency", "usd"),
        ):
            with self.subTest(field=field, value=value):
                invalid = sample_payment()
                invalid["payment_id"] = "P002"
                invalid[field] = value
                with self.assertRaises(ValueError):
                    index_payments([sample_payment(), invalid])


if __name__ == "__main__":
    unittest.main()
```

Run on Windows:

```powershell
py -m unittest -v dictionaries_lab
```

Run on macOS or Linux:

```bash
python3 -m unittest -v dictionaries_lab
```

Expected summary: **6 tests, OK**. Subtests cover additional invalid cases.

No partial index is returned if a later record fails. Source records remain unchanged. This in-memory behavior is not a database transaction or a concurrency guarantee.

The helper performs no monetary arithmetic. Downstream valuations must still enforce currency, timing, sign, and numerical contracts.

## 4.4.12 Updating an Index Is a Business Decision

The lab rejects duplicate identifiers because ordinary assignment would otherwise replace a prior observation.

A correction workflow might instead require a revision number, effective timestamp, or explicit replacement operation. An append-only event history might need a different key or a list of revisions.

Do not substitute “last value wins” for an unresolved identity policy. A valid dictionary cannot recover an observation already discarded during construction.

## 4.4.13 Dictionaries and Structured Types

dict[str, object] documents string keys with varied value representations. It does not tell a static checker which exact keys exist or which type each field holds.

TypedDict or other structured record types can strengthen static documentation when introduced deliberately. Runtime validation and financial meaning remain separate responsibilities.

The lab uses ordinary dictionaries so named fields, duplicate handling, and ownership stay visible before adding more type machinery.

## 4.4.15 Troubleshooting Guide

| Symptom | Likely cause | Correction |
|---|---|---|
| Prior payment disappears | Existing key overwritten | Detect duplicates or use an explicit revision policy |
| Missing amount becomes zero | Unsafe default in get | Validate required fields |
| Membership unexpectedly false | Tested a value against keys | Use the intended view |
| Currency label changes without economic conversion | Metadata edit mistaken for conversion | Apply a documented conversion process |
| Source record changes after copy | Shared nested values | Review ownership |
| RuntimeError during traversal | Dictionary size changed | Build a new result or iterate a snapshot |
| Chronology assumed from dictionary order | Insertion order confused with event time | Preserve dates and sort deliberately |
| Numeric and Boolean IDs collide | Equal heterogeneous keys | Enforce a consistent identifier representation |

## 4.4.16 Key Takeaways

Dictionaries provide named access and keyed lookup. They do not enforce schemas, identity, or correction rules automatically.

Validate required fields, distinguish absence from zero, reject unintended replacement, and make copy ownership explicit.
