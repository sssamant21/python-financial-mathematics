## 4.11.1 Purpose

A scenario should not accidentally rewrite the portfolio used as its baseline. Reliable financial programs need a clear ownership rule: which values may change, which objects are shared, and which transformations return new results.

This section develops that rule through assignment, nested containers, copying, and a small immutable snapshot representation. The lab captures validated holdings as tuples and constructs a new snapshot when a quantity is replaced. It performs no valuation or quantity arithmetic.

## 4.11.2 Learning Objectives

You should be able to:

1. Distinguish mutation from rebinding a name.
2. Use equality and identity checks for their intended purposes.
3. Explain why an immutable container may still expose mutable descendants.
4. Choose between shallow copying, deep copying, and schema reconstruction.
5. Construct a snapshot whose supported field types are immutable.
6. Apply an update by returning a new validated snapshot.
7. Verify baseline preservation and failure behavior.

## 4.11.3 Assignment, Mutation, and Rebinding

Names refer to objects. Assignment can make two names refer to one object; it does not itself copy that object. Lists, dictionaries, and sets support mutation. Strings and built-in numeric values are immutable. Tuple slots cannot be replaced, but their referents may be mutable.

Run the introductory Python blocks in order in one session.

```python
from decimal import Decimal

baseline = [{"security_id": "SEC-A", "quantity": Decimal("10")}]
alias = baseline
assert alias is baseline
alias[0]["quantity"] = Decimal("12")
assert baseline[0]["quantity"] == Decimal("12")

alias = []  # Rebind alias; the original list is still referenced by baseline.
assert alias is not baseline
assert len(baseline) == 1

quantity = Decimal("10")
original_quantity = quantity
quantity = Decimal("12")
assert original_quantity == Decimal("10")
assert quantity == Decimal("12")
```

Updating a record's quantity replaces a dictionary entry; it does not mutate the Decimal object. The difference matters when several records refer to one immutable scalar.

Use `==` to compare values and `is` to check shared objects. Do not use identity as a numeric comparison or depend on reuse of equal immutable objects.

## 4.11.4 A Tuple Is Not Automatically a Frozen Record

```python
wrapped = ({"security_id": "SEC-A", "quantity": Decimal("10")},)
wrapped[0]["quantity"] = Decimal("99")
assert wrapped[0]["quantity"] == Decimal("99")

scalar_record = ("SEC-A", Decimal("10"))
assert scalar_record == ("SEC-A", Decimal("10"))
```

The first tuple still references a mutable dictionary. The second contains supported immutable scalar values. The lab uses a tuple of such scalar records and validates those types before calling the result an immutable snapshot.

Type annotations document shape; they do not freeze a list or validate runtime inputs. A caller can pass an object that does not match an annotation, so the public functions check their contracts.

## 4.11.5 Shallow Copy, Deep Copy, and Reconstruction

A shallow copy creates a new outer container and retains inner references. Deep copying recursively processes a structure, with mechanisms for cycles and custom copy behavior. It can copy more than the application intends and is not a schema validator.

```python
from copy import deepcopy

source = [{"security_id": "SEC-A", "tags": ["baseline"]}]
shallow = list(source)
assert shallow is not source
assert shallow[0] is source[0]

copied = deepcopy(source)
copied[0]["tags"].append("scenario")
assert source[0]["tags"] == ["baseline"]
```

For a narrow financial schema, reconstruction makes the ownership policy visible: validate specific fields, keep immutable scalars, and construct the required containers. Revisit that policy when adding fields. Copying alone does not establish valid quantities, currency, identity, or snapshot timing.

## 4.11.6 Beware Repeated Mutable Containers

```python
shared_rows = [[]] * 2
shared_rows[0].append("SEC-A")
assert shared_rows == [["SEC-A"], ["SEC-A"]]

independent_rows = [[] for _ in range(2)]
independent_rows[0].append("SEC-A")
assert independent_rows == [["SEC-A"], []]
```

The first expression repeats references to one inner list. The second constructs an inner list for each iteration. Similar sharing can arise from mutable default function arguments. When a function needs a new collection on each call, create it inside the function or use a `None` default and initialize explicitly.

## 4.11.7 Snapshot and Update Contracts

The snapshot representation is `tuple[tuple[str, Decimal], ...]`. Each inner pair is security ID and quantity. Order is preserved; IDs are unique within one portfolio supplied by the surrounding application.

This is only the holdings component. A complete persisted portfolio also needs its portfolio identity, snapshot identity, observation basis, and other relevant metadata. An immutable tuple is not an audit archive, transaction boundary, or concurrency mechanism.

The replacement function treats a new quantity as a supplied value. It preserves row order, replaces exactly one existing ID, and returns a new tuple. Unknown IDs are rejected rather than inserted. Inserting or removing holdings should be separate named operations.

## 4.11.8 Lab Contract

Save the complete block as `immutability_lab.py`. Use Python 3.10 or later; no third-party packages are required.

| Item | Rule |
|---|---|
| Capture input | List of dictionaries with exactly security_id and quantity |
| security_id | Exact str, nonempty, no surrounding whitespace |
| quantity | Exact Decimal, finite and nonnegative; fractional and zero allowed |
| Captured output | Tuple of exact tuples containing supported scalar types |
| Snapshot validation | Checks complete shape, types, domain, and duplicate IDs |
| Replacement | Existing security ID required; no insertion |
| Empty capture | Accepted; replacing an ID in an empty snapshot is rejected |
| Ownership | Source dictionaries are not retained; returned representation has no supported mutable descendants |
| Failure | TypeError for wrong types; ValueError for schema/domain/identity errors |

Exact scalar types deliberately exclude subclasses with additional behavior or mutable attributes. This is a narrow teaching boundary rather than a general serializer or arbitrary-object freezing utility.

All snapshot rows are checked before replacement. A valid target does not excuse an invalid later row. Inputs remain unchanged on success and failure.

## 4.11.9 Complete Runnable Lab

```python
"""Capture scalar holdings and replace quantities without mutating a baseline."""

from decimal import Decimal
import unittest

Holding = tuple[str, Decimal]
Snapshot = tuple[Holding, ...]


def checked_id(value: object) -> str:
    if type(value) is not str:
        raise TypeError("security_id must be an exact str")
    if not value or value.strip() != value:
        raise ValueError("security_id must be nonempty and unpadded")
    return value


def checked_quantity(value: object) -> Decimal:
    if type(value) is not Decimal:
        raise TypeError("quantity must be an exact Decimal")
    if not value.is_finite() or value < 0:
        raise ValueError("quantity must be finite and nonnegative")
    return value


def capture_holdings(value: object) -> Snapshot:
    """Validate records and retain only immutable ID/quantity pairs, in order."""
    if not isinstance(value, list):
        raise TypeError("holdings must be a list")
    result: list[Holding] = []
    seen: set[str] = set()
    for index, row in enumerate(value):
        if not isinstance(row, dict):
            raise TypeError(f"holding {index} must be a dictionary")
        if set(row) != {"security_id", "quantity"}:
            raise ValueError(f"holding {index} has incorrect fields")
        security_id = checked_id(row["security_id"])
        quantity = checked_quantity(row["quantity"])
        if security_id in seen:
            raise ValueError(f"duplicate security_id: {security_id}")
        seen.add(security_id)
        result.append((security_id, quantity))
    return tuple(result)


def checked_snapshot(value: object) -> Snapshot:
    if type(value) is not tuple:
        raise TypeError("snapshot must be an exact tuple")
    result: list[Holding] = []
    seen: set[str] = set()
    for row in value:
        if type(row) is not tuple:
            raise TypeError("snapshot rows must be exact tuples")
        if len(row) != 2:
            raise ValueError("snapshot rows must have two fields")
        security_id = checked_id(row[0])
        quantity = checked_quantity(row[1])
        if security_id in seen:
            raise ValueError(f"duplicate security_id: {security_id}")
        seen.add(security_id)
        result.append((security_id, quantity))
    return tuple(result)


def replace_quantity(value: object, security_id: object, quantity: object) -> Snapshot:
    """Return a validated replacement snapshot; preserve the baseline and order."""
    snapshot = checked_snapshot(value)
    target = checked_id(security_id)
    replacement = checked_quantity(quantity)
    if target not in {row[0] for row in snapshot}:
        raise ValueError(f"unknown security_id: {target}")
    return tuple(
        (sid, replacement if sid == target else old_quantity)
        for sid, old_quantity in snapshot
    )


def sample_holdings() -> list[dict[str, object]]:
    return [
        {"security_id": "SEC-B", "quantity": Decimal("0")},
        {"security_id": "SEC-A", "quantity": Decimal("12.5")},
    ]


class ImmutabilityTests(unittest.TestCase):
    def test_capture_order_values_and_empty(self) -> None:
        self.assertEqual(capture_holdings(sample_holdings()), (
            ("SEC-B", Decimal("0")), ("SEC-A", Decimal("12.5"))
        ))
        self.assertEqual(capture_holdings([]), ())

    def test_replacement_preserves_baseline(self) -> None:
        baseline = capture_holdings(sample_holdings())
        changed = replace_quantity(baseline, "SEC-A", Decimal("20"))
        self.assertEqual(changed, (("SEC-B", Decimal("0")), ("SEC-A", Decimal("20"))))
        self.assertEqual(baseline, (("SEC-B", Decimal("0")), ("SEC-A", Decimal("12.5"))))
        self.assertIsNot(changed, baseline)
        self.assertEqual(replace_quantity(changed, "SEC-A", Decimal("0")),
                         (("SEC-B", Decimal("0")), ("SEC-A", Decimal("0"))))

    def test_source_isolation_and_supported_types(self) -> None:
        source = sample_holdings()
        snapshot = capture_holdings(source)
        self.assertEqual(source, sample_holdings())
        source[0]["quantity"] = Decimal("99")
        source.append({"security_id": "SEC-C", "quantity": Decimal("1")})
        self.assertEqual(snapshot, (("SEC-B", Decimal("0")), ("SEC-A", Decimal("12.5"))))
        self.assertIs(type(snapshot), tuple)
        for row in snapshot:
            self.assertIs(type(row), tuple)
            self.assertIs(type(row[0]), str)
            self.assertIs(type(row[1]), Decimal)

    def test_quantity_and_id_validation(self) -> None:
        for quantity in (True, 1, 1.5, "1", None):
            with self.subTest(quantity=quantity):
                with self.assertRaises(TypeError):
                    capture_holdings([{"security_id": "A", "quantity": quantity}])
        for text in ("NaN", "sNaN", "Infinity", "-Infinity", "-1"):
            with self.subTest(text=text):
                with self.assertRaises(ValueError):
                    capture_holdings([{"security_id": "A", "quantity": Decimal(text)}])
        for sid in ("", " A", "A "):
            with self.assertRaises(ValueError):
                capture_holdings([{"security_id": sid, "quantity": Decimal("0")}])
        with self.assertRaises(TypeError):
            capture_holdings([{"security_id": 1, "quantity": Decimal("0")}])

    def test_capture_schema_and_duplicates(self) -> None:
        with self.assertRaises(TypeError):
            capture_holdings(())
        with self.assertRaises(TypeError):
            capture_holdings([None])
        for row in ({}, {"security_id": "A", "quantity": Decimal("0"), "extra": 1}):
            with self.assertRaises(ValueError):
                capture_holdings([row])
        with self.assertRaises(ValueError):
            capture_holdings([
                {"security_id": "A", "quantity": Decimal("0")},
                {"security_id": "A", "quantity": Decimal("1")},
            ])

    def test_snapshot_structure_and_unknown_target(self) -> None:
        with self.assertRaises(TypeError):
            replace_quantity([], "A", Decimal("1"))
        with self.assertRaises(TypeError):
            replace_quantity((["A", Decimal("1")],), "A", Decimal("2"))
        with self.assertRaises(ValueError):
            replace_quantity((("A",),), "A", Decimal("2"))
        with self.assertRaises(ValueError):
            replace_quantity((("A", Decimal("1")), ("A", Decimal("2"))), "A", Decimal("3"))
        for snapshot in ((), (("A", Decimal("1")),)):
            with self.assertRaises(ValueError):
                replace_quantity(snapshot, "UNKNOWN", Decimal("2"))
        with self.assertRaises(TypeError):
            replace_quantity((("A", Decimal("1")),), "A", 2)
        with self.assertRaises(ValueError):
            replace_quantity((("A", Decimal("1")),), "A", Decimal("-1"))

    def test_invalid_later_row_and_subclass(self) -> None:
        invalid = (("A", Decimal("1")), ("B", Decimal("NaN")))
        with self.assertRaises(ValueError):
            replace_quantity(invalid, "A", Decimal("2"))
        self.assertEqual(invalid[0], ("A", Decimal("1")))
        self.assertTrue(invalid[1][1].is_nan())

        class CustomId(str):
            pass

        with self.assertRaises(TypeError):
            capture_holdings([{"security_id": CustomId("A"), "quantity": Decimal("1")}])


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

## 4.11.11 Immutability and Reproducibility

Immutability reduces accidental in-process changes. Reproducing a financial result still requires the input dataset, model version, parameters, numeric context where arithmetic occurs, and observation metadata.

The lab shares immutable scalars safely and creates new tuple records for updates. It does not promise any particular identity reuse for unchanged rows. Test equality for financial values and identity only where the ownership contract requires distinct mutable objects or a new result container.

A frozen baseline also does not make an invalid financial assumption correct. The nonnegative-quantity policy is a declared long-only teaching choice. Extending it to short positions requires a revised domain rule rather than a different copying method.

## 4.11.12 Troubleshooting

| Symptom | Cause to inspect | Correction |
|---|---|---|
| Scenario changes baseline | Two names reference one mutable object | Reconstruct or capture under a schema |
| Tuple record still changes | Mutable descendant retained | Validate every retained field type |
| Copy isolates list but not rows | Shallow copy only | Reconstruct relevant nested containers |
| Equal numbers compare inconsistently | Identity used instead of equality | Compare numeric values with == |
| Repeated rows change together | Same inner container repeated | Construct each mutable child separately |
| Calls accumulate previous results | Mutable default argument | Create a fresh collection per call |
| Invalid later row escapes review | Early update/return | Validate complete snapshot before constructing result |

## 4.11.14 Key Takeaways

Mutation changes an object; rebinding changes which object a name references. An immutable outer container is useful only when its retained descendants satisfy the intended ownership contract.

For a known schema, validate and reconstruct deliberately. Return a new scenario snapshot and preserve the baseline, while keeping financial validation and reproducibility requirements explicit.
