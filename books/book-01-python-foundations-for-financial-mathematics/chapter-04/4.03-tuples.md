## 4.3.1 Purpose

A tuple is an ordered sequence whose element references cannot be replaced, inserted, or removed in place.

Tuples can represent small positional records, related function results, and fixed sequences. Their positions need documented meaning: a pair (period, amount) differs from (amount, period), even when both contain valid financial values.

This section develops construction, indexing, unpacking, immutability limits, and a period-preserving cash-flow selection lab. Dictionaries and named fields follow in Section 4.4.

## 4.3.3 Constructing Tuples

```python
from decimal import Decimal

empty = ()
single = (Decimal("100"),)
grouped_amount = (Decimal("100"))
flow = (2, Decimal("400"))

assert len(empty) == 0
assert len(single) == 1
assert isinstance(grouped_amount, Decimal)
assert isinstance(flow, tuple)
```

The comma distinguishes a single-item tuple from a parenthesized expression. Parentheses make tuple structure readable, but a comma-separated expression can also pack a tuple.

In this example, flow means a receipt of 400 at the end of period 2. All amounts use one documented currency and investor perspective.

## 4.3.4 A Positional Record Contract

| Position | Field | Contract |
|---|---|---|
| 0 | period | Integer 0..1000, excluding bool |
| 1 | amount | Finite Decimal; positive receipt, negative payment, zero allowed |

The tuple does not carry currency, calendar date, or transaction identity. Those must be supplied by the surrounding dataset contract or a richer record.

Two equal tuples can still represent separate economic events. Tuple equality is not a universal deduplication policy.

## 4.3.5 Indexing and Slicing

```python
assert flow[0] == 2
assert flow[-1] == Decimal("400")
assert flow[:1] == (2,)
assert flow[99:] == ()
```

Tuple indexing and slicing follow sequence boundaries: zero-based indexes, negative indexes from the end, and a stop-exclusive slice.

Out-of-range indexing raises IndexError. An out-of-range slice can return an empty tuple. A slice does not acquire a financial meaning merely because it is syntactically valid.

## 4.3.6 Packing and Unpacking

```python
period, amount = flow
assert period == 2
assert amount == Decimal("400")

repacked = period, amount
assert repacked == flow
```

Unpacking assigns values by position. The number of target names must match the number of items unless starred unpacking is used.

A mismatch raises ValueError. Unpacking does not validate financial domains or representations. A two-item tuple can still contain a string period or non-finite amount.

Starred unpacking can collect remaining items into a list, but fixed-size financial records should normally validate their expected shape rather than accept arbitrary extra fields.

## 4.3.7 Returning Related Results

```python
def amount_and_gain(
    starting: Decimal,
    ending: Decimal,
) -> tuple[Decimal, Decimal]:
    """Return ending amount and signed gain; assume validated same-currency inputs."""
    return ending, ending - starting


ending, gain = amount_and_gain(Decimal("1000"), Decimal("1100"))
assert ending == Decimal("1100")
assert gain == Decimal("100")
```

The function returns one tuple containing two values. This illustrative gain calculation assumes no intervening cash flows and uses the active Decimal context.

tuple[Decimal, Decimal] describes a fixed two-item shape to static tooling. tuple[Decimal, ...] describes a variable-length homogeneous tuple. Neither annotation automatically validates actual inputs at runtime.

## 4.3.8 Immutable Container, Potentially Mutable Contents

```python
notes = ["scheduled"]
record = ("P001", notes)
notes.append("reviewed")

assert record[1] == ["scheduled", "reviewed"]
```

The tuple still references the same list. The list's contents can change. A tuple is not automatically a deeply frozen snapshot.

Tuple item assignment raises TypeError. Rebinding a variable to a different tuple is allowed; it does not mutate the original tuple.

Concatenating tuples produces a tuple result rather than extending the original in place. Tuples do not provide list methods such as append or remove.

## 4.3.9 Hashing and Keys

A tuple can be hashable when all its elements are hashable. A tuple containing a list cannot be hashed.

An identifier pair such as ("ACCOUNT-A", "USD") can be useful as a compound dictionary key once the identity contract is established. A tuple containing a mutable notes list cannot serve that purpose.

Do not persist Python hash values as financial identifiers or fingerprints. Hashability is a container requirement, not proof of business uniqueness or durable identity.

## 4.3.10 Preserve Periods During Selection

Section 4.2 selected positive amounts from a list. If positions represented periods, the selected amount-only list lost that mapping.

Representing each observation as (period, amount) preserves its original period when records are selected. A receipt at period 3 remains period 3 even if it becomes the first selected result.

This does not add actual dates, discount rates, or currency metadata. It preserves one specific piece of the supplied contract.

## 4.3.11 Hands-On Lab — Select Period-Amount Pairs

Save as tuples_lab.py. It uses Python 3.10 or later and only the standard library.

The helper accepts a list of two-item tuples and returns a new list of validated positive-flow tuples. It preserves source order, supplied period identifiers, and duplicates. It does not sort or enforce unique periods.

All amounts are assumed to share a currency and investor perspective. Multiple payments can legitimately occur in the same period. No valuation is performed.

```python
"""Validate positional cash-flow pairs while preserving period metadata."""

from decimal import Decimal
import unittest


def positive_period_flows(values: object) -> list[tuple[int, Decimal]]:
    """Select positive (period, amount) pairs into a fresh outer list.

    Require list input and two-item tuple entries. Period is integer
    0..1000 excluding bool; amount is finite Decimal, signed or zero.
    Preserve supplied order, periods, and duplicate receipts.
    Do not mutate input or calculate monetary arithmetic.
    Raise TypeError for representations and ValueError for shape/domain.
    """
    if not isinstance(values, list):
        raise TypeError("values must be a list")

    selected: list[tuple[int, Decimal]] = []
    for entry in values:
        if not isinstance(entry, tuple):
            raise TypeError("each entry must be a tuple")
        if len(entry) != 2:
            raise ValueError("each entry must have two items")
        period, amount = entry

        if not isinstance(period, int) or isinstance(period, bool):
            raise TypeError("period must be an integer excluding bool")
        if not 0 <= period <= 1000:
            raise ValueError("period must be between 0 and 1000")
        if not isinstance(amount, Decimal):
            raise TypeError("amount must be Decimal")
        if not amount.is_finite():
            raise ValueError("amount must be finite")
        if amount > 0:
            selected.append((period, amount))
    return selected


class TestFinancialTuples(unittest.TestCase):
    """Verify positional contracts and tuple behavior."""

    def test_preserved_periods_and_duplicates(self) -> None:
        source = [
            (0, Decimal("-1000")), (3, Decimal("400")),
            (1, Decimal("0")), (3, Decimal("400")),
            (7, Decimal("100")),
        ]
        before = source.copy()
        result = positive_period_flows(source)
        self.assertEqual(
            result,
            [(3, Decimal("400")), (3, Decimal("400")), (7, Decimal("100"))],
        )
        self.assertEqual(source, before)
        self.assertIsNot(result, source)

    def test_empty_and_nonpositive(self) -> None:
        empty: list[tuple[int, Decimal]] = []
        result = positive_period_flows(empty)
        self.assertEqual(result, [])
        self.assertIsNot(result, empty)
        self.assertEqual(
            positive_period_flows([(0, Decimal("-10")), (1, Decimal("0"))]), []
        )

    def test_entry_representations_and_shape(self) -> None:
        with self.assertRaises(TypeError):
            positive_period_flows(((1, Decimal("100")),))
        with self.assertRaises(TypeError):
            positive_period_flows([[1, Decimal("100")]])
        for entry in ((), (1,), (1, Decimal("100"), "USD")):
            with self.subTest(entry=entry):
                with self.assertRaises(ValueError):
                    positive_period_flows([entry])

    def test_period_domain(self) -> None:
        for period in (True, "1", 1.5):
            with self.subTest(period=period):
                with self.assertRaises(TypeError):
                    positive_period_flows([(period, Decimal("100"))])
        for invalid_period in (-1, 1001):
            with self.subTest(period=invalid_period):
                with self.assertRaises(ValueError):
                    positive_period_flows([(invalid_period, Decimal("100"))])

    def test_amount_domain(self) -> None:
        with self.assertRaises(TypeError):
            positive_period_flows([(1, "100")])
        for amount in ("NaN", "Infinity", "-Infinity"):
            with self.subTest(amount=amount):
                with self.assertRaises(ValueError):
                    positive_period_flows([
                        (1, Decimal("100")), (2, Decimal(amount))
                    ])

    def test_tuple_with_mutable_member(self) -> None:
        notes = ["scheduled"]
        record = ("P001", notes)
        notes.append("reviewed")
        self.assertEqual(record[1], ["scheduled", "reviewed"])
        with self.assertRaises(TypeError):
            hash(record)


if __name__ == "__main__":
    unittest.main()
```

Run on Windows:

```powershell
py -m unittest -v tuples_lab
```

Run on macOS or Linux:

```bash
python3 -m unittest -v tuples_lab
```

Expected summary: **6 tests, OK**. Subtests exercise additional cases.

Validation examines all entries before returning. An invalid later amount raises even if an earlier pair was a valid receipt. The function performs no numeric accumulation and requires no new arithmetic-context policy.

## 4.3.12 Choosing a Tuple Deliberately

| Requirement | Tuple suitability |
|---|---|
| Small fixed positional result | Useful when the order is clear |
| Growing collection of observations | A list may express updates more directly |
| Many descriptive or optional fields | Named records may be easier to review |
| Deeply immutable snapshot | Tuple alone is insufficient |
| Compound lookup key | Depends on element hashability and identity policy |

Changing tuple position order is an interface change. Appending a field can break existing unpacking calls. Keep positional contracts small and stable.

Do not assume immutability makes a record financially valid, thread-safe in every surrounding design, or suitable as an audit snapshot.

## 4.3.14 Troubleshooting Guide

| Symptom | Likely cause | Correction |
|---|---|---|
| Single-item value is not a tuple | Trailing comma omitted | Use (value,) |
| TypeError on item replacement | Tuple container is immutable | Build a revised record explicitly |
| ValueError during unpacking | Record length does not match targets | Validate positional shape |
| Tuple contents appear to change | Nested mutable object changed | Review ownership and snapshot policy |
| Unhashable tuple | An element is unhashable | Choose an appropriate key representation |
| Selected flow moves to wrong period | Original period identifier discarded | Retain the period with the amount |
| Same Python types but wrong field meaning | Positional order swapped | Document and validate the contract |

## 4.3.15 Key Takeaways

Tuples preserve order while preventing in-place changes to their element references. They do not enforce a financial schema or freeze nested objects.

Use explicit positional contracts, preserve period metadata, and prefer named records when field meaning becomes difficult to track.
