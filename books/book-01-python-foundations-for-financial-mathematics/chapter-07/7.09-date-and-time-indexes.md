## 7.9.1 Purpose

A financial observation needs a time interpretation as well as a value. A calendar date, a local wall-clock time and a globally identified instant are different kinds of information. Treating them as interchangeable can misorder observations, create duplicate records, or include data outside a calculation interval.

This section constructs a UTC DatetimeIndex for one synthetic instrument's price observations. It verifies explicit timestamp syntax, detects duplicate instants after conversion, sorts complete records chronologically and selects time intervals deliberately. It does not infer a trading calendar or establish when information became available to an investor.

## 7.9.2 Learning Objectives

1. Distinguish Timestamp, DatetimeIndex, Timedelta and Period.
2. Parse a documented timestamp format with explicit failure behavior.
3. Explain naive times, numeric offsets and named time zones.
4. Distinguish localization from time-zone conversion.
5. Detect duplicate instants after normalization to UTC.
6. Sort observations without separating times from values.
7. Select inclusive or half-open intervals intentionally.
8. Recognize daylight-saving, calendar and information-availability limits.

## 7.9.3 Temporal Concepts

| Concept | pandas representation | Example interpretation |
|---|---|---|
| One date/time value | Timestamp | An observation at 14:30 UTC |
| Labeled observation axis | DatetimeIndex | Times attached to a price Series |
| Elapsed duration | Timedelta | Thirty elapsed minutes between observations |
| Calendar span | Period / PeriodIndex | A monthly reporting period |
| Calendar-based step | DateOffset | A movement according to calendar rules |

A date-only valuation label such as 2026-01-30 does not establish a precise market-close instant. An instrument can have several relevant times: event time, publication time, ingestion time and decision time. Preserve those fields separately when they matter.

The lab's event_time identifies a supplied price-observation instant. It cannot establish that the observation was available to a historical strategy at that instant. Correct chronological order alone does not eliminate look-ahead bias.

## 7.9.4 Explicit Parsing Before Indexing

The lab accepts second-resolution strings with the exact structure YYYY-MM-DDTHH:MM:SS followed by Z or a signed HH:MM numeric offset. Examples include `2026-01-30T14:30:00Z` and `2026-01-30T09:30:00-05:00`.

The syntax gate rejects missing offsets, ambiguous slash dates, fractional seconds and surrounding whitespace. Python datetime parsing validates calendar and clock fields; an explicit offset check prevents invalid minute/hour tokens. pandas then parses using a declared format with errors='raise' and utc=True.

This is deliberately narrower than the full set of timestamps pandas can parse. A feed supporting fractional seconds or another documented format should have its own contract and tests. Do not use heuristic date-order preferences to resolve an inherently ambiguous source format.

`errors='coerce'` can be useful for an audit that preserves failed source records, but replacing an invalid timestamp with NaT and dropping it silently can remove a material observation. This component rejects the batch instead.

## 7.9.5 Naive Times, Localization and Conversion

A naive time such as 09:30 has no associated time zone. To interpret it as New York local wall time, explicitly localize it:

```python
naive = pd.DatetimeIndex(['2026-01-30 09:30:00'])
local = naive.tz_localize('America/New_York',
                         ambiguous='raise', nonexistent='raise')
utc = local.tz_convert('UTC')
```

The winter fixture becomes 14:30 UTC. Localization attaches a time-zone interpretation to wall-clock fields. Conversion changes the displayed zone of an already aware instant while preserving that instant.

Passing naive values to `to_datetime(..., utc=True)` interprets those values as UTC; it does not discover their source zone. The public loader rejects naive timestamp strings rather than making that assumption.

A numeric offset describes the difference from UTC at one observation. It does not identify a regional zone or its future daylight-saving rules. Conversely, a named zone uses historical/rule data supplied by the time-zone provider. Record runtime and time-zone dependencies when exact historical conversion reproduction matters.

## 7.9.6 Daylight-Saving Transitions

A local clock can skip a wall time or repeat it during an offset transition. The tests use New York's 2026 spring and autumn transition examples: 02:30 on March 8 is nonexistent; 01:30 on November 1 is ambiguous.

The localization examples request errors for both situations. The tests verify the corresponding exception names rather than accepting any arbitrary failure. Resolving ambiguity, shifting nonexistent times or inferring an ordering is a source-policy choice. Do not silently choose one because it makes parsing succeed.

An explicit numeric offset identifies which instant a repeated wall time represents. The loader checks syntax and valid offset ranges, but does not verify that a numeric offset matches the rules of a separately claimed geographic zone. That would require additional source metadata and validation.

## 7.9.7 Normalize Before Duplicate Detection

The fixture intentionally contains these two timestamp encodings:

| Source token | UTC instant |
|---|---|
| 2026-01-30T10:00:00-05:00 | 2026-01-30T15:00:00Z |
| 2026-01-30T16:00:00+01:00 | 2026-01-30T15:00:00Z |

Different strings can therefore be duplicate instants. The loader checks uniqueness after UTC conversion and rejects this fixture first. The demonstration then changes the second token to 16:30+01:00, yielding a distinct 15:30 UTC observation.

The one-price-per-instant rule is specific to this single-instrument snapshot. A transaction or multi-asset dataset can legitimately contain several records at the same timestamp. Define a composite key, such as instrument and event identifier, rather than globally deleting equal timestamps.

## 7.9.8 Sorting, Slicing and Intervals

The function builds the price Series with each value attached to its parsed timestamp, then calls sort_index. Sorting a timestamp vector independently and reattaching unsorted prices would corrupt the mapping.

A labeled time slice includes matching endpoints:

```python
inclusive = series.loc[start:end]
```

For adjacent processing windows, a half-open interval often expresses a clearer boundary:

```python
window = series.loc[(series.index >= start) & (series.index < end)]
```

The lab's interval from 15:00 UTC inclusive to 15:30 UTC exclusive contains one observation. The inclusive slice contains both boundary observations. Neither convention is universally correct; choose it according to the valuation or reporting contract and avoid counting boundary records twice across windows.

A sorted index does not imply a regular frequency or complete source coverage. The elapsed difference between the first two valid fixture times is thirty minutes, but this does not establish that every expected thirty-minute observation is present.

## 7.9.9 Calendar and Frequency Cautions

`pd.date_range('2026-01-30', periods=3, freq='D')` generates calendar dates, including the weekend in this example. It constructs labels, not observed data. Generic business-day rules are also not a complete exchange calendar: holidays, half-days, instruments and venues can differ.

An elapsed duration such as Timedelta(hours=24) and a calendar-based day step can answer different questions across daylight-saving transitions. State whether a rule concerns elapsed time, local wall-clock recurrence, calendar dates or trading sessions.

Removing time-of-day or timezone information can collapse distinct observations into equal labels. Preserve the original time semantics before deriving reporting dates. Resampling and frequency conversion are addressed in Section 7.13.

## 7.9.11 Complete Lab — time_index.py

```python
"""One synthetic instrument's offset-stamped price observations."""
import re
import numpy as np
import pandas as pd

STAMP=re.compile(r'[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}(?:Z|[+-][0-9]{2}:[0-9]{2})\Z')


def price_series(raw):
    """Require explicit offsets, normalize instants to UTC, reject duplicates.

    Source contains only one instrument, common currency and price convention.
    Event timestamps do not establish when an observer could know the price.
    """
    if not isinstance(raw,pd.DataFrame) or not 1<=len(raw)<=10_000:
        raise ValueError('DataFrame with 1..10000 observations required')
    if not raw.columns.is_unique or raw.columns.tolist()!=['timestamp','price']:
        raise ValueError('exact timestamp, price schema required')
    if not raw['timestamp'].map(lambda x:isinstance(x,str) and STAMP.fullmatch(x) is not None).all():
        raise ValueError('second-resolution timestamp with explicit offset required')
    # Additional clock/offset checks prevent permissive normalization of bad tokens.
    from datetime import datetime
    for token in raw['timestamp']:
        if token.endswith('Z'): offset='00:00'
        else: offset=token[-5:]
        if int(offset[:2])>23 or int(offset[3:])>59:
            raise ValueError('invalid numeric offset')
        datetime.fromisoformat(token.replace('Z','+00:00'))
    parsed=pd.to_datetime(raw['timestamp'],format='%Y-%m-%dT%H:%M:%S%z',
                          errors='raise',utc=True)
    index=pd.DatetimeIndex(parsed,name='event_time')
    if index.hasnans or not index.is_unique:
        raise ValueError('unique nonmissing UTC instants required')
    col=raw['price']
    if not isinstance(col.dtype,np.dtype) or col.dtype.kind not in 'iuf':
        raise ValueError('ordinary real numeric prices required')
    values=col.to_numpy(dtype=np.float64,copy=True)
    if not np.isfinite(values).all() or np.any(values<0):
        raise ValueError('finite nonnegative prices required')
    return pd.Series(values,index=index,name='price').sort_index()


def fixture():
    return pd.DataFrame({'timestamp':['2026-01-30T10:00:00-05:00',
                                     '2026-01-30T14:30:00Z',
                                     '2026-01-30T16:00:00+01:00'],
                         'price':[101.,100.,102.]})

if __name__=='__main__':
    # Fixture intentionally contains two encodings of 15:00 UTC: reject first.
    try: price_series(fixture())
    except ValueError as exc: print('Duplicate example rejected: '+str(exc))
    raw=fixture(); raw.loc[2,'timestamp']='2026-01-30T16:30:00+01:00'
    s=price_series(raw)
    for stamp,value in s.items(): print(f'{stamp.isoformat()}: {value:.2f}')
    start=pd.Timestamp('2026-01-30T15:00:00Z'); end=pd.Timestamp('2026-01-30T15:30:00Z')
    selected=s.loc[(s.index>=start)&(s.index<end)]
    print(f'Half-open interval observations: {len(selected)}')
```

## 7.9.12 Complete Tests — test_time_index.py

```python
import unittest
import numpy as np
import pandas as pd
from time_index import price_series,fixture

class TimeTests(unittest.TestCase):
    def valid(self):
        r=fixture(); r.loc[2,'timestamp']='2026-01-30T16:30:00+01:00'; return r

    def test_sorted_utc_prices(self):
        s=price_series(self.valid())
        self.assertIsInstance(s.index,pd.DatetimeIndex)
        self.assertEqual(str(s.index.tz),'UTC'); self.assertTrue(s.index.is_monotonic_increasing)
        self.assertEqual(s.tolist(),[100,101,102]); self.assertEqual(s.index.name,'event_time')
        self.assertEqual(s.index[0],pd.Timestamp('2026-01-30T14:30:00Z'))

    def test_duplicate_instants(self):
        with self.assertRaises(ValueError): price_series(fixture())

    def test_bad_timestamps(self):
        for token in ['2026-01-30','2026-01-30T10:00:00','01/30/2026 10:00',
                      '2026-02-30T10:00:00Z','2026-01-30T25:00:00Z',
                      '2026-01-30T10:00:00+05:99','',None]:
            r=self.valid(); r.loc[0,'timestamp']=token
            with self.subTest(token=token),self.assertRaises(ValueError): price_series(r)

    def test_bad_price_and_schema(self):
        for vals in [[-1,100,100],[np.nan,100,100],[np.inf,100,100],['1','2','3']]:
            r=self.valid(); r['price']=vals
            with self.assertRaises(ValueError): price_series(r)
        with self.assertRaises(ValueError): price_series(self.valid().assign(extra=1))
        with self.assertRaises(ValueError): price_series(self.valid().iloc[:0])

    def test_zone_conversion_preserves_instant(self):
        s=price_series(self.valid()); local=s.tz_convert('America/New_York')
        self.assertEqual(local.index[0].hour,9)
        pd.testing.assert_series_equal(local.tz_convert('UTC'),s)

    def test_localization_and_dst(self):
        # Unambiguous winter wall time is explicitly attached to its source zone.
        naive=pd.DatetimeIndex(['2026-01-30 09:30:00'])
        aware=naive.tz_localize('America/New_York',ambiguous='raise',nonexistent='raise')
        self.assertEqual(aware.tz_convert('UTC')[0],pd.Timestamp('2026-01-30T14:30:00Z'))
        for text,expected in [('2026-03-08 02:30:00','NonExistentTimeError'),
                              ('2026-11-01 01:30:00','AmbiguousTimeError')]:
            # pandas exposes timezone-provider-specific exception classes.
            with self.assertRaises(Exception) as caught:
                pd.DatetimeIndex([text]).tz_localize('America/New_York',
                                                   ambiguous='raise',nonexistent='raise')
            self.assertEqual(type(caught.exception).__name__,expected)

    def test_interval_and_elapsed_time(self):
        s=price_series(self.valid()); start=s.index[1]; end=s.index[2]
        self.assertEqual(len(s.loc[start:end]),2)  # inclusive labeled endpoints
        self.assertEqual(len(s.loc[(s.index>=start)&(s.index<end)]),1)
        self.assertEqual(s.index[1]-s.index[0],pd.Timedelta(minutes=30))
        self.assertEqual(len(pd.date_range('2026-01-30',periods=3,freq='D')),3)

    def test_source_and_order_independence(self):
        raw=self.valid(); before=raw.copy(deep=True)
        a=price_series(raw); b=price_series(raw.iloc[::-1])
        pd.testing.assert_series_equal(a,b)
        a.iloc[0]=0; pd.testing.assert_frame_equal(raw,before)

if __name__=='__main__': unittest.main()
```

## 7.9.14 Verification and Troubleshooting

The suite checks sorted UTC values, duplicate instants, malformed/naive/invalid calendar timestamps, invalid numeric prices/schema, timezone conversion round trips, explicit localization and daylight-saving errors, interval endpoints, elapsed time, input-order independence and source preservation.

| Symptom | Likely cause | Action |
|---|---|---|
| Two different tokens rejected as duplicates | They encode the same UTC instant | Inspect normalized keys and source record grain |
| Local time shifted unexpectedly | Naive input was interpreted in the wrong zone | Establish source zone before conversion |
| Localization raises during a transition | Wall time is ambiguous or nonexistent | Apply an explicit source-backed policy |
| Adjacent windows double-count a record | Both ends were included | Specify interval closure consistently |
| Sorted observations still have gaps | Ordering did not establish expected coverage | Compare against a documented observation schedule |
| Date range contains nontrading dates | Generic calendar labels were generated | Use the appropriate venue/instrument calendar policy |

Float64 prices remain approximate. The component validates time identity and price domain, not price accuracy or the timing of information availability.
