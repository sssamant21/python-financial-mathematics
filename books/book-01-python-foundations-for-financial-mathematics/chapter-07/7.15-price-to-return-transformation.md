## 7.15.1 Purpose

A price observation describes a level at a time; a return compares values across an interval. Transforming prices into returns therefore requires both arithmetic and a clear relationship between observations.

This section converts one instrument's complete positive-price Series into adjacent-observation simple, gross and logarithmic price returns. It retains interval starts and elapsed durations, preserves the undefined first interval return, and reconciles compounded interval results with the endpoint price ratio. It does not infer total investment performance from unadjusted prices.

## 7.15.2 Learning Objectives

1. Derive simple and gross returns from adjacent positive prices.
2. Interpret pct_change output as fractional change, not an already multiplied percentage.
3. Align each return to its ending observation and retain its start.
4. Distinguish observation steps from equal calendar or trading intervals.
5. Disable implicit missing-price filling and reject incomplete source input.
6. Compare logarithmic returns and multiplicative simple-return linking.
7. Explain zero-price, adjustment and total-return limitations.
8. Reproduce independent scalar and endpoint reconciliation tests.

## 7.15.3 Financial Contract

All observations refer to the same synthetic instrument, same currency/per-unit convention and consistent price-adjustment basis. The source contains no missing prices and is ordered by unique timezone-aware observation instants. Prices are strictly positive.

There are no distributions, fees, taxes, external flows, trades or FX changes in the fixture. These assumptions make the endpoint price ratio an appropriate price-only change measure. It is not automatically a total-return measure for a dividend-paying asset or an investor's money-weighted performance.

| Observation end, UTC | Price | Compared with | Elapsed interval |
|---|---:|---|---|
| 2026-01-30 16:00 | 100 | No prior supplied observation | Undefined |
| 2026-02-02 16:00 | 110 | 2026-01-30 16:00 | 3 days |
| 2026-02-03 16:00 | 99 | 2026-02-02 16:00 | 1 day |

The first interval crosses a weekend. The function neither generates weekend prices nor labels every result a daily return. It computes returns between the supplied observations and records their actual elapsed differences.

## 7.15.4 Simple and Gross Returns

For positive prices P_previous and P_current:

- Gross return G = P_current / P_previous.
- Simple price return r = G − 1.
- Percentage display = 100 × r percent.

The fixture's gross returns are 1.10 and 0.90. Simple returns are 0.10 and −0.10, displayed as +10% and −10%. A stored value 0.10 should not be multiplied by 100 before using Python percent formatting, which already performs that display conversion.

```python
simple = prices.pct_change(periods=1, fill_method=None)
gross = prices / prices.shift(1)
```

Despite its name, pct_change calculates fractional change. The explicit fill_method=None prevents automatic forward filling before comparison in the pinned version. No freq argument is used: periods=1 means one observation step.

The first return is NaN because there is no prior supplied price. It is not an observed zero return. The cumulative return column begins at zero for a different reason: the first price is the selected baseline, so its ratio to itself is one.

## 7.15.5 Align the Interval, Not Just the Number

A return is placed at its ending observation. The report includes interval_start and elapsed so the comparison remains inspectable.

```python
times = pd.Series(prices.index, index=prices.index)
interval_start = times.shift(1)
elapsed = times.diff()
```

Without freq, shift moves prior values into current row positions while retaining the current index. It does not manufacture the quote from one calendar day earlier. A frequency-based shift instead changes temporal labels and can introduce a different alignment problem; use it only under a documented observation schedule.

Complete source cells do not prove a complete expected calendar. An absent observation can lengthen an interval without creating a NaN row. To require daily closes or exchange sessions, validate coverage against the intended calendar first. Equal observation counts do not establish equal elapsed intervals or equal market sessions.

## 7.15.6 Missing Prices and Filling

For the mechanical Series [100,NaN,110], pct_change(fill_method=None) returns missing values for all three positions: no complete adjacent pair exists. Forward filling first instead yields [100,100,110], producing an assumed zero interval followed by +10%.

Those computations express different source assumptions. Dropping the middle observation would create a direct 100-to-110 comparison over a longer interval. It would not restore two observed shorter-interval returns.

The public function rejects missing prices before conversion. The tests show the alternative mechanics separately, without weakening that strict policy. Preserve source missingness and availability evidence when designing a more permissive transformation.

## 7.15.7 Compounding and Endpoint Reconciliation

The fixture demonstrates why adding adjacent simple returns is generally wrong:

(1+0.10) × (1−0.10) − 1 = −0.01.

The price rises from 100 to 110, then falls to 99. The second 10% decline applies to the larger base of 110. Adding +10% and −10% produces zero, while the linked price return is −1%.

For this complete single-instrument path without distributions, the product of adjacent gross ratios telescopes to P_last/P_first. The suite compares the compounded simple-return result with that independent endpoint ratio within fixture-appropriate tolerance.

The cumulative_price_return column is calculated directly as price/first_price − 1 at each observation. This provides an endpoint route rather than deriving every cumulative figure from rounded interval displays. Never compound rounded percentages copied from a report when full-precision observations are available.

## 7.15.8 Logarithmic Returns

For strictly positive prices, logarithmic price return is log(P_current) − log(P_previous). Adjacent logarithmic returns add to log(P_last/P_first) in exact arithmetic; expm1 of that sum reconstructs the endpoint simple price return.

```python
log_return = np.log(prices).diff()
```

Log-price differences avoid first forming an extreme ratio for the logarithm, but this component still requires finite supported simple and gross returns. It is not an unrestricted extreme-range log-only API. Log differences can also lose significant digits for tiny changes between nearby large log values. No universal numerical-accuracy advantage is claimed.

A log return is not itself a simple return or a percentage profit. Convert deliberately when reporting. Logarithmic behavior, compounding and investment-performance theory are developed further in the later returns chapter.

## 7.15.9 Positive-Price and Adjustment Limits

Strict positivity supports all three output representations. A simple price return from a positive price to zero can validly represent total loss, but its log return is not finite and a subsequent zero denominator is undefined. This combined simple/gross/log function rejects zero rather than silently changing representations.

Some instruments can have negative quoted prices or require multipliers and special cash-flow treatment. This positive-price model is unsuitable for them without a different financial contract.

A split can change an unadjusted per-unit quote without representing an equivalent economic loss for the holder. A distribution can reduce price while paying cash. Input adjustment conventions must therefore be consistent and documented. A vendor field named adjusted price is not proof of a particular total-return or reinvestment convention; inspect the source methodology before interpretation.

The function does not annualize results. A three-day interval and a one-day interval require an explicit horizon and calendar convention before any annualized comparison. Price returns alone also do not establish an investor's performance when units held or external cash flows change.

## 7.15.10 Validation and Environment

## 7.15.11 Complete Transformation — returns.py

```python
"""Adjacent-observation price returns without implicit gap filling."""
import numpy as np
import pandas as pd


def transform(prices):
    """One instrument, consistent price/currency/adjustment convention.

    Complete strictly positive prices; no distributions, fees, flows or FX.
    Intervals follow supplied rows, not an inferred trading-day calendar.
    """
    if not isinstance(prices,pd.Series) or not 2<=len(prices)<=10_000:
        raise ValueError('Series with 2..10000 prices required')
    idx=prices.index
    if not isinstance(idx,pd.DatetimeIndex) or idx.tz is None or idx.hasnans:
        raise ValueError('complete aware DatetimeIndex required')
    if not idx.is_unique or not idx.is_monotonic_increasing:
        raise ValueError('ordered unique observation times required')
    if not isinstance(prices.dtype,np.dtype) or prices.dtype.kind not in 'iuf':
        raise ValueError('ordinary real numeric prices required')
    p=prices.astype('float64').copy(deep=True); p.index=p.index.tz_convert('UTC')
    if not np.isfinite(p.to_numpy()).all() or (p<=0).any():
        raise ValueError('complete finite strictly positive prices required')
    try:
        with np.errstate(over='raise',divide='raise',invalid='raise'):
            simple=p.pct_change(periods=1,fill_method=None)
            gross=p/p.shift(1)
            # Log-price differences avoid requiring a representable extreme ratio.
            log_return=np.log(p).diff()
            cumulative=p/p.iloc[0]-1
    except FloatingPointError as exc:
        raise ValueError('unsupported numerical range') from exc
    if not np.isfinite(simple.iloc[1:].to_numpy()).all() or not np.isfinite(gross.iloc[1:].to_numpy()).all():
        raise ValueError('nonfinite interval return')
    if (gross.iloc[1:]<=0).any() or (simple.iloc[1:]<=-1).any():
        raise ValueError('return rounded outside supported positive-price range')
    if not np.isfinite(log_return.iloc[1:].to_numpy()).all() or not np.isfinite(cumulative.to_numpy()).all():
        raise ValueError('nonfinite return output')
    times=pd.Series(p.index,index=p.index)
    return pd.DataFrame({'price':p,'interval_start':times.shift(1),
        'elapsed':times.diff(),'simple_return':simple,'gross_return':gross,
        'log_return':log_return,'cumulative_price_return':cumulative})


def fixture():
    return pd.Series([100.,110.,99.],index=pd.to_datetime(
        ['2026-01-30T16:00:00Z','2026-02-02T16:00:00Z','2026-02-03T16:00:00Z']),name='price')

if __name__=='__main__':
    r=transform(fixture())
    print(r[['price','simple_return','cumulative_price_return']].to_string(float_format=lambda x:f'{x:.4f}'))
    print(f'Endpoint price return: {r["cumulative_price_return"].iloc[-1]:.2%}')
    print('Elapsed intervals: '+', '.join(str(x) for x in r['elapsed'].iloc[1:]))
```

## 7.15.12 Complete Tests — test_returns.py

```python
import unittest
import numpy as np
import pandas as pd
from returns import transform,fixture

class ReturnTests(unittest.TestCase):
    def test_known_answer_and_first_row(self):
        r=transform(fixture())
        np.testing.assert_allclose(r['simple_return'].iloc[1:],[.1,-.1],rtol=0,atol=1e-12)
        self.assertTrue(pd.isna(r['simple_return'].iloc[0]))
        self.assertTrue(pd.isna(r['interval_start'].iloc[0]))
        self.assertEqual(r['cumulative_price_return'].iloc[0],0)
        self.assertAlmostEqual(r['cumulative_price_return'].iloc[-1],-.01)

    def test_scalar_and_linked_reconciliation(self):
        p=fixture(); r=transform(p); scalar=[p.iloc[i]/p.iloc[i-1]-1 for i in range(1,len(p))]
        np.testing.assert_allclose(r['simple_return'].iloc[1:],scalar,rtol=0,atol=1e-12)
        linked=float(np.prod(1+r['simple_return'].iloc[1:])-1)
        self.assertAlmostEqual(linked,p.iloc[-1]/p.iloc[0]-1)
        self.assertAlmostEqual(float(np.expm1(r['log_return'].iloc[1:].sum())),linked)
        self.assertAlmostEqual(r['simple_return'].iloc[1:].sum(),0)

    def test_interval_alignment(self):
        p=fixture(); r=transform(p)
        self.assertEqual(r['interval_start'].iloc[1],p.index[0])
        self.assertEqual(r['elapsed'].iloc[1],pd.Timedelta(days=3))
        self.assertEqual(r['elapsed'].iloc[2],pd.Timedelta(days=1))

    def test_missing_policy_and_no_fill_mechanics(self):
        p=fixture(); p.iloc[1]=np.nan
        with self.assertRaises(ValueError): transform(p)
        raw=pd.Series([100.,np.nan,110.]); r=raw.pct_change(fill_method=None)
        self.assertTrue(r.isna().all())
        filled=raw.ffill().pct_change(fill_method=None)
        self.assertEqual(filled.iloc[1],0); self.assertAlmostEqual(filled.iloc[2],.1)

    def test_invalid_numeric_domain(self):
        for values in [[0,110,99],[-1,110,99],[100,np.inf,99],['100','110','99'],[True,False,True]]:
            with self.assertRaises(ValueError): transform(pd.Series(values,index=fixture().index))
        with self.assertRaises(ValueError): transform(fixture().iloc[:1])
        huge=pd.Series([1e-300,1e300],index=fixture().index[:2])
        with self.assertRaises(ValueError): transform(huge)

    def test_invalid_time_axis(self):
        p=fixture()
        for bad in [p.iloc[::-1],p.tz_localize(None),pd.concat([p,p.iloc[:1]]),p.reset_index(drop=True)]:
            with self.assertRaises(ValueError): transform(bad)

    def test_source_and_scale(self):
        p=fixture(); before=p.copy(deep=True); a=transform(p); b=transform(p*10)
        np.testing.assert_allclose(a['simple_return'].iloc[1:],b['simple_return'].iloc[1:],rtol=0,atol=1e-12)
        a.iloc[0,0]=0; pd.testing.assert_series_equal(p,before)

    def test_future_and_constant(self):
        p=fixture(); a=transform(p); q=p.copy(); q.iloc[-1]=120; b=transform(q)
        pd.testing.assert_frame_equal(a.iloc[:-1],b.iloc[:-1])
        constant=transform(p*0+100)
        self.assertTrue((constant['simple_return'].iloc[1:]==0).all())

if __name__=='__main__': unittest.main()
```

## 7.15.14 Troubleshooting and Exercises

| Symptom | Likely cause | Action |
|---|---|---|
| Returns are 100 times too large | Fraction confused with percent display | Retain decimal fractions internally |
| First return is NaN | No prior supplied observation | Preserve the undefined interval |
| A missing-price period becomes zero | Filling occurred before comparison | Use explicit missingness policy and fill_method=None |
| Linked result differs from sum | Simple returns compound multiplicatively | Compare gross product with endpoint ratio |
| Interval called daily spans several days | Row step confused with calendar step | Retain interval starts and durations |
| Price drop appears to imply total loss | Corporate action/distribution convention omitted | Verify consistent price and cash-flow treatment |

1. Reproduce +10%, −10% and the linked −1% by hand.
2. Explain why the first interval return is missing while the first cumulative baseline return is zero.
3. Change the final price to 121 and compare direct endpoint and compounded results.
4. Replace the middle price with NaN and contrast rejection, no filling, forward filling and dropping the row.
5. Verify that multiplying every price by a common positive scale leaves fixture returns unchanged.
6. Explain why a constant-currency scale is different from changing FX rates across observations.
7. Describe a separate simple-return-only contract that allows a terminal zero price without claiming finite log returns.
8. List source metadata needed before interpreting a price series as a total-return or adjusted-price series.
