## 7.3.1 Purpose

A DataFrame organizes observations into a two-dimensional labeled table. Unlike a single Series, it can hold several measured fields with different column dtypes. Financial analysis benefits when quantities, prices, and derived values remain attached to the same asset identifiers.

This section builds a small holdings table. It emphasizes structure and meaning: which axis identifies assets, which columns represent quantities or prices, and which operations produce a meaningful currency value. A table's appearance alone does not establish a valid schema.

## 7.3.2 Learning Objectives

2. Inspect shape, index, columns, and per-column dtypes.
3. Distinguish single-column Series selection from DataFrame selection.

## 7.3.3 Table Anatomy and Financial Contract

The synthetic fixture represents long-only holdings at one valuation instant. All prices use the same currency and compatible per-unit conventions. Fractional quantities are allowed. Both quantities and prices are nonnegative; zero prices and zero holdings are allowed. There are no trades, distributions, fees, taxes, borrowing, or FX conversion.

| Asset index | quantity: units | price: currency per unit | market_value: currency |
|---|---:|---:|---:|
| ALPHA | 6 | 100 | 600 |
| BETA | 3 | 100 | 300 |
| CASH | 1 | 100 | 100 |

For each asset i, V_i = q_i × p_i. Total market value is sum_i V_i = 1,000. CASH is simply a synthetic instrument identifier; its name does not trigger a special account calculation.

Rows identify assets, while columns identify fields. The completed table has shape (3,3). A DataFrame has two axes even when it contains one row or one column. Its `.size` counts cells; it does not count distinct instruments or nonmissing observations.

## 7.3.4 Construction and Inspection

```python
import pandas as pd
raw = pd.DataFrame(
    {'quantity': [6., 3., 1.], 'price': [100., 100., 100.]},
    index=['ALPHA', 'BETA', 'CASH'],
)
raw.index.name = 'asset'
print(raw.shape)         # (3, 2)
print(raw.columns.tolist())
print(raw.dtypes)
```

A dictionary of lists supplies columns, and each list must match the row count. An explicit index identifies those positions. A dictionary of Series instead allows alignment by the Series indexes; differing coverage can introduce missing cells. Verify the resulting table rather than assuming construction proved completeness.

A DataFrame supports different dtypes in different columns. For example, a separately designed source table might include a currency text column beside numeric quantities. The lab accepts exactly two numeric source columns and rejects extras, including currency. This narrow schema is intentional: common currency is a stated precondition, not an automatically converted field.

Use `.head()` for a preview, `.dtypes` for per-column representation, and `.info()` for a structural summary. A small preview cannot prove that all rows meet the contract. Validation must inspect the relevant full columns.

## 7.3.5 Selection and Result Dimensions

| Expression | Result | Purpose |
|---|---|---|
| `raw['price']` | Series | Select one named column |
| `raw[['price']]` | DataFrame, shape (3,1) | Preserve a two-dimensional table |
| `raw.loc['ALPHA']` | Series for this unique index | Select one labeled row |
| `raw.loc[['ALPHA']]` | DataFrame | Preserve one row as a table |
| `raw.loc['ALPHA','price']` | Scalar | Select a labeled cell |
| `raw.iloc[0,1]` | Scalar | Select a cell by integer positions |
| `raw.loc[:,['price','quantity']]` | DataFrame | Select and order columns explicitly |

These result types depend on the selection and uniqueness contract. Duplicate row or column labels can change expected behavior, so the lab rejects duplicates. Prefer bracket column access over attribute access: a field name can collide with an existing method or attribute.

Section 7.4 develops selection systematically. Here, the essential habit is to know whether the next operation receives a scalar, Series, or DataFrame.

## 7.3.6 Deriving Columns and Financial Units

```python
report = raw.assign(market_value=raw['quantity'] * raw['price'])
large = report.loc[report['market_value'] >= 300,
                   ['quantity', 'price', 'market_value']]
total = report['market_value'].sum(skipna=False)
```

The two selected numeric columns share the table's row index. Elementwise multiplication pairs each quantity with its own price. The resulting currency values can be summed under the common-currency precondition.

Do not sum every numeric column indiscriminately. Quantity, price, and market value have different units. A row-wise total such as `report.sum(axis=1)` would combine incompatible quantities in this table. Selecting the intended measure is part of the mathematics.

`assign` returns a new DataFrame with the specified column added, or replaced if its name already exists. It is not a general schema validator. This component accepts no preexisting derived column: it calculates market_value from validated source fields.

If you later edit quantity or price in the returned report, market_value does not automatically recalculate like a spreadsheet formula. Recompute the derived fields through the calculation function before trusting an updated total.

## 7.3.7 Assignment Aligns a Series by Row Labels

```python
external = pd.Series([10., 20., 30.], index=['CASH','BETA','ALPHA'])
example = raw.assign(check=external)
# ALPHA receives 30, BETA receives 20, CASH receives 10.
```

The assigned Series is aligned by index labels. A plain list of three numbers instead supplies values by position. Converting a Series to an array before assignment discards its label information and changes the relationship being expressed.

If the external Series lacks a row label, assignment can create a missing value for that row. Unexpected external labels may not become new table rows during assignment. Validate expected identities before relying on this mechanism. Do not silently treat missing prices as zero.

The lab's calculation uses columns from one validated table, so it does not need a join. Joining independently sourced holdings and prices is a separate contract covered later in Section 7.12.

The function requires a DataFrame with 1–10,000 rows, a unique flat asset index of trimmed nonempty strings, and exactly the unique columns quantity and price. Input column order may vary; output column order is fixed. Rows retain their input ordering.

Each source column must have an ordinary NumPy-backed integer, unsigned integer, or floating dtype. Text, Boolean, object, complex, and pandas extension dtypes are rejected. Mixed source values may already have lost type information during earlier inference; this is a validated table boundary, not a complete parser for arbitrary raw records.

Source numbers are copied to float64, checked for finite nonnegative values, and multiplied. Both per-asset values and their total must remain finite. The component allows a zero total because it does not derive weights. The row cap is a teaching workload policy, not a guarantee about allocations already made by the caller or peak process memory.

## 7.3.9 Complete Lab — holdings.py

```python
"""Validated single-currency holdings table for one valuation instant."""
import numpy as np
import pandas as pd


def holdings_table(source):
    """Require exactly quantity and price columns; derive market_value.

    Unique flat asset index, long-only quantities, nonnegative prices.
    No FX, fees, cash flows, short positions or exact-decimal accounting.
    """
    if not isinstance(source,pd.DataFrame) or not 1 <= len(source) <= 10_000:
        raise ValueError('DataFrame with 1..10000 rows required')
    if not source.columns.is_unique or set(source.columns) != {'quantity','price'}:
        raise ValueError('exactly quantity and price columns required')
    if isinstance(source.index,pd.MultiIndex) or not source.index.is_unique:
        raise ValueError('unique flat asset index required')
    if any(not isinstance(x,str) or not x or x != x.strip() for x in source.index):
        raise ValueError('trimmed nonempty asset identifiers required')
    data={}
    for name in ('quantity','price'):
        col=source[name]
        if not isinstance(col.dtype,np.dtype) or col.dtype.kind not in 'iuf':
            raise ValueError('ordinary real numeric columns required')
        a=col.to_numpy(dtype=np.float64,copy=True)
        if not np.isfinite(a).all() or np.any(a<0):
            raise ValueError('finite nonnegative values required')
        data[name]=a
    result=pd.DataFrame(data,index=source.index.copy())
    result.index.name='asset'
    try:
        with np.errstate(over='raise',invalid='raise'):
            result=result.assign(market_value=result['quantity']*result['price'])
            total=float(result['market_value'].sum(skipna=False))
    except FloatingPointError as exc:
        raise ValueError('unsupported numerical range') from exc
    if not np.isfinite(result['market_value'].to_numpy()).all() or not np.isfinite(total):
        raise ValueError('nonfinite value or total')
    return result,total


def fixture():
    return pd.DataFrame({'quantity':[6.,3.,1.], 'price':[100.,100.,100.]},
                        index=['ALPHA','BETA','CASH'])

if __name__=='__main__':
    table,total=holdings_table(fixture())
    print(table.to_string(float_format=lambda x:f'{x:.2f}'))
    print(f'Total market value: {total:.2f}')
    print('At least 300: '+', '.join(table.loc[table['market_value']>=300].index))
```

## 7.3.10 Complete Tests — test_holdings.py

```python
import unittest
import numpy as np
import pandas as pd
from holdings import holdings_table,fixture

class HoldingsTests(unittest.TestCase):
    def test_known_values_and_schema(self):
        t,total=holdings_table(fixture())
        self.assertEqual(total,1000)
        np.testing.assert_array_equal(t['market_value'],[600,300,100])
        self.assertEqual(t.shape,(3,3)); self.assertEqual(t.index.name,'asset')
        self.assertEqual(t.columns.tolist(),['quantity','price','market_value'])
        self.assertTrue(all(dtype==np.dtype('float64') for dtype in t.dtypes))

    def test_selection_dimensions(self):
        t,_=holdings_table(fixture())
        self.assertIsInstance(t['price'],pd.Series)
        self.assertIsInstance(t[['price']],pd.DataFrame)
        self.assertEqual(t[['price']].shape,(3,1))
        self.assertEqual(t.loc['ALPHA','market_value'],600)
        self.assertEqual(t.loc[t['market_value']>=300].index.tolist(),['ALPHA','BETA'])

    def test_row_and_column_order(self):
        s=fixture().loc[['CASH','ALPHA','BETA'],['price','quantity']]
        t,total=holdings_table(s)
        self.assertEqual(t.index.tolist(),['CASH','ALPHA','BETA']); self.assertEqual(total,1000)
        self.assertEqual(t.loc['ALPHA','market_value'],600)

    def test_schema_rejections(self):
        for s in [fixture().drop(columns='price'),fixture().assign(currency='USD'),
                  pd.DataFrame([[1,2]],columns=['quantity','quantity'],index=['A'])]:
            with self.assertRaises(ValueError): holdings_table(s)

    def test_identity_and_size_rejections(self):
        for idx in [['A','A','C'],['A',' B','C'],[1,2,3]]:
            s=fixture(); s.index=idx
            with self.assertRaises(ValueError): holdings_table(s)
        for s in [pd.DataFrame(columns=['quantity','price']),
                  pd.DataFrame({'quantity':np.ones(10001),'price':np.ones(10001)})]:
            with self.assertRaises(ValueError): holdings_table(s)

    def test_numeric_rejections_and_zero(self):
        for values in [[-1,2,3],[np.nan,2,3],[np.inf,2,3],['1','2','3'],[True,False,True]]:
            s=fixture(); s['price']=values
            with self.assertRaises(ValueError): holdings_table(s)
        s=fixture()*0; t,total=holdings_table(s)
        self.assertEqual(total,0); self.assertTrue((t['market_value']==0).all())

    def test_overflow_and_scalar_oracle(self):
        s=fixture(); s.loc['ALPHA',['quantity','price']]=[1e308,100]
        with self.assertRaises(ValueError): holdings_table(s)
        s=fixture(); s['price']=[101.5,80.25,1.]
        t,total=holdings_table(s)
        expected=sum(q*p for q,p in zip(s['quantity'],s['price']))
        self.assertAlmostEqual(total,expected)

    def test_input_preservation_and_assignment_alignment(self):
        s=fixture(); before=s.copy(deep=True); t,_=holdings_table(s)
        t.loc['ALPHA','quantity']=99
        pd.testing.assert_frame_equal(s,before)
        extra=pd.Series([10.,20.,30.],index=['CASH','BETA','ALPHA'])
        out=s.assign(check=extra)
        self.assertEqual(out.loc['ALPHA','check'],30)
        self.assertNotIn('check',s.columns)

if __name__=='__main__': unittest.main()
```

## 7.3.12 What the Checks Establish

| Area | Checked behavior |
|---|---|
| Known fixture | Values [600,300,100], total 1000, output schema and float64 columns |
| Selection | Series versus one-column DataFrame, labeled cell and filtered rows |
| Ordering | Reordered inputs preserve asset-level meaning and total |
| Schema | Missing, extra, and duplicate columns rejected |
| Identity and workload | Duplicate/invalid asset labels, empty and oversized tables rejected |
| Numeric domain | Negative, missing, infinite, text, and Boolean prices rejected; zero values allowed |
| Numerical range | Overflow rejected; independent scalar fixture reconciles |
| Ownership and alignment | Input unchanged after report mutation; external Series assignment follows labels |

Validation rejects nonfinite outputs but does not make floating-point arithmetic exact. Large integer conversion may lose precision, tiny products can underflow, and finite results can still have rounding error. The lab is not an exact-cent accounting system. Currency identity and valuation time are preconditions that must be enforced by a wider data workflow.

The returned DataFrame is mutable analysis output. Its independence from the input does not make its derived fields self-maintaining or immutable.

## 7.3.13 Common Mistakes

| Symptom | Likely cause | Action |
|---|---|---|
| A method expects a table but receives a Series | Single brackets selected one column | Use a list of column names when preserving two dimensions |
| Prices appear under wrong assets | Labels were discarded before assignment | Validate identity and retain aligned Series |
| Numeric total mixes units | Aggregated all fields or summed across columns | Select market_value explicitly |
| Derived values become stale | Source columns edited after calculation | Recompute derived columns and total |
| Missing values appear after construction | Series indexes had different coverage | Inspect coverage before calculation |
| Extra currency field is rejected | This component uses an exact narrow schema | Validate currency upstream under the stated contract |
| Existing market_value rejected | Caller supplied a derived field as input | Supply quantity and price and let the function derive values |
