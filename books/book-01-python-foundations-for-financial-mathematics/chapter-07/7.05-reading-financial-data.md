## 7.5.1 Purpose

A successful file read establishes that software interpreted some input. It does not establish that the records describe the expected assets, currency, valuation date, units, or complete holdings population.

This section introduces pandas readers and develops a reproducible local CSV lab. The loader separates text parsing from financial validation, preserves identifiers before numeric conversion, rejects incompatible snapshots, and records a hash of the exact bytes used. File loading and calculation are treated as a connected, inspectable workflow.

## 7.5.2 Learning Objectives

1. Choose a reader according to the source format and contract.
2. Set explicit CSV delimiter, dtype, and missing-token policies.
3. Preserve leading-zero identifiers and literal identifier text.
4. Reject malformed headers, records, duplicate keys, and unsupported numeric tokens.
5. Verify supplied currency and valuation-date expectations.
6. Reconcile loaded holdings with an independent known value.
7. Record source-byte evidence without claiming it proves source correctness.
8. Recognize the boundaries of local, in-memory ingestion.

## 7.5.3 Readers and Source Contracts

| Source | pandas entry point | Decisions before analysis |
|---|---|---|
| CSV or delimited text | `read_csv` | Encoding, delimiter, header, quoting, identifiers and missing tokens |
| Excel workbook | `read_excel` | Workbook engine, sheet, header rows, cell interpretation |
| JSON | `read_json` | Record orientation, nesting and schema |
| Parquet | `read_parquet` | Engine, stored schema and expected fields |
| SQL query | `read_sql_query` | Connection, query, parameter binding and result schema |

These are orientation examples, not executed integrations. Optional dependencies, source access and version-specific settings must be checked for the chosen format. The complete lab uses only a local UTF-8 CSV and needs no credentials or remote service.

A source contract should state one row's meaning, key fields, allowed columns, field types, units, coverage, valuation time and missingness policy. For a holdings snapshot, one row per asset differs from one row per transaction or one row per asset-date. Do not aggregate until that meaning is established.

## 7.5.4 Synthetic CSV Contract

The fixture represents a single long-only snapshot. Each asset has a nonnegative quantity and a nonnegative per-unit price. All rows must match caller-supplied currency USD and calendar label 2026-01-30. Prices and quantities share compatible unit conventions. There are no trades, distributions, fees, FX effects or contract multipliers.

The valuation date is a calendar date, not proof of an exchange close time, timezone or synchronization between sources. The caller supplies expectations independently of the file. Setting expectations to whatever appears in the first record would weaken that check.

| Field | Contract |
|---|---|
| asset | Unique, trimmed, nonempty string; leading zeros preserved |
| quantity | Unsigned ordinary decimal text; zero and fractions allowed |
| price | Same numeric grammar; currency per unit |
| currency | Exact expected uppercase three-letter label |
| valuation_date | Exact expected valid ISO calendar-date string |

The code requires the exact ordered header and rejects extra columns. An uppercase three-letter label passes syntax validation; the code does not verify ISO currency registration. Common currency is checked, not converted.

## 7.5.5 Preserve Text Before Converting Numbers

A generic `pd.read_csv(path)` can infer numeric types and recognize default missing-value tokens. That is convenient for exploration, but potentially wrong for identifiers. A numeric-looking asset identifier such as 00123 must remain text. The identifier NA is literal text in this fixture and must not become missing.

The lab uses `dtype=str`, `keep_default_na=False`, and `na_filter=False` so fields first enter pandas as text without automatic missing-token conversion. Explicit validators then reject empty or invalid numeric fields, while accepting the literal identifier NA. No missing price is replaced by zero.

This is one deliberate policy. Another source might reserve NA as a missing identifier or provide documented null tokens. Set policy from the source contract, rather than copying options without understanding their consequences.

Numeric text in this lab excludes signs, exponents, grouping separators, decimal commas, and surrounding whitespace. Values such as 6, 0 and 0.5 are accepted; 1e2, −1, 1,000 and a blank price are rejected. A different feed can support a broader grammar, but its parsing rules must be explicit and tested. `errors='raise'` avoids silently coercing malformed numbers into missing values.

## 7.5.6 Structural Checks Before pandas Construction

The loader first reads at most 1,000,001 bytes from a local file and rejects snapshots larger than 1,000,000 bytes. It strictly decodes UTF-8 and uses Python's CSV reader to check the original header and each record's field count before pandas parsing.

This preflight matters because a parser can normalize a malformed source into a plausible table. Duplicate header names should be detected at the source boundary, and `on_bad_lines='error'` alone is not a complete schema validator. The preflight rejects both short and long records, blank records, and more than 10,000 data records. A quoted field containing a delimiter is handled by CSV parsing rather than naive string splitting.

The pandas read uses the same in-memory text snapshot. Hashing and parsing therefore refer to the same bytes, rather than separately rereading a changing path. The loader also checks that the two parsers agree on the resulting shape. It is a small local-file workflow, not an arbitrary-format parser or streaming pipeline.

File-access errors, strict UTF-8 decoding errors, CSV syntax errors and pandas conversion errors may propagate as their native exception types. Application-level contract failures raise ValueError. A calling application can handle these categories explicitly without swallowing a failed ingestion.

## 7.5.9 Complete Loader — read_holdings.py

```python
"""Strict small local UTF-8 CSV ingestion for a synthetic snapshot."""
import csv
import hashlib
from io import StringIO
from pathlib import Path
import re
import numpy as np
import pandas as pd

HEADER=['asset','quantity','price','currency','valuation_date']
MAX_BYTES=1_000_000
MAX_ROWS=10_000
NUMBER=re.compile(r'(?:0|[1-9][0-9]*)(?:\.[0-9]+)?\Z')


def load_holdings(path, *, currency, valuation_date):
    """Read local CSV; reject incomplete or incompatible snapshots.

    Numeric grammar: unsigned decimal, no grouping, exponent or whitespace.
    Expected currency/date are explicit strings. Date is a calendar label,
    not an intraday timestamp or exchange close convention.
    """
    if not isinstance(currency,str) or re.fullmatch(r'[A-Z]{3}',currency) is None:
        raise ValueError('expected currency must be three uppercase letters')
    if not isinstance(valuation_date,str) or re.fullmatch(r'\d{4}-\d{2}-\d{2}',valuation_date) is None:
        raise ValueError('expected date must be YYYY-MM-DD')
    from datetime import date
    date.fromisoformat(valuation_date)
    # Bounded read, then hash and parse the same byte snapshot.
    with Path(path).open('rb') as handle:
        payload=handle.read(MAX_BYTES+1)
    if len(payload)>MAX_BYTES:
        raise ValueError('file exceeds byte limit')
    text=payload.decode('utf-8',errors='strict')
    reader=csv.reader(StringIO(text,newline=''),strict=True)
    try:
        header=next(reader)
        if header!=HEADER:
            raise ValueError('exact ordered header required')
        count=0
        for row in reader:
            count+=1
            if count>MAX_ROWS or len(row)!=len(HEADER):
                raise ValueError('row limit or field count violation')
        if not count:
            raise ValueError('at least one record required')
    except StopIteration as exc:
        raise ValueError('header required') from exc
    # Keep identifiers such as 00123 and NA as literal text until validated.
    frame=pd.read_csv(StringIO(text),sep=',',dtype=str,keep_default_na=False,
                      na_filter=False,skip_blank_lines=False,index_col=False,
                      on_bad_lines='error')
    if frame.columns.tolist()!=HEADER or len(frame)!=count:
        raise ValueError('parser shape disagreement')
    asset=frame['asset']
    if asset.duplicated().any() or any(not x or x!=x.strip() for x in asset):
        raise ValueError('unique trimmed nonempty asset identifiers required')
    if not frame['currency'].eq(currency).all():
        raise ValueError('currency differs from expected snapshot')
    if not frame['valuation_date'].eq(valuation_date).all():
        raise ValueError('date differs from expected snapshot')
    for name in ('quantity','price'):
        if not frame[name].map(lambda x:NUMBER.fullmatch(x) is not None).all():
            raise ValueError(f'{name}: unsigned decimal text required')
        frame[name]=pd.to_numeric(frame[name],errors='raise').astype('float64')
        if not np.isfinite(frame[name].to_numpy()).all():
            raise ValueError(f'{name}: finite values required')
    frame=frame.set_index('asset',verify_integrity=True)
    try:
        with np.errstate(over='raise',invalid='raise'):
            frame['market_value']=frame['quantity']*frame['price']
            total=float(frame['market_value'].sum(skipna=False))
    except FloatingPointError as exc:
        raise ValueError('unsupported numerical range') from exc
    if not np.isfinite(frame['market_value'].to_numpy()).all() or not np.isfinite(total):
        raise ValueError('nonfinite valuation')
    evidence={'sha256':hashlib.sha256(payload).hexdigest(),'bytes':len(payload),
              'rows':len(frame),'currency':currency,'valuation_date':valuation_date}
    return frame,total,evidence


if __name__=='__main__':
    path=Path(__file__).with_name('holdings.csv')
    table,total,evidence=load_holdings(path,currency='USD',valuation_date='2026-01-30')
    print(table[['quantity','price','market_value']].to_string(float_format=lambda x:f'{x:.2f}'))
    print(f'Total: {total:.2f} USD')
    print(f'Rows: {evidence["rows"]}; SHA-256: {evidence["sha256"]}')
```

## 7.5.10 Complete Tests — test_read_holdings.py

```python
import hashlib
from pathlib import Path
import tempfile
import unittest
import pandas as pd
from read_holdings import load_holdings,MAX_BYTES,MAX_ROWS

FIXTURE=Path(__file__).with_name('holdings.csv').read_text(encoding='utf-8')

class ReadTests(unittest.TestCase):
    def read(self,text=FIXTURE,**kwargs):
        with tempfile.TemporaryDirectory() as folder:
            path=Path(folder)/'input.csv'; path.write_bytes(text.encode('utf-8'))
            return load_holdings(path,currency=kwargs.get('currency','USD'),
                                 valuation_date=kwargs.get('valuation_date','2026-01-30'))

    def test_known_values_and_identifiers(self):
        t,total,e=self.read()
        self.assertEqual(t.index.tolist(),['00123','BETA','NA'])
        self.assertEqual(total,1000)
        self.assertEqual(t['market_value'].tolist(),[600,300,100])
        self.assertEqual(str(t['quantity'].dtype),'float64')
        self.assertEqual(e['rows'],3)

    def test_snapshot_hash(self):
        _,_,e=self.read()
        self.assertEqual(e['sha256'],hashlib.sha256(FIXTURE.encode()).hexdigest())
        self.assertEqual(e['bytes'],len(FIXTURE.encode()))

    def test_header_and_record_shape(self):
        for text in ['',FIXTURE.splitlines()[0]+'\n',FIXTURE.replace('asset,quantity','quantity,asset',1),
                     FIXTURE.replace('asset,quantity','asset,asset',1),
                     FIXTURE.replace('00123,6,100,','00123,6,100,extra,',1),
                     FIXTURE.replace('00123,6,100,','00123,6,',1),FIXTURE+'\n']:
            with self.subTest(text=text),self.assertRaises(ValueError): self.read(text)

    def test_identity_rejections(self):
        for text in [FIXTURE.replace('BETA','00123'),FIXTURE.replace('BETA',' BETA'),
                     FIXTURE.replace('BETA,',',')]:
            with self.assertRaises(ValueError): self.read(text)

    def test_numeric_rejections(self):
        for token in ['','NA','NaN','inf','-1','1e2',' 6','True','1,000']:
            text=FIXTURE.replace('00123,6,',f'00123,"{token}",',1)
            with self.subTest(token=token),self.assertRaises(ValueError): self.read(text)

    def test_context_rejections(self):
        for text in [FIXTURE.replace('USD','EUR',1),FIXTURE.replace('2026-01-30','2026-01-29',1)]:
            with self.assertRaises(ValueError): self.read(text)
        for context in [dict(currency='usd'),dict(valuation_date='2026-02-30')]:
            with self.assertRaises(ValueError): self.read(**context)

    def test_zero_fraction_and_reordered_rows(self):
        text=FIXTURE.replace('00123,6,','00123,0.5,').replace('BETA,3,','BETA,0,')
        t,total,_=self.read(text)
        self.assertEqual(total,150)
        lines=FIXTURE.splitlines(); reordered='\n'.join([lines[0],*lines[:0:-1]])+'\n'
        other,other_total,_=self.read(reordered)
        self.assertEqual(other.index.tolist(),['NA','BETA','00123']); self.assertEqual(other_total,1000)

    def test_limits_and_overflow(self):
        with self.assertRaises(ValueError): self.read('x'*(MAX_BYTES+1))
        rows=''.join(f'A{i},1,1,USD,2026-01-30\n' for i in range(MAX_ROWS+1))
        with self.assertRaises(ValueError): self.read(FIXTURE.splitlines()[0]+'\n'+rows)
        huge='1'+'0'*200
        text=FIXTURE.replace('00123,6,100,',f'00123,{huge},{huge},')
        with self.assertRaises(ValueError): self.read(text)

if __name__=='__main__': unittest.main()
```

## 7.5.12 What the Checks Establish

| Area | Evidence |
|---|---|
| Known fixture | Preserved identifiers, float64 numeric columns, values and total |
| Snapshot identity | SHA-256 and byte count match the actual test payload |
| Structure | Empty/header-only input, wrong/duplicate header, short/long/blank records rejected |
| Asset identity | Duplicates, surrounding whitespace and empty identifiers rejected |
| Numeric grammar | Blank, missing-looking, infinite, negative, exponent, whitespace, Boolean-looking and grouped text rejected |
| Context | Wrong currency/date and invalid expected calendar date rejected |
| Valid alternatives | Fractional and zero quantities, row reordering accepted |
| Workload/range | Oversized file, excessive rows and extreme numerical input rejected |

The hash identifies a byte sequence; it does not authenticate a vendor, prove economic correctness, or establish a complete holdings universe. The loader checks uniqueness, but has no independently supplied expected asset set. A missing entire record can therefore pass unless a wider workflow checks coverage or control totals.

## 7.5.13 Numerical and Operational Limits

Float64 conversion is approximate. Large integers can lose precision, tiny products can underflow, and huge numeric strings may fail conversion before arithmetic. Per-asset values and the total must be finite; that check alone does not establish cent-exact accounting. This is an analysis pipeline, not a settlement ledger.

The input-byte and row limits bound this teaching snapshot. pandas objects, decoded strings, CSV preflight, conversions and output columns still consume additional memory. Reading a full local snapshot and parsing it twice is appropriate here for clarity; it is not a scaling recommendation for large datasets. A chunked design must additionally enforce cross-chunk key uniqueness, schema consistency and aggregate completeness.

Do not use skipped bad rows to make an ingestion succeed without a documented rejection-report workflow. A partial holdings table can produce a plausible understated total. Retain original source files and recorded expectations when investigating rejected records.

## 7.5.14 Troubleshooting and Exercises

| Symptom | Likely cause | Action |
|---|---|---|
| File not found | Fixture not saved beside script | Check the script-relative path |
| Header rejected | Extra, duplicate, reordered or misspelled field | Verify the original export schema |
| Identifier loses zeros in another workflow | Numeric inference happened upstream | Preserve identifier text at first ingestion |
| Numeric token rejected | Locale, formatting or missingness differs | Define a supported grammar before extending the parser |
| Currency/date mismatch | Export is from another context | Obtain the expected snapshot; do not rewrite context to force acceptance |
| Hash differs but table matches | Bytes or line endings differ | Compare original bytes and recorded provenance |

1. Change 00123 to 00007 and confirm the new identifier stays text.
2. Remove one complete asset record. Explain why uniqueness still passes and what independent coverage evidence is missing.
3. Change one currency or date and inspect the rejection.
4. Put an empty numeric field into the CSV. Explain why zero-filling would change the model.
5. Save an equivalent CRLF fixture and compare its hash with the LF version.
6. Reorder complete records and verify that asset-level values and total are preserved, while the source hash changes.
7. Design an expected-asset-set parameter with missing/extra asset rejection tests before implementing it.
8. Describe how a larger chunked workflow would detect duplicate assets appearing in different chunks.
