## 7.8.1 Purpose

Cleaning financial data means applying documented transformations, validating their results, and retaining evidence about records that cannot be used. It does not mean deleting inconvenient rows until a calculation runs.

This section combines the preceding lessons on reading, conversion and missingness into an auditable local component. It produces accepted records, rejected records and a row-level decision log. An accepted subset is useful for inspection, but it must not be mistaken for a complete portfolio when source records remain unresolved.

## 7.8.2 Learning Objectives

1. Separate approved normalization from correction of unknown facts.
2. Preserve original records and source-row traceability.
3. Detect duplicate keys after normalization.
4. Reject all ambiguous duplicate records rather than picking an arbitrary winner.
5. Validate numeric grammar, domains and currency conventions.
6. Reconcile accepted and rejected record counts with the input.
7. Check repeatability and the stability of normalized accepted content.
8. Explain what further evidence is required before valuation.

## 7.8.3 Cleaning Policy Before Code

The synthetic input is a text DataFrame with exactly four ordered columns: asset, quantity, price and currency. Each record represents one holding at the same valuation instant. The intended model is long-only, common-currency USD, with compatible per-unit prices. There are no fees, trades, distributions, FX conversions or contract multipliers.

| Field | Approved normalization | Validation after normalization |
|---|---|---|
| asset | Strip surrounding whitespace | Nonempty; preserve case and leading zeros; unique across the batch |
| quantity | Strip surrounding whitespace | Unsigned ordinary decimal text; finite value |
| price | Strip surrounding whitespace | Same numeric grammar; finite value |
| currency | Strip surrounding whitespace, then uppercase | Must equal USD |

Trimming is allowed here because the declared source contract says surrounding whitespace is formatting noise. Earlier strict ingestion examples rejected it. These are different explicit boundary policies, not inconsistent descriptions of a pandas requirement.

Asset case remains significant. ALPHA and alpha are distinct identifiers in this lab. Uppercasing every identifier could merge different instruments in another system. Currency uppercasing standardizes spelling; it does not convert EUR values into USD.

No missing price is filled. No negative value is changed to its absolute value. No invalid numeric token is coerced into a usable zero. No unexpected currency is relabeled as USD.

## 7.8.4 Source Identity and Evidence

The component assigns each input record a zero-based source_row ordinal after resetting the DataFrame index. This ordinal locates a record within this exact input ordering, even if the original index contains duplicates. It is not a global transaction identifier or physical CSV line number.

Retain the original input alongside the outputs. The rejection report preserves its original field tokens, normalized asset identifier and reason codes. The decision log records source_row, whether any field changed during normalization, acceptance status and reasons. Accepted records retain source_row and normalized typed fields.

For a persisted workflow, combine this local ordinal with a source-file hash or batch identifier, such as the byte evidence from Section 7.5. Reordering the input changes local ordinals. Do not treat the same ordinal from a different file as the same source record.

The row-level changed flag identifies that normalization occurred; it is not a field-by-field before/after log. The retained raw input lets a reviewer reconstruct those differences. More detailed change logging is an appropriate extension.

## 7.8.5 Duplicate Keys After Normalization

Two records named BETA and space-padded BETA become the same normalized identifier. Duplicate detection must therefore follow the approved key normalization.

```python
duplicate = normalized.duplicated(subset=['asset'], keep=False)
```

`keep=False` flags every occurrence of the duplicated asset, including the first. The lab rejects all records for that key. One of those rows may also have another error; that does not allow a competing row to become an unreviewed winner.

`drop_duplicates(keep='last')` would encode an ordering-based selection policy. Input order alone does not prove that a record is newer, authoritative or corrected. A source with revision numbers or event timestamps could define a precedence rule, but the rule and conflict behavior must be tested explicitly.

A real position system may legitimately have multiple lots per asset. In that case, asset alone is not the correct key. Define the record grain, such as account, instrument and lot, before deciding which records are duplicates. The one-row-per-asset rule belongs to this fixture.

Two rows change during normalization: 0 and 2. Accepted values are ALPHA 600 and CASH 100. Their sum, 700, is only the accepted subset's value. The executable deliberately does not publish a portfolio total, because four source records remain unresolved.

The required count identity is input rows = accepted rows + rejected rows. Each input ordinal also appears exactly once in the decision log. A rejected row can have multiple reason codes, so the number of reason occurrences can exceed the number of rejected records.

Even zero rejections would not prove portfolio completeness: an entire missing record cannot be identified without an independently expected population or control total. The displayed readiness flag means only that this batch has no rejected rows under these local rules. It is not an economic certification.

## 7.8.7 Numerical and Input Contract

Input contains 1–10,000 rows. Every cell must already be a string of at most 64 characters. Wrong schema, duplicate column names, nonstring cells and structural size violations fail the entire call rather than generating per-record rejection reports. The component expects parsed text, not an arbitrary file reader.

Quantity and price accept zero or an unsigned ordinary decimal without signs, grouping separators, exponent notation or redundant leading zeros. Accepted values are converted to float64. Invalid tokens receive stable reason codes. Nonfinite derived values are rejected. With the 64-character token limit, enormous exponent notation is already outside the supported source language.

Float64 is approximate; tiny products can underflow and large integer conversions can lose precision. This lab does not provide exact-cent accounting or unrestricted numerical-range support. Zero is allowed, but an empty token is invalid. These are independent data states.

The output tables are mutable analysis artifacts. Market_value is calculated once; later edits do not update it automatically. No changes are made to the source DataFrame. The row/cell limits are teaching workload policies, not a peak-memory guarantee.

## 7.8.9 Complete Cleaner — cleaning.py

```python
"""Audited, bounded cleaning of text holdings records."""
import re
import numpy as np
import pandas as pd

FIELDS=['asset','quantity','price','currency']
DECIMAL=re.compile(r'(?:0|[1-9][0-9]*)(?:\.[0-9]+)?\Z')


def clean(raw):
    """Trim fields and uppercase currency under this explicit source contract.

    Asset case is significant. Any normalized duplicate asset quarantines all
    of its rows, even when one row has another error. No aggregate is returned.
    Source_row is a zero-based ordinal within this input, not a global key.
    """
    if not isinstance(raw,pd.DataFrame) or not 1<=len(raw)<=10_000:
        raise ValueError('DataFrame with 1..10000 rows required')
    if not raw.columns.is_unique or raw.columns.tolist()!=FIELDS:
        raise ValueError('exact ordered source fields required')
    for c in FIELDS:
        if not raw[c].map(lambda x:isinstance(x,str) and len(x)<=64).all():
            raise ValueError('source cells must be strings of at most 64 characters')
    source=raw.reset_index(drop=True).copy(deep=True)
    normalized=source.apply(lambda col:col.str.strip())
    normalized['currency']=normalized['currency'].str.upper()
    changed=(normalized!=source).any(axis=1)
    duplicates=normalized.duplicated(subset=['asset'],keep=False)
    accepted=[]; rejected=[]; audit=[]
    for i,row in normalized.iterrows():
        reasons=[]; numbers={}
        if not row['asset']: reasons.append('empty_asset')
        if duplicates.loc[i]: reasons.append('duplicate_asset')
        if row['currency']!='USD': reasons.append('unsupported_currency')
        for name in ('quantity','price'):
            text=row[name]
            if not DECIMAL.fullmatch(text):
                reasons.append('invalid_'+name)
            else:
                number=float(text)
                if not np.isfinite(number): reasons.append('nonfinite_'+name)
                else: numbers[name]=number
        if not reasons:
            with np.errstate(over='ignore',invalid='ignore'):
                value=np.float64(numbers['quantity'])*np.float64(numbers['price'])
            if not np.isfinite(value): reasons.append('nonfinite_value')
        status='rejected' if reasons else 'accepted'
        reason=';'.join(reasons)
        audit.append({'source_row':i,'changed':bool(changed.loc[i]),'status':status,'reason':reason})
        if reasons:
            rejected.append({'source_row':i,**source.loc[i].to_dict(),
                             'normalized_asset':row['asset'],'reason':reason})
        else:
            accepted.append({'source_row':i,'asset':row['asset'],**numbers,
                             'currency':row['currency'],'market_value':float(value)})
    good=pd.DataFrame(accepted,columns=['source_row',*FIELDS,'market_value'])
    bad=pd.DataFrame(rejected,columns=['source_row',*FIELDS,'normalized_asset','reason'])
    log=pd.DataFrame(audit)
    assert len(good)+len(bad)==len(source)
    assert log['source_row'].is_unique
    return good,bad,log


def fixture():
    return pd.DataFrame([
        [' ALPHA ','6','100',' usd '], ['BETA','3','100','USD'],
        [' BETA ','3','101','USD'], ['CASH','1','100','USD'],
        ['BAD','1','oops','USD'], ['EURO','1','100','EUR'],
    ],columns=FIELDS)

if __name__=='__main__':
    good,bad,log=clean(fixture())
    print(f'Input={len(log)}; accepted={len(good)}; rejected={len(bad)}')
    print('Accepted assets: '+', '.join(good['asset']))
    print(f'Changed rows: {int(log["changed"].sum())}')
    print('Batch valuation ready: '+str(bad.empty))
```

The two final assertions document internal accounting invariants. They are not replacements for input validation; Python can disable assertions with optimization. Source-contract violations above are handled with explicit checks or record-level reasons.

## 7.8.10 Complete Tests — test_cleaning.py

```python
import unittest
import pandas as pd
from cleaning import clean,fixture,FIELDS

class CleaningTests(unittest.TestCase):
    def test_fixture_and_conservation(self):
        good,bad,log=clean(fixture())
        self.assertEqual((len(good),len(bad),len(log)),(2,4,6))
        self.assertEqual(good['asset'].tolist(),['ALPHA','CASH'])
        self.assertEqual(good['market_value'].tolist(),[600,100])
        self.assertEqual(int(log['changed'].sum()),2)
        self.assertEqual(sorted(good['source_row'].tolist()+bad['source_row'].tolist()),list(range(6)))

    def test_all_duplicates_rejected(self):
        good,bad,_=clean(fixture())
        duplicate=bad.loc[bad['reason'].str.contains('duplicate_asset')]
        self.assertEqual(duplicate['source_row'].tolist(),[1,2])
        raw=pd.DataFrame([['A','1','oops','USD'],[' A ','1','100','USD']],columns=FIELDS)
        self.assertTrue(clean(raw)[0].empty)

    def test_original_tokens_and_multiple_reasons(self):
        raw=pd.DataFrame([[' A ','-1','bad','eur']],columns=FIELDS)
        good,bad,log=clean(raw)
        self.assertTrue(good.empty); self.assertEqual(bad.loc[0,'asset'],' A ')
        self.assertEqual(bad.loc[0,'normalized_asset'],'A')
        self.assertEqual(bad.loc[0,'reason'],'unsupported_currency;invalid_quantity;invalid_price')

    def test_valid_zero_fraction_and_case(self):
        raw=pd.DataFrame([['00123','0.5','100','usd'],['NA','0','0','USD'],
                          ['alpha','1','2','USD'],['ALPHA','1','2','USD']],columns=FIELDS)
        good,bad,_=clean(raw)
        self.assertTrue(bad.empty); self.assertEqual(good['asset'].tolist(),raw['asset'].tolist())
        self.assertEqual(good['market_value'].tolist(),[50,0,2,2])

    def test_schema_and_cell_type(self):
        for r in [fixture().drop(columns='price'),fixture().iloc[:0],fixture().assign(extra='x')]:
            with self.assertRaises(ValueError): clean(r)
        r=fixture(); r['price']=[1,2,3,4,5,6]
        with self.assertRaises(ValueError): clean(r)

    def test_invalid_fields(self):
        raw=pd.DataFrame([['','1','100','USD'],['A','1e2','100','USD'],
                          ['B','1','','USD'],['C','1','inf','USD']],columns=FIELDS)
        good,bad,_=clean(raw)
        self.assertTrue(good.empty); self.assertEqual(len(bad),4)

    def test_source_preservation_and_local_ordinals(self):
        raw=fixture(); raw.index=[7,7,8,8,9,9]; before=raw.copy(deep=True)
        good,bad,log=clean(raw)
        self.assertEqual(log['source_row'].tolist(),list(range(6)))
        good.loc[0,'price']=0
        pd.testing.assert_frame_equal(raw,before)

    def test_repeatable_and_idempotent_normalization(self):
        raw=fixture(); a=clean(raw); b=clean(raw)
        for x,y in zip(a,b): pd.testing.assert_frame_equal(x,y)
        # Reprocess accepted source fields; compare content, not original ordinals.
        good=clean(raw)[0]; reclean,bad,log=clean(good[FIELDS].astype(str))
        self.assertTrue(bad.empty); self.assertFalse(log['changed'].any())
        pd.testing.assert_frame_equal(good[FIELDS].reset_index(drop=True),
                                      reclean[FIELDS].reset_index(drop=True))

if __name__=='__main__': unittest.main()
```

## 7.8.12 Verification and Repeatability

| Area | Checked behavior |
|---|---|
| Fixture and conservation | 2 accepted + 4 rejected = 6 input rows; expected accepted values |
| Duplicate policy | Both normalized duplicate records rejected, including when another error is present |
| Evidence | Original tokens retained; multiple reason codes preserved |
| Valid alternatives | Zero/fractional quantities, leading-zero/NA identifiers and case-sensitive assets accepted |
| Structural contract | Wrong schema, empty input and numeric source objects rejected |
| Field rejection | Empty asset, exponent quantity, blank and infinite-looking prices rejected |
| Ownership and identity | Raw input preserved; local ordinals independent of duplicate source indexes |
| Stability | Same input produces identical outputs; normalized accepted content survives a separate reprocessing check |

The reprocessing test selects accepted source fields and explicitly converts them back to text before invoking the text-boundary cleaner again. It compares normalized content, not original ordinals, because the accepted subset becomes a new local batch. This is a limited normalization-stability check, not a claim that every output table is directly accepted as input or that provenance remains identical across batches.

## 7.8.13 Troubleshooting

| Symptom | Likely explanation | Action |
|---|---|---|
| Valid-looking row rejected as duplicate | Another row has the same normalized key | Review all source records for that key |
| Changed row is still rejected | Formatting normalization did not resolve a semantic error | Inspect reason codes; do not confuse changed with repaired |
| Accepted value differs from a full control total | Rejected or entirely absent records remain | Reconcile population and source controls before valuation |
| Entire call fails | Structural contract violated | Fix the parser/schema boundary before row cleaning |
| Asset case produces separate rows | Case sensitivity is explicit in this fixture | Consult the identifier system before adding normalization |
| Reprocessing has different source_row values | A subset became a new local input | Preserve original batch identity and ordinal separately |
