## 7.10.1 Purpose

Sorting changes presentation order; filtering changes the population retained for analysis. Query expressions offer another way to express row conditions. Each operation needs an explicit contract so that a plausible report does not conceal dropped records, arbitrary tie resolution, or a changed financial question.

This section creates a deterministic reporting screen for a synthetic common-currency holdings snapshot. It validates all source rows, selects a sector and inclusive minimum market value, orders eligible rows by market value and asset, and limits the displayed result. It verifies equivalent selection through a Boolean mask and a fixed query expression.

## 7.10.2 Learning Objectives

1. Distinguish sorting labels from sorting field values.
2. Define sort direction and deterministic tie-breaking.
3. Combine Boolean conditions with deliberate boundary rules.
4. Express an equivalent fixed query using local variables.
5. Distinguish row predicates from DataFrame.filter label selection.
6. Apply eligibility before limiting report rows.
7. Preserve source identifiers and report population counts.
8. Test order independence, empty results and full-input validation.

## 7.10.3 Financial Snapshot and Screen Contract

|---|---|---:|
| BETA | equity | 600 |
| ALPHA | equity | 600 |
| CASH | cash | 100 |
| GAMMA | equity | 300 |

These supplied synthetic market values represent nonnegative exposures at one valuation instant, with one common currency and compatible valuation conventions. The component does not calculate holdings value, convert currencies, validate price provenance or measure return. Sector labels are exact source categories, not a verified security classification system.

The default reporting rule is sector equal to equity and market_value greater than or equal to 300. Eligible assets are BETA, ALPHA and GAMMA. Sort by market_value descending, then asset ascending, and return at most two records: ALPHA and BETA.

This subset is a report, not the whole portfolio or an investment recommendation. Selecting large positions does not make their sum a full-portfolio control total. A future trading screen would additionally need decision-time availability, universe definition and a separate economic rationale.

## 7.10.4 Sort Labels or Sort Values?

`sort_index()` orders axis labels. A default integer index may simply reflect original row positions; sorting it does not rank exposures.

`sort_values()` orders by one or more fields:

```python
ranked = eligible.sort_values(
    ['market_value', 'asset'], ascending=[False, True]
)
```

Descending market value puts the largest exposure first. Ascending asset order provides an explicit secondary key for equal values. Assets are unique under the input contract, so the complete key determines a unique row order independently of source ordering.

A stable single-key sort retains input order among ties, which can be useful, but stability alone does not make a result independent of input order. Use an explicit final unique tie-breaker when that is the report requirement. Do not assume a sort algorithm option controls all multi-column behavior identically.

String ordering is not a financial ranking. This lab uses case-sensitive identifier spelling under pandas ordering, not locale-aware display collation. Numeric-looking text also sorts differently from numeric values; validate dtypes before ranking.

## 7.10.5 Boolean Filtering and Boundary Rules

```python
mask = (table['market_value'] >= floor) & table['sector'].eq(sector)
eligible = table.loc[mask]
```

The floor is inclusive, so GAMMA at exactly 300 qualifies. Use `>` instead only if exclusion of the boundary is intentional. Parentheses keep elementwise conditions clear; use `&`, `|` and `~` for conjunction, disjunction and negation of Boolean conditions.

A condition derived from this same table carries its corresponding index. An externally supplied mask needs the identity and alignment checks developed in Section 7.4. Missing inputs can also produce false or unknown comparisons. This component rejects missing market values and invalid category text before filtering, rather than silently excluding incomplete records.

For membership, a Series method such as `table['sector'].isin(['equity','bond'])` expresses a category list. The complete function below deliberately accepts one exact sector so its input and evidence remain simple.

## 7.10.6 Query Expressions and Local Values

The equivalent fixed expression is:

```python
eligible_query = table.query(
    'market_value >= @floor and sector == @sector',
    local_dict={'floor': floor, 'sector': sector},
    engine='python',
)
```

The @ prefix references supplied local values rather than a column with that name. The code keeps the expression authored and fixed, validates parameter types, and never interpolates input into expression text. Query is an expression-evaluation facility, not a sandbox for arbitrary user-provided expressions. Do not expose free-form query text as an untrusted reporting parameter.

For a column containing spaces, backticks can identify it in an authored expression, such as `` `market value` >= @cutoff ``. The test demonstrates that syntax. Ordinary bracket selection is often clearer when names or conditions are complex.

The lab specifies engine='python' to avoid depending on optional numeric expression acceleration. It asserts frame equality between the mask and query results before ranking. This demonstrates semantic agreement for validated fixtures, not a universal claim that every pandas query parser expression has identical Python operator rules or that one method is faster.

## 7.10.7 DataFrame.filter Is Label Selection

```python
columns_only = table.filter(items=['asset'])
```

This selects a named column; it does not apply a row predicate such as market_value >= 300. The word filter in the method name can obscure this distinction. Use `.loc[mask]` or a fixed `.query(...)` for the row conditions in this section.

Selecting columns is still useful after a row screen, for example to produce an asset/value report. Preserve keys needed to identify records and avoid discarding lineage merely to make a table compact.

## 7.10.8 Filter, Rank, Then Limit

For this report, the operation order is validate → filter eligible population → rank eligible rows → limit output. Taking head first can exclude eligible assets that appeared later in the source. Selecting the largest values globally and then filtering can omit a qualifying lower-ranked sector member because other sectors consumed the initial slots.

The evidence reports input_rows, eligible_rows and returned_rows, plus the floor, sector and limit. The default fixture has 5 input rows, 3 eligible rows and 2 returned rows. These counts distinguish the screen's eligibility rule from display truncation.

The limit is a maximum, not a promise to return that many records. A no-match screen returns an empty DataFrame with the same columns. It does not pad the report with zero-valued records or treat an empty report as a zero-valued portfolio.

At the cutoff, the unique asset tie-breaker determines which tied row appears first. A rule that includes every tie at a rank boundary would be a different report contract and might return more than the requested maximum.

## 7.10.9 Validation and Environment

The component accepts 1–10,000 rows with exactly the ordered columns asset, sector and market_value. Asset and sector fields must be trimmed nonempty strings of at most 64 characters; asset identifiers must be unique. The source index is retained for traceability but is not the financial key. Duplicate source index labels are not prohibited; do not use them as unique record identities.

Market values must have an ordinary NumPy-backed real numeric dtype, be finite and nonnegative. This input boundary rejects nullable extension types, numeric strings and Boolean columns. The floor must be a finite nonnegative real number, the sector a validated text value, and the limit an integer from 1 to 10,000. Boolean floor/limit values are rejected explicitly.

All source rows are validated before eligibility filtering, including rows from sectors that will not be selected. Invalid records must not disappear simply because a reporting condition hides them. Row limits are teaching workload policies, not peak-memory guarantees. The copied report remains approximate numeric analysis data, not exact-decimal accounting.

## 7.10.10 Complete Screen — screen.py

```python
"""Deterministic reporting screen for one common-currency snapshot."""
import numbers
import numpy as np
import pandas as pd


def screen(raw, *, floor=300., sector='equity', limit=2):
    """Validate all rows, filter eligibility, sort value descending/asset ascending.

    This is a reporting subset, not portfolio performance or a trading strategy.
    Market values are supplied observations; no holdings valuation is performed.
    """
    if not isinstance(raw,pd.DataFrame) or not 1<=len(raw)<=10_000:
        raise ValueError('DataFrame with 1..10000 rows required')
    if not raw.columns.is_unique or raw.columns.tolist()!=['asset','sector','market_value']:
        raise ValueError('exact ordered schema required')
    for col in ('asset','sector'):
        if not raw[col].map(lambda x:isinstance(x,str) and 0<len(x)<=64 and x==x.strip()).all():
            raise ValueError('trimmed nonempty text required')
    if raw['asset'].duplicated().any(): raise ValueError('duplicate asset')
    value=raw['market_value']
    if not isinstance(value.dtype,np.dtype) or value.dtype.kind not in 'iuf':
        raise ValueError('ordinary real numeric market values required')
    if not np.isfinite(value.to_numpy()).all() or (value<0).any():
        raise ValueError('finite nonnegative market values required')
    if isinstance(floor,bool) or not isinstance(floor,numbers.Real) or not np.isfinite(floor) or floor<0:
        raise ValueError('finite nonnegative floor required')
    if not isinstance(sector,str) or not sector or len(sector)>64 or sector!=sector.strip():
        raise ValueError('trimmed sector string required')
    if isinstance(limit,bool) or not isinstance(limit,numbers.Integral) or not 1<=limit<=10_000:
        raise ValueError('limit must be an integer from 1 to 10000')
    table=raw.copy(deep=True)
    mask=(table['market_value']>=floor)&table['sector'].eq(sector)
    selected=table.loc[mask]
    # Fixed authored expression; only validated values enter local variables.
    equivalent=table.query('market_value >= @floor and sector == @sector',
                           local_dict={'floor':floor,'sector':sector},engine='python')
    pd.testing.assert_frame_equal(selected,equivalent)
    ranked=selected.sort_values(['market_value','asset'],ascending=[False,True])
    result=ranked.head(int(limit)).copy(deep=True)
    evidence={'input_rows':len(table),'eligible_rows':len(selected),'returned_rows':len(result),
              'floor':float(floor),'sector':sector,'limit':int(limit)}
    return result,evidence


def fixture():
    return pd.DataFrame({'asset':['BETA','ALPHA','CASH','GAMMA','DELTA'],
                         'sector':['equity','equity','cash','equity','bond'],
                         'market_value':[600.,600.,100.,300.,800.]})

if __name__=='__main__':
    result,evidence=screen(fixture())
    print(result.to_string(index=False,float_format=lambda x:f'{x:.2f}'))
    print(f'Eligible={evidence["eligible_rows"]}; returned={evidence["returned_rows"]}')
```

## 7.10.11 Complete Tests — test_screen.py

```python
import unittest
import numpy as np
import pandas as pd
from screen import screen,fixture

class ScreenTests(unittest.TestCase):
    def test_known_answer_and_counts(self):
        r,e=screen(fixture())
        self.assertEqual(r['asset'].tolist(),['ALPHA','BETA'])
        self.assertEqual((e['input_rows'],e['eligible_rows'],e['returned_rows']),(5,3,2))

    def test_permutation_and_tie_break(self):
        a,_=screen(fixture()); b,_=screen(fixture().iloc[::-1])
        pd.testing.assert_frame_equal(a.reset_index(drop=True),b.reset_index(drop=True))
        self.assertEqual(screen(fixture(),limit=1)[0]['asset'].tolist(),['ALPHA'])

    def test_inclusive_floor_and_filter_before_head(self):
        r,_=screen(fixture(),floor=300,limit=10)
        self.assertEqual(r['asset'].tolist(),['ALPHA','BETA','GAMMA'])
        self.assertEqual(screen(fixture(),sector='bond',limit=1)[0]['asset'].tolist(),['DELTA'])

    def test_no_match_preserves_schema(self):
        r,e=screen(fixture(),sector='unknown')
        self.assertTrue(r.empty); self.assertEqual(e['eligible_rows'],0)
        self.assertEqual(r.columns.tolist(),fixture().columns.tolist())

    def test_parameter_rejections(self):
        for change in [dict(floor=np.nan),dict(floor=-1),dict(floor=True),dict(floor='300'),
                       dict(limit=0),dict(limit=1.5),dict(limit=True),dict(sector=' equity')]:
            with self.subTest(change=change),self.assertRaises(ValueError): screen(fixture(),**change)

    def test_full_input_validation(self):
        for values in [[600,600,100,300,np.inf],[600,600,100,300,-1]]:
            raw=fixture(); raw['market_value']=values
            with self.assertRaises(ValueError): screen(raw)
        raw=fixture(); raw.loc[1,'asset']='BETA'
        with self.assertRaises(ValueError): screen(raw)
        with self.assertRaises(ValueError): screen(fixture().assign(extra=1))

    def test_input_copy_and_index(self):
        raw=fixture(); before=raw.copy(deep=True); r,_=screen(raw)
        self.assertEqual(r.index.tolist(),[1,0])
        r.loc[1,'market_value']=0; pd.testing.assert_frame_equal(raw,before)

    def test_sort_and_query_mechanics(self):
        raw=fixture()
        self.assertEqual(raw.sort_index().index.tolist(),[0,1,2,3,4])
        # DataFrame.filter selects column labels here, not rows by a numeric condition.
        self.assertEqual(raw.filter(items=['asset']).shape,(5,1))
        spaced=raw.rename(columns={'market_value':'market value'}); cutoff=600
        q=spaced.query('`market value` >= @cutoff',engine='python')
        self.assertEqual(q['asset'].tolist(),['BETA','ALPHA','DELTA'])
        s=pd.Series([2.,np.nan,1.]).sort_values(na_position='last')
        self.assertTrue(pd.isna(s.iloc[-1]))

if __name__=='__main__': unittest.main()
```

## 7.10.13 Verification and Troubleshooting

| Area | Checked behavior |
|---|---|
| Known fixture | ALPHA/BETA output; 5 input, 3 eligible, 2 returned |
| Ties | Reversing source order preserves output content/order; limit one returns ALPHA |
| Boundaries | Floor includes GAMMA at 300; bond selection finds DELTA before limiting |
| Empty result | Unknown sector yields an empty report with preserved schema |
| Parameters | Invalid floor, limit and sector values rejected |
| Full source | Invalid unselected value, duplicate asset and extra field rejected |
| Ownership | Source index retained; report mutation does not alter input |
| API mechanics | Label filtering, spaced-column query and missing-last sort demonstrated |

`na_position='last'` controls where missing sort values appear; it does not make those values valid. The public component rejects them before sorting. The separate mechanical test illustrates the option without weakening the report's source contract.

| Symptom | Likely cause | Action |
|---|---|---|
| Equal-value rows change order between files | No deterministic final key | Add an explicit unique tie-breaker |
| Eligible records disappear | Limit applied before eligibility | Filter the full validated population first |
| Numeric-looking values rank strangely | Values still stored as text | Parse and validate upstream |
| filter returns a column subset | Used label-selection method for a predicate | Use loc with a Boolean mask or fixed query |
| Empty report interpreted as zero holdings | Screen result confused with full population | Retain criteria and counts; report no matches |
| Query input behaves unexpectedly | Expression text assembled dynamically | Keep expressions authored and validate value parameters |
