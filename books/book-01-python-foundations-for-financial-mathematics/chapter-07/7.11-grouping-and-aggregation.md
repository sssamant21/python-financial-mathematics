## 7.11.1 Purpose

Grouping summarizes records according to a shared key, such as sector, account or instrument. The difficult financial question is often what may be combined and which denominator makes the summary meaningful.

This section aggregates one complete long-only snapshot by sector. It reconciles asset counts, opening values, price-only profit/loss and portfolio return contributions. It also distinguishes a sector's own weighted return from its contribution to the entire portfolio, and preserves an undefined return for a sector with no opening value.

## 7.11.3 Record Grain and Financial Assumptions

The synthetic input contains one record per asset. Each asset belongs to exactly one sector under the supplied classification. Opening values are nonnegative and share one currency and valuation instant. Simple asset price returns cover one common interval. There are no trades, cash flows, distributions, fees, taxes, FX changes or rebalancing.

| Asset | Sector | Opening value | Asset price return | Price-only P&L |
|---|---|---:|---:|---:|
| ALPHA | equity | 600 | 0.10 | 60 |
| BETA | equity | 300 | −0.05 | −15 |
| CASH | cash | 100 | 0.00 | 0 |
| ZERO | unused | 0 | 0.20 | 0 |

Total opening value is 1,000. Total price-only P&L is 45. Portfolio price return is 45/1,000 = 4.50%. The supplied return on ZERO is observed, but there was no opening exposure to that asset.

Grouping does not validate sector classifications, currency conventions, observation availability or the completeness of the asset universe. Those remain source-contract requirements. Multiple accounts, dates or currencies would require additional keys or separate processing; merging them under sector alone could combine incompatible populations.

## 7.11.4 Split, Apply, Combine

```python
grouped = table.groupby('sector', sort=True, dropna=False, observed=True)
report = grouped.agg(
    asset_count=('asset', 'size'),
    opening_value=('opening_value', 'sum'),
    price_pnl=('price_pnl', 'sum'),
)
```

The grouping key partitions records. Named aggregation specifies both the source measure and the operation, producing a report with sector labels as its index. This makes the output meaning clearer than aggregating every numeric field indiscriminately.

`sort=True` controls group-key ordering in the report; it is not a within-sector value ranking. `dropna=False` retains a missing-key group in general pandas usage. The public component rejects missing keys first, but still states the option explicitly. `observed=True` makes the observed-category policy explicit should categorical grouping be introduced; this fixture supplies ordinary strings.

An unused category declared in a categorical vocabulary is different from the actual row labeled unused in this fixture. The latter is an observed sector whose value happens to be zero.

## 7.11.5 Units and Denominators

For asset i, opening value V_i and price return r_i give price-only P&L_i = V_i × r_i. Under the stated fixed-exposure assumptions, this is a currency change in value.

For sector g:

- Sector opening value: V_g = sum of its asset opening values.
- Sector price-only P&L: P_g = sum of its asset P&L.
- Sector portfolio weight: W_g = V_g / V_total.
- Sector return: R_g = P_g / V_g, defined only for V_g > 0.
- Contribution to portfolio return: C_g = P_g / V_total.

Equity has opening value 900 and P&L 45, so its weighted sector return is 5.00%. Its portfolio weight is 90%, and its contribution is 4.50 percentage points. A contribution of 0.045 is dimensionless; it is not 45 currency units, even though both numbers arise in this fixture.

The simple mean of equity's asset returns is (10% − 5%)/2 = 2.50%. That mean gives equal importance to the two asset records, while opening-value weighting gives twice as much exposure to ALPHA. A group mean is not automatically a sector investment return.

Sector contributions sum directly to portfolio return. Sector returns generally do not. For invested sectors, W_g × R_g = C_g. Avoid evaluating 0×undefined as though it were a valid reconciliation route for zero-valued groups; use the directly calculated contributions.

## 7.11.6 Zero Values and Complete Data

A zero-opening-value sector remains visible in the report. Its P&L and portfolio contribution are zero, while its own return is NaN because its denominator is zero. The code masks that denominator deliberately rather than replacing the return with zero.

An all-zero portfolio is rejected because the portfolio return denominator must be positive. This differs from a holdings-value constructor, which may validly represent a zero-valued snapshot without calculating returns.

All numeric inputs must be observed and finite before aggregation. Even a missing return on a zero-valued asset is rejected under this strict complete-input policy. A separate missing-data reporting workflow can preserve incomplete records as in Section 7.7; it must not silently omit them to make a grouped return appear complete.

Group sums normally have missing-value behavior that may skip unknown observations. `min_count=1` can avoid converting an all-missing group sum into zero, but it does not establish complete asset coverage. The lab validates the complete source first, so named sum aggregation has no missing observations to skip.

## 7.11.7 Size, Count and Missing Keys

Group size counts records. Count on a selected measure counts its nonmissing values. They agree for a complete field, but can differ when observations are missing.

```python
example = pd.DataFrame({'sector':['equity',None,'equity'],
                        'value':[10.,20.,float('nan')]})
with_missing_key = example.groupby('sector', dropna=False)
```

This general demonstration has three total grouped records but only two observed numeric values. With the default missing-key exclusion, only two records enter groups. The mechanical test shows these differences; the validated public function rejects that incomplete input.

A missing key can conceal exposure from a report if it is dropped before reconciliation. Check grouped record counts against the validated source and define whether unknown classification is rejected or explicitly represented as a category. Relabeling unknown classifications without preserving evidence is a separate transformation policy.

## 7.11.8 Aggregation Versus Transformation

Aggregation reduces each group to summary rows. Transformation can broadcast a group result back onto the original row axis:

```python
sector_values = table.groupby('sector')['opening_value'].transform('sum')
```

For the fixture, this produces [900,900,100,0] aligned to the original asset rows. It is useful for row-level shares or comparisons within sectors. Summing this repeated vector would double-count the equity sector total, so it is not a grouped summary table.

Use built-in aggregations for these sums and counts rather than a custom apply function that obscures shapes and missingness. More complex group operations may need custom logic, but should retain explicit keys, units, expected result shape and tests. No performance benchmark is claimed here.

## 7.11.9 Reconciliation and Numerical Policy

Required checks include:

- Sum of grouped asset_count equals the input row count.
- Sum of grouped opening_value agrees with portfolio opening value.
- Sum of grouped price_pnl agrees with asset-level P&L.
- Sum of sector portfolio weights agrees with one.
- Sum of sector portfolio contributions agrees with portfolio return.

The independent scalar test calculates portfolio return from Python lists, not from the group report itself. Small fixture comparisons use appropriate floating-point tolerance through almost-equal checks. Exact equality in integer-like fixture totals is not a universal policy for all financial scales.

The public function copies numeric columns to float64 and rejects nonfinite invested-sector output or portfolio return. Overflow is rejected; small products can still underflow and ordinary rounding remains. The intended NaN for a zero-value sector is checked separately from required finite outputs. This is approximate analytical arithmetic, not exact-decimal settlement accounting.

## 7.11.11 Complete Aggregation — grouping.py

```python
"""Sector aggregation for a complete, common-interval long-only snapshot."""
import numpy as np
import pandas as pd


def summarize(raw):
    """Return sector report and portfolio price return; no flows/fees/FX.

    opening_value is common-currency opening exposure. Asset returns share
    one interval. Zero-value sectors remain visible with undefined return.
    """
    if not isinstance(raw,pd.DataFrame) or not 1<=len(raw)<=10_000:
        raise ValueError('DataFrame with 1..10000 rows required')
    if not raw.columns.is_unique or raw.columns.tolist()!=['asset','sector','opening_value','asset_return']:
        raise ValueError('exact ordered schema required')
    for c in ('asset','sector'):
        if not raw[c].map(lambda x:isinstance(x,str) and 0<len(x)<=64 and x==x.strip()).all():
            raise ValueError('complete trimmed asset and sector strings required')
    if raw['asset'].duplicated().any(): raise ValueError('one record per asset required')
    t=raw.reset_index(drop=True).copy(deep=True)
    for c in ('opening_value','asset_return'):
        if not isinstance(t[c].dtype,np.dtype) or t[c].dtype.kind not in 'iuf':
            raise ValueError('ordinary real numeric columns required')
        t[c]=t[c].astype('float64')
        if not np.isfinite(t[c].to_numpy()).all(): raise ValueError('complete finite numbers required')
    if (t['opening_value']<0).any() or (t['asset_return'] < -1).any():
        raise ValueError('invalid long-only value or price return')
    try:
        with np.errstate(over='raise',invalid='raise',divide='raise'):
            total=float(t['opening_value'].sum(skipna=False))
            if not np.isfinite(total) or total<=0: raise ValueError('positive finite portfolio value required')
            t['price_pnl']=t['opening_value']*t['asset_return']
            report=t.groupby('sector',sort=True,dropna=False,observed=True).agg(
                asset_count=('asset','size'),opening_value=('opening_value','sum'),
                price_pnl=('price_pnl','sum'))
            report['portfolio_weight']=report['opening_value']/total
            report['portfolio_contribution']=report['price_pnl']/total
            denominator=report['opening_value'].where(report['opening_value']>0)
            report['sector_return']=report['price_pnl']/denominator
            portfolio_return=float(t['price_pnl'].sum(skipna=False)/total)
    except FloatingPointError as exc:
        raise ValueError('unsupported numerical range') from exc
    required=['opening_value','price_pnl','portfolio_weight','portfolio_contribution']
    if not np.isfinite(report[required].to_numpy()).all() or not np.isfinite(portfolio_return):
        raise ValueError('nonfinite output')
    invested=report['opening_value']>0
    if not np.isfinite(report.loc[invested,'sector_return'].to_numpy()).all():
        raise ValueError('nonfinite invested-sector return')
    return report,portfolio_return


def fixture():
    return pd.DataFrame({'asset':['ALPHA','BETA','CASH','ZERO'],
        'sector':['equity','equity','cash','unused'],
        'opening_value':[600.,300.,100.,0.],'asset_return':[.1,-.05,0.,.2]})

if __name__=='__main__':
    report,total=summarize(fixture())
    print(report.to_string(float_format=lambda x:f'{x:.4f}'))
    print(f'Portfolio price return: {total:.2%}')
```

## 7.11.12 Complete Tests — test_grouping.py

```python
import unittest
import numpy as np
import pandas as pd
from grouping import summarize,fixture

class GroupTests(unittest.TestCase):
    def test_known_answers(self):
        r,total=summarize(fixture())
        self.assertAlmostEqual(total,.045)
        self.assertEqual(r.loc['equity','opening_value'],900)
        self.assertEqual(r.loc['equity','price_pnl'],45)
        self.assertAlmostEqual(r.loc['equity','sector_return'],.05)
        self.assertAlmostEqual(r.loc['equity','portfolio_contribution'],.045)
        self.assertEqual(r.loc['equity','asset_count'],2)

    def test_scalar_oracle_and_reconciliation(self):
        raw=fixture(); r,total=summarize(raw)
        values=raw['opening_value'].tolist(); returns=raw['asset_return'].tolist()
        scalar=sum(v*x for v,x in zip(values,returns))/sum(values)
        self.assertAlmostEqual(total,scalar)
        self.assertAlmostEqual(r['portfolio_weight'].sum(),1)
        self.assertAlmostEqual(r['portfolio_contribution'].sum(),total)
        self.assertEqual(int(r['asset_count'].sum()),len(raw))
        self.assertEqual(r['opening_value'].sum(),sum(values))

    def test_weighted_vs_simple_mean(self):
        raw=fixture(); self.assertAlmostEqual(raw.loc[:1,'asset_return'].mean(),.025)
        self.assertAlmostEqual(summarize(raw)[0].loc['equity','sector_return'],.05)

    def test_zero_sector_and_zero_portfolio(self):
        r,_=summarize(fixture()); self.assertTrue(pd.isna(r.loc['unused','sector_return']))
        self.assertEqual(r.loc['unused','portfolio_contribution'],0)
        raw=fixture(); raw['opening_value']=0.
        with self.assertRaises(ValueError): summarize(raw)

    def test_permutation_and_source(self):
        raw=fixture(); before=raw.copy(deep=True); a,total=summarize(raw)
        b,_=summarize(raw.iloc[::-1]); pd.testing.assert_frame_equal(a,b)
        a.loc['equity','opening_value']=0; pd.testing.assert_frame_equal(raw,before)

    def test_missing_and_duplicate_rejections(self):
        for c,value in [('sector',None),('opening_value',np.nan),('asset_return',np.nan),('asset','BETA')]:
            raw=fixture(); raw.loc[0,c]=value
            with self.assertRaises(ValueError): summarize(raw)

    def test_domain_schema_and_range(self):
        for c,value in [('opening_value',-1.),('asset_return',-1.1),('opening_value',np.inf)]:
            raw=fixture(); raw.loc[0,c]=value
            with self.assertRaises(ValueError): summarize(raw)
        with self.assertRaises(ValueError): summarize(fixture().assign(extra=1))
        raw=fixture(); raw.loc[0,['opening_value','asset_return']]=[1e308,1e308]
        with self.assertRaises(ValueError): summarize(raw)

    def test_groupby_missing_keys_and_transform(self):
        raw=pd.DataFrame({'sector':['equity',None,'equity'],'value':[10.,20.,np.nan]})
        g=raw.groupby('sector',dropna=False)
        self.assertEqual(int(g.size().sum()),3)
        self.assertEqual(int(g['value'].count().sum()),2)
        self.assertEqual(int(raw.groupby('sector').size().sum()),2)
        full=fixture(); totals=full.groupby('sector')['opening_value'].transform('sum')
        self.assertEqual(totals.tolist(),[900,900,100,0])

if __name__=='__main__': unittest.main()
```

## 7.11.14 Troubleshooting and Exercises

| Symptom | Likely cause | Action |
|---|---|---|
| Grouped records do not reconcile | Missing classification keys were excluded | Inspect key policy and compare counts |
| Sector mean differs from return | Equal record weights used instead of opening values | Divide group P&L by group opening value |
| Sector returns do not sum to portfolio return | Different denominators | Sum portfolio contributions instead |
| Zero group reports NaN | No opening value for its own return | Preserve undefined return; inspect contribution separately |
| Transform results overstate totals | Group totals repeated on each row | Aggregate one row per group before summing |
| Report mixes currencies or dates | Group key omitted context | Validate or add the appropriate composite grouping keys |

1. Reproduce equity's 2.50% simple mean, 5.00% weighted return and 4.50% portfolio contribution by hand.
2. Reverse source ordering and verify report keys and results remain consistent for the fixture.
3. Add another invested cash asset and reconcile group counts, values and contributions.
4. Replace one sector with a missing value; contrast general pandas behavior with the public function's rejection.
5. Add a zero-valued observed sector and explain its undefined return.
6. Use transform to attach sector opening totals to rows, then explain why summing those repeated totals is wrong.
7. Design account-and-sector keys for separate account reports; state which denominator each contribution should use.
8. Explain why complete observed groups still require an independently expected asset population before claiming portfolio completeness.
