## 7.6.1 Purpose

A numeric-looking string, an identifier, a whole count and an approximate price may look similar in a table but require different representations. Conversion should implement a field contract rather than merely remove an inconvenient object dtype.

Section 7.5 preserved source text during ingestion. Here we convert a small table into explicitly chosen pandas dtypes, retaining the difference between an unknown count and a known zero. We also inspect cases where conversion succeeds while changing meaning or losing information.

## 7.6.2 Learning Objectives

1. Choose types according to financial meaning and missingness.
2. Distinguish NumPy int64/float64 from pandas nullable Int64/Float64.
3. Use `to_numeric` and `astype` with explicit failure policies.
4. Audit invalid values introduced by coercion.
5. Preserve identifiers without floating-point conversion.
6. Parse Boolean tokens explicitly rather than using string truthiness.
7. Validate exact integer ranges before converting to a nullable integer column.
8. Reproduce a complete conversion component and its tests.

## 7.6.3 Meaning Before Representation

| Field | Example source | Target in this lab | Reason |
|---|---|---|---|
| asset | 00123, NA, BETA | string | Identifier spelling matters |
| lot_count | 6, empty, 0 | Int64 | Whole counts, with an explicit unknown state |
| price | 100.25, 80, 0 | float64 | Approximate nonnegative analysis price |
| reviewed | true, false | boolean | Explicit logical state; no free-text truthiness |

A lot count is a whole count under this fixture's contract, not the fractional quantity held in a security. The empty lot count is allowed to remain unknown, and the component performs no portfolio valuation. It does not multiply unknown counts into prices and report a partial total.

Prices are synthetic, share a supplied currency/per-unit convention, and are observations at one common valuation context. This converter does not authenticate those facts or load a data source. It handles representation and field-level domains.

## 7.6.4 Common pandas Types

| Representation | Typical role | Missingness and precision considerations |
|---|---|---|
| int64 | Ordinary signed whole numbers | Cannot directly store a missing integer marker |
| Int64 | pandas nullable signed whole numbers | Stores integers and pd.NA; capital I is intentional |
| float64 | Approximate numeric analysis | Commonly uses NaN for missingness; not exact decimal arithmetic |
| Float64 | pandas nullable floating extension type | Supports pd.NA, but remains floating-point arithmetic |
| boolean | pandas nullable Boolean extension type | Can represent unknown as well as true/false |
| string | Explicit pandas text representation | Preserves identifier spelling and supports missing text |
| object | General Python objects | Does not guarantee a numeric or uniform semantic field |

A DataFrame has a dtype per column, not necessarily one dtype for the entire table. Inspect `.dtypes` after conversion. A nullable type permits missing values; it does not imply that missing values are acceptable in every field. This lab requires reviewed to be present even though its chosen dtype supports pd.NA.

The uppercase nullable floating type is not a decimal-money type. Changing float64 to Float64 does not solve binary rounding. Exact financial ledgers require a separately specified decimal or scaled-integer policy.

## 7.6.5 Conversion Tools and Their Roles

`pd.to_numeric(series, errors='raise')` parses numeric data and fails when unsupported parsing is encountered. It does not establish the allowed financial domain, units, or completeness. A valid parsed negative number can still be invalid for a long-only count or nonnegative price.

`astype` requests a target representation. It is useful after validation, but conversion can be lossy. For the tested float fixture, `pd.Series([1.75]).astype('int64')` produces 1. An integer result alone therefore does not prove that the source was a whole count.

`convert_dtypes()` can help choose nullable representations for existing data, but inferred types are not a business schema. It cannot know that 00123 is an identifier, that a field is exact cents, or that the empty count is the only approved missing token. It is not a general numeric-string parser.

Avoid `errors='ignore'` in this versioned workflow; it is deprecated for `to_numeric` in pandas 2.2. Catch and report conversion failures explicitly instead of leaving a column in an uncertain state.

## 7.6.6 Coercion Needs an Audit

```python
raw = pd.Series(['100', 'BAD', None])
parsed = pd.to_numeric(raw, errors='coerce')
introduced = raw.notna() & parsed.isna()
# One newly unparseable nonmissing value; two missing results overall.
```

Coercion is useful for identifying rejected records, but not permission to proceed with an incomplete total. Preserve the original token and row identity when reporting conversion failures. The introduced mask distinguishes originally nonmissing values that became missing from values already missing in the source. A source's documented null tokens may need normalization before interpreting that distinction.

The complete component uses strict rejection instead. Broader missing-value policy is the subject of Section 7.7.

## 7.6.7 Identifier, Integer and Boolean Pitfalls

Never convert asset identifiers to floats merely because every observed identifier contains digits. Leading zeros disappear, and sufficiently large integers can collide after conversion. In float64, `float(2**53)` equals `float(2**53+1)` even though the source integers differ. A later conversion to string cannot recover the original identity.

For exact whole counts, the lab first checks an unsigned integer grammar, parses each token with Python int, and rejects values beyond the signed Int64 maximum. This avoids routing the exact boundary check through floating-point values. It does not imply that all future arithmetic on that Int64 column is immune to overflow.

Likewise, `bool('false')` is true because the string is nonempty. A cast to Boolean is not a parser for an agreed token vocabulary. The lab maps only the exact lowercase strings true and false; False, FALSE, 0, yes and an empty token are rejected. A different source can define another vocabulary, but that vocabulary must be explicit.

## 7.6.9 Complete Converter — conversion.py

```python
"""Explicit text-to-type contract; no ingestion or valuation performed."""
import re
import numpy as np
import pandas as pd


def convert_records(raw):
    """Convert asset, lot_count, price and reviewed text fields.

    Empty lot_count alone means unknown; no other null tokens are accepted.
    Whole lot counts are distinct from fractional security quantities.
    """
    columns=['asset','lot_count','price','reviewed']
    if not isinstance(raw,pd.DataFrame) or not 1<=len(raw)<=10_000:
        raise ValueError('DataFrame with 1..10000 rows required')
    if not raw.columns.is_unique or raw.columns.tolist()!=columns:
        raise ValueError('exact ordered schema required')
    if not raw.index.is_unique:
        raise ValueError('unique source row index required')
    for name in columns:
        if not raw[name].map(lambda x:isinstance(x,str) and len(x)<=64).all():
            raise ValueError('all source cells must be strings of at most 64 characters')
    asset=raw['asset']
    if asset.duplicated().any() or any(not x or x!=x.strip() for x in asset):
        raise ValueError('unique trimmed nonempty asset identifiers required')
    counts=[]
    for text in raw['lot_count']:
        if text=='':
            counts.append(pd.NA)
        elif re.fullmatch(r'0|[1-9][0-9]*',text):
            number=int(text)  # Check exact integer range before any floating conversion.
            if number>np.iinfo(np.int64).max:
                raise ValueError('lot_count exceeds Int64 range')
            counts.append(number)
        else:
            raise ValueError('lot_count must be unsigned integer text or empty')
    if not raw['price'].map(lambda x:re.fullmatch(r'(?:0|[1-9][0-9]*)(?:\.[0-9]+)?',x) is not None).all():
        raise ValueError('price must be unsigned decimal text')
    price=pd.to_numeric(raw['price'],errors='raise').astype('float64')
    if not np.isfinite(price.to_numpy()).all():
        raise ValueError('finite price required')
    if not raw['reviewed'].isin(['true','false']).all():
        raise ValueError('reviewed must be exactly true or false')
    return pd.DataFrame({
        'asset':pd.Series(asset.to_numpy(copy=True),index=raw.index,dtype='string'),
        'lot_count':pd.Series(counts,index=raw.index,dtype='Int64'),
        'price':price.copy(deep=True),
        'reviewed':raw['reviewed'].map({'true':True,'false':False}).astype('boolean'),
    },index=raw.index.copy())


def fixture():
    return pd.DataFrame({'asset':['00123','NA','BETA'], 'lot_count':['6','','0'],
                         'price':['100.25','80','0'], 'reviewed':['true','false','true']})

if __name__=='__main__':
    typed=convert_records(fixture())
    print(typed.to_string(index=False))
    print('Dtypes: '+', '.join(f'{c}={typed[c].dtype}' for c in typed))
    print(f'Unknown lot counts: {typed["lot_count"].isna().sum()}')
```

## 7.6.10 Complete Tests — test_conversion.py

```python
import unittest
import numpy as np
import pandas as pd
from conversion import convert_records,fixture

class ConversionTests(unittest.TestCase):
    def test_schema_and_values(self):
        t=convert_records(fixture())
        self.assertEqual([str(x) for x in t.dtypes],['string','Int64','float64','boolean'])
        self.assertEqual(t['asset'].tolist(),['00123','NA','BETA'])
        self.assertEqual(t.loc[0,'price'],100.25)
        self.assertEqual(t['reviewed'].tolist(),[True,False,True])

    def test_nullable_count_and_exact_range(self):
        t=convert_records(fixture()); self.assertTrue(pd.isna(t.loc[1,'lot_count']))
        self.assertEqual(t.loc[2,'lot_count'],0)
        r=fixture(); r.loc[0,'lot_count']=str(np.iinfo(np.int64).max)
        self.assertEqual(convert_records(r).loc[0,'lot_count'],np.iinfo(np.int64).max)
        r.loc[0,'lot_count']=str(int(np.iinfo(np.int64).max)+1)
        with self.assertRaises(ValueError): convert_records(r)

    def test_invalid_count_tokens(self):
        for token in ['1.5','1.0','-1',' 6','NaN','NA','1e2','01']:
            r=fixture(); r.loc[0,'lot_count']=token
            with self.subTest(token=token),self.assertRaises(ValueError): convert_records(r)

    def test_invalid_price_tokens(self):
        for token in ['','NA','inf','-1','1,000','1e2',' 1','True']:
            r=fixture(); r.loc[0,'price']=token
            with self.subTest(token=token),self.assertRaises(ValueError): convert_records(r)

    def test_boolean_mapping(self):
        self.assertTrue(bool('false'))  # Python nonempty-string truthiness is not parsing.
        for token in ['False','FALSE','0','','yes']:
            r=fixture(); r.loc[0,'reviewed']=token
            with self.assertRaises(ValueError): convert_records(r)

    def test_input_and_identity_rejections(self):
        for r in [fixture().drop(columns='price'),fixture().assign(extra='x'),fixture().iloc[:0]]:
            with self.assertRaises(ValueError): convert_records(r)
        for token in ['', ' BETA','00123']:
            r=fixture(); r.loc[2,'asset']=token
            with self.assertRaises(ValueError): convert_records(r)
        r=fixture(); r['price']=[100.,80.,0.]
        with self.assertRaises(ValueError): convert_records(r)

    def test_source_ownership_and_row_index(self):
        r=fixture(); r.index=[30,10,20]; before=r.copy(deep=True)
        t=convert_records(r); self.assertEqual(t.index.tolist(),[30,10,20])
        self.assertEqual(t.loc[30,'lot_count'],6)
        t.loc[30,'price']=1
        pd.testing.assert_frame_equal(r,before)

    def test_coercion_audit_and_precision(self):
        raw=pd.Series(['100','BAD',None])
        parsed=pd.to_numeric(raw,errors='coerce')
        introduced=raw.notna() & parsed.isna()
        self.assertEqual(int(introduced.sum()),1)
        self.assertEqual(int(parsed.isna().sum()),2)
        self.assertEqual(float(2**53),float(2**53+1))
        self.assertEqual(int(pd.Series([1.75]).astype('int64').iloc[0]),1)

if __name__=='__main__': unittest.main()
```

## 7.6.12 Validation Evidence and Limits

| Area | Checks |
|---|---|
| Output schema | Explicit string, Int64, float64 and boolean dtypes; known values |
| Exact count boundary | Int64 maximum retained exactly; maximum plus one rejected |
| Count grammar | Fractions, signs, whitespace, missing-looking tokens, exponents and redundant leading zeros rejected |
| Price grammar | Empty, invalid, infinite, negative, grouped and exponent text rejected |
| Boolean parsing | Exact vocabulary enforced; nonempty-string truthiness illustrated |
| Input contract | Wrong schema, empty table, duplicate/empty/whitespace identifiers and numeric source objects rejected |
| Ownership and alignment | Nondefault source row index retained; output mutation leaves source unchanged |
| Diagnostics | Coercion audit distinguishes new failures; float collision and integer truncation reproduced |

The explicit row and cell-length limits are educational workload policies, not a process-memory guarantee. The source DataFrame already exists before validation. Floating prices remain approximate and can lose precision or underflow for very small decimal tokens. A finite-value check is necessary but does not establish economic accuracy, exact decimals or safe downstream aggregation.

The nullable count maximum test establishes conversion of that exact fixture; it is not an overflow policy for later additions or multiplications. Define result-range checks before using such counts in computations.

## 7.6.13 Troubleshooting

| Symptom | Likely cause | Action |
|---|---|---|
| Identifier changes spelling | Converted to a numeric representation | Preserve source text at first ingestion |
| Fraction silently becomes a whole number | Cast used as validation | Check whole-count grammar/domain before casting |
| False text becomes true | String truthiness mistaken for parsing | Use a documented token mapping |
| Column remains object | Inference or failed mixed input | Inspect source tokens and apply an explicit schema |
| Missing count becomes zero | Default filling changed meaning | Preserve unknown unless an approved policy establishes zero |
| Nullable numeric column rejected by an earlier lab | That lab accepted a narrower contract | Adapt types with explicit missingness checks; do not remove validation blindly |
