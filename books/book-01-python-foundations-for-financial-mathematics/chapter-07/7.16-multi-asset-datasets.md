## 7.16.1 Purpose

A multi-asset dataset must preserve both instrument identity and observation time. A rectangular table is useful for analysis, but its shape alone does not establish complete coverage or comparable return intervals.

This section converts long-form price records into a wide price panel on an independently specified asset/time grid. It rejects duplicate keys, preserves absent observations, calculates returns only across adjacent grid rows without filling, and marks intervals for which every expected asset has observed endpoints. It does not produce portfolio performance from incomplete data.

## 7.16.2 Learning Objectives

1. Define long-form and wide-form financial data layouts.
2. Enforce one observation per asset-time composite key.
3. Build expected asset and time axes independently of supplied records.
4. Preserve missing assets, times and individual observations during reshaping.
5. Distinguish asset-specific observation intervals from common-grid intervals.
6. Calculate per-column returns with explicit no-fill behavior.
7. Retain labels when preparing numerical matrices.
8. Test layout round trips, coverage and order independence.

## 7.16.3 Record Grain and Financial Contract

Each long-form record contains one positive price for one asset at one aware timestamp. Assets share a common currency/per-unit interpretation suitable for this synthetic exercise, and each asset's adjustment convention is consistent through time. The component does not validate those economic metadata or perform FX conversion.

| UTC time | Asset | Price |
|---|---|---:|
| 2026-01-30 16:00 | ALPHA | 100 |
| 2026-01-31 16:00 | ALPHA | 110 |
| 2026-02-01 16:00 | ALPHA | 99 |
| 2026-01-30 16:00 | BETA | 200 |
| 2026-02-01 16:00 | BETA | 220 |

The expected assets are ALPHA and BETA. The expected times are the three displayed calendar-day instants. These dates include a weekend deliberately: the synthetic grid is not an exchange trading calendar or evidence of real quotes on those dates.

There are no distributions, trades, fees, external flows or corporate-action transformations. Outputs are price panels and simple price returns, not investment advice or a portfolio strategy.

## 7.16.4 Long and Wide Layouts

Long form has explicit time, asset and price columns, with one row per composite key. It can carry additional source metadata such as currency, venue, adjustment basis and availability time under a broader schema.

Wide form places time on the row index and assets on the columns:

| Time | ALPHA | BETA |
|---|---:|---:|
| Jan 30 16:00 UTC | 100 | 200 |
| Jan 31 16:00 UTC | 110 | NaN |
| Feb 1 16:00 UTC | 99 | 220 |

Wide form is convenient for per-asset calculations and labeled matrix operations. Long form is often convenient for source validation and composite-key checks. Neither layout is inherently a complete or valid financial dataset.

A MultiIndex can also represent time and asset as labeled index levels without putting each asset in a separate column. Choose the representation for the operation while preserving key semantics. This lab keeps one measured field and uses a plain wide column index for clarity.

## 7.16.5 Unique Keys Before Reshaping

```python
wide = records.pivot(index='time', columns='asset', values='price')
```

Pivot reshapes rather than aggregating duplicate records. If an asset-time pair occurs twice, the single output cell would be ambiguous. The public function rejects those duplicates before pivoting, including duplicates whose prices agree.

`pivot_table` can aggregate multiple records, but selecting a mean, first or last price is an economic/source precedence rule. Do not use aggregation merely to hide duplicate observations. A revision-aware or multi-venue source needs its own key and selection policy.

Timestamps are normalized to UTC before duplicate detection. Two different timezone displays of the same instant and asset are the same key under this contract. Conversely, two assets at the same instant are valid distinct records.

## 7.16.6 Independent Expected Axes

Observed records cannot reveal a wholly absent instrument or reporting time by themselves. The function therefore requires an ordered tuple of expected assets and an ordered expected DatetimeIndex.

```python
wide = wide.reindex(index=expected_times, columns=list(expected_assets))
```

This step establishes both the intended universe and output order. It exposes an entirely absent asset as an all-missing column and an entirely absent reporting instant as an all-missing row. It does not infer that those gaps are zero prices or valid nontrading periods.

Unexpected assets and timestamps are rejected rather than silently removed by reindexing. Before accepting a real grid, establish its source, calendar, observation convention and whether all assets should be observable at those instants. A common UTC timestamp does not prove that different venues have equally fresh information.

The asset tuple controls column order explicitly. Do not depend on pivot's incidental label ordering when preparing arrays for another model.

## 7.16.7 Returns Must Compare the Same Intervals

```python
returns = wide.pct_change(periods=1, fill_method=None)
known_endpoints = wide.notna() & wide.shift(1).notna()
complete_interval = known_endpoints.all(axis=1)
```

Each column compares the current expected grid row with the preceding expected grid row. Missing either endpoint leaves the return unknown. The first row has no previous grid observation and is not a complete interval.

ALPHA's adjacent-grid returns are +10% and −10%. BETA has no price on the middle row, so both adjacent-grid returns remain NaN. The aligned interval flags are therefore all false for the incomplete fixture.

Computing BETA's return only over its own observed rows instead yields +10% from Jan 30 to Feb 1. That two-day return is valid under an asset-specific observation-pair contract, but it must not be combined with ALPHA's one-day return ending Feb 1 as though both describe the same interval.

No fill or row dropping is used to manufacture comparability. Dropping the middle row before calculating would make both assets compare the two-day endpoints, which is a different grid. Calculating first and then dropping incomplete return rows is a different operation again.

## 7.16.8 Coverage and Missingness Policy

Supplied price records must be observed, finite and strictly positive. A supplied NaN is rejected; structural absence is represented only after alignment to the independent grid. This deliberately distinguishes invalid/incomplete source cells from records that did not arrive at all.

The function returns three objects: wide prices, wide returns and a Boolean complete_interval Series. Unknown intervals are not replaced with zero, and the function does not average the available asset returns or renormalize a partial set of portfolio weights.

A complete flag means that all required numerical endpoints are present and supported for that grid interval. It does not authenticate quotes, prove synchronization or establish historical availability. Missing an entire asset from the expected tuple would also weaken the completeness claim; the expected universe must be independently maintained.

Filling prior prices would assume a permitted stale-price convention and could create zero returns during gaps. Backward filling could use future information. Those policies require quote-age, source and timing evidence beyond this example.

## 7.16.9 Matrix Boundaries and Metadata

A complete return table can later be exported to NumPy after its axes and order are checked. Preserve the time index and asset columns beside the resulting array; a bare matrix cannot identify the meaning of a position.

If using a labeled weight Series, require its asset set, order and weighting date to match the return calculation. An equal shape is not sufficient. This section intentionally supplies no weights or portfolio-return calculation; a price panel is a data preparation component, not a portfolio model by itself.

Covariance or correlation routines may use different available observation pairs when missingness remains. That can make assets' reported statistics refer to different samples. Define a common sample or another explicit statistical missing-data method before interpreting a multi-asset risk result.

## 7.16.10 Validation and Environment

Expected assets are 1–100 unique trimmed nonempty strings, each at most 64 characters. Expected times contain 2–1,000 complete, aware, unique increasing instants. Their Cartesian grid has at most 100,000 cells. Source input has 1–100,000 records and exactly time, asset and price columns.

The time column must already be a timezone-aware pandas datetime dtype. Parsing raw timestamp text belongs upstream, such as Section 7.9's contract. Source time keys are converted to UTC. Numeric prices must have an ordinary NumPy-backed real numeric dtype; text, Boolean and extension types are outside this narrow boundary.

The component copies numeric data to float64 and checks finite supported returns where endpoints are known. Extreme ratios that overflow or round to −1 are rejected. Normal rounding and loss of very small changes remain possible. Grid and source bounds limit the teaching workload but do not guarantee peak process memory.

## 7.16.11 Complete Panel Builder — panel.py

```python
"""Long-to-wide price panel on an independently specified observation grid."""
import numpy as np
import pandas as pd


def panel(raw,assets,times):
    """Return wide prices, adjacent-grid returns, and complete interval flags.

    Single common currency and adjustment convention, no fills or portfolio
    weights. Missing asset-time observations remain unknown.
    """
    if not isinstance(assets,tuple) or not 1<=len(assets)<=100:
        raise ValueError('tuple of 1..100 expected assets required')
    if any(not isinstance(x,str) or not 0<len(x)<=64 or x!=x.strip() for x in assets) or len(set(assets))!=len(assets):
        raise ValueError('unique trimmed asset strings required')
    if not isinstance(times,pd.DatetimeIndex) or not 2<=len(times)<=1000:
        raise ValueError('DatetimeIndex with 2..1000 expected times required')
    if times.tz is None or times.hasnans or not times.is_unique or not times.is_monotonic_increasing:
        raise ValueError('aware ordered unique expected times required')
    grid=times.tz_convert('UTC').rename('time')
    if not isinstance(raw,pd.DataFrame) or not 1<=len(raw)<=100_000:
        raise ValueError('DataFrame with 1..100000 records required')
    if not raw.columns.is_unique or raw.columns.tolist()!=['time','asset','price']:
        raise ValueError('exact ordered long schema required')
    if not isinstance(raw['time'].dtype,pd.DatetimeTZDtype) or raw['time'].isna().any():
        raise ValueError('complete aware time column required')
    if not raw['asset'].map(lambda x:isinstance(x,str) and 0<len(x)<=64 and x==x.strip()).all():
        raise ValueError('trimmed asset strings required')
    t=raw.reset_index(drop=True).copy(deep=True); t['time']=t['time'].dt.tz_convert('UTC')
    if not t['asset'].isin(assets).all() or not t['time'].isin(grid).all():
        raise ValueError('record outside expected asset/time grid')
    if t.duplicated(['time','asset']).any(): raise ValueError('duplicate asset-time key')
    if not isinstance(t['price'].dtype,np.dtype) or t['price'].dtype.kind not in 'iuf':
        raise ValueError('ordinary real numeric prices required')
    t['price']=t['price'].astype('float64')
    if not np.isfinite(t['price'].to_numpy()).all() or (t['price']<=0).any():
        raise ValueError('supplied prices must be finite and positive')
    wide=t.pivot(index='time',columns='asset',values='price').reindex(index=grid,columns=list(assets))
    returns=wide.pct_change(periods=1,fill_method=None)
    known=wide.notna() & wide.shift(1).notna()
    observed=returns.to_numpy()[known.to_numpy()]
    if not np.isfinite(observed).all() or np.any(observed<=-1):
        raise ValueError('unsupported return numerical range')
    complete=known.all(axis=1).rename('complete_interval')
    return wide,returns,complete


def fixture():
    times=pd.date_range('2026-01-30T16:00:00Z',periods=3,freq='D')
    raw=pd.DataFrame({'time':[times[0],times[1],times[2],times[0],times[2]],
                      'asset':['ALPHA']*3+['BETA']*2,'price':[100.,110.,99.,200.,220.]})
    return raw,('ALPHA','BETA'),times

if __name__=='__main__':
    wide,returns,complete=panel(*fixture())
    print(wide.to_string())
    print(returns.to_string(float_format=lambda x:f'{x:.4f}'))
    print(f'Complete aligned intervals: {int(complete.sum())}')
```

## 7.16.12 Complete Tests — test_panel.py

```python
import unittest
import numpy as np
import pandas as pd
from panel import panel,fixture

class PanelTests(unittest.TestCase):
    def test_known_layout_and_returns(self):
        wide,r,c=panel(*fixture())
        self.assertEqual(wide.shape,(3,2)); self.assertEqual(wide.columns.tolist(),['ALPHA','BETA'])
        np.testing.assert_allclose(r['ALPHA'].iloc[1:],[.1,-.1],rtol=0,atol=1e-12)
        self.assertTrue(r['BETA'].isna().all()); self.assertFalse(c.any())

    def test_complete_fixture_and_scalar(self):
        raw,assets,times=fixture()
        raw=pd.concat([raw,pd.DataFrame({'time':[times[1]],'asset':['BETA'],'price':[210.]})])
        wide,r,c=panel(raw,assets,times)
        self.assertEqual(c.tolist(),[False,True,True])
        for asset in assets:
            expected=[wide[asset].iloc[i]/wide[asset].iloc[i-1]-1 for i in (1,2)]
            np.testing.assert_allclose(r[asset].iloc[1:],expected,rtol=0,atol=1e-12)

    def test_missing_entire_asset_and_time(self):
        raw,assets,times=fixture(); wide,r,c=panel(raw.loc[raw['asset']=='ALPHA'],assets,times)
        self.assertTrue(wide['BETA'].isna().all())
        wide,_,_=panel(raw.loc[raw['time']!=times[1]],assets,times)
        self.assertTrue(wide.iloc[1].isna().all())

    def test_duplicates_and_unexpected_keys(self):
        raw,assets,times=fixture()
        for bad in [pd.concat([raw,raw.iloc[:1]]),raw.assign(asset='OTHER'),raw.assign(time=raw['time']+pd.Timedelta(days=10))]:
            with self.assertRaises(ValueError): panel(bad,assets,times)

    def test_invalid_numeric_and_axis(self):
        raw,assets,times=fixture()
        for value in [0,-1,np.nan,np.inf]:
            bad=raw.copy(); bad.loc[0,'price']=value
            with self.assertRaises(ValueError): panel(bad,assets,times)
        with self.assertRaises(ValueError): panel(raw,('ALPHA','ALPHA'),times)
        with self.assertRaises(ValueError): panel(raw,assets,times[::-1])
        with self.assertRaises(ValueError): panel(raw,assets,times.tz_localize(None))

    def test_order_and_ownership(self):
        raw,assets,times=fixture(); before=raw.copy(deep=True)
        a=panel(raw,assets,times); b=panel(raw.iloc[::-1],assets,times)
        for x,y in zip(a,b):
            if isinstance(x,pd.Series): pd.testing.assert_series_equal(x,y)
            else: pd.testing.assert_frame_equal(x,y)
        a[0].iloc[0,0]=1; pd.testing.assert_frame_equal(raw,before)
        reversed_wide=panel(raw,assets[::-1],times)[0]
        self.assertEqual(reversed_wide.columns.tolist(),['BETA','ALPHA'])

    def test_asset_specific_interval_differs(self):
        raw,assets,times=fixture(); beta=raw.loc[raw['asset']=='BETA'].sort_values('time')
        self.assertAlmostEqual(beta['price'].pct_change(fill_method=None).iloc[-1],.1)
        self.assertEqual(beta['time'].iloc[-1]-beta['time'].iloc[0],pd.Timedelta(days=2))
        self.assertTrue(pd.isna(panel(raw,assets,times)[1].loc[times[-1],'BETA']))

    def test_long_roundtrip(self):
        raw,assets,times=fixture(); wide,_,_=panel(raw,assets,times)
        restored=wide.reset_index().melt(id_vars='time',var_name='asset',value_name='price').dropna(subset=['price'])
        expected=raw.sort_values(['time','asset']).reset_index(drop=True)
        restored=restored.sort_values(['time','asset']).reset_index(drop=True)
        pd.testing.assert_frame_equal(restored,expected)

if __name__=='__main__': unittest.main()
```

## 7.16.14 Troubleshooting and Exercises

| Symptom | Likely cause | Action |
|---|---|---|
| Pivot rejects records | Duplicate asset-time keys | Investigate source grain/revisions rather than aggregate blindly |
| Whole asset or time disappears | Expected axes derived only from observed records | Supply an independent universe and grid |
| Asset returns compare different horizons | Per-asset gaps skipped before pairing | Retain interval identities or use an explicit common grid |
| Portfolio result looks complete despite missing assets | Available returns were averaged or weights renormalized | Enforce the required coverage policy |
| NumPy output loses meaning | Axes discarded during export | Preserve time and asset labels beside arrays |
| Same timestamp hides stale venue data | UTC equality mistaken for synchronized observations | Track source observation and availability conventions |

1. Add BETA's middle price as 210 and verify two complete intervals with scalar per-asset checks.
2. Remove all BETA records and explain why the expected BETA column must remain visible.
3. Remove every record at the middle instant and inspect the expected all-missing row.
4. Duplicate an ALPHA-time key and explain why pivot-table averaging would require a separate policy.
5. Reverse expected asset order and confirm that column labels and values move together.
6. Calculate BETA's own two-day return and explain why it is not the missing one-day return.
7. Design a common two-day endpoint comparison without relabeling it as daily performance.
8. Specify the metadata and completeness checks required before exporting a return matrix for portfolio risk calculations.
