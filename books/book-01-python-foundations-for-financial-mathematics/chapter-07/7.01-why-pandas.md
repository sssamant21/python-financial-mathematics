## 7.1.1 Purpose

Chapter 6 established numerical array calculations. Financial datasets also need identities: which asset, which observation, which currency, and which field belongs to each value? pandas provides labeled data structures and operations that help preserve those relationships during analysis.

This chapter begins with an alignment problem. Opening portfolio weights and asset returns arrive in different orders. Their lengths match, yet position-by-position multiplication gives the wrong answer. Labels let us express the intended relationship, inspect it, and reject incomplete inputs before aggregation.

pandas does not know whether a price is adjusted, whether a timestamp is economically comparable, or whether a label was assigned correctly. Labels support a data contract; they do not replace one.

## 7.1.3 From Numerical Arrays to Labeled Observations

A NumPy array such as `[.6,.3,.1]` can represent opening weights, but its shape does not identify its assets. In Chapter 6 we carried ordered asset tuples alongside arrays. pandas places axis labels directly on its data structures.

| Structure | Introductory role | Financial example |
|---|---|---|
| Series | One-dimensional values with an index | Opening weights keyed by instrument identifier |
| DataFrame | Two-dimensional labeled table, with a dtype per column | Weight, return, and contribution columns by asset |
| Index | Axis labels used for selection and alignment | The ordered identifiers ALPHA, BETA, CASH |

An index need not be unique in pandas generally. Our financial component requires uniqueness because each asset must contribute exactly once. A label is also not necessarily a database primary key unless the application enforces that rule.

The next sections develop Series and DataFrame in detail. Here we use only enough syntax to establish why they are useful.

## 7.1.4 The Financial Fixture

Assume one common interval, common currency, long-only opening holdings, no trades, no flows, no distributions, no fees, and no FX changes. Supplied simple returns represent price changes over that interval. Weights are fractions of opening portfolio value and sum to one.

| Asset | Opening weight | Asset price return | Portfolio return contribution |
|---|---:|---:|---:|
| ALPHA | 0.60 | 0.10 | 0.060 |
| BETA | 0.30 | −0.05 | −0.015 |
| CASH | 0.10 | 0.00 | 0.000 |

The portfolio price return is 0.60×0.10 + 0.30×(−0.05) + 0.10×0 = 0.045, or 4.50%. Contributions are return fractions, not currency P&L. ALPHA adds six percentage points; BETA subtracts 1.5 percentage points.

The label CASH is an identifier for the supplied zero-return instrument in this fixture. It does not cause pandas to apply cash-account rules.

## 7.1.5 Same Length, Wrong Pairing

Suppose the weight order is ALPHA, BETA, CASH while the return order is CASH, ALPHA, BETA. If labels are discarded and these positions are multiplied, the result is:

```python
import numpy as np
weights = np.array([.6, .3, .1])
returns_in_another_order = np.array([0, .1, -.05])
wrong = weights @ returns_in_another_order
print(f'{wrong:.2%}')  # 2.50%
```

All shapes are valid. The arithmetic is executable and the output looks plausible. The error is the mapping between assets and positions.

A labeled counterpart expresses that mapping explicitly:

```python
import pandas as pd
w = pd.Series([.6, .3, .1], index=['ALPHA', 'BETA', 'CASH'])
r = pd.Series([0, .1, -.05], index=['CASH', 'ALPHA', 'BETA'])
contribution = w * r
```

Series arithmetic aligns by index labels. Do not depend on incidental result ordering; the complete implementation explicitly reindexes returns to the validated weight order before constructing its report. No value is changed merely to achieve this ordering.

These short snippets explain the mechanism. Use the validated function below when applying the fixture contract.

## 7.1.6 Alignment Also Exposes Gaps

Consider weights indexed by A and B, but returns available only for A. Multiplication creates a missing B contribution. A default Series sum skips missing entries and can therefore produce a plausible partial total.

```python
a = pd.Series([.6, .4], index=['A', 'B'])
b = pd.Series([.1], index=['A'])
product = a * b
print(product.sum())              # 0.06: only the available contribution
print(product.sum(skipna=False))  # nan
```

A missing return is not a zero return. Filling it with zero would change the financial assumption. The implementation requires identical asset sets, finite values, and unique labels before arithmetic. It also uses `skipna=False` as a second safeguard.

`min_count` controls the minimum number of nonmissing values needed by sum; it does not validate asset identities. Setting `min_count=1` prevents an all-missing result from becoming zero, but it still permits partial coverage. Problem-specific completeness checks must come first.

## 7.1.7 Choosing the Appropriate Tool

| Need | Useful starting point | Contract still required |
|---|---|---|
| Small configuration keyed by name | Python dictionary | Allowed keys and value meaning |
| Dense matrix products and simulations | NumPy | Axis identities, shapes, numerical limits |
| Tables with labeled columns and observations | pandas | Unique keys, dtypes, missingness and units |
| Data too large for a local in-memory analysis | A separately designed storage/query workflow | Capacity, partitioning and execution model |

pandas and NumPy often work together. Keep labels during ingestion, cleaning, alignment, and inspection. If handing data to a NumPy kernel, first establish the intended order and dtype, then retain the labels beside the array output. Calling `to_numpy()` removes pandas axis labels; numerical operations cannot reconstruct them afterward.

No performance comparison is claimed here. Label handling, indexes, conversion, and intermediate tables have costs. Section 6.15's method of comparing equivalent measured boundaries still applies.

## 7.1.9 Complete Lab — alignment.py

```python
"""Small labeled, single-interval price-return contribution example."""
import numpy as np
import pandas as pd


def checked_series(value, name):
    if not isinstance(value, pd.Series) or value.empty or len(value) > 10_000:
        raise ValueError(f'{name}: nonempty Series of at most 10000 items required')
    if isinstance(value.index, pd.MultiIndex) or not value.index.is_unique:
        raise ValueError(f'{name}: unique flat index required')
    if any(not isinstance(x, str) or not x or x != x.strip() for x in value.index):
        raise ValueError(f'{name}: trimmed nonempty string labels required')
    # Deliberately narrow teaching contract: ordinary NumPy-backed numeric dtypes.
    if not isinstance(value.dtype, np.dtype) or value.dtype.kind not in 'iuf':
        raise ValueError(f'{name}: ordinary real numeric dtype required')
    array = value.to_numpy(dtype=np.float64, copy=True)
    if not np.isfinite(array).all():
        raise ValueError(f'{name}: finite values required')
    return pd.Series(array, index=value.index.copy(), name=name)


def contributions(weights, returns):
    """Long-only opening weights and price returns for one common interval.

    No flows, fees, FX, distributions or rebalancing. Inputs share exactly
    the same unique asset set, but may have different order.
    """
    w = checked_series(weights, 'weight')
    r = checked_series(returns, 'return')
    if set(w.index) != set(r.index):
        raise ValueError('asset sets must match exactly')
    if (w < 0).any() or not np.isclose(w.sum(), 1, rtol=0, atol=1e-12):
        raise ValueError('nonnegative opening weights summing to one required')
    if (r < -1).any():
        raise ValueError('price returns must be at least -1')
    r = r.reindex(w.index)
    with np.errstate(over='raise', invalid='raise'):
        try:
            product = w * r
            total = float(product.sum(skipna=False))
        except FloatingPointError as exc:
            raise ValueError('unsupported numerical range') from exc
    if not np.isfinite(product.to_numpy()).all() or not np.isfinite(total):
        raise ValueError('nonfinite output')
    report = pd.DataFrame({'weight': w, 'return': r, 'contribution': product})
    return report, total


if __name__ == '__main__':
    w = pd.Series([.6,.3,.1], index=['ALPHA','BETA','CASH'])
    r = pd.Series([0,.1,-.05], index=['CASH','ALPHA','BETA'])
    report, total = contributions(w, r)
    print(report.to_string(float_format=lambda x: f'{x:.3f}'))
    print(f'Portfolio price return: {total:.2%}')
```

## 7.1.10 Input and Numerical Policy

The public function accepts two nonempty Series, each bounded to 10,000 values. Each has a flat unique index containing trimmed nonempty string identifiers. Their asset sets must match, but their order may differ. This differs deliberately from the strict ordered-tuple contract in Chapter 6: pandas provides a checked alignment step here.

The numeric contract is deliberately narrow: ordinary NumPy-backed integer, unsigned integer, or floating dtypes. Boolean, text, object, complex, and pandas extension dtypes are rejected. Nullable pandas dtypes will be discussed later. If a caller previously mixed Booleans with numbers and converted them into a numeric Series, that earlier type information is already lost; this helper is not a full ingestion schema validator.

Inputs are copied into float64 Series. Missing and nonfinite values are rejected. Opening weights must be nonnegative and sum to one within absolute tolerance 1e-12; they are not automatically normalized. Returns may be −1, representing total price loss, but not less than −1 under this long-only price-return contract.

Computed contributions and the scalar total must be finite. Float64 remains approximate: conversion of large integers can lose precision, very small products may underflow, and the weight tolerance is a chosen policy for this exercise. This lab does not provide exact-decimal accounting or support arbitrary extreme magnitudes. Display formatting does not round stored intermediates.

## 7.1.11 Complete Tests — test_alignment.py

```python
import unittest
import numpy as np
import pandas as pd
from alignment import contributions

class AlignmentTests(unittest.TestCase):
    def fixture(self):
        return (pd.Series([.6,.3,.1], index=['A','B','C']),
                pd.Series([0,.1,-.05], index=['C','A','B']))

    def test_known_answer(self):
        w,r=self.fixture(); frame,total=contributions(w,r)
        self.assertAlmostEqual(total,.045)
        np.testing.assert_allclose(frame['contribution'],[.06,-.015,0],rtol=0,atol=1e-12)
        self.assertEqual(frame.index.tolist(),['A','B','C'])

    def test_permutation(self):
        w,r=self.fixture()
        self.assertAlmostEqual(contributions(w,r)[1],contributions(w,r.iloc[::-1])[1])

    def test_missing_and_extra_labels(self):
        w,r=self.fixture()
        for bad in [r.drop('A'),r.rename(index={'A':'OTHER'})]:
            with self.assertRaises(ValueError): contributions(w,bad)

    def test_duplicate_and_invalid_index(self):
        w,r=self.fixture()
        for labels in [['A','A','C'],['A',' B','C'],[1,2,3]]:
            bad=r.copy(); bad.index=labels
            with self.assertRaises(ValueError): contributions(w,bad)

    def test_nonfinite_and_dtype(self):
        w,r=self.fixture()
        for values in [[np.nan,0,0],[np.inf,0,0],['0','1','2'],[True,False,True]]:
            with self.assertRaises(ValueError): contributions(w,pd.Series(values,index=r.index))

    def test_financial_domain(self):
        w,r=self.fixture()
        for bad in [w*2,pd.Series([-.1,.6,.5],index=w.index)]:
            with self.assertRaises(ValueError): contributions(bad,r)
        with self.assertRaises(ValueError): contributions(w,r*100)
        loss=pd.Series([-1.,-1.,-1.],index=r.index)
        self.assertAlmostEqual(contributions(w,loss)[1],-1)

    def test_source_preservation(self):
        w,r=self.fixture(); wc=w.copy(deep=True); rc=r.copy(deep=True)
        frame,_=contributions(w,r); frame.iloc[0,0]=99
        pd.testing.assert_series_equal(w,wc); pd.testing.assert_series_equal(r,rc)

    def test_unguarded_alignment_and_skipna(self):
        a=pd.Series([.6,.4],index=['A','B'])
        b=pd.Series([.1],index=['A'])
        product=a*b
        self.assertTrue(pd.isna(product.loc['B']))
        self.assertAlmostEqual(product.sum(),.06)
        self.assertTrue(pd.isna(product.sum(skipna=False)))
        self.assertTrue(pd.isna(product.sum(min_count=2)))

if __name__=='__main__': unittest.main()
```

## 7.1.13 Common Mistakes

| Mistake | Consequence | Better practice |
|---|---|---|
| Convert to arrays before aligning | Valid arithmetic pairs wrong assets | Validate labels and establish order first |
| Accept duplicate identifiers | One asset can be counted more than once | Enforce unique keys for this model |
| Treat NaN as zero return | Incomplete data becomes an economic assumption | Reject or define an explicit missing-data policy |
| Trust a nonmissing sum | Partial contributions can look complete | Validate coverage before aggregation |
| Assume labels establish currency or dates | Incomparable observations can be combined | Retain and check those fields separately |
| Normalize weights silently | Changes supplied exposures | Reject or explicitly document a normalization step |
| Infer exact monetary precision from a table | Formatting hides floating-point approximation | Choose a suitable numerical policy |
