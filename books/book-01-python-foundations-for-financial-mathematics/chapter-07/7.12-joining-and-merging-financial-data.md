## 7.12.1 Purpose

Combining financial tables requires more than finding equal asset names. A valid merge needs a defined record grain, complete keys, an expected match relationship and a policy for unmatched records. Otherwise a join can silently remove holdings or multiply their exposures.

This section reconciles holdings and quotes for one synthetic snapshot using explicit composite keys, one-to-one validation and an outer-join audit. A complete key population permits valuation; any unmatched record withholds it. The lab also demonstrates alternative join mechanics without treating them as interchangeable financial policies.

## 7.12.2 Learning Objectives

1. Define row grain and composite keys before merging.
2. Choose left, inner, right or outer joins according to coverage requirements.
3. Validate one-to-one or many-to-one cardinality explicitly.
4. Detect unmatched records with a merge indicator.
5. Prevent row multiplication and null-key matches from producing false valuations.
6. Preserve units, currency and valuation context across sources.
7. Distinguish merge, index-based join, concatenation and temporal matching.
8. Reconcile matched valuations with independent scalar arithmetic.

## 7.12.3 Snapshot and Key Contract

Holdings have exactly asset, currency, valuation_date and quantity columns. Quotes have the same key fields followed by price. Each source contains one record per composite key:

`(asset, currency, valuation_date)`

The lab expects USD and calendar date 2026-01-30 on every record. Quantities and prices are finite and nonnegative, using ordinary real numeric dtypes. Both sources are assumed to share compatible per-unit conventions and the intended valuation instant. The date label alone does not prove intraday synchronization.

| Asset | Quantity from holdings | Price from quotes | Market value |
|---|---:|---:|---:|
| ALPHA | 6 | 100 | 600 |
| BETA | 3 | 100 | 300 |
| CASH | 1 | 100 | 100 |

All identifiers and observations are synthetic. There are no fees, distributions, FX conversions, contract multipliers, trades or short positions. CASH is an instrument label without special calculation rules. Total value is 1,000 USD when both key populations match exactly.

A different record grain changes the key. Several account holdings for the same instrument can validly match one reference quote, but those holdings need their own account/position identities. Do not enforce asset uniqueness blindly on transaction or lot-level sources.

## 7.12.4 Join Types and Coverage

| Join type | Key population retained | Financial consequence to inspect |
|---|---|---|
| inner | Keys present on both sides | Unpriced holdings can disappear |
| left | Every left-side key | Holdings remain, but quote fields may be missing |
| right | Every right-side key | Quotes remain, but holdings may be missing |
| outer | Union of both key populations | Exposes missing and extra records for reconciliation |
| cross | Every pair of records | Not a keyed holdings/quote match |

A left join can be appropriate when a quote reference table intentionally covers more instruments than the portfolio. This lab uses a stricter exact-population policy: extra quotes are also reported and block valuation. That policy is explicit, not a universal requirement.

An inner join is not a completeness check. If CASH is absent from quotes, the remaining two holdings can still yield a plausible subtotal of 900. The executable instead returns an outer audit showing CASH as left_only and returns no valuation total.

## 7.12.5 Explicit Keys and Cardinality

```python
audit = holdings.merge(
    quotes,
    on=['asset', 'currency', 'valuation_date'],
    how='outer',
    validate='one_to_one',
    indicator=True,
)
```

Always specify the intended keys. With on omitted, pandas may use common column names, which can accidentally make a shared descriptive field part of the match. Matching only asset can instead combine observations from different dates or currencies.

| Validation | Relationship required |
|---|---|
| one_to_one | Keys unique on both sides |
| one_to_many | Left keys unique; right may repeat |
| many_to_one | Right keys unique; left may repeat |
| many_to_many | Duplicates allowed on both sides; no uniqueness protection |

Cardinality validation checks uniqueness, not full coverage. A one-to-one merge can still contain unmatched keys. Combine it with an indicator check and explicit expected-population policy.

The lab validates duplicate composite keys before merging and also requests one_to_one from pandas. It does not select a first or last duplicate as an unverified winner. For the teaching relationship, duplicates are a source error.

## 7.12.6 How Row Multiplication Happens

If two left records share key A and two right records share key A, an ordinary merge produces four pairs. Summing resulting quantities or market values can inflate exposure. With m left occurrences and n right occurrences, that key contributes m×n output records.

The test demonstrates this four-row result, then verifies that many_to_one rejects the duplicated right reference key. A separate example with two holdings and one quote produces two valid pairs under many_to_one. Those cases have different contracts; the number of rows alone cannot establish correctness.

Duplicate checks before merging also help bound output size. The public one-to-one outer result has at most the sum of the two input row counts. Removing cardinality checks can make even bounded inputs produce a much larger Cartesian result.

## 7.12.7 Missing Keys and Match Evidence

pandas can match null keys to null keys, unlike common SQL null-join behavior. The general mechanical test demonstrates this. The public function rejects null, empty and whitespace-padded key values before merging, so two unknown assets cannot become a valid match.

The merge indicator has three values:

- both: the composite key exists in both sources.
- left_only: holdings exist without a matching quote.
- right_only: a quote exists without a matching holding.

The returned audit preserves quantities and prices where available, leaving unmatched fields missing. It is evidence for investigation, not a partially filled valuation. The function returns result=None and total=None whenever any indicator differs from both.

A matched key does not prove that its price is observed and finite. The source validators check numeric completeness and nonnegative domains independently. Conversely, a complete finite quote table does not prove every expected holding was supplied; holdings-universe completeness still needs external controls.

## 7.12.8 Column Names, Order and Source Identity

The two narrow input schemas overlap only on keys. The merge uses suffixes=(False,False) so an unexpected nonkey overlap cannot be quietly hidden behind x/y columns if the schemas are extended later. Before merging broader sources, resolve similarly named fields explicitly rather than assuming they have the same meaning.

Column-to-column merging does not preserve the original DataFrame indexes as row identities. The lab treats the financial key as identity and sorts the outer result by that composite key, then resets its display index. Input source-row provenance should be carried in explicitly named columns if required by a larger workflow.

Sorting the result keeps each quantity and price attached to its key; source ordering need not match. The tests reverse both inputs and verify identical normalized results. They also confirm output mutation does not alter either input.

## 7.12.9 Merge, Join, Concat and As-Of Matching

`DataFrame.join` can combine index-based data. The test sets the same composite index on each source and performs a validated left join. Index uniqueness and coverage remain application responsibilities.

`pd.concat` stacks or aligns objects along an axis; it does not establish a relational key match automatically. Concatenating daily files also needs cross-file duplicate and schema checks. Attaching quotes by row position because two frames have equal lengths is not a substitute for matching identifiers.

`merge_asof` matches nearby ordered keys rather than exact equal instants. For quotes that means an additional policy: direction, instrument grouping, allowed age and information-availability time. A nearest or forward observation may introduce later information into a historical valuation. This section does not implement temporal matching; exact snapshot keys are required.

## 7.12.11 Complete Reconciliation — merging.py

```python
"""Exact one-to-one holdings/quote reconciliation for a single snapshot."""
import numpy as np
import pandas as pd

KEY=['asset','currency','valuation_date']


def validate(table,measure):
    if not isinstance(table,pd.DataFrame) or not 1<=len(table)<=10_000:
        raise ValueError('DataFrame with 1..10000 rows required')
    if not table.columns.is_unique or table.columns.tolist()!=KEY+[measure]:
        raise ValueError('exact ordered schema required')
    for c in KEY:
        if not table[c].map(lambda x:isinstance(x,str) and 0<len(x)<=64 and x==x.strip()).all():
            raise ValueError('complete trimmed string keys required')
    if not table['currency'].eq('USD').all() or not table['valuation_date'].eq('2026-01-30').all():
        raise ValueError('expected USD / 2026-01-30 snapshot required')
    if table.duplicated(KEY).any(): raise ValueError('duplicate composite key')
    v=table[measure]
    if not isinstance(v.dtype,np.dtype) or v.dtype.kind not in 'iuf':
        raise ValueError('ordinary real numeric measure required')
    a=v.to_numpy(dtype=np.float64,copy=True)
    if not np.isfinite(a).all() or np.any(a<0): raise ValueError('finite nonnegative measure required')
    t=table[KEY].reset_index(drop=True).copy(deep=True); t[measure]=a
    return t


def reconcile(holdings,quotes):
    """Return outer audit, optional complete valuation, and optional total.

    Exact same key population required. Any unmatched row blocks valuation,
    including an extra quote. No fill, fuzzy/as-of matching, or FX conversion.
    """
    h=validate(holdings,'quantity'); q=validate(quotes,'price')
    audit=h.merge(q,on=KEY,how='outer',validate='one_to_one',indicator=True,
                  suffixes=(False,False)).sort_values(KEY).reset_index(drop=True)
    if not audit['_merge'].eq('both').all(): return audit,None,None
    result=audit.drop(columns='_merge').copy(deep=True)
    try:
        with np.errstate(over='raise',invalid='raise'):
            result['market_value']=result['quantity']*result['price']
            total=float(result['market_value'].sum(skipna=False))
    except FloatingPointError as exc:
        raise ValueError('unsupported numerical range') from exc
    if not np.isfinite(result['market_value'].to_numpy()).all() or not np.isfinite(total):
        raise ValueError('nonfinite valuation')
    return audit,result,total


def fixture():
    base={'asset':['ALPHA','BETA','CASH'],'currency':['USD']*3,
          'valuation_date':['2026-01-30']*3}
    return pd.DataFrame({**base,'quantity':[6.,3.,1.]}),pd.DataFrame({**base,'price':[100.,100.,100.]})

if __name__=='__main__':
    h,q=fixture(); audit,result,total=reconcile(h,q.iloc[::-1])
    print(f'Matched={int(audit["_merge"].eq("both").sum())}; total={total:.2f} USD')
    audit,result,total=reconcile(h,q.iloc[:2])
    print('Unmatched assets: '+', '.join(audit.loc[audit['_merge']!='both','asset']))
    print(f'Incomplete valuation: result={result}; total={total}')
```

## 7.12.12 Complete Tests — test_merging.py

```python
import unittest
import numpy as np
import pandas as pd
from merging import reconcile,fixture,KEY

class MergeTests(unittest.TestCase):
    def test_complete_known_answer(self):
        h,q=fixture(); audit,result,total=reconcile(h,q)
        self.assertEqual(total,1000); self.assertTrue(audit['_merge'].eq('both').all())
        self.assertEqual(result['market_value'].tolist(),[600,300,100])
        self.assertEqual(len(result),len(h)); self.assertEqual(result['quantity'].sum(),h['quantity'].sum())

    def test_missing_and_extra_quotes(self):
        h,q=fixture(); audit,result,total=reconcile(h,q.iloc[:2])
        self.assertIsNone(result); self.assertIsNone(total)
        self.assertEqual(audit.loc[audit['_merge']=='left_only','asset'].tolist(),['CASH'])
        extra=q.iloc[[0]].copy(); extra['asset']='OTHER'
        audit,result,total=reconcile(h,pd.concat([q,extra]))
        self.assertEqual(audit.loc[audit['_merge']=='right_only','asset'].tolist(),['OTHER'])
        self.assertIsNone(total)

    def test_duplicate_and_null_keys(self):
        h,q=fixture()
        for bad in [pd.concat([q,q.iloc[[0]]]),q.assign(asset=[None,'BETA','CASH'])]:
            with self.assertRaises(ValueError): reconcile(h,bad)
        with self.assertRaises(ValueError): reconcile(pd.concat([h,h.iloc[[0]]]),q)

    def test_context_and_numeric_rejections(self):
        h,q=fixture()
        for bad in [q.assign(currency='EUR'),q.assign(valuation_date='2026-01-29'),
                    q.assign(price=[np.nan,100,100]),q.assign(price=[-1,100,100]),
                    q.assign(price=['100']*3),q.assign(extra=1)]:
            with self.assertRaises(ValueError): reconcile(h,bad)

    def test_permutation_and_sources(self):
        h,q=fixture(); hc=h.copy(deep=True); qc=q.copy(deep=True)
        a=reconcile(h,q)[1]; b=reconcile(h.iloc[::-1],q.iloc[::-1])[1]
        pd.testing.assert_frame_equal(a,b); b.loc[0,'price']=0
        pd.testing.assert_frame_equal(h,hc); pd.testing.assert_frame_equal(q,qc)

    def test_scalar_oracle_zero_and_overflow(self):
        h,q=fixture(); q['price']=[101.5,80.25,0.]
        _,r,total=reconcile(h,q)
        expected=sum(x*y for x,y in zip(h['quantity'],q['price']))
        self.assertAlmostEqual(total,expected)
        h.loc[0,'quantity']=1e308; q.loc[0,'price']=100
        with self.assertRaises(ValueError): reconcile(h,q)

    def test_multiplication_risk_and_validate(self):
        a=pd.DataFrame({'asset':['A','A'],'quantity':[1,2]})
        b=pd.DataFrame({'asset':['A','A'],'price':[10,11]})
        self.assertEqual(len(a.merge(b,on='asset')),4)
        with self.assertRaises(pd.errors.MergeError): a.merge(b,on='asset',validate='many_to_one')
        # Many holdings to one reference quote is a different valid record grain.
        self.assertEqual(len(a.merge(b.iloc[:1],on='asset',validate='many_to_one')),2)

    def test_null_match_and_join_mechanics(self):
        a=pd.DataFrame({'key':[None],'x':[1]}); b=pd.DataFrame({'key':[None],'y':[2]})
        self.assertEqual(len(a.merge(b,on='key')),1)  # pandas null matching, rejected by public API
        h,q=fixture(); joined=h.set_index(KEY).join(q.set_index(KEY),how='left',validate='one_to_one')
        self.assertEqual(len(joined),3); self.assertFalse(joined['price'].isna().any())

if __name__=='__main__': unittest.main()
```

## 7.12.14 Troubleshooting and Exercises

| Symptom | Likely cause | Action |
|---|---|---|
| Row count grows unexpectedly | Duplicate keys created multiple pairs | Inspect both key populations and enforce expected cardinality |
| Portfolio appears smaller | Inner join removed unmatched holdings | Reconcile with outer indicator evidence |
| Both unknown assets matched | Null-key matching was allowed | Reject missing keys before merging |
| Same instrument receives another day's price | Join key omitted temporal context | Match the intended composite key |
| Extra quote blocks this lab | Exact-population policy is strict | Inspect audit; change policy only with an explicit reference-universe contract |
| Suffix columns obscure meaning | Overlapping nonkey names were not resolved | Rename/validate fields before combining |

1. Remove CASH from quotes and inspect its outer indicator and missing fields.
2. Add an extra quote and explain how this lab differs from an intentional broad-reference left-join workflow.
3. Duplicate a quote key and demonstrate one_to_one rejection.
4. Reproduce the two-by-two key multiplication example and explain its effect on exposure totals.
5. Reverse source ordering and verify the normalized valuation is unchanged.
6. Propose a many_to_one contract for multiple accounts sharing one quote per instrument/date/currency.
7. Explain why a matched calendar-date key does not establish equal intraday valuation times.
8. Design source-row and batch-hash columns that preserve provenance across the merge without making those fields accidental join keys.
