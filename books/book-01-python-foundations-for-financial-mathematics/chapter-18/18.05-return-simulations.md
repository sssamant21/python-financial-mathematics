## Learning objectives

Distinguish simple and log returns; simulate a stated return distribution; convert returns to terminal values; interpret mean, volatility and loss frequency; calculate analytical benchmarks and sampling uncertainty; and document model assumptions and limitations.

## 1. Why simulate returns?

A return model describes possible changes in asset value over a specified period. Simulating many returns can help estimate a model's expected terminal value, probability of loss or payoff distribution. The result is conditional on the assumed distribution, parameters, dependence and horizon; it is not a guarantee of future performance.

Always specify whether the target is a simple return, log return, terminal price, profit or discounted payoff. These quantities have different units and interpretations.

## 2. Simple return

For positive starting value V₀ and ending value V₁:

**R = (V₁−V₀)/V₀**, and **V₁=V₀(1+R)**.

An increase from 100 to 110 produces R=.10, or 10%. A fall from 100 to 90 produces R=−.10. If a nonnegative asset has limited liability, a simple return cannot be less than −1. At exactly −1, the terminal value is zero.

Returns of +10% and then −10% produce 100×1.1×.9=99, a cumulative simple return of −1%. Adding the two returns would incorrectly suggest no change.

## 3. Log return

For positive starting and ending values, the log return is **L=ln(V₁/V₀)=ln(1+R)**. Conversely, **R=exp(L)−1**. Log returns add over periods; simple returns compound multiplicatively.

For a simple return of .10, L=ln(1.1)≈.0953102. For small R, `math.log1p(R)` avoids loss of precision; `math.expm1(L)` computes exp(L)−1 accurately near zero. A terminal value of zero corresponds to R=−1, but its finite log return is undefined.

## 4. Discrete return model

Assume R is −.10 with probability .5 and +.10 with probability .5. Then:

- E[R]=0.
- Var(R)=.01 and standard deviation=.10.
- For V₀=100, terminal values are 90 and 110 and E[V₁]=100.
- Probability of a strictly negative return is .5.

A simulation should approximate these benchmarks within sampling uncertainty. The two-state model is educational and omits most market behavior.

## 5. Normal simple returns

One possible assumption is R~Normal(μ,σ²), with μ and σ describing a specified period. This distribution is unbounded below: it can generate R<−1 and hence negative terminal values under V₁=V₀(1+R). Do not silently clip or discard such values: either changes the modeled distribution. Choose a model consistent with the asset and the question.

Annualizing or scaling μ and σ requires additional assumptions about time, independence and the model. Multiplying a monthly standard deviation by √12, for example, is not universally valid.

## 6. Normal log returns

For a one-period illustration, suppose **L~Normal(m,s²)**. Then terminal value is V₁=V₀exp(L), and simple return is exp(L)−1. In exact arithmetic V₁ is positive, though finite floating-point calculations may overflow or underflow.

The model implies:

**E[V₁]=V₀ exp(m+s²/2)** and **E[R]=exp(m+s²/2)−1**.

Thus m is the mean log return, not the mean simple return. When s>0, the probability V₁<V₀ is Φ(−m/s), where Φ is the standard normal CDF. At s=0 the outcome is deterministic and must be handled separately.

These formulas hold for the stated distribution, not for every real asset. Jumps, fat tails, volatility changes and dependence can make a normal log-return model inappropriate.

## 7. Worked benchmark

Let V₀=100, m=.04 and s=.20 for one year. The model's expected terminal value is:

**100 exp(.04+.20²/2)=100 exp(.06)≈106.18365.**

Expected simple return is approximately 6.18365%. Median terminal value is **100 exp(.04)≈104.08108**. The mean exceeds the median because the lognormal distribution is right-skewed. The loss probability is Φ(−.2)≈**.42074**.

The parameters above are mean and standard deviation of the one-year **log return**, not a forecast or investment recommendation.

## 8. Estimation and uncertainty

For N independent draws, estimate E[R] by the sample mean. Estimate its standard error using sample standard deviation / √N when independent, finite-variance assumptions apply. The sample loss frequency estimates the model loss probability; its uncertainty should use a suitable binomial method.

More paths reduce sampling error, typically at the rate 1/√N, but do not remove model error, parameter uncertainty or implementation bias. One larger simulation need not be closer to the benchmark than every smaller one.

## 9. Measure and discounting

For an expected one-year payoff under a specified probability model and constant effective rate r>−1, its arithmetic discounted expectation is E[V₁]/(1+r). A real-world return distribution does not automatically produce a market-consistent price. Risk-neutral valuation requires appropriate risk-neutral dynamics and discounting; specify the intended use and measure.

## 10. Reproducibility and validation

Record the generator, seed, code revision, Python and library versions, count, horizon, return type, parameters and units. Check input domains, finite results and analytical benchmarks. Test deterministic cases such as s=0 and compare simulations over independent replications, interpreting sampling variation.

A fixed seed supports replay in a compatible environment but does not prove the model or generator is correct. A normal distribution's tail can trigger extreme values; handle overflow and underflow explicitly rather than reporting misleading results.

## 11. Reference implementation

Save as `return_simulations.py`. The code uses Python's standard-library generator and simulates independent one-period normal **log** returns. It is instructional and is not a production pricing or risk engine.

~~~python
import math
import random
import statistics
import unittest

def simulate_log_returns(mean_log, sd_log, count, seed):
    if any(type(x) not in (int,float) or not math.isfinite(x)
           for x in (mean_log,sd_log)) or sd_log < 0:
        raise ValueError("finite mean and nonnegative standard deviation required")
    if type(count) is not int or count < 2 or type(seed) is not int:
        raise ValueError("count >= 2 and integer seed required")
    rng = random.Random(seed)
    return [rng.normalvariate(mean_log,sd_log) for _ in range(count)]

def terminal_values(initial, log_returns):
    if type(initial) not in (int,float) or not math.isfinite(initial) or initial <= 0:
        raise ValueError("positive finite initial value required")
    values = []
    for x in log_returns:
        if type(x) not in (int,float) or not math.isfinite(x):
            raise ValueError("finite log returns required")
        try:
            value = initial*math.exp(x)
        except OverflowError as exc:
            raise ValueError("terminal value overflow") from exc
        if not math.isfinite(value) or value <= 0:
            raise ValueError("terminal value overflow or underflow")
        values.append(value)
    return values

def summarize(values, initial):
    values = list(values)
    if type(initial) not in (int,float) or not math.isfinite(initial) or initial <= 0:
        raise ValueError("positive finite initial value required")
    if len(values) < 2 or any(type(v) not in (int,float)
                              or not math.isfinite(v) or v <= 0 for v in values):
        raise ValueError("at least two positive finite terminal values required")
    mean = statistics.mean(values)
    return {
        "count": len(values),
        "mean_terminal": mean,
        "mean_simple_return": mean/initial-1,
        "standard_error_terminal": statistics.stdev(values)/math.sqrt(len(values)),
        "loss_frequency": sum(v < initial for v in values)/len(values),
    }

def expected_terminal(initial, mean_log, sd_log):
    if any(type(x) not in (int,float) or not math.isfinite(x)
           for x in (initial,mean_log,sd_log)) or initial <= 0 or sd_log < 0:
        raise ValueError("invalid model inputs")
    try:
        result = initial*math.exp(mean_log + sd_log*sd_log/2)
    except OverflowError as exc:
        raise ValueError("expectation overflow") from exc
    if not math.isfinite(result) or result <= 0:
        raise ValueError("expectation overflow or underflow")
    return result

class ReturnTests(unittest.TestCase):
    def test_seed_replay(self):
        self.assertEqual(simulate_log_returns(.04,.2,10,42),
                         simulate_log_returns(.04,.2,10,42))
    def test_zero_volatility(self):
        self.assertEqual(simulate_log_returns(.04,0,3,42),[.04]*3)
    def test_terminal_zero_return(self):
        self.assertEqual(terminal_values(100,[0,0]),[100,100])
    def test_terminal_known(self):
        self.assertAlmostEqual(terminal_values(100,[math.log(1.1)])[0],110)
    def test_expectation(self):
        self.assertAlmostEqual(expected_terminal(100,.04,.2),100*math.exp(.06))
    def test_constant_summary(self):
        result = summarize([100,100],100)
        self.assertEqual(result["mean_simple_return"],0)
        self.assertEqual(result["loss_frequency"],0)
        self.assertEqual(result["standard_error_terminal"],0)
    def test_loss_threshold(self):
        self.assertEqual(summarize([90,100,110],100)["loss_frequency"],1/3)
    def test_bad_volatility(self):
        with self.assertRaises(ValueError): simulate_log_returns(0,-.1,10,1)
    def test_bad_initial(self):
        with self.assertRaises(ValueError): terminal_values(0,[0])
    def test_bad_count(self):
        with self.assertRaises(ValueError): simulate_log_returns(0,.1,1,1)

if __name__ == "__main__":
    draws = simulate_log_returns(.04,.2,10000,42)
    print("simulation:", summarize(terminal_values(100,draws),100))
    print("analytical mean:", expected_terminal(100,.04,.2))
    unittest.main(verbosity=2)
~~~

The implementation rejects floating-point terminal values that overflow or underflow to zero. It does not claim to support every representable parameter combination or model market behavior.

## 14. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Negative terminal value under normal simple returns | Distribution permits R<−1 | Reconsider the return model |
| Mean differs from median | Right-skewed terminal distribution | Compare each with the correct analytical quantity |
| Sample mean differs from benchmark | Sampling variation or implementation error | Inspect standard error and repeat independent runs |
| Overflow or zero terminal value | Extreme log return or finite precision | Review parameters and numerical representation |
| Same seed produces different outputs | Generator, environment or draw order changed | Record and compare run metadata |
| Accurate benchmark but implausible forecast | Model assumptions unsuitable | Assess parameters, dependence and tails |
