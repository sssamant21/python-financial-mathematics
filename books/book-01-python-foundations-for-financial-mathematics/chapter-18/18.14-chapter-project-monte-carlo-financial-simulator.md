## Project objectives

Build a reproducible one-period simulator that generates financial outcomes, estimates expected terminal value and sampling error, reports loss frequency and empirical tail measures, and compares results with an analytical benchmark. Explain conventions, assumptions and model limitations before interpreting results.

This project integrates simulation fundamentals, random generators, scenario modeling, Monte Carlo estimation, convergence, confidence, risk and computational tradeoffs from Sections 18.1–18.13.

## 1. Project scenario

An investment costs 100 at time zero. Its modeled one-year terminal value is:

| State | Probability | Terminal value | Loss (100 − value) |
|---|---:|---:|---:|
| Down | .25 | 80 | 20 |
| Flat | .50 | 100 | 0 |
| Up | .25 | 120 | −20 |

The exact expected terminal value is **100**, variance is **200**, and probability of a strictly positive loss is **.25**. The theoretical standard error of the mean for 10,000 independent draws is √200/100≈**.14142**.

The model is a teaching example, not a forecast or a market-calibrated distribution. It has one position, one period, fixed probabilities and no fees, taxes, intermediate cash flows, rebalancing or transaction costs.

## 2. Project requirements

The simulator must:

1. Generate independent modeled state draws using a local seeded generator.
2. Calculate terminal value, mean, sample standard deviation and estimated standard error.
3. Report loss frequency under the definition loss>0.
4. Calculate empirical Value at Risk and Expected Shortfall using stated conventions.
5. Record sample count, seed, generator, confidence level and model assumptions.
6. Support analytical and deterministic test cases.
7. Surface invalid input rather than silently correcting it.

The exact benchmark describes the model. Simulation results fluctuate; a mismatch must be interpreted against sampling uncertainty and investigated when warranted.

## 3. Risk conventions

Define loss **L=initial value−terminal value**. A positive loss is adverse; a negative loss is a gain.

For sorted equally weighted losses and α in (0,1), use nearest-rank empirical VaR with k=ceil(αN), one-based. Empirical ES is the average of the upper N(1−α) observation-equivalents, using a fractional boundary weight where necessary.

For [−10,0,20,40] and α=.75, VaR=20 and ES=40. With discrete masses, the probability strictly above VaR can be less than 1−α. Other packages may use different interpolation or tail conventions.

In the three-state project model, at α=.75 the **population** VaR is 0 and ES is 20. A finite empirical sample can yield a different VaR because counts fluctuate around the distribution boundary. ES and VaR are not maximum possible losses.

## 4. Sampling uncertainty

For independent, finite-variance paths, estimated standard error of the mean is sample standard deviation divided by √N. For a loss-frequency estimate p̂, the usual plug-in Bernoulli SE is √[p̂(1−p̂)/N], but it is misleading at zero or one; use an appropriate binomial interval when needed.

Quantile and ES uncertainty cannot generally be inferred from the standard error of the mean. Investigate tail stability using suitable independent replications or another method appropriate to the estimator and sampling design.

## 5. Discounting and measure

At an annual effective rate r>−1, a one-year terminal payoff has present value V₁/(1+r). For the project distribution at r=.05, the arithmetic discounted expected payoff is **100/1.05≈95.2381**.

This is a calculation under the specified probabilities and rate. It is not automatically a market-consistent price; a pricing use requires appropriate risk-neutral dynamics, discounting and instrument conventions. The code reports undiscounted terminal values and losses.

## 6. Architecture

The implementation separates model sampling, summary calculation, risk measures and reporting. It retains outcomes to calculate exact empirical order statistics, so memory grows with the number of paths. For large workloads, consider batching or a validated selection/sketch approach; approximate quantiles need their own error assessment.

A run record should include seed, generator, path count, model, confidence level, software version and code revision. The example prints configuration; retain the rest as external run evidence.

## 7. Reference implementation

Save as `monte_carlo_financial_simulator.py`.

~~~python
import math
import random
import statistics
import unittest

def finite(x):
    return type(x) in (int,float) and math.isfinite(x)

def sample_values(count, seed):
    if type(count) is not int or count < 2 or type(seed) is not int:
        raise ValueError("count >= 2 and integer seed required")
    rng=random.Random(seed)
    values=[]
    for _ in range(count):
        u=rng.random()
        values.append(80.0 if u < .25 else (100.0 if u < .75 else 120.0))
    return values

def losses_from_values(initial, values):
    if not finite(initial) or initial <= 0:
        raise ValueError("positive finite initial value required")
    vals=list(values)
    if not vals or any(not finite(x) or x < 0 for x in vals):
        raise ValueError("nonempty nonnegative finite values required")
    losses=[initial-x for x in vals]
    if not all(math.isfinite(x) for x in losses):
        raise ValueError("nonfinite loss")
    return losses

def empirical_risk(losses, alpha):
    vals=list(losses)
    if not vals or not all(finite(x) for x in vals):
        raise ValueError("nonempty finite losses required")
    if not finite(alpha) or not 0 < alpha < 1:
        raise ValueError("alpha must be in (0,1)")
    vals.sort()
    n=len(vals)
    rank=math.ceil(alpha*n)
    var=vals[rank-1]
    tail_count=(1-alpha)*n
    full=math.floor(tail_count)
    fraction=tail_count-full
    total=math.fsum(vals[-full:]) if full else 0.0
    if fraction > 0:
        total += fraction*vals[-full-1]
    es=total/tail_count
    if not math.isfinite(es):
        raise ValueError("nonfinite ES")
    return var,es

def report(values, initial, alpha):
    vals=list(values)
    if len(vals)<2:
        raise ValueError("at least two values required")
    losses=losses_from_values(initial,vals)
    var,es=empirical_risk(losses,alpha)
    return {
        "count":len(vals),
        "mean_terminal":statistics.mean(vals),
        "sample_sd":statistics.stdev(vals),
        "standard_error_mean":statistics.stdev(vals)/math.sqrt(len(vals)),
        "loss_frequency":sum(x>0 for x in losses)/len(losses),
        "alpha":alpha,
        "var_nearest_rank":var,
        "es_fractional_tail":es,
    }

class SimulatorTests(unittest.TestCase):
    def test_replay(self):
        self.assertEqual(sample_values(20,42),sample_values(20,42))
    def test_support(self):
        self.assertTrue(all(x in (80,100,120) for x in sample_values(100,1)))
    def test_loss_sign(self):
        self.assertEqual(losses_from_values(100,[110,100,80]),[-10,0,20])
    def test_known_mean(self):
        self.assertEqual(report([80,100,120],100,.75)["mean_terminal"],100)
    def test_known_sd(self):
        self.assertAlmostEqual(report([80,100,120],100,.75)["sample_sd"],20)
    def test_loss_frequency(self):
        self.assertEqual(report([80,100,120,80],100,.75)["loss_frequency"],.5)
    def test_var(self):
        self.assertEqual(empirical_risk([-10,0,20,40],.75)[0],20)
    def test_es(self):
        self.assertEqual(empirical_risk([-10,0,20,40],.75)[1],40)
    def test_fractional_tail(self):
        self.assertAlmostEqual(empirical_risk([-10,0,20,40],.625)[1],100/3)
    def test_bad_alpha(self):
        with self.assertRaises(ValueError): empirical_risk([1,2],1)
    def test_bad_count(self):
        with self.assertRaises(ValueError): sample_values(1,42)
    def test_nonfinite(self):
        with self.assertRaises(ValueError): losses_from_values(100,[float("nan")])

if __name__ == "__main__":
    count,seed,alpha=10000,42,.75
    print("model: three-state one-period; generator: random.Random")
    print("seed:",seed,"paths:",count,"alpha:",alpha)
    print(report(sample_values(count,seed),100,alpha))
    unittest.main(verbosity=2)
~~~

The normal mean SE assumes independent paths and finite variance. The empirical risk routine assumes equally weighted paths and uses ordinary floating-point arithmetic; quantile boundary rounding should be reviewed for production. It is not a complete risk engine or a measure of model uncertainty.

## 11. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Mean differs from 100 | Sampling variation or mapping error | Compare SE and inspect state mapping |
| VaR differs between runs | Quantile near a discrete mass boundary | Review counts and convention |
| ES differs from another tool | Different tail weighting or interpolation | Align definitions |
| Loss sign appears reversed | Profit used as loss | Check initial minus terminal |
| Very small SE but unrealistic risk | Model or input error | Review assumptions and independent stress cases |
| Identical workers | Duplicate streams | Inspect generator setup and assignments |
