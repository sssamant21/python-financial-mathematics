## Learning objectives

Simulate a sequence of prices under explicit assumptions; distinguish drift from volatility and simple from log returns; use a geometric Brownian motion (GBM) model on a time grid; compare terminal results with analytical benchmarks; and explain sampling, monitoring and model limitations.

## 1. Why simulate a path?

A terminal price describes the end of a period. A path describes values at multiple times between the start and end. This distinction matters for a payoff depending on an average, a barrier or an intermediate loss.

A simulated path is a possible outcome under a chosen model, not a guaranteed forecast. Define the horizon, time grid, units, probability measure, assumptions and payoff before generating paths.

## 2. Compounding on a grid

For simple period returns R₁,…,Rₙ, price evolves as **Sᵢ=Sᵢ₋₁(1+Rᵢ)**. For log returns Lᵢ, **Sᵢ=Sᵢ₋₁ exp(Lᵢ)**. Log returns add, while simple returns compound.

For S₀=100, returns +10% and −10% lead to 110 then 99. The cumulative return is −1%, not 0%.

The time step must be consistent with the model's annualized parameters. A normal model for simple returns can generate R<−1 and a negative price; this chapter uses a log-price model instead.

## 3. Geometric Brownian motion

One common model is:

**dSₜ=μSₜdt+σSₜdWₜ**, with S₀>0 and σ≥0.

Here μ is the annualized drift of the price process, σ is annualized volatility, and W is Brownian motion under the chosen probability measure. For constant parameters, the exact update over Δt years is:

**Sₜ₊Δt = Sₜ exp[(μ−σ²/2)Δt + σ√Δt Z]**, with independent standard normal Z for non-overlapping time steps.

The −σ²/2 term appears in the log-price drift. μ is not the expected log return per year; that quantity is μ−σ²/2. In exact arithmetic prices stay positive. Floating-point overflow or underflow can still occur.

This update is exact at the sampled grid times for constant-parameter GBM. It does not make the model realistic or reveal what happens between grid points.

## 4. Units and time grid

With T measured in years and n equal steps, Δt=T/n. One year with 12 steps uses Δt=1/12 year. Annualized σ is multiplied by √Δt and the log drift by Δt. For an irregular grid, use each interval's length and validate that times increase.

A step count controls the observation grid, not the number of independent paths. For path-dependent quantities, a finer grid can change the result even when the exact GBM update is used at each grid point.

## 5. Drift and probability measure

Under a specified measure with constant μ, GBM has **E[Sₜ]=S₀e^(μt)** and **median(Sₜ)=S₀e^((μ−σ²/2)t)**. The mean and median differ when volatility is nonzero.

Real-world drift and risk-neutral drift have different purposes. Under suitable risk-neutral assumptions for an asset with no payouts, the drift is the continuously compounded risk-free rate; dividends, financing and other details change the setup. Do not substitute an estimated real-world drift into a pricing calculation without justification.

## 6. Analytical benchmark

For S₀=100, μ=.05, σ=.20 and T=1 year, the GBM model gives:

- Expected terminal price: **100e^.05 ≈ 105.12711**.
- Median terminal price: **100e^(.05−.20²/2)=100e^.03 ≈ 103.04545**.
- Standard deviation of log terminal price relative to log S₀: **σ√T=.20**.

At σ=0 the path is deterministic, Sₜ=S₀e^(μt), which provides a useful code benchmark. The analytical mean is an expectation under the specified model, not a promise about a realized asset.

## 7. Terminal and path-dependent outcomes

For terminal payoff max(Sₜ−K,0), only the terminal price is needed once the model and payoff are specified. An average-price payoff requires intermediate observations; a barrier payoff depends on whether a threshold is crossed.

A path recorded at discrete dates can miss a barrier crossing between dates. A finer monitoring grid can reduce this monitoring error but does not generally eliminate it; continuous-monitoring adjustments or bridge methods require separate assumptions and validation.

## 8. Sampling and error

For independent paths with finite-variance terminal values, estimate E[Sₜ] with the sample mean and its standard error by sample standard deviation divided by √N. Four times as many paths approximately halves sampling standard error. A larger individual run need not always be closer to the benchmark.

Separate sampling error from model error, parameter uncertainty, floating-point error and monitoring/discretization effects. More paths do not fix an unsuitable model or missing between-grid crossings.

## 9. Reproducibility

Record S₀, μ, σ, T, steps, path count, seed, generator, versions, measure and output conventions. A seed supports replay only with compatible generator behavior, input order and environment. For parallel work, use documented stream spawning; duplicated streams can invalidate uncertainty estimates.

## 10. Reference implementation

Save as `price_path_simulation.py`. It uses exact constant-parameter GBM updates on an equally spaced grid and a local standard-library generator. It is educational and does not model dividends, jumps, stochastic volatility, transaction costs or continuous barrier monitoring.

~~~python
import math
import random
import statistics
import unittest

def simulate_paths(initial, drift, volatility, horizon, steps, count, seed):
    inputs = (initial, drift, volatility, horizon)
    if any(type(x) not in (int, float) or not math.isfinite(x) for x in inputs):
        raise ValueError("finite numeric parameters required")
    if initial <= 0 or volatility < 0 or horizon <= 0:
        raise ValueError("positive initial and horizon, nonnegative volatility required")
    if type(steps) is not int or steps < 1 or type(count) is not int or count < 2:
        raise ValueError("positive steps and at least two paths required")
    if type(seed) is not int:
        raise ValueError("integer seed required")
    dt = horizon/steps
    rng = random.Random(seed)
    paths = []
    for _ in range(count):
        price = initial
        path = [price]
        for _ in range(steps):
            z = rng.normalvariate(0,1)
            exponent = (drift-volatility**2/2)*dt + volatility*math.sqrt(dt)*z
            try:
                price *= math.exp(exponent)
            except OverflowError as exc:
                raise ValueError("price overflow") from exc
            if not math.isfinite(price) or price <= 0:
                raise ValueError("price overflow or underflow")
            path.append(price)
        paths.append(path)
    return paths

def summarize_terminal(paths):
    paths = list(paths)
    if len(paths) < 2 or any(not p for p in paths):
        raise ValueError("at least two nonempty paths required")
    terminal = [p[-1] for p in paths]
    if any(type(v) not in (int,float) or not math.isfinite(v) or v <= 0
           for v in terminal):
        raise ValueError("positive finite terminal values required")
    return {
        "count": len(terminal),
        "mean": statistics.mean(terminal),
        "standard_error": statistics.stdev(terminal)/math.sqrt(len(terminal)),
    }

def expected_terminal(initial, drift, horizon):
    if any(type(x) not in (int,float) or not math.isfinite(x)
           for x in (initial,drift,horizon)) or initial <= 0 or horizon < 0:
        raise ValueError("invalid benchmark inputs")
    try:
        value = initial*math.exp(drift*horizon)
    except OverflowError as exc:
        raise ValueError("benchmark overflow") from exc
    if not math.isfinite(value) or value <= 0:
        raise ValueError("benchmark overflow or underflow")
    return value

def observed_barrier_hit(path, barrier):
    if type(barrier) not in (int,float) or not math.isfinite(barrier) or barrier <= 0:
        raise ValueError("positive finite barrier required")
    if not path or any(type(x) not in (int,float) or not math.isfinite(x) or x <= 0
                       for x in path):
        raise ValueError("nonempty positive finite path required")
    # Includes time zero; this is discrete monitoring only.
    return any(x <= barrier for x in path)

class PathTests(unittest.TestCase):
    def test_replay(self):
        args=(100,.05,.2,1,4,3,42)
        self.assertEqual(simulate_paths(*args),simulate_paths(*args))
    def test_shape(self):
        paths=simulate_paths(100,.05,.2,1,4,3,42)
        self.assertEqual(len(paths),3)
        self.assertTrue(all(len(p)==5 for p in paths))
    def test_initial(self):
        self.assertTrue(all(p[0]==100 for p in simulate_paths(100,.05,.2,1,4,3,42)))
    def test_positive(self):
        self.assertTrue(all(v>0 for p in simulate_paths(100,.05,.2,1,4,3,42) for v in p))
    def test_zero_volatility(self):
        paths=simulate_paths(100,.05,0,1,4,3,42)
        for path in paths:
            self.assertAlmostEqual(path[-1],100*math.exp(.05))
    def test_benchmark(self):
        self.assertAlmostEqual(expected_terminal(100,.05,1),100*math.exp(.05))
    def test_barrier(self):
        self.assertTrue(observed_barrier_hit([100,95,90],95))
        self.assertFalse(observed_barrier_hit([100,96,97],95))
    def test_summary(self):
        result=summarize_terminal([[100,90],[100,110]])
        self.assertEqual(result["mean"],100)
        self.assertAlmostEqual(result["standard_error"],10)
    def test_invalid_volatility(self):
        with self.assertRaises(ValueError): simulate_paths(100,.05,-.2,1,4,3,42)
    def test_invalid_steps(self):
        with self.assertRaises(ValueError): simulate_paths(100,.05,.2,1,0,3,42)

if __name__ == "__main__":
    paths=simulate_paths(100,.05,.2,1,12,10000,42)
    print("terminal summary:",summarize_terminal(paths))
    print("analytical mean:",expected_terminal(100,.05,1))
    unittest.main(verbosity=2)
~~~

The standard error test uses sample standard deviation: for terminal values 90 and 110, s=√200 and s/√2=10. The implementation rejects detected overflow or underflow; it does not guarantee support for every finite extreme parameter.

## 13. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Simulated mean differs from benchmark | Sampling variation or code defect | Compare SE and independent runs |
| Price becomes zero or infinite | Underflow, overflow or extreme inputs | Inspect units and model parameters |
| Barrier rate changes with steps | Discrete monitoring | Examine grid and continuous-monitoring assumptions |
| Different results with same seed | Changed generator or draw order | Compare run metadata and environment |
| Plausible mean but unrealistic tails | Model misspecification | Review calibration, jumps and volatility assumptions |
| Identical parallel paths | Duplicate random streams | Inspect seed and stream spawning |
