## Learning objectives

Explain pseudorandom generators, state and seeds; generate uniform and normally distributed samples; distinguish simulation randomness from cryptographic randomness; manage streams and reproducibility; and design checks and evidence for financial simulations.

## 1. Randomness in a simulation

Monte Carlo methods use samples from specified probability distributions to approximate model quantities. A generator supplies a reproducible sequence of numbers that algorithms transform into draws from the desired distribution.

A generated value is an input to a model, not a prediction of an individual market outcome. Incorrect parameters, dependence assumptions or financial conventions remain incorrect even if the generator is excellent.

## 2. Pseudorandom generators

A pseudorandom number generator (PRNG) is a deterministic algorithm with internal state. It advances that state to produce a sequence designed to have useful statistical properties. Given the same algorithm, state and sequence of operations, it produces the same output.

A **seed** initializes the generator state. The state changes with each draw. A **period** is the length of a cycle for a finite-state generator; a long period alone does not establish quality, independence, or fitness for a particular simulation.

Python's standard `random.Random` is based on Mersenne Twister. It is useful for many simulations but is **not cryptographically secure**. Use Python's `secrets` module for security tokens and other security-sensitive randomness.

## 3. Uniform samples

A uniform draw U on [0,1) lies in that interval and has theoretical mean 1/2 and variance 1/12. A finite sample's mean and variance fluctuate; agreement with these values is a basic check, not a proof of generator quality.

~~~python
import random

rng = random.Random(2026)
draws = [rng.random() for _ in range(5)]
print(draws)
~~~

A local generator avoids accidental interference from unrelated code sharing module-level state.

## 4. From uniform draws to outcomes

For an event of probability p in [0,1], the indicator **1{U<p}** has a Bernoulli distribution with theoretical mean p, assuming U is uniform. At p=0 it is always zero; at p=1 it is always one because U<1.

An asset with initial value 100 and return +10% with probability .6, or −10% otherwise, has expected terminal value .6(110)+.4(90)=**102**. A simulated average estimates this model expectation.

## 5. Other distributions

Transformations or dedicated algorithms use random bits or uniform samples to generate other distributions. A normal draw with mean μ and standard deviation σ has theoretical mean μ and variance σ². Do not confuse standard deviation with variance.

A normal model for simple returns can produce returns below −100%, implying a negative terminal price in the elementary formula V₁=V₀(1+R). Choose and justify an appropriate model; do not silently discard adverse draws without understanding the resulting distribution.

~~~python
import random

rng = random.Random(42)
samples = [rng.normalvariate(0.05, 0.15) for _ in range(5)]
print(samples)
~~~

These are illustrative annual simple returns with μ=.05 and σ=.15, not a recommendation or an established market forecast.

## 6. Python and NumPy

Python's `random.Random(seed)` maintains a separate standard-library generator. NumPy's `numpy.random.default_rng(seed)` returns a `Generator` intended for array-based numerical work. Do not assume equal seeds across different libraries or generator algorithms produce the same draws.

~~~python
import numpy as np

rng = np.random.default_rng(42)
uniform = rng.random(10000)
normal = rng.normal(loc=0.05, scale=0.15, size=10000)
print(uniform.mean(), normal.mean())
~~~

Record Python, NumPy and generator versions and the explicit generator/bit generator where relevant. A seed alone does not ensure identical results across arbitrary library versions, platforms, algorithms, vectorization or changes in draw order.

## 7. State and draw order

Generating one extra sample advances state and changes later samples. Capturing and restoring state can replay a sequence within a compatible environment. Record the generator type, seed, code revision, configuration and operation order for an auditable run.

~~~python
import random

rng = random.Random(10)
saved = rng.getstate()
first = rng.random()
rng.setstate(saved)
assert rng.random() == first
~~~

Persisted generator state should be handled as run metadata; it does not replace the model inputs and code.

## 8. Independent streams and parallel work

Seeding every worker identically can duplicate streams and cause falsely low estimated uncertainty. Different arbitrary seeds do not by themselves prove statistical independence or non-overlap. Use a generator's documented stream-spawning or jump mechanism and retain worker-to-stream assignments.

NumPy's `SeedSequence.spawn` is one supported way to derive child streams:

~~~python
import numpy as np

parent = np.random.SeedSequence(2026)
children = parent.spawn(4)
workers = [np.random.default_rng(child) for child in children]
print([worker.random() for worker in workers])
~~~

Treat streams as designed to be very probably independent, not a mathematical guarantee of non-overlap. Record the NumPy version, parent seed, number of children, assignment, and configuration. Reproducibility also requires a stable work partition and ordering.

## 9. Correlation is a model choice

Independent random streams are not a substitute for correctly modeling dependent financial variables. If two asset returns should be correlated, generate them using an appropriate joint model and validate its covariance or correlation assumptions. Conversely, identical streams can accidentally create unwanted dependence.

For two standard normal variables, one construction with desired correlation ρ in [−1,1] is:

**Y = ρZ₁ + √(1−ρ²)Z₂**, where Z₁ and Z₂ are independent standard normal variables. In the ideal model, Corr(Z₁,Y)=ρ. A finite sample's measured correlation will vary.

## 10. Generator checks and limits

Inspect range, sample mean and variance, and compare a modeled payoff with an independently calculated benchmark. Check stream duplication and replay behavior. Formal distribution and dependence tests can identify defects, but passing a finite set of tests does not prove randomness or validate a model. Statistical failures and ordinary sampling fluctuations must be interpreted in context.

For independent finite-variance samples, standard error of a sample mean is estimated by s/√N. Increasing samples by four approximately halves standard error, while bias from wrong inputs or discretization can remain.

## 11. Reference implementation

Save as `random_generators.py`. It uses local standard-library generators and includes educational checks. It does not implement parallel stream splitting, rigorous generator certification, or production risk modeling.

~~~python
import math
import random
import statistics
import unittest

def uniform_draws(count, seed):
    if type(count) is not int or count < 2 or type(seed) is not int:
        raise ValueError("count >= 2 and integer seed required")
    rng = random.Random(seed)
    return [rng.random() for _ in range(count)]

def bernoulli_draws(probability, count, seed):
    if type(probability) not in (int, float) or not math.isfinite(probability):
        raise ValueError("finite probability required")
    if not 0 <= probability <= 1:
        raise ValueError("probability must be in [0, 1]")
    return [int(u < probability) for u in uniform_draws(count, seed)]

def normal_draws(mean, sd, count, seed):
    if any(type(x) not in (int, float) or not math.isfinite(x)
           for x in (mean, sd)) or sd < 0:
        raise ValueError("finite mean and nonnegative standard deviation required")
    if type(count) is not int or count < 2 or type(seed) is not int:
        raise ValueError("count >= 2 and integer seed required")
    rng = random.Random(seed)
    return [rng.normalvariate(mean, sd) for _ in range(count)]

def summary(values):
    vals = list(values)
    if len(vals) < 2 or any(type(v) not in (int, float)
                            or not math.isfinite(v) for v in vals):
        raise ValueError("at least two finite numeric observations required")
    return {"count": len(vals), "mean": statistics.mean(vals),
            "sample_variance": statistics.variance(vals),
            "standard_error": statistics.stdev(vals)/math.sqrt(len(vals))}

def terminal_values(initial, up_return, down_return, outcomes):
    if any(type(x) not in (int,float) or not math.isfinite(x)
           for x in (initial, up_return, down_return)):
        raise ValueError("finite inputs required")
    if initial <= 0 or min(up_return, down_return) < -1:
        raise ValueError("positive initial value and returns >= -1 required")
    outcomes = list(outcomes)
    if any(type(x) is not int or x not in (0,1) for x in outcomes):
        raise ValueError("outcomes must be integer 0 or 1")
    up, down = initial*(1+up_return), initial*(1+down_return)
    if not math.isfinite(up) or not math.isfinite(down):
        raise ValueError("nonfinite terminal value")
    return [up if x else down for x in outcomes]

class GeneratorTests(unittest.TestCase):
    def test_replay(self):
        self.assertEqual(uniform_draws(20,42),uniform_draws(20,42))
    def test_range(self):
        self.assertTrue(all(0 <= u < 1 for u in uniform_draws(100,1)))
    def test_probability_zero(self):
        self.assertEqual(bernoulli_draws(0,5,1),[0]*5)
    def test_probability_one(self):
        self.assertEqual(bernoulli_draws(1,5,1),[1]*5)
    def test_normal_zero_sd(self):
        self.assertEqual(normal_draws(2,0,4,1),[2]*4)
    def test_known_summary(self):
        result = summary([0,1,0,1])
        self.assertEqual(result["mean"],.5)
        self.assertAlmostEqual(result["sample_variance"],1/3)
    def test_terminal_value(self):
        for value, expected in zip(terminal_values(100,.1,-.1,[1,0]),[110,90]):
            self.assertAlmostEqual(value,expected)
    def test_bad_probability(self):
        with self.assertRaises(ValueError): bernoulli_draws(1.1,10,1)
    def test_bad_sd(self):
        with self.assertRaises(ValueError): normal_draws(0,-1,10,1)
    def test_bad_return(self):
        with self.assertRaises(ValueError): terminal_values(100,.1,-1.1,[0])

if __name__ == "__main__":
    events = bernoulli_draws(.6,10000,42)
    print(summary(terminal_values(100,.1,-.1,events)))
    unittest.main(verbosity=2)
~~~

## 13. Forty worked exercises

1. **PRNG:** Is its sequence deterministic given its state? **Answer:** Yes.
2. **Seed:** What does it initialize? **Answer:** Generator state.
3. **State:** What happens after a draw? **Answer:** The generator advances its state.
4. **Replay:** Same state and operations? **Answer:** Same sequence in a compatible implementation.
5. **Uniform:** Range of Python random()? **Answer:** [0,1).
6. **Uniform mean:** Theoretical value? **Answer:** .5.
7. **Uniform variance:** Theoretical value? **Answer:** 1/12.
8. **Bernoulli:** P(U<.6)? **Answer:** .6 under an ideal uniform model.
9. **p=0:** What outcome? **Answer:** Always zero.
10. **p=1:** What outcome? **Answer:** Always one.
11. **Financial outcome:** 100 with +10%. **Answer:** 110.
12. **Down outcome:** 100 with −10%. **Answer:** 90.
13. **Expected value:** p=.6. **Answer:** .6×110+.4×90=102.
14. **Normal:** Mean .05, SD .15. Variance? **Answer:** .0225.
15. **Sample mean:** Must it equal theoretical mean? **Answer:** No.
16. **Sample variance:** Must it equal theoretical variance? **Answer:** No.
17. **Seed across libraries:** Same values guaranteed? **Answer:** No.
18. **Draw order:** Does an extra draw matter? **Answer:** It advances state and changes later values.
19. **Global state:** Why prefer a local generator? **Answer:** It reduces unintended interference.
20. **Security:** Is random.Random suitable for security tokens? **Answer:** No; use a cryptographic source such as secrets.
21. **Period:** Does a long period alone prove quality? **Answer:** No.
22. **Parallel workers:** Same seed on every worker? **Answer:** May duplicate streams.
23. **Different seeds:** Do they prove independence? **Answer:** No.
24. **Spawn:** Why use documented stream spawning? **Answer:** It provides a supported method to derive child streams.
25. **Correlation:** Do independent streams automatically model correlated assets? **Answer:** No.
26. **Correlation formula:** ρ=0. **Answer:** Y=Z₂ in the stated construction.
27. **Correlation formula:** ρ=1. **Answer:** Y=Z₁.
28. **Correlation formula:** ρ=−1. **Answer:** Y=−Z₁.
29. **Invalid ρ:** 1.1? **Answer:** Invalid; it lies outside [−1,1].
30. **SE:** Independent sample SD 10, N=10,000. **Answer:** 0.1.
31. **More samples:** Four times N. **Answer:** Roughly half the standard error under the assumptions.
32. **Model bias:** Can more samples remove it? **Answer:** No.
33. **Simple return below −1:** Consequence? **Answer:** The elementary price formula yields a negative terminal value.
34. **Truncation:** Can one discard draws below −1 without changing the model? **Answer:** No; the distribution changes.
35. **Finite tests:** Does passing a mean check prove generator quality? **Answer:** No.
36. **Benchmark:** Why compare with 102 in the two-outcome example? **Answer:** It is an analytical expectation under the specified model.
37. **Constant sample:** Sample standard error? **Answer:** Zero, provided at least two observations.
38. **Version:** Why retain NumPy version? **Answer:** It helps reproduce the generator environment.
39. **Simulation:** Is one draw a forecast? **Answer:** No.
40. **Evidence:** Name four records. **Answer:** Model, seed, generator and software version; also retain inputs and results.

## 14. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Same seed, different results | Different algorithm, version or draw order | Record environment and generator state |
| Workers return identical sequences | Duplicate seed or state | Use documented stream spawning and inspect assignments |
| Sample mean differs from target | Sampling variation or defect | Compare uncertainty and validate mapping |
| Negative terminal price | Normal simple-return tail | Reconsider the return model |
| Narrow confidence interval but biased result | Wrong assumptions or discretization | Review the model and independent benchmarks |
| Inconsistent correlated outcomes | Wrong joint construction | Check covariance assumptions and finite-sample results |
