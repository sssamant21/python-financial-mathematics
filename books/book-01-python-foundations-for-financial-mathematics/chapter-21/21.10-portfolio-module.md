## Learning objectives

Calculate a one-period portfolio return from beginning weights and aligned asset returns, specify weight and data contracts, distinguish realized from expected return and return from risk, and use independent benchmarks and financial invariants in the capstone package.

## 1. Scope and assumptions

This educational module computes a weighted average of one-period simple asset returns. Weights represent each asset's fraction of the portfolio value at the **beginning** of the same period. The return at position `i` must correspond to the asset at weight position `i`; vectors are unlabeled, so the function cannot verify instrument identity. All asset returns must use consistent period, currency, valuation, distribution and fee conventions. The calculation assumes the supplied returns and weights already reflect any relevant cash holdings and flows for the specified period.

The reference contract is long-only and approximately fully invested: each weight is between zero and one and the sum is within an absolute tolerance of `1e-12` of one. The function does **not** renormalize accepted weights. It accepts simple returns at least −100%; shorts, leverage and negative-wealth models require a different contract. It does not calculate covariance, volatility, diversification benefit, rebalancing, transaction costs, tax, external-flow-adjusted performance, FX, or optimization. A portfolio return is not a measure of portfolio risk or an investment recommendation.

This is a draft educational example, not a production-certified portfolio system. Reconcile data, timing, currency, holdings, distributions, cash and the intended model before real use.

## 2. Weighted return

For beginning weights $`w_i`$ and corresponding one-period simple asset returns $`R_i`$:

```math
R_p=\sum_{i=1}^{n}w_iR_i.
```

Under the ideal long-only fully invested assumptions, $`w_i\ge0`$ and $`\sum_iw_i=1`$. For weights `[0.6, 0.4]` and returns `[0.10, -0.05]`, the exact weighted return is $`0.6(0.10)+0.4(-0.05)=0.04`$, or 4%. If both inputs are expected returns for the same period and weights are fixed, the same linear formula gives expected portfolio return; that expectation is not a guarantee of realized performance.

For perfectly normalized long-only weights, the exact weighted return lies between the minimum and maximum asset returns. This implementation accepts a tiny sum deviation and does not normalize, so that bound can be exceeded slightly, in addition to floating-point rounding. Set tolerances with a documented rationale; do not silently change weights to make them sum to one.

## 3. Timing, alignment and risk

A beginning weight differs from an end-of-period weight after prices move. Using ending weights with that period's returns can give a different answer and introduce look-ahead. For multi-period performance, calculate each period with appropriate beginning weights and link the resulting portfolio returns, provided the assumptions of Section 21.9 hold. Rebalancing and external flows require their own explicit treatment.

The implementation cannot determine whether the first weight and first return refer to the same instrument, whether a return includes distributions, or whether values are available at the relevant time. Production input layers need identifiers, timestamps, currency, source provenance, missing-data rules and alignment checks. Returning a finite number is not proof those checks occurred.

Portfolio variance is $`w^T\Sigma w`$ under a consistent covariance model, and volatility is the square root when the variance is nonnegative. The reference function below does **not** calculate either, validate a covariance matrix or estimate risk. Covariance units and observation period must match the return horizon, and estimated parameters carry uncertainty.

## 4. Interface and numerical contract

| Item | Teaching policy |
|---|---|
| Containers | Nonempty built-in lists or tuples of equal length, at most 10,000 entries each. |
| Weights | Finite built-in floats in `[0, 1]`; `math.fsum` of weights must be within `1e-12` absolute of 1.0. |
| Returns | Finite built-in floats greater than or equal to −1, in decimal return units. |
| Result | Unrounded finite float in decimal return units; no automatic weight normalization. |
| Failure | Invalid input, nonfinite product, overflow or nonfinite result raises `ValueError`. |
| Numeric behavior | Products are summed with `math.fsum`; rounding and underflow remain possible. The length limit is not an accuracy guarantee. |

Integers, Boolean values and Decimal are rejected rather than silently converted. Zero weights are accepted, but their corresponding returns must still satisfy the contract. The function checks every input and does not mutate the input vectors. Accepted inputs and a valid sum do not validate asset alignment or financial suitability.

## 5. Reference implementation

In the Section 21.3 teaching project, apply package updates through Section 21.9. Create `src/financial_toolkit/portfolio.py`:

```python
"""Educational long-only one-period portfolio return."""
import math

MAX_ASSETS = 10_000
WEIGHT_SUM_TOLERANCE = 1e-12


def portfolio_return(weights: list[float] | tuple[float, ...],
                     returns: list[float] | tuple[float, ...]) -> float:
    """Return a weighted one-period simple return without normalization.

    Inputs must be equal-length nonempty built-in lists or tuples of finite
    built-in floats. Weights are in [0, 1] and sum within 1e-12 of one;
    returns are >= -1. Invalid inputs, nonfinite products or total raise
    ValueError. Float rounding and underflow can occur.
    """
    if type(weights) not in (list, tuple) or type(returns) not in (list, tuple):
        raise ValueError("weights and returns must be lists or tuples")
    if not weights or len(weights) != len(returns) or len(weights) > MAX_ASSETS:
        raise ValueError("inputs must be nonempty, aligned and within the length limit")
    if any(type(w) is not float or not math.isfinite(w) or not 0.0 <= w <= 1.0
           for w in weights):
        raise ValueError("weights must be finite floats in [0, 1]")
    if any(type(r) is not float or not math.isfinite(r) or r < -1.0
           for r in returns):
        raise ValueError("returns must be finite floats >= -1")
    if not math.isclose(math.fsum(weights), 1.0, rel_tol=0.0,
                        abs_tol=WEIGHT_SUM_TOLERANCE):
        raise ValueError("weights must sum to one within tolerance")

    products = [w * r for w, r in zip(weights, returns)]
    if any(not math.isfinite(x) for x in products):
        raise ValueError("nonfinite weighted return")
    try:
        result = math.fsum(products)
    except OverflowError as exc:
        raise ValueError("portfolio return overflow") from exc
    if not math.isfinite(result):
        raise ValueError("nonfinite portfolio return")
    return result
```

The accepted range and sum make the maximum possible weight sum 10,000, so the weight sum itself cannot overflow. `math.fsum` improves many sums but does not recover precision already lost in inputs or products. The code is reference material embedded in this section; it does not create a separate installed package in the repository.

## 6. Worked integration example

```python
from financial_toolkit import simple_price_return, portfolio_return

asset_a = simple_price_return(100.0, 110.0)
asset_b = simple_price_return(100.0, 95.0)
value = portfolio_return([0.6, 0.4], [asset_a, asset_b])
print(f"One-period portfolio price return: {value:.2%}")
```

The exact result is 4% under the stated assumptions. Because Section 21.9's function calculates **price** returns, this example excludes distributions and fees. The weights must refer to the same assets in the same order and to the beginning of the period. Formatting does not change the stored float.

For two separately calculated portfolio returns of 4% and −2%, linking gives $`1.04\times0.98-1=0.0192`$, or 1.92% in exact arithmetic. The weights used to calculate the second period must be appropriate to that period; carrying the first period's weights forward implies an additional rebalancing assumption. The portfolio module does not update weights automatically.

## 7. Twelve Python reference tests

Save as `tests/test_portfolio.py` in the teaching project after applying the earlier capstone module updates. These test definitions have **not** been executed during publication. Return tolerances are illustrative in decimal return units.

```python
import math
import unittest
from financial_toolkit import portfolio_return, simple_price_return


class PortfolioTests(unittest.TestCase):
    def test_two_asset_benchmark(self):
        self.assertTrue(math.isclose(portfolio_return([0.6, 0.4], [0.1, -0.05]),
                                     0.04, rel_tol=0.0, abs_tol=1e-12))
    def test_single_asset(self):
        self.assertEqual(portfolio_return([1.0], [0.05]), 0.05)
    def test_zero_weights(self):
        self.assertEqual(portfolio_return([1.0, 0.0], [0.1, -1.0]), 0.1)
    def test_total_loss(self):
        self.assertEqual(portfolio_return([0.5, 0.5], [-1.0, -1.0]), -1.0)
    def test_matching_returns(self):
        self.assertTrue(math.isclose(portfolio_return([0.25, 0.75], [0.1, 0.1]),
                                     0.1, rel_tol=0.0, abs_tol=1e-12))
    def test_price_return_integration(self):
        a = simple_price_return(100.0, 110.0)
        b = simple_price_return(100.0, 95.0)
        self.assertTrue(math.isclose(portfolio_return([0.6, 0.4], [a, b]), 0.04,
                                     rel_tol=0.0, abs_tol=1e-12))
    def test_inputs_not_mutated(self):
        weights, returns = [0.6, 0.4], [0.1, -0.05]
        portfolio_return(weights, returns)
        self.assertEqual(weights, [0.6, 0.4])
        self.assertEqual(returns, [0.1, -0.05])
    def test_empty_and_mismatched(self):
        for weights, returns in (([], []), ([1.0], [0.1, 0.2])):
            with self.subTest(weights=weights, returns=returns):
                with self.assertRaises(ValueError):
                    portfolio_return(weights, returns)
    def test_invalid_weights(self):
        for weights in ([1], [True], [-0.1, 1.0], [0.4, 0.4], [float("nan")]):
            with self.subTest(weights=weights):
                with self.assertRaises(ValueError):
                    portfolio_return(weights, [0.0] * len(weights))
    def test_invalid_returns(self):
        for returns in ([True], [0], [-1.01], [float("inf")]):
            with self.subTest(returns=returns):
                with self.assertRaises(ValueError):
                    portfolio_return([1.0], returns)
    def test_weight_tolerance_without_normalization(self):
        weights = [0.5, 0.5000000000005]
        result = portfolio_return(weights, [1.0, 1.0])
        self.assertEqual(result, math.fsum(weights))
    def test_oversized(self):
        with self.assertRaises(ValueError):
            portfolio_return([0.0] * 10001, [0.0] * 10001)


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

## 10. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Import error | Export or installed artifact is stale | Check interpreter, package version and exports |
| `ValueError` for weights | Wrong type, range, length or sum | Review the documented input contract and source values |
| Result differs from account performance | Fees, cash flows, distributions, currency or timing differ | Reconcile the methodology and input data |
| Plausible but wrong result | Asset order or dates are misaligned | Check identifiers, timestamps and return definitions before calculation |
