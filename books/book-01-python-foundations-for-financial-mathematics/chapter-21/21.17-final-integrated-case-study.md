## Learning objectives

Trace synthetic data through validation, returns, portfolio calculation, descriptive statistics, valuation and simulation; derive independent benchmarks; state the timing, units and model assumptions; and prepare evidence and review criteria without treating a draft case or unrun tests as certification.

## 1. Case brief

A learner analyzes a synthetic, long-only two-asset portfolio for one observation period. Asset A moves from 100 to 110 and asset B from 100 to 95, in the same currency. Beginning weights are 60% and 40%, respectively. Prices are synthetic, positive, unadjusted price observations available by the specified decision cutoff. The task is to validate the price pairs, calculate each price return and the one-period weighted return, and record assumptions.

The case also illustrates independent examples using the capstone's time-value, cash-flow, loan, bond, statistics and simulation modules. These additional examples share the educational scenario's currency units but are **separate illustrations**, not components of the two-asset portfolio. A two-outcome simulation is applied to a hypothetical 100-unit amount; it is not calibrated to the observed portfolio or used to forecast its actual performance.

This case excludes dividends, distributions, fees, taxes, external flows, FX, real-market data, actual loan dates, bond accrual and credit risk. The results are not recommendations or production-certified valuations. The package modules are provided as reference code in earlier manuscript sections; readers must assemble them locally before running this case.

## 2. Inputs and timeline

| Input | Synthetic value | Meaning |
|---|---:|---|
| Asset A prices | 100 → 110 | Same instrument and currency, two observation times |
| Asset B prices | 100 → 95 | Same period and price convention as A |
| Beginning weights | 0.6 A, 0.4 B | Long-only and sum to one |
| Event times | 2025-01-02 16:00 UTC → 2025-01-03 16:00 UTC | Synthetic observation instants |
| Availability | At each event instant | Simplifying assumption for this example |
| Decision cutoff | 2025-01-03 18:00 UTC | Both observations are available by this time |

| Bond | Face 100, coupon 0.05, yield 0.05, two periods | Simplified coupon-date model |

The synthetic source label and availability assumptions do not establish real-world source quality, point-in-time revision history or a valid valuation policy. The validation layer checks a narrow schema and ordering; it does not verify adjusted-price consistency, source authenticity, currency membership or freshness.

## 3. Independent calculations

1. Asset A price return: \(110/100-1=0.10\), or 10%.
2. Asset B price return: \(95/100-1=-0.05\), or −5%.
3. Portfolio price return: \(0.6(0.10)+0.4(-0.05)=0.04\), or 4%, in exact arithmetic.
4. Arithmetic sample mean of the **two cross-sectional asset returns**: \((0.10-0.05)/2=0.025\), or 2.5%. It is unweighted and is not the portfolio return or a time-series volatility estimate.
5. Sample variance of those two returns: \([(0.10-0.025)^2+(-0.05-0.025)^2]/(2-1)=0.01125\). Sample standard deviation is \(\sqrt{0.01125}\approx0.106066\), or 10.6066 percentage points. With only two assets this is a cross-sectional descriptive statistic, not portfolio risk.
6. One-period present value of 110 at 10%: 100. NPV of `[-100, 110]` at 10%: zero. One-period loan payment on principal 1,000 at 10%: 1,100. All are exact mathematical values under the stated conventions.
7. Two-period par bond: \(5/1.05+105/1.05^2=100\) in exact arithmetic.
8. Toy simulation: possible terminal amounts are 90 and 110; its analytical mean is 100 at probability 0.5. A finite sample's mean need not be 100.

These are independently stated mathematical benchmarks. The actual float outputs may differ slightly. Illustrative tolerances below are in output units and are not universal financial acceptance thresholds.

## 4. Case flow and reference script

After assembling the Section 21.3 teaching project and applying package updates through 21.14, save the following as `examples/integrated_case.py`. It uses synthetic data and returns an in-memory result; it does not retrieve data, write a report, create a plot or record actual QA evidence.

```python
"""Synthetic integrated case; educational draft, not investment advice."""
from datetime import datetime, timezone
from financial_toolkit import (
    fixed_coupon_bond_price, level_payment, net_present_value, portfolio_return,
    present_value, simulate_two_outcome, summarize_sample, validated_price_return,
)


def build_case() -> dict:
    utc = timezone.utc
    first_time = datetime(2025, 1, 2, 16, tzinfo=utc)
    second_time = datetime(2025, 1, 3, 16, tzinfo=utc)
    cutoff = datetime(2025, 1, 3, 18, tzinfo=utc)

    def price(instrument: str, amount: float, when: datetime) -> dict:
        return {"instrument": instrument, "currency": "USD", "price": amount,
                "observed_at": when, "available_at": when, "source": "synthetic"}

    a_return = validated_price_return(price("A", 100.0, first_time),
                                      price("A", 110.0, second_time), cutoff)
    b_return = validated_price_return(price("B", 100.0, first_time),
                                      price("B", 95.0, second_time), cutoff)
    weighted = portfolio_return([0.6, 0.4], [a_return, b_return])
    cross_section = summarize_sample([a_return, b_return])

    run = simulate_two_outcome(100.0, 0.10, -0.10, 0.5, 20, 42)
    simulated_summary = summarize_sample(run.terminal_values)
    return {
        "asset_a_return": a_return,
        "asset_b_return": b_return,
        "portfolio_return": weighted,
        "cross_section_mean": cross_section.mean,
        "cross_section_variance": cross_section.sample_variance,
        "cross_section_stddev": cross_section.sample_stddev,
        "present_value": present_value(110.0, 0.10, 1),
        "cashflow_npv": net_present_value([-100.0, 110.0], 0.10),
        "loan_payment": level_payment(1000.0, 0.10, 1),
        "bond_price": fixed_coupon_bond_price(100.0, 0.05, 0.05, 2),
        "simulation_mean": simulated_summary.mean,
        "simulation_values": run.terminal_values,
        "simulation_seed": run.seed,
        "simulation_count": run.scenarios,
    }


if __name__ == "__main__":
    result = build_case()
    for key, value in result.items():
        print(f"{key}: {value}")
```

`build_case()` passes validated returns to the portfolio and statistics modules. The underlying validator verifies matching labels and time ordering for each pair, but this script and its fixed order are responsible for aligning A and B with the corresponding weights. The simulation uses a local pseudorandom generator; its sample mean is not asserted to equal the theoretical mean. A real evidence record would additionally identify revision, dependencies, actual inputs or controlled references, environment, commands, output and review.

The `examples` directory is not necessarily an importable package. The reference tests below load the script by its path, so they work from the project root without adding `examples/__init__.py`. They require the teaching package to be installed in the same interpreter; the script is not itself a separately published repository code file.

## 6. Twelve Python reference tests

Save as `tests/test_integrated_case.py`. Run from the teaching project root after assembling the package and saving `examples/integrated_case.py`. These test definitions have **not** been executed for publication. The checks use synthetic values and illustrative absolute tolerances in the corresponding output units.

```python
import importlib.util
import math
from pathlib import Path
import unittest


CASE_PATH = Path(__file__).resolve().parents[1] / "examples" / "integrated_case.py"
spec = importlib.util.spec_from_file_location("integrated_case", CASE_PATH)
if spec is None or spec.loader is None:
    raise ImportError("cannot load integrated case script")
case_module = importlib.util.module_from_spec(spec)
spec.loader.exec_module(case_module)


class IntegratedCaseTests(unittest.TestCase):
    @classmethod
    def setUpClass(cls):
        cls.result = case_module.build_case()

    def assert_close(self, actual, expected, tol=1e-10):
        self.assertTrue(math.isclose(actual, expected, rel_tol=0.0, abs_tol=tol))

    def test_asset_a_return(self):
        self.assert_close(self.result["asset_a_return"], 0.10, 1e-12)
    def test_asset_b_return(self):
        self.assert_close(self.result["asset_b_return"], -0.05, 1e-12)
    def test_weighted_return(self):
        self.assert_close(self.result["portfolio_return"], 0.04, 1e-12)
    def test_cross_section_mean(self):
        self.assert_close(self.result["cross_section_mean"], 0.025, 1e-12)
    def test_cross_section_variance(self):
        self.assert_close(self.result["cross_section_variance"], 0.01125, 1e-12)
    def test_cross_section_stddev(self):
        self.assert_close(self.result["cross_section_stddev"], math.sqrt(0.01125), 1e-12)
    def test_present_value(self):
        self.assert_close(self.result["present_value"], 100.0)
    def test_cashflow_npv(self):
        self.assert_close(self.result["cashflow_npv"], 0.0)
    def test_loan_payment(self):
        self.assert_close(self.result["loan_payment"], 1100.0, 1e-9)
    def test_bond_price(self):
        self.assert_close(self.result["bond_price"], 100.0)
    def test_simulation_shape_and_outcomes(self):
        values = self.result["simulation_values"]
        self.assertEqual((self.result["simulation_count"], self.result["simulation_seed"]),
                         (20, 42))
        self.assertEqual(len(values), 20)
        for value in values:
            self.assertTrue(any(math.isclose(value, x, rel_tol=0.0, abs_tol=1e-10)
                                for x in (90.0, 110.0)))
    def test_simulation_repeats_in_same_environment(self):
        other = case_module.build_case()
        self.assertEqual(self.result["simulation_values"], other["simulation_values"])


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

The reproducibility check is restricted to repeated runs in the same environment; it does not guarantee cross-version random sequences. It does not assert that 20 random draws split evenly or that the sample mean equals the theoretical mean. The tests also do not verify currency identity, source authenticity, completeness, model suitability, a chart or an installed wheel. Add boundary, failure, numerical-range and independent review checks during comprehensive QA.

| Symptom | Possible cause | Next step |
|---|---|---|
