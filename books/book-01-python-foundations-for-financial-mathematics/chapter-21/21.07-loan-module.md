## Learning objectives

Calculate a level end-of-period loan payment under stated assumptions, distinguish periodic from annual rates, define numerical and input contracts, connect the calculation to time-value and cash-flow modules, and design tests and reviews for financial and software behavior.

## 1. Scope and conventions

This educational module calculates the positive payment amount for a loan with positive principal, a constant nonnegative effective interest rate per period, and equal payments at the **end** of each period. The initial loan proceeds occur at time zero. The payment and principal have the same currency and amount units; a borrower's payment is an outflow even though the function returns its positive magnitude.

The calculation assumes payments are made in full and on time and that interest accrues once per period. It excludes fees, taxes, insurance, prepayments, arrears, variable rates, actual dates, day-count conventions, currency conversion, contractual installment rounding and final-payment adjustment. It does not produce an amortization schedule or APR. A real loan's contract and applicable rules determine its actual payments and borrowing cost. The reference code is a draft educational example, not a production-certified lending system.

## 2. Level-payment mathematics

Let $`L>0`$ be principal, $`r\geq0`$ the effective rate per payment period, and $`n\geq1`$ the number of end-of-period payments. For $`r>0`$, equating the loan proceeds with the present value of the payments gives

```math
L=A\sum_{t=1}^{n}(1+r)^{-t},\qquad
A=\frac{Lr}{1-(1+r)^{-n}}.
```

At zero rate, the limiting payment is $`A=L/n`$. For a loan of 1,200 units at zero interest over 12 periods, the payment is 100 units per period. For 1,000 at 10% for one period, the payment is 1,100 in exact arithmetic. For 1,000 at 10% for two periods, the exact expression is $`1000(0.1)/(1-1/1.1^2)`$, approximately 576.19047619 per period.

Rate and payment intervals must match. For example, a nominal annual rate of 12% compounded monthly corresponds to a monthly rate of 1%; an **effective** annual rate of 12% instead corresponds to $`(1.12)^{1/12}-1`$, approximately 0.948879% per month. Convert only according to the stated contract. Neither annual-rate conversion nor calendar handling is implemented below.

## 3. Contract and numerical approach

| Item | Reference policy |
|---|---|
| Principal | Positive, finite built-in `float` in payment units. |
| Periodic rate | Finite built-in `float` in the inclusive range 0 to 1, expressed as a decimal per payment period. |
| Periods | Built-in `int` from 1 through 1,200 inclusive; Boolean is rejected. |
| Result | Positive, finite, unrounded `float` payment magnitude, in principal units. |
| Errors | Invalid input, a zero/nonfinite denominator, or a nonpositive/nonfinite result raises `ValueError`. |
| Numerical limits | Floating-point rounding and underflow remain possible. The limits are illustrative and do not guarantee accuracy. |

For positive rates, the implementation computes the denominator as `-expm1(-n * log1p(r))`. This reduces cancellation in the denominator for small rates compared with directly subtracting a power close to one. The zero-rate case is handled separately. Extreme inputs can still underflow or overflow; finite output does not establish accuracy. The code accepts nonnegative rates only, a deliberately narrower domain than the time-value module's rate greater than −1.

No rounding to currency units occurs. A lender may round each installment and adjust the last payment; that is a separate policy and calculation, not implemented here. Any future schedule must define interest, principal, rounding stage and payoff treatment explicitly.

## 4. Reference implementation

In the Section 21.3 teaching project, after applying Sections 21.5 and 21.6, create `src/financial_toolkit/loans.py`:

```python
"""Educational level-payment loan calculation."""
import math

MAX_LOAN_PERIODS = 1_200


def level_payment(principal: float, rate: float, periods: int) -> float:
    """Return positive unrounded end-of-period payment magnitude.

    Principal must be a positive finite built-in float; rate must be a finite
    built-in float in [0, 1] per period; periods must be a built-in int in
    [1, 1200]. Invalid inputs or a nonpositive/nonfinite result raise
    ValueError. Floating-point rounding and underflow may occur.
    """
    if type(principal) is not float or not math.isfinite(principal) or principal <= 0.0:
        raise ValueError("principal must be a positive finite float")
    if type(rate) is not float or not math.isfinite(rate) or not 0.0 <= rate <= 1.0:
        raise ValueError("rate must be a finite float between 0 and 1")
    if type(periods) is not int or not 1 <= periods <= MAX_LOAN_PERIODS:
        raise ValueError("periods must be an integer from 1 to 1200")

    if rate == 0.0:
        payment = principal / periods
    else:
        denominator = -math.expm1(-periods * math.log1p(rate))
        if not math.isfinite(denominator) or denominator <= 0.0:
            raise ValueError("invalid payment denominator")
        payment = principal * (rate / denominator)
    if not math.isfinite(payment) or payment <= 0.0:
        raise ValueError("nonpositive or nonfinite payment")
    return payment
```

The function rejects integer principal and rate, Decimal and Boolean values rather than converting them silently. The output can underflow to zero for sufficiently tiny principal or overflow for sufficiently large principal, in which case it raises `ValueError`. No dates, currency label, schedule or durable evidence are included. Code shown here is manuscript reference material; the repository is not receiving a separately installed library as part of this section.

## 5. Example and integration

```python
from financial_toolkit import level_payment, net_present_value

principal = 1000.0
rate = 0.10
payment = level_payment(principal, rate, 2)
borrower_flows = [principal, -payment, -payment]
print(f"Payment: {payment:.6f} units")
print(f"Borrower NPV: {net_present_value(borrower_flows, rate):.10f} units")
```

The expected payment is approximately 576.190476 units; the borrower's calculated NPV is near zero at the same rate before rounding, subject to floating-point error. This is a useful integration invariant, but it is not an independent benchmark: a shared convention or error could affect both calculations. Derive known values separately and review financial assumptions.

The cash-flow module in Section 21.6 supports at most 1,001 entries, including time zero; thus this particular integration can represent up to 1,000 payments. The loan function's maximum is 1,200 periods. A 1,001–1,200-period loan is within the loan function's input domain but cannot be checked through that cash-flow API without changing its contract. Do not silently truncate the schedule.

For a fixed rate and term, doubling principal doubles the exact payment. Holding positive principal and term fixed, increasing a nonnegative rate increases the exact payment. A longer term generally reduces the payment under the stated level-payment assumptions, but total interest can rise. Financial relationships do not replace numerical tests across the intended range.

## 6. Twelve Python reference tests

Save as `tests/test_loans.py` in the teaching project. Apply the preceding capstone package sections first. These tests are definitions and have **not** been run for this publication. Tolerances are illustrative in payment units.

```python
import math
import unittest
from financial_toolkit import level_payment, net_present_value


class LoanTests(unittest.TestCase):
    def test_zero_rate(self):
        self.assertEqual(level_payment(1200.0, 0.0, 12), 100.0)
    def test_one_period(self):
        self.assertTrue(math.isclose(level_payment(1000.0, 0.1, 1), 1100.0,
                                     rel_tol=0.0, abs_tol=1e-9))
    def test_two_period_benchmark(self):
        self.assertTrue(math.isclose(level_payment(1000.0, 0.1, 2),
                                     576.1904761904761,
                                     rel_tol=0.0, abs_tol=1e-9))
    def test_small_rate_close_to_zero_rate(self):
        self.assertTrue(math.isclose(level_payment(1200.0, 1e-12, 12), 100.0,
                                     rel_tol=0.0, abs_tol=1e-8))
    def test_scale(self):
        self.assertTrue(math.isclose(level_payment(2000.0, 0.1, 2),
                                     2 * level_payment(1000.0, 0.1, 2),
                                     rel_tol=1e-12, abs_tol=1e-9))
    def test_rate_monotonicity(self):
        self.assertGreater(level_payment(1000.0, 0.1, 12),
                           level_payment(1000.0, 0.05, 12))
    def test_longer_term_reduces_payment(self):
        self.assertLess(level_payment(1000.0, 0.05, 24),
                        level_payment(1000.0, 0.05, 12))
    def test_cashflow_integration(self):
        payment = level_payment(1000.0, 0.1, 2)
        npv = net_present_value([1000.0, -payment, -payment], 0.1)
        self.assertTrue(math.isclose(npv, 0.0, rel_tol=0.0, abs_tol=1e-8))
    def test_invalid_principal(self):
        for principal in (0.0, -1.0, 1000, float("nan")):
            with self.subTest(principal=principal):
                with self.assertRaises(ValueError):
                    level_payment(principal, 0.1, 2)
    def test_invalid_rate(self):
        for rate in (-0.01, 1.01, True, float("inf")):
            with self.subTest(rate=rate):
                with self.assertRaises(ValueError):
                    level_payment(1000.0, rate, 2)
    def test_invalid_periods(self):
        for periods in (0, 1201, True, 2.0):
            with self.subTest(periods=periods):
                with self.assertRaises(ValueError):
                    level_payment(1000.0, 0.1, periods)
    def test_overflow_rejected(self):
        with self.assertRaises(ValueError):
            level_payment(1e308, 1.0, 1)


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

| Symptom | Possible cause | Next step |
|---|---|---|
| Import error | Updated export or installed package is stale | Check the selected interpreter, package exports and installation |
| `ValueError` | Invalid input, numerical underflow or overflow | Inspect type, domain and magnitude against the contract |
