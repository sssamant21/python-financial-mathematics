## Learning objectives

Build a simple reproducible scenario simulation, distinguish a model assumption from a sampled outcome, connect simulated results to the statistical module, recognize sampling error and model risk, and define evidence and tests without treating a seed or a test definition as certification.

## 1. Scope and model

This educational module simulates independent **one-period terminal values** under a two-outcome model. Each scenario starts with the same positive value $`V_0`$. It selects an up return $`r_u`$ with probability $`p`$, otherwise a down return $`r_d`$, and calculates

```math
V_1=V_0(1+R), \quad R=\begin{cases}r_u & \text{with probability }p,\\r_d & \text{with probability }1-p.\end{cases}
```

The expected terminal value under this specified model is $`V_0[p(1+r_u)+(1-p)(1+r_d)]`$. This is a model expectation, not a forecast or guarantee. For $`V_0=100`$, $`r_u=0.10`$, $`r_d=-0.10`$, and $`p=0.5`$, the possible terminal values are 110 and 90 and the exact model expectation is 100.

The reference implementation does not model multiple time steps, path dependence, dividends, external flows, fees, taxes, FX, correlations, interest-rate dynamics or a continuous distribution. It does not calculate VaR, confidence intervals or investment advice. The two outcomes, their probabilities and independence are assumptions requiring justification for any actual use. This is a draft educational example, not a production-certified risk engine.

## 2. Sampling error and model risk

A finite simulated mean generally differs from the model expectation because the sample's outcome frequencies vary. Increasing the scenario count can reduce Monte Carlo sampling error under suitable assumptions; it does not correct an inappropriate model, biased inputs, coding errors, poor data or omitted tail events. One seeded run is not an uncertainty assessment.

For independent identically distributed finite-variance outcomes, the estimated standard error of the sample mean is sample standard deviation divided by $`\sqrt{n}`$, for $`n\ge2`$. This describes uncertainty from sampling **under the model**. It is not a measure of model error, parameter uncertainty or real-world forecast accuracy. A confidence interval also requires an appropriate method and assumptions; none is implemented here.

At probability zero the down outcome is selected in every scenario; at probability one the up outcome is selected in every scenario. If up and down returns are equal, every terminal value is the same regardless of probability. Returns of −100% produce zero terminal value, and returns below −100% are outside this simplified nonnegative-wealth contract.

## 3. Reproducibility and numerical contract

| Item | Teaching policy |
|---|---|
| Initial value | Positive finite built-in `float`. |
| Outcomes | Finite built-in float returns at least −1. Their names do not enforce that the up return is greater than the down return. |
| Probability | Finite built-in float in `[0, 1]`. |
| Scenarios | Built-in integer from 2 through 10,000 inclusive; Boolean is rejected. |
| Seed | Built-in integer from 0 through `2**32 - 1` inclusive. This range is a teaching policy, not a Python RNG requirement. |
| Result | Immutable record of the input parameters and a tuple of unrounded terminal-value floats. |
| Failure | Invalid inputs or a nonfinite terminal value raise `ValueError`. Float rounding and underflow remain possible. |

A local `random.Random(seed)` instance isolates the simulation from the module-level random generator; it is a pseudorandom generator, not a cryptographic source. Repeating the same seed and inputs in the same implementation and environment is intended to reproduce the sequence. Record the Python implementation and version, generator and method, source revision, parameters and scenario count; a seed alone is insufficient to guarantee cross-version, cross-platform or cross-library identity. The result record is in memory, not a durable audit trail.

The 10,000-scenario maximum matches Section 21.11's sample-summary limit. It is a resource bound, not a claim that 10,000 scenarios are enough for a particular tail-risk or accuracy objective. Output is in initial-value units; currency and unit compatibility remain the caller's responsibility.

## 4. Reference implementation

In the Section 21.3 teaching project, apply package updates through Section 21.11. Create `src/financial_toolkit/simulation.py`:

```python
"""Educational independent two-outcome one-period simulation."""
from dataclasses import dataclass
import math
import random

MAX_SCENARIOS = 10_000
MAX_SEED = 2**32 - 1


@dataclass(frozen=True)
class ScenarioResult:
    initial: float
    up_return: float
    down_return: float
    up_probability: float
    scenarios: int
    seed: int
    terminal_values: tuple[float, ...]


def simulate_two_outcome(initial: float, up_return: float, down_return: float,
                         up_probability: float, scenarios: int,
                         seed: int) -> ScenarioResult:
    """Sample one-period terminal values from a specified two-outcome model.

    Numeric inputs are finite built-in floats; initial > 0, returns >= -1,
    and probability is in [0, 1]. Scenario count and seed are built-in ints
    within documented bounds. Invalid inputs or nonfinite terminal values
    raise ValueError. Float rounding and underflow may occur.
    """
    if type(initial) is not float or not math.isfinite(initial) or initial <= 0.0:
        raise ValueError("initial must be a positive finite float")
    for value in (up_return, down_return):
        if type(value) is not float or not math.isfinite(value) or value < -1.0:
            raise ValueError("returns must be finite floats >= -1")
    if (type(up_probability) is not float or not math.isfinite(up_probability)
            or not 0.0 <= up_probability <= 1.0):
        raise ValueError("probability must be a finite float in [0, 1]")
    if type(scenarios) is not int or not 2 <= scenarios <= MAX_SCENARIOS:
        raise ValueError("scenarios must be an integer from 2 to 10000")
    if type(seed) is not int or not 0 <= seed <= MAX_SEED:
        raise ValueError("seed must be an integer from 0 to 2**32 - 1")

    rng = random.Random(seed)
    values = []
    for _ in range(scenarios):
        rate = up_return if rng.random() < up_probability else down_return
        value = initial * (1.0 + rate)
        if not math.isfinite(value):
            raise ValueError("nonfinite terminal value")
        values.append(value)
    return ScenarioResult(initial, up_return, down_return, up_probability,
                          scenarios, seed, tuple(values))
```

All inputs are validated before sampling; only selected outcomes are multiplied. Thus a parameter combination whose **unselected** outcome would overflow can still return successfully—for example at probability zero. A release contract may instead require validating both possible terminal values, regardless of selection. Underflow can turn a tiny positive terminal value into zero without an exception. The result does not carry Python version, algorithm version or source revision; capture these externally. The code is supplied in this manuscript and does not itself create a separately installed package in the repository.

## 5. Integration and interpretation

```python
from financial_toolkit import simulate_two_outcome, summarize_sample

run = simulate_two_outcome(100.0, 0.10, -0.10, 0.5, 1000, 42)
summary = summarize_sample(run.terminal_values)
print(f"Sample mean: {summary.mean:.4f} amount units")
print(f"Sample standard deviation: {summary.sample_stddev:.4f} amount units")
```

The theoretical mean is 100 under the stated model; the actual sample mean depends on the generated outcomes and need not equal 100. Section 21.11 uses sample variance with denominator `n-1`. The standard deviation describes dispersion of terminal values, not the standard error of the mean or a loss probability. The integration shares implementation components and is not a substitute for an independent benchmark.

Independently check the probability endpoints, equal outcomes, a total-loss outcome and the analytical expectation. Avoid a test that requires one random sample to have an exact 50/50 split. Distributional tests, confidence intervals and model validation require separately chosen methods, sample sizes and review.

## 6. Twelve Python reference tests

Save as `tests/test_simulation.py` in the teaching project after applying previous capstone package updates. These test definitions have **not** been executed during publication.

```python
import math
import random
import unittest
from dataclasses import FrozenInstanceError
from financial_toolkit import simulate_two_outcome, summarize_sample


class SimulationTests(unittest.TestCase):
    def test_same_seed_repeats(self):
        a = simulate_two_outcome(100.0, 0.1, -0.1, 0.5, 20, 42)
        b = simulate_two_outcome(100.0, 0.1, -0.1, 0.5, 20, 42)
        self.assertEqual(a, b)
    def test_probability_zero(self):
        run = simulate_two_outcome(100.0, 0.1, -0.1, 0.0, 3, 1)
        for value in run.terminal_values:
            self.assertTrue(math.isclose(value, 90.0, rel_tol=0.0, abs_tol=1e-10))
    def test_probability_one(self):
        run = simulate_two_outcome(100.0, 0.1, -0.1, 1.0, 3, 1)
        for value in run.terminal_values:
            self.assertTrue(math.isclose(value, 110.0, rel_tol=0.0, abs_tol=1e-10))
    def test_equal_outcomes(self):
        run = simulate_two_outcome(100.0, 0.0, 0.0, 0.5, 4, 1)
        self.assertEqual(run.terminal_values, (100.0,) * 4)
    def test_total_loss(self):
        run = simulate_two_outcome(100.0, -1.0, 0.0, 1.0, 2, 1)
        self.assertEqual(run.terminal_values, (0.0, 0.0))
    def test_summary_integration(self):
        run = simulate_two_outcome(100.0, 0.0, 0.0, 0.5, 4, 1)
        summary = summarize_sample(run.terminal_values)
        self.assertEqual((summary.count, summary.mean, summary.sample_variance),
                         (4, 100.0, 0.0))
    def test_global_rng_state_unchanged(self):
        before = random.getstate()
        simulate_two_outcome(100.0, 0.1, -0.1, 0.5, 4, 1)
        self.assertEqual(random.getstate(), before)
    def test_result_frozen(self):
        run = simulate_two_outcome(100.0, 0.1, -0.1, 0.5, 2, 1)
        with self.assertRaises(FrozenInstanceError):
            run.seed = 2
    def test_invalid_initial_and_returns(self):
        for initial, up in ((0.0, 0.1), (100, 0.1), (100.0, -1.01),
                            (100.0, float("nan"))):
            with self.subTest(initial=initial, up=up):
                with self.assertRaises(ValueError):
                    simulate_two_outcome(initial, up, 0.0, 0.5, 2, 1)
    def test_invalid_probability(self):
        for p in (-0.1, 1.1, True, float("inf")):
            with self.subTest(p=p):
                with self.assertRaises(ValueError):
                    simulate_two_outcome(100.0, 0.1, -0.1, p, 2, 1)
    def test_invalid_scenarios_and_seed(self):
        for count, seed in ((1, 1), (10001, 1), (True, 1), (2, -1), (2, True)):
            with self.subTest(count=count, seed=seed):
                with self.assertRaises(ValueError):
                    simulate_two_outcome(100.0, 0.1, -0.1, 0.5, count, seed)
    def test_selected_outcome_overflow(self):
        with self.assertRaises(ValueError):
            simulate_two_outcome(1e308, 1.0, 0.0, 1.0, 2, 1)


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

## 9. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Import error | Package export or installation is stale | Check interpreter, package version and exports |
| `ValueError` | Input violates the contract or a selected terminal value overflows | Check input types, domains and magnitudes |
| Sample mean differs from 100 | Finite random sample has unequal outcome frequencies | Compare with the analytical model and assess sampling uncertainty |
| Repeated run differs in another environment | Generator, version, implementation or parameters differ | Compare the complete reproducibility record |
| Simulation is precise but unsuitable | Model assumptions or inputs omit material risks | Obtain independent model and data review |
