## 1. Scope and assumptions

This module values one deterministic amount using a constant effective rate for each equally spaced period. The rate period must match the cash-flow period. A positive amount is an inflow and a negative amount an outflow from the chosen perspective; input and output use the same currency and amount units. No currency conversion or automatic rounding occurs.

The implementation excludes actual dates and day counts, irregular payments, fees, taxes, default, credit, liquidity and inflation. It does not calculate annuities or NPV of multiple cash flows; the next section addresses cash-flow module design. The example is an educational draft, not a production-ready valuation engine.

## 2. Financial relationships

For a present amount \(P\), future amount \(F\), effective per-period rate \(r>-1\) and nonnegative integer number of periods \(n\):

\[
F=P(1+r)^n, \qquad P=\frac{F}{(1+r)^n}.
\]

At 10% per period for two periods, `100 × 1.1² = 121` in exact arithmetic; conversely, 121 due after two periods has present value 100. A zero-period calculation returns the input amount. A zero rate leaves the amount unchanged. A rate of −5% for two periods turns 100 into 90.25 in exact arithmetic. A rate of −1 is excluded by this module's common PV/FV contract because discounting would divide by zero.

An effective annual rate must be converted before applying it to monthly periods. For instance, the equivalent effective monthly rate for an effective annual rate of 12% is \((1.12)^{1/12}-1\), approximately 0.00948879. Simply dividing by 12 is a different convention. Rate conversions and actual-date calculations are outside the reference module below.

## 3. Public contract and numerical policy

| Item | Reference policy |
|---|---|
| Amount and rate | Finite built-in `float` values only; integers, booleans, Decimal and other numeric types are rejected. |
| Rate | Effective rate per period, strictly greater than −1. |
| Period count | Built-in `int` from 0 through 10,000 inclusive; Boolean is rejected. The limit is an educational operational bound. |
| Output | Unrounded finite `float` in the amount's units; display rounding is separate. |
| Failure | Invalid input or a nonfinite intermediate raises `ValueError`. |
| Numerical behavior | Each period is applied sequentially. Rounding, cancellation in subsequent calculations and underflow can occur. A finite result does not guarantee adequate accuracy. |

Repeated multiplication or division is simple to trace but can accumulate rounding; underflow may reduce a nonzero value to zero. Repeated intermediates can overflow even if a different algorithm or exact arithmetic would yield a representable final result. The supported count limit is not an accuracy guarantee. Use independently derived benchmarks, range analysis and tolerances appropriate to the intended use before release. Section 21.4's Decimal example remains a separate policy and is not implicitly applied to these float functions.

## 4. Reference module

This is a replacement for the illustrative `src/financial_toolkit/time_value.py` from Section 21.3. It retains `present_value_one_period` and adds multi-period `present_value` and `future_value`. In the teaching project described there, replace that file with the code below. If the package was installed as a wheel, build and install a new artifact before checking the changed code; an editable installation reads the source tree. The code is included in this manuscript, not published as a separate installed package.

```python
"""Educational single-cash-flow time-value-of-money functions."""
import math

MAX_PERIODS = 10_000


def _validate(amount: float, rate: float, periods: int) -> None:
    if type(amount) is not float or not math.isfinite(amount):
        raise ValueError("amount must be a finite float")
    if type(rate) is not float or not math.isfinite(rate) or rate <= -1.0:
        raise ValueError("rate must be a finite float greater than -1")
    if type(periods) is not int or not 0 <= periods <= MAX_PERIODS:
        raise ValueError("periods must be an integer from 0 to 10000")


def future_value(amount: float, rate: float, periods: int) -> float:
    """Compound one amount by a constant effective per-period rate.

    Return an unrounded float in amount units. Invalid input or a nonfinite
    intermediate raises ValueError. Rounding and underflow can occur.
    """
    _validate(amount, rate, periods)
    value = amount
    factor = 1.0 + rate
    for _ in range(periods):
        value *= factor
        if not math.isfinite(value):
            raise ValueError("nonfinite future-value intermediate")
    return value


def present_value(amount: float, rate: float, periods: int) -> float:
    """Discount one future amount by a constant effective per-period rate.

    Return an unrounded float in amount units. Invalid input or a nonfinite
    intermediate raises ValueError. Rounding and underflow can occur.
    """
    _validate(amount, rate, periods)
    value = amount
    factor = 1.0 + rate
    for _ in range(periods):
        value /= factor
        if not math.isfinite(value):
            raise ValueError("nonfinite present-value intermediate")
    return value


def present_value_one_period(payment: float, rate: float) -> float:
    """Preserve the Section 21.3 one-period entry point."""
    return present_value(payment, rate, 1)
```

## 5. Worked examples and validation strategy

```python
from financial_toolkit import future_value, present_value

print(future_value(100.0, 0.10, 2))   # approximately 121.0
print(present_value(121.0, 0.10, 2))  # approximately 100.0
```

For a positive future amount, PV falls as the rate rises, all else equal. For a negative future amount its PV rises toward zero as the rate rises. The scale property and the PV/FV round trip hold in exact arithmetic, but float checks require justified tolerances and supported ranges. A round trip can conceal a shared error; it complements rather than replaces an independently derived benchmark.

A suitable review also checks periods 0 and 10,000, invalid counts and types, rates near −1, nonfinite inputs, zero amounts, overflow, underflow and accuracy over the intended domain. ## 6. Twelve Python reference tests

Save as `tests/test_tvm_multi.py` within the Section 21.3 teaching project after making the module and export changes. These 12 definitions were not executed during publication. The tolerances are illustrative in amount units.

```python
import math
import unittest
from financial_toolkit import future_value, present_value, present_value_one_period


class TimeValueModuleTests(unittest.TestCase):
    def test_future_known_value(self):
        self.assertTrue(math.isclose(future_value(100.0, 0.1, 2), 121.0,
                                     rel_tol=0.0, abs_tol=1e-10))
    def test_present_known_value(self):
        self.assertTrue(math.isclose(present_value(121.0, 0.1, 2), 100.0,
                                     rel_tol=0.0, abs_tol=1e-10))
    def test_zero_period(self):
        self.assertEqual(future_value(50.0, 0.2, 0), 50.0)
        self.assertEqual(present_value(50.0, 0.2, 0), 50.0)
    def test_zero_rate(self):
        self.assertEqual(future_value(50.0, 0.0, 20), 50.0)
        self.assertEqual(present_value(50.0, 0.0, 20), 50.0)
    def test_negative_rate(self):
        self.assertTrue(math.isclose(future_value(100.0, -0.05, 2), 90.25,
                                     rel_tol=0.0, abs_tol=1e-10))
    def test_one_period_compatibility(self):
        self.assertEqual(present_value_one_period(110.0, 0.1),
                         present_value(110.0, 0.1, 1))
    def test_round_trip(self):
        result = present_value(future_value(100.0, 0.05, 5), 0.05, 5)
        self.assertTrue(math.isclose(result, 100.0, rel_tol=1e-12, abs_tol=1e-10))
    def test_positive_pv_decreases_with_rate(self):
        self.assertGreater(present_value(100.0, 0.05, 2),
                           present_value(100.0, 0.10, 2))
    def test_rate_boundary_rejected(self):
        with self.assertRaises(ValueError):
            present_value(100.0, -1.0, 1)
    def test_invalid_periods(self):
        for periods in (-1, 10001, True, 1.0):
            with self.subTest(periods=periods):
                with self.assertRaises(ValueError):
                    future_value(100.0, 0.1, periods)
    def test_invalid_numeric_inputs(self):
        for amount, rate in ((100, 0.1), (100.0, True),
                             (float("nan"), 0.1), (100.0, float("inf"))):
            with self.subTest(amount=amount, rate=rate):
                with self.assertRaises(ValueError):
                    present_value(amount, rate, 1)
    def test_nonfinite_intermediate(self):
        with self.assertRaises(ValueError):
            future_value(1e308, 1.0, 1)


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

## 9. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Import error for a new function | Package export or installation is stale | Check `__init__.py` and the selected environment |
| `ValueError` | Invalid type, rate, period count or nonfinite intermediate | Inspect the documented contract and sanitized inputs |
| Benchmark discrepancy | Rate frequency, timing or units differ | Reconcile conventions and derive the benchmark independently |
| Small round-trip difference | Floating-point rounding | Assess numerical error against a justified tolerance |
| Zero after many periods | Underflow or rounding | Review supported ranges and consider a suitable numerical method |
