## Learning objectives

Represent a periodic cash-flow timeline, calculate net present value (NPV) using the capstone time-value module, define type, timing and numerical contracts, apply independent benchmarks and financial invariants, and distinguish a project's calculated NPV from a complete investment decision.

## 1. Scope and assumptions

The module values a **nonempty sequence of deterministic cash flows** at consecutive, equally spaced periods. Element zero occurs at time zero; element one occurs at the end of the first period, and so on. A single constant effective rate applies per period. Use zero entries for periods with no payment. Positive values denote inflows and negative values outflows from one consistent perspective. Every amount shares the same currency and units.

The implementation does not handle calendar dates, day-count conventions, irregular dates, variable rates, credit, taxes, transaction costs, liquidity, currency conversion or uncertainty. It does not compute IRR. Model appropriateness depends on the intended use, inputs and assumptions; passing software checks cannot establish that appropriateness. This educational draft is not a production-certified financial library.

## 2. NPV and timeline

For cash flows \(C_0, C_1, \ldots, C_n\) and a constant effective per-period rate \(r>-1\):

\[
NPV=\sum_{t=0}^{n}\frac{C_t}{(1+r)^t}.
\]

The initial flow is not discounted. For `[-100.0, 110.0]` at 10%, NPV is \(-100+110/1.1=0\) in exact arithmetic. For `[-100.0, 60.0, 60.0]`, it is \(-100+60/1.1+60/1.1^2\approx4.132231405\). At zero rate, the mathematical NPV is the sum of the flows; floating-point summation can differ due to rounding.

A gap in timing must be represented explicitly: `[-100.0, 0.0, 121.0]` places 121 at the end of period two and gives zero NPV at 10% in exact arithmetic. A two-element sequence `[-100.0, 121.0]` instead places it at the end of period one. An annual rate cannot be used directly with monthly entries unless it has first been converted to an appropriate effective monthly rate.

## 3. Interface and numerical contract

| Item | Policy for this teaching module |
|---|---|
| Schedule | A nonempty built-in `list` or `tuple` of finite built-in `float` values, at most 1,001 entries. |
| Timeline | The first element is at time zero; subsequent elements are at consecutive period ends. |
| Rate | A finite built-in `float`, greater than −1, effective for each period. |
| Output | Unrounded finite `float` in the cash-flow units. No rounding or currency conversion. |
| Failure | Invalid types, empty or oversized schedule, invalid rate, nonfinite discounted value or nonfinite total raise `ValueError`. |
| Numerical method | Use Section 21.5's `present_value` for each flow and `math.fsum` for the total. Rounding, cancellation and underflow can remain; the method is not exact. |

Integers, booleans, Decimal and other numeric types are rejected. The maximum length makes the largest index 1,000, within Section 21.5's 10,000-period limit. The reference method calls a repeated-period discount function for each entry and therefore has quadratic work as the schedule grows. The 1,001-entry limit is an illustrative resource bound, not a performance or accuracy guarantee. Review alternative algorithms, workload, input ranges and numerical error before use at scale.

A rate must be validated even when the schedule has only a time-zero flow. A finite final result does not prove all small discounted contributions were preserved: repeated division can underflow. An intermediate can overflow even when exact terms might later cancel. `math.fsum` improves many summations but cannot repair information lost in discounting and may raise `OverflowError` on an intermediate sum.

## 4. Reference implementation

In the Section 21.3 teaching project, first apply the `time_value.py` and `__init__.py` updates from Section 21.5. Then create `src/financial_toolkit/cashflows.py`:

```python
"""Educational periodic cash-flow valuation."""
import math
from .time_value import present_value

MAX_CASHFLOWS = 1_001


def net_present_value(cashflows: list[float] | tuple[float, ...],
                      rate: float) -> float:
    """Value a nonempty schedule at a constant effective per-period rate.

    The first flow occurs at time zero. Inputs must be finite built-in floats;
    rate must exceed -1. Return an unrounded float in cash-flow units.
    Invalid inputs or nonfinite intermediate/total raise ValueError.
    Floating-point rounding, cancellation and underflow can occur.
    """
    if type(cashflows) not in (list, tuple) or not cashflows:
        raise ValueError("cashflows must be a nonempty list or tuple")
    if len(cashflows) > MAX_CASHFLOWS:
        raise ValueError("cashflows exceed the 1001-entry limit")
    if type(rate) is not float or not math.isfinite(rate) or rate <= -1.0:
        raise ValueError("rate must be a finite float greater than -1")
    if any(type(c) is not float or not math.isfinite(c) for c in cashflows):
        raise ValueError("cashflows must contain finite floats")

    discounted = [present_value(c, rate, t) for t, c in enumerate(cashflows)]
    try:
        total = math.fsum(discounted)
    except OverflowError as exc:
        raise ValueError("cash-flow total overflow") from exc
    if not math.isfinite(total):
        raise ValueError("nonfinite cash-flow total")
    return total
```

## 5. Worked example and interpretation

```python
from financial_toolkit import net_present_value

flows = [-100.0, 60.0, 60.0]
value = net_present_value(flows, 0.10)
print(f"NPV: {value:.6f} amount units")  # approximately 4.132231
```

For this synthetic example, the present value of the two future inflows exceeds the initial outflow by about 4.132231 amount units at the specified rate. A positive NPV under these assumptions does not alone establish that an investment is appropriate: assess risk, uncertainty, financing, alternatives, taxes and other material factors. Formatting to six decimal places is display only, not proof of six accurate decimals or a rounding policy.

At fixed timing and rate, NPV is additive and scales linearly in exact arithmetic. A positive future flow's contribution decreases as the rate rises, but the NPV of a mixed-sign schedule need not be monotonic. A round-trip or invariant test complements independent known-value benchmarks; it may not detect a shared implementation error.

## 6. Twelve Python reference tests

Save as `tests/test_cashflows.py` in the teaching project. The tests assume the Section 21.5 time-value code and the updated exports above. They have **not** been executed for this publication; tolerances are illustrative in amount units.

```python
import math
import unittest
from financial_toolkit import net_present_value, present_value


class CashFlowTests(unittest.TestCase):
    def test_one_period_break_even(self):
        self.assertTrue(math.isclose(net_present_value([-100.0, 110.0], 0.1), 0.0,
                                     rel_tol=0.0, abs_tol=1e-10))
    def test_two_period_benchmark(self):
        self.assertTrue(math.isclose(net_present_value([-100.0, 60.0, 60.0], 0.1),
                                     4.13223140495868, rel_tol=0.0, abs_tol=1e-10))
    def test_zero_rate(self):
        self.assertEqual(net_present_value([-100.0, 60.0, 60.0], 0.0), 20.0)
    def test_time_zero_only(self):
        self.assertEqual(net_present_value((25.0,), 0.1), 25.0)
    def test_period_gap(self):
        self.assertTrue(math.isclose(net_present_value([-100.0, 0.0, 121.0], 0.1),
                                     0.0, rel_tol=0.0, abs_tol=1e-10))
    def test_negative_rate(self):
        self.assertTrue(math.isclose(net_present_value([0.0, 95.0], -0.05), 100.0,
                                     rel_tol=0.0, abs_tol=1e-10))
    def test_one_future_flow_matches_tvm(self):
        self.assertEqual(net_present_value([0.0, 110.0], 0.1),
                         present_value(110.0, 0.1, 1))
    def test_scaling(self):
        self.assertTrue(math.isclose(net_present_value([-200.0, 120.0, 120.0], 0.1),
                                     2 * net_present_value([-100.0, 60.0, 60.0], 0.1),
                                     rel_tol=1e-12, abs_tol=1e-10))
    def test_input_not_mutated(self):
        flows = [-100.0, 110.0]
        net_present_value(flows, 0.1)
        self.assertEqual(flows, [-100.0, 110.0])
    def test_empty_and_oversized_rejected(self):
        for flows in ([], [0.0] * 1002):
            with self.subTest(length=len(flows)):
                with self.assertRaises(ValueError):
                    net_present_value(flows, 0.1)
    def test_invalid_types_and_values(self):
        for flows, rate in (([1], 0.1), ([1.0], True), ([1.0], -1.0),
                            ([float("nan")], 0.1), ([1.0], float("inf"))):
            with self.subTest(flows=flows, rate=rate):
                with self.assertRaises(ValueError):
                    net_present_value(flows, rate)
    def test_total_overflow_rejected(self):
        with self.assertRaises(ValueError):
            net_present_value([1e308, 1e308], 0.0)


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

## 8. Forty worked exercises

1. **Timeline:** When does the first cash flow occur? **Answer:** At time zero.
2. **Next flow:** When does the second element occur? **Answer:** At the end of period one.
3. **Break-even:** NPV of `[-100, 110]` at 10%? **Answer:** Zero in exact arithmetic.
4. **Two periods:** NPV of `[-100, 60, 60]` at 10%? **Answer:** Approximately 4.132231405.
5. **Zero rate:** NPV of `[-100, 60, 60]` at zero? **Answer:** 20 in exact arithmetic.
6. **Time zero:** NPV of `[25]` at 10%? **Answer:** 25.
7. **Gap:** How do you represent 121 due at period two after an initial −100? **Answer:** `[-100.0, 0.0, 121.0]`.
8. **Gap benchmark:** NPV of that schedule at 10%? **Answer:** Zero in exact arithmetic.
9. **Negative rate:** PV of `[0, 95]` at −5%? **Answer:** 100 in exact arithmetic.
10. **Rate unit:** How is 10% expressed? **Answer:** As `0.10`.
11. **Frequency:** Must rate frequency match cash-flow intervals? **Answer:** Yes.
12. **Boundary:** Why reject −1? **Answer:** Future discounting would divide by zero.
13. **Zero-only:** Is an invalid rate accepted for a time-zero-only schedule? **Answer:** No; the module validates the rate for every request.
14. **Sign:** Can cash flows be negative? **Answer:** Yes; maintain one consistent perspective.
15. **Units:** Does the module convert currency? **Answer:** No; amounts must already share units and currency.
16. **Scale:** What happens when all flows double? **Answer:** NPV doubles in exact arithmetic at the same rate.
17. **Additivity:** What is the NPV of the sum of two aligned schedules? **Answer:** The sum of their NPVs in exact arithmetic at the same rate.
18. **Positive flow:** What happens to its PV when the rate rises? **Answer:** It decreases, all else equal for a future flow.
19. **Mixed signs:** Must NPV always decrease as the rate rises? **Answer:** No; the signs and timings matter.
20. **Empty:** What does the module do with `[]`? **Answer:** Raises `ValueError`.
21. **Container:** Is a generator accepted? **Answer:** No; only a built-in list or tuple is accepted.
22. **Integer:** Is `[100]` accepted? **Answer:** No; each flow must be a built-in float.
23. **Boolean:** Is `True` accepted as the rate? **Answer:** No.
24. **Nonfinite:** Is NaN accepted in a schedule? **Answer:** No.
25. **Length:** Is a 1,002-entry schedule accepted? **Answer:** No; the maximum is 1,001.
26. **Periods:** What is the last period in a 1,001-entry schedule? **Answer:** Period 1,000.
27. **Limit:** Does the length bound guarantee speed or precision? **Answer:** No; workload and numerical analysis remain necessary.
28. **Complexity:** Why does this reference method perform quadratic work? **Answer:** It repeats a period-by-period discount for every successive flow.
29. **Mutation:** Is the caller's list modified? **Answer:** No.
30. **Rounding:** Are results automatically rounded to cents? **Answer:** No.
31. **Underflow:** Can a small contribution become zero? **Answer:** Yes.
32. **Overflow:** What happens if summation overflows? **Answer:** The module raises `ValueError`.
33. **Summation:** Does `math.fsum` make discounting exact? **Answer:** No.
34. **Tolerance:** Why specify absolute tolerance near zero? **Answer:** Relative tolerance alone does not allow nonzero difference from zero.
35. **IRR:** Does this module calculate an internal rate of return? **Answer:** No.
36. **Decision:** Does positive NPV alone prove an investment is suitable? **Answer:** No; other assumptions and risks matter.

## 9. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Import error | Package exports or installed artifact are stale | Check `__init__.py`, interpreter and installation |
| `ValueError` | Invalid input, excessive length or nonfinite intermediate | Check the contract and sanitized values |
| NPV differs from a benchmark | Different timing, rate period, units or signs | Reconcile assumptions and independently derive the result |
| Small discrepancy near zero | Floating-point rounding | Assess against a justified absolute tolerance |
| Long schedule is slow | Repeated discounting performs quadratic work | Evaluate a reviewed alternative for the defined workload |
