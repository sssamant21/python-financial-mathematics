# 21.13 — Data Validation Layer

**Book:** Book 1 — Python Foundations for Financial Mathematics  
**Chapter:** 21 — Integrated Capstone: Financial Mathematics Toolkit  
**Status:** Published draft; scoped runtime checks completed as recorded in the Book 1 QA progress record; comprehensive mathematical, data and editorial QA remains pending.

## Learning objectives

Define a validation boundary for financial data, distinguish schema checks from financial and point-in-time suitability, validate a pair of price observations before calculating a return, document rejection and provenance policies, and design independent tests for invalid and time-inconsistent inputs.

## 1. Purpose and scope

A validation layer checks whether data conforms to a documented contract before calculations use it. A syntactically valid value can still be stale, wrong, revised, misidentified or unsuitable. The caller must establish source quality, meaning and permissions; the checks below do not certify data accuracy or model appropriateness.

This section introduces an educational boundary for **two strictly positive price observations** of the same instrument and currency. Each observation carries an event timestamp, an availability timestamp and a source label. A pair is eligible for a simple price return when both observations were available by a supplied decision time, have matching instrument and currency labels, and have strictly increasing event times. It does not handle zero-price total loss, adjusted prices, dividends, fees, FX, missing-value imputation, corporate actions, duplicates across a dataset, stale-price thresholds, calendars or historical revision histories. Section 21.9's lower-level price-return function accepts a zero ending price; this validation layer intentionally adopts a narrower positive-price contract. The design is a draft, not a production data-quality system.

## 2. A financial data contract

| Field | Teaching contract | What the check cannot establish |
|---|---|---|
| `instrument` | Nonblank string with no leading or trailing whitespace | Stable global identity, venue or correct instrument mapping |
| `currency` | Exactly three uppercase ASCII letters | ISO membership, FX conversion or correct reporting currency |
| `price` | Positive finite built-in `float` | Market validity, adjustment basis or economic suitability |
| `observed_at` | Timezone-aware `datetime` marking the observation | Whether the source timestamp is truthful or market-close semantics are correct |
| `available_at` | Timezone-aware `datetime`, not earlier than the observation and not later than decision time | Whether an earlier or revised version exists in the source |
| `source` | Nonblank string with no leading or trailing whitespace | Authenticity, license or data quality |
| `as_of` | Timezone-aware `datetime` supplied to validation | Whether it represents the correct business decision cutoff |

A timestamp identifies an instant when it includes a UTC offset. The validator converts aware datetimes to UTC for instant comparisons, including repeated local times during a daylight-saving transition. It preserves the provided datetime values in the returned record and does not normalize them for storage. Never assume that an event date and publication or revision date are interchangeable. An observation may be available well after its event time; revised data requires versioned availability history, which this example does not provide.

The schema requires exactly the six named keys: missing or extra fields are rejected. This makes changes visible but requires a deliberate versioning policy in a real system. Input timestamps are already `datetime` objects; parsing strings, resolving ambiguous local times, normalizing identifiers and mapping currencies belong to separately specified boundaries.

## 3. Point-in-time and semantic checks

For a decision at time $`T`$, this example requires each record's observation time $`\le`$ availability time $`\le T`$. For the pair, the earlier observation must strictly precede the later one. Requiring availability by $`T`$ reduces one form of look-ahead but does not prove that the selected revision was the version actually available at $`T`$. Proper point-in-time analysis also needs revision lineage, publication timestamps, source contracts and historical snapshots.

The pair must have identical instrument and currency strings. The code does **not** require matching source labels or verify the same price basis, adjustment policy or observation frequency. A real interface should specify and verify those conditions. A successful structural check is an eligible input to the next calculation, not an assertion that the source is correct.

For prices 100 and 110 of the same instrument and currency, the mathematical simple price return is $`110/100-1=0.10`$, or 10%. Dividends, fees and taxes are excluded by Section 21.9. A different financial use may require a total-return series and a different validation contract.

## 4. Reference validation layer

In the Section 21.3 teaching project, apply capstone package updates through Section 21.12. Create `src/financial_toolkit/validation.py`:

```python
"""Educational point-in-time validation for a pair of price observations."""
from dataclasses import dataclass
from datetime import datetime, timezone
import math
from .returns import simple_price_return

FIELDS = frozenset({"instrument", "currency", "price", "observed_at",
                    "available_at", "source"})


@dataclass(frozen=True)
class PriceObservation:
    instrument: str
    currency: str
    price: float
    observed_at: datetime
    available_at: datetime
    source: str


def _aware(value: object) -> bool:
    return (type(value) is datetime and value.tzinfo is not None
            and value.utcoffset() is not None)


def _label(value: object) -> bool:
    return type(value) is str and bool(value) and value == value.strip()


def validate_price_record(record: dict, as_of: datetime) -> PriceObservation:
    """Validate one exact-schema record against an aware decision time.

    No parsing, conversion, normalization, source authentication or historical
    revision verification is performed. Invalid inputs raise ValueError.
    """
    if not _aware(as_of):
        raise ValueError("as_of must be a timezone-aware datetime")
    if type(record) is not dict or record.keys() != FIELDS:
        raise ValueError("record must contain exactly the required fields")
    if not _label(record["instrument"]) or not _label(record["source"]):
        raise ValueError("instrument and source must be nonblank trimmed strings")
    currency = record["currency"]
    if (type(currency) is not str or len(currency) != 3
            or any(ch < "A" or ch > "Z" for ch in currency)):
        raise ValueError("currency must be three uppercase ASCII letters")
    price = record["price"]
    if type(price) is not float or not math.isfinite(price) or price <= 0.0:
        raise ValueError("price must be a positive finite float")
    observed = record["observed_at"]
    available = record["available_at"]
    if not _aware(observed) or not _aware(available):
        raise ValueError("record timestamps must be timezone-aware")
    if (observed.astimezone(timezone.utc) > available.astimezone(timezone.utc)
            or available.astimezone(timezone.utc) > as_of.astimezone(timezone.utc)):
        raise ValueError("timestamps violate point-in-time ordering")
    return PriceObservation(record["instrument"], currency, price, observed,
                            available, record["source"])


def validated_price_return(first: dict, second: dict, as_of: datetime) -> float:
    """Validate two records and calculate a simple price return.

    Both must be available by as_of, match instrument and currency labels,
    and have strictly increasing observation times. Data authenticity and
    adjustment consistency remain the caller's responsibility.
    """
    a = validate_price_record(first, as_of)
    b = validate_price_record(second, as_of)
    if a.instrument != b.instrument or a.currency != b.currency:
        raise ValueError("instrument and currency must match")
    if a.observed_at.astimezone(timezone.utc) >= b.observed_at.astimezone(timezone.utc):
        raise ValueError("observation times must be strictly increasing")
    return simple_price_return(a.price, b.price)
```

The function rejects Boolean and integer prices instead of coercing them, and copies validated fields into a frozen record without modifying the caller's dictionary. Python type annotations do not enforce runtime types. The code does not log or persist records. Error messages identify a failure category without embedding input values, but application logging and access control still need an explicit policy. A frozen dataclass does not establish durable provenance.

## 5. Worked example

```python
from datetime import datetime, timezone
from financial_toolkit import validated_price_return

utc = timezone.utc
first = {"instrument": "EXAMPLE", "currency": "USD", "price": 100.0,
         "observed_at": datetime(2025, 1, 2, 16, tzinfo=utc),
         "available_at": datetime(2025, 1, 2, 17, tzinfo=utc), "source": "synthetic"}
second = {"instrument": "EXAMPLE", "currency": "USD", "price": 110.0,
          "observed_at": datetime(2025, 1, 3, 16, tzinfo=utc),
          "available_at": datetime(2025, 1, 3, 17, tzinfo=utc), "source": "synthetic"}
cutoff = datetime(2025, 1, 3, 18, tzinfo=utc)
print(f"Price return: {validated_price_return(first, second, cutoff):.2%}")
```

The mathematical result is 10%; floating-point output may differ slightly. Moving the cutoff before the second availability time causes a rejection. Changing a currency label causes a rejection; it does not trigger currency conversion. The example's synthetic labels and timestamps do not establish real source quality.

## 6. Fourteen Python reference tests

Save as `tests/test_validation.py` in the teaching project after applying previous capstone updates. The original 12 checks and two DST regression checks were executed in the scoped QA run described in the Book 1 QA progress record; broader validation remains pending.

```python
from datetime import datetime, timedelta, timezone
from zoneinfo import ZoneInfo
import math
import unittest
from financial_toolkit import validate_price_record, validated_price_return

UTC = timezone.utc
T1 = datetime(2025, 1, 2, 16, tzinfo=UTC)
T2 = datetime(2025, 1, 3, 16, tzinfo=UTC)
CUTOFF = datetime(2025, 1, 3, 18, tzinfo=UTC)


def record(price=100.0, observed=T1, available=T1, **changes):
    result = dict(instrument="EXAMPLE", currency="USD", price=price,
                  observed_at=observed, available_at=available, source="synthetic")
    result.update(changes)
    return result


class ValidationTests(unittest.TestCase):
    def test_valid_record(self):
        result = validate_price_record(record(), CUTOFF)
        self.assertEqual((result.instrument, result.currency, result.price),
                         ("EXAMPLE", "USD", 100.0))
    def test_valid_pair_return(self):
        result = validated_price_return(record(), record(110.0, T2, T2), CUTOFF)
        self.assertTrue(math.isclose(result, 0.1, rel_tol=0.0, abs_tol=1e-12))
    def test_missing_field(self):
        item = record()
        del item["source"]
        with self.assertRaises(ValueError):
            validate_price_record(item, CUTOFF)
    def test_extra_field(self):
        with self.assertRaises(ValueError):
            validate_price_record(record(extra="x"), CUTOFF)
    def test_invalid_price(self):
        for price in (0.0, -1.0, 100, True, float("nan")):
            with self.subTest(price=price):
                with self.assertRaises(ValueError):
                    validate_price_record(record(price=price), CUTOFF)
    def test_invalid_currency(self):
        for currency in ("usd", "US", "U$D"):
            with self.subTest(currency=currency):
                with self.assertRaises(ValueError):
                    validate_price_record(record(currency=currency), CUTOFF)
    def test_naive_timestamp(self):
        with self.assertRaises(ValueError):
            validate_price_record(record(observed=datetime(2025, 1, 2)), CUTOFF)
    def test_availability_after_cutoff(self):
        with self.assertRaises(ValueError):
            validate_price_record(record(available=CUTOFF + timedelta(seconds=1)), CUTOFF)
    def test_available_before_observation(self):
        with self.assertRaises(ValueError):
            validate_price_record(record(available=T1 - timedelta(seconds=1)), CUTOFF)
    def test_pair_mismatch(self):
        with self.assertRaises(ValueError):
            validated_price_return(record(), record(110.0, T2, T2, currency="EUR"), CUTOFF)
    def test_pair_time_order(self):
        with self.assertRaises(ValueError):
            validated_price_return(record(), record(110.0, T1, T1), CUTOFF)
    def test_dst_fold_reversed_availability_rejected(self):
        zone = ZoneInfo("America/New_York")
        observed = datetime(2025, 11, 2, 1, 15, tzinfo=zone, fold=1)
        available = datetime(2025, 11, 2, 1, 30, tzinfo=zone, fold=0)
        cutoff = datetime(2025, 11, 2, 8, tzinfo=UTC)
        with self.assertRaises(ValueError):
            validate_price_record(record(observed=observed, available=available), cutoff)
    def test_dst_fold_pair_order_by_instant(self):
        zone = ZoneInfo("America/New_York")
        first = datetime(2025, 11, 2, 1, 30, tzinfo=zone, fold=0)
        second = datetime(2025, 11, 2, 1, 15, tzinfo=zone, fold=1)
        cutoff = datetime(2025, 11, 2, 8, tzinfo=UTC)
        result = validated_price_return(record(100.0, first, first),
                                        record(110.0, second, second), cutoff)
        self.assertTrue(math.isclose(result, 0.1, rel_tol=0.0, abs_tol=1e-12))
    def test_input_not_mutated(self):
        item = record()
        before = item.copy()
        validate_price_record(item, CUTOFF)
        self.assertEqual(item, before)


if __name__ == "__main__":
    unittest.main(verbosity=2)
```

## 9. Troubleshooting

| Symptom | Possible cause | Next step |
|---|---|---|
| Import error | Updated package or export is not installed in the selected interpreter | Check the environment and package version |
| `ValueError` for schema | Missing, extra or incorrectly typed field | Compare the input with the exact contract |
| Timestamp rejection | Naive timestamp or invalid availability ordering | Resolve timezone and source timing according to policy |
| Pair rejected | Instrument, currency or observation ordering differs | Reconcile identifiers and timing; do not silently convert |
| Validated result is financially misleading | Source, adjustment, revision or freshness assumptions are wrong | Inspect provenance and perform independent financial review |
