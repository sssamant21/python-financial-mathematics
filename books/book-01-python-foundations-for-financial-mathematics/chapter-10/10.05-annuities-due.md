## Learning objectives

Distinguish an annuity due from an ordinary annuity, model beginning-of-period payments, derive present and future value formulas, solve for the payment amount, and implement and validate annuity-due calculations in Python.

## 1. Payment timing defines an annuity due

An **annuity due** is a finite series of equal payments at the **beginning** of each period. For three payments, the dates are periods 0, 1, and 2. An ordinary annuity instead pays at periods 1, 2, and 3.

```text
Period        0           1           2           3
              |-----------|-----------|-----------|
Annuity due   C           C           C
Ordinary                  C           C           C
```

Examples can include rent payable in advance and certain insurance premiums. The contract, not the product label, determines payment timing.

## 2. Present value derivation

For a constant payment C, periodic rate i greater than -1, and n nonnegative integer payments, the annuity-due present value is the sum over k = 0 through n - 1 of C/(1+i)^k.

The ordinary-annuity present value is the sum over k = 1 through n of C/(1+i)^k. Every due payment is shifted exactly one period earlier. Therefore:

**PV_due = PV_ordinary × (1+i).**

For nonzero i:

**PV_due = C × [1 - (1+i)^(-n)] / i × (1+i).**

For i = 0, PV_due = n × C. For n = 0, the present value is zero.

### Worked example

Three payments of $100 at the beginning of each annual period with a 10% effective annual rate:

PV_due = 100 + 100/1.1 + 100/1.1² = approximately **$273.55**.

The corresponding ordinary-annuity present value is approximately $248.69. Multiplying it by 1.1 produces the due value, apart from displayed rounding.

## 3. Future value at the end of period n

The first annuity-due payment accumulates for n periods and the last payment for one period. Consequently:

**FV_due = C × [(1+i)^n - 1] / i × (1+i)** for nonzero i.

At zero interest, FV_due = n × C. The reconciliation identity is:

**FV_due = PV_due × (1+i)^n.**

For three $100 beginning-of-year payments at 10%, FV_due = **$364.10** at the end of year 3.

## 4. Solve for the beginning-of-period payment

Given target present value P and n positive payments, the due payment is P divided by the annuity-due factor:

C = P / { [1 - (1+i)^(-n)] × (1+i) / i } when i is nonzero.

At i = 0, C = P/n. At n = 0, a payment cannot be inferred from a nonempty target.

**Example:** To fund a present value of $1,000 with ten equal payments at the beginnings of successive periods at 5% per period, compute the ordinary-annuity factor, multiply by 1.05, and divide $1,000 by that result. Confirm by discounting the ten individual payments at periods 0 through 9.

## 5. Practical modeling considerations

The periodic rate must match the payment frequency. For a 6% nominal annual rate convertible monthly, use a 0.5% monthly rate for monthly payments. For a 6% effective annual rate, use (1.06)^(1/12) - 1 instead.

A negative periodic rate between -1 and 0 is mathematically permitted; it reverses some familiar comparisons. Payment amounts can be negative if they represent outflows from the chosen perspective. The reference model uses binary floating point, validates inputs, and avoids premature cent rounding. Real contracts may require different rounding and date rules.

```python
import math
import unittest

def validate(payment, rate, periods):
    if isinstance(periods, bool) or not isinstance(periods, int):
        raise TypeError("periods must be integer")
    if periods < 0:
        raise ValueError("periods must be nonnegative")
    for value in (payment, rate):
        if isinstance(value, bool) or not isinstance(value, (int, float)):
            raise TypeError("numeric input required")
        if not math.isfinite(value):
            raise ValueError("finite input required")
    if rate <= -1:
        raise ValueError("rate must exceed -1")

def ordinary_pv(payment, rate, periods):
    validate(payment, rate, periods)
    if periods == 0:
        return 0.0
    if rate == 0:
        return float(payment * periods)
    result = payment * (-math.expm1(-periods * math.log1p(rate))) / rate
    if not math.isfinite(result):
        raise ValueError("PV out of range")
    return result

def due_pv(payment, rate, periods):
    result = ordinary_pv(payment, rate, periods) * (1 + rate)
    if not math.isfinite(result):
        raise ValueError("PV out of range")
    return result

def due_fv(payment, rate, periods):
    validate(payment, rate, periods)
    if periods == 0:
        return 0.0
    if rate == 0:
        return float(payment * periods)
    try:
        result = payment * math.expm1(periods * math.log1p(rate)) / rate * (1 + rate)
    except OverflowError as exc:
        raise ValueError("FV out of range") from exc
    if not math.isfinite(result):
        raise ValueError("FV out of range")
    return result

def due_timeline_pv(payment, rate, periods):
    validate(payment, rate, periods)
    return math.fsum(payment * math.exp(-k * math.log1p(rate))
                     for k in range(periods))

def due_payment_from_pv(target, rate, periods):
    validate(target, rate, periods)
    if periods == 0:
        raise ValueError("no payments to solve")
    factor = due_pv(1, rate, periods)
    if factor == 0 or not math.isfinite(factor):
        raise ValueError("factor not representable")
    return target / factor

class AnnuityDueTests(unittest.TestCase):
    def test_01_timing(self):
        self.assertEqual(list(range(3)), [0,1,2])
    def test_02_pv(self):
        self.assertAlmostEqual(due_pv(100,.1,3),100+100/1.1+100/1.1**2)
    def test_03_fv(self):
        self.assertAlmostEqual(due_fv(100,.1,3),364.1)
    def test_04_due_ordinary_relation(self):
        self.assertAlmostEqual(due_pv(100,.1,3),ordinary_pv(100,.1,3)*1.1)
    def test_05_zero_rate(self):
        self.assertEqual(due_pv(200,0,5),1000)
        self.assertEqual(due_fv(200,0,5),1000)
    def test_06_zero_periods(self):
        self.assertEqual(due_pv(100,.05,0),0)
        self.assertEqual(due_fv(100,.05,0),0)
    def test_07_negative_rate(self):
        self.assertAlmostEqual(due_pv(100,-.1,2),100+100/.9)
    def test_08_timeline(self):
        self.assertAlmostEqual(due_timeline_pv(125,.04,24),
                               due_pv(125,.04,24),places=8)
    def test_09_payment_inverse(self):
        p=due_payment_from_pv(1000,.05,10)
        self.assertAlmostEqual(due_pv(p,.05,10),1000)
    def test_10_fv_pv_identity(self):
        self.assertAlmostEqual(due_fv(100,.1,3),due_pv(100,.1,3)*1.1**3)
    def test_11_signed(self):
        self.assertAlmostEqual(due_pv(-100,.1,3),-due_pv(100,.1,3))
    def test_12_invalid(self):
        with self.assertRaises(ValueError): due_pv(100,-1,3)
        with self.assertRaises(TypeError): due_pv(100,.05,2.5)
        with self.assertRaises(ValueError): due_payment_from_pv(100,.05,0)

if __name__ == "__main__":
    print(f"PV due: {due_pv(100,.1,3):.2f}")
    print(f"FV due: {due_fv(100,.1,3):.2f}")
    unittest.main(verbosity=2)
```

## 7. Exercises and worked answers

1. **Timing:** When are three annuity-due payments made? **Answer:** Periods 0, 1, and 2.
2. **Comparison:** When are three ordinary-annuity payments made? **Answer:** Periods 1, 2, and 3.
3. **Present value:** Find PV of three $100 due payments at 10%. **Answer:** Approximately $273.55.
4. **Future value:** Find FV at year 3 of the same due payments. **Answer:** $364.10.
5. **Shift identity:** How does PV_due relate to PV_ordinary? **Answer:** Multiply by 1+i.
6. **Zero interest:** Find PV of five $200 due payments at zero rate. **Answer:** $1,000.
7. **Negative interest:** Find PV of two $100 due payments at -10%. **Answer:** 100 + 100/0.9 = approximately $211.11.
8. **Monthly convention:** What periodic rate corresponds to 6% nominal annual compounded monthly? **Answer:** 0.005.
9. **Effective annual conversion:** What monthly rate corresponds to 6% effective annual? **Answer:** (1.06)^(1/12) - 1.
10. **Payment inversion:** How do you compute the payment from target PV? **Answer:** Divide target PV by the due-annuity factor.
11. **Zero periods:** What is PV of an empty due stream? **Answer:** Zero.
12. **Audit:** How do you independently check a due formula? **Answer:** Discount payments individually at periods 0 through n-1 and compare the sum.
