## Definition and timeline

An ordinary annuity is a finite series of equal payments at the **end** of equally spaced periods. A three-payment ordinary annuity has payments at times 1, 2, and 3; there is no payment at time zero.

```text
Time         0        1        2        3
             |--------|--------|--------|
Payment               C        C        C
```

The interest rate must be a **periodic rate matching the payment interval**. For 6% nominal annual convertible monthly, the monthly rate is 0.06/12 = 0.005. For 6% effective annual, the equivalent monthly rate is (1.06)^(1/12) - 1, a different value.

## Present value

For a constant periodic payment C, periodic rate i greater than -1, and n end-of-period payments:

PV = sum from k=1 to n of C/(1+i)^k.

The geometric-series formula for nonzero i is:

**PV = C × [1 - (1+i)^(-n)] / i.**

For i = 0, PV = n × C. For n = 0, PV = 0.

**Example:** Three end-of-year payments of $100 discounted at 10% effective annual give PV = 100/1.1 + 100/1.1² + 100/1.1³, approximately **$248.69**.

## Future value

At the end of period n, each earlier payment is accumulated:

FV = sum from k=1 to n of C × (1+i)^(n-k).

For nonzero i:

**FV = C × [(1+i)^n - 1] / i.**

For i = 0, FV = n × C. The identity FV = PV × (1+i)^n reconciles present and future values.

**Example:** Three $100 payments at 10% give FV = 100 × (1 + 1.1 + 1.1²) = **$331**.

## Solving for the payment

Given a present-value target P and n greater than zero, the ordinary-annuity payment is P divided by the annuity PV factor:

C = P × i / [1 - (1+i)^(-n)] for nonzero i; C = P/n for zero i.

This mathematical result does not incorporate contractual rounding, fees, or loan-specific amortization rules.

## Numerical considerations

The sample uses math.log1p and math.expm1 for improved precision near zero rates. It validates rates and integer payment counts, permits signed payments and periodic rates between -1 and 0, and avoids treating an empty schedule as a solvable inverse-payment problem. For financial ledgers, use an explicit fixed-point currency rounding policy.

```python
import math
import unittest

def pv(payment, rate, periods):
    if not isinstance(periods, int) or isinstance(periods, bool) or periods < 0:
        raise ValueError("periods must be a nonnegative integer")
    if not all(isinstance(x, (int, float)) and not isinstance(x, bool)
               and math.isfinite(x) for x in (payment, rate)):
        raise ValueError("finite numeric inputs required")
    if rate <= -1:
        raise ValueError("rate must exceed -1")
    if periods == 0:
        return 0.0
    if rate == 0:
        return payment * periods
    return payment * (-math.expm1(-periods * math.log1p(rate))) / rate

def fv(payment, rate, periods):
    if periods == 0:
        return pv(payment, rate, periods)
    if rate == 0:
        return pv(payment, rate, periods)
    result = pv(payment, rate, periods) * math.exp(periods * math.log1p(rate))
    if not math.isfinite(result):
        raise ValueError("future value overflow")
    return result

def payment_from_pv(target, rate, periods):
    factor = pv(1, rate, periods)
    if factor == 0:
        raise ValueError("payment not identifiable")
    return target / factor

class Checks(unittest.TestCase):
    def test_pv(self):
        self.assertAlmostEqual(pv(100, .1, 3), sum(100/1.1**k for k in range(1,4)))
    def test_fv(self):
        self.assertAlmostEqual(fv(100, .1, 3), 331)
    def test_identity(self):
        self.assertAlmostEqual(fv(100, .1, 3), pv(100, .1, 3)*1.1**3)
    def test_zero_rate(self):
        self.assertEqual(pv(200, 0, 5), 1000)
    def test_zero_periods(self):
        self.assertEqual(pv(100, .05, 0), 0)
    def test_payment(self):
        self.assertAlmostEqual(pv(payment_from_pv(1000,.05,10),.05,10),1000)
    def test_monthly(self):
        self.assertAlmostEqual(.06/12, .005)
    def test_negative_rate(self):
        self.assertAlmostEqual(pv(100,-.1,2),100/.9+100/.9**2)
    def test_small_rate(self):
        self.assertAlmostEqual(pv(100,1e-12,12),sum(100/(1+1e-12)**k for k in range(1,13)),places=7)
    def test_negative_payment(self):
        self.assertAlmostEqual(pv(-100,.1,3),-pv(100,.1,3))
    def test_invalid_rate(self):
        with self.assertRaises(ValueError):
            pv(100,-1,3)
    def test_invalid_periods(self):
        with self.assertRaises(ValueError):
            pv(100,.05,2.5)

if __name__ == "__main__":
    unittest.main(verbosity=2)
```

## Exercises with answers

1. When do three ordinary-annuity payments occur? **Answer:** At the ends of periods 1, 2, and 3.
2. Find PV of three $100 payments at 10%. **Answer:** Approximately $248.69.
3. Find FV of those payments at the end of year 3. **Answer:** $331.
4. Find PV of five $200 payments at 0%. **Answer:** $1,000.
5. Convert 6% nominal annual compounded monthly. **Answer:** 0.5% per month.
6. Convert 6% effective annual to monthly effective. **Answer:** (1.06)^(1/12) - 1, approximately 0.48676%.
7. State the inverse-payment formula. **Answer:** C = P × i/[1 - (1+i)^(-n)] for i not zero.
8. Find PV of two $100 payments at -10% periodic. **Answer:** Approximately $234.57.
9. Reconcile PV and FV. **Answer:** FV = PV × (1+i)^n.
10. What does a negative payment represent? **Answer:** An outflow from the chosen perspective.
11. What is the PV of zero payments? **Answer:** Zero.
12. How can the formula be independently checked? **Answer:** Discount each dated payment and sum the results.
