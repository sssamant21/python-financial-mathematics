## Learning objectives

Represent nonuniform cash-flow amounts and dates, choose an explicit day-count convention, discount each payment to a valuation date, distinguish dated valuation from equal-period annuity calculations, and validate a Python XNPV-style engine.

## 1. Why irregular cash flows matter

Most real projects do not produce perfectly level payments at identical intervals. Construction draws, milestone invoices, healthcare claims reimbursements, and equipment maintenance expenses can have irregular dates and amounts. An ordinary annuity factor cannot accurately represent arbitrary schedules.

Consider these example transactions:

| Date | Cash flow | Explanation |
|---|---:|---|
| 2026-01-01 | -$1,000 | Initial investment |
| 2026-04-15 | +$250 | Interim receipt |
| 2026-11-30 | +$500 | Milestone receipt |
| 2027-03-01 | +$400 | Final receipt |

Positive amounts are inflows, and negative amounts are outflows from the chosen perspective.

## 2. Dates, day counts, and discounting

Let the valuation date be D0 and the payment date be Dk. Define the year fraction under an **Actual/365 Fixed** convention:

**tau(k) = (Dk - D0 in calendar days)/365.**

For a constant **effective annual discount rate r > -1**, the present value is:

**PV(D0) = sum over k of Ck / (1+r)^tau(k).**

The number 365 is fixed even in leap years. This is a modeling choice, not a universal market convention. Actual/Actual, 30/360, business-day calendars, and continuously compounded rates can give different values.

## 3. Worked example: dated investment

For the example above, discount each receipt from its actual payment date to 2026-01-01:

PV = -1000 + 250/(1+r)^(104/365) + 500/(1+r)^(333/365) + 400/(1+r)^(424/365).

The date differences should be checked against a calendar or a date library. At r = 10%, the Python reference function calculates the value without rounding intermediate terms.

## 4. Selecting a valuation date

A cash-flow engine should not assume the earliest payment is always the desired reporting date. The anchor may be the investment date, reporting date, or settlement date. If a cash flow occurs before the chosen anchor, its exponent is negative and the amount is accumulated forward to the anchor.

The reference implementation defaults to the earliest date for convenience but accepts an explicit `anchor`. This default is a software interface choice, not a financial requirement.

## 5. Repeated dates, ordering, and signs

Two cash flows can occur on the same date and can be combined algebraically. Sorting is useful for reporting, but the valuation should not change when transaction order changes. Both inflows and outflows must be retained, and the rate must match the stated compounding convention.

An empty cash-flow schedule has zero value in the reference implementation. Missing transactions must not silently be treated as empty schedules in production systems.

## 6. Risk and numerical limitations

The model assumes a single constant effective annual rate and deterministic cash flows. Real valuation may require a discount curve, credit adjustments, currency conversion, taxes, inflation scenarios, and settlement calendars. For large time spans and negative rates close to -100%, numerical overflow is possible. The implementation validates finite inputs and reports unsupported results.

The lab includes twelve tests for the valuation anchor, one-year discounting, zero and negative rates, transaction order, repeated dates, leap-year behavior, signed flows, and invalid input.

```python
"""Irregular dated cash-flow valuation using actual/365 fixed."""
from datetime import date
from math import exp, fsum, isfinite, log1p
import unittest

def xnpv(rate, flows, anchor=None):
    if isinstance(rate, bool) or not isinstance(rate, (int, float)) or not isfinite(rate) or rate <= -1:
        raise ValueError("rate must be finite and greater than -1")
    data = list(flows)
    if not data:
        return 0.0
    for day, amount in data:
        if not isinstance(day, date) or isinstance(day, __import__("datetime").datetime):
            raise TypeError("dates must be datetime.date")
        if isinstance(amount, bool) or not isinstance(amount, (int, float)) or not isfinite(amount):
            raise ValueError("amounts must be finite numbers")
    if anchor is None:
        anchor = min(day for day, _ in data)
    if not isinstance(anchor, date) or isinstance(anchor, __import__("datetime").datetime):
        raise TypeError("anchor must be datetime.date")
    try:
        value = fsum(amount * exp(-((day-anchor).days/365)*log1p(rate))
                     for day, amount in data)
    except OverflowError as exc:
        raise ValueError("discount overflow") from exc
    if not isfinite(value):
        raise ValueError("result not finite")
    return value

class Tests(unittest.TestCase):
    def setUp(self):
        self.a = date(2026,1,1)
    def test_01_anchor(self):
        self.assertEqual(xnpv(.1,[(self.a,100)]),100)
    def test_02_one_year(self):
        self.assertAlmostEqual(xnpv(.1,[(self.a,0),(date(2027,1,1),110)]),100)
    def test_03_zero_rate(self):
        self.assertEqual(xnpv(0,[(self.a,-100),(date(2027,1,1),150)]),50)
    def test_04_mixed(self):
        self.assertAlmostEqual(xnpv(.1,[(self.a,-100),(date(2027,1,1),110)]),0)
    def test_05_order(self):
        a=[(date(2027,1,1),110),(self.a,-100)]
        self.assertAlmostEqual(xnpv(.1,a),xnpv(.1,list(reversed(a))))
    def test_06_repeated_date(self):
        self.assertEqual(xnpv(.1,[(self.a,10),(self.a,20)]),30)
    def test_07_leap_year(self):
        self.assertAlmostEqual(xnpv(.1,[(date(2024,1,1),0),(date(2025,1,1),100)]),
                               100/(1.1**(366/365)))
    def test_08_negative_rate(self):
        self.assertAlmostEqual(xnpv(-.1,[(self.a,0),(date(2027,1,1),90)]),100)
    def test_09_future_anchor(self):
        self.assertAlmostEqual(xnpv(.1,[(self.a,100)],date(2027,1,1)),110)
    def test_10_empty(self):
        self.assertEqual(xnpv(.1,[]),0)
    def test_11_negative_amount(self):
        self.assertEqual(xnpv(.1,[(self.a,-100)]),-100)
    def test_12_invalid(self):
        with self.assertRaises(ValueError): xnpv(-1,[(self.a,100)])
        with self.assertRaises(TypeError): xnpv(.1,[("2026-01-01",100)])
        with self.assertRaises(ValueError): xnpv(.1,[(self.a,float("nan"))])

if __name__ == "__main__":
    unittest.main(verbosity=2)
```

## 8. Exercises and worked answers

1. **Why not use a level annuity factor?** **Answer:** The payment amounts and dates need not be uniform.
2. **What does a negative cash flow mean?** **Answer:** An outflow from the chosen perspective.
3. **Define Actual/365 Fixed.** **Answer:** Divide actual calendar-day differences by 365.
4. **What is the year fraction for 365 days?** **Answer:** 1.
5. **What is the year fraction for 366 days?** **Answer:** 366/365, not 1.
6. **Value $110 exactly 365 days after the anchor at 10%.** **Answer:** $100.
7. **Value $100 on the valuation date.** **Answer:** $100.
8. **Value a -$100 outflow on the valuation date.** **Answer:** -$100.
9. **Does reordering transactions affect PV?** **Answer:** No, aside from insignificant floating-point summation differences.
10. **How do two payments of $10 and $20 on one date combine?** **Answer:** Into one $30 payment on that date.
11. **What happens at zero discount rate?** **Answer:** PV is the sum of signed payments.
12. **What should a reviewer verify before using the result?** **Answer:** Dates, currency, signs, rate convention, day-count convention, and completeness of transactions.
