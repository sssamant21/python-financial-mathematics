## 1. Cash-flow timeline fundamentals

A cash-flow timeline maps each amount to a date or modeled time. Positive amounts represent receipts and negative amounts represent payments from the chosen perspective.

```text
Year             0                 1                 2
                 |-----------------|-----------------|
Cash flow      -1000             +600              +600
                 ^
            valuation date
```

The valuation date is the origin of the timeline. An initial cost already included as a negative time-zero flow must not be deducted twice.

For cash flows \\(C_i\\) at year fractions \\(t_i\\) and a constant effective annual rate \\(r>-1\\), present value is

\\[ V_0=\\sum_i C_i(1+r)^{-t_i}. \\]

A time-zero event has discount factor one. At 10% effective annual, a receipt of 110 USD exactly one modeled year away has present value 100 USD.

## 2. Calendar dates versus model years

A calendar year and a model year fraction are not always identical. A day-count convention maps actual dates to numerical year fractions. This chapter demonstrates:

- **ACT/365F:** actual days divided by 365, including 366/365 for a leap-year span.
- **ACT/360:** actual days divided by 360, giving 365/360 for a 365-day span.

Other standards, such as ACT/ACT and 30/360, require their own explicitly specified rules and are not implemented here. The examples use annual effective discounting applied to the resulting fractions, which is an explicit modeling choice.

## 3. Multiple and irregular events

Cash flows may occur on arbitrary dates, and multiple events may share a date. Preserve each event for auditability, even if same-date amounts could be netted. Sort by date using a stable algorithm so the original order of equal-date records is retained.

**Example:** -100 USD on January 1, 2026 and +110 USD on January 1, 2027 have NPV zero at 10% effective annual under ACT/365F because the dates are exactly 365 days apart.

The lab includes ten tests for year zero, day-count conventions, event ordering, same-day stability, discounting, NPV, leap years, empty schedules, and invalid inputs.

```python
from dataclasses import dataclass
from datetime import date
import math
import unittest

@dataclass(frozen=True)
class CashFlow:
    when: date
    amount: float
    label: str = ""
    def __post_init__(self):
        if not isinstance(self.when, date):
            raise TypeError("date required")
        if isinstance(self.amount, bool) or not isinstance(self.amount, (int, float)):
            raise TypeError("numeric amount required")
        if not math.isfinite(self.amount):
            raise ValueError("finite amount required")

def year_fraction(origin, when, basis="ACT/365F"):
    if not isinstance(origin, date) or not isinstance(when, date):
        raise TypeError("dates required")
    if when < origin:
        raise ValueError("historical event not supported")
    denominators = {"ACT/365F":365, "ACT/360":360}
    if basis not in denominators:
        raise ValueError("unsupported basis")
    return (when-origin).days/denominators[basis]

def schedule(events, origin, basis="ACT/365F"):
    return [(year_fraction(origin,e.when,basis),e.amount,e.label)
            for e in sorted(events,key=lambda e:e.when)]

def npv(events, origin, rate, basis="ACT/365F"):
    if isinstance(rate,bool) or not isinstance(rate,(int,float)):
        raise TypeError("numeric rate required")
    if not math.isfinite(rate) or rate <= -1:
        raise ValueError("invalid effective annual rate")
    terms=[]
    for t,amount,_ in schedule(events,origin,basis):
        term=amount*math.exp(-t*math.log1p(rate))
        if not math.isfinite(term):
            raise ValueError("nonfinite present value")
        terms.append(term)
    return math.fsum(terms)

class Tests(unittest.TestCase):
    def setUp(self):
        self.d=date(2026,1,1)
    def test_01_zero(self): self.assertEqual(year_fraction(self.d,self.d),0)
    def test_02_365(self): self.assertEqual(year_fraction(self.d,date(2027,1,1)),1)
    def test_03_360(self): self.assertAlmostEqual(year_fraction(self.d,date(2027,1,1),"ACT/360"),365/360)
    def test_04_sort(self):
        a=[CashFlow(date(2027,1,1),110),CashFlow(self.d,-100)]
        self.assertEqual(schedule(a,self.d)[0][1],-100)
    def test_05_same_day(self):
        a=[CashFlow(self.d,1,"first"),CashFlow(self.d,2,"second")]
        self.assertEqual([x[2] for x in schedule(a,self.d)],["first","second"])
    def test_06_discount(self): self.assertAlmostEqual(npv([CashFlow(date(2027,1,1),110)],self.d,.1),100)
    def test_07_npv(self): self.assertAlmostEqual(npv([CashFlow(self.d,-100),CashFlow(date(2027,1,1),110)],self.d,.1),0)
    def test_08_leap(self): self.assertAlmostEqual(year_fraction(date(2024,1,1),date(2025,1,1)),366/365)
    def test_09_empty(self): self.assertEqual(npv([],self.d,.05),0)
    def test_10_validation(self):
        with self.assertRaises(ValueError): year_fraction(self.d,date(2025,1,1))
        with self.assertRaises(ValueError): year_fraction(self.d,self.d,"30/360")
        with self.assertRaises(ValueError): npv([],self.d,-1)
        with self.assertRaises(TypeError): CashFlow(self.d,True)

if __name__=="__main__":
    unittest.main(verbosity=2)
```

## 5. Exercises with worked answers

1. **Perspective:** A borrower receives 10,000 USD today and pays 11,000 USD in a year. **Answer:** +10,000 at time zero; -11,000 at year one.
2. **Time zero:** Discount a -250 USD payment today. **Answer:** -250 USD.
3. **ACT/365F:** January 1, 2026 to January 1, 2027. **Answer:** 365/365 = 1.
4. **ACT/360:** The same dates. **Answer:** 365/360 ≈ 1.013889.
5. **Leap year:** January 1, 2024 to January 1, 2025 under ACT/365F. **Answer:** 366/365 ≈ 1.002740.
6. **Same-day events:** Two receipts of 100 and 150 USD today. **Answer:** 250 USD combined present value.
7. **Discount:** 110 USD in one modeled year at 10% effective annual. **Answer:** 100 USD.
8. **NPV:** -100 USD now, +110 USD in one year at 10%. **Answer:** Zero.
9. **Reordering:** Does reordering dated events change their NPV? **Answer:** No, aside from possible floating-point summation differences; this lab uses `math.fsum`.
10. **Audit:** Why retain separate same-day events? **Answer:** They preserve event-level traceability.
