## Objectives

Derive the finite growing-annuity present-value formula, identify first-payment timing, handle equal growth and discount rates, compute future value, and independently verify calculations using a dated payment stream.

## Definition and timeline

A growing annuity is a **finite** sequence of regular payments increasing or decreasing at a constant periodic growth rate g. For an end-of-period stream with first payment C at period 1, the payment at period k is C(1+g)^(k-1).

```text
Period       0          1           2             3
             |----------|-----------|-------------|
Payment                 C         C(1+g)       C(1+g)^2
```

The first payment is C, not C(1+g). The discount rate i and payment growth rate g must use the same period. Assume i > -1, g > -1, and n is a nonnegative integer.

## Present-value derivation

The value at time zero is the sum from k = 1 through n of:

C × (1+g)^(k-1) / (1+i)^k.

This is a finite geometric series with ratio (1+g)/(1+i). When i differs from g:

**PV = C × [1 - ((1+g)/(1+i))^n] / (i-g).**

When **i = g**, each discounted payment equals C/(1+i), so:

**PV = n × C/(1+i).**

When n = 0, PV = 0. When g = 0, the formula reduces to the ordinary level-annuity formula. The finite series remains defined when g > i; the convergence condition for an infinite growing perpetuity does not apply here.

## Worked example

Three annual payments start at $100 and grow 5% each year: $100 at year 1, $105 at year 2, and $110.25 at year 3. At 10% effective annual discounting:

PV = 100/1.1 + 105/1.1² + 110.25/1.1³.

The same result follows from the closed-form formula. The lab below checks this equivalence.

## Future value

Accumulate the time-zero value to the end of period n:

**FV = PV × (1+i)^n.**

This assumes the same periodic rate throughout and measures future value at the final payment date.

## Modeling and numerical safeguards

A negative g between -1 and 0 represents declining payments. Negative C represents outgoing payments from the chosen perspective. Rates must be aligned with payment frequency. For near-equal i and g, subtracting two logarithms can lose precision. The implementation computes the log of their ratio using `log1p((g-i)/(1+i))`, uses `expm1`, and handles i = g explicitly. For extreme ratios that round to −1 or overflow, it falls back to a difference of logarithms; this fallback does not guarantee accuracy across all magnitudes. Overflow, payment uncertainty, fees, taxes, and contractual cent rounding require separate policies.

The reference implementation contains fourteen tests covering timeline valuation, closed-form reconciliation, equal and near-equal rates, zero growth, zero discounting, negative growth, growth exceeding discounting, terminal value, signs, and invalid inputs.

```python
import math
import unittest
from decimal import Decimal, localcontext

def pv(first, discount, growth, periods):
    if isinstance(periods, bool) or not isinstance(periods, int) or periods < 0:
        raise ValueError("periods must be nonnegative integer")
    for x in (first, discount, growth):
        if isinstance(x, bool) or not isinstance(x, (int,float)) or not math.isfinite(x):
            raise ValueError("finite numeric inputs required")
    if discount <= -1 or growth <= -1:
        raise ValueError("rates must exceed -1")
    if periods == 0:
        return 0.0
    if discount == growth:
        return first * periods / (1 + discount)
    ratio_change = (growth - discount) / (1.0 + discount)
    if math.isfinite(ratio_change) and ratio_change > -1.0:
        log_ratio = math.log1p(ratio_change)
    else:
        log_ratio = math.log1p(growth) - math.log1p(discount)
    x = periods * log_ratio
    try:
        result = first * (-math.expm1(x)) / (discount - growth)
    except OverflowError as exc:
        raise ValueError("present value overflow") from exc
    if not math.isfinite(result):
        raise ValueError("present value overflow")
    return result

def pv_timeline(first, discount, growth, periods):
    pv(first, discount, growth, periods)
    return math.fsum(first * math.exp((k-1)*math.log1p(growth)
                                    -k*math.log1p(discount))
                     for k in range(1,periods+1))

def fv(first, discount, growth, periods):
    value = pv(first, discount, growth, periods)
    try:
        result = value * math.exp(periods * math.log1p(discount))
    except OverflowError as exc:
        raise ValueError("future value overflow") from exc
    if not math.isfinite(result):
        raise ValueError("future value overflow")
    return result

class Tests(unittest.TestCase):
    def test_01_timeline(self):
        self.assertAlmostEqual(pv_timeline(100,.1,.05,3),
                               100/1.1+105/1.1**2+110.25/1.1**3)
    def test_02_closed_form(self):
        self.assertAlmostEqual(pv(100,.1,.05,3),pv_timeline(100,.1,.05,3))
    def test_03_equal_rates(self):
        self.assertAlmostEqual(pv(100,.05,.05,4),400/1.05)
    def test_04_level_annuity(self):
        self.assertAlmostEqual(pv(100,.1,0,3),
                               sum(100/1.1**k for k in range(1,4)))
    def test_05_zero_discount(self):
        self.assertAlmostEqual(pv(100,0,.1,3),331)
    def test_06_zero_periods(self):
        self.assertEqual(pv(100,.1,.05,0),0)
    def test_07_negative_growth(self):
        self.assertAlmostEqual(pv(100,.1,-.1,3),pv_timeline(100,.1,-.1,3))
    def test_08_growth_above_discount(self):
        self.assertAlmostEqual(pv(100,.03,.08,5),pv_timeline(100,.03,.08,5))
    def test_09_fv(self):
        self.assertAlmostEqual(fv(100,.1,.05,3),pv(100,.1,.05,3)*1.1**3)
    def test_10_signed(self):
        self.assertAlmostEqual(pv(-100,.1,.05,3),-pv(100,.1,.05,3))
    def test_11_near_equal(self):
        self.assertAlmostEqual(pv(100,.05,.05+1e-10,12),
                               pv_timeline(100,.05,.05+1e-10,12),places=5)
    def test_13_near_equal_decimal_reference(self):
        discount, growth, periods = .05, .05 + 1e-10, 12
        with localcontext() as ctx:
            ctx.prec = 70
            d, g = Decimal.from_float(discount), Decimal.from_float(growth)
            expected = sum(Decimal(100) * (1 + g)**(k - 1) / (1 + d)**k
                           for k in range(1, periods + 1))
        self.assertTrue(math.isclose(pv(100, discount, growth, periods),
                                     float(expected), rel_tol=0.0, abs_tol=1e-9))
    def test_14_extreme_ratio_fallback(self):
        self.assertTrue(math.isclose(pv(100, 1e308, -.5, 1), 1e-306,
                                     rel_tol=1e-12, abs_tol=0.0))
    def test_12_invalid(self):
        with self.assertRaises(ValueError): pv(100,-1,.05,3)
        with self.assertRaises(ValueError): pv(100,.05,-1,3)
        with self.assertRaises(ValueError): pv(100,.05,.02,2.5)
        with self.assertRaises(ValueError): pv(True,.05,.02,3)

if __name__ == "__main__":
    unittest.main(verbosity=2)
```

## Exercises and answers

1. List three payments starting at $100 and growing 5%. **Answer:** $100, $105, $110.25.
2. Write their PV at 10%. **Answer:** 100/1.1 + 105/1.1² + 110.25/1.1³.
3. Find PV when C = $100, n = 4, and i = g = 5%. **Answer:** 400/1.05, approximately $380.95.
4. What happens when g = 0? **Answer:** The ordinary level-annuity formula applies.
5. Find PV of $100, $110, and $121 when i = 0. **Answer:** $331.
6. List three payments for C = $100 and g = -10%. **Answer:** $100, $90, $81.
7. Can g exceed i for a finite annuity? **Answer:** Yes.
8. Find PV when n = 0. **Answer:** Zero.
9. Convert PV to FV at time n. **Answer:** Multiply by (1+i)^n.
10. How should payer outflows be signed? **Answer:** Negative.
11. Why is an equal-rate branch necessary? **Answer:** The general formula has a zero denominator at i = g, while its limit exists.
12. How can PV be independently audited? **Answer:** Generate each payment, discount it by its own period, and sum.
