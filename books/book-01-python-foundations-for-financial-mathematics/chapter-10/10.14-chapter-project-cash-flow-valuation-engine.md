## Project brief

Build a reusable, auditable **finite, integer-period cash-flow valuation engine** in Python using only the standard library. The engine will represent signed cash flows, generate ordinary, due, deferred, and growing payment schedules, calculate values at any integer-period date, compute net present value (NPV), and solve for an internal rate of return (IRR) using a bracketed numerical method.

The engine deliberately **does not implement infinite perpetuities**: these are valued analytically in Sections 10.8–10.9. It also does not implement irregular calendar dates, which require a documented day-count convention as discussed in Section 10.11. This explicit scope avoids mixing periodic and dated models.

## Learning outcomes and acceptance criteria

By the end of the project, the reader should be able to:

1. Define a typed cash-flow record with a nonnegative integer period and signed amount.
2. Generate ordinary, due, deferred, and growing finite annuities without off-by-one timing errors.
3. Discount or accumulate all cash flows to a specified valuation period.
4. Reconcile NPV and future value using the identity V(T) = PV × (1+r)^T.
5. Solve an IRR within a specified bracket and report when no sign change is present.
6. Run a repeatable set of unit tests and explain the financial assumptions and numerical limitations.

## 1. Architecture and data contract

A `CashFlow` object has two fields: `period` and `amount`. Period 0 is the valuation origin, period 1 is the first complete period, and negative amounts represent outflows. The discount rate is effective **per period**, and must exceed -100%.

```text
Signed CashFlow records
        |
        +--> ordinary / due / deferred / growing schedule builders
        |
        +--> value_at(flows, rate, period)
                    |
                    +--> NPV: value_at(..., period=0)
                    +--> FV:  value_at(..., period=T)
                    +--> IRR: root of value_at(..., period=0)
```

This design separates **cash-flow construction** from **valuation**. It makes the model easier to test and prevents an annuity formula from hiding payment timing.

## 2. Core valuation equation

For cash flows Ck at integer periods tk and a constant effective periodic rate r > -1, the value at period T is:

**V(T) = sum over k of Ck × (1+r)^(T-tk).**

At T = 0, this is present value (or NPV when the stream represents all project cash flows). At a later horizon, the same function produces future value. For a fixed rate:

**V(T) = V(0) × (1+r)^T.**

The engine uses `math.log1p`, `math.exp`, and `math.fsum` for reasonably stable evaluation of finite cash-flow sums. Very large exponents may still overflow; production implementations need scale-specific numeric controls.

## 3. Schedule generation

The `ordinary` function creates a level stream with default payment dates 1 through n. Setting `start=0` produces an annuity due. Setting `start=d+1` produces a deferred ordinary annuity whose first payment occurs at period d+1.

The `growing` function creates payments C, C(1+g), C(1+g)^2, ... at successive periods, where the first payment is **C** and g > -1. Both builders return explicit records so the generated timeline can be inspected.

## 4. NPV and IRR workflow

NPV is the value of the complete signed project stream at time zero. IRR is a rate that makes this NPV zero.

The `irr` function uses bisection on an explicitly supplied bracket. It rejects a bracket without opposite-sign endpoint values. This is a **single-bracket solver**, not a comprehensive root enumerator. For nonconventional cash flows, multiple IRRs may exist, so scan plausible brackets and analyze NPV directly rather than relying on a single IRR.

## 5. Worked project scenario

A project requires $100 at time zero and produces $60 at periods 1 and 2. At a 10% periodic required return:

NPV = -100 + 60/1.1 + 60/1.1² ≈ **+$4.13**.

The project IRR is approximately **13.07%**. The Python example prints both quantities. Compare them with an independent spreadsheet or calculator, and inspect the cash-flow dates before accepting the result.

```python
"""Chapter 10 capstone: finite periodic cash-flow valuation engine."""
from dataclasses import dataclass
from math import exp, fsum, isfinite, log1p
import unittest

@dataclass(frozen=True)
class CashFlow:
    period: int
    amount: float

    def __post_init__(self):
        if isinstance(self.period, bool) or not isinstance(self.period, int) or self.period < 0:
            raise ValueError("period must be a nonnegative integer")
        if isinstance(self.amount, bool) or not isinstance(self.amount, (int, float)) or not isfinite(self.amount):
            raise ValueError("amount must be finite numeric")

def check_rate(rate):
    if isinstance(rate, bool) or not isinstance(rate, (int, float)) or not isfinite(rate) or rate <= -1:
        raise ValueError("periodic rate must be finite and > -1")

def value_at(flows, rate, period=0):
    check_rate(rate)
    if isinstance(period, bool) or not isinstance(period, int) or period < 0:
        raise ValueError("valuation period must be a nonnegative integer")
    data = list(flows)
    if not all(isinstance(x, CashFlow) for x in data):
        raise TypeError("flows must contain CashFlow objects")
    try:
        result = fsum(x.amount * exp((period-x.period)*log1p(rate)) for x in data)
    except OverflowError as exc:
        raise ValueError("valuation overflow") from exc
    if not isfinite(result):
        raise ValueError("valuation overflow")
    return result

def ordinary(payment, count, start=1):
    if isinstance(count, bool) or not isinstance(count, int) or count < 0:
        raise ValueError("count must be a nonnegative integer")
    if isinstance(start, bool) or not isinstance(start, int) or start < 0:
        raise ValueError("start must be a nonnegative integer")
    return [CashFlow(start+k, payment) for k in range(count)]

def growing(first, growth, count, start=1):
    if isinstance(growth, bool) or not isinstance(growth, (int,float)) or not isfinite(growth) or growth <= -1:
        raise ValueError("growth must be finite and > -1")
    if isinstance(count, bool) or not isinstance(count,int) or count < 0:
        raise ValueError("count must be a nonnegative integer")
    if isinstance(start, bool) or not isinstance(start,int) or start < 0:
        raise ValueError("start must be a nonnegative integer")
    return [CashFlow(start+k, first*(1+growth)**k) for k in range(count)]

def irr(flows, low=0.0, high=1.0, tolerance=1e-10, iterations=300):
    data=list(flows)
    if not data or not any(x.amount>0 for x in data) or not any(x.amount<0 for x in data):
        raise ValueError("IRR requires both cash-flow signs")
    if not (-1 < low < high) or tolerance <= 0 or iterations < 1:
        raise ValueError("invalid root bracket or tolerance")
    a,b=low,high
    fa,fb=value_at(data,a),value_at(data,b)
    if abs(fa)<tolerance: return a
    if abs(fb)<tolerance: return b
    if fa*fb>0:
        raise ValueError("no sign change within bracket")
    for _ in range(iterations):
        mid=(a+b)/2
        fm=value_at(data,mid)
        if abs(fm)<tolerance or b-a < tolerance:
            return mid
        if fa*fm<0: b,fb=mid,fm
        else: a,fa=mid,fm
    raise RuntimeError("IRR did not converge")

class EngineTests(unittest.TestCase):
    def test_01_initial(self):
        self.assertEqual(value_at([CashFlow(0,-100)],.1),-100)
    def test_02_ordinary(self):
        self.assertAlmostEqual(value_at(ordinary(100,3),.1),sum(100/1.1**k for k in (1,2,3)))
    def test_03_due(self):
        self.assertAlmostEqual(value_at(ordinary(100,3,0),.1),100+100/1.1+100/1.1**2)
    def test_04_deferred(self):
        self.assertAlmostEqual(value_at(ordinary(100,3,3),.1),sum(100/1.1**k for k in (3,4,5)))
    def test_05_growing(self):
        self.assertAlmostEqual(value_at(growing(100,.05,3),.1),100/1.1+105/1.1**2+110.25/1.1**3)
    def test_06_fv_identity(self):
        a=ordinary(100,3)
        self.assertAlmostEqual(value_at(a,.1,3),value_at(a,.1)*1.1**3)
    def test_07_mixed(self):
        a=[CashFlow(0,-100),CashFlow(1,60),CashFlow(2,60)]
        self.assertAlmostEqual(value_at(a,.1),-100+60/1.1+60/1.1**2)
    def test_08_irr(self):
        a=[CashFlow(0,-100),CashFlow(1,110)]
        self.assertAlmostEqual(irr(a),.1,places=8)
    def test_09_multiple_irr(self):
        a=[CashFlow(0,-100),CashFlow(1,230),CashFlow(2,-132)]
        self.assertAlmostEqual(irr(a,.05,.15),.1,places=7)
        self.assertAlmostEqual(irr(a,.15,.3),.2,places=7)
    def test_10_zero(self):
        self.assertEqual(value_at([],.1),0)
    def test_11_invalid(self):
        with self.assertRaises(ValueError): CashFlow(-1,100)
        with self.assertRaises(ValueError): value_at([], -1)
        with self.assertRaises(ValueError): growing(100,-1,3)
    def test_12_no_bracket(self):
        a=[CashFlow(0,-100),CashFlow(1,40)]
        with self.assertRaises(ValueError): irr(a,.1,.5)

if __name__ == "__main__":
    example=[CashFlow(0,-100),CashFlow(1,60),CashFlow(2,60)]
    print("NPV at 10%:", round(value_at(example,.1),2))
    print("IRR:", round(irr(example),6))
    unittest.main(verbosity=2)
```

## 8. Troubleshooting and extension ideas

**Incorrect NPV:** Check whether the initial outflow is entered at period 0 and whether cash flows are signed consistently.

**Annuity off by one period:** Print the generated records and compare them against a timeline before evaluating.

**IRR solver rejects a bracket:** Evaluate NPV at both endpoints, try economically plausible alternative intervals, and investigate possible multiple or absent roots.

**Monthly versus annual mismatch:** Convert rates and payment periods consistently before valuation.

**Extension:** Add date-aware cash flows using Actual/365 Fixed, Decimal-based monetary rounding, scenario analysis, structured CSV input, and automated reconciliation reports. Each extension should have independent tests and clearly stated conventions.
