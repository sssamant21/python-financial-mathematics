## Learning objectives

Understand pseudo-random number generators (PRNGs), seeds and generator state; build reproducible financial simulations; distinguish reproducibility from statistical validity; use variance-reduction techniques; design simulation manifests; and choose cryptographic randomness for security-sensitive tasks.

## 1. Why reproducibility matters in finance

Simulation is widely used for portfolio scenario analysis, default-count models, pricing prototypes, operational risk, and stress tests. A model that cannot reproduce its inputs and outputs is difficult to audit, debug, or compare after changes.

A **pseudo-random number generator** produces a deterministic sequence that resembles random samples for its intended statistical use. A seed initializes the generator state. Repeating the same algorithm, seed, draw order, and compatible runtime reproduces the sequence.

**Reproducible does not mean correct.** A biased model can be reproduced perfectly.

## 2. Pseudo-random versus physical randomness

Python's standard-library `random` module implements a general-purpose PRNG suitable for educational simulation and many non-security modeling tasks. It is **not cryptographically secure**.

For tokens, passwords, session identifiers, and security secrets, use `secrets` or an approved cryptographic randomness source. Do not substitute a fixed-seed PRNG for security requirements.

## 3. Seeds, state, and draw order

```python
import random
rng = random.Random(42)
print([rng.random() for _ in range(3)])
```

The generator produces values in [0,1). Recreating `random.Random(42)` and repeating the same calls produces a repeatable sequence in a compatible environment.

The sequence can change if the code inserts extra draws or changes algorithms. Avoid relying on global `random.seed()` in larger projects because unrelated modules may consume the shared state.

### Worked example A — Isolated simulations

Two independently created `random.Random(42)` objects begin from equivalent state and reproduce the same sequence. They are not two independent random experiments: their draws match exactly.

## 4. Sampling from distributions

Uniform random values are a starting point for many sampling methods.

For a Bernoulli event with probability p, define **D=1 if U<p**, otherwise zero, where U is idealized Uniform(0,1).

For an exponential waiting time with rate λ>0, inverse-transform sampling gives:

**T=−ln(1−U)/λ**.

For λ=.5 per hour, the expected waiting time is 2 hours.

Python's `random.gauss(mu, sigma)` generates normal samples. `random.choices` generates weighted discrete scenarios with replacement.

## 5. Financial scenario engine

Consider hypothetical net payoffs:

| Scenario | Probability | Payoff |
|---|---:|---:|
| Downside | .25 | −$20 |
| Base | .50 | +$5 |
| Upside | .25 | +$30 |

The exact expected payoff is:

**E[X]=.25(−20)+.50(5)+.25(30)=$5.**

Monte Carlo draws approximate this expectation. With n iid draws and finite variance σ², the standard error of the simulated mean is **σ/√n**.

The exact variance for this distribution is 312.5 dollars², so for n=10,000:

**SE≈√312.5/100≈$0.17678.**

A fixed seed reproduces the simulated estimate, but does not force it to equal the exact $5.

## 6. Monte Carlo error versus model risk

**Monte Carlo error** arises from finite random sampling of a specified model.

**Model risk** arises from wrong assumptions, input probabilities, dependence structures, calibration, or scenario definitions.

Increasing the number of draws typically reduces Monte Carlo error, but cannot remove model misspecification.

Under iid finite-variance sampling, increasing n by a factor of four approximately halves the standard error. Computational costs typically increase with sample count.

## 7. Common random numbers

**Common random numbers (CRN)** compare two alternatives using the same underlying random draws. When the paired outputs are positively correlated, the variance of their difference may be smaller than when using independent streams.

For simulated outcomes A and B:

**Var(A−B)=Var(A)+Var(B)−2Cov(A,B).**

### Worked example B — Deterministic scenario shift

If stressed payoff B=A+.02 for every simulated draw, then every paired difference B−A equals .02. Its sample mean is exactly .02 apart from floating-point rounding, even with few draws.

CRN is not universally beneficial; if covariance is negative, it can increase variance of differences.

## 8. Antithetic variates

For U uniform on (0,1), **1−U** is also uniform. Pairing transformed outcomes g(U) and g(1−U) can reduce variance when their covariance is negative.

This is a variance-reduction technique, not a guarantee. Measure the empirical variance of the paired estimator and validate unbiasedness under the model.

## 9. Stratified sampling

Divide the random input space into strata, sample each stratum, and combine estimates with correct weights. This can improve coverage of rare or important regions, including financial downside scenarios.

Incorrect stratum weighting produces bias. Rare-event sampling requires special care with likelihood weights.

## 10. Parallel simulation

Parallel workers must not accidentally clone identical generator state and generate duplicate sequences. A naïve approach of assigning consecutive integer seeds to workers is not a mathematical guarantee of independent substreams.

For large production simulations, use a vetted generator with documented stream-splitting or counter-based capabilities, record worker assignments, and test cross-worker reproducibility.

## 11. Simulation manifest and audit trail

Retain the following metadata with each run:

- Model name and version, code commit, and Python/runtime version.
- PRNG implementation, seed, and sampling algorithm.
- Sample count, scenario probabilities, and payoff units.
- Input data version and time horizon.
- Statistical summary, standard error, and uncertainty assumptions.
- Validation results and exception logs.

A SHA-256 hash of canonicalized configuration JSON can help identify the exact configuration bytes. It does not certify the accuracy or integrity of external input datasets unless those are included in the provenance scheme.

## 12. Numerical and operational safeguards

Validate all probabilities, payoffs, sample sizes, and seeds. Reject nonfinite inputs and zero-sum weights. Use `math.fsum` for accurate finite summation.

For very large simulations, avoid retaining every draw if online summaries are sufficient. Track runtime, memory, and failure rates. Preserve sufficient evidence to reproduce or explain results.

The lab uses only Python's standard library and includes deterministic uniform, normal, and weighted-scenario draws; a common-random-numbers comparison; a SHA-256 configuration manifest; and **12 reference unit tests**.

```python
import hashlib
import json
import math
import random
import secrets
import unittest

def validate(n, seed):
    if type(n) is not int or n <= 0 or type(seed) is not int:
        raise ValueError("n must be positive integer; seed must be integer")

def uniform_draws(n, seed):
    validate(n, seed)
    rng = random.Random(seed)
    return [rng.random() for _ in range(n)]

def normal_draws(n, seed, mu=0.0, sigma=1.0):
    validate(n, seed)
    if not all(type(v) in (int, float) and math.isfinite(v) for v in (mu, sigma)) or sigma <= 0:
        raise ValueError("invalid normal parameters")
    rng = random.Random(seed)
    return [rng.gauss(mu, sigma) for _ in range(n)]

def scenario_draws(values, weights, n, seed):
    validate(n, seed)
    values, weights = list(values), list(weights)
    if not values or len(values) != len(weights):
        raise ValueError("scenario length mismatch")
    if not all(type(x) in (int, float) and math.isfinite(x) for x in values):
        raise ValueError("nonfinite payoff")
    if not all(type(w) in (int, float) and math.isfinite(w) and w >= 0 for w in weights):
        raise ValueError("invalid weights")
    if math.fsum(weights) <= 0:
        raise ValueError("zero total weight")
    return random.Random(seed).choices(values, weights=weights, k=n)

def mean(xs):
    xs = list(xs)
    if not xs or not all(type(x) in (int, float) and math.isfinite(x) for x in xs):
        raise ValueError("finite nonempty sample required")
    return math.fsum(xs) / len(xs)

def paired_mean_difference(n, seed, shock=0.02):
    validate(n, seed)
    if type(shock) not in (int, float) or not math.isfinite(shock):
        raise ValueError("invalid shock")
    base = uniform_draws(n, seed)
    stressed = [x + shock for x in base]
    return mean(stressed) - mean(base)

def manifest(seed, n, scenario_weights):
    validate(n, seed)
    weights = list(scenario_weights)
    if not weights or not all(type(w) in (int, float) and math.isfinite(w) and w >= 0 for w in weights) or math.fsum(weights) <= 0:
        raise ValueError("invalid weights")
    payload = {"seed": seed, "n": n, "weights": weights, "generator": "random.Random"}
    canonical = json.dumps(payload, sort_keys=True, separators=(",", ":"))
    return {"configuration": payload, "sha256": hashlib.sha256(canonical.encode()).hexdigest()}

class RNGTests(unittest.TestCase):
    def test_01_replay(self): self.assertEqual(uniform_draws(50, 42), uniform_draws(50, 42))
    def test_02_seed_change(self): self.assertNotEqual(uniform_draws(10, 1), uniform_draws(10, 2))
    def test_03_range(self): self.assertTrue(all(0 <= x < 1 for x in uniform_draws(100, 3)))
    def test_04_length(self): self.assertEqual(len(uniform_draws(11, 1)), 11)
    def test_05_normal_replay(self): self.assertEqual(normal_draws(10, 5), normal_draws(10, 5))
    def test_06_scenarios(self): self.assertEqual(scenario_draws([-1, 1], [1, 3], 20, 8), scenario_draws([-1, 1], [1, 3], 20, 8))
    def test_07_scenario_length(self): self.assertEqual(len(scenario_draws([0, 1], [1, 1], 7, 2)), 7)
    def test_08_mean(self): self.assertEqual(mean([1, 2, 3]), 2)
    def test_09_crn(self): self.assertAlmostEqual(paired_mean_difference(100, 7), .02)
    def test_10_manifest(self): self.assertEqual(manifest(42, 100, [1, 2])["sha256"], manifest(42, 100, [1, 2])["sha256"])
    def test_11_crypto(self): self.assertEqual(len(secrets.token_bytes(16)), 16)
    def test_12_invalid(self):
        for f in (lambda: uniform_draws(0, 1), lambda: uniform_draws(2, True),
                  lambda: normal_draws(3, 1, sigma=0),
                  lambda: scenario_draws([1], [0], 3, 1),
                  lambda: manifest(1, 2, [])):
            with self.assertRaises(ValueError): f()

if __name__ == "__main__":
    result = unittest.TextTestRunner(verbosity=2).run(
        unittest.defaultTestLoader.loadTestsFromTestCase(RNGTests))
    if not result.wasSuccessful():
        raise SystemExit(1)
```

## 14. Twenty-four worked exercises

1. **PRNG replay:** Same seed 42 and algorithm. **Solution:** Identical draw sequence in the same supported runtime.

2. **Different seeds:** Seeds 1 and 2. **Solution:** Different sequences are expected, not a proof of statistical independence.

3. **Uniform support:** U generated by random(). **Solution:** 0≤U<1.

4. **Inverse Bernoulli:** Default if U<.02. **Solution:** P(default)=.02 for ideal uniform draws.

5. **Inverse exponential:** T=−ln(1−U)/λ, λ=.5. **Solution:** E[T]=2 hours.

6. **Normal scaling:** Z standard normal, R=.01+.02Z. **Solution:** E[R]=.01; SD(R)=.02.

7. **Scenario weights:** [1,2,1]. **Solution:** Normalized probabilities [.25,.5,.25].

8. **Expected payoff:** Payoffs −20,5,30 with weights .25,.5,.25. **Solution:** E[X]=$5.

9. **MC standard error:** σ=10,n=100. **Solution:** SE=1.

10. **Fourfold sample:** n=100→400. **Solution:** SE halves under iid finite-variance assumptions.

11. **Confidence interval:** Mean 5, SE 1. **Solution:** Approx 95% interval [3.04,6.96].

12. **Fixed seed:** Repeat run with seed 42. **Solution:** Useful for debugging and regression comparison.

13. **Global RNG hazard:** Another function consumes random draws. **Solution:** Later values can change if sharing global RNG state.

14. **Local RNG isolation:** Each experiment constructs Random(seed). **Solution:** Independent generator state from other modules.

15. **Common random numbers:** Same underlying U for base and stressed payoff. **Solution:** Paired differences can have reduced Monte Carlo variance.

16. **Paired deterministic shift:** Stressed=base+.02. **Solution:** Paired sample mean difference exactly .02, apart from floating error.

17. **Independent seeds caveat:** Different integer seeds. **Solution:** Do not assume independent substreams are mathematically guaranteed.

18. **Simulation budget:** 20,000 draws, 10 scenarios per draw. **Solution:** 200,000 scenario evaluations.

19. **Quantile reproducibility:** Same sample and quantile convention. **Solution:** Same empirical quantile.

20. **Manifest:** Seed, sample size, weights, version. **Solution:** Record as run metadata.

21. **Hash:** SHA-256 of canonical configuration JSON. **Solution:** Identifies configuration bytes, not model correctness.

22. **Cryptographic token:** Need secure random token. **Solution:** Use secrets, not random.Random.

23. **Risk model caveat:** More draws with incorrect PD. **Solution:** Lower MC noise but unchanged model bias.

24. **Parallel runs:** Workers receive overlapping RNG states. **Solution:** Duplicate or correlated streams can contaminate estimates.

## 15. Applied mini-project — Reproducible financial Monte Carlo engine

Build a simulation runner for the three-scenario portfolio and a stressed alternative.

### Input configuration

| Parameter | Value |
|---|---|
| Outcomes | −$20, +$5, +$30 |
| Weights | .25, .50, .25 |
| Sample sizes | 1,000 and 20,000 |
| Primary seed | 42 |
| Alternative seed | 2026 |
| Stress transformation | Add $2 to each payoff |

### Requirements

1. Validate weights, outcomes, seeds, and sample counts.
2. Calculate theoretical mean $5 and variance 312.5 dollars².
3. Run seeded samples for both sample sizes.
4. Repeat the same run and verify exact reproducibility.
5. Change the seed and compare results without treating the two streams as guaranteed independent.
6. Calculate estimated Monte Carlo standard errors.
7. Compare base and stressed portfolios using common random numbers.
8. Record configuration metadata and its SHA-256 fingerprint.
9. Explain simulation error, model risk, and cryptographic security boundaries.
10. Execute all 12 reference tests and retain evidence.

### Acceptance checkpoints

| Measure | Expected result |
|---|---:|
| Exact scenario mean | $5 |
| Exact scenario variance | 312.5 dollars² |
| Exact scenario SD | ≈$17.6777 |
| Approximate SE at n=10,000 | ≈$0.17678 |
| Paired mean shift for +$2 transformation | $2 |
| Same-seed replay | Identical sequences |
| Invalid weights or sample size | Explicit error |

Simulated means are random and must be evaluated using tolerances, not exact equality to the theoretical mean.

### Acceptance gate

The implementation must reject invalid inputs, reproduce fixed-seed runs, record configuration and model assumptions, and pass all 12 reference tests when independently executed. The engine must not claim that a reproducible Monte Carlo estimate is automatically a validated financial forecast.

## 16. Troubleshooting and runbook

| Symptom | Likely cause | Corrective action |
|---|---|---|
| Same-seed runs differ | Draw order, code, or runtime changed | Compare manifests and generator calls |
| Parallel workers produce identical results | Cloned generator state | Use vetted independent stream strategy |
| Simulation error stays high | Too few draws or heavy tails | Quantify uncertainty and adjust design |
| Results remain biased with larger n | Wrong model inputs | Review assumptions and calibration |
| Stress comparison is noisy | Unpaired scenarios | Consider common random numbers |
| Unexpected memory pressure | Retaining all draws | Use streaming summaries |
| Security token predictable | Non-cryptographic PRNG | Use `secrets` |
