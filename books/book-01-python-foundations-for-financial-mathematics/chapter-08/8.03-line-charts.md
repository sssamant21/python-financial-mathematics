## 1. Purpose

A line chart connects observations along an ordered horizontal variable. In financial work, that variable might be elapsed time, maturity, a scenario input, or a model parameter. The connection helps readers follow changes, but its meaning depends on what is known between the observations.

This section develops ordinary line charts, observation markers, missing-data breaks, and step charts. Its lab compares two supplied account-value paths with a separate position-state ledger. The distinction matters: an account valuation is observed at a point in time, whereas an authoritative position ledger may explicitly state that a quantity remains effective until its next update.

Section 8.4 extends these ideas to financial timestamps and calendars. Here the horizontal variable is a deliberately small grid of elapsed calendar-day offsets.

## 3. Coordinates and Connection Order

The basic call is:

```python
line, = ax.plot(x, y, marker="o", linestyle="-", label="Account A")
```

Here `ax` is an existing Axes and `x` and `y` contain corresponding coordinates. `plot` creates line Artists and supports properties such as markers, line style, color, and width [1]. Supplying x explicitly makes its units and spacing reviewable. If x is omitted, the horizontal positions are observation offsets, which may not describe the actual elapsed time.

A line follows the sequence of supplied coordinates. Do not assume that plotting will clean, chronologically sort, or reconcile duplicate observations for you. A sequence of days `[0, 3, 1]` can draw backward along the horizontal axis. In this lab, the analytical contract rejects unsorted and duplicate days. It does not silently sort them, because an unexplained reorder could hide an upstream data problem.

For financial data, equal-length arrays are only the first requirement. The values must also refer to the intended observations. A correctly shaped array of prices for one asset can still be mislabeled as another asset's data.

## 4. What a Straight Segment Says

A segment between two points is a visual connection. It can also be interpreted as a linear interpolant if that interpretation is explicitly adopted. Those meanings must not be confused.

For observations $(x_0,y_0)$ and $(x_1,y_1)$, the linear interpolation formula is:

$$\widehat y(x)=y_0+\frac{x-x_0}{x_1-x_0}(y_1-y_0),\qquad x_0\leq x\leq x_1.$$

For Account A below, the day-1 value is USD 1,020 and the day-3 value USD 1,010. Linear interpolation would assign USD 1,015 at day 2. That is a calculation under an interpolation assumption, not an observed account value. The lab does not add that point to its source or output arrays.

Markers identify supplied observations. They help distinguish a sparse observed path from a densely calculated curve. A visually smooth line does not establish smooth economic behavior; spline smoothing or other fitting would introduce additional assumptions and can create unsupported extrema.

A line's apparent slope also depends on the axis scales and the figure's aspect ratio. A steeper-looking export does not imply that the underlying dollar changes became larger.

The position ledger is an independent illustration, not a decomposition or explanation of either account's valuation.

Keep USD values and share counts on separate panels with explicitly labeled vertical axes. There is no meaningful common vertical scale for those two units. The shared horizontal axis is meaningful because both use the same elapsed-day convention.

The two account series already use a common currency and equal starting values in this fixture. Other comparisons may require indexing, currency conversion, or additional context. Those are analytical transformations, not a consequence of choosing a line style.

## 6. Two Different Kinds of Gap

**Missing value at a supplied point:** Account A lacks a value at day 4. Retain its NaN. Matplotlib breaks the line at a NaN and omits its marker [2]. Dropping day 4 from that series would permit a segment between days 3 and 7 and conceal the missing supplied point.

**Long interval with no supplied intermediate point:** Account B has valid values at days 4 and 7. Ordinary plotting would connect them. The lab applies a separate display policy: do not connect neighboring supplied rows more than two calendar days apart. It inserts a NaN separator before the day-7 row for both columns.

This threshold is a teaching policy, not an exchange-calendar rule or a universal definition of stale data. A weekend might be an expected closure, while a one-hour gap might be serious for another feed. The application must define an appropriate calendar and freshness contract. The present threshold controls visible connections only; it does not remove source points or label either endpoint invalid.

| Case | Source array | Plotting consequence |
|---|---|---|
| Day 3→4, Account A | Day-4 value is NaN | No connection or marker at the missing value |
| Day 3→4, Account B | Both values supplied, one day apart | Connect the two observations |
| Day 4→7, both columns | Three-day interval | Insert a NaN separator under the two-day policy |
| Day 7→8, both columns | Both values supplied, one day apart | Connect the two observations |

The three-day interval is broken even for Account B, which has no missing value at a supplied grid point. Missingness and a long elapsed interval are distinct conditions.

## 7. Presentation Separators Preserve the Source

The source day vector is `[0, 1, 3, 4, 7, 8]`. With the two-day policy, the rendered vector becomes `[0, 1, 3, 4, 7, 7, 8]`. The first rendered day-7 row contains NaN in both value columns; the next holds the actual day-7 values.

This duplicate rendered coordinate is intentional. It puts a line break immediately before the next real observation. It is not a duplicate financial observation and must not be passed back into source validation as though it were one. A separate rendering array makes that distinction explicit.

No source rows are dropped or filled. Account A's original missing value remains missing. The helper returns independent copies of the original day grid, value matrix, and share vector alongside the expanded plotting arrays.

A threshold of two days permits the exact two-day day-1→3 connection; it breaks only intervals strictly greater than two. The tests include that boundary. Setting the threshold to three restores the day-4→7 connection but still preserves Account A's original NaN.

## 8. Step Charts for Explicitly Persistent States

Suppose an authoritative ledger states that each recorded share quantity becomes effective at its update time and remains in force until the next update. A post-step chart expresses that contract:

```python
ax.step(days, shares, where="post", marker="^", label="Recorded position")
```

With `where="post"`, the value at $x_i$ extends to the right over $[x_i,x_{i+1})$ [3]. The fixture therefore represents:

| Interval, elapsed days | Shares held |
|---|---:|
| [0, 1) | 10 |
| [1, 3) | 12 |
| [3, 4) | 8 |
| [4, 7) | 8 |
| [7, 8) | 9 |

At day 8 the recorded state is also 9; the drawing ends there and does not assert a reporting horizon beyond the last supplied point. Repeated values at days 3 and 4 create no economic change.

A straight segment from 10 shares at day 0 to 12 at day 1 would visually suggest gradual accumulation. The ledger instead specifies a change at day 1. A post-step therefore fits this stated information. `where="pre"` extends a value to the left, while `where="mid"` places transitions halfway between supplied x coordinates [3]. Choose among them from the effective-time contract.

The ledger line remains connected across day 4→7 because persistence is explicitly part of its meaning. This is not a license to forward-fill an observed market quote or unknown account valuation. The two panels apply different rules because their data contracts differ.

## 9. Readability and Analytical Boundaries

Use markers and distinct line styles as well as color. Keep labels tied to the actual data columns. A legend helps identify the series but cannot correct a mismatched input array. Too many overlaid paths can obscure observations; separate panels or a narrower comparison can be more useful.

A focused vertical range helps inspect the USD 990–1,060 observations here. Its tick labels remain visible. This is a line chart, not a bar-length comparison; zero need not occupy most of the panel. State and review axis choices rather than interpreting visual steepness as a new financial result.

Use a logarithmic price axis only under a justified positive-value contract and with explicit labeling. Equal proportional movements then occupy equal vertical distances. That transformation is distinct from calculating log returns. The lab uses linear axes and performs no return calculation, resampling, smoothing, annualization, or inference.

Dense-data reduction also changes what is visible. Taking every tenth observation may discard a large move. Any sampling or aggregation policy needs its own justification and validation. The lab limits its input size and plots all observed points instead.

### `line_charts.py`

```python
"""Observed value paths and an explicitly persistent position-state schedule."""
from pathlib import Path
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt
import numpy as np


def fixture():
    return (np.array([0, 1, 3, 4, 7, 8]),
            np.array([[1000., 1000.], [1020., 990.], [1010., 1005.],
                      [np.nan, 1015.], [1050., 1030.], [1060., 1025.]]),
            np.array([10., 12., 8., 8., 9., 9.]))


def prepare(days, values, shares, max_gap=2):
    """Validate and copy data; insert NaN separators across long intervals."""
    if (not isinstance(days, np.ndarray) or days.ndim != 1
            or days.dtype.kind not in 'iu' or not 2 <= len(days) <= 1000):
        raise ValueError('days must be a 1-D integer array with 2..1000 points')
    if days[0] != 0 or days[-1] > 365 or np.any(days[1:] <= days[:-1]):
        raise ValueError('days must increase strictly from zero within 365 days')
    if (isinstance(max_gap, (bool, np.bool_))
            or not isinstance(max_gap, (int, np.integer)) or not 1 <= max_gap <= 365):
        raise ValueError('max_gap must be an integer in 1..365')
    if (not isinstance(values, np.ndarray) or values.shape != (len(days), 2)
            or values.dtype.kind not in 'iuf'):
        raise ValueError('values must be a numeric array with two columns')
    if (not isinstance(shares, np.ndarray) or shares.shape != days.shape
            or shares.dtype.kind not in 'iuf'):
        raise ValueError('shares must be a numeric vector on the same grid')
    v = values.astype(float, copy=True)
    q = shares.astype(float, copy=True)
    if (np.isinf(v).any() or np.any(v[np.isfinite(v)] <= 0)
            or np.any(v[np.isfinite(v)] > 1e12)
            or not np.isfinite(v[[0, -1]]).all()):
        raise ValueError('observed values must be in (0, 1e12]; endpoints required')
    if not np.isfinite(q).all() or np.any(q < 0) or np.any(q > 1e9):
        raise ValueError('shares must be finite and in [0, 1e9]')
    xplot, yplot = [], []
    for i, day in enumerate(days):
        if i and int(day) - int(days[i - 1]) > max_gap:
            xplot.append(float(day))
            yplot.append([np.nan, np.nan])
        xplot.append(float(day))
        yplot.append(v[i].copy())
    return days.copy(), v, q, np.array(xplot), np.array(yplot)


def build_figure(days, values, shares, max_gap=2):
    x, v, q, xp, vp = prepare(days, values, shares, max_gap)
    fig, axes = plt.subplots(2, 1, figsize=(9, 7), sharex=True,
                             layout='constrained')
    for j, (label, color, marker, style) in enumerate([
            ('Account A', '#0072B2', 'o', '-'),
            ('Account B', '#D55E00', 's', '--')]):
        axes[0].plot(xp, vp[:, j], label=label, color=color,
                     marker=marker, linestyle=style, linewidth=1.8)
    axes[0].set(title=f'Observed account values | break intervals > {max_gap} days',
                ylabel='Account value (USD)')
    axes[0].legend(loc='upper left')
    axes[1].step(x, q, where='post', color='#009E73', marker='^',
                 label='Position state effective at each update')
    axes[1].set(title='Separate position ledger | state persists until next update',
                ylabel='Shares held', xlabel='Elapsed calendar days')
    axes[1].legend(loc='center right')
    axes[1].set_xticks(x[np.unique(np.linspace(0, len(x)-1, min(8, len(x)), dtype=int))])
    for ax in axes:
        ax.grid(alpha=0.2)
    fig.suptitle('Line segments and step states encode different assumptions')
    fig.supxlabel('Synthetic data | no imputation or smoothing | ledger is not an account valuation',
                  fontsize=9)
    return fig, axes


def main():
    days, values, shares = fixture()
    _, _, _, xp, vp = prepare(days, values, shares)
    print(f'Source observations: {len(days)}; plotted rows: {len(xp)}')
    print(f'Observed account values: {np.isfinite(values).sum()}/12')
    print(f'Inserted gap-separator rows: {np.isnan(vp).all(axis=1).sum()}')
    fig, _ = build_figure(days, values, shares)
    try:
        Path('output').mkdir(exist_ok=True)
        fig.savefig('output/line_charts.png', dpi=150)
    finally:
        plt.close(fig)
    print('Saved output/line_charts.png')


if __name__ == '__main__':
    main()
```

The numerical helper validates before creating a Figure. The rendering helper returns the open Figure and its Axes. The demonstration caller saves and closes that specific Figure in a `finally` block. Re-running it replaces the output PNG. The returned source copies and presentation arrays make their different roles inspectable.

### `test_line_charts.py`

```python
import tempfile
import unittest
from pathlib import Path
import numpy as np
from numpy.testing import assert_allclose, assert_array_equal
from line_charts import fixture, prepare, build_figure, plt


class LineChartTests(unittest.TestCase):
    def test_gap_expansion_and_original_missingness(self):
        d, v, q = fixture()
        _, _, _, xp, vp = prepare(d, v, q)
        assert_array_equal(xp, [0, 1, 3, 4, 7, 7, 8])
        self.assertTrue(np.isnan(vp[3, 0]))
        self.assertTrue(np.isnan(vp[4]).all())
        assert_allclose(vp[5:], [[1050, 1030], [1060, 1025]])

    def test_threshold_boundary_and_no_filtering(self):
        d, v, q = fixture()
        _, _, _, xp, vp = prepare(d, v, q, max_gap=3)
        assert_array_equal(xp, d)
        assert_allclose(vp, v, equal_nan=True)
        _, _, _, xp, _ = prepare(d, v, q, max_gap=1)
        self.assertEqual(len(xp), 8)

    def test_invalid_days(self):
        d, v, q = fixture()
        for bad in [d.astype(float), d + 1, np.array([0, 1, 1, 4, 7, 8]),
                    np.array([0, 3, 1, 4, 7, 8]), np.array([0, 1, 3, 4, 7, 366])]:
            with self.subTest(days=bad), self.assertRaises(ValueError):
                prepare(bad, v, q)

    def test_invalid_values_and_states(self):
        d, v, q = fixture()
        for bad_value in [0, -1, np.inf, 1e13]:
            bad = v.copy(); bad[1, 0] = bad_value
            with self.assertRaises(ValueError): prepare(d, bad, q)
        bad = v.copy(); bad[0, 0] = np.nan
        with self.assertRaises(ValueError): prepare(d, bad, q)
        for bad_value in [-1, np.nan, np.inf, 1e10]:
            bad = q.copy(); bad[2] = bad_value
            with self.assertRaises(ValueError): prepare(d, v, bad)
        with self.assertRaises(ValueError): prepare(d, v[:, :1], q)
        with self.assertRaises(ValueError): prepare(d, v.astype(str), q)
        with self.assertRaises(ValueError): prepare(d, v, q[:-1])

    def test_invalid_gap_policy(self):
        d, v, q = fixture()
        for gap in [True, 0, 366, 2.0, '2']:
            with self.assertRaises(ValueError): prepare(d, v, q, gap)

    def test_source_preserved_and_copies_independent(self):
        d, v, q = fixture(); original = v.copy()
        x, copied, state, xp, vp = prepare(d, v, q)
        x[0] = 99; copied[0, 0] = 1; state[0] = 1; vp[0, 1] = 1
        assert_allclose(v, original, equal_nan=True)
        self.assertEqual(d[0], 0); self.assertEqual(q[0], 10)

    def test_line_and_step_artists(self):
        d, v, q = fixture(); fig, axes = build_figure(d, v, q)
        try:
            self.assertEqual(len(axes[0].lines), 2)
            assert_array_equal(axes[0].lines[0].get_xdata(), [0, 1, 3, 4, 7, 7, 8])
            self.assertTrue(np.isnan(axes[0].lines[1].get_ydata()[4]))
            line = axes[1].lines[0]
            self.assertEqual(line.get_drawstyle(), 'steps-post')
            assert_array_equal(line.get_xdata(), d)
            assert_allclose(line.get_ydata(), q)
            # First step holds 10 shares until the update at day 1.
            assert_allclose(line.get_path().vertices[:3], [[0, 10], [1, 10], [1, 12]])
        finally:
            plt.close(fig)

    def test_png_and_cleanup(self):
        d, v, q = fixture(); before = set(plt.get_fignums())
        fig, _ = build_figure(d, v, q)
        try:
            with tempfile.TemporaryDirectory() as folder:
                path = Path(folder) / 'line.png'; fig.savefig(path)
                self.assertEqual(path.read_bytes()[:8], b'\x89PNG\r\n\x1a\n')
        finally:
            plt.close(fig)
        self.assertEqual(set(plt.get_fignums()), before)


if __name__ == '__main__':
    unittest.main()
```

The eight tests cover the exact rendering expansion, threshold boundaries, source missingness, invalid days/values/states/policy, input preservation, plotted line data, post-step geometry, PNG format, and figure cleanup. The path-vertex check independently verifies the first state transition: the step stays at 10 shares through the interval and changes to 12 at day 1.

The test suite does not compare raster pixels. Automated checks establish the input-to-Artist mapping and file creation; they cannot establish that a legend avoids an important point or that text remains readable at the intended display size. Inspect the exported picture separately.

## 14. Common Mistakes

| Mistake | Consequence | Correction |
|---|---|---|
| Omitting x for irregular observations | Equal visual spacing hides elapsed intervals | Supply the actual offsets |
| Sorting x independently of y | Values become attached to the wrong observations | Validate paired records and apply any authorized reorder jointly |
| Dropping NaNs to make the line continuous | A missing observation becomes invisible | Retain a gap under a stated policy |
| Joining a long interval automatically | Suggests more continuity than the policy permits | Add presentation-only separators |
| Feeding separators back into ingestion | Duplicate rendered x positions appear to be duplicate source data | Keep source and rendering arrays separate |
| Using a step chart for an unknown quote | Implies persistence without evidence | Require a valid effective-state contract |
| Calling account-value change investment return | Ignores external cash flows and other effects | Obtain the required performance inputs |
| Smoothing without disclosure | Adds model-dependent intermediate behavior | Show observations and document any fitted transformation |

## 15. Exercises and Answer Guidance

1. **Interpolation:** What day-2 value would linear interpolation assign Account A? Is it observed?  
   **Guidance:** USD 1,015; it is inferred under a linear assumption, not supplied.
2. **Threshold:** Why is the day-1→3 segment retained with `max_gap=2`?  
   **Guidance:** Its duration equals two; the policy breaks strictly larger intervals.
3. **Change the policy:** Set `max_gap=3`. Which connection changes?  
   **Guidance:** Account B's day-4→7 segment reappears. Account A's original day-4 NaN still prevents its adjacent connection.
4. **Source accounting:** Why do seven plotted rows not imply seven source observations?  
   **Guidance:** One row is a NaN rendering separator. Six supplied observations remain unchanged.
5. **Step convention:** What is the ledger state at elapsed day 2?  
   **Guidance:** 12 shares under the explicit post-update persistence contract.
6. **Repeated state:** Does the day-4 share record change the position?  
   **Guidance:** No; it remains at 8. An additional recorded state need not represent a trade.
7. **Unknown quote:** May the ledger's persistence rule be transferred to Account A's missing value?  
   **Guidance:** No. Persistent authoritative states and unknown observed valuations have different meanings.
8. **Financial inference:** Can Account A's higher endpoint establish better investment performance?  
   **Guidance:** No. The fixture omits cash flows and other performance inputs; the line chart only displays the supplied account-value paths.
