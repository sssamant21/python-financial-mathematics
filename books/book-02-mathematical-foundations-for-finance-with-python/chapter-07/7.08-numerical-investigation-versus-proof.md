## Learning objectives

Distinguish numerical observations from universal mathematical claims; identify misleading limit tables; use counterexamples to refute claims; recognize the limits of floating-point arithmetic; and design reproducible financial calculations with independent verification.

## 1. What counts as evidence?

A **numerical investigation** evaluates a mathematical expression at selected inputs. It is valuable for discovering patterns, testing conjectures, checking algebra, and detecting mistakes. However, a finite set of samples cannot establish a claim about *every* point in an interval or about *all sufficiently small* perturbations.

A **mathematical proof** derives a conclusion from stated assumptions using valid reasoning. A single valid counterexample disproves a universal assertion, but thousands of successful examples do not by themselves prove it.

The distinction is especially important for financial models, where a plausible numerical answer can conceal an incorrect rate convention, discontinuous fee, or unstable algorithm.

## 2. A misleading limit table

Consider

\[
f(x)=\frac{x^2-1}{x-1},\quad x\ne1.
\]

Numerical values near 1 approach 2. This suggests the limit, but the proof is algebraic:

\[
\frac{(x-1)(x+1)}{x-1}=x+1,\quad x\ne1.
\]

Therefore \(\lim_{x\to1}f(x)=2\). Notice that the original function is still undefined at 1; the existence of a limit does not establish continuity at that point.

## 3. When samples conceal oscillation

For \(x\ne0\), let \(g(x)=\sin(1/x)\). Some sequences approaching zero give values near zero, while others give values near \(1\) or \(-1\).

For example, choose

\[
x_n=\frac{1}{2\pi n},\qquad
y_n=\frac{1}{\pi/2+2\pi n}.
\]

Both sequences approach zero through positive values, but \(g(x_n)=0\) and \(g(y_n)=1\). If a finite limit existed, every sequence approaching zero through the domain would have the same function limit. Hence the right-hand limit does not exist. An ordinary decimal sampling grid might miss this distinction.

## 4. Sign changes and discontinuities

A sampled function can appear to cross zero even when it jumps over zero. The step function

\[
s(x)=\begin{cases}-1,&x<0,\\1,&x\ge0\end{cases}
\]

has opposite endpoint signs on \([-1,1]\) but no root. The Intermediate Value Theorem requires continuity. A numerical root finder cannot infer that hypothesis merely from sampled signs.

Similarly, \(h(x)=x^2\) has a root at zero without a sign change. Thus a sign-change search can miss roots, and a sign change alone does not prove a root for a discontinuous function.

## 5. Floating-point arithmetic is not exact real arithmetic

IEEE 754 binary floating-point numbers represent only a finite subset of real numbers. Common consequences include:

- **Rounding:** decimal values such as 0.1 are generally not represented exactly.
- **Cancellation:** subtracting nearly equal numbers can erase meaningful digits.
- **Overflow and underflow:** mathematically finite expressions can exceed the machine's range or round to zero.
- **Scale sensitivity:** an absolute tolerance appropriate for values near 1 may be inappropriate for values near \(10^{12}\).
- **Nonassociativity:** \((a+b)+c\) can differ from \(a+(b+c)\) after rounding.

For example, direct evaluation of \((e^h-1)/h\) can become inaccurate for tiny \(h\). The stable expression \(\operatorname{expm1}(h)/h\) avoids much of the cancellation. At \(h=0\), the quotient is undefined, but its continuous extension equals 1.

## 6. Financial example: verifying a present-value identity

Suppose \(C>0\), \(r>-1\), and \(n\) is a nonnegative integer. The present value of a payment in period \(n\) is

\[
PV=\frac{C}{(1+r)^n}.
\]

An independent calculation uses the logarithmic form

\[
PV=C\exp\left(-n\log(1+r)\right).
\]

These expressions are mathematically equal under the assumptions. Agreement between two floating-point implementations is useful evidence, but does not prove either implementation is correct for all possible inputs.

A stronger verification strategy combines a mathematical derivation, boundary tests such as \(r=0\) and \(n=0\), comparisons over a representative domain, and explicit handling of overflow and underflow.

## 7. Financial example: yield root verification

For a positive-cash-flow bond with price \(P>0\), define

\[
F(y)=\sum_{k=1}^{n}\frac{C_k}{(1+y)^k}-P,\qquad y>-1.
\]

Continuity and strict decrease guarantee a unique root if a sign-changing bracket exists. A bisection routine then supplies a numerical approximation. A small residual \(|F(\hat y)|\) alone does not automatically imply a small yield error if the function is very flat; the final bracket gives an independent positional guarantee.

A production-quality result should record the original assumptions, the bracket, the tolerance, the residual, the iteration count, and any convergence warnings.

## 8. A disciplined verification ladder

1. **State the claim and domain.** Identify whether the result is exact, approximate, or conditional.
2. **Prove what can be proved.** Use algebra, inequalities, monotonicity, or established theorems.
3. **Seek counterexamples.** Test boundaries, discontinuities, zero values, negative values, and extreme scales.
4. **Use independent calculations.** Compare against an algebraically distinct implementation where feasible.
5. **Check numerical stability.** Prefer \`log1p\`, \`expm1\`, normalized formulas, and bracketed algorithms.
6. **Report uncertainty.** Document tolerances and known limits instead of labeling an untested calculation as validated.
