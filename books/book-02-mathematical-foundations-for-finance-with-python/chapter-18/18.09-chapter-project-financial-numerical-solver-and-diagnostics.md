## 2. Requirements and acceptance contract

The solver takes a continuous scalar function \(f\), its derivative \(f'\), a bracket \([a,b]\), absolute and relative rate tolerances, and a positive iteration budget.

**Preconditions:** finite inputs, \(a<b\), \(a_x>0\), \(r_x\ge0\), positive integer iteration limit, and either an exact endpoint root or opposite-sign endpoint values. The caller is responsible for continuity on the bracket.

**Postconditions:** report a candidate, final interval, residual, width, iteration count, function and derivative evaluation counts, Newton and bisection step counts, and one of the statuses \`endpoint_root\`, \`exact_root\`, \`converged\`, \`stagnation\`, or \`max_iter\`.

Do not call an exhausted or stagnated run converged. A numerical report is not evidence of validated cash flows or market data.

## 3. Numerical foundation

For a root equation \(f(x)=0\), the Newton proposal is

\[
n=x-\frac{f(x)}{f'(x)}.
\]

When the derivative is zero, nonfinite, or otherwise unusable, use bisection. Even with a valid derivative, accept a Newton proposal only if it lies inside the **middle half** of the current bracket:

\[
a+\frac{b-a}{4}<n<b-\frac{b-a}{4}.
\]

Otherwise use

\[
m=a+\frac{b-a}{2}.
\]

This conservative rule prevents tiny Newton steps near the endpoints from undermining bracket progress. The selected point replaces whichever endpoint has the same function sign, retaining a root-containing bracket under the continuity assumption.

## 4. Stopping rules

For bracket width \(w=b-a\), declare width convergence when

\[
w\le a_x+r_x\max(|a|,|b|).
\]

The midpoint is then within \(w/2\) of at least one bracketed root. A small function residual alone does not certify root accuracy. Exact-zero evaluation may terminate immediately.

If the computed midpoint equals an endpoint, return \`stagnation\`. If the iteration budget is exhausted, return \`max_iter\`. The diagnostic report should preserve the latest valid bracket in both cases.

## 5. Financial model A: zero-coupon yield

For face value \(F=1000\), price \(P=900\), and maturity \(T=2\) years, under annual effective compounding:

\[
f(r)=F(1+r)^{-T}-P,\qquad r>-1,
\]

\[
f'(r)=-TF(1+r)^{-T-1}.
\]

The analytical reference is

\[
r^*=(F/P)^{1/T}-1=\sqrt{10/9}-1
\approx0.054092553389.
\]

The initial bracket \([0,0.2]\) has opposite-sign endpoint residuals. The objective is strictly decreasing for \(r>-1\), so this financial root is unique.

For stable near-zero rate evaluation, use \(\exp(-T\operatorname{log1p}(r))\).

## 6. Financial model B: one-period NPV

For cash flows \((-1000,1100)\), solve

\[
NPV(r)=-1000+\frac{1100}{1+r}=0,\qquad r>-1.
\]

Its derivative is \(-1100/(1+r)^2\), and the analytical root is \(r^*=0.10\). The same initial bracket \([0,0.2]\) works.

**Units:** both residuals are currency amounts, while the unknown is a decimal effective rate per specified period. Report these units separately.

## 7. Multiple-IRR limitation

For \((-100,230,-132)\), the NPV equation has two roots, \(r=0.10\) and \(r=0.20\). One root-solver call can certify only the root in its chosen sign-change bracket. A complete multiple-IRR study requires interval isolation and mathematical root-count analysis; finite scanning alone cannot guarantee completeness.

## 8. Diagnostic data model

Each result includes:

| Field | Meaning |
|---|---|
| \`root\` | Final candidate |
| \`bracket\` | Last root-containing interval |
| \`width\` | Interval width in rate units |
| \`residual\` | Signed objective value in currency |
| \`status\` | Explicit termination reason |
| \`iterations\` | Completed update count |
| \`function_evaluations\` | Objective evaluation count |
| \`derivative_evaluations\` | Derivative evaluation count |
| \`newton_steps\` | Accepted Newton proposals |
| \`bisection_steps\` | Fallback midpoint updates |
| \`trace\` | Iteration records and accepted step types |
| \`tolerances\` | Requested numerical thresholds |

A status of \`converged\` indicates satisfaction of the declared width criterion, not enterprise certification.

## 9. Error budget and reliability boundaries

Distinguish four categories:

- **Numerical error:** finite precision, stopping tolerance, derivative evaluation, and iteration limits.
- **Input error:** quoted price precision, inaccurate or missing cash flows.
- **Model error:** compounding convention, cash-flow timing, assumptions, and omitted risks.
- **Implementation risk:** programming defects and untested edge cases.

A tight numerical tolerance cannot compensate for errors in the other categories.

## 11. Twenty worked exercises

**1.** Define the root-solving problem.  
*Solution:* Find \(x\) such that \(f(x)=0\).

**2.** State the initial bracket condition.  
*Solution:* Opposite endpoint signs, assuming continuity, or an exact endpoint root.

**3.** Give Newton's update.  
*Solution:* \(x-f(x)/f'(x)\).

**4.** When is Newton's proposal rejected?  
*Solution:* If its derivative is unusable or its proposal violates the interior safeguard.

**5.** Give the fallback point.  
*Solution:* \(a+(b-a)/2\).

**6.** What invariant does the solver preserve?  
*Solution:* A root-containing sign-change bracket.

**7.** State the width tolerance.  
*Solution:* \(b-a\le a_x+r_x\max(|a|,|b|)\).

**8.** Bound the midpoint error.  
*Solution:* At most half the bracket width relative to some bracketed root.

**9.** What does \`stagnation\` mean?  
*Solution:* The interval cannot be reduced in the current floating-point representation.

**10.** Does \`max_iter\` imply success?  
*Solution:* No.

**11.** What are the zero-coupon financial inputs?  
*Solution:* \(F=1000\), \(P=900\), and \(T=2\) years.

**12.** State the zero-coupon residual.  
*Solution:* \(1000(1+r)^{-2}-900\).

**13.** Differentiate it.  
*Solution:* \(-2000(1+r)^{-3}\).

**14.** Give its exact yield.  
*Solution:* \(\sqrt{10/9}-1\).

**15.** Why is this yield unique?  
*Solution:* Its objective is strictly decreasing for \(r>-1\).

**16.** State the one-period NPV equation.  
*Solution:* \(-1000+1100/(1+r)=0\).

**17.** Give its exact IRR.  
*Solution:* \(0.10\).

**18.** Can one solver call identify every IRR of a nonconventional stream?  
*Solution:* Not generally.

**19.** Why keep function-evaluation counts?  
*Solution:* To audit computational cost and investigate unusual solver behavior.
