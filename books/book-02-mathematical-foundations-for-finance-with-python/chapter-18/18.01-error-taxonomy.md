## Learning objectives

Distinguish errors in model specification, data, measurement, approximation, discretization, floating-point representation, algorithms, implementation, and interpretation. Separate absolute error from relative error, forward error from backward error, and uncertainty from numerical inaccuracy. Build a reproducible error budget for a financial calculation.

## 1. Why error classification comes first

A mathematically correct algorithm can produce an economically misleading answer when inputs or assumptions are wrong. Conversely, a sound financial model may produce inaccurate numbers because its numerical implementation is unstable. Diagnosing the category of error determines the appropriate remedy.

A useful pipeline is:

\[
\text{economic assumptions}\to\text{data}\to\text{mathematical model}
\to\text{discretization}\to\text{algorithm}\to\text{implementation}\to\text{reported result}.
\]

Each transition can introduce distinct errors. Numerical precision cannot cure an invalid model, and more observations do not automatically fix an unstable algorithm.

## 2. Modeling and specification errors

A **modeling error** occurs when the mathematical structure does not represent the economic process adequately. Examples include assuming a constant interest rate when rates vary, ignoring fees or defaults, or applying continuous compounding when a contract specifies discrete compounding.

A **specification error** occurs when a stated formula or constraint does not match the intended rule. For example, using a monthly rate as if it were annual changes the model's meaning even if every arithmetic operation is exact.

These errors require domain review, explicit assumptions, and comparisons against contractual or business requirements—not merely tighter floating-point tolerances.

## 3. Data and measurement errors

Inputs may contain missing values, stale prices, inconsistent currencies, rounded measurements, incorrect timestamps, or incompatible rate conventions. Data uncertainty may be stochastic and irreducible with the available information.

For a financial value \(F(x)\), small input perturbations \(\delta x\) can produce approximately

\[
\delta F\approx F'(x)\,\delta x.
\]

This is **input sensitivity**, not necessarily a flaw in the computation. Record the provenance, units, precision, and as-of time of every input.

## 4. Approximation and truncation errors

Approximation replaces an exact mathematical expression with a simpler one. For example, \(e^x\approx1+x\) for small \(x\) omits higher-order terms:

\[
e^x=1+x+\frac{x^2}{2}+O(x^3).
\]

The leading approximation error is approximately \(x^2/2\). At \(x=0.1\), the first-order approximation is \(1.1\), while \(e^{0.1}\approx1.105170185\); the absolute error is approximately \(0.005170185\).

**Truncation error** often refers to omitted terms in a series or the finite-step error of a numerical method. It is conceptually different from rounding error.

## 5. Discretization errors

Discretization replaces a continuous model with finite time steps or a grid. For continuously compounded growth,

\[
A(t)=Pe^{rt},
\]

the approximation \(P(1+r\Delta t)^{t/\Delta t}\), for compatible integer step counts, converges to the continuous expression as \(\Delta t\to0\) under appropriate assumptions. A larger step may be computationally cheaper but less accurate.

Discretization error should be studied with step refinement, convergence rates, and independent benchmarks.

## 6. Floating-point representation and rounding

Binary floating-point cannot represent many decimal fractions exactly. In Python, \`0.1+0.2\` is not exactly the binary floating-point representation of \`0.3\`. This is expected finite-precision behavior, not evidence that Python's arithmetic is arbitrarily broken.

A floating-point computation may also experience overflow, underflow, or loss of significant digits. Currency calculations that require exact decimal rounding rules often benefit from the \`decimal\` module, with a declared rounding policy.

## 7. Cancellation and instability

Subtracting nearly equal quantities can amplify relative error. For small \(x\), evaluating \(e^x-1\) by separately computing \`exp(x)\` and subtracting one may lose precision; \`math.expm1(x)\` is designed for this situation.

A **numerically unstable algorithm** can amplify representation or intermediate rounding errors beyond what the mathematical problem's conditioning requires. A **well-conditioned problem** is relatively insensitive to small input changes; an **ill-conditioned problem** is inherently sensitive. Stability and conditioning are different properties.

## 8. Iteration and solver errors

Root finders and optimizers often stop when a residual, step size, iteration count, or tolerance threshold is reached. A small residual does not always imply a small solution error, especially near a flat derivative or in an ill-conditioned system.

Distinguish **termination error** from **model error**. A solver's success flag is not an independent certificate of correctness. Check residuals, brackets, feasibility, derivatives, and known analytical benchmarks as appropriate.

## 9. Implementation and interpretation errors

An implementation can contain a wrong sign, off-by-one period count, incorrect compounding frequency, or unit conversion bug. Even a correctly computed number can be misreported—for example, presenting variance as volatility or a decimal return as a percentage without multiplying by 100.

Independent tests should compare outputs to mathematical invariants and separate reference calculations rather than reproducing the same code path.

## 10. Error measures

For an approximation \(\widehat y\) of a nonzero reference \(y\),

\[
E_{\rm abs}=|\widehat y-y|,\qquad
E_{\rm rel}=\frac{|\widehat y-y|}{|y|}.
\]

Relative error is undefined when the reference is zero; use absolute error or a carefully defined scale-aware metric. A **forward error** measures the output discrepancy; a **backward error** asks how much the input would need to change to make the computed output exact. Small backward error does not guarantee small forward error for an ill-conditioned problem.

## 11. Financial worked example: present value

For one payment \(C=1000\) due in two years at an annual effective discount rate \(r=0.05\),

\[
PV=\frac{1000}{(1.05)^2}\approx907.029478458.
\]

A model that discounts for three years instead of two has a **period specification error**. An input rate entered as \(5\) instead of \(0.05\) is a **unit/data error**. Replacing the exact discount factor with a first-order approximation creates **approximation error**. Converting the result to cents introduces a declared **rounding step**. These errors require different corrective actions.

## 12. Error budget and reporting

For each important result, maintain a register with the error source, mechanism, possible direction, estimated magnitude or bound, verification method, and owner. Some error sources can be bounded analytically; others require sensitivity studies or external validation. Do not add worst-case errors or statistical uncertainties together without stating the dependence and aggregation assumptions.

A useful release report contains the input convention, reference benchmark, absolute and relative discrepancies, algorithm and tolerance settings, and unresolved model assumptions.

## 14. Twenty worked exercises

**1.** Define modeling error.  
*Solution:* A mismatch between a mathematical model and the economic process it intends to represent.

**2.** Define specification error.  
*Solution:* An incorrect or inconsistent formal rule, formula, constraint, or unit convention.

**3.** Give a data error example.  
*Solution:* Using a stale exchange rate.

**4.** Define truncation error.  
*Solution:* Error from omitting terms or using a finite numerical step.

**5.** Define rounding error.  
*Solution:* Error introduced when a value is represented or rounded with limited precision.

**6.** What is discretization?  
*Solution:* Replacing a continuous model with finite steps or a grid.

**7.** Define absolute error.  
*Solution:* \(|\widehat y-y|\).

**8.** Define relative error for \(y\ne0\).  
*Solution:* \(|\widehat y-y|/|y|\).

**9.** Is ordinary relative error defined for \(y=0\)?  
*Solution:* No.

**10.** Define forward error.  
*Solution:* Difference between a computed output and the exact output for the stated input.

**11.** Define backward error.  
*Solution:* The smallest relevant input perturbation making the computed output exact, under a specified norm.

**12.** Distinguish conditioning from stability.  
*Solution:* Conditioning concerns sensitivity of the problem; stability concerns error propagation by the algorithm.

**13.** Give a cancellation example.  
*Solution:* Evaluating \(e^x-1\) directly for very small \(x\).

**14.** Which Python function helps with that example?  
*Solution:* \`math.expm1(x)\`.

**15.** What is the first-order approximation to \(e^x\)?  
*Solution:* \(1+x\).

**16.** What is the leading omitted term?  
*Solution:* \(x^2/2\).

**17.** State the two-year PV formula for \(C=1000,r=0.05\).  
*Solution:* \(1000/(1.05)^2\).

**18.** Is using \(r=5\) instead of \(0.05\) primarily a rounding error?  
*Solution:* No; it is a unit/input error.

**19.** Why is a solver success flag insufficient?  
*Solution:* It does not independently validate the model, inputs, or numerical solution.
