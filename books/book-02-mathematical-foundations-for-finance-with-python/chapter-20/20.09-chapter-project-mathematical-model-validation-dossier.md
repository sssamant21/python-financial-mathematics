## Project objective

Build a reproducible, evidence-backed validation dossier for a deterministic discounted cash-flow model. Combine an explicit specification, independent known values, boundaries, mathematical properties, numerical tolerances, findings, and a release decision record. The dossier is an educational draft and does not certify a model for production.

## 1. Model specification

For signed cash flows \(C_i\) at nonnegative times \(t_i\), measured in years, and a constant continuously compounded annual rate \(r\),

\[
V=\sum_{i=1}^m C_i e^{-rt_i}.
\]

Assume finite real inputs and a finite sequence of paired amounts and times. The empty portfolio has value zero in this educational contract. Negative rates and signed cash flows are permitted; negative times and non-finite inputs are rejected. This model excludes default risk, stochastic rates, taxes, costs, currency conversion and intraday conventions. All amounts share a currency. A valid mathematical input may still exceed floating-point range.

## 2. Independent benchmarks

At zero rate, two payments of 100 and 200 have value 300 regardless of their nonnegative times. With \(r=\ln 2\), a payment of 100 at year one has value 50. A payment at time zero is unchanged. These benchmarks derive from the formula and provide anchors independent of a property test.

A defective implementation that returns zero can preserve scaling and permutation; the nonzero benchmark exposes it. Known values and properties serve different purposes.

## 3. Boundary and property plan

| Check | Input or transformation | Expected behavior |
|---|---|---|
| Empty | No cash flows | 0 |
| Time zero | Any finite cash flow at 0 | Cash flow unchanged |
| Negative time | \(t<0\) | Reject |
| Non-finite | NaN or infinity | Reject |
| Permutation | Reorder amount-time pairs | Same value within tolerance |
| Split | Split a cash flow at the same time | Same value within tolerance |
| Scale | Multiply all amounts by a constant | Value scales by that constant |
| Rate change | Increase rate for positive cash flow and positive time | Value decreases |

Floating-point results are compared using a documented tolerance. The lab uses math.isclose with relative tolerance \(10^{-12}\) and absolute tolerance \(10^{-9}\) currency units as illustrative thresholds, not universal financial materiality limits.

## 4. Evidence and findings

Record source commit and dirty state, input and assumptions, environment, command, execution time, exit code, expected and actual outcomes, tolerance and review scope. Store sensitive inputs securely. A hash can identify exact input bytes but does not prove authenticity or anonymize guessable data.

Each finding should include an ID, evidence, expected and actual behavior, impact, severity rationale, owner, status and verification. An authorized exception must identify scope and expiry; it is not a correction.

## 5. Gate and decision

A proposed release gate should require the specification, reproducible executed checks, independent mathematical and software review, resolution or authorized acceptance of findings, business review and a decision by an authorized owner. Production use may additionally require monitoring, operational controls and rollback. A script cannot establish that reviews or approvals are authentic.

The supplied dossier starts with execution and review pending. Never change those fields to passed merely because the source exists. If a test fails, retain the failure and do not label the dossier approved.

## 7. Worked examples

1. \(V[(100,1),(200,2)]\) at zero rate equals 300.
2. \(V[(100,1)]\) at \(r=\ln 2\) equals 50.
3. \(V[(75,0)]\) equals 75 for any finite rate.
4. At zero rate a signed pair 100 and -40 totals 60.
5. An empty sequence returns 0 by contract.
6. A negative horizon is rejected.
7. A NaN amount is rejected.
8. Reversing pairs preserves the mathematical total.
9. Splitting 100 into 40 and 60 at the same date preserves value.
10. Scaling amounts by -2 scales value by -2.
11. For a positive payment at positive time, a higher rate reduces value.
12. For a negative payment, the direction reverses.
13. A zero implementation passes scaling but fails example 2.
14. A test result must name the source version.
15. A seed must be accompanied by generator and version information.
16. A hash is not independent approval.
17. A dirty working tree must be recorded.
18. Missing execution evidence remains pending.
19. A finding accepted as risk remains a finding.
20. A passing checklist is not itself a release approval.

## 8. Twelve-step project lab

1. Record intended use, units and exclusions.
2. Specify the formula and admissible domain.
3. Implement the valuation function.
4. Derive independent known-value cases.
5. Check zero-rate and zero-horizon boundaries.
6. Check rejection of negative time and non-finite values.
7. Test permutation and same-date splitting.
8. Test scaling and conditional monotonicity.
9. Choose and justify tolerances.
10. Record exact code, environment, command and output during execution.
11. Document findings and independent review.
12. Present the gate evidence and authorized decision separately.
