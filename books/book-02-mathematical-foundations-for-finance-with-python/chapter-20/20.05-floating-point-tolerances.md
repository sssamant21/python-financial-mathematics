## Learning objectives

Explain rounding error, distinguish absolute and relative tolerance, select tolerances from an error budget and scale, compare values near zero, and recognize why a passing numerical test does not prove financial or model correctness.

## 1. Why exact equality can fail

Many decimal fractions have no finite binary floating-point representation. Arithmetic rounds intermediate results, and the order of operations can change the result. For example, 0.1 + 0.2 need not equal 0.3 exactly in binary floating point. This is a representation issue, not evidence that either value was entered incorrectly.

Exact comparisons remain suitable for exact contracts such as integer counts, Boolean results, and explicitly returned sentinel values. For computed floating-point quantities, specify a comparison appropriate to the purpose.

## 2. Absolute and relative error

Given actual \(a\) and independent reference \(b\),

\[
e_{\rm abs}=|a-b|,\qquad
e_{\rm rel}=\frac{|a-b|}{|b|}\quad(b\ne0).
\]

Absolute error has the units of the quantity; relative error is dimensionless. Relative error against a zero reference is undefined. A commonly used asymmetric rule is

\[
|a-b|\le \mathrm{atol}+\mathrm{rtol}|b|.
\]

Here \(b\) is the designated reference. Both tolerances must be finite and nonnegative, and should be justified in the units and scale of the model. For a zero reference, the rule reduces to absolute tolerance.

Python's math.isclose instead uses the symmetric rule

\[
|a-b|\le\max(\mathrm{rel\_tol}\max(|a|,|b|),\mathrm{abs\_tol}).
\]

The sum rule and max rule are different; document which is used. NaN is never close, even to itself. The lab rejects all non-finite inputs before comparison.

## 3. Choosing a tolerance

Begin with the question being tested. Separate rounding, input precision, algorithm approximation, model assumptions, and business materiality. Where possible, bound or estimate each numerical contribution and choose a threshold justified by that error budget. A tolerance is not a license to hide unexplained discrepancies.

For a value in dollars, an absolute threshold of 0.01 means one cent; whether it is acceptable depends on the application. At a value of one million, a relative threshold of \(10^{-6}\) permits an error of approximately one dollar. At a reference of zero, only the absolute term contributes in the sum rule.

Use stricter thresholds for deterministic analytic benchmarks than for approximate numerical integration or iterative solvers when their error analyses justify that distinction. Document the norm, scale, units, and expected approximation error.

## 4. Conditioning and cancellation

For \(f(x)\), small input errors can be amplified when the problem is ill-conditioned. Cancellation occurs when subtracting nearly equal numbers, discarding significant digits. For small \(x\), computing \(e^x-1\) by direct subtraction can lose precision; expm1 is designed for this case. Likewise, log1p evaluates \(\log(1+x)\) accurately near zero.

A stable implementation reduces avoidable algorithmic error; it cannot remove inherent sensitivity or repair invalid data. Compare against a separately derived reference or higher-precision calculation, not only another implementation of the same unstable formula.

## 5. Vectors, matrices, and constraints

Componentwise comparison can hide cumulative error in a long vector. A norm-based rule could be

\[
\|a-b\|_2\le \mathrm{atol}+\mathrm{rtol}\|b\|_2.
\]

State the norm and dimensionality, and choose scale-aware bounds. For a linear system \(Ax=b\), inspect the residual \(Ax-b\) and its scaling. A small residual does not guarantee a small solution error when \(A\) is ill-conditioned.

For a feasibility constraint \(g(x)\le0\), report the signed violation \(\max(0,g(x))\) and the tolerance in meaningful units. A mathematically small violation can still be operationally unacceptable; feasibility does not prove optimality.

## 6. Independent reference checks

Test near zero, across magnitude scales, at tolerance boundaries, and with invalid tolerances. Expected results should come from analytic identities, exact arithmetic, or a separately justified high-precision method. For a threshold test, choose exactly representable numbers when practical to avoid confusing test design with binary rounding.

Do not select tolerance after looking at a failing output merely to make it pass. Investigate discrepancies, retain evidence, and record any agreed adjustment with its rationale.

## 7. Twenty worked exercises

1. For \(a=101,b=100\), absolute error is 1.
2. For the same values, relative error against \(b\) is 0.01.
3. Relative error against zero is undefined.
4. For \(a=0.0001,b=0\), absolute error is 0.0001.
5. If atol is 0.001 and rtol is zero, exercise 4 passes.
6. If both tolerances are zero, the same comparison fails.
7. With \(a=101,b=100\), atol 0 and rtol 0.01, the sum-rule boundary passes.
8. With \(a=102,b=100\), atol 0 and rtol 0.01, it fails.
9. A negative tolerance is invalid.
10. NaN must not be treated as a successful numerical comparison.
11. One cent is an absolute monetary tolerance of 0.01 dollars.
12. An error of 1 on a reference of 1,000,000 has relative error \(10^{-6}\).
13. Relative tolerance alone cannot accept a nonzero result against zero under the asymmetric rule.
14. A residual of zero in exact arithmetic satisfies the linear equations.
15. A small residual alone does not guarantee a small solution error.
16. A tolerance must reflect both numerical accuracy and the use of the result.
17. A longer vector may require a scale-aware norm threshold.
18. An unstable formula may agree with itself while being inaccurate.
19. A feasibility tolerance should carry the units of its constraint.
20. A passing numerical comparison does not independently validate model assumptions.

## 8. Twelve-step hands-on lab

1. Identify the reference value and units.
2. Calculate absolute error.
3. Calculate relative error only when the reference is nonzero.
4. Implement the asymmetric sum rule.
5. Reject non-finite inputs and invalid tolerances.
6. Compare the result against zero using absolute tolerance.
7. Test an exactly representable threshold boundary.
8. Test a value outside the threshold.
9. Compare the sum rule with Python's symmetric max rule.
10. Compare direct and stable evaluation of exp(x)-1 for small x.
11. Design a vector norm and a scaled residual check.
12. Record runtime, results, tolerances, error budget, and reviewer status when validation is executed.
