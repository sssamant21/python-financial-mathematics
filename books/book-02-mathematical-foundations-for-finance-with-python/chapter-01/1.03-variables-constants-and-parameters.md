## 1.3.1 Learning Objectives

By the end of this section, you should be able to:

- Identify independent variables, dependent quantities, fixed parameters, and unknowns in a financial question.
- Explain why the same symbol can play different roles in different questions.
- Distinguish mathematical constants, fixed scenario assumptions, and Python names.
- Construct a scenario comparison that holds specified inputs fixed.
- Recognize hidden assumptions when several inputs change together.
- Write a small model whose inputs and scenario records make these roles explicit.

The central question is not simply “Which symbols appear in the formula?” It is “What are we allowing to change, what are we holding fixed, and what are we trying to determine?”

## 1.3.2 Roles Depend on the Question

Recall the deterministic growth model:

$$V=P(1+r)^n.$$

Here P is principal, r is an effective rate per period, n is a whole-period count, and V is ending value. All four quantities appear in the relationship, but their roles depend on the experiment or equation we choose.

| Question | Quantity being varied or solved for | Held fixed | Output or condition |
|---|---|---|---|
| How does value change with rate? | r varies | P and n | V is calculated |
| How does value change with principal? | P varies | r and n | V is calculated |
| How does value change over time? | n varies | P and r | V is calculated |
| What principal reaches a target? | P is unknown | Target V, r, and n | Satisfy the value equation |
| What one-year rate reaches a target? | r is unknown | P, target V, n=1 | Satisfy the value equation |

Calling r a parameter in one study does not forbid changing it in a later study. The label describes its role in the current formulation, not an inherent property of the symbol.

Before coding, write a short sentence such as: “Vary the effective annual rate while holding principal at 1000 and the horizon at two years.” That sentence is part of the model specification.

## 1.3.3 Independent and Dependent Variables

An independent variable is an input allowed to range over its admissible domain in a function-based study. The dependent variable is determined by the function once its inputs and fixed parameters are specified. Reference 1 develops this language for functions.

For a rate study, define:

$$f(r)=1000(1+r)^2,\qquad r>-1.$$

The input r is the independent variable and f(r) is the dependent value. At r=0.05, the output is 1102.5.

“Independent” here describes a mathematical input role. It does not mean statistically independent from another random quantity. This book's present example is deterministic; no joint probability distribution has been specified.

Nor does an independent variable have to represent time. Rate, principal, fee amount, or a portfolio weight can be the input being studied. Time itself can be a fixed parameter in a rate-comparison experiment.

## 1.3.4 Parameters Define a Family of Functions

Write the same growth rule as:

$$f(r;P,n)=P(1+r)^n.$$

The semicolon is an explanatory notation separating the variable of interest from parameters held fixed for this study. It is not a new arithmetic operation or Python syntax requirement.

Each fixed pair (P,n) selects a member of the function family. For example:

$$f(r;1000,2)=1000(1+r)^2,$$

$$f(r;2000,2)=2000(1+r)^2.$$

At every admissible rate, the second value is twice the first because principal enters multiplicatively. This statement follows from the formula, not from testing only one rate.

If we instead fix P and r and vary n, we obtain a sequence:

$$g(n;P,r)=P(1+r)^n,\qquad n\in\mathbb{N}_0.$$

The same rule supports a different input domain and a different question. Our whole-period implementation rejects n=1.5; a fractional-year model would require an explicit additional convention.

## 1.3.5 Three Meanings of Constant

A mathematical constant, a fixed model input, and a programming naming convention should not be conflated.

**Mathematical constant.** Numbers such as 2, pi, and e denote fixed mathematical values. Their numerical representation may still be approximate, as Section 1.2 explained.

**Fixed input for an experiment.** Principal P=1000 can remain constant while a scenario table varies r. Principal can change in a separate experiment. Likewise, a fixed-rate assumption describes the model's chosen path; it does not claim that market rates never change.

**Named programming convention.** PEP 8 conventionally uses uppercase names for module-level constants. A name such as BASIS_POINTS_PER_UNIT=10000 communicates intent; ordinary Python assignment does not prevent someone from rebinding it. Reference 3 describes the convention.

The conversion factor 10000 basis points per unit decimal rate is exact by definition. A selected base rate of 0.05 is an input assumption, even if a programmer names it BASE_RATE. Uppercase spelling cannot make that assumption universal or establish that it matches a contract.

## 1.3.6 Unknowns Are Not Just Changing Inputs

An unknown is a quantity to determine by satisfying a relationship. A scenario variable is deliberately supplied with alternative values to observe outputs. These are different uses of an equation.

For one year's growth, let P=100 and target V=110:

$$110=100(1+r).$$

Rearrange to obtain:

$$r=\frac{110}{100}-1=0.1.$$

This solves a target condition. In contrast, a table of values at r=0,0.05,0.1 supplies r directly and calculates V.

The unknown must be identifiable from the stated conditions. If P=0 and target V=0, the equation 0=0(1+r) holds for every admissible r. It cannot determine a unique rate. If P=0 and target V=10, there is no solution under this no-contribution model.

For positive principal, zero time creates another special case: V=P regardless of r. Rate inference then gives either many admissible rates when the target equals P or no rate when it differs. Rearranging symbols without inspecting these cases can hide the loss of information.

## 1.3.7 A Controlled Rate Scenario

Hold principal P=1000 and horizon n=2 fixed:

| Effective annual rate | Calculation | Ending value |
|---:|---|---:|
| 0% | 1000(1.00)^2 | 1000.00 |
| 3% | 1000(1.03)^2 | 1060.90 |
| 5% | 1000(1.05)^2 | 1102.50 |

Only rate changes between rows. The resulting differences can therefore be attributed to rate within this particular mathematical model and fixed-input comparison. They are not empirical estimates of a causal relationship in market data.

Compare a 5% rate with a 6% rate:

$$\Delta V=1000[(1.06)^2-(1.05)^2]=21.1.$$

The move is one percentage point, or 100 basis points, represented by h=0.01. It is not a relative 1% increase in the original rate. Relative to 5%, the rate rose by 20%.

For the two-period model, expand the exact finite difference:

$$V(r+h)-V(r)=P[2(1+r)h+h^2].$$

With P=1000,r=0.05,h=0.01, the two terms contribute 21 and 0.1, totaling 21.1. This identity needs no calculus. Later sensitivity chapters use the same structure to explain local approximations and their remainder terms.

## 1.3.8 Changing Two Inputs Changes the Comparison

Now move principal from 1000 to 2000 and rate from 5% to 6%, keeping n=2:

$$V_{old}=1000(1.05)^2=1102.5,$$

$$V_{new}=2000(1.06)^2=2247.2.$$

Total change is 1144.7. Calling all of it a “rate effect” would be wrong because principal changed too.

A principal-first decomposition gives:

- Principal change at the old rate: 2205-1102.5=1102.5.
- Rate change at the new principal: 2247.2-2205=42.2.

A rate-first decomposition gives:

- Rate change at the old principal: 1123.6-1102.5=21.1.
- Principal change at the new rate: 2247.2-1123.6=1123.6.

Both paths sum to 1144.7, but their separate labels differ. The rate effect scales with principal, so there is an interaction. An attribution report must state its decomposition convention. A path difference is not an arithmetic contradiction or evidence that one calculation is wrong.

## 1.3.9 Model Parameters and Python Function Parameters

A Python function parameter is a name in a function definition. It can receive a value regardless of that quantity's mathematical role in a particular experiment. In a definition such as annual_value(principal,rate,years), all three inputs are function parameters in programming terminology.

For a rate study, principal and years are fixed mathematical parameters and rate is the mathematical independent variable. For a principal study, principal becomes the independent variable. A function signature does not decide that distinction automatically.

Use descriptive names and explicit argument passing to keep roles reviewable. Keyword-only arguments are useful when several inputs are numerically similar but semantically different. Passing rate and years in the wrong order can otherwise produce an apparently valid value for the wrong model. Reference 2 describes Python function and argument conventions.

Avoid hiding scenario inputs in mutable module globals. A function that reads an externally reassigned base rate can produce different results from the same visible arguments. Passing inputs explicitly makes the calculation's dependencies easier to inspect and reproduce.

## 1.3.10 Executable Scenario Lab

We reuse the validated compound_value teaching kernel from Section 1.1. The new annual_value wrapper labels its rate and period basis explicitly; it does not change the underlying mathematics.

Save this complete example as [code/section_1_03.py](code/section_1_03.py), alongside the existing [section_1_01.py](code/section_1_01.py).

```python
from math import isclose
from section_1_01 import compound_value


BASIS_POINTS_PER_UNIT = 10000


def annual_value(*, principal, annual_effective_rate, years):
    """Whole years; fixed annual effective rate; no fees or intervening flows."""
    return compound_value(principal, annual_effective_rate, years)


def rate_scenarios(*, principal, years, rates):
    """Keep principal/horizon fixed; return ordered (rate, value) records.

    Rates is a small finite iterable. The reused kernel validates each row.
    No output or input-repair policy is inferred from an empty rate list.
    """
    return tuple(
        (rate, annual_value(principal=principal,
                            annual_effective_rate=rate, years=years))
        for rate in rates
    )


def main():
    assumptions = {"principal": 1000.0, "years": 2}
    snapshot = assumptions.copy()  # scalar-valued dictionary in this example
    rows = rate_scenarios(**assumptions, rates=(0.0, 0.03, 0.05))
    assert assumptions == snapshot
    assert all(isclose(value, expected, rel_tol=1e-12)
               for (_, value), expected in zip(rows, (1000, 1060.9, 1102.5)))
    for rate, value in rows:
        print(f"Rate {rate:.2%}: {value:.2f}")
    before = annual_value(**assumptions, annual_effective_rate=0.05)
    after = annual_value(**assumptions, annual_effective_rate=0.06)
    exact_change = after - before
    h = 100 / BASIS_POINTS_PER_UNIT
    expanded_change = 1000 * (2 * (1 + 0.05) * h + h*h)
    assert isclose(exact_change, expanded_change, rel_tol=1e-12)
    assert isclose(exact_change, 21.1, rel_tol=1e-12)
    implied_one_year_rate = 110 / 100 - 1
    assert isclose(implied_one_year_rate, 0.1, rel_tol=1e-12)
    print(f"100-basis-point scenario change: {exact_change:.2f}")
    print(f"Implied one-year effective rate: {implied_one_year_rate:.2%}")


if __name__ == "__main__":
    main()
```

Expected output:

```text
Rate 0.00%: 1000.00
Rate 3.00%: 1060.90
Rate 5.00%: 1102.50
100-basis-point scenario change: 21.10
Implied one-year effective rate: 10.00%
```

The row's value uses the same rate stored beside it. The result retains order and duplicate scenarios; it does not sort or average inputs silently. The assumptions dictionary contains scalar values and is not modified. Its shallow copy is sufficient for this example's scalar snapshot, not a general guarantee for nested mutable objects.

Each generated row inherits Section 1.1's input restrictions and numerical-range checks. In particular, years must be a nonnegative built-in integer and booleans are rejected as numeric inputs. The wrapper does not convert monthly inputs, parse quoted percentages, or repair missing values.

An empty rates iterable produces no rows and therefore performs no row-level validation. If an application requires validation even without scenarios, that is an additional interface requirement. A nonempty invalid rate sequence fails explicitly; no partial report is returned.

## 1.3.11 Reproducible Scenario Records

A result such as 1102.5 is incomplete without its assumptions. A reproducible record should include principal, rate, rate convention, horizon, period unit, fee treatment, and the version of the implemented formula.

For this lab, the experiment is small enough that the function call and rate/value table retain most of that information, while the docstring supplies the remaining convention. A larger application should use a structured record containing the complete model specification rather than rely on a reader remembering a previous notebook cell.

A deterministic output does not turn an assumed rate into a known future rate. Input uncertainty and stochastic models are separate topics. Even when a parameter is estimated elsewhere, it is treated as fixed conditional input in this scenario calculation unless a model explicitly allows it to vary.

## 1.3.13 Practice Problems and Worked Answers

**Problem 1 — Roles.** For f(r)=500(1+r)^3, identify the independent variable, dependent quantity, and fixed parameters. Does r have to be a random variable?

**Answer.** Rate r is the independent variable, f(r) the dependent value, and principal 500 and horizon three periods are fixed parameters. No random-variable interpretation is required; the study is deterministic.

**Problem 2 — Change the question.** Rewrite the previous model as a time study at a fixed 4% effective annual rate. State the input domain used by this section.

**Answer.** Use g(n)=500(1.04)^n for n in the nonnegative integers. Now n varies while principal 500 and rate 0.04 are fixed. Supporting fractional time would require a different stated interface and convention.

**Problem 3 — Target principal.** Determine the initial amount needed to reach 1210 after two years at 10% effective annually, with no other payments.

**Answer.** Solve P=1210/(1.1)^2=1000. Principal is unknown in this target question; target value, rate, and horizon are fixed. Substitution verifies 1000(1.1)^2=1210.

**Problem 4 — Insufficient information.** Can the equation 0=0(1+r)^2 identify r? What about 1000=1000(1+r)^0?

**Answer.** Neither identifies a unique rate. Each holds for every admissible rate r>-1. A formula can be well-defined without the supplied conditions uniquely determining its unknown.

**Problem 5 — Constant convention.** A program defines BASE_RATE=0.05. Is this a universal mathematical constant or an enforced immutable Python value?

**Answer.** Neither. It is a selected numerical input with an uppercase naming convention. Ordinary Python rebinding is still possible. The name should be accompanied by the rate's period and compounding convention; its value can change between separately defined experiments.

**Problem 6 — Exact rate change.** For P=500,n=2,r=0.04, calculate the exact value change from a 50-basis-point rate increase. Show both direct revaluation and the expanded expression.

**Answer.** The rate move is h=0.005. Direct change is 500[(1.045)^2-(1.04)^2]=5.2125. Expansion gives 500[2(1.04)(0.005)+(0.005)^2]=500(0.010425)=5.2125. This finite-change identity is exact under the two-period model, subject to numerical representation when implemented.

## 1.3.14 Common Mistakes and Summary

| Mistake | Consequence | Correction |
|---|---|---|
| Calling an input a parameter forever | The role no longer matches the question | State what varies in the present experiment |
| Confusing independent input with statistical independence | An unsupported probability claim appears | Separate deterministic function roles from stochastic assumptions |
| Changing principal and rate but reporting only a rate effect | The attribution mixes changes and interactions | Hold inputs fixed or disclose a decomposition path |
| Assuming uppercase names cannot change | Program state can differ from the intended fixed assumption | Use explicit inputs and document naming conventions |
| Assuming a Python function parameter must be mathematically fixed | Programming and mathematical terminology are conflated | Describe the experimental role separately |
| Solving for a rate from zero principal or zero horizon without checks | Uniqueness is claimed without information | Check existence and identifiability before rearranging |
| Treating a scenario input as an observed future fact | Interpretation exceeds the model | Keep conclusions conditional on assumptions |

A variable is allowed to change in a specified question, a parameter is held fixed for that question, and an unknown is determined from a condition when sufficient information exists. Constants and programming names require their own interpretation. Explicit roles make scenario comparisons and Python implementations easier to review.
