- Separate mathematical, financial, software-interface, and numerical-range restrictions.
- Test endpoints and implement an explicit tolerance policy without silently changing a domain.

Section 1.3 identified which inputs change and which remain fixed. We now formalize where those inputs are allowed to range.

## 1.4.2 Sets and Membership

A set describes a collection through its members. Write $x\in A$ when x belongs to A and $x\notin A$ when it does not. Repetition and order do not change a set: {1,2,2} and {2,1} describe the same mathematical set.

A finite set can be listed. For example, a model might support currency labels:

$$C=\{\mathrm{USD},\mathrm{EUR},\mathrm{JPY}\}.$$

This says which labels the application recognizes. It does not establish exchange rates, settlement precision, or permission to add amounts from different currencies.

Infinite sets normally use a rule rather than a complete list. For a positive-growth-factor rate model, define:

$$R=\{r\in\mathbb{R}:r>-1\}.$$

The colon means “such that.” The rule states membership directly, including negative rates between -1 and zero. A few example rates are not a complete description of this infinite domain.

Python set supports finite membership and set operations. An interval of real values should instead be represented by its bounds and a membership predicate; constructing a finite list of sampled points does not create every real value between them. Reference 3 documents Python's set behavior.

## 1.4.3 Intervals and Endpoints

For real numbers a<b, the following notations describe connected portions of the real line:

| Interval | Membership condition | Included endpoints |
|---|---|---|
| $(a,b)$ | $a<x<b$ | Neither |
| $[a,b]$ | $a\leq x\leq b$ | Both |
| $[a,b)$ | $a\leq x<b$ | Only a |
| $(a,b]$ | $a<x\leq b$ | Only b |

A square bracket includes a finite endpoint. A parenthesis excludes it. This distinction controls whether equality at a threshold is permitted; it is not a cosmetic formatting choice.

For a weight required to lie between zero and one inclusive, write $w\in[0,1]$. The endpoints allow investing none or all in that component. If a contract instead requires a strictly positive share below one, its domain is $(0,1)$.

A time window $[0,1)$ includes the opening date and excludes the closing date. Adjacent windows $[0,1)$ and $[1,2)$ avoid assigning the shared boundary to both windows. That example concerns interval membership, not a complete calendar or day-count implementation. Reference 1 provides the underlying interval conventions.

## 1.4.4 Unbounded, Empty, and Singleton Sets

An unbounded interval has no finite endpoint in one or both directions:

$$(-1,\infty),\qquad [0,\infty),\qquad (-\infty,0].$$

Infinity is not an ordinary real endpoint that belongs to these intervals. Use a parenthesis at infinity. A Python float containing infinity is therefore not an admissible member of a finite-real input model just because an interval is unbounded.

The empty set, $\varnothing$, contains no values. An inconsistent pair of restrictions can produce it: no real x satisfies both x>=2 and x<=1.

A singleton contains exactly one value. The closed interval [a,a] equals {a}. If equal endpoints are not both included, the corresponding interval is empty. Thus [1,1] contains one while (1,1), [1,1), and (1,1] contain none.

An empty feasible set means the conditions cannot be satisfied. It should not be replaced by zero, a default rate, or an arbitrary “closest” value without defining a different problem.

## 1.4.5 Combine Restrictions with Set Operations

Intersection selects values satisfying both restrictions. Union selects values satisfying at least one. Difference removes members of one set from another.

| Operation | Notation | Membership meaning |
|---|---|---|
| Intersection | $A\cap B$ | In A and in B |
| Union | $A\cup B$ | In A or in B, including both |
| Difference | $A\setminus B$ | In A and not in B |

Suppose a mathematical rate model allows A=(-1,infinity), while a hypothetical policy allows B=[-0.05,0.20]. The permitted rate domain is:

$$A\cap B=[-0.05,0.20].$$

A policy allowing a rate below -1 would not override the mathematical model. For B=[-1.2,0.20], the intersection would instead be (-1,0.20].

A complement must state its universe. If U={USD,EUR,JPY} and A={USD,EUR}, then $U\setminus A=\{JPY\}$. Saying “everything not in A” without identifying U leaves the scope unclear.

## 1.4.6 A Domain Can Have Gaps

Not every domain is one interval. The real-valued expression:

$$f(x)=\frac{1}{x-2}$$

excludes x=2. Its maximal real domain is:

$$(-\infty,2)\cup(2,\infty).$$

Writing only “x is real” misses the excluded denominator zero. Writing one closed interval from a lower to an upper sampled value could incorrectly include the gap.

Cancellation also requires care. For:

$$g(x)=\frac{x^2-1}{x-1},$$

factoring gives g(x)=x+1 only for x!=1. The simplified rule can be extended to x=1, but that extension is a new domain decision; algebraic cancellation alone does not make the original fraction defined there.

The function's specification includes its domain as well as its formula. Reference 2 discusses restrictions introduced by denominators and real-valued roots.

## 1.4.7 Mathematical Restrictions and Financial Interpretation

A formula's maximal algebraic domain may be broader than the intended financial domain.

For a single-period simple return:

$$R=\frac{P_1-P_0}{P_0},$$

the fraction requires P_0!=0. A simplified nonnegative-price interpretation can additionally require P_0>0 and P_1>=0. Under those assumptions, R>=-1, and R=-1 represents a complete loss to zero.

This is different from the positive-growth-factor discount-rate convention r>-1 used earlier. A logarithmic return would require a positive gross-return ratio, excluding the complete-loss boundary. Do not apply one model's domain to every quantity named “rate” or “return.”

Similarly, a real square root requires a nonnegative argument, while a real logarithm requires a strictly positive argument. These statements tell us where real-valued operations are defined; financial conventions may add further restrictions.

We will derive and apply these functions in later chapters. Here the important habit is to write the particular operation and interpretation before choosing the domain.

## 1.4.8 Product Domains and Coupled Constraints

For the whole-period growth model, a convenient domain is:

$$D=[0,\infty)\times(-1,\infty)\times\mathbb{N}_0.$$

An element is an ordered triple (P,r,n). The multiplication symbol between sets denotes a Cartesian product: choose one admissible coordinate from each set. It does not multiply principal by rate by time.

Some domains need extra relationships between coordinates. A fully invested, long-only two-asset allocation requires:

$$w_1\in[0,1],\qquad w_2\in[0,1],\qquad w_1+w_2=1.$$

The square [0,1] times [0,1] contains (0.8,0.8), but that pair violates the budget equation. The feasible set is the line segment joining (0,1) and (1,0), not the whole square.

For another example, an upfront fee F in a no-borrowing account can require P>=0 and 0<=F<=P. Testing F>=0 alone would miss the coupling between fee and principal. Multi-input validation must check the joint specification as well as individual bounds.

## 1.4.9 Mathematical Domain, Interface, and Numerical Range

Keep four different questions visible:

1. Is the operation mathematically defined?
2. Does the value satisfy the chosen financial interpretation and policy?
3. Does the software accept this representation and input shape?
4. Can the implementation evaluate the result within its numerical range and accuracy needs?

For example, n=2.0 represents an integer-valued real number but is rejected by our earlier whole-period API, which requires a built-in Python int. That is a software-interface restriction, not evidence that the mathematical value two is invalid.

A finite principal and valid rate can still produce an overflowing future value at a very long horizon. Domain admissibility does not guarantee numerical representability. Conversely, a computer may calculate a number for an economically inadmissible input; successful evaluation is not domain validation.

NaN and infinities are not finite real inputs. They require explicit handling rather than only sign comparisons. The code below also excludes booleans and limits supported scalar representations to built-in int and float inputs that can be converted to finite float values.

## 1.4.10 Tolerances Must Have a Specific Role

The mathematical budget equation w_1+w_2=1 is exact. A numerical membership check may deliberately use:

$$\left|(w_1+w_2)-1\right|\leq\varepsilon.$$

This defines an approximate budget acceptance rule, which is wider than the exact feasible set when epsilon is positive. State epsilon, its units, and which constraint it affects. It does not automatically normalize the weights or change their values.

In this section's example, each weight must still satisfy its closed interval exactly as represented. A tiny negative weight is rejected even if the sum is close to one. The tolerance applies only to the sum equation, not to the component bounds.

A large tolerance makes the check less restrictive. Choosing one should follow the intended accuracy policy rather than merely making a failing case pass. The default 1e-12 is an instructional absolute tolerance on a dimensionless weight sum, not a universal trading or accounting standard.

For strict boundaries such as r>-1, the example applies a strict comparison without an added epsilon. Widening that boundary could admit a zero or negative growth factor, changing the mathematical model.

## 1.4.11 Executable Membership Lab

Save this complete standard-library example as [code/section_1_04.py](code/section_1_04.py). It is independent of earlier code modules.

```python
from math import fsum, isclose, isfinite


def finite_float(value):
    """Return a supported finite float, or None for an excluded input."""
    if type(value) not in (int, float):
        return None
    try:
        result = float(value)
    except OverflowError:
        return None
    return result if isfinite(result) else None


def interval_contains(value, lower, upper, *, left_closed=True, right_closed=True):
    """Finite bounds only; invalid configuration raises; excluded value returns False."""
    lo, hi = finite_float(lower), finite_float(upper)
    if lo is None or hi is None or lo > hi:
        raise ValueError("finite bounds with lower <= upper required")
    if type(left_closed) is not bool or type(right_closed) is not bool:
        raise TypeError("endpoint flags must be bool")
    x = finite_float(value)
    if x is None:
        return False
    left = x >= lo if left_closed else x > lo
    right = x <= hi if right_closed else x < hi
    return left and right


def discount_rate_member(value):
    """Finite real representation and strictly positive growth factor."""
    rate = finite_float(value)
    return rate is not None and rate > -1


def growth_domain_member(principal, rate, periods):
    amount = finite_float(principal)
    return (amount is not None and amount >= 0
            and discount_rate_member(rate)
            and type(periods) is int and periods >= 0)


def long_only_pair_member(first, second, *, budget_tol=1e-12):
    """Exact represented [0,1] bounds; approximate absolute budget check only."""
    tol = finite_float(budget_tol)
    if tol is None or tol < 0:
        raise ValueError("budget_tol must be finite and nonnegative")
    if not (interval_contains(first, 0, 1) and interval_contains(second, 0, 1)):
        return False
    total = fsum((finite_float(first), finite_float(second)))
    return isclose(total, 1.0, rel_tol=0.0, abs_tol=tol)


def main():
    first = {"USD", "EUR"}
    second = {"EUR", "JPY"}
    print(f"Intersection: {sorted(first & second)}")
    print(f"Union: {sorted(first | second)}")
    for rate in (-1.0, -0.05, 0.0):
        print(f"Discount rate {rate}: {discount_rate_member(rate)}")
    print(f"[0,1] contains 0: {interval_contains(0, 0, 1)}")
    print(f"(0,1) contains 0: {interval_contains(0, 0, 1, left_closed=False, right_closed=False)}")
    print(f"Growth triple (1000,0.05,2): {growth_domain_member(1000, 0.05, 2)}")
    print(f"Weights (0.4,0.6): {long_only_pair_member(0.4, 0.6)}")
    print(f"Weights (0.8,0.8): {long_only_pair_member(0.8, 0.8)}")
    assert interval_contains(1, 1, 1)
    assert not interval_contains(1, 1, 1, left_closed=False)
    assert not long_only_pair_member(-1e-15, 1.0)


if __name__ == "__main__":
    main()
```

Expected output:

```text
Intersection: ['EUR']
Union: ['EUR', 'JPY', 'USD']
Discount rate -1.0: False
Discount rate -0.05: True
Discount rate 0.0: True
[0,1] contains 0: True
(0,1) contains 0: False
Growth triple (1000,0.05,2): True
Weights (0.4,0.6): True
Weights (0.8,0.8): False
```

The finite-interval helper deliberately does not encode unbounded intervals with infinity arguments; the separate rate predicate implements its unbounded mathematical restriction directly while requiring a finite observation. Reversed bounds are treated as invalid configuration rather than as an alternative notation for an empty interval.

The helper converts supported observations and finite bounds to floats. Comparisons therefore concern those representations, not arbitrary-precision integer ordering. Distinct integers larger than float's exact-integer range can map to the same float. Use an exact integer or decimal comparison policy when those distinctions matter. Whole-period counts are checked as integers without this conversion.

## 1.4.13 Practice Problems and Worked Answers

**Problem 1 — Translate notation.** Describe membership of [-0.02,0.10), and decide whether each endpoint belongs.

**Answer.** A real x must satisfy -0.02<=x<0.10. The lower endpoint belongs and the upper endpoint does not. The notation is a restriction on values, not an assertion that every rate in the interval is appropriate for an actual contract.

**Problem 2 — Intersect restrictions.** A positive-growth-factor model permits r>-1. A policy permits -1.2<=r<=0.15. Find the combined rate domain.

**Answer.** The intersection is (-1,0.15]. The model excludes -1 and all lower values even though the policy alone allows them. The upper endpoint 0.15 is included.

**Problem 3 — Excluded point.** Find the maximal real domain of 1/(r-0.03). Does simplifying a different expression (r^2-1)/(r-1) remove its original exclusion?

**Answer.** The first domain is (-infinity,0.03) union (0.03,infinity). The second expression remains undefined at r=1, even though it agrees with r+1 everywhere else. Defining a value at the excluded point is an extension rather than a consequence of cancellation.

**Problem 4 — Feasible pairs.** Which pairs satisfy exact full investment and long-only bounds: (0,1),(0.5,0.5),(0.8,0.8),(1.1,-0.1)?

**Answer.** The first two satisfy both requirements. The third satisfies component bounds but sums to 1.6. The fourth sums to one but violates both component bounds. Individual domains and a joint constraint must be checked separately.

**Problem 5 — Return boundary.** For P_0=100 and P_1=0, calculate simple return. Explain why its admissibility does not make r=-1 valid in the discount-rate model used in this chapter.

**Answer.** Simple return is (0-100)/100=-1, representing a complete loss under the nonnegative-price interpretation. The discount-rate model requires a strictly positive growth factor 1+r, excluding r=-1. The formulas and their interpretations differ; the same numeric value need not share a domain across models.

**Problem 6 — Empty or singleton.** Describe the sets satisfying x>=2 and x<=1, then x>=2 and x<=2. State how the finite-interval helper handles a call with reversed bounds.

**Answer.** The first mathematical feasible set is empty, while the second is the singleton {2}. The helper supports equal finite bounds but rejects reversed bounds with ValueError as an interface-configuration policy. Its error behavior is distinct from the mathematical fact that a pair of inconsistent inequalities has no solutions.

## 1.4.14 Common Mistakes and Summary

| Mistake | Consequence | Correction |
|---|---|---|
| Using a bracket at infinity | Infinity appears to be an included real value | Use an open unbounded end and validate finite inputs |
| Replacing an interval with a sampled Python set | Most admissible real values are omitted | Store bounds and evaluate membership |
| Using union when every rule must hold | Inputs satisfying only one restriction pass | Intersect simultaneous restrictions |
| Checking coordinate bounds but ignoring a budget | Individually valid weights form an infeasible allocation | Check coupled constraints |
| Removing excluded points after cancellation | The original expression's domain changes silently | Retain exclusions or state an extension |
| Applying r>-1 to every return formula | A valid complete-loss simple return is rejected | Derive each formula's own domain |
| Using an unstated epsilon for every comparison | Strict boundaries and financial policies change | Assign tolerances to specific numerical checks |
| Treating numerical overflow as a domain proof | Representation limits are confused with mathematics | Report mathematical and computational restrictions separately |

Sets state membership; intervals express common real-valued restrictions; intersections combine requirements; and Cartesian products describe independent coordinate choices. Joint financial constraints can narrow those product domains. An implementation should make its representation and tolerance policies equally explicit.
