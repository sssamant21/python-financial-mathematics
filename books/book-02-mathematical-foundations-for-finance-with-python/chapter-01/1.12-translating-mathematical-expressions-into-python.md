## 1.12.1 Learning Objectives

After this section, you should be able to translate mathematical grouping, powers, fractions, indexed quantities, finite sums, and piecewise definitions into readable Python. You should also be able to preserve a formula's domain, choose an explicit numeric representation, map mathematical time indices to sequence positions, and identify translation mistakes that produce valid Python but the wrong calculation.

Section 1.11 translated a question into a mathematical specification. This section takes an already stated expression and makes it executable. These are separate steps: selecting a formula is modeling; implementing that formula requires attention to syntax, types, indexing, and evaluation.

Our main lab evaluates fixed-period compound growth and a small discounted cash-flow schedule. The financial relationships are supplied as hypothetical model definitions. Their wider derivation and applications receive fuller treatment in later chapters; here they provide concrete expressions to translate.

## 1.12.2 Make the Symbol-to-Name Mapping Explicit

Start with a dictionary of meanings before writing a long expression. For the compound-growth model

\[
A=P(1+r)^n,
\]

use this correspondence:

| Mathematics | Meaning | Python name or representation |
|---|---|---|
| \(P\) | Nonnegative initial principal | `principal` |
| \(r\) | Effective decimal rate per period | `period_rate` |
| \(n\) | Nonnegative integer period count | `periods` |
| \(1+r\) | Growth factor per period | `1 + rate` |
| \(A\) | Modeled final balance | Function return value |

Mathematical symbols are concise because the surrounding text carries their meaning. In a function interface, descriptive names reduce dependence on memory. A parameter named `rate` still needs its quotation and period specified; a longer identifier cannot replace a domain statement.

The lab requires \(P\geq0\), \(r>-1\), and integer \(n\geq0\). The positivity of \(1+r\) also supports the discount denominators used later. Rates are decimal fractions, so 5% is supplied as `"0.05"`. All periods must match the rate's period. Inputs share one currency and scale, as established in Section 1.10.

## 1.12.3 Translate Operators, Not Typography

Mathematical notation often omits multiplication signs and places exponents or denominators spatially. Python needs explicit operators and grouping:

| Mathematical expression | Python expression |
|---|---|
| \(ab\) | `a * b` |
| \(a^n\) | `a ** n` |
| \(\frac{a+b}{c+d}\) | `(a + b) / (c + d)` |
| \(\lvert x\rvert\) | `abs(x)` |
| \(\max(0,T-D)\) | `max(0, target - destination)` |
| \(a\leq x\leq b\) | `a <= x <= b` |

The caret `^` is bitwise exclusive-or, not exponentiation. For integer operands, `2 ^ 3` returns 1 while `2 ** 3` returns 8. A program can therefore run successfully while evaluating a different operation.

Also distinguish assignment and comparison. `balance = expression` assigns a result to a name; `balance == expression` compares values. Neither asks Python to solve an equation for an unknown. Translating a mathematical equation into code may require a separate rearrangement or algorithm before evaluation is possible.

For ordinary numeric operands, `/` performs division; `//` performs floor division. Floor division is not a replacement for a fraction bar when the intended result can be nonintegral. Rounding or truncation is a separate modeling choice.

## 1.12.4 Preserve Grouping and Order of Operations

The fraction

\[
\frac{C}{(1+r)^t}
\]

translates as `cash_flow / (1 + rate) ** time`. The parentheses identify the full growth factor before exponentiation. Writing `cash_flow / 1 + rate ** time` changes both the denominator and the grouping.

Similarly, compound growth translates as `principal * (1 + rate) ** periods`, not `(principal * (1 + rate)) ** periods`. The latter raises the principal to a power too. For \(P=100\), \(r=0.10\), and \(n=2\), the correct result is 121; the second expression gives 12,100.

Powers and signs deserve a check: `-2 ** 2` evaluates as `-(2 ** 2)`, giving −4, whereas `(-2) ** 2` gives 4. Python also groups chained powers from the right: `2 ** 3 ** 2` means `2 ** (3 ** 2)`.

Use parentheses when they reveal the structure you intend, even where precedence would already produce the same result. Named intermediate values can help too: compute `growth_factor`, then apply the power, then multiply by principal. Read the expression back into mathematical notation before trusting the output.

## 1.12.5 Division Depends on Numeric Representation

With built-in integers, `1 / 3` produces a floating-point approximation. If a lab needs exact rational arithmetic, use `Fraction(1, 3)` or a rational string accepted by a deliberately defined interface.

This section uses `Fraction` to keep small rational calculations exact. Integer powers and arithmetic on rational inputs remain rational under the operations used here. Constructing from the decimal string `"0.05"` preserves exactly \(1/20\); constructing from the float `0.05` preserves that float's binary value instead.

Our input helper therefore accepts only built-in integers, strings understood by `Fraction`, and `Fraction` objects. It rejects floats and Boolean values. This is an explicit teaching interface rather than a general recommendation to reject floats in every application.

Exact arithmetic does not establish economic correctness, and fractions can grow large under repeated powers. The lab uses small inputs on a CPU. Later numerical sections address approximation, stability, and performance. For now, choose the number system deliberately rather than switching types accidentally halfway through a formula.

## 1.12.6 Carry the Domain into the Function

A mathematical formula is often written beside assumptions. Those assumptions must travel with the implementation. The function should reject unsupported inputs before evaluating an expression whose meaning depends on them.

For \(A=P(1+r)^n\), zero periods are allowed, so \(A=P\). A zero principal is allowed. A zero rate is allowed. Negative rates greater than −1 are also allowed: for example, −10% per period gives a positive factor of 0.9.

The lab excludes \(r\leq-1\). This shared interface keeps the discount factor strictly positive and avoids a zero denominator in present-value calculations. Some growth expressions can be defined at rates outside this domain for particular integer powers, but that does not enlarge the declared domain of these functions automatically.

A period count must be a built-in integer, and Boolean values are excluded even though Python treats `bool` as a subclass of `int`. The function rejects `2.0` rather than silently rounding or truncating it. An input policy should be visible in the interface and prose, not inferred from whichever operations happen to succeed.

## 1.12.7 Translate Indices into Positions

Suppose cash flows are specified as

\[
C_0,C_1,\ldots,C_n,
\]

with \(C_t\) paid at time \(t\), measured in matching periods. The lab stores them in a sequence whose position is the time index: position 0 is time zero, position 1 is one period later, and so on.

For `cash_flows = (-100, 55, "60.5")`, the initial outflow is −100 at time zero, followed by receipts 55 and 60.5 at times one and two. Negative means an outflow from the chosen perspective; positive means an inflow. The sequence contains three cash flows but spans two future periods.

Using `enumerate(cash_flows)` exposes both position and value. Starting the count at one would move every payment one period later, including the initial outflow. Conversely, if a separate specification lists only \(C_1,\ldots,C_n\), a start index of one may be correct. The mapping depends on the stated schedule.

Missing periods must be represented explicitly with zero cash flow when the position defines time. Removing a zero entry changes the timing of every later entry. A sparse schedule with explicit date or time labels needs a different interface; it cannot be reconstructed from positions alone.

## 1.12.8 Translate a Finite Sum Term by Term

For a fixed periodic discount rate \(r>-1\), define the modeled time-zero value

\[
V_0:=\sum_{t=0}^{n}\frac{C_t}{(1+r)^t}.
\]

First translate one term, then the indexing, then the reduction. A readable implementation builds terms using `cash_flow / (1 + rate) ** time` and sums them. Keeping the terms available helps inspect timing and signs.

For the example schedule and \(r=0.10\),

\[
V_0=-100+\frac{55}{1.1}+\frac{60.5}{1.1^2}
=-100+50+50=0.
\]

The time-zero term is unchanged because \((1+r)^0=1\). This is a useful translation check. Zero here is the value of this supplied schedule under the declared rate; it is not a general statement that the transaction is risk-free or economically suitable.

The lab supplies an explicit zero `Fraction` as the start value for `sum`. It rejects an empty schedule because the interface requires a time-zero entry. This application decision does not alter the mathematical convention that an empty sum equals zero.

## 1.12.9 Translate Products, Conditions, and Piecewise Rules

A finite product \(\prod_{j=1}^{n}(1+r_j)\) requires multiplying the factors over exactly the stated indices. A loop with initial accumulator 1 expresses that structure. The empty product is 1. If varying rates are stored by period, document which rate applies before each payment; a product is not interchangeable with adding rates.

Piecewise expressions become branches. In Section 1.11, a fee is zero when the transfer is zero and equals \(F+kx\) when the transfer is positive. An explicit `if` statement or conditional expression preserves that distinction. Evaluating the positive-transfer formula at zero would change the model.

Use `and`, `or`, and `not` for scalar logical combinations of well-defined Boolean conditions. A chained comparison such as `0 <= weight <= 1` represents the conjunction of its two bounds. As Section 1.8 explained, Python truth testing can accept objects other than Boolean values; input validation remains necessary.

This lab implements a constant-rate sum and a growth power. Variable-rate products and piecewise fee rules are translation patterns discussed here, not additional features claimed for the functions below.

## 1.12.10 Prefer Small Functions to One Dense Expression

A useful mathematical function has a clear input contract and a return value with a stated meaning. Separate conversion, domain validation, and calculation so that a reader can inspect each step.

The lab uses `periodic_rate` to normalize and validate one rate, `compound_balance` for the growth expression, and `present_value` for the supplied schedule. Named arguments reduce the chance of confusing principal with rate or periods. A returned report includes discounted terms as well as the total.

Avoid constructing a formula as text and passing it to `eval`. These formulas can be expressed directly with ordinary operators and functions. Direct code makes names, types, and validation visible without introducing a separate expression-language problem.

Do not round intermediate terms merely to make them look like currency. A contractual rounding policy might require that, but it would be an additional model rule. The lab preserves exact terms and prints them directly. Section 1.13 will examine result checking more systematically; this section establishes a readable translation that can be checked.

## 1.12.11 Worked Python Lab — Growth and a Discounted Schedule

Save as [code/section_1_12.py](code/section_1_12.py). Cash-flow position zero always represents time zero. Rates are effective decimal rates per matching period. The schedule must be a nonempty list or tuple, and signed cash flows are allowed.

```python
"""Exact translation of a growth power and an indexed discounted sum."""
from fractions import Fraction


def rational(value):
    if type(value) not in (int, str, Fraction):
        raise TypeError("use an integer, rational string, or Fraction")
    return Fraction(value)


def periodic_rate(value):
    rate = rational(value)
    if rate <= -1:
        raise ValueError("period rate must exceed -1")
    return rate


def compound_balance(*, principal, period_rate, periods):
    p = rational(principal)
    rate = periodic_rate(period_rate)
    if p < 0:
        raise ValueError("principal must be nonnegative")
    if type(periods) is not int:
        raise TypeError("periods must be an integer, excluding bool")
    if periods < 0:
        raise ValueError("periods must be nonnegative")
    growth_factor = 1 + rate
    return p * growth_factor ** periods


def present_value(*, cash_flows, period_rate):
    rate = periodic_rate(period_rate)
    if type(cash_flows) not in (list, tuple):
        raise TypeError("cash flows must be a list or tuple")
    if not cash_flows:
        raise ValueError("include at least the time-zero cash flow")
    flows = tuple(rational(value) for value in cash_flows)
    terms = tuple(cash_flow / (1 + rate) ** time
                  for time, cash_flow in enumerate(flows))
    return {"period_rate": rate, "cash_flows": flows,
            "discounted_terms": terms, "total": sum(terms, Fraction(0))}


def main():
    balance = compound_balance(principal=100, period_rate="0.10", periods=2)
    print(f"Compound balance: {balance}")
    report = present_value(cash_flows=(-100, 55, "60.5"), period_rate="0.10")
    for time, term in enumerate(report["discounted_terms"]):
        print(f"t={time}: discounted cash flow={term}")
    print(f"Time-zero value: {report['total']}")
    zero_rate = present_value(cash_flows=(-100, 55, "60.5"), period_rate=0)
    print(f"At zero rate: {zero_rate['total']}")
    print(f"Power versus XOR: {2 ** 3} versus {2 ^ 3}")


if __name__ == "__main__":
    main()
```

Expected output:

```text
Compound balance: 121
t=0: discounted cash flow=-100
t=1: discounted cash flow=50
t=2: discounted cash flow=50
Time-zero value: 0
At zero rate: 31/2
Power versus XOR: 8 versus 1
```

## 1.12.12 Practice Problems

1. Translate \((a+b)/(c+d)\), \(P(1+r)^n\), and \(\lvert x-w\rvert\leq\epsilon\) into Python. State the denominator restriction for the first expression.
2. Evaluate `-3 ** 2`, `(-3) ** 2`, and `3 ^ 2`. Explain why the third is not a power.
3. Under the lab's schedule convention, what cash flows does `(0, 0, 121)` represent? Find its value at rate 10%. What changes if the middle zero is removed?
4. Calculate compound balance for principal 200, rate −10% per period, and two periods. Identify an allowed negative rate and the excluded boundary.
5. Translate and evaluate \(V_0=-50+55/(1+r)\) at \(r=0.10\). Which sequence should be passed to `present_value`?
6. Why does the lab reject an empty schedule, a float rate `0.1`, and period count `True`? Are all three mathematical impossibilities?

## 1.12.13 Worked Answers

1. Use `(a + b) / (c + d)`, `principal * (1 + rate) ** periods`, and `abs(x - target_weight) <= half_width`. Require \(c+d\ne0\). The latter two also need the domains and conventions of their intended models; syntax alone does not establish them.
2. The results are −9, 9, and 1. The first applies negation after exponentiation, the second squares the grouped negative number, and the third performs integer bitwise XOR.
3. There is no time-zero flow, no time-one flow, and a receipt of 121 at time two. Its value is \(121/1.1^2=100\). Removing the middle zero moves the receipt to time one, giving \(121/1.1=110\). A zero amount still carries timing information through its position.
4. \(200(0.9)^2=162\). Rate −0.10 is allowed because it exceeds −1. Rate −1 is excluded by the shared positive-growth-factor domain, as are smaller rates.
5. Use `cash_flows=(-50, 55)` and `period_rate="0.10"`. The discounted receipt is 50, so the total is zero. The initial outflow is at time zero and must not be discounted by an extra period.
6. The empty schedule violates the interface's requirement for a time-zero entry; the float rate violates its exact-input convention; and `True` violates its explicit integer-count policy. These are declared software contracts. An empty sum has a mathematical definition, floats can support approximate calculations in other interfaces, and Python's Boolean/integer relationship does not determine the intended meaning of a period count.

## 1.12.14 Common Mistakes, Summary, and Sources

Common translation errors include using `^` for powers, losing denominator parentheses, using floor division where a ratio is required, shifting an index by one, deleting zero entries from a position-based schedule, and confusing equation solving with assigning a calculated value. Implicit percentage conversion or unplanned numeric-type changes can also alter the result.

Use a repeatable sequence: map symbols to names, carry domains and conventions into the interface, translate one grouped term, establish the index mapping, and only then combine terms or repeat operations. Keep intermediate values available when they help explain the formula. Check a hand-solvable case before trusting a larger calculation.

The lab covers constant effective periodic rates, nonnegative integer horizons, nonnegative principal for growth, and a nonempty signed cash-flow sequence indexed from time zero. It does not implement dates, day-count conventions, variable-rate curves, irregular timing, rounding rules, or a production valuation system. Canonical editorial review remains pending.
