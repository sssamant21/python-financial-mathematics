# 13.9 — Chapter Project — Least-Squares Replication Analyzer

**Status:** Draft — runtime validation, independent review, and production certification pending.

## Project brief

Build a small, reproducible analyzer that compares a target risk-factor exposure vector against the span of a set of available financial instruments. Compute a least-squares replication portfolio, report signed residuals, assess factor-specific hard limits, and preserve sufficient evidence for review.

**Boundary:** This is an educational, unconstrained, full-column-rank analyzer. It does not execute trades, estimate real market sensitivities, or certify an economically acceptable hedge.

## Learning outcomes

Integrate the chapter's ideas of span, independence, rank, column space, projection, least squares, QR, unit normalization, and risk governance into a coherent pipeline. Explain why an optimizer's numerical success is not the same as risk-policy approval.

## Architecture

\`\`\`text
Labeled factor sensitivities + target + scales + hard limits
       |
       v
Input validation: shapes, units, labels, finiteness
       |
       v
Scale each factor row and target by approved positive scale
       |
       v
Householder QR least-squares solver (full column rank)
       |
       v
Positions -> achieved exposures -> signed residuals
       |
       v
Weighted objective + orthogonality diagnostic
       |
       v
Independent factor-limit checks -> auditable report
\`\`\`

The project uses a QR solver rather than explicitly inverting normal equations. It intentionally rejects underdetermined or rank-deficient models; extending it to rank-revealing QR/SVD and regularization is an advanced exercise.

## Dataset and business scenario

A fictional portfolio has three standardized exposure factors (RATE, CREDIT, LIQUIDITY) and two hypothetical instruments (BOND_A and BOND_B). Rows are factors, columns are instruments:

\[
A=\begin{bmatrix}
1&0\\
0&1\\
1&1
\end{bmatrix},
\quad b=\begin{bmatrix}2\\3\\6\end{bmatrix}.
\]

The model cannot replicate the target exactly because every attainable vector satisfies LIQUIDITY = RATE + CREDIT, while the target does not.

With factor scales \(s=(1,1,1)\), the weighted objective reduces to ordinary least squares:

\[
J(x)=\tfrac12\sum_i\left(\frac{b_i-(Ax)_i}{s_i}\right)^2.
\]

The expected solution is

\[
x^*=(7/3,10/3),\quad Ax^*=(7/3,10/3,17/3),
\]

\[
r=b-Ax^*=(-1/3,-1/3,1/3),\quad J^*=1/6.
\]

Set hard residual limits RATE \(0.40\), CREDIT \(0.40\), and LIQUIDITY \(0.25\). RATE and CREDIT pass, but LIQUIDITY fails. The project must report **REJECT**, even though the least-squares optimum is mathematically correct.

## Core mathematical checks

1. **Rank:** two independent instrument columns are required for this educational solver.
2. **Projection:** the achieved exposure lies in \(\operatorname{col}(A)\).
3. **Residual:** report \(r=b-Ax\), not an unsigned mismatch.
4. **Optimality:** standardized residuals satisfy \(\widetilde A^\mathsf T\widetilde r\approx0\), where \(\widetilde A_{ij}=A_{ij}/s_i\).
5. **Objective:** \(J=\frac12\|\widetilde r\|_2^2\).
6. **Policy:** check each \(|r_i|\le L_i\) independently; the weighted objective is not a substitute for hard limits.

### Report contract

The JSON report includes:

- Instrument quantities, achieved exposures, and target-minus-achieved residuals.
- Dimensionless standardized residuals and weighted least-squares objective.
- Weighted first-order gradient by instrument.
- Per-factor PASS/FAIL booleans and aggregate ACCEPT/REJECT.
- A solver identifier and explicit \`runtime_certified: false\` flag.

### Operational guardrails

Reject missing or duplicated labels, nonfinite values, invalid shapes, zero or negative scales, negative hard limits, inconsistent factor units, and rank-deficient systems. Never silently repair bad factor mappings or assume that matching labels imply matching economic units.

### Numerical acceptance tolerance

The educational reference case is small and well-scaled. Acceptance checks compare positions, exposures, objective, and gradient to independently derived fractions using a numerical tolerance. Production use requires additional condition-number monitoring, rank-revealing decomposition, input governance, scenario testing, and independent risk approval.

## Ten project tasks with expected answers

**1.** Identify the matrix dimensions.  
*Answer:* Three factors by two instruments.

**2.** Determine the model's rank.  
*Answer:* Two.

**3.** Explain why the target is not exactly attainable.  
*Answer:* Target LIQUIDITY 6 differs from RATE + CREDIT = 5.

**4.** Calculate the optimal BOND_A quantity.  
*Answer:* \(7/3\).

**5.** Calculate the optimal BOND_B quantity.  
*Answer:* \(10/3\).

**6.** Calculate achieved LIQUIDITY exposure.  
*Answer:* \(17/3\).

**7.** Calculate the residual vector.  
*Answer:* \((-1/3,-1/3,1/3)\).

**8.** Calculate the weighted objective with unit scales.  
*Answer:* \(1/6\).

**9.** Identify the policy breach.  
*Answer:* LIQUIDITY residual magnitude \(1/3>0.25\).

**10.** State the overall decision.  
*Answer:* REJECT.

## Advanced extensions

- Introduce non-unit factor scales and verify invariance under consistent unit conversion.
- Compare QR results with a trusted SVD reference.
- Add rank-deficient instrument columns and implement a documented regularization strategy.
- Add no-short, concentration, and gross-notional constraints using an appropriate constrained optimizer.
- Produce scenario-based stability diagnostics and a reproducible model-governance record.
