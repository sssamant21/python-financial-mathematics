## Project mission

Build a standard-library Python tool that compares analytically derived first and second derivatives with forward, backward, centered, and Richardson-extrapolated finite differences. Apply the tool to financial functions, study step-size sensitivity, and produce an auditable acceptance report.

This project integrates Sections 8.1–8.8. Its objective is **verification**, not to replace analytic mathematics or assert that numerical agreement proves differentiability.

## 1. Requirements

The comparator must:

1. Accept a callable function, its analytic first derivative, and optionally its analytic second derivative.
2. Validate numeric inputs and positive finite step sizes.
3. Evaluate forward, backward, centered, and Richardson first derivatives.
4. Evaluate the centered second derivative when an analytic second derivative is supplied.
5. Report signed and absolute error for each approximation.
6. Support a configurable absolute/relative tolerance gate and a step-size ladder.
7. Handle invalid domains, singularities, nonfinite values, and non-differentiable points explicitly.
8. Include financial test cases: continuous-compounding accumulation, discounted cash flow, quadratic profit, and a smooth positive ratio.
9. Use only the Python standard library.
10. Keep test evidence distinct from manuscript publication status.

## 2. Mathematical methods

For smooth \(f\) and \(h>0\),

\[
D_h^+f(x)=\frac{f(x+h)-f(x)}h,\qquad
D_h^-f(x)=\frac{f(x)-f(x-h)}h,
\]

\[
D_h^0f(x)=\frac{f(x+h)-f(x-h)}{2h},
\qquad
D_h^{(2)}f(x)=\frac{f(x+h)-2f(x)+f(x-h)}{h^2}.
\]

Richardson extrapolation cancels the leading \(O(h^2)\) truncation term of the centered first derivative:

\[
D_h^R f(x)=\frac{4D_{h/2}^0f(x)-D_h^0f(x)}3.
\]

For each method \(m\), define

\[
e_m=\widehat{f'}_m-f'(x),\qquad E_m=|e_m|.
\]

A method passes its numerical gate if

\[
|\widehat{f'}_m-f'(x)|\le a_{\mathrm{tol}}+
r_{\mathrm{tol}}|f'(x)|.
\]

This is a *numerical agreement* criterion, not a proof of the analytic formula.

## 3. Financial model A: continuous accumulation

For principal \(P>0\), annual continuous rate \(r\), and time \(t\ge0\),

\[
A(t)=Pe^{rt},\quad A'(t)=rA(t),\quad A''(t)=r^2A(t).
\]

Use \(P=1000\), \(r=0.04\), and \(t=5\). The model tests smooth exponential growth and both derivative orders. The variable being differentiated is **time**, measured in years.

## 4. Financial model B: discounted cash flow

For cash flow \(C>0\), fixed horizon \(t>0\), and variable continuously compounded rate \(r\),

\[
V(r)=Ce^{-rt},\quad V'(r)=-tV(r),\quad V''(r)=t^2V(r).
\]

Use \(C=5000\), \(t=4\), and \(r=0.03\). The differentiated variable is the **decimal interest rate**. A perturbation \(h=0.0001\) is one basis point; do not confuse it with one percentage point.

## 5. Financial model C: quadratic profit

For quantity \(q\) within a feasible range,

\[
\Pi(q)=-1000+80q-0.25q^2,
\quad \Pi'(q)=80-0.5q,
\quad \Pi''(q)=-0.5.
\]

Use \(q=100\) and \(q=160\). At \(q=160\), the first derivative is zero, so a **relative-only** error test would be meaningless. The acceptance gate must include an absolute tolerance.

For quadratic functions, the centered first and second differences are algebraically exact in real arithmetic. Floating-point roundoff can still affect their computed values.

## 6. Financial model D: smooth ratio

For \(x>0\),

\[
Q(x)=\frac{100+8x}{50+3x}.
\]

The first and second derivatives are

\[
Q'(x)=\frac{100}{(50+3x)^2},
\qquad
Q''(x)=-\frac{600}{(50+3x)^3}.
\]

Use \(x=2\) and test the function's domain. This model checks quotient-rule formulas and a nonconstant second derivative.

## 8. Failure modes and safeguards

- **Domain boundary:** A centered stencil may cross into an invalid region. Report a domain error instead of silently changing the method.
- **Nondifferentiability:** At \(x=0\), \(f(x)=|x|\) has no two-sided derivative, although its centered difference is zero. Do not declare a derivative from that output.
- **Cancellation:** Very small \(h\) can make \(f(x+h)-f(x-h)\) inaccurate.
- **Noisy models:** Simulation noise can dominate the derivative; use paired randomness or alternative estimators where appropriate.
- **Wrong reference formula:** A numerical match at a single point is insufficient. Validate analytic derivatives independently over multiple points.
- **Unit confusion:** Report the variable and its units alongside each sensitivity.
- **Tolerance gaming:** Do not loosen tolerances merely to force a passing result. Investigate failures and document accepted numerical limits.

### Expected conclusions

1. Analytic references are derived independently of the numerical comparator.
2. First-order one-sided errors generally decrease linearly with \(h\) before roundoff dominates.
3. Centered first differences generally converge quadratically for smooth functions.
4. Richardson extrapolation can reduce truncation error but may amplify noise.
5. Second derivatives are more sensitive to cancellation than first derivatives.
6. At stationary points, absolute tolerance is essential.
7. Domain checks and branch consistency are part of numerical correctness.
8. Runtime results must be preserved as evidence, not inferred from code publication.

## Comparator audit follow-up

Each report retains `abs_tol`, `rel_tol` and the asymmetric sum-rule description. Signed error means numerical estimate minus supplied analytic derivative; absolute error is its magnitude. Selected dyadic polynomial examples check both error fields and inclusive acceptance boundaries, including zero analytic references and deliberately incorrect reference callbacks.

Finite callback outputs do not guarantee finite numerical stencils or error differences. The comparator now validates every returned estimate and signed error, raising `ValueError` if these calculations become nonfinite. This prevents an infinite error from passing against an overflowed threshold. Ordinary cancellation, underflow and wrong-but-plausible supplied references remain possible; passing a comparator is not a proof of differentiability or reference correctness.
