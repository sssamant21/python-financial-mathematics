## Learning objectives

Model threshold events in continuous-time financial systems; derive account depletion times; distinguish event detection from event localization; implement continuous trajectories with discrete jumps; choose explicit terminal, reset, and boundary policies; and audit solver accuracy and financial assumptions.

## 1. Events in initial-value problems

Consider an ODE \(A'=f(t,A)\) with initial balance \(A(0)=A_0\). An **event function** \(g(t,A)\) defines a threshold by \(g(t,A)=0\). For depletion, \(g(t,A)=A\). An event is not automatically a discontinuity in the state: the trajectory may remain continuous while crossing a threshold. A *jump event* is different and requires a separate state update.

Event metadata should specify its direction: decreasing crossings (\(+\) to \(-\)), increasing crossings (\(-\) to \(+\)), or both. A **terminal event** stops integration at the first qualifying crossing. A **nonterminal event** records the event and continues, subject to the business rules.

## 2. Constant-withdrawal account

For a constant continuously compounded rate \(r\) and fixed withdrawal rate \(w>0\),

\[
A'=rA-w,\qquad A(0)=A_0>0.
\]

When \(r\ne0\), the solution is

\[
A(t)=A_0e^{rt}-w\frac{e^{rt}-1}{r}
=A_0+(rA_0-w)\frac{\operatorname{expm1}(rt)}{r}.
\]

For \(r=0\), \(A(t)=A_0-wt\). At \(r>0\), depletion occurs if and only if \(w>rA_0\), with

\[
\boxed{t_*=\frac{\ln\bigl(w/(w-rA_0)\bigr)}{r}}
=\frac{-\ln(1-rA_0/w)}{r}.
\]

The latter expression is best evaluated with \`-log1p(-r*A0/w)/r\` when the ratio is small. If \(w=rA_0\), the balance remains constant; if \(w<rA_0\), it grows. For \(r<0\), with positive \(A_0,w\), depletion occurs at finite time and the same formula applies, with a positive logarithm argument. The zero-rate limit is \(t_*=A_0/w\).

**Example:** \(A_0=1000\), \(r=0.04\) per year, \(w=100\) currency units per year. The threshold is \(rA_0=40\), so depletion occurs at \(-\ln(0.6)/0.04\approx12.77064\) years.

## 3. Detecting and localizing a crossing

For a decreasing zero-balance event, inspect the signs of consecutive states: \(A_n>0\) and \(A_{n+1}\le0\) indicate a crossing within the step *if the trajectory is continuous and the numerical approximation resolves the crossing*. This bracket alone does not give an accurate event time.

A simple localization interpolates between the endpoints:

\[
t_{\rm lin}=t_n+h\frac{A_n}{A_n-A_{n+1}}.
\]

This is only an approximation. More reliable localization evaluates a continuous interpolant or re-integrates the ODE over the bracket and solves \(g(t,A(t))=0\) with a bracketed root finder. Dense-output methods can provide efficient event localization.

A crossing can be missed when both endpoints have the same sign, for example if the event function crosses zero twice within one step or touches zero tangentially. Direction filtering, maximum step sizes, and event-specific analysis matter.

## 4. Event handling is a modeling decision

Three distinct policies are common:

- **Stop at depletion:** terminate the model at the first downward zero crossing and record the time.
- **Continue with overdraft:** permit negative balances and apply explicit borrowing-rate or credit rules; do not silently extend the original account model.
- **Apply a boundary or intervention:** stop withdrawals, inject capital, or impose a floor under an explicit rule. A naive numerical clamp \`max(0,A)\` changes the dynamics and can hide solver overshoot.

Choose the policy before implementation. A boundary rule is not a consequence of the differential equation alone.

## 5. Lump-sum transfers

A discrete deposit or withdrawal \(J\) at \(t_j\) creates a jump:

\[
\boxed{A(t_j^+)=A(t_j^-)+J}.
\]

Integrate continuously to the jump time, apply the jump once, and restart the solver with the updated state. Do not model an instantaneous jump as a large continuous cash-flow rate over an arbitrary tiny interval unless the approximation and its sensitivity are justified.

For a constant rate \(r\), a deposit \(J\) at \(t_j\) adds \(Je^{r(T-t_j)}\) to the balance at horizon \(T\), assuming no other policy changes.

## 6. Multiple events and ordering

An account may have scheduled deposits, scheduled withdrawals, depletion, and an end-of-horizon event. Specify the order when two events share a timestamp. For example, a deposit at the exact depletion time could be applied before or after a terminal depletion policy; these choices produce different results.

Record whether a scheduled jump is applied before testing the post-jump balance and whether zero at the initial time is terminal. Avoid applying the same jump twice after a solver restart.

## 7. Numerical safeguards

Event-aware simulation should enforce finite inputs, nonnegative horizons, increasing event times, finite event magnitudes, and a documented convention for initial threshold states. For analytical constant-withdrawal models, compute the event time directly where possible and compare with numerical detection.

For a numerical solver, include an event-time tolerance, maximum steps, maximum iterations for localization, and an explicit failure status if an event cannot be resolved. A successful integration to the horizon does not prove no threshold crossing occurred between steps.

## 8. Sensitivity and financial interpretation

Depletion time is sensitive to initial balance, return rate, and withdrawal rate. When \(w\) approaches \(rA_0\) from above for \(r>0\), the depletion time becomes very large. Small parameter changes near this boundary can dramatically alter the forecast.

This is a deterministic scenario calculation, not a probability of retirement ruin or a guarantee of solvency. Market volatility, taxes, fees, and spending changes require additional modeling.

**1.** Define an event function.  
*Solution:* A function \(g(t,A)\) whose zeros define candidate events.

**2.** Give the depletion event function.  
*Solution:* \(g(t,A)=A\).

**3.** What does a decreasing event direction mean?  
*Solution:* The event function crosses from positive to negative.

**4.** What does a terminal event do?  
*Solution:* Stops integration at the qualifying event.

**5.** Write the fixed-withdrawal ODE.  
*Solution:* \(A'=rA-w\).

**6.** State its solution for \(r\ne0\).  
*Solution:* \(A=A_0e^{rt}-w(e^{rt}-1)/r\).

**7.** State the solution for \(r=0\).  
*Solution:* \(A=A_0-wt\).

**8.** Find the zero-rate depletion time.  
*Solution:* \(t_*=A_0/w\).

**9.** State the positive-rate depletion condition.  
*Solution:* \(w>rA_0\).

**10.** Give the positive-rate depletion time.  
*Solution:* \(t_*=-\ln(1-rA_0/w)/r\).

**11.** What happens if \(w=rA_0\) for \(r>0\)?  
*Solution:* The balance remains constant.

**12.** What happens if \(w<rA_0\) for \(r>0\)?  
*Solution:* The balance grows; there is no depletion.

**13.** Give a simple crossing bracket.  
*Solution:* \(A_n>0\) and \(A_{n+1}\le0\).

**14.** Give the linear event-time estimate.  
*Solution:* \(t_n+hA_n/(A_n-A_{n+1})\).

**15.** Is linear interpolation always exact?  
*Solution:* No; it approximates the crossing time.

**18.** What is the final value of a deposit \(J\) made at \(t_j\) under constant \(r\)?
