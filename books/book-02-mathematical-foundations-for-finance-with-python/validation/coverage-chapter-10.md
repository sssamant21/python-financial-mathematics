## Project and integrated requirements

The 10.9 project functional gates have positive-path coverage for three streams, discrete and mixed values, affine quadrature and negative flat rates. Explicit signed-payment/negative-stream cases and zero-horizon engine cases are not in its numbered check. Frozen dataclasses are implemented but attempted mutation is not tested. Finite input checks cover bool/NaN, while not every constructor, callback or overflow route is asserted.

The project sensitivity comparison reuses portfolio valuation and central differences at two bumps. It does not compare the mixed portfolio derivative against a separately evaluated time-weighted integral plus exact discrete derivative. Affine refinement checks decreasing differences, without an independent value oracle or asserted /15 error estimate. Deterministic JSON, explicit tolerances, bump metadata and report assumptions are not fully asserted; source inspection also shows the assessment report omits several requested audit details rather than merely lacking tests.

For 10.10 integrated Tasks 1–2, the engine constructs components using shared primitives; the check does not separately assert every analytic component. Task 3 checks three grid rows, finest discrepancy and coarse/fine ordering, but not each exact count or a recorded maximum discrepancy. Task 4 checks only positivity of the affine total, not its independent value. Task 5 checks derivative signs rather than the displayed integral formula. Task 6 remains manual model/governance reasoning. Rubric credit cannot be inferred from script success.
