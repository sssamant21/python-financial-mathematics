## Events, project and adaptive evidence

19.7 intentionally applies an exactly coincident scheduled jump before its post-jump zero check, subject to floating-point comparisons.19.9 explicitly gives continuous depletion precedence at simultaneous future jumps; both apply t0 jumps before initial depletion. Manuscript states this difference; it is not an accidental inconsistency. Both exact-zero-rate examples are tested. Near-coincident events, negative jump terminal handling, logs and nonterminal overdraft policy remain partial. Analytical crossing and linear interpolation examples are not a general event-localizing numerical ODE engine.

19.9's project report promises initial balance, rate, flow and horizon, but _result does not retain these input fields; it retains units, status/final time/balance/depletion, scheduled/applied counts and event log. Exact log order/amount/balance, nonapplied event details, deterministic JSON and source/configuration metadata lack assertions. Optional monthly-transfer/overdraft/transaction-id extensions are not mandatory missing features.

Adaptive RK4 tests establish useful analytic accuracy and count relationships, plus two failure statuses. They do not independently validate error=abs(twohalf-full)/15, scale, accepted-state update, controller clipping/exponent, or lack of time advancement after rejection. No assertion requires a rejected attempt or an independently known acceptance/rejection sequence. Local tolerance is not a global-error certificate.

19.10 Applied B convergence experiment has explicit first/fourth-order ratio support, unlike many earlier chapters' monotonic-only checks. Applied A withdrawal equilibrium/depletion partially covered; terminal simulation is19.9. Applied C changed mean-reversion inputs (0.6,5000,3000) and D deposit500 at years1/3 absent as exact cases. Applied E financial assumption/independent-review checklist remains manual.
