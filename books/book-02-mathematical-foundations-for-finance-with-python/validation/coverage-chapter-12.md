## Project acceptance and output contract

The seven 12.9 functional requirements have implementation paths for validation/alignment, pivoted solve, inverse-column condition calculation, achieved/residual metrics, factor/condition decisions and structured output. Ordinary accepted, singular and condition-rejected cases are asserted. A factor-tolerance rejection reason is implemented but not exercised; accepted exact reference residuals do not exercise it. Numerical pivot tolerance and condition-limit boundaries and invalid guardrail values are untested.

The acceptance matrix asks for nonfinite coefficient rejection, but the project check inserts NaN into a Vector, not the coefficient matrix. Other section checks reject nonfinite matrices; that does not test this project's ExposureSystem constructor. Unit mismatch and rectangular project-system rejection are likewise implemented without direct project assertions. Permuted targets and tolerances are tested by comparison with the reference report.

Runbook logging fields only partly match output: pivot tolerance, condition limit, gross/net positions, achieved/residual and factor decisions are present; factor tolerance values, input timestamps and policy/model versions are not all retained. Deterministic JSON/repeated calls and CLI error reporting are not asserted. No production data provenance or access-control validation is established.

The 12.10 implementation is a smaller solver and condition-decision report, not a general matrix-operations/rank/residual-metric assessment. It omits dedicated multiplication, transpose, diagonal and rank helpers, imperfect-candidate residual examples, and target-relative/backward metrics. The manuscript's broad assessment description needs this scope distinction during editorial revision.

## Numerical and oracle limitations

[Inverse scaling regressions](../chapter-12/code/check_inverse_scaling.py) add identity inverses at scales 1,1e200,1e-200, nondiagonal known inverses at extreme scales, condition number 1 for scaled identities in 12.7, and singular rejection. See [focused inverse review](chapter-12-inverse-scaling-review.md). The direct determinant helper intentionally remains separate from normalized inverse arithmetic; scaled inverse success does not establish representability of an unscaled determinant.

Most solver/condition checks use the same two reference matrices. Larger dimensions, multiple pivot swaps, severe cancellation, relative pivot thresholds and scaling of normalizers are not broadly exercised. Condition estimation via repeated calls to the same elimination routine is implementation evidence, not an independent oracle for arbitrary systems.

12.5 uses a shared threshold based on the largest augmented entry, including target b. Thus changing target magnitude can change the reported numerical rank of A, even with fixed A. The report warns that ranks are tolerance-dependent, but no source assertion probes this dependence. It must be evaluated before treating classification as a general mathematical existence determination.

12.7 asserts bound_satisfied booleans and expected endpoints; it does not independently assert every relative-change/bound number. The manuscript's coefficient perturbation inequality has a denominator-positivity condition that remains a manual derivation/assumption review item. Finite tested bounds do not prove the inequalities.
