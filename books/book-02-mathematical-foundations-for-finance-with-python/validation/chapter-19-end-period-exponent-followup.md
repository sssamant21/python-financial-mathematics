The helper now accepts selected cases through `abs(rate*years) = 5000`. It carries the total growth factor directly rather than reconstructing deep decay from a rounded difference. The single-payment path adds the undiscounted final payment to the grown initial state. For more than one period, the geometric factor uses the same period correction as before, retained before rounding even for extremely fine payment schedules. Exact zero and zero-flow handling are unchanged. The extended domain still rejects final overflow and nonzero balances that round to zero. The remaining explicit exponent guard is a scope restriction, not a classification of excluded balances.

The [runnable checker](../chapter-19/code/check_end_period_exponent_range.py) computes short schedules by separately compounding and summing each end-period payment, and bounds the timing correction for very large period counts. It replays all four previously [checkpointed cases](chapter-19-end-period-exponent-baseline.md), plus genuine overflow, genuine underflow, subnormal midpoint cases and both sides of the new guard. From the book root run `python chapter-19/code/check_end_period_exponent_range.py` with assertions enabled; for baseline overlay only this checker onto the baseline revision. The logs distinguish a source mismatch from the checker's initial exception-message classification.
