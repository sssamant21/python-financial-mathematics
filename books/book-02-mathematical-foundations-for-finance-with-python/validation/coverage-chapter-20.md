## Project, evidence and numerical limitations

20.9's twelve-step lab has reference/property checks for steps3–8 but only limited invalid input classes and no explicit rate monotonicity within its own script. Tests do not execute an intentionally wrong always-zero function, exercise all overflow/underflow branches or verify the pending dossier's full schema. An empty findings list means a template, not “no findings.” Source/environment remain None by design.

20.7 records Python at manifest creation and input hash, but leaves source/dirty tree/command/exit/actual/tolerance pending. Its report cannot substitute for the actual pinned execution evidence. Exclusive write/no-overwrite is meaningfully asserted. Full field schema, readback beyond hash, interrupted writes, dependency capture and cross-environment replay are not demonstrated.

20.8 checks syntactic completeness, explicitly never authorizes release. Finding lifecycle, authorized exceptions/expiry, reviewer identity, evidence references, business use and production controls are human/artifact review work. A complete dictionary does not establish valid review. The Federal Reserve/NIST reference context was repaired in [source resolution](source-reference-resolution.md); these citations do not make this educational checklist a compliance certificate.

20.5 close_to_reference evaluates its asymmetric sum comparison exactly for represented binary floats using Fraction. Adjacent and overflow-prone comparisons have regression evidence. Its errors helper separately subtracts/divides floats and may produce unrepresentable errors for extreme inputs; comparator correctness is not full error-report range validation. Other chapters' close helpers use different isclose rules; tolerances are not interchangeable.

20.4 includes the small-payment/subnormal annuity regression from [focused boundary review](chapter-20-boundary-review.md).20.2 closed annuity and20.2/20.3 continuous account copies use different intermediate arithmetic and are not covered by that same assertion.20.6 uses bounded generated inputs and lacks the stronger finite/type/output contract of20.9. These differences require explicit scope and numerical review.
