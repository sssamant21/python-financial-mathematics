## Project and oracle detail

The six project mathematical checks have positive reference evidence: full-rank QR rejection/solve paths, achieved vector via multiplication, signed residual fractions, near-zero weighted gradient, fraction objective and factor-policy rejection. Neither zero gradient nor successful solve alone establishes global numerical reliability. The reference is small and well-scaled.

The report implements positions, achieved/residual/standardized values, objective, gradient, factor units, booleans, decision, solver and pending flag. Assertions do not inspect all standardized residual values, unit metadata, solver identifier, schema completeness or deterministic serialized output. Inputs contain scales, target and limits, but the report does not retain all of them. Unit strings are only checked for nonempty per-factor values; they cannot independently verify that a sensitivity row, target, scale and hard limit were converted consistently. The consistent-conversion test is useful evidence for a controlled example, not an economic unit validator.

Rank-deficient, underdetermined, constrained, generalized-weight and production SVD extensions are explicitly outside the project scope. Their absence is not a failed mandatory feature. The separate regularization helper is fixed to the two-identical-column example.

[Projection scaling regressions](../chapter-13/code/check_projection_scaling.py) assert known projected values, distance and coefficient scaling for directions scaled by 1,1e200,1e-200,-1e200, plus zero rejection. These support the [focused scaling fix](chapter-13-projection-scaling-review.md), not all projection copies, target scales, coefficient range or raw orthogonality diagnostic range.
