## Project mission

Build a reproducible **multi-input, multi-output valuation sensitivity engine** using Python's standard library. The engine calculates exact revaluation, gradients, a Jacobian, output-specific Hessians, first- and second-order Taylor changes, and scenario errors. The project integrates Sections 15.1–15.8 without claiming to be a production pricing or risk-management system.

## 1. Financial model and units

Consider a hypothetical two-instrument portfolio driven by the same three inputs:

\[
x=(P,r,t)^\mathsf T,\qquad P>0,\quad t\ge0,
\]

where \(P\) is a currency principal, \(r\) is an annual continuously compounded decimal rate, and \(t\) is years. Define

\[
\boxed{F(P,r,t)=\begin{bmatrix}
V_1(P,r,t)\\V_2(P,r,t)
\end{bmatrix}
=\begin{bmatrix}
Pe^{rt}\\0.5Pe^{-rt}
\end{bmatrix}}.
\]

The first output is a future-value model and the second is a discounted-value model of half the principal. These are deliberately simplified teaching instruments, not arbitrage-free prices of a real portfolio. The portfolio total is \(S=V_1+V_2\). Rate shocks are **decimal rate changes**: \(0.01\) means one percentage point, not one percent of the current rate.

## 2. Analytical gradient and Jacobian

Let \(a=e^{rt}\), \(b=e^{-rt}\). The output gradients, with coordinates ordered \((P,r,t)\), are

\[
\nabla V_1=\begin{bmatrix}a\\Pta\\Pra\end{bmatrix},
\qquad
\nabla V_2=\begin{bmatrix}0.5b\\-0.5Ptb\\-0.5Prb\end{bmatrix}.
\]

Stacking their transposes gives the \(2\times3\) Jacobian:

\[
\boxed{J_F=\begin{bmatrix}
a&Pta&Pra\\
0.5b&-0.5Ptb&-0.5Prb
\end{bmatrix}}.
\]

The total-value gradient is \(\nabla S=\nabla V_1+\nabla V_2\). A scenario displacement \(h=(\Delta P,\Delta r,\Delta t)^\mathsf T\) produces first-order output changes \(J_Fh\).

## 3. Analytical Hessians

The Hessian of the first output is

\[
\boxed{H_1=
a\begin{bmatrix}
0&t&r\\
t&Pt^2&P(1+rt)\\
r&P(1+rt)&Pr^2
\end{bmatrix}}.
\]

For the second output,

\[
\boxed{H_2=
0.5b\begin{bmatrix}
0&-t&-r\\
-t&Pt^2&P(rt-1)\\
-r&P(rt-1)&Pr^2
\end{bmatrix}}.
\]

Both matrices are symmetric, including the principal-rate and principal-time cross partials. The total-value Hessian is \(H_S=H_1+H_2\).

## 4. Scenario approximation

For each instrument \(i\),

\[
\Delta V_i^{(1)}=\nabla V_i(x)^\mathsf Th,
\]

\[
\boxed{\Delta V_i^{(2)}=\nabla V_i(x)^\mathsf Th+\tfrac12h^\mathsf TH_i(x)h}.
\]

The exact change is

\[
\boxed{\Delta V_i^{\rm exact}=V_i(x+h)-V_i(x)}.
\]

Define **signed approximation errors** as estimate minus exact:

\[
E_i^{(k)}=\Delta V_i^{(k)}-\Delta V_i^{\rm exact},
\qquad k\in\{1,2\}.
\]

Report absolute errors as \(|E_i^{(k)}|\). Sum signed instrument errors to obtain the portfolio signed error; the portfolio absolute error is the absolute value of that sum, not the sum of absolute instrument errors. Avoid computing relative error when the exact change is near zero without an explicit denominator convention.

The scenario report exposes `portfolio_first_order_error`, `portfolio_second_order_error`, `absolute_portfolio_first_order_error` and `absolute_portfolio_second_order_error` for these totals.

## 5. Reference scenario

Use the base inputs

\[
(P,r,t)=(1000,\ 0.05,\ 2)
\]

and scenario shocks

\[
(\Delta P,\Delta r,\Delta t)=(100,\ 0.01,\ 0.5).
\]

The shocked inputs are \((1100,0.06,2.5)\). Base and shocked output levels are

\[
F(x)=\begin{bmatrix}1000e^{0.1}\\500e^{-0.1}\end{bmatrix},
\qquad
F(x+h)=\begin{bmatrix}1100e^{0.15}\\550e^{-0.15}\end{bmatrix}.
\]

The exact changes are

\[
\Delta V_1=1100e^{0.15}-1000e^{0.1},
\qquad
\Delta V_2=550e^{-0.15}-500e^{-0.1}.
\]

The first-order changes are

\[
\boxed{\Delta V_1^{(1)}=145e^{0.1}},
\qquad
\boxed{\Delta V_2^{(1)}=27.5e^{-0.1}}.
\]

The first-order term for \(V_2\) is positive because the principal increase outweighs the rate and maturity effects locally.

For \(V_1\), the quadratic correction can be organized as

\[
e^{0.1}\left[
\Delta P(t\Delta r+r\Delta t)
+\frac P2\left(t^2\Delta r^2+2(1+rt)\Delta r\Delta t+r^2\Delta t^2\right)
\right].
\]

For \(V_2\), it is

\[
\frac{e^{-0.1}}2\left[
-\Delta P(t\Delta r+r\Delta t)
+\frac P2\left(t^2\Delta r^2+2(rt-1)\Delta r\Delta t+r^2\Delta t^2\right)
\right].
\]

For this reference shock, the second-order changes simplify to \(155.5125e^{0.1}\) and \(23.25625e^{-0.1}\). The checker also derives expected changes by expanding the one-dimensional shocked-input path, without calling the engine's derivative or quadratic-form helpers.

These are second-order Taylor corrections about the **base** inputs; no derivatives are recomputed at the shocked point when forming the local estimate.

## 6. Architecture and data contracts

The companion module provides:

- \`valuation(principal, rate, years)\`: two modeled output levels.
- \`jacobian(principal, rate, years)\`: a \(2\times3\) sensitivity matrix.
- \`hessians(principal, rate, years)\`: two symmetric \(3\times3\) matrices.
- \`scenario(base, shock)\`: exact and Taylor changes, errors, and portfolio totals.
- \`centered_jacobian_column(base, index, step)\`: numerical check of one Jacobian column.
- \`assessment()\`: deterministic educational reference scenario.

Inputs are finite real numbers (excluding booleans); principal is positive, time is nonnegative, and shocked time must remain nonnegative. Invalid dimensions, nonfinite calculations, and exponential overflow must fail clearly. Use no external packages and do not log credentials or production customer data.

## 7. Hands-on lab — twelve steps

1. Create a clean Python 3 environment and locate the chapter's \`code\` directory.
2. Read the financial model and identify all input/output units.
3. Evaluate the two base instrument values and their portfolio sum.
4. Derive the three partial derivatives of each output by hand.
5. Construct and inspect the \(2\times3\) Jacobian.
6. Derive the two \(3\times3\) Hessians and verify symmetry algebraically.
7. Evaluate the reference shock and its exact revaluation.
8. Compute the first-order scenario estimate with \(J_Fh\).
9. Compute each second-order correction with \(\tfrac12h^\mathsf TH_ih\).
10. Report signed and absolute approximation errors for both outputs and their total.
11. Compare the analytical Jacobian columns against centered finite differences using input-specific steps.
12. Run the independent reference-check source, document any failures, and retain **Draft** status until the separate runtime and editorial QA phase.

## 8. Production-engineering interpretation

This project deliberately does **not** model yield curves, credit spreads, stochastic volatility, transaction costs, or calibrated market instruments. A financial implementation should establish the economic meaning of each input, instrument pricing conventions, numerical precision policy, reproducible calibration, sensitivity unit conventions, audit trails, and scenario governance.

Do not interpret the raw Euclidean magnitude of a gradient with heterogeneous units as a meaningful risk ranking. Scale inputs or use clearly defined shock vectors. If several outputs must remain constant to first order, examine the null space of the Jacobian, then verify proposed finite moves with exact revaluation and feasibility checks.

### Finite-difference accuracy limits

Distinct finite perturbations are a prerequisite, not an accuracy guarantee. The centered-column helper uses the requested `2*h` denominator; floating-point additions can produce unequal represented offsets. Tiny steps can also lose most of the function difference to rounding. Selected rate/time step ladders exhibit second-order truncation convergence, while principal dependence is linear; very small accepted steps produce materially worse results. Compare multiple sensible steps with analytic or independent references and respect input domains. [Selected production-float checks and limits](../validation/chapter-15-jacobian-accuracy-followup.md).
